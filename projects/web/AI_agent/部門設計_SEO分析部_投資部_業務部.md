# 小龍蝦 AI 指揮室 — 後三部門角色設計（SEO 分析部 / 投資部 / 業務部）

依前七部門的風格補完，設計依據為 2026 年實際運作中的多 Agent 框架與產業實務（見文末參考來源）。

---

## 第八個 SEO 分析部（4 人）

2026 年的 SEO 已經是「多 Agent 分工」的標準做法：單一 Agent 同時做研究、寫作、優化，每個環節都平庸；拆成專職 Agent 互相接力，品質才會穩定。這個部門的定位是「幫其他部門找到市場在搜什麼、缺什麼」，產出直接餵給產品開發部和社群推廣部。

**市場爬蟲（Market Crawler）：**
部門的資料入口。負責抓取 SERP（搜尋結果頁）、競品網站內容、關鍵字量與熱門問答，把原始資料整理成結構化格式交給後面三位分析師。他不做判斷，只保證資料新鮮、完整、可追溯。

**SEO 分析師（SEO Analyst）：**
拿到爬蟲的資料後，負責關鍵字策略：搜尋量、競爭度、搜尋意圖分類，以及自家內容（產品頁、社群貼文）的 SEO 健檢與優化建議。2026 年還多了一個新戰場——GEO（生成式引擎優化），也就是讓內容更容易被 AI 搜尋引擎引用，這也歸他管。

**趨勢週期分析師（Trend Cycle Analyst）：**
看的是時間軸。哪些主題正在起量、哪些已過熱、哪些有季節性週期（例如節慶貼圖的需求高峰）。他的價值在於告訴團隊「什麼時候做什麼」，讓產品和文案不要追在趨勢尾巴後面。

**市場機會分析師（Market Opportunity Analyst）：**
部門的出口。整合前三人的產出，找出「搜尋量存在、但沒有好答案」的內容缺口與產品機會，寫成機會清單（附預估流量與競爭難度）交給產品開發部當 idea 來源。

工作流：市場爬蟲 → SEO 分析師 + 趨勢週期分析師（並行）→ 市場機會分析師彙整 → 交付產品開發部 / 社群推廣部。

## 第九個 投資部（9 人，模擬盤）

這是十個部門中人數最多的，設計上直接對標 UCLA + MIT 的開源框架 TradingAgents（GitHub 8 萬星以上，目前最主流的多 Agent 交易架構）。該框架證明了「分析師團隊 → 研究辯論 → 交易決策 → 風控審核 → 基金經理核准」的多層結構，回測績效比單一模型好 6–25%。投資部把這個結構本地化成台股 + 美股雙市場版本。

### 分析師層（六位，並行蒐集情報）

**台股權值分析師（大盤/權值股）：**
盯台股加權指數與權值股（台積電、鴻海等），分析大盤結構、外資動向、權值股基本面。

**台股題材分析師（熱門題材）：**
盯題材股與族群輪動：AI 供應鏈、重電、軍工等當期熱門族群的資金流向與續航力。

**美股分析師：**
負責美股大盤與個股，特別是與台股連動高的半導體、科技股（美股收盤直接影響隔日台股開盤）。

**全球市場分析師：**
看宏觀：聯準會利率、匯率、原物料、地緣政治，判斷大環境是順風還是逆風。

**財經新聞分析師：**
即時掃描財經新聞與重大事件，評估單一事件對持倉與觀察清單的影響方向與強度（對應 TradingAgents 的 News Analyst）。

**期權分析師（Futures & Options）：**
看台指期、選擇權的未平倉與籌碼結構，提供市場情緒指標（Put/Call Ratio 等），也負責評估避險策略。

### 決策層（三位，串行把關）

**數據分析師（Data Analyst）：**
把六位分析師的定性判斷轉成定量訊號：技術指標（MACD、RSI）、回測數據、勝率統計，避免決策只靠「感覺」。

**投資風控官（Investment Risk Officer）：**
獨立於分析師之外，對每筆模擬交易做風險評估：部位上限、停損條件、集中度檢查，風險過高有權否決（對應 TradingAgents 的 Risk Manager）。

**投資經理（Investment Manager）：**
最終決策者。彙整分析師意見與風控意見，決定模擬盤的進出場，並定期向總經理與使用者彙報績效（對應 Fund Manager）。

工作流：六位分析師並行 → 數據分析師量化 → 投資經理擬單 → 投資風控官審核 → 記入模擬盤帳本（未實現/已實現損益進公司財務）。

**重要邊界：全程模擬盤，絕不連接真實券商下單。** 這一點和審批中心「絕不執行真實動作」的原則一致。

## 第十個 業務部（6 人）

2026 年 AI SDR（AI 業務開發代理人）已是成熟品類——Gartner 預估 2026 年底 75% 的 B2B 銷售組織會部署 AI 銷售工具，實務數據是 pipeline 提升 20–30%、回應速度快 80%。業務部就是把這套「找客戶 → 開發 → 成交 → 維繫」的流水線搬進公司，服務對象是自家產品（貼圖、工具、訂閱服務）的銷售。

**業務策略師（Sales Strategist）：**
部門的大腦。定義目標客群輪廓（ICP）、定價策略、銷售渠道優先序，並根據營收分析師的數據調整打法。

**客戶開發（Customer Development Agent）：**
對應 AI SDR 的核心職能：從市場找潛在客戶與合作機會（例如貼圖平台、團購主、社群合作），草擬開發訊息與提案。**只產草稿，實際寄送與接觸由使用者核准後執行**——和社群部「絕不自動發布」同一條紅線。

**訂單管理（Order Manager）：**
追蹤每筆訂單從成立到交付的狀態，異常（退款、延遲）即時上報，訂單數據同步給會計部入帳。

**營收分析師（Revenue Analyst）：**
分析銷售數據：哪個產品賣得動、哪個渠道轉換率高、客單價與回購率變化，每週產出簡報給業務經理與月度財報員。

**客戶關係管理（CRM Manager）：**
維護客戶資料庫與互動紀錄，負責售後：分群、回購提醒草稿、流失預警。CRM 資料自動保持最新是 AI 業務團隊的標配。

**業務經理（Sales Manager）：**
部門主管。彙整策略、開發進度、訂單與營收四條線，對總經理負責，跨部門需求（例如要設計部出銷售素材）由他發起。

工作流：業務策略師定方向 → 客戶開發執行（人工核准關卡）→ 訂單管理 + CRM 承接 → 營收分析師回饋數據 → 業務經理彙報。

## 能不能做出這樣的 AI 團隊？—— 可以，而且你的架構已經走在正確的路上

三個佐證：

1. **投資部的架構已被開源驗證。** TradingAgents 用幾乎相同的「多分析師 + 研究辯論 + 風控 + 經理核准」結構跑出優於基準的回測績效，是 GitHub 上最多星的 AI 交易框架。你的 9 人投資部等於它的台股擴充版。
2. **SEO 多 Agent 分工是 2026 年業界標準。** 90% 的行銷組織已在用 AI Agent，且共識是「專職 Agent 接力 > 全能單一 Agent」，你把爬蟲/分析/趨勢/機會拆成四個角色的做法符合最佳實踐。
3. **AI SDR 是成熟商業品類。** 11x、Qualified 等公司已把「自主找客戶、寫信、跟進、同步 CRM」做成產品，證明業務部的每個角色都有現實對應物。

三個成敗關鍵（也是業界共同結論）：

1. **人工核准關卡不能省。** 2026 年的共識是「AI 執行、人類核准」——你的審批中心、模擬盤、不自動發布三條紅線正是這個原則，務必保持。
2. **成本控管決定能跑多久。** 38 個角色若全用高階模型會燒穿 US$90 月預算；你目前「日常角色用 Gemini Flash、關鍵決策角色用 Claude Opus/Sonnet」的分級配置是對的，API 成本會計要每日盯。
3. **資料品質是天花板。** 投資部要穩定的行情/新聞來源、SEO 部要穩定的搜尋資料來源、業務部要乾淨的客戶資料。Agent 再聰明，餵髒資料就輸出垃圾。建議每個部門先接通一個可靠資料源再擴充。
