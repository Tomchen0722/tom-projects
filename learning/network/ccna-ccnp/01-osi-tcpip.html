🏛️ OSI 七層模型

OSI（Open Systems Interconnection）是 1984 年 ISO 制定的網路通訊標準架構。現實世界用 TCP/IP，但 OSI 提供了一套精確的語言讓工程師溝通。當你說「這是 Layer 3 的問題」，全世界的工程師都懂你的意思。

比喻：把 OSI 想成一份快遞的生命週期。你寫信（應用層），信紙封好信封（表達層），確認對方有沒有空收（會話層），決定要用航空還是船運（傳輸層），在信封上寫城市/國家（網路層），交給快遞公司處理包裹（資料鏈路層），最後司機開車送達（實體層）。
7
應用層
Application
直接提供服務給使用者應用程式。負責資料的最終意義，例如「這是一個 HTTP GET 請求」。
PDU：訊息（Message）
HTTP HTTPS FTP SMTP POP3 IMAP DNS DHCP Telnet SSH SNMP
6
表達層
Presentation
資料格式轉換（ASCII ↔ EBCDIC）、加密/解密（TLS）、壓縮（gzip）。讓雙方使用共同語言。
PDU：訊息（Message）
SSL TLS JPEG PNG MPEG ASCII EBCDIC
5
會話層
Session
建立、管理、終止兩個應用程式之間的對話（Session）。例如一次 Web 連線從開始到結束。
PDU：訊息（Message）
NetBIOS RPC SQL NFS SIP
4
傳輸層
Transport
端到端（End-to-End）的可靠傳輸。用 Port 號識別上層應用，TCP 保證可靠，UDP 追求速度。
PDU：片段（Segment）
TCP UDP SCTP Port 號
3
網路層
Network
跨網段的邏輯定址（IP 位址）和路徑選擇（路由）。Router 在這層工作。
PDU：封包（Packet）
IPv4 IPv6 ICMP OSPF BGP EIGRP ARP（功能上）
2
資料鏈路層
Data Link
同一個區域網路內，用 MAC 位址定址，Switch 在這層工作。偵測並可能修正實體層錯誤（CRC）。
PDU：訊框（Frame）
Ethernet 802.3 Wi-Fi 802.11 PPP HDLC 802.1Q VLAN
1
實體層
Physical
實際的電壓、光脈衝、無線電訊號傳輸。定義接頭規格、線材類型、傳輸速率。
PDU：位元（Bit）
RJ-45 光纖 同軸 Wi-Fi 藍牙 USB RS-232

📦 封裝（Encapsulation）與解封過程

資料從上層往下傳時，每一層都會加上自己的標頭（Header），這個過程叫封裝。到了對方後，從下往上把標頭一層一層剝掉，叫解封（Decapsulation）。

層加上什麼稱為內容
應用層 (L7-5)應用資料資料（Data）HTTP 請求、郵件內容等
傳輸層 (L4)TCP/UDP 標頭片段（Segment）來源/目的 Port、序號、ACK
網路層 (L3)IP 標頭封包（Packet）來源/目的 IP 位址、TTL
資料鏈路 (L2)乙太網路標頭 + 尾部訊框（Frame）來源/目的 MAC、EtherType、CRC
實體層 (L1)編碼為訊號位元（Bit）電壓高低、光脈衝
 
# 封裝後的實際大小（以 1 個 HTTP GET 為例）
應用資料：   "GET / HTTP/1.1\r\nHost: example.com\r\n\r\n"   約 40 bytes
TCP 標頭：   20 bytes（來源Port 55000, 目的Port 80, 序號, ACK...）
IP 標頭：    20 bytes（來源IP, 目的IP, TTL=64, Protocol=6...）
以太網標頭： 14 bytes（MAC×2, EtherType）+ 4 bytes CRC
總計：       約 98 bytes（原始 40 bytes 資料 + 58 bytes 標頭）
封裝的開銷（Overhead）讓每個封包都有額外的「空白」。這就是為什麼 1000Mbps 的網路實際吞吐量大約只有 950Mbps，小封包（如 VoIP）的有效載荷比例更低。

🔗 TCP/IP 四層 vs OSI 七層

實際網際網路使用的是 TCP/IP 模型，比 OSI 更簡化。

TCP/IP 四層對應 OSI 層主要協定
應用層OSI 5、6、7 層合併HTTP、FTP、DNS、DHCP、SSH、SMTP
傳輸層OSI 第 4 層TCP、UDP
網際網路層OSI 第 3 層IPv4、IPv6、ICMP、OSPF、BGP
網路存取層OSI 第 1、2 層合併Ethernet、Wi-Fi、PPP

⚖️ TCP vs UDP 完整對比

特性TCPUDP
連線方式面向連線（需要先三向交握）無連線（直接傳送）
可靠性保證送達（ACK 確認，遺失重傳）不保證（送出去就算）
順序保證按順序到達（序號機制）不保證順序
流量控制有（滑動視窗 Sliding Window）無
壅塞控制有（慢啟動、擁塞避免）無
速度較慢（有確認機制）較快（直接傳）
標頭大小20 bytes（最小）8 bytes
適合場景網頁、email、檔案傳輸（要求正確）VoIP、視訊直播、DNS 查詢（要求快速）
代表協定HTTP、FTP、SMTP、SSH、TelnetDNS、DHCP、TFTP、VoIP（RTP）、SNMP
TCP 比喻：掛號信。你寄出去，對方要簽收確認，如果沒收到會補寄，絕對保證送達，但比較慢。
UDP 比喻：廣播廣告。一次對所有人說，不知道誰有沒有聽到，也不管，但夠快。VoIP 晚 0.5 秒傳到比重傳還糟，所以用 UDP。

🤝 TCP 三向交握 + 四次揮手

三向交握（建立連線）

每一次 TCP 連線開始前，Client 和 Server 要先完成三步驟的「握手」，確認雙方都準備好了，也交換初始的序號（Sequence Number）。

Client（瀏覽器）
Step 1傳送 SYN
Seq=1000, SYN=1, ACK=0
「我想連線，我的起始序號是 1000」
Step 3傳送 ACK
Seq=1001, ACK=2001
「收到！連線建立，可以開始傳資料了」
→
SYN
←
SYN-ACK
→
ACK
Server（網站）
Step 2回應 SYN-ACK
Seq=2000, ACK=1001, SYN=1
「同意！我的序號是 2000，確認收到你的 1000」
連線建立，開始傳資料

四次揮手（斷開連線）

任何一方都可以主動關閉，但因為 TCP 是全雙工（雙向），所以雙方各要自己發一個 FIN 和收到對方的 ACK，共 4 次。

步驟方向說明
1Client → ServerFIN：「我沒有資料要傳了，想關閉」
2Server → ClientACK：「收到，但我可能還有資料要傳給你」
3Server → ClientFIN：「我也傳完了，可以關閉了」
4Client → ServerACK：「確認，等 2MSL 後正式關閉」
TIME_WAIT 狀態：Client 發完最後一個 ACK 後，要等 2MSL（Maximum Segment Lifetime，約 60-120 秒）才正式關閉，確保這個 ACK 有送到 Server。這就是為什麼關閉連線後，Port 不能立刻重用。

🚪 重要 Port 號速查

🔬 Wireshark 觀察實驗

理論要配合實際封包才能真正理解。Wireshark 是免費的封包分析工具，可以讓你親眼看到三向交握、IP 標頭、TCP 序號。

實驗步驟

  1. 下載並安裝 Wireshark（wireshark.org，完全免費）
  2. 選擇你的網路介面（通常是 Wi-Fi 或乙太網路）開始捕捉
  3. 在瀏覽器輸入任何 HTTP 網站（如 http://neverssl.com，這個網站故意不用 HTTPS）
  4. 在 Wireshark 過濾框輸入 tcp.port == 80，只看 HTTP 流量
  5. 找到三個 TCP 封包：SYN、SYN-ACK、ACK，分別點開看標頭
# Wireshark 常用過濾語法
ip.addr == 8.8.8.8          # 只看和 8.8.8.8 相關的封包
tcp.port == 80               # HTTP 流量
udp.port == 53               # DNS 查詢
tcp.flags.syn == 1           # 只看 SYN 封包（連線建立）
tcp.flags.fin == 1           # 只看 FIN 封包（連線關閉）
http                         # 只看 HTTP 封包
dns                          # 只看 DNS 查詢
