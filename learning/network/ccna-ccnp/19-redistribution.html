CH 6-3 · 路由政策

路由重分配與路由政策

公司併購、部門用不同路由協定、要把靜態路由丟進 OSPF——這些都會用到重分配。它是 CCNP 最容易做出災難的一項技術，而 Route Map 與 Prefix List 就是控制它的方向盤。

1. 什麼時候需要重分配

重分配就像兩家公司合併後的通訊錄整合——A 公司用 Excel、B 公司用 CRM，你要把兩邊的聯絡人互相同步。
問題在於：兩邊的欄位定義不一樣（A 的「重要度」是 1–5 分，B 的是「高中低」），同步時一定要決定怎麼換算。路由的 metric 就是那個換算不了的欄位。
企業併購一邊用 OSPF、一邊用 EIGRP，短期內不可能全部改造。
與外部互連內部 OSPF、對 ISP 跑 BGP，兩邊要交換路由。
靜態路由入動態VPN 隧道、預設路由要讓全網知道。
協定遷移過渡從 EIGRP 換到 OSPF 的過程中，兩者並存一段時間。
重分配的核心觀念：不同路由協定的 metric 完全無法互相換算。
OSPF 的 cost 依頻寬算、EIGRP 的 metric 綜合頻寬與延遲、RIP 用跳數、BGP 用一堆屬性。
所以重分配時必須人為指定一個「種子度量（seed metric）」——等於告訴新協定「這些外來的路由，你就當成 X 分」。

2. 種子度量：不設會出事

重分配「進入」的協定預設種子度量結果
OSPF20（來自 BGP 是 1）有預設值，能運作
EIGRP無限大（infinity）路由被視為不可達，完全不會出現在路由表
RIP無限大同上，路由消失
BGPIGP 的 metric能運作
IS-IS0能運作
這是初學者最常遇到的「設定看起來對，但路由就是不出現」。
往 EIGRP 或 RIP 重分配時，沒有指定 metric 就等於指定了無限大，路由器認為那些路由不可達，直接丟掉。
OSPF 有預設值 20，所以往 OSPF 重分配「看起來會動」——這反而讓人以為所有協定都一樣，換成 EIGRP 就踩坑。
養成習慣：不管往哪個協定重分配，都明確指定 metric。
! ── 往 EIGRP 重分配一定要給 metric（五個參數）──
R1(config)# router eigrp 100
R1(config-router)# redistribute ospf 1 metric 100000 100 255 1 1500
                                          ! 頻寬  延遲 可靠度 負載 MTU

! 或用 default-metric 一次設定所有重分配來源
R1(config-router)# default-metric 100000 100 255 1 1500
R1(config-router)# redistribute ospf 1

! ── 往 OSPF 重分配（有預設值,但仍建議明確指定）──
R1(config)# router ospf 1
R1(config-router)# redistribute eigrp 100 subnets metric 100 metric-type 1
                                        ! subnets 一定要加,見下方陷阱
OSPF 重分配忘記加 subnets：只有主類別網路會被帶進來。
沒加這個關鍵字，只有等長於預設類別遮罩的網路（如 10.0.0.0/8、192.168.1.0/24）會被重分配，所有切過子網路的網段（10.1.1.0/24）全部被丟掉。
症狀非常典型：「有些網段通、有些不通」，而不通的剛好都是切過子網路的。
新版 IOS 已經預設加上，但考題與舊設備仍會考這一點。

OSPF 外部路由的兩種型別

E1（metric-type 1）E2（metric-type 2，預設）
cost 怎麼算種子度量 + 沿途累加的內部 cost只有種子度量，不累加
選路影響離入口越遠 cost 越高，會選最近的入口不管多遠 cost 都一樣，可能選到繞遠路的入口
適用有多個重分配入口時，想讓流量走最近的只有單一入口，或不在意路徑
選路順序：E1 永遠優於 E2（不管 cost 多少）。
考題常見情境：「兩個 ASBR 都重分配同一條路由，為什麼所有流量都跑去遠的那台？」——因為用了預設的 E2，cost 都一樣，路由器就照其他規則挑。改成 E1 就會依實際距離選最近的入口。

3. 實作一：基本重分配

情境：併購後,A 網域跑 OSPF、B 網域跑 EIGRP OSPF Area 0 R1 EIGRP AS 100 10.1.0.0/16 ───── （邊界路由器） ───── 10.2.0.0/16 兩邊都要重分配
! ═══ R1：雙向重分配 ═══

! ── OSPF 的路由 → 進入 EIGRP ──
R1(config)# router eigrp 100
R1(config-router)# redistribute ospf 1 metric 1000000 10 255 1 1500

! ── EIGRP 的路由 → 進入 OSPF ──
R1(config)# router ospf 1
R1(config-router)# redistribute eigrp 100 subnets metric 100 metric-type 1

! ── 驗證：在對側路由器上看 ──
R2# show ip route ospf
      ! O E1 10.2.1.0/24 [110/110] via ... ← E1 外部路由
R3# show ip route eigrp
      ! D EX 10.1.1.0/24 [170/...] via ...  ← EX 代表外部,AD 是 170 不是 90
路由表代號要認得：
O = OSPF 內部｜O IA = 跨區域｜O E1 / O E2 = 外部（重分配進來的）
D = EIGRP 內部（AD 90）｜D EX = EIGRP 外部（AD 170）
看到 E 或 EX 就代表這條路由是從別的協定重分配進來的——排錯時這是第一個線索。

4. 路由迴圈與次佳路徑（核心）

單點重分配很安全，雙點重分配會出事。這是這一章最重要的觀念，也是 CCNP 考試的核心考點。
雙點雙向重分配的災難 OSPF 網域 EIGRP 網域 ┌─── R1 ───┐ 10.1.1.0/24 │ │ ●────────┤ ├──────── 10.2.2.0/24 │ │ └─── R2 ───┘ 10.1.1.0/24 原本是 OSPF 的路由（AD 110） 1. R1 把它重分配進 EIGRP 2. R2 從 EIGRP 學到它,AD 170... 但等等 3. R2 又把它重分配回 OSPF 4. R1 從 OSPF 學到「外部的 10.1.1.0/24」 結果：路由繞圈,或選到次佳路徑（明明就在隔壁卻繞了一大圈）

為什麼 AD 值救不了你

直覺會想：「OSPF 的 AD 是 110，EIGRP 外部是 170，OSPF 比較優先，應該不會有問題吧？」
問題出在 EIGRP 內部路由的 AD 是 90，比 OSPF 的 110 更優先。所以在 EIGRP 網域裡，一條「原本屬於 OSPF、被重分配進來、再被當成內部路由傳播」的路由，可能會壓過真正的 OSPF 路由。
這種「路由回頭」造成的次佳路徑，在網路正常時可能看不出來，直到某條線路斷掉才爆發——而且非常難查。

三種防護手段

① 路由標籤（Tag）最推薦。重分配出去時打上標籤，重分配回來時拒絕帶有該標籤的路由。一次設定，之後新增網段都自動生效。
② 過濾（Prefix List）明確列出允許或拒絕哪些網段。精確但每次新增網段都要改設定，容易遺漏。
③ 調整 AD 值用 distance 讓外部路由的 AD 變差。可行但影響範圍大、副作用難預期，是最後手段。
標準做法就是「打標籤 + 擋標籤」，四行設定解決： 
! 在 R1 與 R2 上都做同樣的事

! ① 定義：拒絕帶有標籤 100 的路由,其餘允許並打上標籤 100
route-map OSPF-TO-EIGRP deny 10
 match tag 100
route-map OSPF-TO-EIGRP permit 20
 set tag 100

! ② 套用在重分配上
router eigrp 100
 redistribute ospf 1 metric 1000000 10 255 1 1500 route-map OSPF-TO-EIGRP
邏輯：從 OSPF 進 EIGRP 的路由都蓋章「100」；當這條路由繞了一圈想從另一台再進來時，因為身上有章就被擋掉。路由不可能回到自己出發的網域。
企業實例｜某集團併購後的三個月排錯
A 公司（OSPF）併購 B 公司（EIGRP），兩地各有一台邊界路由器做雙向重分配（雙點）。上線後三個月一切正常。
某天南部機房的一條線斷了，結果台北到台中的流量竟然繞道高雄，延遲從 5ms 暴增到 45ms。查了兩天才發現：台中的網段有一條路由是「從 OSPF 出去、繞進 EIGRP、又被另一台重分配回 OSPF」的迴圈路由，平常因為 cost 較差不會被選中，線路一斷就浮上來變成最佳路徑。
修正：兩台邊界路由器都加上 tag 過濾（就是上面那四行），問題消失。
教訓：雙點重分配的問題在網路正常時不會出現，它會等到你最不希望出事的時候才爆。設計時就要防，不要等出事再查。

5. Prefix List：比 ACL 適合篩路由

ACL 也能過濾路由，但它只能比對網路位址，不能比對前綴長度。Prefix List 就是為了補這個缺口。

同樣要「只允許 10.1.0.0/16」 用 ACL： access-list 10 permit 10.1.0.0 0.0.255.255 → 10.1.0.0/16、10.1.1.0/24、10.1.1.128/25 全部都會通過 因為 ACL 根本不看遮罩長度 用 Prefix List： ip prefix-list PL permit 10.1.0.0/16 → 只有剛好 /16 的那一條會通過

語法與 ge / le

ip prefix-list 名稱 [seq 序號] {permit|deny} 網路/長度 [ge 最小長度] [le 最大長度]
寫法符合什麼
permit 10.1.0.0/16只有 10.1.0.0/16 這一條
permit 10.1.0.0/16 le 2410.1.0.0 開頭、前綴長度 16 到 24 之間
permit 10.1.0.0/16 ge 2410.1.0.0 開頭、前綴長度 24 到 32 之間
permit 10.1.0.0/16 ge 20 le 24長度在 20 到 24 之間
permit 0.0.0.0/0只有預設路由這一條
permit 0.0.0.0/0 le 32全部路由（等同 permit any）
三個必記的細節：
① 結尾有隱含的 deny any——跟 ACL 一樣，沒被明確允許的就被拒絕。
② ge 與 le 的值必須大於前面的前綴長度，且 ge ≤ le。
③ 「只有預設路由」與「全部路由」的寫法只差 le 32——這是考題最愛的一組，非常容易看錯。
! ── 常見用途：只讓預設路由與特定彙總進來 ──
R1(config)# ip prefix-list ALLOW-IN seq 5 permit 0.0.0.0/0
R1(config)# ip prefix-list ALLOW-IN seq 10 permit 10.0.0.0/8 le 16

! ── 套用在 BGP 鄰居上 ──
R1(config)# router bgp 65001
R1(config-router)# neighbor 203.0.113.2 prefix-list ALLOW-IN in

! ── 驗證 ──
R1# show ip prefix-list
R1# show ip prefix-list ALLOW-IN

6. Route Map：路由界的 if-then

Route Map 就是一連串的 if-then 規則，由上往下逐條比對，符合就執行動作然後停止，不符合就往下一條。
跟寫程式的 if / elif / else 完全一樣的邏輯。
route-map 名稱 {permit|deny} 序號
  match <條件>    ← if（可以有多個，同一行內是 OR，不同行是 AND）
  set <動作>      ← then
常用 match常用 set
match ip address prefix-list X
match ip address 10（ACL）
match tag 100
match metric 100
match interface g0/1
match route-type external
match as-path 1（BGP）
match community 1（BGP）		set metric 100
set metric-type type-1
set tag 100
set local-preference 200（BGP）
set as-path prepend 65001 65001（BGP）
set community 100:1（BGP）
set ip next-hop 10.1.1.1（PBR）
四個關鍵規則（考題重災區）：
① 由上往下比對，符合第一條就停止——序號的順序決定一切。
② 結尾有隱含的 deny any——如果你只寫了 permit 10，其他全部會被拒絕。要放行其餘一定要補一條空的 route-map X permit 999。
③ 只有 match 沒有 set = 符合的就通過，不修改任何屬性。
④ 只有 set 沒有 match = 所有路由都符合，全部套用這個動作。這是「打標籤給全部」的寫法。
⑤ deny 的條目裡寫 set 沒有意義——被 deny 的路由根本不會被處理。
讀懂這段 Route Map
route-map FILTER deny 10
 match tag 100

route-map FILTER permit 20
 match ip address prefix-list SERVERS
 set metric 50
 set tag 200

route-map FILTER permit 30
 set tag 200

逐條翻譯：
序號 10：如果路由帶著標籤 100 → 拒絕（擋掉，不再往下比）
序號 20：如果路由符合 SERVERS 這個 prefix-list → 允許，並把 metric 設成 50、標籤設成 200
序號 30：其餘全部允許（沒有 match 代表全部符合），並打上標籤 200

如果沒有序號 30 會怎樣？因為隱含的 deny any，除了 SERVERS 之外的路由全部會被擋掉——這是最常見的災難性設定錯誤。

7. 實作二：用 Route Map 控制重分配

需求 1. 只把 10.1.0.0/16 底下的 /24 網段重分配進 EIGRP 2. 這些路由打上標籤 100（防止繞回來） 3. 拒絕任何已經帶著標籤 100 的路由（防迴圈） 4. 伺服器網段 10.1.99.0/24 要有更好的 metric
! ── 步驟 1：定義 Prefix List ──
R1(config)# ip prefix-list LAN-NETS seq 5 permit 10.1.0.0/16 ge 24 le 24
R1(config)# ip prefix-list SERVERS seq 5 permit 10.1.99.0/24

! ── 步驟 2：定義 Route Map ──
R1(config)# route-map TO-EIGRP deny 10
R1(config-route-map)# match tag 100          ! 防迴圈：擋掉繞回來的

R1(config)# route-map TO-EIGRP permit 20
R1(config-route-map)# match ip address prefix-list SERVERS
R1(config-route-map)# set metric 10000000 10 255 1 1500   ! 伺服器給好一點的 metric
R1(config-route-map)# set tag 100

R1(config)# route-map TO-EIGRP permit 30
R1(config-route-map)# match ip address prefix-list LAN-NETS
R1(config-route-map)# set metric 1000000 100 255 1 1500
R1(config-route-map)# set tag 100

! 注意：這裡「沒有」第四條 permit,代表其餘路由一律不重分配
! 這是刻意的——我們只想放出 LAN 網段

! ── 步驟 3：套用 ──
R1(config)# router eigrp 100
R1(config-router)# redistribute ospf 1 route-map TO-EIGRP

! ── 驗證 ──
R1# show route-map TO-EIGRP        ! 看每條規則命中幾次（很有用）
R2# show ip route eigrp
R2# show ip route 10.1.99.0        ! 確認 tag 與 metric
show route-map 是排錯的利器。它會顯示每一條規則被命中的次數（Policy routing matches 或 matches）。
命中次數是 0 → 這條規則的 match 條件寫錯了，或前面的規則先攔截了。
路由沒出現但規則有命中 → 問題在 set 的 metric 或協定端。
這一個指令可以省下大量猜測時間。

8. PBR：不照路由表走

政策路由（Policy-Based Routing）讓你依「來源 IP、協定、埠號」等條件決定封包走哪條路，而不是只看目的地位址。

典型情境：兩條對外線路,依用途分流 ┌──── 專線（貴、穩） ──── ISP-A 內網 ── R1 ──┤ └──── 寬頻（便宜、不穩） ── ISP-B 正常路由表只會依「目的地」選一條路。 PBR 可以做到： • 財務部（10.1.10.0/24）的流量 → 走專線 • 其他部門的一般上網 → 走寬頻 • VoIP 流量（依 DSCP 判斷） → 一律走專線
! ── 步驟 1：用 ACL 定義「感興趣的流量」──
R1(config)# access-list 110 permit ip 10.1.10.0 0.0.0.255 any   ! 財務部

! ── 步驟 2：Route Map 指定下一跳 ──
R1(config)# route-map PBR-FINANCE permit 10
R1(config-route-map)# match ip address 110
R1(config-route-map)# set ip next-hop 203.0.113.1       ! 專線的下一跳

R1(config)# route-map PBR-FINANCE permit 20      ! 其餘走正常路由表

! ── 步驟 3：套在「流量進來的介面」上（不是出口！）──
R1(config)# interface gigabitEthernet 0/0
R1(config-if)# ip policy route-map PBR-FINANCE

! ── 驗證 ──
R1# show ip policy
R1# show route-map PBR-FINANCE
R1# debug ip policy            ! 正式環境慎用
PBR 的三個經典錯誤：
① 套錯介面——要套在流量進來的介面（inbound），不是出去的介面。這是最常見的錯誤。
② 忘了放行其餘流量——route-map 有隱含 deny any，但 PBR 的行為是「不符合的就照正常路由表走」，所以通常沒事；不過若寫了明確的 deny 條目就要小心。
③ 路由器自己發出的封包不受 PBR 影響——PBR 處理的是經過路由器的流量。要對本機流量套用要用 ip local policy route-map。
企業實例｜某設計公司的雙線分流
公司有一條 100M 專線（月租高）與一條 500M 光纖寬頻（便宜）。原本全部走專線，尖峰時段設計師上傳大型檔案把頻寬吃光，導致視訊會議斷斷續續。
用 PBR 分流：① 視訊會議與雲端 ERP 的流量（依目的地網段與 DSCP）→ 專線；② 一般上網與大檔上傳 → 寬頻；③ 專線斷線時，用 IP SLA 追蹤自動讓 PBR 失效並全部回落到寬頻。
成效：視訊會議品質問題完全消失，而且沒有增加任何頻寬費用。
設計重點：PBR 一定要搭配 IP SLA + track，否則指定的下一跳掛掉時，封包會被送進黑洞——PBR 本身不會偵測下一跳是否可達，這是它跟正常路由最大的差別，也是最危險的地方。

實作 Lab：雙點重分配與防迴圈

約 60 分鐘。這個 Lab 的價值在於親眼看到迴圈發生，再親手修好。

OSPF Area 0 EIGRP AS 100 ┌── R1 ──┐ R4 ── 10.1.1.0/24 ┤ ├ 10.2.2.0/24 ── R5 └── R2 ──┘

階段一：先讓兩邊各自跑起來

  1. R4、R1、R2 之間跑 OSPF；R5、R1、R2 之間跑 EIGRP
  2. 確認 OSPF 鄰居與 EIGRP 鄰居都建立起來
  3. 此時兩個網域還不通，這是正常的

階段二：做出問題（重要）

  1. 在 R1 與 R2 上都做雙向重分配，先不加任何過濾
  2. 在 R4 上 show ip route，找出 10.2.2.0/24 的路徑
  3. 在 R5 上 show ip route，找出 10.1.1.0/24 的路徑
  4. 觀察是否有網段學到了「繞遠路」的路徑，或路由在兩條之間跳動
  5. 把 R1 的其中一個介面 shutdown，觀察路由收斂後有沒有出現不合理的路徑
沒看到問題也很正常——迴圈與次佳路徑是否浮現，取決於拓撲與 metric 的組合。這正是雙點重分配可怕的地方：它可能潛伏很久。所以不管有沒有看到問題，下一階段的防護都要做。

階段三：加上 tag 防護

  1. 在 R1 與 R2 上都建立兩個 route-map（OSPF→EIGRP 用 tag 100、EIGRP→OSPF 用 tag 200）
  2. 每個 route-map 的第一條都是 deny + match tag（擋掉對向的標籤）
  3. 第二條 permit + set tag
  4. 套用到重分配指令上
  5. 用 show ip route 10.1.1.0 確認路由上有正確的 tag
  6. 再做一次階段二的斷線測試，確認路徑合理

階段四：Prefix List 與 Route Map 練習

  1. 寫一個 prefix-list 只允許 10.1.0.0/16 ge 24 le 24，套進重分配
  2. 在 R5 上驗證只有 /24 的網段進來了
  3. 用 show route-map 觀察各條規則的命中次數
  4. 故意把 route-map 的最後一條 permit 拿掉，觀察所有路由都消失——親身體會隱含 deny any 的威力

10. 考試陷阱整理

陷阱 1：往 EIGRP / RIP 重分配沒給 metric
預設是無限大，路由直接消失。OSPF 有預設值 20，所以「往 OSPF 做會動、往 EIGRP 做不會動」讓很多人困惑。
陷阱 2：OSPF 重分配忘記加 subnets
只有主類別網路會進來，所有切過子網路的網段消失。症狀是「有些網段通、有些不通」。
陷阱 3：E1 與 E2 搞混
E1 會累加沿途 cost（多入口時會選最近的）；E2 不累加（預設，cost 都一樣）。E1 永遠優於 E2。
陷阱 4：雙點重分配不做防護
會產生迴圈或次佳路徑，而且平常看不出來，斷線時才爆。標準做法是 tag + 擋 tag。
陷阱 5：Route Map 忘記最後一條 permit
隱含 deny any 會把其餘路由全部擋掉。要放行其餘必須補一條空的 permit 999。
陷阱 6：Prefix List 的 0.0.0.0/0 與 0.0.0.0/0 le 32
前者只有預設路由，後者全部路由。只差三個字，意思完全相反。
陷阱 7：以為 ACL 能篩前綴長度
ACL 不看遮罩長度，10.1.0.0/16 的 ACL 會連 /24、/25 一起放行。要精確控制前綴長度只能用 Prefix List。
陷阱 8：PBR 套在出口介面
要套在流量進來的介面。另外路由器自己產生的封包不受 PBR 影響，那要用 ip local policy。
陷阱 9：PBR 沒搭配 IP SLA
PBR 不會偵測下一跳是否可達。指定的下一跳掛掉時封包會進黑洞，必須搭配 set ip next-hop verify-availability 或 track。
💡一句話記憶：
重分配一定要給 metric，往 OSPF 一定要加 subnets；
雙點重分配一定要打標籤，Route Map 一定要補最後一條 permit；
要篩前綴長度只能用 Prefix List，PBR 一定要配 IP SLA。
