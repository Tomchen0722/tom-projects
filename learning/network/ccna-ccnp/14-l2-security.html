二層資安防護：DHCP Snooping / DAI / 802.1X

防火牆擋的是從外面進來的攻擊。但如果攻擊者已經在你的辦公室插了一條網路線，防火牆完全看不到他。這一章處理內網的第一道防線——CCNA 資安領域的核心考點。

1. 為什麼二層特別脆弱

大樓的門禁做得很嚴，但一旦有人混進來，裡面的每一間辦公室都沒鎖。
二層網路就是這種狀態——OSI 第二層的協定（ARP、DHCP）設計於「網路裡的人都是好人」的年代，完全沒有身分驗證機制。
二層協定的先天問題 ARP ── 誰都可以宣稱「我是那個 IP」,沒有驗證 DHCP ── 誰都可以架一台 DHCP 伺服器發 IP STP ── 誰都可以發 BPDU 宣稱自己是 Root 攻擊者只要能插上一條線,就能： • 假冒閘道,把全網段流量導到自己身上（中間人） • 發假 IP 讓大家連不上網（阻斷服務） • 竊聽、竄改、注入流量 而防火牆在網段外面,對這些完全看不見。
這一章的四個機制是層層堆疊的，順序有意義：
802.1X（你是誰才能上線）→ DHCP Snooping（誰能發 IP）→ DAI（誰能宣稱這個 IP）→ IPSG（誰能用這個 IP 送封包）。
後三個都建立在 DHCP Snooping 的資料庫之上，所以 DHCP Snooping 是地基。

2. DHCP 欺騙與 DHCP Snooping

攻擊：DHCP Spoofing（假冒 DHCP 伺服器）
攻擊者在辦公室角落插一台筆電，開一個 DHCP 伺服器，把預設閘道設成自己。
因為 DHCP 是「誰先回應就用誰」，離得近的攻擊者常常贏過真正的伺服器。
結果：受害者的所有流量都先經過攻擊者 → 完整的中間人攻擊。

另一種：DHCP 耗竭（Starvation）——攻擊者用大量偽造 MAC 狂要 IP，把位址池抽乾，讓正常使用者拿不到 IP。
DHCP Snooping 的原理：把埠分成兩類 Trusted（信任埠） → 通往真正的 DHCP 伺服器或上層交換器 → 允許通過 DHCP 「伺服器端」訊息（OFFER、ACK） Untrusted（不信任埠,預設） → 接使用者的埠 → 只允許客戶端訊息（DISCOVER、REQUEST） → 收到 OFFER/ACK → 直接丟棄並把埠關掉 同時建立「綁定表」（Binding Table） 記錄每次合法配發: ┌──────────────┬────────────┬──────┬─────────┐ │ MAC │ IP │ VLAN │ 介面 │ ├──────────────┼────────────┼──────┼─────────┤ │ aabb.cc00.01 │ 10.1.1.50 │ 10 │ Gi1/0/5 │ └──────────────┴────────────┴──────┴─────────┘ 這張表是 DAI 和 IPSG 的資料來源
! 全域啟用,並指定要保護的 VLAN SW(config)# ip dhcp snooping SW(config)# ip dhcp snooping vlan 10,20 ! 上行埠設為信任（通往真正的 DHCP 伺服器） SW(config)# interface gi1/0/24 SW(config-if)# ip dhcp snooping trust ! 使用者埠限制每秒 DHCP 封包數,防耗竭 SW(config)# interface range gi1/0/1-20 SW(config-if-range)# ip dhcp snooping limit rate 10 ! 驗證 SW# show ip dhcp snooping SW# show ip dhcp snooping binding
陷阱：Option 82 導致 DHCP 失效
DHCP Snooping 預設會在轉發時插入 Option 82（記錄來源交換器與埠）。
但很多 DHCP 伺服器看到 giaddr 為 0 卻帶著 Option 82 的封包會直接丟棄——結果就是「開了 snooping 之後大家都拿不到 IP」。

兩個解法：
① 交換器上關掉插入：no ip dhcp snooping information option
② 或在 DHCP 伺服器端設定接受

這是實務上啟用 DHCP Snooping 最常見的翻車點。

3. ARP 欺騙與動態 ARP 檢查（DAI）

攻擊：ARP Spoofing / ARP Poisoning
ARP 沒有任何驗證機制。攻擊者只要持續廣播「192.168.1.254（閘道）的 MAC 是我」，
網段內所有電腦的 ARP 表就會被污染，流量全部送到攻擊者那裡。

這個攻擊極其容易執行——現成工具一行指令就能做，而且受害者完全無感。
它也是內網滲透最常用的第一步。
DAI 的原理 攔截所有 ARP 封包,拿去比對 DHCP Snooping 綁定表 ARP 說：「10.1.1.50 的 MAC 是 aabb.cc00.01」 ↓ 查表:10.1.1.50 ←→ aabb.cc00.01 在 Gi1/0/5 ✓ 相符 → 放行 ARP 說：「10.1.1.254 的 MAC 是 dead.beef.0001」 ↓ 查表:綁定表裡沒有這組 ✗ → 丟棄 + 記錄 + 可關埠 埠的信任狀態 Untrusted（使用者埠）→ 要檢查 Trusted（上行埠） → 不檢查,直接放行 上行埠一定要設 trust,否則交換器之間的 ARP 全被擋掉
! 對指定 VLAN 啟用 SW(config)# ip arp inspection vlan 10,20 ! 上行埠設信任 SW(config)# interface gi1/0/24 SW(config-if)# ip arp inspection trust ! 靜態 IP 的裝置(印表機、伺服器)沒有 DHCP 紀錄 ! 要手動建立 ARP ACL,否則會被擋 SW(config)# arp access-list STATIC-HOSTS SW(config-arp-nacl)# permit ip host 10.1.1.100 mac host aabb.cc00.0099 SW(config)# ip arp inspection filter STATIC-HOSTS vlan 10 ! 驗證 SW# show ip arp inspection SW# show ip arp inspection statistics
陷阱：DAI 依賴 DHCP Snooping
DAI 比對的是 DHCP Snooping 建立的綁定表。沒有先開 DHCP Snooping，DAI 就沒有依據，所有 ARP 都會被判定為非法——整個網段直接癱瘓。

順序一定是：先 DHCP Snooping → 等綁定表建立 → 再開 DAI。
而且靜態 IP 的裝置一定要先用 ARP ACL 放行，否則印表機、伺服器全部不通。

4. IP Source Guard

DAI 管的是「你能不能宣稱這個 IP」，IPSG 管的是「你能不能用這個 IP 送封包」。

攻擊：IP Spoofing（來源位址偽造）
攻擊者把自己的來源 IP 改成別人的，用來繞過以 IP 為基礎的 ACL、或讓攻擊流量看起來來自無辜的主機。
IPSG 的原理 在埠上動態建立過濾規則（依 DHCP Snooping 綁定表） Gi1/0/5 的綁定:10.1.1.50 / aabb.cc00.01 ↓ 從 Gi1/0/5 進來的封包 來源 IP = 10.1.1.50 ✓ 放行 來源 IP = 10.1.1.99 ✗ 丟棄 加上 port-security 還能一併驗 MAC
SW(config)# interface range gi1/0/1-20 SW(config-if-range)# ip verify source ! 只驗 IP SW(config-if-range)# ip verify source port-security ! IP + MAC 都驗 ! 靜態 IP 裝置要手動綁 SW(config)# ip source binding aabb.cc00.0099 vlan 10 10.1.1.100 interface gi1/0/8 SW# show ip verify source
Port Security管 MAC——這個埠允許幾個、哪些 MAC。（第 04 章已教）
DHCP Snooping管 誰能發 IP，並建立綁定表。
DAI管 ARP 宣告是否與綁定表相符。
IPSG管 來源 IP 是否與綁定表相符。

5. 802.1X：連上線之前先驗身分

前面四個機制都是「先讓你上線，再限制你能做什麼」。802.1X 更前面一步——驗證通過之前，這個埠根本不通。

802.1X 的三個角色 Supplicant（請求者） = 使用者的裝置,內建 802.1X 用戶端 │ │ EAPOL（EAP over LAN） ↓ Authenticator（驗證者） = 交換器。它只是傳話的,不做判斷 │ │ RADIUS ↓ Authentication Server（驗證伺服器） = RADIUS 伺服器（Cisco ISE、Windows NPS、FreeRADIUS） = 真正決定放不放行的人 驗證前 vs 驗證後 驗證前:埠只放行 EAPOL,其他流量全擋 驗證後:埠打開,還可由 RADIUS 動態指派 VLAN 與 ACL
埠模式行為用途
force-authorized永遠放行（預設）等於沒開 802.1X
force-unauthorized永遠拒絕停用的埠
auto要驗證才放行正式使用的設定
! RADIUS 伺服器 SW(config)# radius server ISE SW(config-radius-server)# address ipv4 10.1.1.10 auth-port 1812 acct-port 1813 SW(config-radius-server)# key R4d1usK3y SW(config)# aaa new-model SW(config)# aaa authentication dot1x default group radius SW(config)# aaa authorization network default group radius SW(config)# dot1x system-auth-control ! 埠上啟用 SW(config)# interface gi1/0/5 SW(config-if)# switchport mode access SW(config-if)# authentication port-control auto SW(config-if)# dot1x pae authenticator ! 沒有 802.1X 用戶端的裝置(印表機、IP 電話)改用 MAC 驗證 SW(config-if)# mab SW# show dot1x interface gi1/0/5 details SW# show authentication sessions
陷阱：不是所有裝置都支援 802.1X
印表機、IP 攝影機、門禁讀卡機這類裝置通常沒有 802.1X 用戶端。
解法有兩個：
• MAB（MAC Authentication Bypass）——改用 MAC 位址當帳號向 RADIUS 驗證。安全性較低（MAC 可偽造），但實務上必要。
• Guest VLAN——驗證失敗的裝置丟進一個只能上網、碰不到內網的 VLAN。

企業導入 802.1X 最大的工作量不是設定交換器，是盤點「有哪些裝置驗證不過」。建議先用 monitor 模式（只記錄不阻擋）跑一兩個月，把清單整理出來再正式啟用。

6. 整體防護堆疊

一個接入埠應該有的完整防護 ┌─ 802.1X / MAB ──── 你是誰?不是自己人不給上線 │ ├─ Port Security ──── 這個埠只准 N 個 MAC │ ├─ DHCP Snooping ──── 你不能假扮 DHCP 伺服器 │ ├─ DAI ─────────────── 你不能宣稱別人的 IP │ ├─ IP Source Guard ── 你不能用別人的 IP 送封包 │ └─ BPDU Guard ──────── 你不能宣稱自己是 STP Root （第 06 章已教） 層層堆疊,每一層擋一種攻擊手法。 缺任何一層,對應的攻擊就有機會成功。
✅ 導入順序的實務建議：
① BPDU Guard + Port Security——風險最低，先做
② DHCP Snooping——注意 Option 82 的坑
③ DAI——確認綁定表已建立、靜態裝置已加 ARP ACL
④ IPSG——同樣要處理靜態綁定
⑤ 802.1X——最後做，因為要先盤點裝置、建 RADIUS

每一步都先在一個測試 VLAN 跑過再推全網。

7. 實作：完整的接入層安全設定

1
先建立地基（DHCP Snooping）
SW(config)# ip dhcp snooping SW(config)# ip dhcp snooping vlan 10 SW(config)# no ip dhcp snooping information option ! 避開 Option 82 的坑 SW(config)# interface gi1/0/24 SW(config-if)# description === 上行到核心 === SW(config-if)# ip dhcp snooping trust
2
等綁定表建立，確認有資料才往下做
SW# show ip dhcp snooping binding MacAddress IpAddress Lease(sec) Type VLAN Interface ----------------- ------------ ---------- ------------- ---- --------- AA:BB:CC:00:00:01 10.1.1.50 86400 dhcp-snooping 10 Gi1/0/5 ! 沒看到資料就不要開 DAI,會全斷
3
處理靜態 IP 裝置
! 印表機是固定 IP,沒有 DHCP 紀錄,要先放行 SW(config)# arp access-list STATIC SW(config-arp-nacl)# permit ip host 10.1.1.100 mac host aabb.cc00.0099 SW(config)# ip arp inspection filter STATIC vlan 10 SW(config)# ip source binding aabb.cc00.0099 vlan 10 10.1.1.100 interface gi1/0/8
4
開啟 DAI 與 IPSG
SW(config)# ip arp inspection vlan 10 SW(config)# interface gi1/0/24 SW(config-if)# ip arp inspection trust SW(config)# interface range gi1/0/1-20 SW(config-if-range)# ip verify source port-security SW(config-if-range)# ip arp inspection limit rate 15
5
加上 Port Security 與 BPDU Guard
SW(config)# interface range gi1/0/1-20 SW(config-if-range)# switchport mode access SW(config-if-range)# switchport port-security SW(config-if-range)# switchport port-security maximum 2 ! 電腦 + IP 電話 SW(config-if-range)# switchport port-security violation restrict SW(config-if-range)# switchport port-security mac-address sticky SW(config-if-range)# spanning-tree portfast SW(config-if-range)# spanning-tree bpduguard enable
6
驗證與監看
SW# show ip dhcp snooping SW# show ip arp inspection statistics SW# show ip verify source SW# show port-security SW# show errdisable recovery ! 建議設定自動恢復,避免誤觸要人工去開 SW(config)# errdisable recovery cause bpduguard SW(config)# errdisable recovery cause psecure-violation SW(config)# errdisable recovery interval 300
正式環境務必先用 restrict 而非 shutdown。
violation shutdown 會把埠關進 err-disabled，要人工去開。導入初期誤判很常見，用 restrict（丟棄違規流量但埠仍通）加上告警，觀察一段時間再收緊。

8. 考試陷阱整理

陷阱 1：DAI 與 IPSG 都依賴 DHCP Snooping
沒有綁定表就沒有比對依據。順序永遠是 DHCP Snooping 先。
陷阱 2：上行埠一定要 trust
DHCP Snooping 與 DAI 的上行埠都要設 trust，否則交換器之間的正常流量會被擋。
陷阱 3：靜態 IP 裝置要手動綁定
沒有 DHCP 紀錄的裝置，DAI 要 ARP ACL、IPSG 要 ip source binding。
陷阱 4：802.1X 的三個角色
Supplicant（裝置）、Authenticator（交換器）、Authentication Server（RADIUS）。交換器不做判斷，只轉送。
陷阱 5：沒有 802.1X 用戶端的裝置用 MAB
印表機、IP 電話 → MAB 或 Guest VLAN。
陷阱 6：Option 82
「開了 DHCP Snooping 後大家拿不到 IP」→ 想 Option 82。
陷阱 7：分清楚各機制管什麼
Port Security 管 MAC 數量、DAI 管 ARP 宣告、IPSG 管 來源 IP、802.1X 管 身分。
✅ 一句話記憶：
假冒發 IP 的人 → DHCP Snooping
假冒別人的 MAC-IP 對應 → DAI
假冒來源 IP → IP Source Guard
根本不該上線的人 → 802.1X
