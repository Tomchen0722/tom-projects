🏨 DHCP — 動態主機設定協定

DHCP 讓設備自動取得 IP 位址、子網路遮罩、預設閘道、DNS 伺服器四項資訊，不需要人工設定。企業環境中 99% 的用戶端設備都用 DHCP。

比喻：飯店 Check-in。你不用自己挑房號，櫃檯（DHCP Server）分配一間空房（IP）給你，並告訴你電梯在哪（Gateway）、餐廳分機幾號（DNS）。退房後房間回收給下一位客人（Lease 到期釋放）。

DORA 四步驟（考試必背）

D
Discover — 客戶端廣播尋找
剛開機的電腦沒有 IP，用來源 0.0.0.0 向 255.255.255.255 廣播「有 DHCP Server 嗎？」。這是 UDP 封包，來源 Port 68，目的 Port 67。
Src: 0.0.0.0:68 → Dst: 255.255.255.255:67　| 廣播
O
Offer — 伺服器提供 IP
DHCP Server 從位址池挑一個未使用的 IP，連同遮罩、閘道、DNS、租約時間一起回覆。如果有多台 DHCP Server，客戶端會收到多個 Offer。
Src: 192.168.1.1:67 → Dst: 255.255.255.255:68　| 含 IP + Mask + GW + DNS
R
Request — 客戶端正式請求
客戶端選定其中一個 Offer（通常是第一個收到的），再次廣播宣告「我要用 192.168.1.100，是 A 伺服器給的」。廣播的目的是讓其他 DHCP Server 知道它們的 Offer 被拒絕，可以把 IP 收回位址池。
Src: 0.0.0.0:68 → Dst: 255.255.255.255:67　| 廣播，含選定的 Server ID
A
Acknowledge — 伺服器確認
Server 確認分配，記錄租約（Lease）到資料庫。客戶端收到後才正式設定 IP，並開始計算租約時間。
Src: 192.168.1.1:67 → Dst: 255.255.255.255:68　| 租約成立

租約續約（Renewal）機制

時間點行為說明
T1（50% 租約）單播續約給原 Server例如租約 8 天，第 4 天直接跟原 Server 要求延長
T2（87.5% 租約）廣播續約給任何 Server原 Server 沒回應，第 7 天改用廣播找任何 Server
100%放棄 IP，重新 DORA沒續約成功，IP 失效，回到 Discover

Cisco Router 當 DHCP Server

# 步驟 1：排除不要分配的 IP（通常是伺服器和網路設備）
Router(config)# ip dhcp excluded-address 192.168.10.1 192.168.10.20
Router(config)# ip dhcp excluded-address 192.168.10.250 192.168.10.254

# 步驟 2：建立位址池
Router(config)# ip dhcp pool SALES_POOL
Router(dhcp-config)# network 192.168.10.0 255.255.255.0
Router(dhcp-config)# default-router 192.168.10.1      # 預設閘道
Router(dhcp-config)# dns-server 8.8.8.8 8.8.4.4        # DNS 伺服器
Router(dhcp-config)# domain-name company.local
Router(dhcp-config)# lease 7                          # 租約 7 天

# 步驟 3：驗證
Router# show ip dhcp binding          # 已分配的 IP 清單
Router# show ip dhcp pool             # 位址池使用狀況
Router# show ip dhcp conflict         # IP 衝突紀錄
Router# debug ip dhcp server events   # 即時除錯（正式環境慎用）

DHCP Relay（跨網段轉發）

問題：DHCP Discover 是廣播，路由器預設不轉發廣播。所以如果 DHCP Server 在別的網段，客戶端拿不到 IP。
解法：在客戶端所在網段的路由器介面上設 ip helper-address，把廣播轉成單播送給指定的 Server。

# 客戶端在 192.168.20.0/24，DHCP Server 在 10.1.1.100
Router(config)# interface GigabitEthernet0/1
Router(config-if)# ip address 192.168.20.1 255.255.255.0
Router(config-if)# ip helper-address 10.1.1.100

# ip helper-address 預設也會轉發這幾種 UDP 廣播：
#   TFTP(69) DNS(53) Time(37) NetBIOS(137/138) TACACS(49) DHCP(67/68)
# 想關掉不需要的可以用 no ip forward-protocol udp
常見錯誤：ip helper-address 要設在客戶端所在的介面，不是靠近 Server 的介面。設錯位置是新手最常犯的錯。

📖 DNS — 網域名稱系統

DNS 把人類記得住的名字（google.com）翻譯成電腦用的 IP（142.250.1.14）。它是一個分散式階層資料庫，全球有 13 組根伺服器。

DNS 查詢的完整流程

# 你在瀏覽器輸入 www.example.com 時發生的事：

1. 檢查瀏覽器快取         → 有 → 直接用
2. 檢查作業系統快取       → 有 → 直接用（Windows: ipconfig /displaydns）
3. 檢查 hosts 檔案        → 有 → 直接用
4. 問本地 DNS Server（通常是 ISP 或 8.8.8.8）
   ↓ 如果本地 DNS 沒有快取，開始遞迴查詢：
5.   問根伺服器 (.)         → 回：「去問 .com 的伺服器」
6.   問 .com TLD 伺服器     → 回：「去問 example.com 的權威伺服器」
7.   問 example.com 權威伺服器 → 回：「www.example.com = 93.184.216.34」
8. 本地 DNS 快取結果並回傳給你
查詢類型誰做說明
遞迴查詢（Recursive）客戶端 → 本地 DNS「幫我查到底，直接給我答案」，本地 DNS 負責跑完全程
疊代查詢（Iterative）本地 DNS → 各層伺服器「我不知道，但你可以去問它」，一層一層問下去

DNS 紀錄類型（考試常考）

類型用途範例
A網域 → IPv4 位址example.com → 93.184.216.34
AAAA網域 → IPv6 位址example.com → 2606:2800:220:1:248:1893::
CNAME別名（指向另一個網域）www.example.com → example.com
MX郵件伺服器（含優先權）example.com → 10 mail.example.com
NS該網域的權威 DNS 伺服器example.com → ns1.example.com
PTR反解（IP → 網域）34.216.184.93.in-addr.arpa → example.com
TXT任意文字（SPF、DKIM、網域驗證）"v=spf1 include:_spf.google.com ~all"
SOA區域起始授權（序號、更新頻率）每個 Zone 必有一筆

實作：DNS 查詢與故障排除

# === Windows ===
nslookup google.com                 # 基本查詢
nslookup -type=MX gmail.com         # 查郵件伺服器
nslookup google.com 1.1.1.1         # 指定用 Cloudflare DNS
ipconfig /displaydns                # 顯示本機 DNS 快取
ipconfig /flushdns                  # 清除 DNS 快取（改 DNS 後必做）

# === Linux / macOS ===
dig google.com                      # 詳細查詢（推薦）
dig +trace google.com               # 顯示完整查詢路徑（從根開始）
dig -x 8.8.8.8                      # 反解查詢
host google.com                     # 簡易查詢

# === Cisco Router ===
Router(config)# ip domain-lookup              # 啟用 DNS 解析
Router(config)# ip name-server 8.8.8.8 8.8.4.4
Router(config)# ip domain-name company.local
Router(config)# ip host SERVER1 10.1.1.50       # 靜態對應（類似 hosts 檔）
Router# show hosts                            # 查看已知的主機名稱
實務技巧：如果在 Cisco 設備上打錯指令（例如打成 shwo），設備會誤以為那是主機名稱，開始做 DNS 查詢，卡住 30 秒。用 no ip domain-lookup 關掉就不會有這個困擾（Lab 環境必設）。

🔍 ARP — 位址解析協定

你有對方的 IP，但要傳訊框需要 MAC 位址。ARP 就是廣播問「誰是 192.168.1.1？把你的 MAC 告訴我」。

ARP 完整流程

# PC-A（192.168.1.10）要 ping PC-B（192.168.1.20），同一網段

1. PC-A 檢查自己的 ARP 快取表 → 沒有 192.168.1.20 的記錄
2. PC-A 廣播 ARP Request：
     來源 MAC: AA:AA:AA:AA:AA:AA
     目的 MAC: FF:FF:FF:FF:FF:FF（廣播）
     內容: "Who has 192.168.1.20? Tell 192.168.1.10"
3. 同網段所有設備都收到，只有 192.168.1.20 回應
4. PC-B 單播 ARP Reply：
     來源 MAC: BB:BB:BB:BB:BB:BB
     目的 MAC: AA:AA:AA:AA:AA:AA（單播回給 PC-A）
     內容: "192.168.1.20 is at BB:BB:BB:BB:BB:BB"
5. PC-A 記入 ARP 快取（預設保存 4 小時，Cisco 是 4 小時）
6. 現在可以組裝訊框並送出 ICMP Echo Request

跨網段時的 ARP

關鍵觀念：如果目的 IP 不在同一網段，PC 不會 ARP 目的 IP，而是 ARP 預設閘道的 MAC。因為封包要先送到路由器，由路由器負責後續轉發。
這是新手最容易搞混的地方：IP 位址是端到端不變的，MAC 位址是逐跳（hop-by-hop）改變的。

ARP 相關指令

# === Windows ===
arp -a                              # 顯示 ARP 快取表
arp -d *                            # 清除所有 ARP 快取（需管理員權限）
arp -s 192.168.1.1 aa-bb-cc-dd-ee-ff # 靜態綁定（防 ARP 欺騙）

# === Cisco ===
Router# show ip arp                    # 查看 ARP 表
Router# show ip arp 192.168.1.20       # 查特定 IP
Router# clear arp-cache                # 清除 ARP 快取
Router(config)# arp 192.168.1.50 aabb.ccdd.eeff arpa  # 靜態 ARP
Router(config-if)# arp timeout 300       # 修改老化時間（秒）

ARP 欺騙（ARP Spoofing）與防護

攻擊原理：攻擊者持續發送假的 ARP Reply，宣稱「我是預設閘道」，讓受害者把流量送給攻擊者，形成中間人攻擊（MITM）。ARP 沒有任何認證機制，任何人都可以宣稱自己是任何 IP。

# === 防護方法 1：Dynamic ARP Inspection（DAI）===
# 依 DHCP Snooping 資料庫驗證 ARP 封包的合法性
Switch(config)# ip dhcp snooping
Switch(config)# ip dhcp snooping vlan 10
Switch(config)# ip arp inspection vlan 10

# 信任的 Port（通往合法 DHCP Server 和上游 Switch）
Switch(config)# interface GigabitEthernet0/24
Switch(config-if)# ip dhcp snooping trust
Switch(config-if)# ip arp inspection trust

# 驗證
Switch# show ip arp inspection
Switch# show ip dhcp snooping binding

# === 防護方法 2：Port Security（限制每個 Port 的 MAC 數量）===
Switch(config-if)# switchport port-security
Switch(config-if)# switchport port-security maximum 2
Switch(config-if)# switchport port-security violation restrict
Switch(config-if)# switchport port-security mac-address sticky

🔄 NAT / PAT — 網路位址轉換

NAT 讓內部私有 IP 能存取網際網路。因為 IPv4 位址不夠用，NAT 成為必要技術。企業防火牆、家用路由器全都在做 NAT。

四個關鍵術語（考試必考）

術語意義範例
Inside Local內部設備的真實私有 IP192.168.1.10（PC 自己的 IP）
Inside Global內部設備對外呈現的公有 IP203.0.113.5（NAT 後的 IP）
Outside Local外部設備在內部看到的 IP通常和 Outside Global 相同
Outside Global外部設備的真實公有 IP8.8.8.8（Google DNS）
記憶技巧：Inside/Outside 指的是「這台設備在網路哪一邊」；Local/Global 指的是「從內部視角看還是從外部視角看」。

三種 NAT 完整設定

1. Static NAT（一對一固定對應）

用途：對外提供服務的伺服器，需要固定的公有 IP。

# 把內部 Web Server 192.168.1.100 固定對應到公有 IP 203.0.113.10
Router(config)# ip nat inside source static 192.168.1.100 203.0.113.10

# 指定介面角色（不設這兩行 NAT 不會生效！）
Router(config)# interface GigabitEthernet0/0
Router(config-if)# ip nat inside          # 連向內網的介面
Router(config)# interface GigabitEthernet0/1
Router(config-if)# ip nat outside         # 連向網際網路的介面

# 只轉發特定 Port（Port Forwarding / PAT 靜態）
Router(config)# ip nat inside source static tcp 192.168.1.100 80 203.0.113.10 80

2. Dynamic NAT（動態從位址池取）

# 建立公有 IP 位址池
Router(config)# ip nat pool PUBLIC_POOL 203.0.113.10 203.0.113.20 netmask 255.255.255.0

# 定義哪些內部 IP 可以做 NAT
Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255

# 綁定 ACL 和位址池
Router(config)# ip nat inside source list 1 pool PUBLIC_POOL

3. PAT / NAT Overload（多對一，最常用）

所有內部設備共用一個公有 IP，靠不同的 Port 號區分。這是家用路由器和大多數企業的做法。

# 方法 A：共用外部介面的 IP（最常見）
Router(config)# access-list 1 permit 192.168.0.0 0.0.255.255
Router(config)# ip nat inside source list 1 interface GigabitEthernet0/1 overload

# 方法 B：共用位址池（多個公有 IP 輪流用）
Router(config)# ip nat pool POOL2 203.0.113.10 203.0.113.12 netmask 255.255.255.248
Router(config)# ip nat inside source list 1 pool POOL2 overload

# 介面設定同上（inside / outside）

NAT 驗證與故障排除

# 查看目前的 NAT 轉換表（最重要的指令）
Router# show ip nat translations

Pro Inside global      Inside local       Outside local      Outside global
tcp 203.0.113.5:1024   192.168.1.10:52341 8.8.8.8:53         8.8.8.8:53
tcp 203.0.113.5:1025   192.168.1.11:49832 142.250.1.14:443   142.250.1.14:443
    ^^^^^^^^^^^^^^     ^^^^^^^^^^^^^^^^^^
    對外呈現的 IP:Port  內部真實 IP:Port    ← PAT 靠 Port 區分不同主機

# 查看 NAT 統計（轉換次數、命中率）
Router# show ip nat statistics

# 清除轉換表（改設定後必做）
Router# clear ip nat translation *

# 即時除錯（正式環境慎用，會拖慢設備）
Router# debug ip nat
Router# undebug all                   # 記得關掉
NAT 三大常見錯誤：
1. 忘記在介面上設 ip nat inside / ip nat outside — NAT 完全不會運作
2. ACL 用 deny 反向思考 — NAT 的 ACL 是「permit 的才做 NAT」，不是防火牆邏輯
3. 改了設定但沒 clear ip nat translation * — 舊的轉換記錄還在，看起來像沒生效

🔧 故障排除完整流程

「連不上網」是最常見的申告。用這個由下而上的流程逐層排查，不要亂猜。

# ═══ Layer 1：實體層 ═══
□ 網路線有插好嗎？Switch Port 燈有亮嗎？
Switch# show interfaces status                # 看 Port 是 connected 還是 notconnect
Router# show ip interface brief             # Status/Protocol 都要是 up

# ═══ Layer 2：資料鏈路層 ═══
□ MAC 位址學到了嗎？VLAN 對嗎？
Switch# show mac address-table
Switch# show vlan brief
Switch# show interfaces trunk

# ═══ Layer 3：網路層 ═══
□ 步驟 1：ping 自己（127.0.0.1）→ TCP/IP 堆疊正常？
□ 步驟 2：ping 自己的 IP → 網卡正常？
□ 步驟 3：ping 同網段其他主機 → Layer 2 通嗎？
□ 步驟 4：ping 預設閘道 → 到路由器通嗎？
□ 步驟 5：ping 外部 IP（8.8.8.8）→ 路由設定對嗎？
□ 步驟 6：ping 外部網域（google.com）→ 只有 DNS 有問題？

tracert 8.8.8.8                            # Windows：看在哪一跳斷掉
traceroute 8.8.8.8                         # Linux/Cisco

# ═══ 常見結論 ═══
ping IP 通 + ping 網域不通  → DNS 問題
ping 閘道通 + ping 外網不通 → 路由或 NAT 問題
ping 同網段不通            → VLAN 或實體層問題
ping 自己不通             → 網卡驅動或 TCP/IP 堆疊問題

🔬 Packet Tracer 實作 Lab

目標：建立一個完整的企業小型網路，包含 DHCP、DNS、NAT，並驗證每個協定的運作。

拓樸

[PC1] [PC2] ─── [Switch] ─── [Router] ─── [Internet Cloud] ─── [DNS Server 8.8.8.8]
 192.168.10.x (DHCP)         Gi0/0        Gi0/1
                          192.168.10.1   203.0.113.2

步驟

  1. 設定 Router 介面：Gi0/0 為 192.168.10.1/24，Gi0/1 為 203.0.113.2/30
  2. 設定 DHCP Pool：排除 .1 到 .10，池範圍 192.168.10.0/24，DNS 指向 8.8.8.8
  3. PC 設為 DHCP：觀察 PC 是否自動取得 IP，在 Simulation 模式下觀察 DORA 四個封包
  4. 設定 PAT：ACL permit 192.168.10.0/24，overload 到 Gi0/1
  5. 驗證：從 PC ping 8.8.8.8，在 Router 上執行 show ip nat translations 看到轉換記錄
  6. 觀察 ARP：PC1 ping PC2，用 Simulation 模式看 ARP Request 廣播和 Reply 單播
  7. 加分挑戰：把 DHCP Server 移到另一個網段，設定 ip helper-address 讓它仍然運作
