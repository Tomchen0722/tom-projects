IPv6 深入：位址、SLAAC 與 NDP

前面章節只在靜態路由與 ACL 順帶提過 IPv6。但官方大綱有整整一個區塊在考它，而且實務上行動網路與新建機房早就是雙堆疊。這一章把位址、自動組態與 NDP 一次講完。

1. 為什麼非學不可

IPv4 像是七碼的市話號碼——當年設計時覺得夠用一輩子，結果人口一多就號碼不夠，只好靠分機（NAT）硬撐。
IPv6 則是直接把號碼加長到讓每顆沙子都能有一個，從此不需要分機。
位址空間對比 IPv4 32 bits ≈ 43 億個位址 全球人口的一半都不夠 IPv6 128 bits ≈ 3.4 × 10³⁸ 個位址 地球上每平方公尺都能分到天文數字 實務上為什麼躲不掉： • 行動網路（4G/5G）核心早就是 IPv6-only,用 NAT64 回接 IPv4 • 雲端服務商的新區域預設雙堆疊 • 政府與大型標案常直接要求支援 IPv6 • IoT 裝置數量遠超 IPv4 能負擔的規模
CCNA 不會考你「背下 IPv6 的所有 RFC」，考的是四件事：位址縮寫、位址類型判別、SLAAC 與 DHCPv6 的差別、NDP 取代了誰。這四項掌握了，這個區塊的分數就穩了。

2. 位址結構與縮寫規則

128 bits = 8 組 × 每組 4 個十六進位字元（16 bits），用冒號分隔

2001:0DB8:0000:0000:0000:FF00:0042:8329

兩條縮寫規則

1
每組的前導零可以省略0DB8 → DB8；0000 → 0。注意是「前導」零，中間與結尾的零不能省——8329 不能寫成 839。
2
連續的全零組可用 :: 取代，但整個位址只能用一次如果有兩段連續零，只能縮其中一段（慣例縮較長的那段）。用兩次會讓對方無法還原中間各有幾組零。
縮寫練習（先自己做再看答案）
原始位址 縮寫結果 2001:0DB8:0000:0000:0000:FF00:0042:8329 2001:DB8::FF00:42:8329 FE80:0000:0000:0000:0204:61FF:FE9D:F156 FE80::204:61FF:FE9D:F156 0000:0000:0000:0000:0000:0000:0000:0001 ::1 （本機迴路） 0000:0000:0000:0000:0000:0000:0000:0000 :: （未指定位址） 2001:0DB8:0000:0001:0000:0000:0000:0001 2001:DB8:0:1::1 ← 注意這個 最後一個為什麼不能寫成 2001:DB8::1::1 ？ 因為 :: 只能出現一次。兩段零只能縮長的那段（後面三組）， 前面那組單獨的 0000 只能縮成 0。
考試陷阱：把中間或結尾的零也省掉
2001:0DB8:0000:0000:0000:FF00:0042:8329 中的 0042 縮成 42 是對的（前導零），但 8329 不能動。
另一個常見錯誤是把 2001:DB8:0:0:0:0:0:1 寫成 2001:DB8::0::1——兩個 :: 一定錯。

前綴表示法

IPv6 沒有子網路遮罩，一律用前綴長度：2001:DB8:1::/64。
實務慣例：網段一律切 /64（因為 SLAAC 需要 64 bits 的介面 ID），路由器對接的點對點鏈路可用 /127，Loopback 用 /128。
ISP 通常配給企業 /48（可切出 65,536 個 /64 網段），家用寬頻常見 /56 或 /60。

最重要的一句：IPv6 沒有廣播（Broadcast）。
所有原本靠廣播完成的事（ARP、DHCP 探索）都改用多播，只吵到真正需要的裝置。
考題最愛問「下列何者不是 IPv6 的位址類型」——答案就是 Broadcast。

Link-Local 為什麼這麼重要？因為 IPv6 的路由協定鄰居關係、NDP、預設閘道全部使用 Link-Local 位址通訊，而不是 Global 位址。
這代表：即使你還沒設定任何全球位址，只要介面啟用了 IPv6，同網段的裝置就已經可以互通。排錯時 show ipv6 interface brief 看到 FE80 開頭的位址就是它。

4. EUI-64：從 MAC 算出介面 ID

SLAAC 讓主機自己產生位址：前 64 bits 的網段前綴由路由器公告，後 64 bits 的介面 ID 自己算。EUI-64 就是最經典的算法。

1
把 48-bit 的 MAC 從中間切開前 24 bits（OUI 廠商碼）與後 24 bits（序號）。
2
中間插入 FFFE湊成 64 bits。
3
翻轉第 7 個 bit（U/L bit）0 變 1、1 變 0。實務上就是把第一個位元組的十六進位值加減 2。
手算範例
MAC 位址： 001A.2B3C.4D5E 步驟 1 切開： 001A2B | 3C4D5E 步驟 2 插 FFFE： 001A2B FFFE 3C4D5E 步驟 3 翻第 7 bit： 第一個位元組 00 = 0000 0000 ↑ 第 7 個 bit 翻轉後 02 = 0000 0010 結果介面 ID： 021A:2BFF:FE3C:4D5E 若網段前綴是 2001:DB8:1::/64,完整位址就是 2001:DB8:1:0:021A:2BFF:FE3C:4D5E/64 縮寫 → 2001:DB8:1:0:21A:2BFF:FE3C:4D5E/64
翻轉第 7 bit 的速算法：看第一個位元組的第二個十六進位數字——
偶數（0/2/4/6/8/A/C/E）就 +2；奇數就 −2。
00→02、0C→0E、1A→18、B4→B6。考試時這個技巧省很多時間。
實務注意：現代作業系統預設不用 EUI-64。
Windows、macOS、Linux 現在多半使用隨機產生的介面 ID（隱私延伸，RFC 4941），因為 EUI-64 會把 MAC 位址暴露在 IPv6 位址裡，可以被用來追蹤裝置。
但考試仍然會考 EUI-64 的手算，而且 Cisco 設備下 ipv6 address ... eui-64 時就是用這個算法。

5. NDP：取代 ARP 的四種訊息

IPv6 把 ARP 廢掉了，改用 NDP（鄰居探索協定），而 NDP 是跑在 ICMPv6 之上的。

訊息ICMPv6 型別做什麼取代 IPv4 的
RS Router Solicitation133主機開機時喊：「這裡有路由器嗎？」
送到 FF02::2		ICMP Router Discovery
RA Router Advertisement134路由器回答：「我在，網段前綴是這個，我可以當你的閘道。」
送到 FF02::1，也會定期主動發送		DHCP 的閘道與前綴資訊
NS Neighbor Solicitation135「這個 IPv6 位址的 MAC 是多少？」
送到 Solicited-node 多播		ARP Request
NA Neighbor Advertisement136「是我，我的 MAC 在這。」ARP Reply
Redirect137「這個目的地走另一台路由器比較近。」ICMP Redirect
主機 A 要跟同網段的主機 B 通訊 A ──NS──▶ FF02::1:FF00:0002 「2001:DB8:1::2 的 MAC 是誰？」 （Solicited-node 多播，只吵到末 24 bits 相同的主機） A ◀──NA── B 「是我,MAC 是 00:1A:2B:3C:4D:5E」 對比 IPv4 的 ARP： A ──ARP Request──▶ FF:FF:FF:FF:FF:FF（廣播,全網段每台都被吵） 這就是 IPv6 廢掉廣播的實際好處——同樣一件事,吵到的機器少非常多。

DAD：重複位址偵測

主機取得一個位址後、正式使用前，會先對自己的位址發一個 NS。
沒人回應 → 這個位址沒被佔用，可以用。
有人回 NA → 位址衝突，這個位址標記為 duplicate 不能用。
這是 IPv4 完全沒有的機制（IPv4 的 Gratuitous ARP 只是通知，不是驗證）。排錯時看到介面 IPv6 位址狀態是 DUPLICATE，就是 DAD 失敗。
資安提醒：NDP 跟 ARP 一樣沒有驗證。
攻擊者可以偽造 RA 把自己宣稱成路由器（Rogue RA），效果等同 IPv4 的 DHCP 欺騙加 ARP 毒化。
防護機制是 RA Guard（在接入層交換器上只允許指定埠發出 RA），以及 IPv6 Snooping / ND Inspection——這是第 14 章二層防護的 IPv6 版本。很多企業做了 DHCP Snooping 卻忘了做 RA Guard，等於留了一扇後門。

6. 取得位址的三種方式

① 靜態設定手動打上位址。用在路由器、伺服器、印表機這些位址不能變的裝置。
② SLAAC無狀態自動組態。從 RA 拿到前綴，介面 ID 自己算（EUI-64 或隨機）。不需要任何伺服器。
③ DHCPv6跟 IPv4 的 DHCP 類似，由伺服器集中配發並記錄。

RA 裡的兩個關鍵旗標：M 與 O

模式M 旗標O 旗標位址從哪來DNS 等資訊從哪來
純 SLAAC00自己算RA（若路由器有帶 RDNSS）
SLAAC + Stateless DHCPv601自己算DHCPv6 伺服器
Stateful DHCPv611DHCPv6 伺服器DHCPv6 伺服器
記法：M = Managed（位址被管理），O = Other（其他資訊）。
M=1 就是「位址交給 DHCPv6 管」；O=1 就是「其他資訊（DNS、NTP）跟 DHCPv6 拿」。
這張表是考題最愛的一組，判斷點永遠是「位址從哪來」與「DNS 從哪來」分開問。
SLAAC 的最大限制：早期版本無法提供 DNS 伺服器位址。
這就是為什麼會有「SLAAC + Stateless DHCPv6」這種混合模式——位址自己算（省掉伺服器負擔），但 DNS 還是要跟 DHCPv6 拿。
現在的 RA 可以帶 RDNSS 選項直接公告 DNS，但不是所有作業系統都支援，所以混合模式在企業中仍很常見。
! ── 路由器：啟用 IPv6 路由並設定介面 ──
R1(config)# ipv6 unicast-routing          ! 沒下這行,路由器不會轉送 IPv6,也不會發 RA
R1(config)# interface gigabitEthernet 0/0
R1(config-if)# ipv6 address 2001:DB8:1::1/64
R1(config-if)# no shutdown

! ── 讓主機用 Stateful DHCPv6（M=1）──
R1(config-if)# ipv6 nd managed-config-flag

! ── 讓主機用 SLAAC + Stateless DHCPv6（O=1）──
R1(config-if)# ipv6 nd other-config-flag

! ── 介面用 EUI-64 自動算介面 ID ──
R1(config-if)# ipv6 address 2001:DB8:1::/64 eui-64

! ── 只啟用 IPv6（只產生 Link-Local,不設全球位址）──
R1(config-if)# ipv6 enable
最常見的設定漏洞：忘記下 ipv6 unicast-routing。
沒有這行，路由器可以有 IPv6 位址、可以被 ping 到，但不會轉送 IPv6 封包，也不會發送 RA——主機因此拿不到前綴，SLAAC 完全失效。
排錯症狀是「主機只有 FE80 開頭的位址，沒有全球位址」。看到這個症狀，先去路由器確認這一行。

7. 雙堆疊與過渡技術

雙堆疊 Dual Stack首選做法。裝置同時跑 IPv4 與 IPv6，各走各的。缺點是兩套都要管、兩套 ACL、兩套路由。
通道 Tunneling把 IPv6 封包包在 IPv4 裡穿過只支援 IPv4 的網路（GRE、手動通道、6to4）。用於過渡期的孤島互連。
轉換 TranslationNAT64 + DNS64：讓 IPv6-only 的主機能存取只有 IPv4 的服務。行動網路大量使用。
NAT64 + DNS64 的運作 IPv6-only 手機 ──查 www.example.com──▶ DNS64 │ 發現只有 A 記錄（IPv4） │ 合成一筆假的 AAAA 記錄 ▼ 64:FF9B::203.0.113.10 │ 手機 ──送封包到那個 IPv6 位址──▶ NAT64 閘道 │ 轉換成 IPv4 封包 ▼ 只有 IPv4 的伺服器 手機全程以為自己在跟 IPv6 伺服器通訊。
企業實例｜某電信商的 IPv6-only 行動核心網
該電信商的 4G/5G 核心早已是 IPv6-only——因為用戶數遠超過 IPv4 位址能負擔的規模，即使做 CGNAT（電信級 NAT）也會遇到埠號耗盡與追蹤困難。
做法：手機只拿 IPv6 位址，要連 IPv4 網站時走 NAT64/DNS64。
踩到的坑：少數 App 把 IPv4 位址寫死在程式碼裡（不走 DNS 查詢），DNS64 因此攔截不到，這些 App 在 IPv6-only 網路上會完全連不上。解法是額外部署 464XLAT（在手機端也做一層轉換）。
這也是為什麼工程師要懂 IPv6：問題不會出現在你的網路，會出現在別人寫死 IPv4 的應用程式上，而你要有能力判斷那不是你的錯。
過渡策略的選擇原則：能雙堆疊就雙堆疊。
通道與轉換都會增加延遲、增加故障點、讓排錯變複雜（封包被包起來，Wireshark 要多解一層）。
考題若問「最佳的過渡方案」，答案通常是 Dual Stack；只有在「中間網路不支援 IPv6」或「必須讓 IPv6-only 存取 IPv4 服務」時，才輪到通道與 NAT64。

! ── 驗證指令 ──
R1# show ipv6 interface brief      ! 看每個介面的 IPv6 位址（含 Link-Local）
R1# show ipv6 neighbors           ! 相當於 show ip arp
R1# show ipv6 route               ! IPv6 路由表
R1# show ipv6 ospf neighbor
R1# ping 2001:DB8:2::1
OSPFv3 最常見的錯誤：忘記手動設 Router ID。
Router ID 仍然是 32-bit 的點分十進位格式（不是 IPv6 位址）。在純 IPv6 環境中，路由器沒有任何 IPv4 位址可以拿來自動選 Router ID，程序會起不來並回報錯誤。
純 IPv6 網路一定要手動下 router-id。

實作 Lab：雙堆疊網路與 SLAAC 驗證

約 45 分鐘。用 Packet Tracer 或 GNS3 都可以，兩台路由器 + 兩台 PC。

拓撲

PC1 ──── R1 ════ R2 ──── PC2 g0/0 g0/1 g0/1 g0/0 網段規劃： PC1 網段 2001:DB8:1::/64 （用 SLAAC） R1-R2 2001:DB8:12::/64 （手動 /64,R1 是 ::1、R2 是 ::2） PC2 網段 2001:DB8:2::/64 （用 SLAAC）

階段一：基本雙堆疊

  1. 兩台路由器都下 ipv6 unicast-routing（先做這一步，忘了後面全錯）
  2. 設定各介面的 IPv6 位址
  3. 在 PC 上開啟 IPv6 自動組態，觀察它自己算出的位址
  4. 用 show ipv6 interface brief 確認每個介面都有兩個位址：一個 FE80 開頭的 Link-Local、一個全球位址

階段二：驗證 SLAAC 與 NDP

  1. 在 PC1 上查看取得的位址，手算驗證 EUI-64 是否與 MAC 對得起來（若作業系統用隨機介面 ID 就對不起來，這本身就是一個觀察點）
  2. 在 R1 上 show ipv6 neighbors，確認學到了 PC1 的位址與 MAC
  3. 用 debug ipv6 nd 觀察 RS/RA 的往返（看完記得 undebug all）
  4. 把 R1 的 ipv6 unicast-routing 拿掉，觀察 PC1 過一段時間後失去全球位址、只剩 Link-Local——這就是最常見的故障症狀

階段三：路由與連通性

  1. 設定靜態路由或 OSPFv3 讓兩個網段互通（OSPFv3 記得手動設 router-id）
  2. PC1 ping PC2 的 IPv6 位址
  3. 用 traceroute 觀察路徑
ping 不通的檢查順序：
① 兩台路由器都下了 ipv6 unicast-routing 嗎？② 介面 no shutdown 了嗎？③ show ipv6 route 看得到對方網段嗎？④ show ipv6 neighbors 學到鄰居了嗎？⑤ PC 的預設閘道是不是路由器的 Link-Local 位址（IPv6 的閘道用 Link-Local，不是全球位址）？

10. 考試陷阱整理

陷阱 1：:: 用了兩次
一個 IPv6 位址中 :: 只能出現一次。看到兩個就是錯的選項。
陷阱 2：把中間或結尾的零也省掉
只有前導零可省。0042 → 42 對；8329 → 839 錯。
陷阱 3：以為 IPv6 有廣播
沒有 Broadcast，全部改用多播。「下列何者不是 IPv6 位址類型」的答案就是它。
陷阱 4：忘記 ipv6 unicast-routing
沒有這行，路由器不轉送 IPv6、不發 RA。症狀是主機只有 FE80 位址。
陷阱 5：M 與 O 旗標搞反
M = Managed = 位址交給 DHCPv6；O = Other = 其他資訊（DNS）跟 DHCPv6 拿。
陷阱 6：OSPFv3 沒設 Router ID
Router ID 仍是 32-bit 點分格式。純 IPv6 環境沒有 IPv4 位址可自動選，必須手動設。
陷阱 7：以為預設閘道是全球位址
IPv6 主機的預設閘道是路由器的 Link-Local 位址（從 RA 學到的），不是全球位址。
陷阱 8：EUI-64 忘記翻轉 U/L bit
插入 FFFE 之後還要翻第 7 個 bit。速算：第一個位元組的第二個十六進位數字，偶數 +2、奇數 −2。
陷阱 9：做了 DHCP Snooping 卻沒做 RA Guard
IPv6 的 Rogue RA 攻擊效果等同 DHCP 欺騙 + ARP 毒化。雙堆疊環境兩邊都要防。
💡一句話記憶：
縮寫時 :: 只能用一次，零只能省前導；
FE80 是本地必有、FF02::1 全體、FF02::2 路由器；
NS/NA 取代 ARP、RS/RA 給前綴，M 管位址、O 管其他；
忘了 unicast-routing 就只剩 Link-Local。
