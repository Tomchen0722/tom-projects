FHRP 閘道備援：HSRP / VRRP / GLBP

你把核心層做了雙機、線路做了 EtherChannel，但如果電腦的預設閘道那台路由器掛了，整個網段還是全斷。這一章補上這個洞——CCNA 必考，實務上也是每個企業網路都會有的設計。

1. 問題：預設閘道是單點故障

你家有兩條網路可以出門，但你的手機只設定了「從大門走」。
大門鎖住的那天，就算後門開著，手機也不知道要改走後門——因為它只認得那一個出口。

電腦要送封包到其他網段時，會丟給預設閘道。這個閘道 IP 是寫死在電腦裡的（DHCP 發的也一樣）。

正常狀態 PC (192.168.1.10) 預設閘道 = 192.168.1.1 │ ↓ R1 (192.168.1.1) ──→ 網際網路 R2 (192.168.1.2) ← 備援,但沒人用它 R1 掛掉 PC 還是拚命送給 192.168.1.1 → 全網段斷線 → R2 明明還活著,但 PC 不知道要改用它 要解決,有三種爛方法和一種好方法： ✗ 手動改每台 PC 的閘道 → 幾百台改到天亮 ✗ 縮短 DHCP 租約 → 還是要等,而且不可靠 ✗ 用動態路由跑到 PC 上 → PC 不跑路由協定 ✓ 讓兩台路由器共用一個「虛擬 IP」 ← 這就是 FHRP
FHRP = First Hop Redundancy Protocol，「第一跳備援協定」。第一跳指的就是預設閘道——封包離開電腦的第一站。

2. FHRP 的共同原理：虛擬 IP 與虛擬 MAC

三種 FHRP 的實作細節不同，但核心概念完全一樣，先把這個吃透，後面就只是背差異。

FHRP 的運作 PC 的預設閘道設成 192.168.1.254 ← 這是「虛擬 IP」 沒有任何一台實體路由器叫這個名字 ┌─────────────────┴─────────────────┐ ↓ ↓ R1 實體 IP 192.168.1.1 R2 實體 IP 192.168.1.2 目前是 Active（扛流量） 目前是 Standby（待命） │ │ └──── 互相發 Hello 確認對方還活著 ────┘ 關鍵：虛擬 MAC PC 送 ARP 問「192.168.1.254 的 MAC 是多少」 → Active 路由器回覆一個虛擬 MAC → PC 的 ARP 表記住這個虛擬 MAC 切換時發生什麼 R1 掛掉 → R2 接手,連虛擬 MAC 一起接手 → PC 的 ARP 表完全不用更新 → PC 甚至不知道換了一台機器
✅ 這就是 FHRP 的精髓：切換時虛擬 IP 和虛擬 MAC 都不變，所以終端裝置無感。
如果只有虛擬 IP 沒有虛擬 MAC，每次切換都要等所有 PC 的 ARP 表過期（可能好幾分鐘），那就沒意義了。

3. HSRP：Cisco 的主力

HSRP（Hot Standby Router Protocol）是 Cisco 專有協定，也是實務上在 Cisco 環境最常見的。

項目HSRPv1HSRPv2
群組編號範圍0–2550–4095
虛擬 MAC0000.0C07.ACxx0000.0C9F.Fxxx
multicast 位址224.0.0.2224.0.0.102
IPv6 支援不支援支援

xx 是群組編號的十六進位。群組 1 的虛擬 MAC 就是 0000.0C07.AC01——考試很愛考這個對應。

角色Active（扛流量）、Standby（第一順位備援）、其餘是 Listen。注意 HSRP 只有一台 Standby。
優先權預設 100，越大越優先。相同時比實體 IP，大的贏。
計時器Hello 預設 3 秒、Hold 10 秒。可調到毫秒級加快收斂。
搶佔預設關閉。原本的 Active 修好回來不會自動搶回，要 standby preempt 才會。
陷阱：HSRP 的 preempt 預設是關的
這是 HSRP 與 VRRP 最常考的差異之一。
情境：R1 優先權 110（本來是 Active）→ R1 掛掉，R2 接手 → R1 修好回來
• 沒設 preempt：R1 乖乖當 Standby，R2 繼續當 Active（即使 R1 優先權比較高）
• 有設 preempt：R1 立刻搶回 Active

實務上通常會開 preempt，讓角色回到你設計的樣子，但要搭配 delay minimum 避免 R1 剛開機、路由表還沒收斂就搶回去造成黑洞。

4. VRRP：業界標準版

VRRP（Virtual Router Redundancy Protocol）是 IETF 標準（RFC），非 Cisco 設備也支援。混廠牌環境要做閘道備援就得用它。

項目VRRP與 HSRP 的差異
標準IETF 開放標準HSRP 是 Cisco 專有
角色名稱Master / BackupHSRP 叫 Active / Standby
虛擬 MAC0000.5E00.01xx不同前綴
multicast224.0.0.18—
計時器Hello 1 秒、Hold 3 秒比 HSRP 快
搶佔預設開啟與 HSRP 相反
可用虛擬 IP可以直接用實體介面 IP 當虛擬 IPHSRP 的虛擬 IP 必須另外指定
陷阱：VRRP 的 preempt 預設是開的
和 HSRP 剛好相反，這組對照幾乎必考：
HSRP preempt 預設關 ／ VRRP preempt 預設開

記憶法：VRRP 是標準協定，行為比較「符合直覺」——優先權高的本來就該當老大，修好就搶回來。

5. GLBP：能同時分擔流量的那個

HSRP 和 VRRP 有一個共同的浪費：備援那台平常完全閒著。你買了兩台路由器，但只有一台在做事。

GLBP（Gateway Load Balancing Protocol）是 Cisco 專有協定，解決的就是這件事。

GLBP 怎麼做到負載分擔 關鍵：每台路由器有「不同的」虛擬 MAC 但共用同一個虛擬 IP AVG（Active Virtual Gateway）= 負責回答 ARP 的那台 └─ 它決定「這次 ARP 要回哪一個虛擬 MAC」 AVF（Active Virtual Forwarder）= 實際轉送封包的角色 R1 = AVF1,虛擬 MAC ...0001 R2 = AVF2,虛擬 MAC ...0002 實際流程 PC-A 問「閘道的 MAC?」→ AVG 回 R1 的虛擬 MAC → PC-A 走 R1 PC-B 問「閘道的 MAC?」→ AVG 回 R2 的虛擬 MAC → PC-B 走 R2 PC-C 問 → 回 R1 ... 輪流分配 結果:兩台路由器同時在扛流量
Round-robin預設。輪流分配虛擬 MAC，最平均。
Weighted依權重分配，適合兩台效能不同時。
Host-dependent同一台主機永遠拿到同一個 MAC，適合需要連線黏性的場景。
陷阱：GLBP 的負載分擔是「以主機為單位」
它不是把單一條連線拆開走兩邊，而是把不同的主機分配到不同路由器。
所以如果你的網段只有 2 台主機，分擔效果趨近於零；有 200 台才會平均。

另外 GLBP 是 Cisco 專有——混廠牌環境不能用。

選型的一句話：
• 全 Cisco 環境、要簡單 → HSRP
• 混廠牌 → VRRP（唯一選擇）
• 全 Cisco 且想讓兩台都做事 → GLBP

但要注意：現代資料中心更常用 StackWise / VSS / vPC 把兩台實體交換器變成邏輯上的一台，這樣連 FHRP 都不需要了，因為對下游來說本來就只有一台。
✅ HSRP/VRRP 也能做負載分擔——用「多群組」。
做法：VLAN 10 用群組 1（R1 當 Active），VLAN 20 用群組 2（R2 當 Active）。
這樣兩台都在扛流量，只是分擔的單位是 VLAN 而不是主機。實務上這比 GLBP 更常見，因為它不綁 Cisco。

7. 介面追蹤：避免「假活著」

沒有追蹤的話，會發生這種災難
R1 是 Active，內網介面好好的，但對外的 WAN 介面斷了。
→ R1 還是繼續當 Active（因為 HSRP 只看內網介面的 Hello）
→ 所有流量繼續送給 R1
→ R1 送不出去，全部丟掉
→ R2 的 WAN 明明是通的，但它還在 Standby 乖乖等

這叫「黑洞」——路由器活著，但路不通。

解法是介面追蹤（tracking）：讓 FHRP 監看其他介面的狀態，出事就自動降低自己的優先權。

追蹤的運作 R1 優先權 110，追蹤 WAN 介面（decrement 20） WAN 正常 → 優先權 110 → R1 是 Active ✓ WAN 斷線 → 優先權 110 - 20 = 90 → 低於 R2 的 100 → R2 搶佔成為 Active（前提:R2 有開 preempt） WAN 恢復 → 優先權回到 110 → R1 搶回 重點：decrement 值要夠大 如果 R1 是 110、R2 是 100,decrement 設 5 → 110-5 = 105 還是比 100 大 → 不會切換 → 追蹤形同虛設
✅ 設定追蹤的口訣：降完之後一定要比對方低。這是設定 tracking 最常犯的錯——設了但數值不夠大，等於沒設。
進階做法是追蹤 IP SLA（例如持續 ping 上游閘道），這樣連「介面是 up 但對端不通」也能偵測到。

8. 實作：HSRP 雙機備援

1
R1 設定（主要）
R1(config)# interface gi0/1 R1(config-if)# ip address 192.168.1.1 255.255.255.0 ! HSRP 群組 1,虛擬 IP 192.168.1.254 R1(config-if)# standby version 2 R1(config-if)# standby 1 ip 192.168.1.254 R1(config-if)# standby 1 priority 110 R1(config-if)# standby 1 preempt delay minimum 60 R1(config-if)# standby 1 authentication md5 key-string S3cr3t ! 追蹤 WAN 介面,斷了就降 20 R1(config-if)# standby 1 track gi0/0 20
2
R2 設定（備援）
R2(config)# interface gi0/1 R2(config-if)# ip address 192.168.1.2 255.255.255.0 R2(config-if)# standby version 2 R2(config-if)# standby 1 ip 192.168.1.254 R2(config-if)# standby 1 priority 100 ! 預設值,可省略 R2(config-if)# standby 1 preempt R2(config-if)# standby 1 authentication md5 key-string S3cr3t

兩邊的虛擬 IP、群組編號、認證金鑰必須一致，否則會各自成為 Active（雙主）。

3
驗證
R1# show standby brief Interface Grp Pri P State Active Standby Virtual IP Gi0/1 1 110 P Active local 192.168.1.2 192.168.1.254 R1# show standby gi0/1 1 ! 看得到虛擬 MAC、計時器、追蹤狀態 ! 從 PC 驗證 C:\> arp -a 192.168.1.254 0000-0c9f-f001 ← 虛擬 MAC,不是 R1 的實體 MAC
4
測試切換
! 從 PC 開一個持續 ping C:\> ping 8.8.8.8 -t ! 在 R1 關掉介面模擬故障 R1(config)# interface gi0/1 R1(config-if)# shutdown ! 觀察:應該只掉 1-3 個封包就恢復 ! R2 上確認已接手 R2# show standby brief Gi0/1 1 100 P Active local unknown 192.168.1.254
實驗完記得收尾：把 shutdown 的介面 no shutdown 開回來，並確認 R1 有依 preempt 設定搶回 Active。

9. 故障排除與考試陷阱

症狀可能原因怎麼查
兩台都是 Active（雙主）彼此收不到 Hello：VLAN 不通、群組編號不同、認證不符show standby 比對群組與認證；確認二層路徑
切換後流量還是不通沒設追蹤，或上游路由沒收斂檢查 track 設定與 decrement 值
Active 一直跳來跳去Hello 太短、線路不穩、CPU 過載show log 看切換紀錄；放寬計時器
修好的路由器不搶回HSRP 沒開 preempt加 standby X preempt
剛開機就搶回造成短暫斷線preempt 沒設 delay加 preempt delay minimum 60
陷阱 1：preempt 預設值
HSRP 關、VRRP 開。這組對照極常考。
陷阱 2：虛擬 MAC 前綴
HSRP 0000.0C07.AC、VRRP 0000.5E00.01、GLBP 0007.B400。看到 MAC 就要認得出是哪個協定。
陷阱 3：只有 GLBP 原生支援負載分擔
但題目若限定「必須是標準協定」→ VRRP + 多群組，不能選 GLBP。
陷阱 4：追蹤的 decrement 要夠大
降完之後必須低於對方，否則不會切換。
陷阱 5：HSRP 只有一台 Standby
三台以上的話，第三台之後是 Listen 狀態，不是 Standby。
✅ 一句話記憶：
HSRP = Cisco、Active/Standby、preempt 預設關
VRRP = 標準、Master/Backup、preempt 預設開、計時器較快
GLBP = Cisco、AVG/AVF、唯一原生負載分擔
