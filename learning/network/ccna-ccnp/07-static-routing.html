1. 路由器轉發封包的完整流程

一個封包從進到出，路由器做了七件事。理解這七步，之後所有的路由故障你都能自己推。

1
收到訊框，檢查 FCS錯誤就直接丟掉並累加 input errors 計數器。
2
檢查目的 MAC 是不是自己不是自己也不是廣播 → 丟掉。路由器不像交換器會 flooding。
3
剝掉二層表頭，取出 IP 封包這步之後，原本的乙太表頭就永遠不存在了。
4
檢查 TTLTTL 減 1。減完變 0 → 丟棄並回送 ICMP Time Exceeded（traceroute 就是靠這個運作的）。
5
查路由表，用最長前綴匹配找出「下一跳 IP」和「出口介面」。查不到 → 丟棄並回 ICMP Destination Unreachable。
6
查 ARP 表取得下一跳的 MACARP 表沒有就先發 ARP 請求，封包暫存等待。
7
封裝新的二層表頭並送出來源 MAC 改成出口介面自己的，目的 MAC 是下一跳的。重算 FCS。
一句話總結（CH 1-3 講過，這裡再強調一次）：
IP 位址 = 端到端不變
MAC 位址 = 逐跳改變
TTL = 每跳減 1
第 5 步是關鍵分歧點。路由表查不到就是丟棄——路由器不會猜、不會廣播、不會問別人。「ping 不通」的問題有八成是因為某台路由器的表裡沒有回程路由。永遠記得檢查雙向：去程有路由，回程也要有。

2. 最長前綴匹配（Longest Prefix Match）

路由表裡可能同時有好幾條路由都「涵蓋」目的地。規則只有一條：前綴最長（遮罩最精確）的那條贏，跟 AD、跟 metric 都無關。

推演：目的地 172.16.20.130，路由表裡有四條
0.0.0.0/0預設路由，涵蓋全世界。前綴長度 0
172.16.0.0/16涵蓋 172.16.0.0 – 172.16.255.255。長度 16
172.16.20.0/24涵蓋 172.16.20.0 – 172.16.20.255。長度 24
172.16.20.128/26 ✅涵蓋 172.16.20.128 – 172.16.20.191。長度 26 → 最長，贏

四條都匹配，但 /26 最精確，所以封包走 /26 那條的下一跳。即使 /24 那條的 AD 更低、metric 更小，也完全不影響——前綴長度優先於一切。

最常被誤解的一點：AD 和 metric 只在「前綴長度相同」時才拿出來比。
1. 先比前綴長度 → 長的贏
2. 長度相同 → 比 AD → 小的贏
3. AD 也相同（同一種協定）→ 比 metric → 小的贏
4. metric 也相同 → 等價負載分擔（ECMP）
! 直接問路由器「172.16.20.130 這個目的地你會怎麼走」
R1# show ip route 172.16.20.130
Routing entry for 172.16.20.128/26
  Known via "static", distance 1, metric 0
  Routing Descriptor Blocks:
  * 10.0.0.2
      Route metric is 0, traffic share count is 1
這個指令是排錯神器。與其自己盯著整張路由表推，不如直接問路由器。它會告訴你實際選中的是哪一條，省下大量猜測。

C 和 L 有什麼不同？

C（Connected）L（Local）
代表整個直連網段路由器自己那個 IP
遮罩介面設定的遮罩永遠 /32
範例10.0.0.0/3010.0.0.1/32
作用知道「這個網段從這個介面出去」知道「送給我自己的封包，交給上層處理」
C 和 L 出現的前提：介面必須 up/up 而且有 IP。
  • 介面被 shutdown → C 和 L 都消失
  • 線拔掉（protocol down）→ C 和 L 都消失
  • 連帶效應：所有以那個介面為出口的靜態路由，也會一起從路由表消失
這個連帶效應是浮動靜態路由能運作的基礎（第 8 節）。

R1# show ip route static
R1# show ip route ospf
R1# show ip route connected

! 只看特定網段（比 | include 準確，會做最長匹配）
R1# show ip route 192.168.30.0 255.255.255.0

! 統計有幾條路由（大型網路很有用）
R1# show ip route summary

4. 管理距離 AD 完整表

AD（Administrative Distance）是「可信度」，數字愈小愈可信。當兩種不同來源都學到同一個前綴長度的路由時，AD 小的那條被放進路由表，另一條被丟棄。

來源AD備註
Connected（直連）0親眼看到的，最可信
Static（靜態）1人設定的
EIGRP Summary5
eBGP（外部）20比 IGP 都低，跨自治系統的資訊優先
EIGRP（內部）90Cisco 專有
IGRP100已淘汰
OSPF110業界標準 IGP
IS-IS115電信業常用
RIP120
EIGRP External170從別的協定重分佈進來的
iBGP（內部）200刻意設高，避免蓋掉 IGP
Unknown / 不可達255永遠不會被放進路由表
速記口訣：0-1-20-90-110-115-120-170-200——直連 0、靜態 1、eBGP 20、EIGRP 90、OSPF 110、IS-IS 115、RIP 120、EIGRP 外部 170、iBGP 200。CCNA 一定會考「同時學到 OSPF 和 EIGRP 的同一條路由，哪個進表」→ EIGRP 90 < OSPF 110，EIGRP 贏。
AD 255 = 直接丟棄。這個設計是浮動靜態路由的極端用法，也是某些「先設好但先不生效」技巧的基礎。不要誤以為 255 是「最不優先但還是會用」——它是完全不會用。

手動修改 AD

! 靜態路由改 AD（最後那個數字就是 AD）
R1(config)# ip route 192.168.30.0 255.255.255.0 10.0.0.2 200

! 整個協定改 AD（謹慎使用，會影響全部路由）
R1(config)# router ospf 1
R1(config-router)# distance 95

! 只改特定來源學到的路由的 AD
R1(config-router)# distance 95 10.0.0.2 0.0.0.0

5. 路由來源：直連、靜態、動態

直連靜態動態
怎麼產生介面設 IP 且 up 就自動有人工一條條打路由器之間自動交換
會不會自動繞路—不會會
CPU／頻寬負擔無無有
規模上限—小型（< 10 台路由器）無上限
可預測性高最高中
典型用途—末端網路、對 ISP 的預設路由、備援企業內部主要路由
企業實務怎麼混用？
  • 內部網段之間 → OSPF 或 EIGRP（自動收斂）
  • 對 ISP → 一條靜態預設路由（沒必要跟 ISP 跑動態）
  • 末端分公司（只有一條線出去）→ 靜態，跑動態協定是浪費
  • 備援線路 → 浮動靜態路由（第 8 節）

6. 實作一：靜態路由的四種寫法

ip route <目的網路> <遮罩> { <下一跳 IP> | <出口介面> } [AD] [name 說明]

寫法 A：指定下一跳 IP（最常用，推薦）

R1(config)# ip route 192.168.30.0 255.255.255.0 10.0.0.2
  • 優點：語意清楚、在乙太網路上行為正確
  • 路由器需要做遞迴查詢：先查「10.0.0.2 怎麼去」，再決定出口介面
  • 乙太網路（多重存取）上一定要用這種或寫法 C

寫法 B：指定出口介面

R1(config)# ip route 192.168.30.0 255.255.255.0 gigabitEthernet 0/1
在乙太網路上這樣寫會出大問題。路由器會認為「這個網段直接掛在 Gi0/1 上」，於是對每一個目的 IP 都發 ARP 請求。

症狀：ARP 表爆量成長、CPU 升高、有時通有時不通。

這種寫法只適合點對點鏈路（Serial、PPP、GRE Tunnel）——那種線的對面只有一個人，不需要 ARP。

寫法 C：兩個都寫（Fully Specified，最穩）

R1(config)# ip route 192.168.30.0 255.255.255.0 gigabitEthernet 0/1 10.0.0.2
這是企業環境的最佳寫法。
  • 不需要遞迴查詢，效率最好
  • 不會濫發 ARP
  • 介面一 down，這條路由立刻消失——備援切換最快
  • 一個介面上有多個下一跳時（例如接到交換器再連多台路由器），語意毫無歧義

寫法 D：加上 AD 與說明

R1(config)# ip route 192.168.30.0 255.255.255.0 10.0.0.2 name TO-BRANCH-TAIPEI
R1(config)# ip route 192.168.30.0 255.255.255.0 10.0.1.2 210 name BACKUP-4G

name 只是註解，但在有 50 條靜態路由的路由器上，它能救你的命。show ip route static 不會顯示 name，要用 show running-config | include ip route 才看得到。

刪除靜態路由

! 要把整行原封不動地加 no 前綴，多一個字少一個字都不會刪掉
R1(config)# no ip route 192.168.30.0 255.255.255.0 10.0.0.2
完整範例：三台路由器串聯
[LAN 192.168.10.0/24]--R1--10.0.0.0/30--R2--10.0.1.0/30--R3--[LAN 192.168.30.0/24]
! R1：要去 R2 的 LAN 和 R3 的 LAN 和中間那段
R1(config)# ip route 10.0.1.0 255.255.255.252 gi0/1 10.0.0.2
R1(config)# ip route 192.168.20.0 255.255.255.0 gi0/1 10.0.0.2
R1(config)# ip route 192.168.30.0 255.255.255.0 gi0/1 10.0.0.2

! R2：兩邊都要寫
R2(config)# ip route 192.168.10.0 255.255.255.0 gi0/0 10.0.0.1
R2(config)# ip route 192.168.30.0 255.255.255.0 gi0/1 10.0.1.2

! R3：回程路由（最常被忘記的一台）
R3(config)# ip route 10.0.0.0 255.255.255.252 gi0/0 10.0.1.1
R3(config)# ip route 192.168.10.0 255.255.255.0 gi0/0 10.0.1.1
R3(config)# ip route 192.168.20.0 255.255.255.0 gi0/0 10.0.1.1

觀察：3 台路由器就要寫 8 條。10 台就是幾十條，而且任何一條線路變動都要手動改全部。這就是為什麼要有動態路由協定——下一章 OSPF 只要幾行設定就能取代這一切。

7. 實作二：預設路由與 Gateway of Last Resort

預設路由是 0.0.0.0/0——遮罩全 0，代表「涵蓋所有目的地」。因為前綴長度是 0，它永遠是最短的匹配，所以只有在其他所有路由都不匹配時才會用到。這就是「最後手段的閘道」（Gateway of Last Resort）的意思。

! 對 ISP 的標準寫法
R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1 name TO-ISP-HINET

! 用出口介面（點對點 WAN 才這樣寫）
R1(config)# ip route 0.0.0.0 0.0.0.0 serial 0/0/0

! 交換器（二層）用另一個指令，不是 ip route
SW1(config)# ip default-gateway 192.168.99.1
三個容易混淆的指令：
指令用在前提
ip route 0.0.0.0 0.0.0.0 x.x.x.x路由器、三層交換器有開 ip routing
ip default-gateway二層交換器沒有開 ip routing 時才有效
ip default-network舊式，配 RIP/EIGRP幾乎已淘汰
三層交換器開了 ip routing 之後，ip default-gateway 就完全失效了——這是很多人設定三層交換器管理位址時的困惑點。 
R1# show ip route | include Gateway|0.0.0.0
Gateway of last resort is 203.0.113.1 to network 0.0.0.0
S*    0.0.0.0/0 [1/0] via 203.0.113.1
看到 Gateway of last resort is not set 就代表沒有預設路由，任何不在路由表裡的目的地都會被丟棄。分公司路由器最常見的「內網通、上不了網」就是這個原因。

8. 實作三：浮動靜態路由（備援）

公司有兩條對外線路：主線是光纖，備線是 4G。平常只走光纖，光纖斷了自動切 4G。做法是給備援路由一個比較大的 AD，讓它平常「浮」在路由表外面。

! 主線：AD 使用預設值 1
R1(config)# ip route 0.0.0.0 0.0.0.0 gi0/1 203.0.113.1 name PRIMARY-FIBER

! 備線：AD 設 100，平常不會進路由表
R1(config)# ip route 0.0.0.0 0.0.0.0 gi0/2 198.51.100.1 100 name BACKUP-4G
1
平常狀態兩條前綴長度都是 /0，比 AD → 1 < 100，只有主線在路由表裡。備線存在 running-config 但不在 routing table。
2
Gi0/1 斷線介面變 down，C 和 L 路由消失，連帶讓主線靜態路由失效（因為寫法 C 綁定了介面）。
3
備線自動上場剩下 AD 100 那條，它被裝進路由表，流量改走 4G。
4
光纖修好Gi0/1 恢復 up，AD 1 那條回來、蓋掉 AD 100 那條，流量自動切回光纖。
浮動靜態路由有個大坑：介面 up 不代表線路通。

如果 ISP 那端的設備掛了，但你和 ISP 之間的實體線路還在（例如中間隔了一台媒體轉換器或交換器），你的介面會一直是 up/up，主線路由永遠不會消失，備援永遠不會切換。使用者會抱怨「網路斷了但路由器顯示一切正常」。

解法是 IP SLA + Track：主動 ping 一個遠端目標，ping 不到就把路由撤下來。

IP SLA + Object Tracking（企業標準做法）

! ── 步驟 1：建立一個 ICMP 探測，每 5 秒 ping 一次 8.8.8.8 ──
R1(config)# ip sla 1
R1(config-ip-sla)# icmp-echo 8.8.8.8 source-interface gigabitEthernet 0/1
R1(config-ip-sla-echo)# frequency 5
R1(config-ip-sla-echo)# threshold 1000          ← 超過 1000ms 算異常
R1(config-ip-sla-echo)# timeout 2000
R1(config-ip-sla-echo)# exit

! ── 步驟 2：讓探測立刻開始、永久執行 ──
R1(config)# ip sla schedule 1 life forever start-time now

! ── 步驟 3：建立追蹤物件，延遲避免線路抖動造成頻繁切換 ──
R1(config)# track 1 ip sla 1 reachability
R1(config-track)# delay down 10 up 30            ← 掛 10 秒才切走，好 30 秒才切回
R1(config-track)# exit

! ── 步驟 4：把主線路由綁上追蹤物件 ──
R1(config)# no ip route 0.0.0.0 0.0.0.0 gi0/1 203.0.113.1
R1(config)# ip route 0.0.0.0 0.0.0.0 gi0/1 203.0.113.1 track 1 name PRIMARY-FIBER
! 驗證
R1# show ip sla statistics 1
IPSLA operation id: 1
        Latest RTT: 12 milliseconds
Latest operation return code: OK
Number of successes: 847
Number of failures: 0

R1# show track 1
Track 1
  IP SLA 1 reachability
  Reachability is Up
    1 change, last change 02:14:07
  Delay up 30 secs, down 10 secs
delay down 10 up 30 為什麼要不對稱？「切走」要快（10 秒），使用者才不會斷太久；「切回」要慢（30 秒），因為剛修好的線路常常會再抖幾次，太快切回會造成流量反覆震盪。

9. 實作四：彙總靜態路由

如果總部要去分公司的四個網段，可以寫四條路由，也可以合併成一條。這叫路由彙總（Route Summarization）。

推演：把四個 /24 合併
192.168.8.0/24   →  11000000.10101000.00001000.00000000
192.168.9.0/24   →  11000000.10101000.00001001.00000000
192.168.10.0/24  →  11000000.10101000.00001010.00000000
192.168.11.0/24  →  11000000.10101000.00001011.00000000
                                              ↑↑
                            前 22 位元完全相同，第 23、24 位元才不同
共同前綴 = 22 位元 → 192.168.8.0/22
! 四條變一條
R1(config)# ip route 192.168.8.0 255.255.252.0 10.0.0.2 name BRANCH-ALL

怎麼手算彙總

1
把所有網段轉成二進位只需要轉「有變化的那個位元組」，前面相同的直接跳過。
2
從左往右找出共同前綴的長度一路對齊到第一個不同的位元為止。
3
共同位元數 = 新的遮罩長度剩下的位元全補 0，就是彙總後的網路位址。
4
驗算：這個彙總有沒有多涵蓋不該涵蓋的網段？192.168.8.0/22 涵蓋 8、9、10、11 四個。如果 192.168.11.0 其實是別家公司的，你就把流量吸過來丟掉了。
彙總的代價：範圍會擴大。只要彙總範圍內有任何一個網段其實不在那個方向，流量就會被錯誤地送過去然後被丟棄——而且路由表看起來完全正常，非常難查。彙總前務必確認整個範圍都屬於同一個方向。
彙總的好處：路由表變小 → 查表快、記憶體省；而且單一分公司網段變動不會傳播出去，上游路由器完全不需要重新收斂。大型網路的穩定性有很大一部分來自良好的彙總設計。

10. IPv6 靜態路由

! ── 先開啟 IPv6 路由功能（預設是關的，最常忘記的一行）──
R1(config)# ipv6 unicast-routing

! ── 介面設定 ──
R1(config)# interface gigabitEthernet 0/1
R1(config-if)# ipv6 address 2001:db8:0:1::1/64
R1(config-if)# ipv6 enable                      ← 自動產生 link-local 位址

! ── 寫法 A：全域單播位址當下一跳 ──
R1(config)# ipv6 route 2001:db8:0:30::/64 2001:db8:0:1::2

! ── 寫法 B：link-local 當下一跳（必須同時指定介面）──
R1(config)# ipv6 route 2001:db8:0:30::/64 gigabitEthernet 0/1 fe80::2

! ── 預設路由 ──
R1(config)# ipv6 route ::/0 2001:db8:0:1::2

! ── 浮動備援 ──
R1(config)# ipv6 route ::/0 2001:db8:0:2::2 100
用 link-local 當下一跳時，一定要同時寫出口介面。因為 link-local 位址（fe80::/10）在每一個介面上都可能重複——它只在該鏈路內有意義。不寫介面，路由器不知道要從哪個埠出去，指令會被拒絕。
R1# show ipv6 route static
IPv6 Routing Table - default - 6 entries
S   2001:DB8:0:30::/64 [1/0]
     via FE80::2, GigabitEthernet0/1
S   ::/0 [1/0]
     via 2001:DB8:0:1::2

R1# show ipv6 interface brief
IPv4 和 IPv6 的路由表是完全獨立的兩張表，互不影響。這叫 Dual Stack（雙協定堆疊），是目前企業過渡到 IPv6 的主流做法——兩套並存，應用程式自己選要用哪個。

11. 遞迴查詢與 CEF

當靜態路由只寫了下一跳 IP（寫法 A），路由器必須做兩次以上的查表：

1
第一次查「192.168.30.0/24 → via 10.0.0.2」。但 10.0.0.2 要從哪個介面出去？不知道。
2
第二次查「10.0.0.0/30 → directly connected, Gi0/1」。現在知道出口是 Gi0/1 了。
3
查 ARP取得 10.0.0.2 的 MAC，封裝送出。
遞迴失敗的情境：如果第二次查也查不到 10.0.0.2 怎麼去（例如那條直連路由消失了），整條靜態路由會從路由表裡消失。用 show ip route static 明明設定了卻看不到，八成就是遞迴解析失敗。

CEF：把遞迴的結果先算好

CEF（Cisco Express Forwarding）是現代 Cisco 設備的預設轉發引擎。它預先把路由表和 ARP 表整合成兩張表，封包來的時候直接查一次就得到答案，不用每次遞迴。

表內容對應的原始資料
FIB（Forwarding Information Base）前綴 → 下一跳由路由表產生
Adjacency Table下一跳 → 完整的二層表頭由 ARP 表產生
R1# show ip cef 192.168.30.130
192.168.30.0/24
  nexthop 10.0.0.2 GigabitEthernet0/1

R1# show adjacency gigabitEthernet 0/1 detail
Protocol Interface       Address
IP       GigabitEthernet0/1  10.0.0.2(7)
                             0 packets, 0 bytes
                             00505600000200505600000108 00   ← 預先算好的二層表頭

R1# show ip cef summary
為什麼要知道 CEF？當你改了路由但流量沒改變、或 ping 通但實際流量走錯方向時，問題常常出在 FIB 和路由表不同步。這時查 show ip cef 而不是 show ip route，才看得到路由器實際上怎麼轉發。必要時 clear ip cef * 重建（會短暫影響流量，別在尖峰做）。

12. 故障排除

1
介面 up/up 嗎？show ip interface brief。administratively down = 忘了 no shutdown；up/down = 實體層通但協定不通（封裝或時脈問題）。
2
直連路由在嗎？show ip route connected。連 C 都沒有，靜態路由再怎麼寫都沒用。
3
去程路由在嗎？show ip route <目的IP>。直接問路由器它會走哪條，比自己盯整張表快。
4
回程路由在嗎？到對方那台路由器上查show ip route <來源IP>。這是最常被忽略的一步，「單向不通」幾乎都是這個原因。
5
逐跳定位traceroute <目的IP>。看到連續的 * * * 就是斷在那一跳，去那台路由器查。
6
指定來源測試ping 192.168.30.10 source 192.168.10.1。路由器預設用出口介面 IP 當來源，不指定的話你測的不是使用者實際的路徑。
7
ARP 通嗎？show ip arp。下一跳的 MAC 是 Incomplete 就是 ARP 沒解析成功，往二層查。
8
ACL 擋住了嗎？show ip interface gi0/1 | include access list，再 show access-lists 看命中數。
真實案例：「分公司 ping 得到總部路由器，但 ping 不到總部電腦」

排查：分公司 R3 上 ping 10.0.0.1 通、ping 192.168.10.10 不通。到總部 R1 上查 show ip route 192.168.30.0 → 沒有這條路由。

原因：去程有（R3 寫了到總部的路由），但 R1 沒寫回分公司的路由。ping 路由器會通是因為那是直連網段。修法：R1 補上 ip route 192.168.30.0 255.255.255.0 gi0/1 10.0.0.2。

真實案例：「換了 ISP 之後，只有部分網站開不了」

排查：ping 8.8.8.8 通、ping -l 1472 8.8.8.8（大封包）不通。

原因：新 ISP 用 PPPoE，MTU 只有 1492，小封包過得去大封包被丟。修法：在 WAN 介面設 ip mtu 1492 和 ip tcp adjust-mss 1452。這跟 CH 2-2 的 Baby Giant 是同一類問題。

完整實作 Lab：總部 + 兩分公司 + 雙 ISP 備援

Packet Tracer 或 GNS3，約 70 分鐘。

拓樸

                    [ ISP-A ]        [ ISP-B ]
                  203.0.113.1      198.51.100.1
                        │                │
                     Gi0/1            Gi0/2
                       [ R1 總部 ]
                     Gi0/0 │ 192.168.10.1/24
                  ┌────────┴────────┐
               Gi0/3            Gi0/4
          10.0.0.0/30        10.0.1.0/30
               │                  │
          [ R2 台北 ]         [ R3 台中 ]
        192.168.20.0/24     192.168.30.0/26

步驟

  1. 所有介面設 IP 並 no shutdown，確認 show ip int brief 全是 up/up
  2. R1 用 fully specified 寫法，加到兩個分公司網段的靜態路由
  3. R2、R3 各寫一條預設路由指向 R1（分公司只有一條出口，不需要細寫）
  4. R1 設主線預設路由指向 ISP-A（AD 預設 1）
  5. R1 設備援預設路由指向 ISP-B，AD 100
  6. 設定 IP SLA 1 每 5 秒 ping 8.8.8.8，source 為 Gi0/1
  7. 建立 track 1，delay down 10 up 30，並把主線路由綁上去
  8. R1 對兩個分公司的路由改成一條彙總路由（自己算出正確的遮罩）
  9. 全部加上 name 註解

驗收清單

  • 台北 PC ping 得到台中 PC
  • 兩地 PC 都 ping 得到 8.8.8.8
  • show ip route 在 R1 上，只能看到 ISP-A 那條預設路由
  • 把 Gi0/1 shutdown → 10 秒內流量切到 ISP-B，show track 1 顯示 Down
  • 把 Gi0/1 開回來 → 30 秒後切回 ISP-A
  • show ip route 192.168.20.10 命中的是彙總那條，不是明細

加碼挑戰

  1. 把 R1 到 R2 的靜態路由改成只寫出口介面（寫法 B），然後在 R1 上 show ip arp，觀察 ARP 表項目數量的變化，體會第 6 節的警告。
  2. 故意在 R3 上刪掉回程路由，用 traceroute 找出斷點在哪一跳。
  3. 算出「涵蓋 192.168.16.0/24 到 192.168.23.0/24 共 8 個網段」的最小彙總，並驗證它不會多涵蓋 192.168.24.0/24。
  4. 在 R1 加一條 ip route 192.168.20.0 255.255.255.0 null 0 250，觀察它在什麼情況下才會被用到，思考這種「黑洞路由」的用途。

本章重點回顧

  • 轉發七步驟：檢查 FCS → 檢查目的 MAC → 剝表頭 → TTL−1 → 查路由 → 查 ARP → 重新封裝
  • 最長前綴匹配優先於一切；長度相同才比 AD，AD 相同才比 metric
  • AD 速記：0 / 1 / 20 / 90 / 110 / 115 / 120 / 170 / 200，255 = 永不使用
  • C 是整個直連網段，L 是路由器自己那個 /32
  • 乙太網路上的靜態路由用 fully specified（出口介面 + 下一跳）最穩
  • 只寫出口介面在乙太網路上會濫發 ARP，只適合點對點鏈路
  • 浮動靜態路由靠 大 AD 待命，但必須配 IP SLA + Track 才防得住「介面 up 但線路不通」
  • IPv6 別忘了 ipv6 unicast-routing；link-local 當下一跳必須同時寫介面
  • 查不到問題時，記得 回程路由和 show ip cef
