CH 5-3 · 無線

無線網路與 WLC 設定

CCNA 官方大綱有八個項目在講無線與 WLC，而這是有線工程師最容易忽略的一塊。這一章從無線本質講到 WLC 上實際建一個 WLAN。

本章目錄

  1. 無線和有線根本的三個不同
  2. 頻段、通道與干擾
  3. 三種部署架構
  4. CAPWAP 與 Split-MAC
  5. WLC 的埠與介面（最容易混淆）
  6. 無線安全：WEP 到 WPA3

1. 無線和有線根本的三個不同

有線網路像每個人有自己的專用電話線——你講話不影響別人。
無線網路像一群人在同一個會議室講話——同一時間只能有一個人說，而且隔壁會議室的聲音會傳過來干擾。
差異有線無線
傳輸媒介獨占的銅線／光纖共享的空氣——所有人搶同一個頻道
碰撞處理全雙工，基本上沒有碰撞半雙工，用 CSMA/CA 事前避免
安全邊界要插上線才進得來訊號穿牆，停車場就能嘗試連線
必考：CSMA/CD vs CSMA/CA
• 有線用 CSMA/CD（Collision Detection）——邊送邊聽，撞到了才處理。
• 無線用 CSMA/CA（Collision Avoidance）——因為無線網卡不能同時收發，撞了根本偵測不到，所以只能事前避免：先聽有沒有人在講，沒有才送，還要等一段隨機時間。

這也解釋了為什麼無線的實際吞吐量大約只有標稱值的一半——大量時間花在協調誰可以講話。

2. 頻段、通道與干擾

頻段穿透力速度不重疊通道特性
2.4 GHz好（傳得遠）慢只有 3 個（1、6、11）擁擠，微波爐/藍牙都在這
5 GHz差（穿牆衰減大）快20 個以上企業主力
6 GHz最差最快更多Wi-Fi 6E／7，需新設備
2.4 GHz 為什麼只能用 1、6、11 每個通道佔 22 MHz 寬,但通道間距只有 5 MHz → 相鄰通道會互相重疊干擾 ch1 ch6 ch11 ▓▓▓▓ ▓▓▓▓ ▓▓▓▓ ← 完全不重疊 ✓ ch3 ▓▓▓▓ ← 與 ch1 重疊 ✗ 部署原則 相鄰的 AP 要用不同通道,並排成蜂巢狀 同通道的 AP 要離得夠遠
陷阱：同通道干擾 vs 相鄰通道干擾
• 同通道干擾（Co-channel）：兩台 AP 用同一個通道 → 它們會「輪流講話」，頻寬被瓜分但還能運作。
• 相鄰通道干擾（Adjacent-channel）：用了 ch1 和 ch3 → 訊號重疊但無法協調，變成純粹的雜訊，比同通道更糟。

所以寧可讓兩台 AP 同用 ch1，也不要一台 ch1 一台 ch3。這是很反直覺但必考的觀念。

3. 三種部署架構

架構AP 類型怎麼管適合規模
自主式
Autonomous		Autonomous AP每台 AP 各自設定，各自獨立幾台以內的小辦公室
集中式
Centralized		Lightweight APWLC 集中管理，AP 開機自動下載設定企業標準
雲端式
Cloud		Meraki 等雲端儀表板管理多分點、無 IT 人力
為什麼企業一定要 WLC
想像 200 台自主式 AP：要改一個 SSID 密碼，得逐台登入改 200 次。
而且沒有 WLC 就沒有：集中的通道與功率自動調整（RRM）、無縫漫遊、統一的安全政策、集中監控與 Rogue AP 偵測。

大綱裡「登入 WLC、監控 WLC、配置 Dynamic Interface、配置 DHCP Scope、配置 WLAN」這五個實驗，講的都是集中式架構。

4. CAPWAP 與 Split-MAC

CAPWAP（Control and Provisioning of Wireless Access Points）是 Lightweight AP 與 WLC 之間的通道協定。

CAPWAP 的兩條通道 Lightweight AP ══════════════ WLC │ ┌───────────┴───────────┐ │ │ 控制通道 UDP 5246 資料通道 UDP 5247 一定加密（DTLS） 預設不加密（可開啟） 設定下發、韌體、狀態 使用者的實際流量 Split-MAC:把 802.11 的工作拆成兩半 AP 負責（即時性要求高） WLC 負責（需要全域視野） • 信標 Beacon 發送 • 驗證與關聯的決策 • 封包確認 ACK • 安全政策（金鑰管理） • 資料加解密 • 漫遊決策 • 佇列與優先權 • RRM（通道與功率調整） • Rogue AP 偵測
必考：CAPWAP 的兩個埠與加密狀態
UDP 5246 = 控制（一定用 DTLS 加密）
UDP 5247 = 資料（預設不加密）

另外：CAPWAP 會把使用者流量封裝後送到 WLC，所以 AP 與 WLC 之間的路徑要能承載額外的封裝開銷——MTU 不足會造成分片與效能問題。
Local Mode預設。所有流量都繞回 WLC 才出去。管理集中，但分點會有「髮夾彎」延遲。
FlexConnect分點專用。控制走 WLC，但資料在本地直接出去。WAN 斷掉時 AP 還能繼續服務。
Monitor Mode不服務用戶端，專門掃描偵測 Rogue AP 與干擾。
Sniffer Mode把收到的封包轉給分析工具，用於排錯。
陷阱：分點該用 FlexConnect
題目情境：「分公司的 AP 透過 WAN 連到總部 WLC，使用者抱怨連內部伺服器很慢，而且 WAN 一斷無線就全掛。」
→ 答案是改用 FlexConnect。Local Mode 會把分點使用者的流量全部繞回總部再送出去，既慢又浪費 WAN 頻寬；FlexConnect 讓資料在本地交換。

5. WLC 的埠與介面（最容易混淆）

這一段是 WLC 設定的核心，也是新手最容易搞混的地方。「埠」是實體的，「介面」是邏輯的。

名稱類型用途
Management Interface邏輯管理 WLC 用，也是 AP 註冊 CAPWAP 的目標位址
Dynamic Interface邏輯對應到一個 VLAN，使用者流量從這裡進入有線網路
Virtual Interface邏輯給 Web 認證、DHCP 中繼用的虛擬位址（傳統上設 1.1.1.1）
Service Port實體頻外管理專用，獨立於資料網路
Distribution Port實體接到交換器的資料埠，通常做成 LAG
一個 WLAN 怎麼對應到有線 VLAN 使用者連上 SSID「Corp-WiFi」 │ ↓ WLAN 設定檔（SSID + 安全設定） │ 綁定 ↓ Dynamic Interface「vlan10-staff」 │ 對應 ↓ VLAN 10 ──→ 交換器 ──→ 有線網路 關鍵:一個 WLAN 綁一個 Dynamic Interface 要做員工/訪客分流,就建兩個 WLAN + 兩個 Dynamic Interface 對應到不同 VLAN,再用 ACL 隔離
陷阱：WLC 與交換器之間一定要設 Trunk
因為 WLC 要同時承載多個 VLAN 的使用者流量（員工 VLAN 10、訪客 VLAN 20……），交換器上連到 WLC 的埠必須是 trunk 且放行這些 VLAN。
設成 access port 是最常見的錯誤——結果只有一個 VLAN 通，其他 WLAN 全部不通。

6. 無線安全：WEP 到 WPA3

標準加密狀態說明
WEPRC4❌ 完全破解幾分鐘就能破，絕對不可使用
WPATKIP❌ 已淘汰WEP 的過渡方案
WPA2AES-CCMP✅ 目前主流企業標準；有 KRACK 弱點但已修補
WPA3AES-GCMP + SAE✅ 新標準抗離線字典攻擊、強制 PMF
Personal（PSK）大家共用一組密碼。缺點：離職員工也知道密碼，要換就全部要換。適合家庭與小店。
Enterprise（802.1X）每人用自己的帳號向 RADIUS 驗證。可依身分指派不同 VLAN，離職停用帳號即可。企業標準。
必考：WPA3 改進了什麼
① SAE 取代 PSK 的四向交握——WPA2-PSK 可以被離線暴力破解（抓到交握封包後回家慢慢猜），WPA3 的 SAE 讓離線猜測失效，每次嘗試都要與 AP 互動。
② 強制 PMF（受保護管理框架）——防止偽造的解除關聯攻擊。
③ 前向保密——就算密碼之後外洩，先前錄下的流量也解不開。
陷阱：Rogue AP 與 Evil Twin
• Rogue AP：未經授權接到公司網路的 AP（常常是員工自己帶來的分享器）——它是一個繞過所有防護的後門。
• Evil Twin：攻擊者架一台同名 SSID 且訊號更強的假 AP，騙使用者連上去做中間人攻擊。

WLC 的 Rogue Detection 會比對偵測到的 AP 是否出現在自家有線網路上，藉此區分「隔壁公司的 AP」與「真正插在我們網路上的 Rogue」。

7. 實作：在 WLC 上建立 WLAN

這一節對應官方大綱的五個實驗：登入 WLC、監控 WLC、配置 Dynamic Interface、配置 DHCP Scope、配置 WLAN。

1
登入與檢視狀態
用瀏覽器連到 Management Interface 的 IP（https://10.1.1.10）。
Monitor → Summary 可以看到：加入的 AP 數量、目前的用戶端數、各 AP 的通道與功率、Rogue AP 清單。
AP 沒出現在清單就是沒註冊成功，先查第 8 節的排錯。
2
建立 Dynamic Interface（對應員工 VLAN 10）
Controller → Interfaces → New
Interface Name : vlan10-staff VLAN Identifier: 10 IP Address : 10.10.10.5 Netmask : 255.255.255.0 Gateway : 10.10.10.1 ← VLAN 10 的閘道（通常是交換器 SVI） DHCP Server : 10.1.1.50 ← 主要 DHCP 伺服器
這個介面就是「無線使用者進入有線網路的門」。
3
交換器端設定 Trunk（很容易漏掉）
SW(config)# interface gi1/0/48 SW(config-if)# description === 連到 WLC === SW(config-if)# switchport mode trunk SW(config-if)# switchport trunk allowed vlan 10,20,99 SW(config-if)# spanning-tree portfast trunk
4
設定 DHCP Scope
兩種做法，實務上多用第二種：
• WLC 內建 DHCP：Controller → Internal DHCP Server → DHCP Scope，適合小環境或訪客網路。
• 外部 DHCP 伺服器：在 Dynamic Interface 指定 DHCP Server IP，由 WLC 做中繼。企業幾乎都用這種，因為位址管理要集中。
5
建立 WLAN（WPA2-Enterprise）
WLANs → Create New
【General 頁籤】 Profile Name : Corp-Staff SSID : Corp-WiFi Status : Enabled Interface : vlan10-staff ← 綁到剛才建的 Dynamic Interface 【Security → Layer 2】 Layer 2 Security : WPA+WPA2 WPA2 Policy : Enabled WPA2 Encryption : AES ← 不要選 TKIP Auth Key Mgmt : 802.1X ← 企業模式 【Security → AAA Servers】 Authentication Server 1 : 10.1.1.20（RADIUS，埠 1812） 【Advanced】 Session Timeout : 1800 Client Exclusion : Enabled FlexConnect Local Switching : （分點才勾）
6
定義 RADIUS 伺服器
Security → AAA → RADIUS → Authentication → New
Server IP Address : 10.1.1.20 Shared Secret : （與 RADIUS 端一致） Port Number : 1812 Server Status : Enabled Support for RFC 3576 (CoA) : Enabled ← 允許動態變更授權
Shared Secret 兩邊不一致是最常見的驗證失敗原因，而錯誤訊息不會直接告訴你。
7
建立訪客 WLAN（WPA2-PSK，對應大綱的 WPA2-PSK 實驗）
Profile Name : Guest SSID : Guest-WiFi Interface : vlan20-guest ← 另一個 Dynamic Interface 【Security → Layer 2】 Layer 2 Security : WPA+WPA2 WPA2 Encryption : AES Auth Key Mgmt : PSK PSK Format : ASCII Pre-Shared Key : （設定密碼）
訪客網路務必再做兩件事：用 ACL 阻擋訪客 VLAN 存取內部網段，並限制頻寬避免影響公司業務。

8. 排錯與考試陷阱

症狀先查什麼
AP 註冊不到 WLCAP 有沒有拿到 IP、能不能連到 Management Interface、DHCP Option 43 或 DNS 有沒有指對、時間是否同步（憑證驗證會因時間差失敗）
使用者連得上但拿不到 IPDynamic Interface 的 VLAN 與 DHCP 設定、交換器埠是不是 trunk、DHCP Scope 有沒有位址
802.1X 驗證失敗RADIUS 的 Shared Secret、WLC 的 IP 有沒有加進 RADIUS 的用戶端清單、憑證是否過期
訊號滿格但很慢同通道干擾、太多用戶擠一台 AP、2.4GHz 頻段擁擠、是否有非 Wi-Fi 干擾源
移動時會斷線AP 之間的通道與功率規劃、漫遊門檻設定、覆蓋是否有死角
陷阱 1：CAPWAP 的埠
控制 UDP 5246（DTLS 加密）、資料 UDP 5247（預設不加密）。
陷阱 2：2.4GHz 只有 1、6、11
而且同通道干擾比相鄰通道干擾好。
陷阱 3：CSMA/CA 不是 CD
無線不能邊送邊聽，所以只能事前避免。
陷阱 4：WLC 上連埠要 trunk
多個 WLAN 對應多個 VLAN，access port 會讓大部分 WLAN 不通。
陷阱 5：分點用 FlexConnect
Local Mode 會把流量繞回總部，WAN 斷了無線就掛。
陷阱 6：一個 WLAN 綁一個 Dynamic Interface
要做員工／訪客分流就要建兩組。
✅ 一句話記憶：
AP 與 WLC 之間走 CAPWAP（5246 控制／5247 資料）；
WLAN 是無線那一側的 SSID，Dynamic Interface 是有線那一側的 VLAN，兩者綁在一起才通；
企業用 802.1X、訪客用 PSK，分點用 FlexConnect。
