BGP 與路由政策

OSPF 找最短路徑，BGP 找「符合商業政策的路徑」。這章講清楚 BGP 為什麼跟其他協定完全不同、十一步選路順序怎麼記，以及企業雙 ISP 該怎麼設計進出流量。

1. BGP 為什麼跟其他協定不一樣

IGP（OSPF、EIGRP）BGP
目標找最快的路徑找符合政策的路徑
範圍單一組織內部組織之間（網際網路的骨幹）
類型連結狀態 / 距離向量路徑向量（Path Vector）
傳輸自己的封包格式（協定 89 / 88）TCP port 179
鄰居自動發現必須手動指定
metric單一數值一整套屬性，十一步比較
路由數量數百到數千全網際網路約 95 萬條以上
收斂秒級分鐘級（刻意設計得慢而穩）
比喻：OSPF 像 Google Maps——「哪條路最快就走哪條」。BGP 像貨運公司排路線——「這家客戶跟我們有合約，走他們的路便宜；那家是競爭對手，就算比較近也不走」。BGP 的決策是商業的，不是技術的。
路徑向量是什麼意思？BGP 宣告路由時會帶上「這條路經過了哪些 AS」的清單（AS_PATH）。這有兩個作用：
  • 防迴圈：收到的路由如果 AS_PATH 裡已經有自己的 AS 號，直接丟棄
  • 選路：AS_PATH 愈短通常代表跳過愈少家業者，是選路順序中很重要的一項
什麼時候不該用 BGP？只有一條對外線路的公司，一條靜態預設路由就夠了。導入 BGP 意味著：要跟 ISP 申請 AS 號和自有 IP、路由器要有足夠記憶體吃下全表（至少 4 GB）、要有人懂得維護。沒有雙 ISP 或多出口需求，BGP 純粹是自找麻煩。

2. AS 號與公私有範圍

AS（Autonomous System，自治系統）是「由同一個組織統一管理路由政策的一群路由器」。每家 ISP、每家有自己對外政策的大企業，都有自己的 AS 號。

範圍類型用途
1 – 64495公有 16 bit網際網路上使用，向 RIR（亞太是 APNIC）申請
64512 – 65534私有 16 bit企業內部、實驗室。不能出現在網際網路上
65535保留—
65536 – 4199999999公有 32 bit16 bit 快用完了，新申請多是這個範圍
4200000000 – 4294967294私有 32 bit大型企業內部多 AS 設計
! 32 bit AS 號的表示法：asplain 或 asdot
R1(config)# router bgp 65536              ← asplain（現行標準）
R1(config)# bgp asnotation dot            ← 改成顯示 1.0 這種格式
台灣的實務：要申請公有 AS 號和自有 IP 位址段，需要向 TWNIC（APNIC 的下級單位）提出申請，通常要求「有兩家以上的上游 ISP」作為理由。單一 ISP 的企業申請不會過——因為那種情況根本不需要 BGP。

3. eBGP vs iBGP

eBGP（外部）iBGP（內部）
鄰居的 AS不同 AS相同 AS
AD20200
預設 TTL1（必須直連）255
AS_PATH宣告時加上自己的 AS不改
Next-Hop宣告時改成自己不改（所以要 next-hop-self）
路由再傳播學到的可以傳給任何鄰居從 iBGP 學到的不能再傳給其他 iBGP
拓樸需求直連邏輯全網狀或 Route Reflector
iBGP 水平分割規則（最重要的一條）：
從 iBGP 鄰居學到的路由，不會再宣告給其他 iBGP 鄰居
為什麼？因為 iBGP 之間 AS_PATH 不變，沒有防迴圈機制。所以只能靠這條規則。

後果：AS 內有 N 台 BGP 路由器，就需要 N(N−1)/2 條 iBGP session。10 台 = 45 條，50 台 = 1225 條。這就是為什麼需要 Route Reflector（第 7 節）。

eBGP 的 TTL 限制與 multihop

! eBGP 預設 TTL=1，代表鄰居必須直連。
! 如果要用 Loopback 建立 eBGP（中間隔了一跳），必須加 multihop
R1(config-router)# neighbor 2.2.2.2 ebgp-multihop 2
R1(config-router)# neighbor 2.2.2.2 update-source loopback 0

! 較新的做法：ttl-security，比 multihop 安全
R1(config-router)# neighbor 2.2.2.2 ttl-security hops 2
什麼時候用 Loopback 建 eBGP？當兩台路由器之間有多條實體線路時。用實體介面 IP 建 session，那條線斷了 session 就掉；用 Loopback，只要還有任何一條路能通，session 就活著。單一線路的情況不要用 Loopback，反而增加複雜度。

4. Session 建立與四種訊息

六個狀態

狀態意義卡住的原因
Idle還沒開始，或剛失敗退回來沒有到鄰居 IP 的路由；或 session 一直失敗被退避
Connect正在等 TCP 三次握手完成TCP 179 被防火牆擋
ActiveTCP 失敗了，正在主動重試最常見的卡住狀態：IP 打錯、對方沒設定、ACL 擋住
OpenSent送出 Open 訊息，等對方回應AS 號不符、Router ID 重複
OpenConfirm等 Keepalive 確認認證密碼不符
Established正常狀態，開始交換路由—
「Active」不是好事。名字聽起來很正面，實際上代表 TCP 連不上，正在一直重試。在 show ip bgp summary 裡看到 Active 或 Idle，就是 session 沒建起來。Established 才是唯一正常的狀態。

四種訊息

訊息做什麼
OPEN自我介紹：我的 AS 號、Router ID、Hold Time、支援的能力
UPDATE宣告新路由（含屬性）或撤銷路由（Withdrawn Routes）
KEEPALIVE每 60 秒一次，維持 session。Hold Time 預設 180 秒
NOTIFICATION出錯了，送完就關閉 session。錯誤碼會告訴你原因
Hold Time 會取兩邊較小的那個。所以你設 90 秒、對方設 180 秒，實際生效的是 90 秒。Keepalive 通常是 Hold Time 的三分之一。

5. 實作一：基本 eBGP 設定

! ═══ 我方 AS 65001，ISP 是 AS 64500 ═══
R1(config)# router bgp 65001
R1(config-router)# bgp router-id 1.1.1.1
R1(config-router)# bgp log-neighbor-changes

! ── 定義鄰居 ──
R1(config-router)# neighbor 203.0.113.1 remote-as 64500
R1(config-router)# neighbor 203.0.113.1 description == ISP-A HINET ==
R1(config-router)# neighbor 203.0.113.1 password S3cureBGP!

! ── 宣告自己的網段 ──
R1(config-router)# network 198.51.100.0 mask 255.255.255.0
BGP 的 network 跟 OSPF 完全不同！
OSPF 的 networkBGP 的 network
意義「這些介面要跑 OSPF」「宣告這個網段給鄰居」
遮罩wildcard（0.0.0.255）正常遮罩（mask 255.255.255.0）
前提介面要 up路由表裡必須有完全一致的這條路由
最常見的「宣告了但對方看不到」原因：路由表裡沒有精確匹配的路由。

你打 network 198.51.100.0 mask 255.255.255.0，但路由表裡只有 198.51.100.0/25 和 198.51.100.128/25 兩條 → BGP 不會宣告，因為沒有一條剛好是 /24。

標準解法：加一條指向 Null0 的靜態路由，讓路由表裡確實存在那個前綴： 
R1(config)# ip route 198.51.100.0 255.255.255.0 null 0
這條路由不會造成問題——更精確的 /25 路由會因為最長前綴匹配而優先，Null0 只是讓 BGP 有東西可以宣告。

Peer Group 與 Peer Template（鄰居多的時候）

! 傳統 peer-group
R1(config-router)# neighbor IBGP-PEERS peer-group
R1(config-router)# neighbor IBGP-PEERS remote-as 65001
R1(config-router)# neighbor IBGP-PEERS update-source loopback 0
R1(config-router)# neighbor IBGP-PEERS next-hop-self
R1(config-router)# neighbor 2.2.2.2 peer-group IBGP-PEERS
R1(config-router)# neighbor 3.3.3.3 peer-group IBGP-PEERS

6. next-hop-self 與同步問題

問題場景
[ ISP 64500 ]───203.0.113.1
                     │
                 203.0.113.2
              [ R1 ]────iBGP────[ R2 ]
                    10.0.0.1  10.0.0.2
  1. R1 從 ISP 學到路由，Next-Hop = 203.0.113.1
  2. R1 把路由傳給 R2（iBGP）。iBGP 不改 Next-Hop，所以 R2 收到的還是 203.0.113.1
  3. R2 的路由表裡沒有 203.0.113.0/24 這個網段（那是 R1 對外的線）
  4. 結果：R2 認為這條路由的下一跳不可達，標成 inaccessible，不會放進路由表
! 解法：R1 在傳給 iBGP 鄰居時，把 Next-Hop 改成自己
R1(config-router)# neighbor 10.0.0.2 next-hop-self
規則很簡單：所有 iBGP 鄰居都加 next-hop-self。這幾乎沒有例外，是 BGP 設定的標準動作。忘記加就會出現「BGP 表裡有路由但路由表裡沒有」的困惑。
! 症狀長這樣：BGP 表裡有，但沒有 > 符號
R2# show ip bgp
   Network          Next Hop         Metric LocPrf Weight Path
*  172.16.0.0/16    203.0.113.1           0    100      0 64500 i
                    ↑ 沒有 >，代表沒被選為 best

R2# show ip bgp 172.16.0.0
  64500
    203.0.113.1 (inaccessible) from 10.0.0.1 (1.1.1.1)
另一種解法：把連接 ISP 的網段用 IGP 宣告出去。這樣 R2 就知道怎麼到 203.0.113.1。但一般不建議——你把對外網段丟進內部 IGP，等於多了一個攻擊面，而且 next-hop-self 一行就解決了。

7. iBGP 全網狀與 Route Reflector

N 台 iBGP 路由器 → 需要 N(N−1)/2 條 session
10 台 = 45 條　　50 台 = 1225 條

維護 1225 條 session 是不可能的。Route Reflector（RR，路由反射器）打破 iBGP 水平分割規則：RR 可以把從一個 iBGP 鄰居學到的路由，反射給其他 iBGP 鄰居。

角色設定行為
Route Reflector在 RR 上設 route-reflector-client會反射路由
Client不用設定，是被 RR 指定的只跟 RR 建 session
Non-Client一般 iBGP 鄰居跟 RR 和其他 Non-Client 都要全網狀

反射規則

路由來自反射給 Client反射給 Non-Client反射給 eBGP
Client✅✅✅
Non-Client✅❌✅
eBGP✅✅✅
! ═══ 在 RR 上設定（R2 當 RR）═══
R2(config)# router bgp 65001
R2(config-router)# neighbor 1.1.1.1 remote-as 65001
R2(config-router)# neighbor 1.1.1.1 update-source loopback 0
R2(config-router)# neighbor 1.1.1.1 next-hop-self
R2(config-router)# neighbor 1.1.1.1 route-reflector-client
R2(config-router)# neighbor 3.3.3.3 route-reflector-client
R2(config-router)# neighbor 4.4.4.4 route-reflector-client

! ═══ Client 端（R1）：完全是一般的 iBGP 設定 ═══
R1(config-router)# neighbor 2.2.2.2 remote-as 65001
R1(config-router)# neighbor 2.2.2.2 update-source loopback 0
R1(config-router)# neighbor 2.2.2.2 next-hop-self

RR 的防迴圈機制

屬性作用
Originator-ID記錄「這條路由原本是誰宣告的」。路由器看到自己的 RID 就丟棄
Cluster-List記錄「經過了哪些 RR Cluster」。看到自己的 Cluster-ID 就丟棄
RR 一定要做冗餘。只有一台 RR，它掛了整個 AS 的 iBGP 路由傳播就斷了。標準做法是兩台 RR 放在同一個 Cluster，所有 Client 同時跟兩台建 session： 
R2(config-router)# bgp cluster-id 10.0.0.1
R3(config-router)# bgp cluster-id 10.0.0.1   ← 兩台用同一個 cluster-id
另一個方案：Confederation（聯盟）。把一個大 AS 切成好幾個「子 AS」，子 AS 之間跑 eBGP 規則（所以沒有水平分割問題），對外看起來仍是一個 AS。設定比 RR 複雜很多，實務上 95% 的網路都選 RR。CCNP 考試會問差異，知道概念即可。

8. 十一步選路順序（核心）

當同一個前綴有多條路徑時，BGP 依序比較以下項目，一旦分出勝負就停止。

W
Weight — 大的贏Cisco 專有，只有本機意義，不會傳給任何鄰居。預設：自己產生的 32768，學來的 0。最快速的本機覆寫手段。
L
Local Preference — 大的贏預設 100。在整個 AS 內部傳播，用來統一決定「本 AS 的流量要從哪個出口出去」。控制出方向流量的首選工具。
L
Locally originated — 自己起源的贏用 network 或 redistribute 或 aggregate-address 產生的路由，優先於學來的。
A
AS_PATH — 短的贏經過的 AS 數量。控制入方向流量最常用的工具（用 AS-PATH prepending 把自己的路徑加長，讓別人不想走）。
O
Origin — IGP > EGP > Incompletei（network 宣告）優於 e（老舊 EGP，幾乎絕跡）優於 ?（重分佈進來）。
M
MED — 小的贏Multi-Exit Discriminator。送給鄰居 AS 的建議：「你要進我的網路，走這個入口比較好」。預設只在同一個鄰居 AS 之間比較。
e
eBGP 優於 iBGP外部學來的優先於內部學來的。
I
IGP metric to next-hop — 小的贏到下一跳的 IGP 成本。這叫「熱馬鈴薯路由」——把流量儘快丟出自己的網路。
R
最老的 eBGP 路徑贏穩定性優先，避免頻繁切換。
R
Router ID — 小的贏純粹的破平手規則。
R
鄰居 IP 位址 — 小的贏最後手段。
W – L – L – A – O – M – e – I – R – R – R

「We Love Low AS Origin MED eBGP IGP Router-ID Recent Reachability」
有些教材寫「BGP 選路 13 步驟」，那是把幾個項目拆得更細（例如把 AS_PATH 的 AS_SET／AS_CONFED 分開算、把 multipath 判定獨立成一步）。順序和結論完全相同，記 11 步這版就夠應付考試和實務。
實務上你只會用到前四項。Weight（本機臨時覆寫）、Local Preference（決定出方向）、AS_PATH（影響入方向）、MED（給鄰居的建議）。剩下七項是破平手用的，考試要記，實務很少主動去調。
! 直接看某條前綴的完整比較過程
R1# show ip bgp 172.16.0.0/16

  64600 64700

9. 屬性詳解與影響方向

屬性類別傳播範圍影響哪個方向的流量
WeightCisco 專有只有本機出方向（僅這台）
Local PreferenceWell-known discretionary整個 AS 內出方向（全 AS 統一）
AS_PATHWell-known mandatory全球入方向（用 prepend）
Next-HopWell-known mandatory視 eBGP/iBGP—
OriginWell-known mandatory全球—
MEDOptional non-transitive只到鄰居 AS入方向（建議性質）
CommunityOptional transitive可跨 AS視 ISP 政策
記住這條原則：
出方向流量（我要怎麼出去）→ 我自己說了算 → 用 Local Preference

入方向流量（別人怎麼進來）→ 別人說了算，我只能影響 → 用 AS_PATH prepend
這是 BGP 最重要的觀念之一：你無法命令別人怎麼把流量送給你，只能讓某條路徑看起來比較差。

MED 的兩個陷阱

  1. MED 預設只在同一個鄰居 AS 的路徑之間比較。兩條路徑分別來自 AS 100 和 AS 200，MED 根本不會被拿來比。要跨 AS 比較必須開 bgp always-compare-med（全網要一致，否則會造成路由震盪）。
  2. MED 只是建議，對方可以完全無視。大多數 ISP 會在收到路由時就把 MED 清掉，改用自己的 Local Preference。所以別指望用 MED 精確控制入方向流量。

BGP Community：跟 ISP 溝通的暗號

! 格式：AS:VALUE，例如 64500:120
! 每家 ISP 自己定義意義，要查他們的文件

! 知名的保留 community
!   no-export      → 不要傳給 eBGP 鄰居（可傳給同聯盟）
!   no-advertise   → 不要傳給任何鄰居
!   local-as       → 不要傳出本地子 AS

R1(config)# route-map SET-COMM permit 10
R1(config-route-map)# set community 64500:120 no-export
R1(config-route-map)# exit
R1(config-router)# neighbor 203.0.113.1 route-map SET-COMM out
R1(config-router)# neighbor 203.0.113.1 send-community       ← 忘了這行 community 不會被送出去
Community 的實際用途：ISP 常提供類似「打上 64500:120 我就幫你把 Local Preference 設成 120」或「打上 64500:666 我就幫你黑洞掉這個前綴（DDoS 緊急處理）」的服務。這比自己做 prepend 精準得多，導入 BGP 前一定要跟 ISP 要一份 community 對照表。

10. 實作二：用屬性控制流量

情境：主線走 ISP-A，備線 ISP-B

控制出方向：Local Preference

! 對 ISP-A 學到的路由，Local Pref 設 200（預設 100）
R1(config)# route-map ISP-A-IN permit 10
R1(config-route-map)# set local-preference 200
R1(config-route-map)# exit

R1(config)# router bgp 65001
R1(config-router)# neighbor 203.0.113.1 route-map ISP-A-IN in

! ISP-B 那邊維持預設 100 → 全 AS 的流量都會優先走 ISP-A

控制入方向：AS_PATH Prepending

! 對 ISP-B 宣告時，把自己的 AS 重複三次
! 別人看到的 AS_PATH 從「65001」變成「65001 65001 65001」
R1(config)# route-map ISP-B-OUT permit 10
R1(config-route-map)# set as-path prepend 65001 65001 65001
R1(config-route-map)# exit

R1(config-router)# neighbor 198.51.100.1 route-map ISP-B-OUT out
Prepend 不保證有效。因為 AS_PATH 只是選路順序的第 4 項——如果對方的 ISP 用 Local Preference（第 2 項）強制走 ISP-B，你 prepend 十次也沒用。prepend 通常 3 次就夠了，加更多只是浪費，還會讓某些 ISP 的過濾規則把你的路由當異常丟掉。

臨時覆寫：Weight

! 只影響這一台，馬上生效，不傳播
R1(config-router)# neighbor 203.0.113.1 weight 100

! 或用 route-map 精細控制
R1(config)# route-map SET-WEIGHT permit 10
R1(config-route-map)# match ip address prefix-list IMPORTANT
R1(config-route-map)# set weight 500

套用政策變更（不要重啟 session）

! ✗ 這會斷線重建，全部路由重新學一次
R1# clear ip bgp 203.0.113.1

! ✓ Soft Reset：只重新套用政策，session 不斷
R1# clear ip bgp 203.0.113.1 soft in
R1# clear ip bgp 203.0.113.1 soft out

! 需要 soft in 的前提：對方支援 route-refresh（現代設備都支援）
R1# show ip bgp neighbors 203.0.113.1 | include Route refresh
  Route refresh: advertised and received(old & new)

! 若對方不支援，要先開 soft-reconfiguration（會多耗記憶體）
R1(config-router)# neighbor 203.0.113.1 soft-reconfiguration inbound
正式環境絕對不要打 clear ip bgp *。那會重建所有 session，全表重新收斂需要好幾分鐘，這段期間對外流量會中斷。永遠先用 soft。

11. 實作三：路由過濾

沒有過濾的 BGP 是危險的。2008 年巴基斯坦電信誤宣告了 YouTube 的前綴，因為上游沒有過濾，全球有一大部分的 YouTube 流量被導向巴基斯坦，持續兩小時。2021 年也有類似的大規模事件。入方向和出方向都必須過濾。

方法 A：Prefix-list（最常用）

! 只宣告自己的網段出去（防止變成中轉路由器）
R1(config)# ip prefix-list MY-NETS permit 198.51.100.0/24
R1(config)# ip prefix-list MY-NETS permit 198.51.101.0/24
R1(config-router)# neighbor 203.0.113.1 prefix-list MY-NETS out

! 入方向：擋掉私有網段、預設路由、過長過短的前綴
R1(config)# ip prefix-list BOGONS deny 0.0.0.0/0
R1(config)# ip prefix-list BOGONS deny 10.0.0.0/8 le 32
R1(config)# ip prefix-list BOGONS deny 172.16.0.0/12 le 32
R1(config)# ip prefix-list BOGONS deny 192.168.0.0/16 le 32
R1(config)# ip prefix-list BOGONS deny 127.0.0.0/8 le 32
R1(config)# ip prefix-list BOGONS deny 0.0.0.0/0 ge 25      ← 比 /24 更細的不收
R1(config)# ip prefix-list BOGONS permit 0.0.0.0/0 le 24
R1(config-router)# neighbor 203.0.113.1 prefix-list BOGONS in
ge 和 le 怎麼讀：
  • 10.0.0.0/8 le 32 = 「10.0.0.0/8 這個範圍內，遮罩從 /8 到 /32 的全部」
  • 0.0.0.0/0 ge 25 = 「任何網段，但遮罩必須 /25 或更細」
  • 0.0.0.0/0 le 24 = 「任何網段，遮罩 /24 或更粗」
ISP 普遍不接受比 /24 更細的前綴，因為那會讓全球路由表爆炸。

方法 B：AS-PATH 過濾（用正規表示式）

! ^$ = 空的 AS_PATH，代表「只有自己起源的路由」
R1(config)# ip as-path access-list 1 permit ^$
R1(config-router)# neighbor 203.0.113.1 filter-list 1 out

! ^64500_ = 直接鄰居是 AS 64500 的路由
R1(config)# ip as-path access-list 2 permit ^64500_

! _64700$ = 起源自 AS 64700 的路由
R1(config)# ip as-path access-list 3 permit _64700$

! .* = 全部
R1(config)# ip as-path access-list 4 permit .*
符號意義
^字串開頭（= 直接鄰居）
$字串結尾（= 起源 AS）
_分隔符（空格、開頭、結尾、逗號、括號）
.任一字元
*前一項出現 0 次以上
^$ 是最重要的一個。企業對 ISP 宣告時，加上 filter-list permit ^$ 表示「只宣告我自己的網段」。這能防止你意外變成兩家 ISP 之間的中轉站——那會讓別人的流量塞爆你的線路，而且你要付錢。

方法 C：Route-map（最靈活，可以邊過濾邊改屬性）

R1(config)# ip prefix-list CUSTOMER-A permit 172.16.0.0/16

R1(config)# route-map ISP-A-IN permit 10
R1(config-route-map)# match ip address prefix-list CUSTOMER-A
R1(config-route-map)# set local-preference 200
R1(config-route-map)# set community 65001:100
R1(config-route-map)# exit

R1(config)# route-map ISP-A-IN permit 20          ← 其他的照收但不改屬性
R1(config-route-map)# exit
route-map 結尾有隱含的 deny any。只寫 permit 10 而沒有寫 permit 20，所有不匹配的路由都會被丟棄。這是最常見的 route-map 事故——設定完之後路由突然全部消失。永遠記得補一個空的 permit 在最後。

限制接收的前綴數量（防止對方誤宣告全表）

! 超過 1000 條就警告，超過 1200 條就斷開 session
R1(config-router)# neighbor 203.0.113.1 maximum-prefix 1200 80
!                                          ↑    ↑ 到 80% (960 條) 時發警告

! 只警告不斷線
R1(config-router)# neighbor 203.0.113.1 maximum-prefix 1200 warning-only

! 斷線後 5 分鐘自動重連
R1(config-router)# neighbor 203.0.113.1 maximum-prefix 1200 restart 5

12. 雙 ISP 設計實務

設計收到的路由記憶體需求適合誰
只收預設路由1 條極低大多數企業
預設路由 + 部分路由數千條中需要對特定目的地優化的企業
收全表95 萬條以上4 GB 以上ISP、大型內容業者
99% 的企業應該選第一種。你不需要知道全世界的路由，你只需要知道「哪個出口比較好」。收全表的路由器成本可能是收預設路由的十倍，而且收斂時間長很多。
! ═══ 只跟 ISP 要預設路由 ═══
R1(config)# ip prefix-list DEFAULT-ONLY permit 0.0.0.0/0
R1(config-router)# neighbor 203.0.113.1 prefix-list DEFAULT-ONLY in
R1(config-router)# neighbor 198.51.100.1 prefix-list DEFAULT-ONLY in

! ═══ 出方向：只宣告自己的網段 ═══
R1(config)# ip as-path access-list 1 permit ^$
R1(config-router)# neighbor 203.0.113.1 filter-list 1 out
R1(config-router)# neighbor 198.51.100.1 filter-list 1 out

! ═══ 出方向流量偏好 ISP-A ═══
R1(config)# route-map PREFER-A permit 10
R1(config-route-map)# set local-preference 200
R1(config-router)# neighbor 203.0.113.1 route-map PREFER-A in

! ═══ 入方向流量偏好 ISP-A（對 B prepend）═══
R1(config)# route-map PREPEND-B permit 10
R1(config-route-map)# set as-path prepend 65001 65001 65001
R1(config-router)# neighbor 198.51.100.1 route-map PREPEND-B out

! ═══ 安全上限 ═══
R1(config-router)# neighbor 203.0.113.1 maximum-prefix 10 restart 5
導入 BGP 前的行政準備（跟錢和合約有關，先確認再動手）：
  • 向 TWNIC 申請自有 AS 號與 IP 位址段（有年費、需要文件證明）
  • 兩家 ISP 都要簽 BGP peering 的合約條款，通常比一般固接方案貴
  • 建立 RPKI ROA（路由起源授權），現在多數大型 ISP 會驗證，沒有 ROA 的前綴可能被丟棄
  • 把前綴登錄到 IRR（Internet Routing Registry），ISP 會依此產生過濾清單
這些流程通常要 4 到 8 週，不是設定完就能上線。

13. 故障排除

1
Session 建起來了嗎？show ip bgp summary。State/PfxRcd 是數字才算 Established。
2
卡在 Active？先 ping <鄰居IP>，通不了就是三層問題。通了就查 TCP 179 有沒有被 ACL 或防火牆擋。
3
AS 號打對了嗎？show ip bgp neighbors x.x.x.x | include remote AS。打錯會卡在 OpenSent 並收到 NOTIFICATION。
4
iBGP 用 Loopback？那必須有 update-source loopback 0，而且 IGP 要能通到對方的 Loopback。
5
路由收到了但沒進路由表？看 show ip bgp 有沒有 >。沒有的話多半是 Next-Hop inaccessible → 忘了 next-hop-self。
6
宣告了但對方看不到？查 show ip bgp neighbors x.x.x.x advertised-routes。空的就是被 out 方向的 filter 擋了。
7
network 指令沒生效？show ip route <前綴> 確認路由表裡有完全一致的那條。沒有就加 Null0 靜態路由。
8
選路結果不如預期？show ip bgp <前綴> 看每條路徑的屬性，照 W-L-L-A-O-M 順序自己比一次。
! 三個方向的路由都要能查
R1# show ip bgp neighbors 203.0.113.1 received-routes   ! 對方送來的原始路由（需 soft-reconfiguration）
R1# show ip bgp neighbors 203.0.113.1 routes            ! 通過 in filter 之後留下的
R1# show ip bgp neighbors 203.0.113.1 advertised-routes ! 我送出去的

! 看 session 細節與錯誤原因
R1# show ip bgp neighbors 203.0.113.1
  Last reset 00:04:11, due to BGP Notification sent, hold time expired

R1# debug ip bgp 203.0.113.1 updates        ! 一定要指定鄰居，不然訊息量會爆
真實案例：「iBGP session 建起來了，但一條路由都沒有」

排查：show ip bgp summary → PfxRcd = 0。到對面 show ip bgp neighbors x advertised-routes → 有 12 條。

原因：對面是從另一個 iBGP 鄰居學到那些路由的，受 iBGP 水平分割限制不會再傳。修法：改成 Route Reflector 架構，或補上缺少的 iBGP session 湊成全網狀。

真實案例：「改了 route-map 之後路由全部消失」

排查：show route-map ISP-A-IN → 只有一個 permit 10 且有 match 條件。

原因：route-map 結尾隱含 deny any，不匹配 permit 10 的路由全被丟掉。修法：加一個空的 route-map ISP-A-IN permit 99 放行其餘。

完整實作 Lab：雙 ISP + Route Reflector + 政策控制

GNS3 或 CML（Packet Tracer 的 BGP 功能有限），約 90 分鐘。

拓樸

  [ ISP-A 64500 ]              [ ISP-B 64600 ]
    203.0.113.1                  198.51.100.1
         │                             │
    [ R1 邊界 ]                   [ R4 邊界 ]
    Lo0 1.1.1.1                   Lo0 4.4.4.4
         └──────┐            ┌─────────┘
                │            │
             [ R2 = RR ]  [ R3 = RR ]
             Lo0 2.2.2.2  Lo0 3.3.3.3
                  同一個 cluster-id

              本地 AS 65001
         自有網段 198.51.101.0/24

步驟

  1. 先跑 OSPF Area 0 讓所有 Loopback 互通（iBGP 的前提）
  2. 四台都設 bgp router-id 與 log-neighbor-changes
  3. R2、R3 設成 Route Reflector，cluster-id 相同；R1、R4 是 Client
  4. 所有 iBGP session 用 update-source loopback 0 + next-hop-self
  5. R1 對 ISP-A、R4 對 ISP-B 建立 eBGP，兩邊都設 password
  6. 宣告 198.51.101.0/24，並在 R1、R4 各加一條 Null0 靜態路由撐住這個前綴
  7. 入方向：兩家 ISP 都只收 預設路由（prefix-list DEFAULT-ONLY）
  8. 出方向：filter-list permit ^$，只宣告自己的網段
  9. 出方向流量偏好 ISP-A：對 ISP-A 學到的路由 set local-preference 200
  10. 入方向流量偏好 ISP-A：對 ISP-B 宣告時 as-path prepend 三次
  11. 兩個 eBGP 鄰居都設 maximum-prefix 10 restart 5

驗收清單

  • 所有 session 的 State/PfxRcd 欄位都是數字，沒有 Active 或 Idle
  • R2、R3 的 show ip bgp 都看得到 198.51.101.0/24（RR 反射成功）
  • R1 上的預設路由 Local Pref 是 200，R4 上的是 100
  • R4 上 show ip bgp neighbors 198.51.100.1 advertised-routes 的 AS_PATH 有三個 65001
  • 每台的 show ip bgp 都只有兩三條，沒有全表
  • 把 R1 的 eBGP shutdown → 流量在 3 分鐘內切到 R4／ISP-B

加碼挑戰

  1. 拿掉一台 RR 的 next-hop-self，觀察 show ip bgp 出現 inaccessible，再改回來。
  2. 把出方向的 filter-list ^$ 拿掉，觀察你是否開始把 ISP-A 的路由宣告給 ISP-B（＝變成中轉站）。
  3. 寫一個 route-map 只有 permit 10 + match，觀察路由全部消失，然後加上空的 permit 99 修好它。
  4. 建立一個 community 標記，用 show ip bgp community 65001:100 驗證，並確認忘記 send-community 時對方收不到。
  5. 用 clear ip bgp x.x.x.x soft in 與 clear ip bgp x.x.x.x 各做一次，比較 show ip bgp summary 的 Up/Down 計時器差異。

本章重點回顧

  • BGP 是路徑向量協定，跑在 TCP 179，鄰居必須手動指定
  • eBGP AD 20、TTL 1、會改 AS_PATH 和 Next-Hop；iBGP AD 200、都不改
  • iBGP 水平分割：從 iBGP 學到的不再傳給其他 iBGP → 需要全網狀或 Route Reflector
  • 所有 iBGP 鄰居都要 next-hop-self，不然路由會 inaccessible
  • BGP 的 network 用正常遮罩，而且路由表必須有完全一致的前綴（常用 Null0 撐住）
  • 選路口訣 W-L-L-A-O-M-e-I-R-R-R，實務只用前四項
  • 出方向用 Local Preference，入方向用 AS_PATH prepend
  • MED 只在同一鄰居 AS 之間比較，而且對方可以無視
  • 過濾是必要的：出方向 ^$ 防中轉，入方向擋私有網段和過細前綴
  • route-map 結尾有隱含 deny any，永遠補一個空的 permit
  • 套用政策用 soft reset，不要 clear ip bgp *
BGP 在 CCNA 只考基本概念（AS、eBGP/iBGP 差異、選路前幾項），CCNP ENCOR 才會深入考屬性和政策。去 模擬試題 選「路由技術」並勾選 CCNP 難度。
