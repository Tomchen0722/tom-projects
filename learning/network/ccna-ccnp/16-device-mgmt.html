1. CDP 與 LLDP：自動畫出拓撲

接手一個沒有文件的機房時，你面對的是幾十條沒標籤的線。
CDP/LLDP 就像每台設備都會自我介紹：「我是 SW-2F-01，我的 Gi0/1 接到你的 Gi0/24，我是 Catalyst 9300。」
CDPLLDP
標準Cisco 專有IEEE 802.1AB 開放標準
預設狀態Cisco 設備預設開啟多數 Cisco 設備預設關閉
Hello / Hold60 秒 / 180 秒30 秒 / 120 秒
混廠牌環境❌ 只認 Cisco✅ 跨廠牌可用
# CDP SW# show cdp neighbors ← 摘要 SW# show cdp neighbors detail ← 含對方 IP 與 IOS 版本 SW(config)# no cdp run ← 全域關閉 SW(config-if)# no cdp enable ← 單一介面關閉 # LLDP（要手動開） SW(config)# lldp run SW# show lldp neighbors detail
資安考點：CDP 應該關掉嗎？
CDP 會把設備型號、IOS 版本、管理 IP、介面名稱廣播出去——攻擊者接上一條線就拿到完整情資，還能據此查對應的已知漏洞。

標準做法：
• 面向使用者與外部的埠 → no cdp enable 關掉
• 交換器之間的骨幹埠 → 保留，維運要用

但有個例外：Cisco IP 電話依賴 CDP 取得語音 VLAN 資訊。接電話的埠關掉 CDP 會讓電話無法正常運作，這是實務上常見的自找麻煩。

2. NTP：所有排錯的前提

先講為什麼這件事很重要
設備時間不同步時會發生：
• 日誌無法比對——三台設備的事件時間各差幾分鐘，你排不出因果順序
• 憑證驗證失敗——時間超出憑證有效期就被拒（AP 註冊 WLC 失敗的經典原因）
• Kerberos 登入失敗——時鐘差超過 5 分鐘就不給過
• 稽核紀錄失去法律效力——時間戳記不可信

所以「先確認 NTP 有沒有同步」是排錯的第一步，不是最後一步。
Stratum:離原子鐘幾層 Stratum 0 原子鐘 / GPS（不直接連網） ↓ Stratum 1 直接接 Stratum 0 的伺服器 ↓ Stratum 2 向 Stratum 1 同步 ↓ Stratum 3 ...以此類推,最多到 15 Stratum 16 = 未同步（無效） 數字越小越權威。設備會挑 stratum 最小的來源。
# 基本設定 R1(config)# ntp server 10.1.1.100 prefer R1(config)# ntp server 10.1.1.101 R1(config)# clock timezone TPE 8 ← 台灣 UTC+8 # 讓日誌帶上精確時間（很重要） R1(config)# service timestamps log datetime msec localtime show-timezone R1(config)# service timestamps debug datetime msec # 驗證 R1# show ntp status Clock is synchronized, stratum 3, reference is 10.1.1.100 ← 要看到 synchronized R1# show ntp associations *~10.1.1.100 .GPS. 1 45 64 377 1.2 0.05 0.1 ← * 代表目前選用
NTP 驗證（考試會問）
攻擊者若能偽造 NTP 回應，就能把設備時間調亂，藉此讓憑證失效或干擾日誌。
R1(config)# ntp authenticate R1(config)# ntp authentication-key 1 md5 MySecretKey R1(config)# ntp trusted-key 1 R1(config)# ntp server 10.1.1.100 key 1
正式環境的 NTP 應該向內部的可信來源同步，而不是每台設備各自連到網際網路。

3. Syslog：八個嚴重等級

等級名稱意義要不要立刻處理
0Emergency系統無法使用🔴 立即
1Alert需要立即處理🔴 立即
2Critical嚴重狀況🔴 立即
3Error錯誤訊息🟠 儘快
4Warning警告🟡 觀察
5Notification正常但重要（介面 up/down）🟡 觀察
6Informational一般資訊⚪ 參考
7Debugging除錯訊息⚪ 排錯時才開
必考：設定的等級是「含以下全部」
設 logging trap 4 代表記錄等級 0 到 4（Emergency 到 Warning），不是只記等級 4。

記憶口訣（由 0 到 7）：Every Awesome Cisco Engineer Will Need Ice-cream Daily
（Emergency, Alert, Critical, Error, Warning, Notification, Informational, Debugging）

另一個必考：介面 up/down 是等級 5（Notification）。
# 送到 Syslog 伺服器 R1(config)# logging host 10.1.1.50 R1(config)# logging trap informational ← 送出 0-6 級 R1(config)# logging source-interface loopback 0 # 本機緩衝區 R1(config)# logging buffered 16384 debugging R1(config)# no logging console ← 建議關掉,否則 console 會被洗版 # SSH 連線時要看即時日誌 R1# terminal monitor R1# show logging
實務陷阱：不要在正式環境開 console logging
如果設備正在大量產生日誌（例如介面持續 flapping），console 輸出會佔用 CPU 並讓你連指令都打不進去。
標準做法：no logging console + logging buffered + 送到外部 Syslog 伺服器。

4. SNMP：三個版本的差別

SNMP 的三個角色 Manager（NMS 網管系統） │ │ ① Get / GetNext / GetBulk ── 主動去問 │ ② Set ── 去改設定 ↓ Agent（網路設備上的代理程式） │ │ ③ Trap / Inform ── 設備主動回報 ↓ Manager MIB = 可以查詢的資料項目清單（樹狀結構） OID = 每個項目的唯一編號,例如 1.3.6.1.2.1.1.5.0 = 主機名稱
版本驗證方式加密評價
v1Community String（明文）❌ 無❌ 不要用
v2cCommunity String（明文）❌ 無⚠️ 仍常見但不安全
v3使用者名稱 + 驗證✅ 可加密✅ 正式環境唯一正解
必考：SNMPv3 的三種安全等級
• noAuthNoPriv——不驗證、不加密（等於 v2c）
• authNoPriv——驗證但不加密（MD5 或 SHA）
• authPriv——驗證 + 加密（加上 DES/AES）← 正式環境要用這個

記法：auth = 確認是誰送的；Priv（Privacy）= 內容加密。
# v2c（僅供理解，正式環境不要用） R1(config)# snmp-server community MyRO ro 10 R1(config)# snmp-server community MyRW rw 10 ← rw 極危險 # v3（建議做法） R1(config)# snmp-server group NETADMIN v3 priv R1(config)# snmp-server user tomchen NETADMIN v3 auth sha AuthPass123 priv aes 128 PrivPass123 R1(config)# snmp-server host 10.1.1.50 version 3 priv tomchen R1(config)# snmp-server enable traps
Trap vs Inform（考試會問）
• Trap：送出去就算了，不確認對方有沒有收到（UDP，沒有回應）。
• Inform：要求對方確認，沒收到會重送。可靠但佔用較多資源。

重要告警（例如設備重開機）建議用 Inform，一般狀態用 Trap。

5. IOS Image 備份與升級

升級前一定要做的四件事
① 備份現有設定（copy running-config tftp:）
② 備份現有 IOS——出事才有東西可以退回
③ 確認 flash 空間夠（show flash:）
④ 核對新映像的完整性——比對 MD5，確保檔案沒損毀也沒被掉包

跳過第 ② 步是很多人升級失敗後回不去的原因。
1
檢查現況
R1# show version ← 目前版本與 flash 大小 R1# show flash: ← 現有檔案與剩餘空間 R1# dir flash:
2
備份設定與現有映像
R1# copy running-config startup-config R1# copy startup-config tftp: Address or name of remote host []? 10.1.1.50 Destination filename [r1-confg]? r1-backup-20260818.cfg R1# copy flash:c2900-universalk9-mz.SPA.157-3.M.bin tftp:
3
上傳新映像並驗證完整性
R1# copy tftp: flash: Address or name of remote host []? 10.1.1.50 Source filename []? c2900-universalk9-mz.SPA.158-3.M2.bin R1# verify /md5 flash:c2900-universalk9-mz.SPA.158-3.M2.bin ← 把結果與 Cisco 官網公布的 MD5 比對,不一致就不要用
4
設定開機順序並重開
R1(config)# boot system flash:c2900-universalk9-mz.SPA.158-3.M2.bin R1(config)# boot system flash:c2900-universalk9-mz.SPA.157-3.M.bin ← 舊版當備援 R1# copy running-config startup-config R1# reload # 重開後確認 R1# show version
保留兩行 boot system：新版開不起來時會自動退回舊版。
Configuration Register 的兩個常考值
• 0x2102——正常，開機讀取 startup-config
• 0x2142——略過 startup-config，用於密碼救援

密碼救援流程：開機時 Break → confreg 0x2142 → reset → 進入後 copy startup-config running-config（注意方向，不要反了，反了會清掉設定）→ 改密碼 → config-register 0x2102 → 存檔重開。

6. 設備加固標準流程

對應官方大綱的「保護管理存取」與「設備加固」兩項。

① 密碼加密service password-encryption（弱）
enable secret（強，用雜湊）
使用者密碼用 secret 不要用 password
② 只允許 SSH停用 Telnet：transport input ssh
並使用 SSHv2
③ 限制來源用 ACL 限定只有管理網段能連 VTY
④ 關閉未用服務關掉不需要的服務與未使用的實體埠
⑤ 登入橫幅banner motd 放法律警告（不要寫 Welcome）
⑥ 逾時與稽核exec-timeout 自動登出、AAA 記錄誰下了什麼指令
# SSH 設定（四個前置條件缺一不可） R1(config)# hostname R1 ← ① 要有主機名 R1(config)# ip domain-name example.com ← ② 要有網域名 R1(config)# crypto key generate rsa modulus 2048 ← ③ 要有金鑰(≥768 才能用 v2) R1(config)# username admin secret StrongPass ← ④ 要有本機帳號 R1(config)# ip ssh version 2 R1(config)# line vty 0 15 R1(config-line)# transport input ssh ← 只允許 SSH,擋掉 Telnet R1(config-line)# login local R1(config-line)# exec-timeout 5 0 R1(config-line)# access-class MGMT-ONLY in ← 限制來源網段 R1(config)# banner motd ^ ** 授權人員限定。所有存取行為均被記錄。 ** ^
陷阱：登入橫幅不要寫「Welcome」
這在資安與法律上是實際會被討論的問題——寫 Welcome 可能被辯稱為「系統邀請我進入」。
正確寫法是明確的授權警告：僅限授權人員、所有行為均被記錄、未經授權存取將依法處理。
陷阱：SSH 的四個前置條件
主機名、網域名、RSA 金鑰、本機帳號——缺任何一個 SSH 都起不來，而且錯誤訊息不一定明確。
另外 crypto key generate rsa 的 modulus 要 ≥ 768 才支援 SSHv2，實務上建議 2048。

7. 考試陷阱整理

陷阱 1：CDP 專有、LLDP 標準
CDP 預設開、LLDP 預設關。混廠牌要用 LLDP。
陷阱 2：Syslog 等級是「含以下全部」
logging trap 4 = 記錄 0–4 級。介面 up/down 是等級 5。
陷阱 3：SNMPv3 的 authPriv
只有 v3 能加密；authPriv 才是驗證加加密。
陷阱 4：Trap 不可靠、Inform 會確認
陷阱 5：Stratum 16 代表未同步
數字越小越權威，最大 15 有效。
陷阱 6：0x2142 是密碼救援
救援時是 copy startup-config running-config，方向不要反。
陷阱 7：SSH 四前置條件
主機名、網域名、RSA 金鑰、本機帳號。
✅ 一句話記憶：
畫拓撲用 CDP/LLDP，對時間用 NTP（排錯第一步），
看日誌用 Syslog（0–7 八級），做監控用 SNMPv3（authPriv），
升級前先備份舊映像，加固從只留 SSH 開始。
