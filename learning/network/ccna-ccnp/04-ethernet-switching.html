📦 乙太網路訊框結構

訊框（Frame）是 Layer 2 的資料單位。每一個從網路卡送出去的資料，都會被包成這個格式。

Preamble7 bytes
SFD1 byte
目的 MAC6 bytes
來源 MAC6 bytes
Type/Length2 bytes
Payload46–1500 bytes
FCS4 bytes
欄位長度作用
Preamble7 bytes10101010 重複 7 次，讓接收端的時脈同步（像賽跑前的「預備」）
SFD1 byte10101011，最後兩個 1 表示「訊框正式開始」
目的 MAC6 bytes要送給誰。FF:FF:FF:FF:FF:FF 表示廣播
來源 MAC6 bytes誰送出的。交換器就是靠這個欄位學習 MAC 表
Type/Length2 bytes>1536 是 Type（0x0800=IPv4, 0x0806=ARP, 0x86DD=IPv6）；≤1500 是長度
Payload46–1500實際資料（含 IP 封包）。不足 46 會補 Padding。1500 就是 MTU
FCS4 bytesCRC 錯誤檢查碼。算出來對不上就直接丟棄，不會重傳（重傳是 TCP 的事）
訊框總長度 = 64 bytes（最小）到 1518 bytes（最大，不含 Preamble/SFD）。加上 802.1Q VLAN Tag 的 4 bytes 後最大變 1522 bytes。Jumbo Frame 可以到 9000 bytes，常用於儲存網路（iSCSI）和資料中心。

🏷️ MAC 位址的組成

MAC 位址是 48 bits（6 bytes），燒錄在網路卡上，理論上全球唯一。寫法有三種但意義相同。

# 同一個 MAC 位址的三種寫法
00:1A:2B:3C:4D:5E     # 冒號分隔（Linux / 一般文件）
00-1A-2B-3C-4D-5E     # 連字號分隔（Windows）
001A.2B3C.4D5E        # 點分隔，每 4 位一組（Cisco）

# 結構拆解
00:1A:2B : 3C:4D:5E
^^^^^^^^   ^^^^^^^^
  OUI       NIC 序號
廠商代碼    廠商自行分配的流水號
(前 24 bit) (後 24 bit)

# 常見 OUI
00:50:56  →  VMware
00:0C:29  →  VMware
00:1B:44  →  Cisco
00:03:47  →  Intel
DC:A6:32  →  Raspberry Pi

第一個 byte 的兩個特殊 bit

第一個 byte: 0000 0000
                    ^^^^
                    ││
                    │└─ I/G bit（最低位）: 0 = 單播  1 = 群播/廣播
                    └── U/L bit（次低位）: 0 = 全球唯一  1 = 本地管理

# 判斷範例
00:1A:2B:...  第一 byte = 0x00 = 0000 0000 → 單播、全球唯一
01:00:5E:...  第一 byte = 0x01 = 0000 0001 → 群播（IPv4 Multicast 專用）
33:33:...     第一 byte = 0x33 = 0011 0011 → 群播（IPv6 Multicast 專用）
FF:FF:FF:...  全 1                          → 廣播

🧠 交換器如何學習與轉送

比喻：新來的郵差。第一天完全不認識住戶，所以每封信都挨家挨戶問（Flooding）。但他會記下「我在 3 樓收到王先生寄的信」→ 下次要送給王先生就直接去 3 樓（Forwarding）。這本筆記本就是 MAC 位址表。

學習機制：看「來源 MAC」

1
訊框進入某個 Port交換器讀取訊框的來源 MAC欄位
2
寫入 MAC 表記錄「來源 MAC ↔ 這個 Port ↔ VLAN」的對應關係
3
啟動老化計時器Cisco 預設 300 秒（5 分鐘）。這段時間沒再看到這個 MAC 就刪除
4
查詢目的 MAC用訊框的目的 MAC查表，決定要怎麼轉送

三種轉送行為（考試必考）

行為觸發條件做法
Forwarding
（轉送）		目的 MAC 在表中，且不在同一個 Port只送到那一個 Port，其他 Port 完全不受影響
Flooding
（氾濫）		① 目的 MAC 不在表中（Unknown Unicast）
② 廣播 FF:FF:FF:FF:FF:FF
③ 群播且沒設 IGMP Snooping		送到同 VLAN 的所有 Port，除了進來的那個
Filtering
（過濾／丟棄）		目的 MAC 就在進來的同一個 Port 上直接丟棄，不轉送（因為對方本來就收得到）

完整運作範例

# 初始狀態：MAC 表是空的
Switch# show mac address-table
  (empty)

# === 事件 1：PC-A(Fa0/1, MAC=AAAA) 送訊框給 PC-B(MAC=BBBB) ===
① 學習：來源 AAAA 從 Fa0/1 進來 → 記錄 [AAAA, Fa0/1, VLAN1]
② 查詢：目的 BBBB 不在表中 → Flooding 到 Fa0/2~Fa0/24
③ 結果：所有人都收到，但只有 PC-B 會處理

# === 事件 2：PC-B(Fa0/5, MAC=BBBB) 回覆給 PC-A ===
① 學習：來源 BBBB 從 Fa0/5 進來 → 記錄 [BBBB, Fa0/5, VLAN1]
② 查詢：目的 AAAA 在表中，對應 Fa0/1 → Forwarding 只送 Fa0/1
③ 結果：只有 PC-A 收到，其他 Port 完全沒流量

# 現在的 MAC 表
Switch# show mac address-table
Vlan  Mac Address       Type      Ports
1     aaaa.aaaa.aaaa    DYNAMIC   Fa0/1
1     bbbb.bbbb.bbbb    DYNAMIC   Fa0/5

三種交換模式（CCNP 範圍）

模式何時開始轉送延遲錯誤處理
Store-and-Forward收完整個訊框、驗證 FCS 後最高錯誤訊框直接丟棄（最安全，Cisco 預設）
Cut-Through只讀完前 6 bytes（目的 MAC）就轉最低錯誤訊框也會轉出去
Fragment-Free讀完前 64 bytes 才轉中等能擋掉大部分碰撞產生的殘片

⚡ 雙工、速度與碰撞域

半雙工 vs 全雙工

項目半雙工 Half-Duplex全雙工 Full-Duplex
比喻對講機（一次只能一個人講）電話（可以同時講和聽）
CSMA/CD需要（偵測碰撞）不需要（沒有碰撞）
頻寬使用100Mbps 收發共用收 100Mbps + 發 100Mbps
典型設備Hub（集線器，已淘汰）Switch（交換器，現代標準）
Duplex Mismatch — 最陰險的故障：一端設全雙工、另一端設半雙工。網路「會通」但速度極慢，ping 通但傳檔案龜速。半雙工那端會看到大量 collisions 和 late collisions。
診斷：show interfaces Fa0/1 看 late collision 數字持續增加。
解法：兩端都設 auto，或兩端都手動設成一樣。不要一端 auto、一端手動（手動端不參與協商，auto 端會退回半雙工）。 
# 手動設定速度與雙工
Switch(config)# interface GigabitEthernet0/1
Switch(config-if)# speed 1000            # 10 / 100 / 1000 / auto
Switch(config-if)# duplex full            # half / full / auto

# 檢查目前狀態（a- 前綴表示是協商來的）
Switch# show interfaces status
Port    Name  Status       Vlan  Duplex  Speed Type
Gi0/1         connected    1     a-full  a-1000 10/100/1000BaseTX
                                  ^^^^^^  ^^^^^^ ← a- = auto-negotiated

碰撞域 vs 廣播域

設備碰撞域數量廣播域數量
Hub（24 Port）1 個（全部共用）1 個
Switch（24 Port）24 個（每 Port 一個）1 個（除非切 VLAN）
Switch + 4 個 VLAN24 個4 個
Router（4 介面）4 個4 個（路由器不轉發廣播）
一句話總結：Switch 切碰撞域，Router（或 VLAN）切廣播域。這是 CCNA 最常考的觀念題。

🔗 線材與介面選擇

直通線 vs 交叉線

# 判斷法則：同類設備用交叉線，不同類設備用直通線

同類（Crossover 交叉線）：
  Switch ←→ Switch
  Router ←→ Router
  PC     ←→ PC
  Router ←→ PC          # 路由器和 PC 都算「主機端」

不同類（Straight-through 直通線）：
  PC     ←→ Switch
  Router ←→ Switch
  Server ←→ Switch

Console 線（Rollover，藍色扁線）：
  PC COM Port ←→ Switch/Router Console Port
現代設備幾乎都支援 Auto-MDIX，會自動偵測並調整，所以實務上用哪種線都能通。但 Packet Tracer 和考試仍會考這個規則。指令：mdix auto

光纖 vs 銅纜

類型距離速度用途
Cat5e UTP100m1 Gbps一般辦公室桌機
Cat6 UTP100m（10G 限 55m）10 Gbps新建置辦公室
Cat6a UTP100m10 Gbps資料中心接入層
多模光纖 MMF550m（1G）/ 300m（10G）10–100 Gbps樓層之間、機房內
單模光纖 SMF10–80 km10–400 Gbps園區之間、電信骨幹
DAC 銅纜1–7m10–100 Gbps機櫃內 Switch 對接（便宜、低延遲）

🔐 Port Security 完整設定

限制一個交換器 Port 上可以出現幾個 MAC 位址，防止有人私接 Hub 或做 MAC Flooding 攻擊。

MAC Flooding 攻擊原理

攻擊者用工具（如 macof）以每秒數千個假的來源 MAC 送訊框。交換器 MAC 表滿了之後（通常 8000–128000 筆），新的訊框全部變成 Unknown Unicast → Flooding，攻擊者就能用抓包工具看到整個 VLAN 的流量。

設定步驟

Switch(config)# interface FastEthernet0/1

# 步驟 1：Port 必須先是 access 模式（不能是 dynamic）
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 10

# 步驟 2：啟用 Port Security
Switch(config-if)# switchport port-security

# 步驟 3：設定最大 MAC 數量（預設 1）
Switch(config-if)# switchport port-security maximum 2
     # 為什麼常設 2？因為 IP 話機後面接 PC 就有 2 個 MAC

# 步驟 4：學習方式（三選一）
   方式 A：靜態綁定（最嚴格，但要一台一台設）
Switch(config-if)# switchport port-security mac-address aabb.ccdd.eeff

   方式 B：Sticky（動態學習後自動寫入 running-config，最實用）
Switch(config-if)# switchport port-security mac-address sticky

   方式 C：不設 = 動態學習，但重開機後清空

# 步驟 5：違規處理模式（三選一）
Switch(config-if)# switchport port-security violation shutdown   # 預設

三種違規模式差異（考試必考）

模式丟棄違規訊框Syslog/SNMP 通知違規計數器Port 關閉
protect✅❌❌❌
restrict✅✅✅❌
shutdown（預設）✅✅✅✅ err-disabled

Port 被關閉後怎麼恢復

# 方法 1：手動恢復（先排除問題再做）
Switch(config)# interface Fa0/1
Switch(config-if)# shutdown
Switch(config-if)# no shutdown

# 方法 2：設定自動恢復（300 秒後自動 no shut）
Switch(config)# errdisable recovery cause psecure-violation
Switch(config)# errdisable recovery interval 300

# 查看被關閉的原因
Switch# show interfaces status err-disabled
Switch# show errdisable recovery

驗證指令

Switch# show port-security                    # 所有 Port 的摘要
Switch# show port-security interface Fa0/1     # 單一 Port 詳細（最常用）
Switch# show port-security address            # 已綁定的 MAC 清單

# 輸出範例
Port Security              : Enabled
Port Status                : Secure-shutdown       ← 已違規被關
Violation Mode             : Shutdown
Maximum MAC Addresses      : 2
Total MAC Addresses        : 2

🔎 交換器驗證指令總整理

# === 介面狀態 ===
show interfaces status                  # 一覽：連線狀態、VLAN、雙工、速度
show interfaces Fa0/1                   # 單一介面詳細（錯誤計數在這）
show interfaces description             # 介面說明文字
show ip interface brief                 # IP 位址一覽
show interfaces counters errors         # 錯誤統計

# === MAC 位址表 ===
show mac address-table                  # 完整表
show mac address-table dynamic          # 只看動態學習的
show mac address-table interface Fa0/1  # 某 Port 學到的 MAC
show mac address-table count            # 統計數量
clear mac address-table dynamic         # 清除動態記錄

# === 需要注意的錯誤計數 ===
input errors      → 實體層問題（線材、接頭、干擾）
CRC               → 線材品質差或有電磁干擾
collisions        → 半雙工正常現象；全雙工出現就是設定錯
late collisions   → Duplex mismatch 或線材超長
runts             → 訊框小於 64 bytes（碰撞殘片）
giants            → 訊框大於 1518 bytes（MTU 設定不一致）
input queue drops → 交換器負載過高或有廣播風暴

🔬 Packet Tracer 實作 Lab

目標：觀察交換器學習過程，並設定 Port Security 阻擋未授權設備。

步驟

  1. 建拓樸：1 台 2960 Switch + 3 台 PC（Fa0/1、Fa0/2、Fa0/3），設同網段 IP
  2. 清空 MAC 表：clear mac address-table dynamic，確認 show mac address-table 是空的
  3. 觀察 Flooding：切到 Simulation 模式，PC1 ping PC2，觀察第一個 ARP 封包如何送到所有 Port
  4. 觀察學習：ping 完成後再看 show mac address-table，應該有 3 筆記錄
  5. 觀察 Forwarding：再 ping 一次，這次封包只走 PC1↔PC2 的路徑
  6. 設 Port Security：在 Fa0/1 設 maximum 1 + sticky + shutdown
  7. 觸發違規：把 PC1 拔掉，換接一台新 PC 到 Fa0/1
  8. 驗證：Port 燈變紅，show interfaces status 顯示 err-disabled
  9. 恢復：shutdown 再 no shutdown
  10. 加分：把違規模式改成 restrict，觀察 Port 不會關但違規計數會增加
