1. 連結狀態 vs 距離向量

距離向量（RIP、EIGRP）連結狀態（OSPF、IS-IS）
知道什麼只知道「往那個方向走 N 跳會到」知道整個網路的完整地圖
交換什麼自己的路由表自己的鏈路狀態（我有哪些介面、接到誰、成本多少）
怎麼算路徑相信鄰居說的（rumor by routing）自己跑 Dijkstra SPF 演算法算出最短路徑樹
迴圈風險高，需要毒性反轉、抑制計時器等機制區域內天生無迴圈
收斂速度慢快
CPU／記憶體低高（要存整張地圖 + 跑演算法）
比喻：距離向量像問路——「往前走遇到紅綠燈右轉」，你只知道下一步，完全信任告訴你的人。連結狀態像拿到一整張地圖——每個路口、每條路的距離你都知道，自己算出最短路線。地圖大所以要花記憶體，但你不會被錯誤的指路害到。
OSPF 的核心運作可以濃縮成四句話：
  1. 每台路由器把「我有哪些鏈路、成本多少」寫成 LSA
  2. LSA 在區域內氾濫（flooding）給每一台路由器
  3. 每台路由器把收到的 LSA 存進 LSDB（連結狀態資料庫）——同區域內每台的 LSDB 完全相同
  4. 每台路由器以自己為根跑 SPF，算出到每個目的地的最短路徑，放進路由表

2. 三張表與五種封包

三張表

表指令內容
鄰居表show ip ospf neighbor我跟誰建立了關係、現在什麼狀態
拓樸表（LSDB）show ip ospf database整個區域的地圖，同區域內每台都一樣
路由表show ip route ospfSPF 算完的結果，每台不同（因為根不同）
排錯的黃金順序：鄰居表 → 拓樸表 → 路由表。鄰居建不起來，後面兩張表一定空。鄰居 Full 但路由表沒東西，就去查 LSDB 和 area 設定。這個順序能省下大量時間。

五種 OSPF 封包（協定號 89）

Type名稱做什麼
1Hello找鄰居、維持鄰居關係、選 DR/BDR。送到 224.0.0.5
2DBD（Database Description）「我的 LSDB 裡有這些 LSA 的摘要」——只有標題，不含內容
3LSR（Link-State Request）「你剛剛提到的那幾筆我沒有，給我完整內容」
4LSU（Link-State Update）真正夾帶 LSA 的封包
5LSAck確認收到 LSU。OSPF 靠它做可靠傳輸
群播位址誰在聽
224.0.0.5AllSPFRouters — 所有 OSPF 路由器
224.0.0.6AllDRouters — 只有 DR 和 BDR
Hello 封包裡帶著八個欄位，其中五個必須完全一致才能成為鄰居——這是第 13 節排錯的核心，先記住有這件事。

3. 鄰居建立的七個狀態

Down→ Init→ 2-Way→ ExStart→ Exchange→ Loading→ Full
1
Down還沒收到任何 Hello。
2
Init我收到對方的 Hello 了，但那個 Hello 裡沒有列出我的 Router ID——代表對方還沒聽到我。單向。
3
2-Way對方的 Hello 裡有我的 Router ID → 雙向確認。DR/BDR 選舉就在這一刻進行。
4
ExStart用 DBD 決定誰是 Master、誰是 Slave（Router ID 大的當 Master），並協調序號。
5
Exchange互相交換 DBD——只有 LSA 的摘要，比對彼此少了什麼。
6
Loading用 LSR 索取缺少的 LSA，對方用 LSU 回覆，自己回 LSAck。
7
FullLSDB 完全同步。這才是正常的最終狀態。
有些教材說「OSPF 有 8 個狀態」，多的那個是 Attempt——只出現在 NBMA（Frame Relay）網路上，代表「我依設定主動對這個鄰居發單播 Hello，但還沒收到回應」。乙太網路和點對點鏈路永遠不會出現 Attempt，所以實務上只會看到上面這 7 個。考試看到 Attempt，答案一定跟 NBMA 有關。
2-Way 不一定是錯的。在廣播型網路（乙太網路）上，DROther 之間永遠停在 2-Way——這是設計如此，不是故障。

規則：
  • DROther ↔ DR：Full
  • DROther ↔ BDR：Full
  • DROther ↔ DROther：2-Way（正常！）
  • 點對點鏈路上：一定要 Full，卡在 2-Way 就是有問題
這樣設計是為了避免 N 台路由器建立 N(N−1)/2 個完整鄰接關係——10 台就要 45 組，LSDB 同步的流量會爆掉。
卡在特定狀態的常見原因：
卡在最可能的原因
Init單向通訊——對方收不到我的 Hello。查 ACL、查該介面是否 passive、查單向鏈路
ExStart / ExchangeMTU 不一致（最經典）。或 Router ID 重複
LoadingLSA 損毀或記憶體不足，罕見
不斷 Full ↔ Down 跳動Dead Timer 太短、線路不穩、CPU 過載
R1# show ip ospf neighbor
Neighbor ID     Pri   State           Dead Time   Address         Interface
2.2.2.2           1   FULL/DR         00:00:33    10.0.0.2        GigabitEthernet0/1
3.3.3.3           1   FULL/BDR        00:00:35    10.0.0.3        GigabitEthernet0/1
4.4.4.4           0   2WAY/DROTHER    00:00:31    10.0.0.4        GigabitEthernet0/1

! Dead Time 應該在 30~40 秒之間跳動（每收到 Hello 就重置回 40）
! 如果數字一直往下掉到 0，代表 Hello 收不到了

4. Router ID 的選擇順序

Router ID 是 OSPF 裡每台路由器的唯一身分，格式長得像 IP 但它不是 IP，只是一個 32 位元的識別碼。

1
手動設定的 router-id最高優先。企業一律手動設。
2
最高的 Loopback 介面 IP沒手動設就看這個。Loopback 永遠不會 down，所以比實體介面穩定。
3
最高的實體介面 IP最後才用這個。而且只看 up 狀態的介面。
! 標準做法：Loopback + 手動 Router ID，兩個都設且一致
R1(config)# interface loopback 0
R1(config-if)# ip address 1.1.1.1 255.255.255.255
R1(config-if)# exit
R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1
改了 Router ID 不會立刻生效。必須重啟 OSPF 程序： 
R1# clear ip ospf process
Reset ALL OSPF processes? [no]: yes
這會讓所有鄰居關係重建，流量中斷數秒到數十秒。絕對不要在上班時間做。
Router ID 重複的後果非常難查。兩台路由器 RID 相同時，症狀是：鄰居一直在 ExStart/Exchange 之間跳、LSDB 內容錯亂、路由時有時無。log 會出現： 
%OSPF-4-DUP_RTRID_NBR: OSPF detected duplicate router-id 2.2.2.2
from 10.0.0.5 on interface GigabitEthernet0/1
命名慣例：企業通常讓 Router ID 有意義，例如 10.255.1.1 代表「區域 1 的第 1 台」，或直接用 Loopback0 的位址。統一規則能讓你光看 show ip ospf neighbor 就知道是哪台機器。

5. 網路類型與 DR/BDR

網路類型預設用在選 DR/BDR？Hello / Dead要不要手動設鄰居
Broadcast乙太網路要10 / 40 秒不用
Point-to-PointSerial、PPP、子介面不要10 / 40 秒不用
Non-Broadcast (NBMA)Frame Relay 主介面要30 / 120 秒要
Point-to-MultipointFR 多點子介面不要30 / 120 秒不用
LoopbackLoopback 介面———
兩邊的網路類型不同 → Hello/Dead 計時器不同 → 鄰居建不起來。這是很常見的故障，尤其在把 Serial 換成乙太網路、或用 GRE Tunnel 的時候。用 show ip ospf interface gi0/1 看 Network Type 欄位。

為什麼需要 DR/BDR

N 台路由器在同一個乙太網段全互連 → N(N−1)/2 組鄰接
10 台 → 45 組。每次拓樸變動要氾濫 45 次。

DR 的做法：大家只跟 DR 和 BDR 建立完整鄰接，變成 N−1 組。DR 負責把 LSA 轉發給所有人，等於一個中央集散點。

選舉規則

1
比 OSPF Interface Priority預設 1，範圍 0–255，大的贏。設成 0 就是放棄參選。
2
Priority 相同 → 比 Router ID大的贏。注意方向和 STP 相反——STP 是 Bridge ID 小的贏。
DR 選舉是「非搶佔式」（non-preemptive）。選出來之後，就算來了一台 Priority 更高的路由器，也不會重選。只有在 DR 掛掉時，BDR 才升上來，然後重新選一個新的 BDR。

這代表：開機順序決定了誰是 DR。想指定特定機器當 DR，設完 priority 後要 clear ip ospf process 才會生效。 
! 讓核心路由器當 DR
R-CORE(config)# interface gigabitEthernet 0/1
R-CORE(config-if)# ip ospf priority 255

! 讓分公司路由器完全不參選
R-BRANCH(config)# interface gigabitEthernet 0/1
R-BRANCH(config-if)# ip ospf priority 0

! 把乙太介面改成點對點，直接跳過 DR 選舉（兩台對接時最推薦）
R1(config)# interface gigabitEthernet 0/1
R1(config-if)# ip ospf network point-to-point
實務技巧：兩台路由器用一條線直連時，把網路類型改成 point-to-point。好處：不用選 DR（省 40 秒收斂時間）、LSDB 少一筆 Type-2 LSA、設定更單純。這在資料中心和點對點骨幹上是標準做法。

6. Cost 計算與參考頻寬

Cost = 參考頻寬 ÷ 介面頻寬　（結果無條件捨去，最小值為 1）
預設參考頻寬 = 100 Mbps
介面速率預設 Cost（參考 100M）參考頻寬改成 100000 後
T1 (1.544 Mbps)6464766
10 Mbps1010000
100 Mbps11000
1 Gbps1 ⚠100
10 Gbps1 ⚠10
100 Gbps1 ⚠1
預設值在現代網路完全失效。100M、1G、10G 的 cost 全部都是 1，OSPF 分不出哪條線比較快，可能把 10 Gbps 骨幹和 100 Mbps 備線視為等價，做等價負載分擔——一半的流量塞進慢線。
! 解法 1：把參考頻寬提高（推薦，且必須全網一致）
R1(config)# router ospf 1
R1(config-router)# auto-cost reference-bandwidth 100000   ← 單位 Mbps，即 100 Gbps

! 解法 2：介面上直接指定 cost（覆蓋計算結果）
R1(config)# interface gigabitEthernet 0/1
R1(config-if)# ip ospf cost 20
參考頻寬必須全網統一。只改一台，那台算出來的路徑成本跟別人不同，會產生次佳路徑甚至路由迴圈。IOS 會警告你： 
% OSPF: Reference bandwidth is changed.
        Please ensure reference bandwidth is consistent across all routers.
Cost 是「出去的介面」在累加，跟 STP 的「進來的埠累加」方向相反。從 R1 到某網段，累加的是 R1 出口、R2 出口、R3 出口……最後那台連接目的網段的介面 cost 也要算。

7. 實作一：單區域 OSPF

方法 A：network 指令（傳統，考試常考）

R1(config)# router ospf 1              ← 這個 1 是 Process ID，只有本機意義
R1(config-router)# router-id 1.1.1.1
R1(config-router)# network 192.168.10.0 0.0.0.255 area 0
R1(config-router)# network 10.0.0.0 0.0.0.3 area 0
三個必須釐清的觀念：
  • Process ID 只有本機意義。R1 用 1、R2 用 100，照樣能建立鄰居。這跟 EIGRP 的 AS 號完全不同（那個必須一致）。
  • network 用的是 wildcard mask（反向遮罩），不是子網路遮罩。/24 → 0.0.0.255，/30 → 0.0.0.3。算法：255.255.255.255 − 子網路遮罩。
  • network 的真正意義是「哪些介面要跑 OSPF」，不是「宣告哪些網段」。它比對的是介面的 IP 位址。
network 的精確與寬鬆寫法
! 精確：只匹配 10.0.0.1 這一個介面（推薦，語意清楚）
R1(config-router)# network 10.0.0.1 0.0.0.0 area 0

! 網段：匹配 10.0.0.0/30 內的介面
R1(config-router)# network 10.0.0.0 0.0.0.3 area 0

! 全匹配：所有介面都跑 OSPF（危險，會把 WAN 介面也丟進去）
R1(config-router)# network 0.0.0.0 255.255.255.255 area 0

方法 B：介面模式（現代，推薦）

R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1
R1(config-router)# exit

R1(config)# interface gigabitEthernet 0/0
R1(config-if)# ip ospf 1 area 0
R1(config)# interface gigabitEthernet 0/1
R1(config-if)# ip ospf 1 area 0
為什麼推薦介面模式？不用算 wildcard mask、不會誤把不該加的介面加進去、看介面設定就知道它在哪個 area。實務上新建網路幾乎都用這種。但考試還是會考 network 指令，兩種都要會。

passive-interface：不要對使用者網段送 Hello

! 單獨設定某個介面
R1(config-router)# passive-interface gigabitEthernet 0/0

! 推薦做法：全部 passive，再把需要建鄰居的挑出來
R1(config-router)# passive-interface default
R1(config-router)# no passive-interface gigabitEthernet 0/1
R1(config-router)# no passive-interface gigabitEthernet 0/2
passive-interface 的效果
該網段還會不會被宣告出去會（路由資訊照常傳播）
該介面還會不會送 Hello不會
該介面能不能建立鄰居不能
為什麼一定要設 passive？
  • 資安：使用者網段上有人跑一個假 OSPF 就能注入惡意路由，把流量導到自己機器上（中間人攻擊）
  • 效能：對著 200 台電腦每 10 秒廣播一次 Hello，純粹浪費
這是 CCNA 考試和資安稽核都會檢查的項目。

8. 多區域架構與 LSA 六種類型

單一區域的問題：拓樸一變，整個區域每台路由器都要重跑 SPF。100 台路由器的網路，任何一條線閃一下，全部 CPU 一起飆。多區域把爆炸範圍切開。

Area 0 = Backbone（骨幹區域）
所有其他區域都必須直接連到 Area 0

四種路由器角色

角色全名定義
Internal Router內部路由器所有介面都在同一個區域
Backbone Router骨幹路由器至少一個介面在 Area 0
ABRArea Border Router同時連接 Area 0 和其他區域。負責產生 Type-3 LSA
ASBRAS Boundary Router把外部路由（靜態、BGP、其他協定）重分佈進 OSPF。產生 Type-5 LSA

LSA 六種類型（CCNP 必考，CCNA 考 1/2/3/5）

Type 1 · Router LSA每台路由器描述「我有哪些鏈路、成本多少、接到誰」。只在本區域內氾濫，不跨區。每台都會產生。
Type 2 · Network LSA由 DR 產生，描述「這個多重存取網段上有哪些路由器」。只在本區域內氾濫。點對點鏈路不會有。
Type 3 · Summary LSA由 ABR 產生，把區域 A 的網段告訴區域 B。只傳前綴和成本，不傳拓樸細節——這是多區域省 CPU 的關鍵。
Type 4 · ASBR Summary LSA由 ABR 產生，告訴其他區域「要去 ASBR 該往哪走」。因為 Type-5 不含到 ASBR 的路徑資訊。
Type 5 · External LSA由 ASBR 產生，描述 OSPF 以外的路由（靜態、BGP、RIP 重分佈進來的）。氾濫到整個 OSPF 網域（Stub 區域除外）。
Type 7 · NSSA External LSA只存在於 NSSA 區域內。到了 ABR 會被轉換成 Type 5 再往外傳。用來解決「Stub 區域裡有 ASBR」的矛盾。
速記：
  • 1 = 我自己（每台都發）
  • 2 = 這個網段（DR 發）
  • 3 = 隔壁區域有什麼（ABR 發）
  • 4 = ASBR 在那邊（ABR 發）
  • 5 = 外面的世界（ASBR 發）
  • 7 = NSSA 版的 5（NSSA 內的 ASBR 發）

E1 vs E2：外部路由的兩種成本計算

E2（預設）E1
成本怎麼算只算外部成本，內部路徑成本忽略外部成本 + 內部路徑成本
結果不管離 ASBR 多遠，成本都一樣離 ASBR 愈近成本愈低
什麼時候用只有一個出口，簡單有多個 ASBR 時，才選得出最近的那個
雙 ISP 出口一定要改成 E1。用預設的 E2，兩個出口的成本都一樣，路由器無法判斷哪個 ISP 比較近，可能把流量送去繞遠路那台。default-information originate metric-type 1。

10.0.0.2        2.2.2.2         389    0x80000002 0x005E6F

                Summary Net Link States (Area 0)
Link ID         ADV Router      Age    Seq#       Checksum
192.168.30.0    2.2.2.2         201    0x80000003 0x00778A

! 看某一筆的完整內容
R1# show ip ospf database router 2.2.2.2
Age 超過 3600 秒（1 小時）的 LSA 會被清除。正常情況下每 30 分鐘（LSRefreshTime）原始產生者會刷新一次，Age 歸零。如果看到 Age 一直逼近 3600 沒被刷新，代表產生者可能失聯了。

9. 特殊區域：Stub / Totally Stubby / NSSA

分公司通常只有一條線出去，卻要背負整個公司的完整 LSDB，浪費記憶體和 CPU。特殊區域的做法是：擋掉某些 LSA，改用一條預設路由代替。

區域類型Type 3
（跨區）		Type 4/5
（外部）		Type 7ABR 注入預設路由
Normal✅✅❌否
Stub✅❌ 擋掉❌是（0.0.0.0）
Totally Stubby
（Cisco 專有）		❌ 擋掉❌ 擋掉❌是
NSSA✅❌ 擋掉✅可選
Totally NSSA❌ 擋掉❌ 擋掉✅是
怎麼選？
  • 分公司只有一條線出去、沒有外部路由 → Totally Stubby（LSDB 最小）
  • 分公司有自己的外部路由要注入（例如接了另一家 ISP、或有靜態路由要宣告）→ NSSA
  • 不確定就用 Stub，相容性最好（Totally Stubby 是 Cisco 專有）
! ── Stub：區域內每一台都要設，包含 ABR ──
R-ABR(config)# router ospf 1
R-ABR(config-router)# area 10 stub
R-BRANCH(config-router)# area 10 stub

! ── Totally Stubby：只有 ABR 多加 no-summary ──
R-ABR(config-router)# area 10 stub no-summary       ← ABR 才要加
R-BRANCH(config-router)# area 10 stub                ← 內部路由器一樣只寫 stub

! ── NSSA ──
R-ABR(config-router)# area 20 nssa
R-BRANCH(config-router)# area 20 nssa

! ── NSSA 內的 ASBR 把靜態路由注入（會變成 Type 7）──
R-BRANCH(config-router)# redistribute static subnets
Stub 區域的三個硬性限制：
  1. 區域內每一台路由器都必須設成 stub，漏一台就建不起鄰居——因為 Hello 封包裡的 E bit 必須一致
  2. Area 0 不能是 Stub（骨幹必須能傳遞所有資訊）
  3. Stub 區域內不能有 ASBR（要有的話就得改用 NSSA）
! 驗證：分公司路由器的路由表應該只剩一條預設路由
R-BRANCH# show ip route ospf
O*IA  0.0.0.0/0 [110/2] via 10.0.10.1, 00:03:11, GigabitEthernet0/0

! LSDB 應該小很多
R-BRANCH# show ip ospf database database-summary

10. 實作二：多區域 + 彙總 + 預設路由

多區域設定

! ═══ R-ABR：一腳在 Area 0，一腳在 Area 10 ═══
R-ABR(config)# router ospf 1
R-ABR(config-router)# router-id 2.2.2.2
R-ABR(config-router)# exit

R-ABR(config)# interface gigabitEthernet 0/0
R-ABR(config-if)# ip ospf 1 area 0          ← 往骨幹
R-ABR(config)# interface gigabitEthernet 0/1
R-ABR(config-if)# ip ospf 1 area 10         ← 往分公司

區域間彙總（在 ABR 上做）

! Area 10 裡有 192.168.16.0/24 ~ 192.168.23.0/24 共 8 個網段
! 彙總成一條再送進 Area 0
R-ABR(config-router)# area 10 range 192.168.16.0 255.255.248.0

外部路由彙總（在 ASBR 上做）

R-ASBR(config-router)# summary-address 172.16.0.0 255.255.0.0
兩個彙總指令用錯地方是常見錯誤：
指令在哪台彙總什麼
area X rangeABRType 3（區域之間）
summary-addressASBRType 5（外部重分佈進來的）
在 ABR 上打 summary-address 不會有效果，也不會報錯——這種「打了但沒作用」的情況最難查。
彙總的副作用：ABR 會自動產生一條指向 Null0 的路由。這是防迴圈設計——彙總範圍內若有網段不存在，流量會被丟進 Null0 而不是繞回來。看到 O 192.168.16.0/21 is directly connected, Null0 是正常的。

注入預設路由

! ASBR 上：把預設路由宣告給整個 OSPF 網域
R-EDGE(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1
R-EDGE(config)# router ospf 1
R-EDGE(config-router)# default-information originate

! always：就算自己沒有預設路由也照樣宣告（謹慎使用）
R-EDGE(config-router)# default-information originate always

! 雙出口環境：改成 E1 讓成本可比較
R-EDGE(config-router)# default-information originate metric 10 metric-type 1
always 的風險：就算這台自己上不了網，它還是會跟全公司說「往我這走可以出去」。結果全公司流量湧向一台不通的路由器，形成黑洞。只有在你另外用 IP SLA 確認過線路狀態時才加 always。

重分佈（把其他協定引進 OSPF）

R-ASBR(config-router)# redistribute static subnets metric 20 metric-type 1
R-ASBR(config-router)# redistribute connected subnets
R-ASBR(config-router)# redistribute eigrp 100 subnets metric 30
忘記 subnets 關鍵字是經典陷阱。不加的話，只有主類別網路（classful）會被重分佈，所有 /24、/30 這種子網路都會被默默忽略。設定看起來完全正確，但路由就是不出現。

11. 實作三：認證與加固

沒有認證的 OSPF 是開放的。任何人接進網路、跑一個 OSPF 程序，就能：宣告自己有最短路徑把流量吸過來（中間人）、注入大量假路由塞爆 LSDB（阻斷服務）、或宣告一條假的預設路由把全公司流量導向自己。

方法 A：介面層級 MD5（傳統，考試考這個）

R1(config)# interface gigabitEthernet 0/1
R1(config-if)# ip ospf authentication message-digest
R1(config-if)# ip ospf message-digest-key 1 md5 Str0ngOspfKey!

! 或整個區域一次開
R1(config)# router ospf 1
R1(config-router)# area 0 authentication message-digest

方法 B：SHA 金鑰鏈（現代，推薦）

R1(config)# key chain OSPF-KEYS
R1(config-keychain)# key 1
R1(config-keychain-key)# key-string Str0ngOspfKey2025!
R1(config-keychain-key)# cryptographic-algorithm hmac-sha-256
R1(config-keychain-key)# exit

R1(config)# interface gigabitEthernet 0/1
R1(config-if)# ip ospf authentication key-chain OSPF-KEYS
認證不一致 = 鄰居直接建不起來，而且沒有明顯錯誤。啟用認證時兩邊要同時做，或先用 debug ip ospf adj 確認。遠端操作時，只在一邊開會立刻失去該路由器的連線。

看得到的線索： 
%OSPF-4-BADLSATYPE 或
OSPF: Rcv pkt from 10.0.0.2 : Mismatch Authentication type

其他加固項目

! 1. 全部介面 passive，只開需要的（第 7 節講過，再強調一次）
R1(config-router)# passive-interface default
R1(config-router)# no passive-interface gigabitEthernet 0/1

! 2. 限制 LSDB 大小，防止有人灌爆你的記憶體
R1(config-router)# max-lsa 12000

! 3. 記錄鄰居變化（排錯時非常有用）
R1(config-router)# log-adjacency-changes detail

! 4. 用 ACL 只允許已知鄰居的 OSPF 封包
R1(config)# ip access-list extended OSPF-PEERS
R1(config-ext-nacl)# permit ospf host 10.0.0.2 any
R1(config-ext-nacl)# deny ospf any any log
R1(config-ext-nacl)# permit ip any any
R1# show ip ospf interface gi0/1 | include authentication|Message
  Message digest authentication enabled
    Youngest key id is 1

12. 收斂調校

參數預設調校後效果
Hello / Dead10 / 40 秒1 / 4 秒 或用 BFD更快發現鄰居掛掉
SPF 計算延遲5000 / 10000 ms50 / 200 / 5000 ms第一次變動立刻算，連續變動才退避
LSA 產生間隔—10 / 100 / 5000 ms更快把變動傳出去
! ── 調整 Hello/Dead（兩邊必須一致）──
R1(config)# interface gigabitEthernet 0/1
R1(config-if)# ip ospf hello-interval 1
R1(config-if)# ip ospf dead-interval 4

! ── SPF 節流：初始 50ms、遞增 200ms、上限 5000ms ──
R1(config)# router ospf 1
R1(config-router)# timers throttle spf 50 200 5000
R1(config-router)# timers throttle lsa 10 100 5000
比調計時器更好的方案：BFD。Hello 調到 1 秒會讓 CPU 一直忙。BFD（Bidirectional Forwarding Detection）是專門做「快速偵測鏈路死亡」的輕量協定，可以在毫秒級發現故障，然後通知 OSPF。而且一個 BFD session 可以同時服務 OSPF、BGP、EIGRP。 
R1(config)# interface gigabitEthernet 0/1
R1(config-if)# bfd interval 50 min_rx 50 multiplier 3
R1(config-if)# exit
R1(config)# router ospf 1
R1(config-router)# bfd all-interfaces
不要盲目把計時器調到最短。線路輕微抖動就會觸發全網重新收斂，反而比慢一點更不穩定。企業實務的順序是：先用 BFD → 不支援才調 SPF throttle → 最後才動 Hello/Dead。

13. 故障排除：鄰居建不起來的八個原因

Hello 封包裡這五個欄位必須完全一致，否則絕不成為鄰居：
  1. Area ID
  2. Hello Interval
  3. Dead Interval
  4. 認證類型與密碼
  5. Stub Flag（E bit）
另外 子網路遮罩也必須一致（點對點鏈路除外）。
#原因怎麼確認
1介面 downshow ip interface brief
2介面沒被 OSPF 啟用show ip ospf interface brief 看有沒有那個介面
3設成 passive-interfaceshow ip protocols 的 Passive Interface(s) 清單
4Area ID 不一致show ip ospf interface gi0/1 | include Area 兩邊比對
5Hello/Dead 不一致同上，看 Timer intervals
6認證不一致debug ip ospf adj 會直接說 Mismatch Authentication
7子網路遮罩不一致一邊 /24 一邊 /25 → Hello 被丟棄
8MTU 不一致卡在 ExStart/Exchange。show interfaces gi0/1 | include MTU

MTU 不一致的細節

! 症狀：鄰居永遠在 EXSTART 或 EXCHANGE 之間反覆
R1# show ip ospf neighbor
Neighbor ID     Pri   State      Dead Time   Address     Interface
2.2.2.2           1   EXSTART/DR  00:00:36    10.0.0.2    Gi0/1

! log 訊息
%OSPF-5-ADJCHG: Process 1, Nbr 2.2.2.2 on Gi0/1 from EXCHANGE to DOWN,
Neighbor Down: Too many retransmissions

! 正解：把 MTU 改一致
R1(config-if)# mtu 1500

! 應急解（不建議，只是繞過檢查，實際仍可能丟大封包）
R1(config-if)# ip ospf mtu-ignore

排錯指令清單

R1# show ip ospf neighbor                    ! 第一站
R1# show ip ospf interface brief             ! 哪些介面在跑、在哪個 area
R1# show ip protocols                        ! RID、network 語句、passive 清單
R1# show ip ospf database database-summary   ! 各類 LSA 數量，一眼看出異常
R1# show ip ospf border-routers              ! 到 ABR/ASBR 的路徑
R1# show ip ospf statistics                  ! SPF 跑了幾次、多久跑一次

! debug 前先開時間戳記，並確認 CPU 有餘裕
R1(config)# service timestamps debug datetime msec
R1# debug ip ospf adj          ! 鄰居建立過程
R1# debug ip ospf hello        ! Hello 封包內容
R1# undebug all                ! 用完一定要關
正式環境 debug 前務必先看 CPU。show processes cpu sorted | include CPU。CPU 已經 60% 以上就不要開 debug——大量除錯訊息可能直接把路由器打掛。真的需要就配 ACL 限制範圍：debug ip ospf adj 前先 debug condition interface gi0/1。
真實案例：「新接的分公司路由器一直建不起鄰居」

症狀：兩邊介面都 up/up，能互相 ping 通，但 show ip ospf neighbor 是空的。

排查：show ip ospf interface gi0/1 兩邊比對 → 總部是 Area 0，分公司打成了 Area 10。

原因：Area ID 不一致，Hello 直接被丟棄，連 Init 都到不了。啟示：能 ping 通完全不代表 OSPF 會建立——它們是不同層次的檢查。

真實案例：「加了 GRE Tunnel 之後 OSPF 卡在 EXSTART」

排查：show interfaces tunnel0 | include MTU → 一邊 1476、另一邊 1400（對方多套了 IPsec）。

原因：MTU 不一致，DBD 封包大小協商失敗。修法：兩邊統一 ip mtu 1400，並加 ip tcp adjust-mss 1360。

完整實作 Lab：三區域 OSPF + 認證 + 彙總 + 外部路由

Packet Tracer 或 GNS3，約 100 分鐘。這個 Lab 涵蓋 CCNA OSPF 的全部考點。

拓樸

                       [ ISP ] 203.0.113.1
                          │
                   [ R1 = ASBR ]  Lo0 1.1.1.1
                          │ Area 0
                   [ R2 = 骨幹 ]  Lo0 2.2.2.2
              Area 0 ┌────┴────┐ Area 0
        [ R3 = ABR ]           [ R4 = ABR ]
         Lo0 3.3.3.3            Lo0 4.4.4.4
              │ Area 10              │ Area 20 (NSSA)
        [ R5 台北 ]              [ R6 台中 ]
         Lo0 5.5.5.5             Lo0 6.6.6.6
      192.168.16-23.0/24      192.168.32.0/24
                              + 一條靜態路由要注入

步驟

  1. 每台都設 Loopback0 並手動指定 router-id（1.1.1.1 ~ 6.6.6.6）
  2. 全部改用介面模式啟用 OSPF（ip ospf 1 area X）
  3. 全網統一 auto-cost reference-bandwidth 100000
  4. 所有 LAN 介面設 passive-interface（用 default 再挑出例外）
  5. R2–R3、R2–R4 的鏈路改成 ip ospf network point-to-point
  6. Area 0 開啟 MD5 認證，所有相關介面都要設
  7. R3 把 Area 10 設成 Totally Stubby（R3 加 no-summary，R5 只寫 stub）
  8. R3 上做區域彙總：把 192.168.16.0 ~ 192.168.23.0 合成一條（自己算遮罩）
  9. R4 把 Area 20 設成 NSSA，R6 上 redistribute static subnets
  10. R1 設靜態預設路由到 ISP，並 default-information originate metric-type 1
  11. 全網開啟 log-adjacency-changes detail

驗收清單

  • 所有鄰居都是 FULL（點對點鏈路上不能有 2WAY）
  • R5 的 show ip route ospf 只有一條 O*IA 0.0.0.0/0
  • R2 的路由表看得到彙總後的 /21，看不到 8 條 /24 明細
  • R3 上有一條 O 192.168.16.0/21 is directly connected, Null0
  • R2 上 show ip ospf database nssa-external 是空的（Type 7 沒有跨出 Area 20）
  • R2 上看得到 R6 注入的路由，代碼是 O E1 或 O E2（已被 R4 轉換成 Type 5）
  • R5、R6 都 ping 得到 8.8.8.8
  • show ip ospf database database-summary 在 R5 上的總數明顯小於 R2

加碼挑戰

  1. 把 R3 的 Area 10 介面 MTU 改成 1400，觀察鄰居卡在 EXSTART，用 debug ip ospf adj 確認訊息後改回來。
  2. 故意把 R5 的 router-id 改成 3.3.3.3（跟 R3 重複），觀察 log 出現什麼、鄰居行為如何異常。
  3. 把 R2–R3 的 cost 手動調高，用 show ip route 觀察 R2 到 Area 10 的路徑是否改走 R4 繞路。
  4. 在 R5 上算出「到 192.168.32.0/24 的完整 cost 累加過程」，並用 show ip ospf database 逐段驗證你的計算。
  5. 把 Area 10 從 Totally Stubby 改成一般區域，比較 R5 的 show ip ospf database database-summary 數字差多少。

本章重點回顧

  • OSPF 是連結狀態協定：交換 LSA → 建立相同的 LSDB → 各自跑 SPF
  • 三張表順序排錯：鄰居 → 拓樸 → 路由
  • 狀態機：Down → Init → 2-Way（選 DR） → ExStart → Exchange → Loading → Full
  • 廣播網路上 DROther 之間停在 2-Way 是正常的
  • Router ID：手動 > 最高 Loopback > 最高實體介面。改了要 clear ip ospf process
  • DR 選舉：Priority 大的贏，其次 Router ID 大的贏（跟 STP 方向相反），且不搶佔
  • Cost = 參考頻寬 ÷ 介面頻寬。預設 100M 在現代網路失效，必須全網一起調高
  • LSA：1 我自己、2 這網段、3 隔壁區、4 ASBR 在那、5 外面世界、7 NSSA 版的 5
  • Stub 擋 4/5，Totally Stubby 連 3 也擋，NSSA 允許區域內有 ASBR
  • area X range 用在 ABR；summary-address 用在 ASBR
  • 鄰居建不起來先查五要素：Area、Hello、Dead、認證、Stub flag；卡 ExStart 就查 MTU
OSPF 是 CCNA 的最大單一考點。去 模擬試題 選「路由技術」練到全對，尤其是 DR 選舉和 LSA 類型的題目。
