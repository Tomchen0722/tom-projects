1. 為什麼要有 VLAN

先回到上一章的結論：交換器切碰撞域，路由器切廣播域。這句話有個很現實的問題——如果一家公司有 200 台電腦全接在同一組交換器上，它們就全在同一個廣播域。任何一台電腦發 ARP 廣播，其他 199 台都要收、都要拆封包判斷「是不是問我」。

用辦公室來想：整層樓是一個大開放空間，任何人要找同事都得站起來大喊。人少的時候還好，200 個人同時這樣做，整層樓就只剩噪音。

VLAN 做的事，就是在同一層樓裡拉起隔音牆，把業務部、工程部、財務部隔開。喊話只在自己的區域內傳，跨區要找人得走正式管道（路由器）。而且隔音牆是「用軟體畫的」——要調整部門位置，改設定就好，不用真的拆牆。

沒有 VLAN 的四個問題

問題實際會發生什麼VLAN 怎麼解
廣播風暴放大一個迴圈或一張壞網卡狂發廣播，整棟樓網路全掛爆炸範圍被限制在單一 VLAN 內
沒有資安邊界訪客筆電插上會議室網路孔，就跟財務部同網段，可以直接掃描訪客丟到 VLAN 40，跨 VLAN 要過 ACL
實體位置綁死邏輯分組工程師換座位到三樓，IP 網段就得跟著改把那個埠設成 VLAN 20，IP 完全不用動
沒辦法差別對待流量VoIP 電話跟下載大檔案的電腦搶頻寬，通話就會斷斷續續語音獨立 VLAN，搭配 QoS 優先處理
VLAN 的完整定義：一個 VLAN 就是一個廣播域，也就是一個 IP 子網路。這兩件事在企業網路裡幾乎永遠是 1:1 對應。所以規劃 VLAN 的同時就是在規劃子網路——上一章 CH 1-2 的 VLSM 切法，這裡直接派上用場。
實務範例：一家 180 人公司的 VLAN 規劃
VLAN 10 · 業務部192.168.10.0/24 · 60 人
VLAN 20 · 工程部192.168.20.0/24 · 80 人
VLAN 30 · 財務部192.168.30.0/26 · 12 人
VLAN 40 · 訪客192.168.40.0/24 · 隔離
VLAN 50 · 語音192.168.50.0/24 · IP 電話
VLAN 99 · 管理192.168.99.0/28 · 設備自己

注意財務部只有 12 人卻不給 /24——用 /26（62 個可用）就夠了，剩下的位址留給未來其他部門。這就是 VLSM 的用途。管理 VLAN 更只給 /28（14 個），因為那裡面只有交換器和路由器自己的管理位址。

VLAN ID 的合法範圍

範圍名稱可否刪除存在哪裡

1Default VLAN不能刪vlan.dat
2 – 1005Normal Range（常用範圍）可以快閃記憶體的 vlan.dat

考試最愛考、實務最容易踩的陷阱：VLAN 設定不在 running-config 裡。

Normal Range 的 VLAN 存在一個叫 vlan.dat 的獨立檔案，放在 flash。所以：
  • write erase + reload 清不掉 VLAN，交換器重開後 VLAN 還在
  • 真正要清乾淨必須加上 delete flash:vlan.dat
  • 備份 config 的時候如果只存 running-config，VLAN 資料庫沒被備份到
! 把一台二手交換器徹底恢復原廠（實驗室交接標準流程）
Switch# write erase
Switch# delete flash:vlan.dat
Delete filename [vlan.dat]? <Enter>
Delete flash:/vlan.dat? [confirm] <Enter>
Switch# reload
System configuration has been modified. Save? [yes/no]: no   ← 一定要 no

3. 實作一：建立 VLAN 與 Access Port

Access Port（存取埠）是接末端裝置的埠——電腦、印表機、監視器。它的規則很單純：一個 Access Port 只屬於一個 Data VLAN，進出的訊框都不帶標籤。電腦完全不知道 VLAN 存在，交換器自己在內部記住「這個埠是 VLAN 10」。

步驟拆解

1
建立 VLAN 並命名名稱只是給人看的備註，不影響運作，但沒有名稱的 VLAN 半年後你會看不懂。
2
把埠改成 Access 模式不寫這行，埠會停留在預設的 dynamic auto，有機會被對面協商成 Trunk。
3
指定埠屬於哪個 VLAN如果指定一個還不存在的 VLAN，IOS 會自動幫你建立（但沒有名稱）。
4
關掉 DTP 協商switchport nonegotiate。接電腦的埠不需要協商，關掉可以省一點時間也少一個攻擊面。
5
開啟 PortFast + BPDU Guard讓埠插上線立刻可用（不用等 STP 30 秒），同時防止有人偷接交換器。細節在 CH 2-3。
! ── 步驟 1：建立 VLAN ──────────────────────
Switch# configure terminal
Switch(config)# vlan 10
Switch(config-vlan)# name SALES
Switch(config-vlan)# exit
Switch(config)# vlan 20
Switch(config-vlan)# name ENGINEERING
Switch(config-vlan)# exit
Switch(config)# vlan 30
Switch(config-vlan)# name FINANCE
Switch(config-vlan)# exit

! ── 步驟 2~5：一次設定一整排埠 ──────────────
Switch(config)# interface range fastEthernet 0/1 - 8
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# switchport access vlan 10
Switch(config-if-range)# switchport nonegotiate
Switch(config-if-range)# spanning-tree portfast
Switch(config-if-range)# spanning-tree bpduguard enable
Switch(config-if-range)# description == SALES USER PORTS ==
Switch(config-if-range)# no shutdown
interface range fa0/1 - 8 一次設定 8 個埠。不連續的埠可以用逗號：interface range fa0/1 - 4 , fa0/9 , fa0/12 - 15。注意逗號和減號前後都要有空格，這是 IOS 的怪規則。

驗證：三個必看指令

4. 802.1Q 標籤到底加了什麼

問題來了：兩台交換器之間只有一條線，Sales（VLAN 10）和 Engineering（VLAN 20）的流量都要走。訊框到了對面，對面交換器怎麼知道這個訊框屬於哪個 VLAN？

答案是 IEEE 802.1Q：在原本的乙太訊框裡插入 4 個位元組的標籤，位置就在來源 MAC 之後、型態欄位之前。

原本的訊框

目的 MAC6 bytes
來源 MAC6 bytes
Type2 bytes
資料46–1500 bytes
FCS4 bytes

加上 802.1Q 標籤之後

目的 MAC6 bytes
來源 MAC6 bytes
TPID0x8100
PCP3 bits
DEI1 bit
VLAN ID12 bits
Type2 bytes
資料46–1500 bytes
FCS重算
欄位長度值意義
TPID16 bits固定 0x8100告訴接收端「我後面有 VLAN 標籤，別照一般訊框解讀」
PCP3 bits0 – 7優先權，也叫 CoS。QoS 就是靠這 3 個位元分等級，語音通常設 5
DEI1 bit0 / 1壅塞時這個訊框可不可以先丟掉。舊名 CFI
VLAN ID12 bits0 – 4095這個訊框屬於哪個 VLAN
212 = 4096 → 扣掉保留的 0 和 4095 → 可用 VLAN 共 4094 個

這就是為什麼 VLAN 最多只能到 4094——不是廠商小氣，是標籤欄位就只有 12 個位元。也正因為這個上限，雲端資料中心才需要 VXLAN（24 bits，1600 萬個），那是 CCNP 的內容，會在 CH 4-1 講。

MTU 的連鎖反應。標準乙太訊框最大 1518 bytes，加了 4 bytes 標籤變成 1522，這叫 Baby Giant。現代交換器都支援，但如果中間有老舊設備或某些 WAN 線路，就會看到「小封包通、大封包不通、ping 得到但網頁開不了」這種詭異症狀。解法是把路徑上的介面 MTU 調大，或在端點降低 TCP MSS。
還有一個舊協定叫 ISL，是 Cisco 自家的，做法是把整個訊框「包起來」（封裝 26 bytes 前綴 + 4 bytes CRC）而不是插入。現在所有新設備都不支援了，考試只要記得「ISL 是 Cisco 專有、802.1Q 是業界標準、實務一律用 802.1Q」。

5. 實作二：設定 Trunk 幹線

Trunk（幹線埠）就是能同時承載多個 VLAN 的埠，用在交換器對交換器、交換器對路由器、交換器對虛擬機主機。

比喻：Access Port 像公司內線分機——一個分機對應一個人。Trunk 像總機的主幹電話線——一條線進來，靠「分機號碼」（VLAN 標籤）判斷該轉給誰。

設定步驟（兩邊都要做）

! ═══ SW1 的 Gi0/1 ═══
SW1(config)# interface gigabitEthernet 0/1
SW1(config-if)# description == TRUNK TO SW2 ==
SW1(config-if)# switchport trunk encapsulation dot1q   ← 老機型才需要，新機型只支援 dot1q 會報錯，跳過即可
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk native vlan 999
SW1(config-if)# switchport trunk allowed vlan 10,20,30,50,99
SW1(config-if)# switchport nonegotiate
SW1(config-if)# no shutdown

! ═══ SW2 的 Gi0/1（設定必須完全對稱）═══
SW2(config)# interface gigabitEthernet 0/1
SW2(config-if)# description == TRUNK TO SW1 ==
SW2(config-if)# switchport mode trunk
SW2(config-if)# switchport trunk native vlan 999
SW2(config-if)# switchport trunk allowed vlan 10,20,30,50,99
SW2(config-if)# switchport nonegotiate
兩個致命的順序問題：
  • 某些機型必須先 switchport trunk encapsulation dot1q，後 switchport mode trunk。順序反了會出現 Command rejected: An interface whose trunk encapsulation is "Auto" can not be configured to "trunk" mode。
  • 如果你是遠端 SSH 進去設定，先打 switchport trunk allowed vlan 10 這種只留一個 VLAN 的指令，而你的管理流量走 VLAN 99，你會當場斷線。遠端改 Trunk 之前先設 reload in 5，設定成功再 reload cancel。

驗證

SW1# show interfaces trunk

Port        Mode         Encapsulation  Status        Native vlan
Gi0/1       on           802.1q         trunking      999

Port        Vlans allowed on trunk
Gi0/1       10,20,30,50,99                          ← 我允許的清單

Port        Vlans allowed and active in management domain
Gi0/1       10,20,30,50,99                          ← 允許 且 這台真的有建立的

Port        Vlans in spanning tree forwarding state and not pruned
Gi0/1       10,20,30,50,99                          ← 最終真的在傳的（重點看這行）
三段清單要一起看。如果第一段有 VLAN 40，第二段卻沒有 → 這台交換器上根本沒建立 VLAN 40。如果第二段有、第三段沒有 → 被 STP 擋住（Blocking 狀態）或被 VTP Pruning 修掉了。這個判讀順序可以省下大量猜測時間。

6. Native VLAN 與它的資安地雷

802.1Q 有個歷史包袱：早期網路上有些設備看不懂標籤（例如舊的集線器、某些無線橋接器）。所以標準保留了一個「例外」——Native VLAN 的訊框在 Trunk 上不加標籤，直接裸傳。

預設的 Native VLAN 是 VLAN 1。這帶來兩個問題。

問題一：Native VLAN Mismatch

如果 SW1 的 Trunk Native 是 VLAN 1，SW2 是 VLAN 99：

  • SW1 的 VLAN 1 流量不加標籤送出
  • SW2 收到沒有標籤的訊框，依自己的設定判定「這是 VLAN 99」
  • 結果：VLAN 1 和 VLAN 99 被接通了，兩個本該隔離的網段變成同一個廣播域
! CDP 會在 log 裡直接吼你
%CDP-4-NATIVE_VLAN_MISMATCH: Native VLAN mismatch discovered on
GigabitEthernet0/1 (1), with SW2 GigabitEthernet0/1 (99).

要注意：如果你把 CDP 關掉（no cdp run，有些公司基於資安會這樣做），這個警告就不會出現了，錯誤會靜靜地留在網路上。

問題二：VLAN Hopping 雙標籤攻擊

1
攻擊者接在 VLAN 1（= Native VLAN）的埠上他想打進 VLAN 30 財務部。
2
送出一個帶「兩層標籤」的訊框外層標 VLAN 1，內層標 VLAN 30。
3
第一台交換器剝掉外層因為外層是 Native VLAN，出 Trunk 時本來就不加標籤，等於把外層丟掉。
4
第二台交換器看到內層標籤 VLAN 30它完全不知道發生過什麼，老實地把封包送進財務部網段。
三道防線（企業標準做法，三個都要做）：
  1. 把 Native VLAN 改成一個完全沒有任何裝置的閒置 VLAN，例如 999
  2. 把 999 從 allowed 清單裡拿掉（switchport trunk allowed vlan 10,20,30,50,99 就是這個意思——沒寫 999）
  3. 所有沒在用的埠 shutdown 並丟進一個黑洞 VLAN
! ── 完整的 Native VLAN 加固 ──
SW1(config)# vlan 999
SW1(config-vlan)# name BLACKHOLE-NATIVE
SW1(config-vlan)# exit

SW1(config)# interface gi0/1
SW1(config-if)# switchport trunk native vlan 999
SW1(config-if)# switchport trunk allowed vlan 10,20,30,50,99

! ── 未使用的埠全部關閉並隔離 ──
SW1(config)# interface range fa0/13 - 24
SW1(config-if-range)# switchport mode access
SW1(config-if-range)# switchport access vlan 999
SW1(config-if-range)# shutdown
SW1(config-if-range)# description == UNUSED - DISABLED ==
另一種 VLAN Hopping 是 Switch Spoofing：攻擊者的電腦假裝成交換器，發 DTP 封包跟交換器協商，把自己的埠變成 Trunk，就能看到所有 VLAN。防法就是下一節的 switchport nonegotiate。

7. DTP 協商模式對照表

DTP（Dynamic Trunking Protocol）是 Cisco 專有協定，讓兩台交換器自己講好要不要當 Trunk。方便，但也是安全漏洞。

模式指令行為
accessswitchport mode access永遠是 Access，不協商
trunkswitchport mode trunk永遠是 Trunk，但仍會發 DTP 封包（除非加 nonegotiate）
dynamic desirableswitchport mode dynamic desirable主動發 DTP 求對方一起當 Trunk
dynamic autoswitchport mode dynamic auto被動等對方來邀請，自己不主動

協商結果矩陣（必背）

本端 ＼ 對端accessdynamic autodynamic desirabletrunk
accessAccessAccessAccess⚠ 不一致
dynamic autoAccessAccessTrunkTrunk
dynamic desirableAccessTrunkTrunkTrunk
trunk⚠ 不一致TrunkTrunkTrunk
記憶技巧：只有兩邊都是 auto（兩個都在等對方開口）才會協商失敗變成 Access。其他只要有一邊是 desirable 或 trunk，就會成為 Trunk。
企業實務結論：把 DTP 全部關掉。Cisco 官方硬化指引明確建議所有埠手動指定 access 或 trunk，並一律加上 switchport nonegotiate。理由：一台筆電裝上 Yersinia 這類工具就能偽造 DTP 封包，把自己的埠協商成 Trunk，然後整個公司所有 VLAN 的流量都看得到。
! 檢查全公司還有哪些埠開著 DTP
SW1# show interfaces switchport | include Name|Negotiation
Name: Fa0/1
Negotiation of Trunking: Off      ← 安全
Name: Fa0/2
Negotiation of Trunking: On       ← 這個要修

8. 修剪 Trunk：allowed vlan 清單

Trunk 預設會放行 1 – 4094 全部的 VLAN。這代表財務部的廣播封包，會被送到一台根本沒有財務部使用者的邊緣交換器上，白白浪費頻寬，也擴大了資安曝險。

四個容易搞混的指令

指令效果危險度
switchport trunk allowed vlan 10,20整個取代成只剩 10 和 20高 · 遠端下會斷線
switchport trunk allowed vlan add 30在現有清單加上 30低
switchport trunk allowed vlan remove 30從現有清單移除 30中
switchport trunk allowed vlan all恢復成放行全部低（但不建議）
最經典的機房事故：工程師想「再多放行一個 VLAN 40」，直覺打了 switchport trunk allowed vlan 40——結果不是「加上 40」，而是「只剩 40」，原本的 10、20、30 全被砍掉，整棟樓斷線。要加 VLAN 永遠要記得寫 add。
! ✗ 錯誤：這會清掉所有原本允許的 VLAN
SW1(config-if)# switchport trunk allowed vlan 40

! ✓ 正確：只是新增
SW1(config-if)# switchport trunk allowed vlan add 40

! 用範圍也可以，逗號和減號混用
SW1(config-if)# switchport trunk allowed vlan 10,20,30-35,50,99

! 除了某幾個以外全放行
SW1(config-if)# switchport trunk allowed vlan except 1,1002-1005
還有一種自動修剪叫 VTP Pruning（vtp pruning），它會自動判斷「下游沒人用 VLAN 30，那就不要送過去」。省事，但只在 VTP Server/Client 模式下有效，而且無法修剪 VLAN 1。企業實務上多數人選擇手動 allowed 清單，因為行為可預測、可稽核。

9. Voice VLAN：一條線接電話又接電腦

辦公桌上通常只有一個網路孔。IP 電話的解法是：牆上的線接進電話，電話上再有一個孔接電腦。電話內部其實就是一台迷你三埠交換器。

牆上網路孔 ──► IP 電話（Voice VLAN 50，有標籤）
　　　　　　　　└──► 電腦（Data VLAN 10，無標籤）

所以這個埠有點特別：它看起來是 Access Port，但實際上會傳兩個 VLAN——一個帶標籤（語音）、一個不帶（資料）。Cisco 有時稱它 Mini-Trunk。

SW1(config)# vlan 50
SW1(config-vlan)# name VOICE
SW1(config-vlan)# exit

SW1(config)# interface fastEthernet 0/5
SW1(config-if)# switchport mode access
SW1(config-if)# switchport access vlan 10       ← 電腦走這個，不帶標籤
SW1(config-if)# switchport voice vlan 50        ← 電話走這個，帶標籤
SW1(config-if)# mls qos trust cos               ← 信任電話標的優先權
SW1(config-if)# spanning-tree portfast
SW1(config-if)# power inline auto               ← PoE 供電給電話

驗證

SW1# show interfaces fa0/5 switchport | include VLAN
Access Mode VLAN: 10 (SALES)
Voice VLAN: 50 (VOICE)

SW1# show power inline fa0/5
Interface Admin  Oper       Power   Device              Class Max
--------- ------ ---------- ------- ------------------- ----- ----
Fa0/5     auto   on         6.3     IP Phone 7945       2     15.4

SW1# show cdp neighbors fa0/5 detail | include Phone|IP address
Platform: Cisco IP Phone 7945,  Capabilities: Host Phone
  IP address: 192.168.50.31
電話怎麼知道自己該用 VLAN 50？靠 CDP（Cisco 電話）或 LLDP-MED（其他廠牌）。交換器會透過這兩個協定告訴電話「你的語音 VLAN 是 50」。所以如果用非 Cisco 電話而 CDP 又關掉了，記得開 lldp run，否則電話拿不到 VLAN 資訊，會一直停在開機畫面。
常見故障：電話正常、電腦上不了網。八成是這個埠只設了 switchport voice vlan 50 卻忘了 switchport access vlan 10。電腦的不帶標籤流量會掉進 VLAN 1，而 VLAN 1 通常沒有 DHCP 也沒有閘道。

10. VTP：方便但會炸掉整個機房

VTP（VLAN Trunking Protocol）讓你在一台交換器上建立 VLAN，自動同步給全公司其他交換器。聽起來很棒，但它是網路工程界最有名的地雷之一。

模式能不能建 / 改 VLAN會不會轉發 VTP 通告會不會同步別人的
Server（預設）可以會會
Client不行會會
Transparent可以（只影響自己）會（只是轉手）不會
Off（v3 才有）可以不會不會
VTP 大災難是怎麼發生的：
  1. VTP 靠一個叫 Revision Number（版本序號）的計數器判斷「誰的資料比較新」。每改一次 VLAN，序號 +1。
  2. 某工程師拿一台實驗室用過的舊交換器來擴充機房。那台在實驗室被反覆改設定，序號已經衝到 87。
  3. 正式環境的序號只有 12。
  4. 舊交換器一插上 Trunk，其他所有交換器看到「87 > 12，他的比較新」，全部把自己的 VLAN 資料庫換成實驗室那份。
  5. 全公司 VLAN 瞬間消失，所有使用者的埠掉回 VLAN 1，整棟樓斷線。
接新交換器進網路前的鐵則（三選一，一定要做）：
  1. 先設成 vtp mode transparent，序號會被歸零
  2. 或改一個假的 VTP domain 名稱再改回來，序號同樣歸零
  3. 或 delete flash:vlan.dat + reload，徹底清空
做完後用 show vtp status 確認 Revision 是 0 再接線。 
SW1# show vtp status

VTP version running             : 1
VTP Domain Name                 : CORP
VTP Pruning Mode                : Disabled
VTP Traps Generation            : Disabled
Device ID                       : 0c11.6789.aa00
Configuration last modified by 192.168.99.2 at 3-1-25 09:14:22
Local updater ID is 192.168.99.2
Feature VLAN:
--------------
VTP Operating Mode              : Server
Maximum VLANs supported locally : 1005
Number of existing VLANs        : 8
Configuration Revision          : 12       ← 就是這個數字會害死人

安全的 VTP 設定

! 加密碼，沒密碼的設備無法加入 domain
SW1(config)# vtp domain CORP
SW1(config)# vtp password Str0ng-VTP-Pass
SW1(config)# vtp version 3

! v3 最大的改良：必須明確指定「誰是主要伺服器」，
! 沒被指定的機器就算 revision 再高也蓋不掉別人
SW1# vtp primary vlan
企業實務怎麼選？多數大型網路直接不用 VTP——全部設成 vtp mode transparent（或 v3 的 off），VLAN 用 Ansible／Python 腳本推送。理由是「自動同步」帶來的方便，遠遠比不上「一台舊機器毀掉整個網路」的風險。這也連結到 CH 4-2 的網路自動化。

11. 實作三：VLAN 之間怎麼互通（三種做法）

VLAN 把網路切開了，但業務部還是需要連財務部的 ERP 系統。跨 VLAN 通訊必須經過第三層設備——這叫 Inter-VLAN Routing。有三種做法。

做法 A：Legacy Router（每個 VLAN 一條實體線）

路由器上每個 VLAN 接一個實體介面。概念最單純，但 VLAN 一多路由器的埠就不夠用，實務上早就淘汰。只有考試會問，知道有這回事就好。

做法 B：Router-on-a-Stick（單臂路由）

路由器只用一個實體介面接交換器，這條線設成 Trunk，然後在路由器上為每個 VLAN 建立一個「子介面」。

! ═══ 交換器端：接路由器的埠設成 Trunk ═══
SW1(config)# interface gigabitEthernet 0/1
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk allowed vlan 10,20,30
SW1(config-if)# switchport nonegotiate

! ═══ 路由器端：實體介面只開起來，不給 IP ═══
R1(config)# interface gigabitEthernet 0/0
R1(config-if)# no ip address
R1(config-if)# no shutdown
R1(config-if)# exit

! ═══ 每個 VLAN 一個子介面 ═══
R1(config)# interface gigabitEthernet 0/0.10
R1(config-subif)# description == SALES GATEWAY ==
R1(config-subif)# encapsulation dot1Q 10              ← 這行告訴路由器：這個子介面處理標籤 10
R1(config-subif)# ip address 192.168.10.1 255.255.255.0
R1(config-subif)# exit

R1(config)# interface gigabitEthernet 0/0.20
R1(config-subif)# encapsulation dot1Q 20
R1(config-subif)# ip address 192.168.20.1 255.255.255.0
R1(config-subif)# exit

R1(config)# interface gigabitEthernet 0/0.30
R1(config-subif)# encapsulation dot1Q 30
R1(config-subif)# ip address 192.168.30.1 255.255.255.192   ← /26，配合 VLSM 規劃
子介面編號和 VLAN ID 沒有任何關聯。你可以寫 gi0/0.777 然後 encapsulation dot1Q 10，功能完全一樣。真正決定 VLAN 的是 encapsulation 那行。但實務上一律讓兩個數字一致，不然半年後接手的人會瘋掉。
Native VLAN 在單臂路由的特殊寫法

如果 Trunk 上的 Native VLAN 是 99，而 99 也需要路由，子介面要加 native 關鍵字，否則路由器不知道要處理沒有標籤的訊框：

R1(config)# interface gi0/0.99
R1(config-subif)# encapsulation dot1Q 99 native
R1(config-subif)# ip address 192.168.99.1 255.255.255.240
單臂路由的天花板：所有跨 VLAN 流量都要從那一條線出去、再從同一條線回來，等於頻寬對折。一條 1 Gbps 的線，實際跨 VLAN 吞吐量大約只有 500 Mbps。小辦公室夠用，超過 100 人就該換做法 C。

做法 C：三層交換器 SVI（企業標準答案）

三層交換器（Layer 3 Switch）內建路由功能，用 SVI（Switched Virtual Interface）直接在交換器內部完成路由。速度是硬體 ASIC 處理，遠快過路由器的軟體轉發。

! ═══ 第一步：開啟路由功能（很多人忘記這行）═══
SW-L3(config)# ip routing

! ═══ 第二步：為每個 VLAN 建立 SVI ═══
SW-L3(config)# interface vlan 10
SW-L3(config-if)# description == SALES GATEWAY ==
SW-L3(config-if)# ip address 192.168.10.1 255.255.255.0
SW-L3(config-if)# no shutdown
SW-L3(config-if)# exit

SW-L3(config)# interface vlan 20
SW-L3(config-if)# ip address 192.168.20.1 255.255.255.0
SW-L3(config-if)# no shutdown
SW-L3(config-if)# exit

SW-L3(config)# interface vlan 30
SW-L3(config-if)# ip address 192.168.30.1 255.255.255.192
SW-L3(config-if)# no shutdown

! ═══ 第三步：接對外路由器的埠改成「路由埠」═══
SW-L3(config)# interface gigabitEthernet 0/24
SW-L3(config-if)# no switchport                  ← 這行把它從二層埠變成三層埠
SW-L3(config-if)# ip address 10.0.0.2 255.255.255.252
SW-L3(config-if)# no shutdown

! ═══ 第四步：預設路由指向對外路由器 ═══
SW-L3(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.1
SVI 起不來的三個條件（考試必考）。SVI 的狀態要變成 up/up，必須同時滿足：
  1. 該 VLAN 已經在 VLAN 資料庫裡建立，而且是 active
  2. 至少有一個實體埠屬於該 VLAN 且是 up，或有一條 Trunk 允許該 VLAN 通過
  3. SVI 本身沒有 shutdown
只建立 interface vlan 20 給 IP，但沒有任何一台電腦接在 VLAN 20 的埠上 → SVI 會是 down/down，ping 不到自己的閘道。

三種做法比較

比較項目Legacy RouterRouter-on-a-Stick三層交換器 SVI
需要的實體埠每 VLAN 一個1 個0（內部處理）
轉發方式軟體軟體硬體 ASIC
效能低低（頻寬對折）線速
成本高低中～高
適用規模已淘汰小型辦公室企業標準

12. 故障排除十個檢查點

使用者說「連不上」，按這個順序查，九成的問題會在前五步就找到。

1
埠是不是 up？show interfaces status。看到 notconnect 就是線或對面的問題，跟 VLAN 無關，先去查線。err-disabled 通常是 Port Security 或 BPDU Guard 觸發。
2
埠在正確的 VLAN 嗎？show vlan brief。如果那個埠不在任何 VLAN 的列表裡，它很可能是 Trunk 或處於 err-disabled。
3
VLAN 本身是 active 還是 suspended？show vlan id 20。VTP 同步異常時會出現 suspended。
4
Trunk 兩邊模式一致嗎？show interfaces trunk 在兩台上都跑一次。一邊 trunking、一邊沒出現在清單裡 = 沒協商成功。
5
Trunk 有放行這個 VLAN 嗎？show interfaces trunk 的第三段清單才是真的在傳的。第一段有、第三段沒有，就往 STP 或 pruning 查。
6
Native VLAN 兩邊一樣嗎？show interfaces trunk 的 Native vlan 欄位。不一致會造成兩個 VLAN 詭異地互通。
7
SVI 是 up/up 嗎？show ip interface brief | include Vlan。down/down 代表該 VLAN 沒有任何 active 的埠。
8
ip routing 開了沒？show ip route。三層交換器沒開這行，SVI 各自能 ping 通但 VLAN 之間不通——這是最常見的「設定看起來全對卻不通」。
9
電腦的 IP／遮罩／閘道對嗎？閘道打錯、或遮罩寫成 /24 但實際是 /26，症狀是「同網段通、跨網段不通」。
10
有沒有 ACL 擋住？show access-lists、show ip interface vlan 30。財務 VLAN 通常有 ACL，很容易忘記自己半年前設過。
真實案例：「新來的同事電腦連不上，隔壁桌的都正常」

症狀：PC 拿不到 IP，自己給自己 169.254.x.x。

排查：第 1 步 show interfaces status fa0/7 → connected，線沒問題。第 2 步 show vlan brief → Fa0/7 出現在 VLAN 1，隔壁的 Fa0/6 在 VLAN 10。

原因：前一位管理員設定時 interface range fa0/1 - 6 少打了一個埠。VLAN 1 沒有 DHCP，所以拿不到 IP。修法：interface fa0/7 → switchport access vlan 10。

真實案例：「換了一台新交換器之後，某些 VLAN 突然不通」

症狀：VLAN 10、20 正常，VLAN 30、50 完全不通。

排查：show interfaces trunk 第一段顯示 allowed 10,20,30,50，但第二段（allowed and active）只有 10,20。

原因：新交換器上根本沒有建立 VLAN 30 和 50。allowed 清單可以寫不存在的 VLAN ID，IOS 不會報錯。修法：在新交換器上補建 VLAN 30、50。

完整實作 Lab：三層交換器 + 兩台接入交換器

用 Packet Tracer 或 GNS3 建，全部做完大約 60 分鐘。做完你就具備一般企業辦公室網路的建置能力。

拓樸

          [ R1 對外路由器 ]
                 │ 10.0.0.1/30
                 │ Gi0/24 (routed port)
         [ SW-L3 三層交換器 ]
          Gi0/1 ┴─────┴ Gi0/2
            │           │
        [ SW1 ]      [ SW2 ]
       Fa0/1-8      Fa0/1-8
      VLAN 10,50   VLAN 20,30

步驟

  1. 三台交換器都建立 VLAN 10 SALES、20 ENG、30 FIN、50 VOICE、99 MGMT、999 BLACKHOLE
  2. SW1 的 Fa0/1-8 設成 VLAN 10 Access，其中 Fa0/5 額外加 voice vlan 50
  3. SW2 的 Fa0/1-4 設 VLAN 20、Fa0/5-8 設 VLAN 30
  4. 三台之間的 Gi 埠設成 Trunk，native vlan 999，allowed 10,20,30,50,99，全部加 nonegotiate
  5. SW-L3 開 ip routing，建立 VLAN 10/20/30/50/99 的 SVI，遮罩依 VLSM 規劃（FIN 用 /26、MGMT 用 /28）
  6. SW-L3 的 Gi0/24 下 no switchport 並給 10.0.0.2/30，加預設路由指向 10.0.0.1
  7. SW1 / SW2 各設 interface vlan 99 的管理 IP，並設 ip default-gateway 192.168.99.1
  8. 所有未使用的埠丟進 VLAN 999 並 shutdown

驗收清單

  • SW1 的 VLAN 10 電腦，ping 得到 SW2 的 VLAN 20 電腦
  • show interfaces trunk 三段清單都要看到 10,20,30,50,99，且不能有 999
  • show ip route 在 SW-L3 上要看到 5 條 C（直連）+ 1 條 S*（預設路由）
  • 從 VLAN 10 的電腦 SSH 到 192.168.99.2（SW1 管理位址）要成功
  • 把一台電腦插進 Fa0/20（未使用埠），應該完全不通

加碼挑戰

  1. 寫一條 ACL，讓 VLAN 10（業務）只能連到財務伺服器 192.168.30.10 的 tcp/1433，其他財務主機一律擋掉。（做法在 CH 3-4）
  2. 故意把 SW2 的 Trunk native 改成 VLAN 1，觀察 log 出現什麼訊息，再改回來。
  3. 在 SW1 打 switchport trunk allowed vlan 40（不加 add），觀察多少 VLAN 瞬間斷線，體會第 8 節那個事故。

本章重點回顧

  • 一個 VLAN = 一個廣播域 = 一個 IP 子網路，規劃 VLAN 就是在規劃子網路
  • Normal Range VLAN 存在 vlan.dat，不在 running-config，write erase 清不掉
  • 802.1Q 插入 4 bytes，其中 VLAN ID 佔 12 bits → 上限 4094 個
  • Native VLAN 不打標籤；改成閒置 VLAN 並移出 allowed 清單是資安基本功
  • 只有兩邊都 dynamic auto 才協商失敗；企業實務一律 nonegotiate
  • allowed vlan X 是取代，allowed vlan add X 才是新增
  • VTP 的 Revision Number 是機房殺手，接新設備前務必歸零
  • 跨 VLAN 三種做法，企業標準答案是三層交換器 SVI，別忘了 ip routing
