1. 迴圈為什麼是二層的死刑

企業網路一定會有備援線路——SW1 接 SW2，SW2 接 SW3，SW3 再接回 SW1。任何一條線斷了還有另一條可以走。但這個「環」在第二層會造成災難。

關鍵原因：乙太訊框的表頭裡沒有 TTL。

IP 封包有 TTL（存活時間），每經過一台路由器就減 1，減到 0 就丟掉，所以三層的迴圈頂多繞 255 次就自己停了。

乙太訊框沒有這個欄位。一個訊框進入環狀拓樸，會以線速永遠繞下去，直到你把線拔掉為止。

三個同時發生的災難

災難成因觀察到的症狀
廣播風暴廣播訊框在環裡無限複製、無限繞所有交換器 CPU 100%、指令輸入沒反應、埠燈全部狂閃
MAC 表震盪
（MAC Flapping）		同一個來源 MAC 一下從 Gi0/1 進來、一下從 Gi0/2 進來，交換器不斷改寫 MAC 表log 出現 %MAC_MOVE 或 HOST_FLAPPING
單播訊框重複同一個封包從兩條路徑都送到目的地TCP 大量重傳、應用層資料錯亂
! 迴圈發生時，log 會長這樣
%SW_MATM-4-MACFLAP_NOTIF: Host 0050.56c0.0001 in vlan 10 is flapping
between port Gi0/1 and port Gi0/2
比喻：兩個人在走廊兩端互相傳話，中間有兩條走廊都通。A 喊一句話，兩條走廊各傳一份給 B，B 又把兩份各傳回兩條走廊……三秒之內整棟樓只剩尖叫聲。STP 做的事，就是先把其中一條走廊的門鎖起來，只留一條路。等到主要走廊塌了，再把備用那扇門打開。
STP 的一句話定義：在有實體備援的二層拓樸上，自動計算出一棵無迴圈的樹，把不在樹上的埠設成 Blocking。主路徑斷掉時，自動把備援埠打開。標準是 IEEE 802.1D。

2. BPDU 與 Bridge ID 的結構

交換器之間靠 BPDU（Bridge Protocol Data Unit）互相自我介紹，決定誰當老大。BPDU 每 2 秒從所有埠送出一次，目的 MAC 是保留的群播位址 01:80:C2:00:00:00。

Bridge ID：8 個位元組決定一切

Bridge Priority4 bits · 0–61440，以 4096 為級距
Extended System ID12 bits · = VLAN ID
MAC Address48 bits · 交換器自己的基底 MAC
實際 Priority = 設定的 Priority + VLAN ID
例：priority 24576 在 VLAN 10 → 24586

這就是為什麼 show spanning-tree 顯示的優先權常常是 32778 而不是 32768——因為 32768 + VLAN 10 = 32778。很多人第一次看到會以為設定跑掉了。

Priority 只能是 4096 的倍數。因為欄位只有 4 個位元，能表達的是 0、4096、8192、12288 … 61440 共 16 個值。打 spanning-tree vlan 10 priority 20000 會被 IOS 拒絕。預設值是 32768（正中間，方便往上往下調）。

BPDU 裡帶什麼資訊

欄位意義
Root Bridge ID「我認為的老大是誰」
Root Path Cost「從我這裡走到老大要花多少成本」
Sender Bridge ID「我是誰」
Port ID「這個 BPDU 是從我的哪個埠送出的」（Port Priority + Port Number）
Message Age / Max Age / Hello / Forward Delay計時器參數，由 Root Bridge 統一決定，全網路跟著它
計時器由 Root Bridge 決定並廣播給全網，所以你只需要在 Root 上調整。這也是「一定要明確指定誰是 Root」的原因之一——不然你不知道現在全網用的是誰的參數。

3. 四步驟選舉

STP 收斂的過程可以拆成四個步驟，順序固定，考試和實務都是照這個順序推。

1
選出唯一一台 Root Bridge整個網路（每個 VLAN 各一棵樹）只有一台。比較規則：Bridge ID 最小的贏。先比 Priority，Priority 一樣就比 MAC，MAC 小的贏。
2
每一台非 Root 交換器選一個 Root Port（RP）「離老大最近的那個埠」。所有非 Root 的交換器都一定有且只有一個 RP。
3
每一個網段選一個 Designated Port（DP）「這個網段上負責往下轉發的那個埠」。Root Bridge 上所有埠都是 DP。
4
剩下的埠通通變成 Blocking既不是 RP 也不是 DP 的埠 → Non-Designated / Blocking，只收 BPDU、不轉發任何資料。迴圈就是在這裡被切斷的。

Root Port 的比較順序（四層 tiebreaker，必背）

順序比什麼誰贏
1Root Path Cost 累加成本小的贏
2對端的 Bridge ID（上游鄰居是誰）小的贏
3對端的 Port Priority（預設 128）小的贏
4對端的 Port Number小的贏
第 3、4 項比的是「對面的」，不是自己的。這是 CCNA 最經典的陷阱題。當 SW2 有兩條線都接到同一台 SW1，成本一樣、對端 Bridge ID 也一樣（都是 SW1），這時要看 SW1 那兩個埠的 Port ID，不是 SW2 自己的。所以要改變選擇結果，得去 SW1 上調 spanning-tree port-priority。
推演範例
SW1  priority 32768  MAC 0011.1111.1111   ← 三台裡 MAC 最小
SW2  priority 32768  MAC 0022.2222.2222
SW3  priority 32768  MAC 0033.3333.3333

三台互相用 1 Gbps 連成三角形
  • 步驟 1：Priority 全部一樣 → 比 MAC → SW1 是 Root Bridge
  • 步驟 2：SW2 到 SW1 直連成本 4；繞 SW3 是 4+4=8 → SW2 的 RP 是直連 SW1 那個埠。SW3 同理。
  • 步驟 3：SW1 兩個埠都是 DP。SW2↔SW3 這個網段，兩邊到 Root 的成本都是 4，平手 → 比 Bridge ID → SW2 較小 → SW2 那端是 DP。
  • 步驟 4：SW3 接 SW2 的那個埠 → Blocking。迴圈解除。
Root Port (RP)非 Root 交換器上，往 Root 最近的埠。Forwarding。每台一個。
Designated Port (DP)每個網段一個，負責往該網段轉發。Forwarding。
Non-Designated都不是 → Blocking。只收 BPDU，不轉發資料。

4. 路徑成本表（必背）

成本是「頻寬愈大、成本愈低」。要注意 成本是「進來的埠」在累加——訊框每進入一台交換器的一個埠，就把那個埠的成本加上去。

速率舊標準成本（預設，考試考這個）Long Mode 成本
10 Mbps1002,000,000
100 Mbps19200,000
1 Gbps420,000
10 Gbps22,000
100 Gbps1（會撞在一起）200
舊標準在 10 Gbps 以上就開始擠在一起（10G=2、40G=1、100G=1），完全分不出優劣。所以現代資料中心要開 spanning-tree pathcost method long。注意：要全網一起改，混用會造成計算錯亂。

手動調整成本

! 針對特定介面、特定 VLAN 調成本（值愈小愈優先）
SW2(config)# interface gigabitEthernet 0/2
SW2(config-if)# spanning-tree vlan 10 cost 100

! 調 Port Priority（影響對端的 RP 選擇，預設 128，級距 16）
SW1(config)# interface gigabitEthernet 0/1
SW1(config-if)# spanning-tree vlan 10 port-priority 64
實務上調成本比調優先權常見。因為成本改的是「我自己這端」，直覺、好維護。Port Priority 要跑去對端改，容易改錯機器。

5. 埠狀態與計時器

傳統 802.1D 的五種狀態

狀態學 MAC？轉發資料？收送 BPDU？停留時間
Disabled否否否被 shutdown
Blocking否否只收最多 20 秒（Max Age）
Listening否否收+送15 秒（Forward Delay）
Learning是否收+送15 秒（Forward Delay）
Forwarding是是收+送穩定狀態
從 Blocking 到 Forwarding = 20 + 15 + 15 = 50 秒
從線路剛插上（Listening 開始）= 15 + 15 = 30 秒
這 30 秒就是使用者抱怨的來源。電腦開機、網路線重插，要等 30 秒才拿得到 DHCP。很多 Windows 的 DHCP 請求在 30 秒內就逾時了，結果拿到 169.254 的自動位址。解法是接末端裝置的埠一律開 PortFast（第 9 節）。

三個計時器

計時器預設作用
Hello Time2 秒Root 發送 BPDU 的間隔
Max Age20 秒沒收到 BPDU 多久後判定上游掛了（= 10 個 Hello）
Forward Delay15 秒Listening 和 Learning 各停留多久
不要手動改計時器。Cisco 官方建議用 spanning-tree vlan 10 root primary diameter 5 這種方式讓 IOS 自己算，或乾脆改用 RSTP。手動縮短 Max Age 常導致網路在高負載時誤判鄰居掛掉，反而不穩。

6. STP 家族：PVST+ / RPVST+ / MST

版本標準每個 VLAN 一棵樹？收斂速度CPU 負擔
STP802.1D否（全網一棵）30–50 秒低
PVST+Cisco 專有是30–50 秒高（VLAN 多會爆）
RSTP802.1w否< 1 秒低
Rapid PVST+Cisco 專有是< 1 秒高
MST802.1s多個 VLAN 對應到一個 Instance< 1 秒低
怎麼選？
  • VLAN 少於 ~100 個、全 Cisco 設備 → Rapid PVST+，設定簡單，每 VLAN 可以獨立做負載分擔
  • VLAN 上百個、或混廠牌 → MST，把 100 個 VLAN 對應到 2~3 個 Instance，CPU 省非常多
  • 不要留在預設的 PVST+，收斂 50 秒在現代網路是無法接受的
! 切換到 Rapid PVST+（最常見的第一步）
SW1(config)# spanning-tree mode rapid-pvst

! MST 設定：把 VLAN 分組到 Instance
SW1(config)# spanning-tree mode mst
SW1(config)# spanning-tree mst configuration
SW1(config-mst)# name CORP-REGION
SW1(config-mst)# revision 1
SW1(config-mst)# instance 1 vlan 10,20,30
SW1(config-mst)# instance 2 vlan 40,50,99
SW1(config-mst)# show pending          ← 套用前先看一次
SW1(config-mst)# exit

! 兩個 Instance 各指定不同 Root，達成負載分擔
SW1(config)# spanning-tree mst 1 root primary
SW1(config)# spanning-tree mst 2 root secondary
MST 的致命前提：同一個 Region 的三個參數必須完全一致——name、revision、VLAN 對 Instance 的對應表。任何一台打錯一個字，它就會被視為在不同 Region，退化成一棵大樹，設計整個失效。而且錯誤不會有明顯報錯，要用 show spanning-tree mst configuration digest 比對雜湊值才看得出來。

7. RSTP 快在哪裡

RSTP（802.1w）把收斂從 50 秒縮到 1 秒以內，靠三個改變。

改變一：埠狀態簡化成三種

802.1D802.1w
Disabled / Blocking / ListeningDiscarding
LearningLearning
ForwardingForwarding

改變二：多了兩個「預備」角色

Alternate PortRoot Port 的備胎。RP 一掛，它立刻接手，不用等計時器。
Backup PortDesignated Port 的備胎，只出現在接集線器這種共享媒介上，實務罕見。

改變三：Proposal / Agreement 握手

802.1D 是「等計時器過完，賭沒問題了才轉發」。RSTP 改成兩台交換器直接對話確認：

1
上游送出 Proposal「我想讓這個埠變成 Designated 並開始轉發，可以嗎？」
2
下游執行 Sync把自己其他所有非邊緣埠先設成 Discarding，確保不會產生迴圈。
3
下游回 Agreement「我這邊安全了，你可以轉發。」
4
上游立刻進入 Forwarding整個過程數十毫秒，然後這個流程往下一台交換器逐跳傳遞。

Link Type 的關鍵影響

Link Type判定依據能不能快速收斂
Point-to-Point全雙工可以（能做 Proposal/Agreement）
Shared半雙工不行，退化成 802.1D 的慢速收斂
Edge設了 PortFast直接 Forwarding，完全不參與
Duplex Mismatch 會讓 RSTP 悄悄失效。一邊自動協商成半雙工，RSTP 就把那條線判定為 Shared，收斂時間從 1 秒退回 30 秒。而且不會有任何錯誤訊息，只會有人抱怨「切換備援好像變慢了」。用 show spanning-tree interface gi0/1 detail 看 Link type 欄位確認。必要時手動指定：spanning-tree link-type point-to-point。

8. 實作一：手動指定 Root Bridge

絕對不要讓 STP 自己選 Root。預設 Priority 全部一樣，最後是「MAC 位址最小的贏」。MAC 小通常代表機器最老——結果你花大錢買的核心交換器在旁邊納涼，五年前的邊緣小交換器變成全網流量的中心點。這是真實世界最常見的效能問題之一。

方法 A：用 root primary（推薦，IOS 自己算）

! 核心交換器 SW-CORE1 當所有 VLAN 的主 Root
SW-CORE1(config)# spanning-tree vlan 1-100 root primary

! SW-CORE2 當備援 Root（主的掛了它接手）
SW-CORE2(config)# spanning-tree vlan 1-100 root secondary

root primary 的實際行為：IOS 先看目前 Root 的優先權，把自己設成比它低 4096；如果目前 Root 已經是 24576 以下，就直接設成 24576。root secondary 一律設成 28672。

方法 B：手動指定 Priority（可預測，大型網路推薦）

SW-CORE1(config)# spanning-tree vlan 10,30,50 priority 4096    ← 奇數 VLAN 的主 Root
SW-CORE1(config)# spanning-tree vlan 20,40,99 priority 8192    ← 偶數 VLAN 的備 Root

SW-CORE2(config)# spanning-tree vlan 20,40,99 priority 4096    ← 偶數 VLAN 的主 Root
SW-CORE2(config)# spanning-tree vlan 10,30,50 priority 8192    ← 奇數 VLAN 的備 Root
這叫 STP 負載分擔（Load Balancing）。PVST+ 每個 VLAN 有自己的樹，所以可以讓一半的 VLAN 走 SW-CORE1、另一半走 SW-CORE2，兩台核心和兩條上行線同時在做事，而不是一台閒置。這是企業設計的標準做法。

9. 實作二：五道保護機制

STP 本身會運作，但它太信任別人——任何送 BPDU 的設備都能參與選舉。以下五個機制是企業網路的標準配備。

機制用在哪種埠防什麼觸發後的動作
PortFast接末端裝置的 Access 埠省掉 30 秒等待直接 Forwarding
BPDU Guard同上（配 PortFast 一起用）有人偷接交換器err-disable 關埠
BPDU Filter特殊情境不送也不收 BPDU安靜忽略（危險）
Root Guard接下游／接分公司的埠下游設備搶當 Root設成 root-inconsistent
Loop GuardRoot Port 和 Alternate Port單向鏈路造成 BPDU 消失設成 loop-inconsistent

PortFast + BPDU Guard（最基本、一定要做）

! 方法 1：一個一個介面設
SW1(config)# interface range fa0/1 - 24
SW1(config-if-range)# spanning-tree portfast
SW1(config-if-range)# spanning-tree bpduguard enable

! 方法 2：全域預設（推薦，新埠自動套用，不會漏設）
SW1(config)# spanning-tree portfast default
SW1(config)# spanning-tree portfast bpduguard default
! 注意：全域版只對「access 模式」的埠生效，trunk 埠不受影響
PortFast 千萬不要設在 Trunk 埠上。Trunk 接的是另一台交換器，PortFast 讓它跳過 Listening/Learning 直接轉發，會在收斂完成前就製造出迴圈。IOS 會警告你，但不會阻止你。（例外：接 VMware ESXi 主機的 Trunk 可用 spanning-tree portfast trunk，因為虛擬交換器不送 BPDU。）

err-disable 之後怎麼恢復

! 查是誰、為什麼被關
SW1# show interfaces status err-disabled
Port      Name               Status       Reason
Fa0/7     MEETING-ROOM       err-disabled bpduguard

! 手動恢復：進去 shut / no shut
SW1(config)# interface fa0/7
SW1(config-if)# shutdown
SW1(config-if)# no shutdown

! 自動恢復（實務常設，避免半夜被叫起來）
SW1(config)# errdisable recovery cause bpduguard
SW1(config)# errdisable recovery cause psecure-violation
SW1(config)# errdisable recovery interval 300       ← 5 分鐘後自己試著開回來

SW1# show errdisable recovery

Root Guard：不准下游搶當老大

! 設在「面向下游／面向外部」的埠上
SW-CORE1(config)# interface gi0/5
SW-CORE1(config-if)# spanning-tree guard root

行為：如果這個埠收到「比目前 Root 更優的 BPDU」，就把它設成 root-inconsistent（等同 Blocking）。等對方不再送優越 BPDU，會自動恢復，不需要人工介入。

SW1# show spanning-tree inconsistentports
Name                 Interface              Inconsistency
-------------------- ---------------------- ------------------
VLAN0010             GigabitEthernet0/5     Root Inconsistent

Loop Guard 與 UDLD：對付單向鏈路

什麼是單向鏈路？光纖有兩芯，一收一發。如果收的那芯斷了、發的還好著，實體層看起來是 up，但只有單向能通。這時 Blocking 的埠收不到 BPDU，會以為「上游沒有更好的路徑了」，於是自己轉成 Forwarding——迴圈就這樣產生了，而且沒有任何警訊。
! Loop Guard：收不到 BPDU 時，不要轉 Forwarding，改成 loop-inconsistent
SW1(config)# spanning-tree loopguard default      ← 全域，只影響 RP/Alternate

! UDLD：主動偵測單向鏈路（光纖鏈路一定要開）
SW1(config)# udld aggressive                       ← 全域，只對光纖埠生效
SW1(config)# interface gi0/1
SW1(config-if)# udld port aggressive               ← 銅線埠要個別開

SW1# show udld gi0/1
Loop GuardUDLD
偵測方式被動（發現 BPDU 不見了）主動（互相打招呼）
層級只保護 STP保護所有流量
觸發後loop-inconsistent（自動恢復）err-disable（aggressive 模式）
建議兩個一起開，它們互補而非替代
BPDU Filter 是把雙面刃，非必要不要用。它讓埠完全不送也不收 BPDU。設在介面層級時，那個埠等於脫離 STP 保護——有人在那裡接一台交換器造成迴圈，沒有任何機制會發現。只有在「連到不受信任的第三方、且不能讓他們看到我們的拓樸」這種特殊需求下才用，而且要搭配 Port Security。

10. STP 故障排除

1
Root 是不是你要的那台？show spanning-tree vlan 10 | include Root ID 在每一台上跑，看 Address 是否一致且是核心那台。
2
有沒有埠一直在跳？show spanning-tree detail | include ieee|occurr 看 topology change 次數。數字持續增加代表某條線在閃斷。
3
誰造成 TCN？show spanning-tree vlan 10 detail 裡的 from GigabitEthernet0/2 告訴你 TCN 從哪個埠進來，順著查上游。
4
有沒有不一致的埠？show spanning-tree inconsistentports，一行就看出 Root Guard / Loop Guard 有沒有觸發。
5
Link type 對嗎？show spanning-tree interface gi0/1 detail | include Link。出現 Shr 就去查 duplex。
6
全網 STP 模式一致嗎？一台跑 MST、旁邊跑 Rapid PVST+，邊界行為會非常難預測。show spanning-tree summary | include mode。
真實案例：「每天下午三點網路卡一下」

症狀：使用者反映每天固定時段會斷線 1~2 秒，VoIP 通話會掉。

排查：show spanning-tree detail | include occurred → topology change 次數每天穩定增加。追 TCN 來源 → 某台邊緣交換器的 Fa0/18。

原因：那個埠接會議室投影機，沒有設 PortFast。有人下午開會插拔線，每次插拔都觸發一次 TCN，全網 MAC 表被清空重學。修法：該埠加 PortFast + BPDU Guard，TCN 不再產生。

真實案例：「新分公司接上總部後，總部整個變慢」

症狀：接了分公司的線之後，總部核心交換器 CPU 飆高，跨 VLAN 流量變慢。

排查：show spanning-tree vlan 10 → Root ID 的 MAC 變成一台沒看過的位址。

原因：分公司那台舊交換器 MAC 位址比總部核心小，把 Root 搶走了，全公司流量都繞去分公司那條慢速線再繞回來。修法：總部核心設 root primary，並在對外埠加 spanning-tree guard root。

11. EtherChannel：把多條線綁成一條

STP 有個副作用：備援線路是被 Blocking 的，等於花錢買了一條線但平常完全不用。EtherChannel 解決這個問題——把 2~8 條實體線綁成一個邏輯介面，STP 只看到一條線，所以不會 Blocking，頻寬直接相加。

4 條 1 Gbps 綁成 EtherChannel → STP 眼中是 一條 4 Gbps 的線
其中一條斷了 → 自動變 3 Gbps，STP 完全不用重新收斂

三種協商模式

記憶法跟 DTP 一樣：兩個「被動」湊在一起就失敗。passive+passive、auto+auto 都不成。企業實務一律用 LACP active 兩端都設——它是 IEEE 標準，跨廠牌相容，而且會主動偵測對端狀態。
on 模式為什麼危險？它完全不協商，直接強制綁定。如果對面忘了設、或設錯，你這端還是會把流量往多條線送，對面看到的是多條獨立的線，STP 來不及反應 → 立刻產生迴圈。LACP 至少會因為協商失敗而不啟用，安全得多。

八個必須一致的參數

成員埠的以下設定只要有一項不同，該埠就會被踢出 Channel：

  1. 速率（speed）
  2. 雙工（duplex）
  3. Access 或 Trunk 模式
  4. Access VLAN（若為 Access）
  5. Native VLAN（若為 Trunk）
  6. Allowed VLAN 清單（若為 Trunk）
  7. STP 相關參數（cost、port-priority）
  8. MTU

負載分擔：不是「平均分配」

EtherChannel 不會把單一條連線切開來傳。它用雜湊演算法（依 MAC 或 IP 或 Port）決定「這個流量走哪一條實體線」，同一條 TCP 連線永遠只走同一條線。所以：4 條 1 Gbps 綁起來，單一檔案傳輸最快還是只有 1 Gbps。要總量 4 Gbps 必須有夠多的不同來源／目的組合。
! 查目前用什麼演算法
SW1# show etherchannel load-balance
  Source XOR Destination IP address

! 調整（選項依機型不同）
SW1(config)# port-channel load-balance src-dst-ip
! 可選：src-mac / dst-mac / src-dst-mac / src-ip / dst-ip / src-dst-ip
!       src-port / dst-port / src-dst-port（L4，分散最均勻）
怎麼選演算法？看流量特性。伺服器區有大量不同 IP 互連 → src-dst-ip。若流量集中在少數幾對 IP（例如都連同一台備份主機）→ 用 src-dst-port 把 TCP 埠也納入雜湊，分散度才會夠。

12. 實作三：LACP 與 L3 EtherChannel

二層 EtherChannel（Trunk）

! ═══ SW1：注意設定順序 ═══
SW1(config)# interface range gigabitEthernet 0/1 - 2
SW1(config-if-range)# shutdown                             ← 先關，避免綁定過程產生迴圈
SW1(config-if-range)# switchport mode trunk
SW1(config-if-range)# switchport trunk native vlan 999
SW1(config-if-range)# switchport trunk allowed vlan 10,20,30,50,99
SW1(config-if-range)# channel-group 1 mode active          ← LACP 主動
SW1(config-if-range)# no shutdown

! 設定 Port-channel 邏輯介面（設定會自動同步給成員埠）
SW1(config)# interface port-channel 1
SW1(config-if)# description == LACP TO SW2 ==
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk allowed vlan 10,20,30,50,99
設定順序的鐵則：
  1. 先 shutdown 所有要綁的實體埠
  2. 把 VLAN / Trunk 設定弄成完全一致
  3. 下 channel-group
  4. 兩邊都設定完才 no shutdown
跳過第 1 步，在綁定的空窗期就可能形成迴圈，讓網路癱瘓幾十秒。

三層 EtherChannel（核心對核心，跑路由）

SW-CORE1(config)# interface port-channel 10
SW-CORE1(config-if)# no switchport                      ← 關鍵：變成三層介面
SW-CORE1(config-if)# ip address 10.0.0.1 255.255.255.252
SW-CORE1(config-if)# exit

SW-CORE1(config)# interface range ten 1/1/1 - 2
SW-CORE1(config-if-range)# no switchport                 ← 成員埠也要先變三層
SW-CORE1(config-if-range)# no ip address
SW-CORE1(config-if-range)# channel-group 10 mode active
SW-CORE1(config-if-range)# no shutdown
三層 EtherChannel 的順序不能反。必須先在成員埠下 no switchport，再下 channel-group。順序反了，Port-channel 會被建成二層介面，之後再改會出現各種奇怪的殘留設定，通常只能砍掉重建。

完整實作 Lab：雙核心 + LACP + STP 負載分擔

Packet Tracer 或 GNS3，約 75 分鐘。做完你就理解了企業匯聚層的標準設計。

拓樸

   [ SW-CORE1 ]═══ Po10 (2×1G LACP) ═══[ SW-CORE2 ]
       ║  ║                                ║  ║
       ║  ╚════════ Po1 ══════════╗        ║  ║
       ║                          ║        ║  ║
    Po2║                       Po3║        ║  ║

步驟

  1. 四台全部切換到 spanning-tree mode rapid-pvst
  2. 建立 VLAN 10、20、30、99、999
  3. SW-CORE1：VLAN 10,30 priority 4096、VLAN 20,99 priority 8192
  4. SW-CORE2：VLAN 20,99 priority 4096、VLAN 10,30 priority 8192
  5. 兩台核心之間用 Po10，LACP active，兩條 1G
  6. 每台接入交換器各用 2 條線綁成 Port-channel 上行到核心（記得先 shutdown 再綁）
  7. 所有 Port-channel 設成 Trunk，native vlan 999，allowed 10,20,30,99
  8. 所有接電腦的埠：portfast + bpduguard
  9. 兩台核心的下行埠：spanning-tree guard root
  10. 全域開啟 spanning-tree loopguard default 與 udld aggressive
  11. 設定 errdisable recovery cause bpduguard，interval 300

驗收清單

  • show spanning-tree vlan 10 | include This bridge → 只有 SW-CORE1 顯示是 Root
  • show spanning-tree vlan 20 | include This bridge → 只有 SW-CORE2 顯示是 Root
  • show etherchannel summary → 所有 Port-channel 都是 SU，成員全 (P)
  • 在 SW1 上 show spanning-tree vlan 10，Po 的 Type 欄位必須是 P2p，不能是 Shr
  • 拔掉 Po10 其中一條線 → 流量不中斷，show etherchannel summary 少一個成員但 Po 仍是 SU

加碼挑戰

  1. 把一台電腦換成交換器接進 Fa0/3，觀察 BPDU Guard 觸發，再用 show interfaces status err-disabled 確認，等 300 秒看它自動恢復。
  2. 故意把 SW1 的 priority 設成 0，觀察 SW-CORE1 對下埠的 Root Guard 觸發，並用 show spanning-tree inconsistentports 驗證。
  3. 把 Po1 一邊改成 mode passive、另一邊也是 passive，觀察 show etherchannel summary 出現什麼旗標。
  4. 把其中一條成員埠的 allowed vlan 改掉，觀察它被踢成 (s) suspended。

本章重點回顧

  • 乙太訊框沒有 TTL，所以二層迴圈會無限繞 → 廣播風暴 + MAC 震盪 + 訊框重複
  • Bridge ID = Priority(4b) + VLAN ID(12b) + MAC(48b)；Priority 只能是 4096 的倍數
  • 選舉順序：Root Bridge → Root Port → Designated Port → 其餘 Blocking
  • 成本速記：10M=100、100M=19、1G=4、10G=2
  • 802.1D 收斂 30~50 秒；RSTP 靠 Proposal/Agreement 壓到 1 秒內
  • 一定要手動指定 Root，否則 MAC 最小（= 最老的機器）會當選
  • 接末端的埠 PortFast + BPDU Guard；對外埠 Root Guard；光纖 UDLD + Loop Guard
  • EtherChannel 兩邊都用 LACP active；兩個被動湊一起會失敗；on 模式容易造成迴圈
  • EtherChannel 單一連線不會跨線分流，4×1G 的單檔傳輸上限仍是 1 Gbps
學完這章，去 模擬試題 選「交換技術」主題，STP 的計算題是 CCNA 的高頻考點，務必練到能在紙上推出 Blocking 埠。
