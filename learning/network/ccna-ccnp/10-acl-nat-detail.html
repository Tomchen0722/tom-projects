1. ACL 的運作原理與三條鐵則

ACL（Access Control List，存取控制清單）是一串「條件 + 動作」的規則，路由器拿封包去逐條比對，決定放行還是丟棄。

三條鐵則，違反任何一條都會出事：
  1. 由上往下逐條比對，一旦匹配就停止。後面的規則完全不會被看到。
  2. 每個 ACL 結尾都有一條看不見的 deny any any。所以只寫 permit 的 ACL，會擋掉其他所有東西。
  3. 每個介面、每個方向、每個協定，只能套用一個 ACL。三個維度：in/out × IPv4/IPv6 × 介面。
鐵則一的經典錯誤
! ✗ 錯誤：第二行永遠不會被執行
access-list 100 permit ip 192.168.10.0 0.0.0.255 any
access-list 100 deny   ip host 192.168.10.66 any        ← 已經被上一行放行了

! ✓ 正確：具體的規則放前面
access-list 100 deny   ip host 192.168.10.66 any
access-list 100 permit ip 192.168.10.0 0.0.0.255 any
鐵則二的經典錯誤
! 需求：只擋掉業務部連財務伺服器
access-list 100 deny ip 192.168.10.0 0.0.0.255 host 192.168.30.10
! ← 就寫這一行，然後套到介面上

結果：全公司斷網。因為隱含的 deny any any 把其他所有流量也擋了。正確做法要補上：

access-list 100 deny   ip 192.168.10.0 0.0.0.255 host 192.168.30.10
access-list 100 permit ip any any          ← 這行不能忘

兩種 ACL 的能力差異

標準 ACL延伸 ACL
編號範圍1–99、1300–1999100–199、2000–2699
能比對只有來源 IP來源 IP、目的 IP、協定、埠號、旗標
放在哪愈靠近目的地愈好愈靠近來源愈好
實務使用少（多半用在路由過濾、VTY）絕大多數情況
為什麼放置位置相反？標準 ACL 只能看來源，放太前面會把「這個來源去所有地方」都擋掉，所以要放靠近目的地才不會誤傷。延伸 ACL 能精確指定目的地，放靠近來源可以及早丟棄，不浪費中間的頻寬。

進階：不連續的 Wildcard

Wildcard 不像子網路遮罩必須是連續的 1，它可以跳著寫，用來一次匹配特定模式的位址。

需求：一次匹配 192.168.10.0/24、192.168.11.0/24、192.168.12.0/24、192.168.13.0/24

10 = 00001010
11 = 00001011
12 = 00001100
13 = 00001101
　　 ↑↑↑↑　↑↑　　前四位相同(0000)，第 5、6 位不同，第 7、8 位不同

但 10~13 是連續的 → 直接用 192.168.10.0 0.0.3.255（涵蓋 10,11,12,13）
真正需要不連續 Wildcard 的情境：只匹配奇數網段
! 匹配 192.168.1.0、192.168.3.0、192.168.5.0 ... 所有奇數第三段
! 1 = 00000001、3 = 00000011、5 = 00000101 ... 最後一位都是 1
! 前 7 位不管(1111111=254)、最後一位必須相同(0)
access-list 10 permit 192.168.1.0 0.0.254.255

實務上很少用到，但 CCNA 考試喜歡考。看到不連續的 wildcard，就把它轉成二進位找規律。

OSPF 的 network 也用 wildcard，但意義不同。ACL 的 wildcard 是「比對封包的來源／目的 IP」，OSPF 的 wildcard 是「比對本機介面的 IP」。同樣的寫法，用途完全不同，別混淆。

3. 實作一：標準 ACL

access-list <1-99> { permit | deny } <來源> [wildcard]

編號式

! 需求：只允許 192.168.10.0/24 存取，其他全擋
R1(config)# access-list 10 permit 192.168.10.0 0.0.0.255
R1(config)# access-list 10 deny any log          ← 明確寫出來，log 可看到被擋的紀錄

R1(config)# interface gigabitEthernet 0/1
R1(config-if)# ip access-group 10 out

具名式（推薦）

R1(config)# ip access-list standard MGMT-ALLOW
R1(config-std-nacl)# 10 permit 192.168.99.0 0.0.0.255
R1(config-std-nacl)# 20 permit host 203.0.113.50
R1(config-std-nacl)# 30 deny any log
R1(config-std-nacl)# exit
具名式的三個優勢：名字有意義（半年後看得懂）、可以用序號插入或刪除單一條目、不會用光編號。新設定一律用具名式。
標準 ACL 要放靠近目的地。

需求：擋掉 192.168.10.0/24 存取 192.168.30.0/24，但它還是要能上網。

放錯（靠近來源，在 R1 的 Gi0/0 in）：192.168.10.0 的所有流量都被擋，連上網都不行。

放對（靠近目的地，在 R3 連接 192.168.30.0 的介面 out）：只有去 192.168.30.0 的被擋，其他照常。

完整範例：財務伺服器的存取控制
R1(config)# ip access-list extended FINANCE-PROTECT

! 1. 財務部自己完全放行
R1(config-ext-nacl)# permit ip 192.168.30.0 0.0.0.63 any

! 2. 業務部只能連 ERP 的 SQL 埠
R1(config-ext-nacl)# permit tcp 192.168.10.0 0.0.0.255 host 192.168.30.10 eq 1433

! 3. 工程部可以 SSH 進去維護（來源限定跳板機）
R1(config-ext-nacl)# permit tcp host 192.168.20.5 192.168.30.0 0.0.0.63 eq 22

! 4. 允許回應封包進來（重要！沒這行外面回不來）
R1(config-ext-nacl)# permit tcp any 192.168.30.0 0.0.0.63 established

! 5. 允許 DNS 查詢
R1(config-ext-nacl)# permit udp 192.168.30.0 0.0.0.63 any eq 53

! 6. 允許 ping 回應（方便排錯）
R1(config-ext-nacl)# permit icmp any 192.168.30.0 0.0.0.63 echo-reply

! 7. 其他全部拒絕並記錄
R1(config-ext-nacl)# deny ip any any log
R1(config-ext-nacl)# exit

R1(config)# interface vlan 30
R1(config-if)# ip access-group FINANCE-PROTECT in

established 這個關鍵字的意義

ACL 是無狀態的（stateless）。它不知道「這個回應封包是對應到剛剛某個請求」。所以你放行了「內網 → 外網」，回程的封包還是會被 deny any 擋掉，結果就是「什麼都連不上」。

established 的做法：檢查 TCP 表頭的 ACK 或 RST 旗標。有這些旗標代表「這是既有連線的一部分」，不是新的連線請求。

限制：只對 TCP 有效。UDP 沒有旗標，所以 DNS、DHCP 這些要另外開規則。真正需要狀態追蹤要用防火牆或 Reflexive ACL / CBAC / ZBF（第 7 節）。

驗證與命中統計

R1# show access-lists FINANCE-PROTECT
Extended IP access list FINANCE-PROTECT
    10 permit ip 192.168.30.0 0.0.0.63 any (14203 matches)
    20 permit tcp 192.168.10.0 0.0.0.255 host 192.168.30.10 eq 1433 (892 matches)
    30 permit tcp host 192.168.20.5 192.168.30.0 0.0.0.63 eq 22 (12 matches)
    40 permit tcp any 192.168.30.0 0.0.0.63 established (8241 matches)
    50 permit udp 192.168.30.0 0.0.0.63 any eq domain (1502 matches)
    60 permit icmp any 192.168.30.0 0.0.0.63 echo-reply (44 matches)

! 歸零計數器，方便測試某條規則有沒有被命中
R1# clear access-list counters FINANCE-PROTECT
命中數是排錯的關鍵線索。某條 permit 規則命中數是 0 → 那條規則寫錯了或被前面的規則吃掉了。最後的 deny 命中數一直暴增 → 有正常流量被誤擋，配合 show logging 看被擋的是誰。
log 關鍵字要謹慎用。每一筆被記錄的封包都會從硬體交換路徑掉到 CPU 處理（process switching），高流量下可能把 CPU 打滿。正式環境只在最後那條 deny 加 log，而且要搭配 ip access-list logging interval 1000 限制頻率。

5. 放置位置的判斷法

1
先問：這是標準還是延伸？標準 → 靠近目的地。延伸 → 靠近來源。
2
再問：流量的方向是什麼？站在路由器的角度想，不是站在使用者角度。封包「進入」介面是 in，「離開」介面是 out。
3
優先選 in。in 方向的 ACL 在路由查表之前執行，被擋的封包不會浪費路由器的處理資源。out 方向要先查完路由才過濾。
4
畫圖確認。把來源、目的、經過的介面畫出來，標上箭頭方向。這一步不能省。
方向判斷練習
[PC-A 192.168.10.5]──Gi0/0──[ R1 ]──Gi0/1──[Server 192.168.30.10]
需求放哪方向
擋 PC-A 去 ServerGi0/0in（封包從 PC 進入 R1）
擋 Server 回 PC-AGi0/1in（封包從 Server 進入 R1）
擋所有東西去 ServerGi0/1out（封包從 R1 出去給 Server）
套在介面上的 ACL 不會過濾路由器自己產生的流量。Gi0/1 的 out 方向 ACL 擋不住路由器自己發出的 ping、SNMP trap、syslog。要控制路由器自己的流量要用 Control Plane Policing 或在對方的入口擋。
遠端設定 ACL 的自保流程：
  1. 先下 reload in 10（10 分鐘後自動重開，回到未存檔的設定）
  2. 套用 ACL
  3. 確認自己還連得上、業務正常
  4. reload cancel 取消重開
  5. write memory 存檔
如果第 3 步就斷線了，10 分鐘後路由器自己重開，設定回到套用前——你不用開車去機房。

6. 編輯與序號管理

編號式 ACL 不能刪除單一條目。no access-list 100 deny ... 會把整個 ACL 100 刪光。這是機房事故的常見來源。具名式 ACL 才能單條編輯。
! ── 看目前的序號 ──
R1# show access-lists FINANCE-PROTECT
    10 permit ip 192.168.30.0 0.0.0.63 any
    20 permit tcp 192.168.10.0 0.0.0.255 host 192.168.30.10 eq 1433
    30 deny ip any any log

! ── 在 20 和 30 之間插入一條 ──
R1(config)# ip access-list extended FINANCE-PROTECT
R1(config-ext-nacl)# 25 permit tcp host 192.168.20.5 any eq 22

! ── 刪除單一條目 ──
R1(config-ext-nacl)# no 25

! ── 序號用完了？重新編號（間隔 10，從 10 開始）──
R1(config)# ip access-list resequence FINANCE-PROTECT 10 10
建議做法：新建 ACL 時序號用 10、20、30…間隔 10。這樣中間永遠有空間插入。IOS 預設就是這樣自動編號的，但如果你手動指定成 1、2、3，之後就沒地方插了。

安全的修改流程（正式環境）

1
建立一個新名字的 ACL例如 FINANCE-PROTECT-V2，完整寫好所有規則。
2
設 reload in 10 保險萬一改壞了會自己回復。
3
一行指令切換ip access-group FINANCE-PROTECT-V2 in。套新的會自動取代舊的，沒有空窗期。
4
驗證後 reload cancel + write確認業務正常再取消重開並存檔。
5
觀察幾天再刪舊的確定沒問題才 no ip access-list extended FINANCE-PROTECT。
不要用「先移除舊 ACL 再套新 ACL」的做法。中間那幾秒鐘介面是完全沒有保護的。直接套新的會原子性地取代。

7. 進階：時間型、物件群組、反射式

Time-based ACL：上班時間才開放

! 定義時間範圍
R1(config)# time-range WORK-HOURS
R1(config-time-range)# periodic weekdays 08:30 to 18:30
R1(config-time-range)# exit

R1(config)# time-range MAINTENANCE
R1(config-time-range)# absolute start 02:00 15 March 2026 end 06:00 15 March 2026
R1(config-time-range)# exit

! 套用到 ACL 條目
R1(config)# ip access-list extended GUEST-WIFI
R1(config-ext-nacl)# permit tcp 192.168.40.0 0.0.0.255 any eq 443 time-range WORK-HOURS
R1(config-ext-nacl)# deny ip any any
Time-based ACL 完全依賴路由器的時間。沒設 NTP 的話，時間可能停在 1993 年，整條規則永遠不生效或永遠生效。用之前一定要先設好 NTP 和時區： 
R1(config)# clock timezone CST 8
R1(config)# ntp server 118.163.81.61       ← 台灣的 NTP
R1# show ntp status
R1# show clock detail

Object Group：規則多的時候救命

! 定義網路群組
R1(config)# object-group network TRUSTED-ADMINS
R1(config-network-group)# host 192.168.20.5
R1(config-network-group)# host 192.168.20.6
R1(config-network-group)# 192.168.99.0 255.255.255.0
R1(config-network-group)# exit

! 定義服務群組
R1(config)# object-group service MGMT-PORTS
R1(config-service-group)# tcp eq 22
R1(config-service-group)# tcp eq 443
R1(config-service-group)# udp eq 161
R1(config-service-group)# exit

! 一行取代原本要寫 9 行（3 來源 × 3 埠）
R1(config)# ip access-list extended MGMT-ACL
R1(config-ext-nacl)# permit object-group MGMT-PORTS object-group TRUSTED-ADMINS any
Object Group 的最大價值是維護。新增一台管理主機時，只要在 object-group 裡加一行，所有引用它的 ACL 自動生效，不用去改十幾條規則。企業環境強烈建議使用。

Reflexive ACL：模擬狀態追蹤

! 出去的流量建立一個暫時的「反射項目」
R1(config)# ip access-list extended OUTBOUND
R1(config-ext-nacl)# permit tcp any any reflect TCP-SESSIONS timeout 300
R1(config-ext-nacl)# permit udp any any reflect UDP-SESSIONS timeout 60
R1(config-ext-nacl)# permit icmp any any reflect ICMP-SESSIONS timeout 10
R1(config-ext-nacl)# exit

! 進來的流量比對那些反射項目
R1(config)# ip access-list extended INBOUND
R1(config-ext-nacl)# evaluate TCP-SESSIONS
R1(config-ext-nacl)# evaluate UDP-SESSIONS
R1(config-ext-nacl)# evaluate ICMP-SESSIONS
R1(config-ext-nacl)# deny ip any any log
R1(config-ext-nacl)# exit

R1(config)# interface gigabitEthernet 0/1
R1(config-if)# ip access-group OUTBOUND out
R1(config-if)# ip access-group INBOUND in

R1# show ip access-lists TCP-SESSIONS       ! 看目前有哪些活躍 session
Reflexive ACL 比 established 好在哪？它對 UDP 和 ICMP 也有效，而且是真的追蹤「這個回應是對應到哪個請求」，不是只看 ACK 旗標。缺點是不懂應用層協定（例如 FTP 主動模式的資料通道會被擋）。要處理那種情況需要 ZBF（Zone-Based Firewall），那是 CCNP Security 的範圍。

8. 保護 VTY 與管理平面

路由器暴露 SSH／Telnet 給整個網路是重大資安缺口。就算有密碼，暴力破解和已知漏洞掃描也是實際威脅。限制來源是最有效的一道防線。
! ── 1. 定義誰可以連進來 ──
R1(config)# ip access-list standard VTY-ACCESS
R1(config-std-nacl)# permit 192.168.99.0 0.0.0.255       ← 管理網段
R1(config-std-nacl)# permit host 203.0.113.50              ← 遠端維護跳板機
R1(config-std-nacl)# deny any log
R1(config-std-nacl)# exit

! ── 2. 套用到 VTY（注意是 access-class，不是 access-group）──
R1(config)# line vty 0 15
R1(config-line)# access-class VTY-ACCESS in
R1(config-line)# transport input ssh                     ← 只准 SSH，關掉 Telnet
R1(config-line)# exec-timeout 10 0                       ← 閒置 10 分鐘自動登出
R1(config-line)# login local
R1(config-line)# logging synchronous
介面用 ip access-group，VTY 用 access-class。這是考試必考的區別，也是實務上打錯會被 IOS 拒絕的地方。

完整的 SSH 加固

R1(config)# hostname R1
R1(config)# ip domain-name corp.local
R1(config)# crypto key generate rsa modulus 2048      ← 至少 2048
R1(config)# ip ssh version 2
R1(config)# ip ssh time-out 60
R1(config)# ip ssh authentication-retries 3
R1(config)# username admin privilege 15 secret Str0ng-P@ssw0rd
R1(config)# service password-encryption

! 登入失敗自動封鎖
R1(config)# login block-for 120 attempts 3 within 60
! ↑ 60 秒內失敗 3 次 → 封鎖 120 秒
R1(config)# login on-failure log
R1(config)# login on-success log

R1# show ip ssh
R1# show login
路由器的密碼建議搭配 TACACS+ 或 RADIUS 集中管理。用本機帳號的話，員工離職時你要一台一台改密碼；集中認證只要在一個地方停用帳號。這在有稽核需求的企業是必要的。

permit icmp any any nd-ns
deny ipv6 any any
IPv6 的隱含規則多了兩條，這是關鍵設計。IPv6 用 NDP（Neighbor Discovery Protocol）取代 ARP，nd-na／nd-ns 就是 NDP 的訊息。如果沒有這兩條隱含放行，套上 ACL 之後整個網段會立刻失去鄰居解析能力，所有裝置都無法通訊。

但是：如果你自己在 ACL 結尾寫了明確的 deny ipv6 any any，隱含規則就不會生效——你必須自己補上 NDP 放行： 
R1(config-ipv6-acl)# permit icmp any any nd-na
R1(config-ipv6-acl)# permit icmp any any nd-ns
R1(config-ipv6-acl)# deny ipv6 any any log
R1(config)# ipv6 access-list BLOCK-GUEST
R1(config-ipv6-acl)# permit tcp 2001:db8:0:40::/64 any eq 443
R1(config-ipv6-acl)# permit udp 2001:db8:0:40::/64 any eq 53
R1(config-ipv6-acl)# permit icmp any any nd-na
R1(config-ipv6-acl)# permit icmp any any nd-ns
R1(config-ipv6-acl)# deny ipv6 any any log
R1(config-ipv6-acl)# exit

R1(config)# interface gigabitEthernet 0/2
R1(config-if)# ipv6 traffic-filter BLOCK-GUEST in

R1# show ipv6 access-list

10. NAT 四個術語與運作

NAT（Network Address Translation）把私有 IP 換成公有 IP，讓內網可以上網。它解決了 IPv4 位址不足的問題，也順便提供了一層隱藏內網結構的保護。

Inside Local內部主機的真實私有位址。
例：192.168.10.5
Inside Global內部主機在外面看起來的公有位址。
例：203.0.113.10
Outside Local外部主機在內網看起來的位址。
通常等於 Outside Global
Outside Global外部主機的真實公有位址。
例：8.8.8.8
記憶法，拆成兩個字來看：
Inside / Outside → 這台機器實際在哪一邊
Local / Global → 從內網看到的名字 / 從外網看到的名字
所以 Inside Local = 內部機器、內網看到的位址 = 它的真實私有 IP。
Inside Global = 內部機器、外網看到的位址 = 轉換後的公有 IP。

三種 NAT

類型對應關係用途
Static NAT1 對 1，固定對外提供服務的伺服器
Dynamic NAT多對多，從位址池動態取用公有位址夠多的情況（現在很少）
PAT / NAT Overload多對一，靠埠號區分99% 的企業和家用場景
PAT 的理論上限與實際上限。理論上一個公有 IP 有 65535 個埠，但實際可用的動態埠範圍約 1024–65535，即 6 萬多個。而且：
  • 現代網頁一次可能開 10–20 個並行連線
  • 手機 App 背景同步也在佔用
  • 轉換項目有逾時時間（TCP 預設 24 小時），不會馬上釋放
經驗值：一個公有 IP 大約支撐 200–500 個使用者。超過就要準備位址池。

11. 實作三：靜態、動態、PAT

共同的第一步：標記介面

R1(config)# interface gigabitEthernet 0/0
R1(config-if)# ip nat inside                    ← 面向內網
R1(config-if)# exit

R1(config)# interface gigabitEthernet 0/1
R1(config-if)# ip nat outside                   ← 面向外網
忘記標記 inside/outside 是最常見的 NAT 故障。設定全部正確、show ip nat translations 卻永遠是空的，八成就是這兩行沒下。而且如果有多個內網介面（多個 VLAN），每一個都要標 inside。

PAT：最常用的設定

! ── 步驟 1：定義「哪些內網位址要被轉換」──
R1(config)# ip access-list standard NAT-INSIDE
R1(config-std-nacl)# permit 192.168.10.0 0.0.0.255
R1(config-std-nacl)# permit 192.168.20.0 0.0.0.255
R1(config-std-nacl)# permit 192.168.30.0 0.0.0.63
R1(config-std-nacl)# exit

! ── 步驟 2：用出口介面的 IP 做 overload ──
R1(config)# ip nat inside source list NAT-INSIDE interface gigabitEthernet 0/1 overload
這個 ACL 的 deny 意義跟過濾時完全不同。在 NAT 裡：
  • permit = 「這些位址要被轉換」
  • deny = 「這些位址不要被轉換」（不是「擋掉」！）
這在有 VPN 的環境非常重要——要去 VPN 對端的流量必須 deny（不轉換），否則封包被 NAT 掉就進不了 VPN 通道。這叫 NAT Exemption。 
! VPN 環境的正確寫法（延伸 ACL 才能指定目的地）
R1(config)# ip access-list extended NAT-INSIDE
R1(config-ext-nacl)# deny ip 192.168.10.0 0.0.0.255 172.16.0.0 0.0.255.255   ← 去分公司的不轉換
R1(config-ext-nacl)# permit ip 192.168.10.0 0.0.0.255 any                    ← 其他的轉換

PAT 用位址池（使用者多的時候）

R1(config)# ip nat pool PUBLIC-POOL 203.0.113.10 203.0.113.14 netmask 255.255.255.248
R1(config)# ip nat inside source list NAT-INSIDE pool PUBLIC-POOL overload

Static NAT：伺服器對外

! 整台機器 1 對 1 對應
R1(config)# ip nat inside source static 192.168.30.10 203.0.113.20

Dynamic NAT（不 overload）

R1(config)# ip nat pool DYN-POOL 203.0.113.30 203.0.113.39 netmask 255.255.255.240
R1(config)# ip nat inside source list NAT-INSIDE pool DYN-POOL
! 沒有 overload → 位址用完了，第 11 個使用者就上不了網

驗證

R1# show ip nat translations
Pro  Inside global      Inside local       Outside local      Outside global
tcp  203.0.113.2:1055   192.168.10.5:1055   142.250.1.1:443    142.250.1.1:443
tcp  203.0.113.2:1056   192.168.10.8:1055   142.250.1.1:443    142.250.1.1:443
!                  ↑ 兩台不同電腦用了相同的來源埠，PAT 改寫其中一個以區分
---  203.0.113.20       192.168.30.10      ---                ---
!    ↑ Static NAT 沒有協定和埠，永久存在

R1# show ip nat statistics
Total active translations: 47 (1 static, 46 dynamic; 46 extended)
Outside interfaces: GigabitEthernet0/1
Inside interfaces: GigabitEthernet0/0
Hits: 28492  Misses: 0
Expired translations: 1204

! 清除（Static 不會被清掉）
R1# clear ip nat translation *

調整逾時（NAT 表滿了的時候）

R1(config)# ip nat translation timeout 3600          ! 一般，預設 86400（24 小時）
R1(config)# ip nat translation tcp-timeout 3600
R1(config)# ip nat translation udp-timeout 300       ! 預設 300
R1(config)# ip nat translation icmp-timeout 60
R1(config)# ip nat translation max-entries 20000     ! 上限保護
什麼時候該調 timeout？show ip nat statistics 的 Misses 一直增加，或 active translations 逼近上限時。預設的 24 小時 TCP timeout 在使用者多的環境會累積大量殭屍項目，調成 1 小時通常就解決了。

12. 實作四：埠轉發與伺服器對外

公司只有一個公有 IP，但要對外提供網站（80/443）和郵件（25）——這些服務在不同的內部伺服器上。解法是依埠號轉發。

! ── 網站：外部連 203.0.113.2:443 → 內部 192.168.30.20:443 ──
R1(config)# ip nat inside source static tcp 192.168.30.20 443 interface gi0/1 443

! ── 換埠也可以：外部 8443 → 內部 443 ──
R1(config)# ip nat inside source static tcp 192.168.30.20 443 interface gi0/1 8443

! ── 郵件在另一台 ──
R1(config)# ip nat inside source static tcp 192.168.30.25 25 interface gi0/1 25

! ── UDP 也可以（例如 VPN）──
R1(config)# ip nat inside source static udp 192.168.30.30 500 interface gi0/1 500
NAT 和 ACL 的執行順序決定你的 ACL 該怎麼寫。
方向執行順序ACL 該用哪個位址
Inside → Outside先 ACL（in），再路由，再 NAT私有位址（192.168.x.x）
Outside → Inside先 NAT，再 ACL，再路由私有位址（NAT 已經轉換完了）
結論：兩個方向的 ACL 都用私有位址寫。很多人在 outside in 的 ACL 裡寫公有位址，結果永遠不匹配。
完整的對外服務保護
! 埠轉發
R1(config)# ip nat inside source static tcp 192.168.30.20 443 interface gi0/1 443

! 外部進來的 ACL —— 注意用「私有位址」當目的地
R1(config)# ip access-list extended FROM-INTERNET
R1(config-ext-nacl)# permit tcp any host 192.168.30.20 eq 443
R1(config-ext-nacl)# permit tcp any any established
R1(config-ext-nacl)# permit icmp any any echo-reply
R1(config-ext-nacl)# permit icmp any any packet-too-big       ← PMTUD 需要，別擋
R1(config-ext-nacl)# deny ip 10.0.0.0 0.255.255.255 any log      ← 擋偽造私有來源
R1(config-ext-nacl)# deny ip 172.16.0.0 0.15.255.255 any log
R1(config-ext-nacl)# deny ip 192.168.0.0 0.0.255.255 any log
R1(config-ext-nacl)# deny ip any any log
R1(config-ext-nacl)# exit

R1(config)# interface gigabitEthernet 0/1
R1(config-if)# ip access-group FROM-INTERNET in
不要擋掉 icmp packet-too-big（IPv4 是 unreachable 的一種）。它是 Path MTU Discovery 的核心。擋掉之後症狀是「小封包通、大檔案傳到一半卡住」——這種問題可以查上一整天。

NAT 迴環（Hairpin）：內部用網域名稱連自家伺服器

常見抱怨：「在公司內網打 www.company.com 連不上，用手機 4G 就可以」。

原因：內網 DNS 回傳的是公有 IP 203.0.113.2。封包從內網送出，目的地是自己路由器的外部 IP——路由器不會把它繞回內網。

三種解法（由好到差）：
  1. Split DNS（推薦）：內部 DNS 直接回傳私有 IP 192.168.30.20。最乾淨、沒有效能損失。
  2. NAT hairpin：在路由器上做迴環轉換，設定複雜且吃 CPU。
  3. 叫使用者記私有 IP。（不要這樣做）

13. 故障排除

1
介面標記了嗎？show ip nat statistics 看 Inside/Outside interfaces 兩行。空的就是沒標。多 VLAN 環境每個內網介面都要標。
2
轉換有產生嗎？show ip nat translations。空的 → ACL 沒匹配到，或介面沒標。
3
ACL 匹配了嗎？show access-lists NAT-INSIDE 看命中數。0 就是 wildcard 寫錯或網段不對。
4
路由通嗎？NAT 只負責改位址，路由是另一回事。show ip route 0.0.0.0 確認有預設路由。
5
對外的位址池有效嗎？公有 IP 必須是 ISP 真的路由給你的。用了不屬於自己的位址，封包出去了回不來。
6
ACL 擋住了嗎？注意上一節講的順序——outside in 的 ACL 要用私有位址。
7
轉換表滿了嗎？show ip nat statistics 的 Misses 一直增加就是。調 timeout 或加位址池。
8
用 debug 追debug ip nat，但一定要先用 ACL 限制範圍，不然訊息量會把路由器打掛。
! 安全的 NAT debug
R1(config)# access-list 199 permit ip host 192.168.10.5 any
R1# debug ip nat 199
R1# undebug all            ← 用完立刻關

! 逐跳確認轉換有沒有發生
R1# show ip nat translations verbose
真實案例：「新加的 VLAN 上不了網，舊的都正常」

排查：show ip nat statistics → Inside interfaces 只列了 Vlan10、Vlan20，沒有新加的 Vlan40。

原因：新建 SVI 時忘了下 ip nat inside。啟示：每次新增內網介面都要記得標記，這個檢查應該寫進部署清單。

真實案例：「VPN 建起來了，但兩邊互相 ping 不到」

排查：show ip nat translations → 看到去分公司 172.16.x.x 的流量被 NAT 成公有 IP 了。

原因：NAT ACL 用 permit 192.168.10.0 0.0.0.255（標準 ACL，看不到目的地），所以去 VPN 的流量也被轉換。修法：改成延伸 ACL 並在最前面加 deny ip 192.168.10.0 0.0.0.255 172.16.0.0 0.0.255.255。

完整實作 Lab：分段防護 + PAT + 對外服務

Packet Tracer 或 GNS3，約 80 分鐘。

拓樸

                    [ Internet ]  8.8.8.8
                          │ 203.0.113.1
                       Gi0/1 (outside) 203.0.113.2/30
                       [ R1 ]
                       Gi0/0 (inside) trunk
                          │
                    [ SW-L3 ]
        ┌───────┬─────────┼─────────┬────────┐
     VLAN10   VLAN20   VLAN30    VLAN40   VLAN99
      業務     工程      財務      訪客      管理
   .10.0/24 .20.0/24 .30.0/26  .40.0/24 .99.0/28
                        └ Web 30.20
                        └ SQL 30.10

步驟

  1. 建立所有 VLAN 與 SVI，R1 用單臂路由或三層交換器都可以
  2. R1 的 Gi0/0 標 ip nat inside、Gi0/1 標 ip nat outside（若用 SVI 則每個 SVI 都要標）
  3. 設定 PAT：VLAN 10/20/30 可以上網，VLAN 99 不可以（管理網段不該對外）
  4. VLAN 40 訪客只能走 tcp/443 和 udp/53，且限定上班時間（time-range）
  5. 寫 FINANCE-PROTECT：業務部只能連 30.10 的 1433；工程部跳板機 20.5 可以 SSH 進 VLAN 30；訪客完全不能碰 VLAN 30
  6. 設定埠轉發：外部 443 → 192.168.30.20:443
  7. 寫 FROM-INTERNET ACL 套在 Gi0/1 in，記得用私有位址，並放行 established 與 packet-too-big
  8. 建立 VTY-ACCESS，只允許 VLAN 99 SSH，套用 access-class
  9. 設定 NTP + timezone（time-range 的前提）
  10. 建立 object-group 管理跳板機清單

驗收清單

  • VLAN 10/20/30 的 PC 都能 ping 8.8.8.8；VLAN 99 不能
  • show ip nat translations 看得到各 VLAN 的轉換項目
  • VLAN 10 的 PC 能連 30.10:1433，但 ping 不到 30.10（ACL 只放行 tcp/1433）
  • VLAN 40 訪客在上班時間能開 https 網站，改路由器時間到半夜後就不行
  • 從外部（模擬 Internet 的 PC）連 203.0.113.2:443 能到 Web 伺服器
  • 從 VLAN 10 SSH 到 R1 被拒絕；從 VLAN 99 可以
  • show access-lists 每條 permit 的命中數都 > 0（代表規則都有用到，沒有死規則）

加碼挑戰

  1. 把 FINANCE-PROTECT 最後的 permit ip any any 拿掉，觀察多少服務瞬間中斷，體會隱含 deny。
  2. 把 NAT 的 ACL 從標準改成延伸，加上 deny ip 192.168.10.0 0.0.0.255 172.16.0.0 0.0.255.255，驗證去 172.16.x.x 的流量不會出現在 NAT 表裡。
  3. 在 FROM-INTERNET 裡故意用公有位址 203.0.113.2 當目的地，觀察為什麼永遠不匹配。
  4. 設定 Reflexive ACL 取代 established，測試 UDP（DNS）在兩種做法下的差異。
  5. 把 R1 的時間改到半夜，用 show access-lists 觀察 time-range 那條規則消失。
  6. 用 ip access-list resequence 把某個 ACL 重新編號，然後在中間插入一條新規則。

本章重點回顧

  • ACL 三鐵則：由上往下、隱含 deny any、每介面每方向每協定只能一個
  • Wildcard = 255.255.255.255 − 子網路遮罩；0 = 要相同，1 = 不管
  • 標準 ACL 靠近目的地，延伸 ACL 靠近來源；優先選 in 方向
  • 只寫 deny 而忘了補 permit ip any any = 全公司斷網
  • ACL 是無狀態的，回程要靠 established（僅 TCP）或 Reflexive ACL（含 UDP/ICMP）
  • 編號式 ACL 不能刪單條；一律用具名式，序號間隔 10
  • 介面用 ip access-group，VTY 用 access-class
  • IPv6 ACL 隱含放行 nd-na / nd-ns，自己寫 deny 就要手動補回來
  • NAT 四術語：Inside/Outside 是機器在哪邊，Local/Global 是從哪邊看
  • NAT 的 ACL 裡 deny = 不轉換，不是「擋掉」——VPN 環境的關鍵
  • 兩個方向的 ACL 都用私有位址寫；別擋 packet-too-big
  • 忘記 ip nat inside/outside 是最常見的 NAT 故障
ACL 和 NAT 在 CCNA 佔比很高，而且題目常是「給一段設定，問哪個封包會被擋」。去 模擬試題 選「網路資安」和「IP 服務」兩個主題各練一輪。
