RBAC、TACACS+、First Hop Security、MACsec、CoPP——資料中心的設備安全和企業網路的重點不太一樣，尤其是控制平面保護。

1. RBAC：不要每個工程師都給 admin

很多機房的現況是「大家共用一組 admin 密碼」。
出事時你查不出是誰下的指令，離職時你也不敢改密碼（怕改了什麼會壞掉）。
NX-OS 內建角色權限
network-admin完整讀寫（等同 root）
network-operator唯讀
vdc-admin該 VDC 內完整權限
vdc-operator該 VDC 內唯讀
# 自訂角色：只讓儲存團隊管 VSAN，不能碰路由 N9K(config)# role name storage-team N9K(config-role)# description 儲存團隊 N9K(config-role)# rule 1 permit read N9K(config-role)# rule 2 permit command show * N9K(config-role)# rule 3 permit config feature vsan N9K(config-role)# rule 4 deny command configure terminal ; router * N9K(config)# username alice password S3cure role storage-team N9K# show role N9K# show user-account
陷阱：規則編號由大到小評估
NX-OS 的角色規則是從編號最大的往下比對，第一個符合的就決定結果。
這和一般 ACL「由上往下」的直覺相反，設定時很容易搞錯優先順序。

2. AAA 與 SSH

RADIUSTACACS+
傳輸UDP 1812/1813TCP 49
加密只加密密碼整個封包
AAA 拆分驗證授權綁一起三者獨立
DC 用途使用者網路存取設備管理與指令授權 ✅
✅ 資料中心的設備管理一律用 TACACS+，因為它能做到指令層級的授權與稽核——「誰在幾點下了哪一條指令」全部有紀錄。這是法遵稽核的基本要求。
N9K(config)# feature tacacs+ N9K(config)# tacacs-server host 10.1.1.20 key 7 MySecretKey N9K(config)# aaa group server tacacs+ TACGROUP N9K(config-tacacs+)# server 10.1.1.20 N9K(config)# aaa authentication login default group TACGROUP local N9K(config)# aaa accounting default group TACGROUP ↑ local 當後備,避免 TACACS 掛掉就登不進去 # SSH N9K(config)# ssh key rsa 2048 force N9K(config)# feature ssh N9K(config)# no feature telnet ← 一定要關
陷阱：一定要留 local 後備
如果 AAA 只設 group TACGROUP 而沒有 local，TACACS 伺服器一掛你就完全登不進交換器——而且通常是在網路出事的時候一起掛。
這是實務上真的會發生的災難，務必留本機帳號當後備。

3. First Hop Security

和第 14 章（CCNA）的二層資安同一套邏輯，但在資料中心規模更大、影響更廣。

DHCP Snooping建立 IP-MAC-埠 綁定表，是後面兩者的地基。
DAI比對 ARP 宣告是否與綁定表相符，擋 ARP 毒化。
IP Source Guard擋來源 IP 偽造。
Port Security限制每埠的 MAC 數量。DC 要注意虛擬化環境一個埠後面有很多 VM。
DC 特有的注意事項
伺服器埠後面可能有幾十台虛擬機，每台都有自己的 MAC。
如果照企業網路的習慣設 port-security maximum 2，一開機就會把整台實體主機的網路關掉。
DC 的接入埠要依實際 VM 密度調整上限，或改用其他機制。

4. MACsec：線路層加密

MACsec 補的是哪個洞 TLS/IPsec 保護的是應用層與網路層 但實體線路上的原始訊框仍是明文 威脅情境: • 機房間的暗光纖被竊聽（光纖分光很容易） • 跨大樓的線路經過不受控區域 • 內部人員在配線間接線側錄 MACsec（IEEE 802.1AE） 在第二層逐跳加密整個訊框 線上跑的東西即使被截走也是密文
項目說明
標準IEEE 802.1AE
加密AES-GCM 128／256
金鑰協商MKA（MACsec Key Agreement）
特性逐跳（hop-by-hop）——每一段各自加密，中繼設備看得到明文
必考：MACsec 是逐跳，不是端對端
這是它和 IPsec/TLS 最大的差別。MACsec 保護的是「這一段線路」，封包到了對端交換器會被解密，再由下一段重新加密。
所以它防的是「線路被竊聽」，不是「中繼設備不可信」。如果連中繼設備都不信任，要用端對端的 IPsec。

5. CoPP：保護控制平面

為什麼交換器會被「打死」 資料平面（Data Plane）= 硬體 ASIC 轉發,速度極快 控制平面（Control Plane）= CPU 處理,速度慢很多 哪些封包會上送 CPU? • 路由協定（OSPF、BGP）的 Hello 與更新 • ARP、ICMP • SSH/SNMP 管理流量 • TTL 過期、需要 ICMP 回覆的封包 攻擊手法:大量送這類封包 → CPU 100% → 路由協定鄰居斷線 → 整台設備失效 不需要打穿任何漏洞,只要讓 CPU 忙不過來 CoPP = 對「上送 CPU 的流量」套用 QoS 政策 重要的（路由協定）優先且保障頻寬 次要的（ICMP）限速 可疑的直接丟
# NX-OS 內建幾種預設策略,通常直接套用即可 N9K(config)# copp profile strict ← 最嚴格 N9K(config)# copp profile moderate N9K(config)# copp profile lenient N9K# show copp status N9K# show policy-map interface control-plane ← 看有沒有被丟棄的封包
✅ 排錯用途：show policy-map interface control-plane 的 drop 計數如果一直增加，代表有東西在對控制平面送過量流量——可能是攻擊，也可能是某個設定錯誤造成的迴圈。這是很有價值的健康指標。
