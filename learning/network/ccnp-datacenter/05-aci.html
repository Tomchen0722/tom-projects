Cisco ACI：架構與政策模型

ACI 把網路從「一台一台設定」變成「對整個機房下政策」。這一章講 Spine-Leaf 架構、Tenant 到 EPG 的階層，以及最容易卡住的 Contract 方向。

1. ACI 到底改變了什麼

傳統網路管理像一台一台交代：這台交換器開這個 VLAN、那台設這條 ACL。你要記得每一台的狀態。
ACI 像對整個機房下一份政策：「財務系統只能被財務部存取」——至於要在哪幾台交換器上設什麼，控制器自己去算。
兩種思維的根本差別 傳統（命令式 Imperative） 你說:「在 Leaf-1 的 Eth1/5 設 VLAN 10」 「在 Leaf-2 的 Eth1/8 設 VLAN 10」 「在核心加一條 ACL 擋 A 到 B」 → 你要知道每一台的位置與狀態 → 漏設一台就出問題,而且很難發現 ACI（宣告式 Declarative） 你說:「Web 群組可以用 TCP 443 連 App 群組」 → APIC 自己算出要在哪些 Leaf 下什麼設定 → 伺服器搬到別的機櫃,政策自動跟著走 關鍵字:意圖（intent） 你描述「想要什麼結果」,不描述「怎麼做」
✅ ACI 最實際的價值：政策跟著工作負載走。傳統上虛擬機從機櫃 A 搬到機櫃 B，網路組要重新設定 VLAN 與 ACL；在 ACI 裡，工作負載屬於哪個 EPG 就套用哪些政策，換位置不用改設定。

2. 架構：Spine-Leaf 與 APIC

ACI Fabric 拓撲 Spine-1 Spine-2 ╱ │ ╲ ╱ │ ╲ ╱ │ ╲ ╱ │ ╲ Leaf-1 Leaf-2 Leaf-3 Leaf-4 ... │ │ │ │ 伺服器 伺服器 防火牆 對外路由器 規則（考試會問） • 每個 Leaf 都連到每個 Spine • Leaf 之間不互連 • Spine 之間不互連 • 所有端點都接在 Leaf 上,Spine 不接任何終端裝置 → 任兩台伺服器之間永遠只隔兩跳（可預測的延遲） APIC（Application Policy Infrastructure Controller） • 集中管理的控制器,通常 3 台一組 • 只做管理平面——APIC 全掛,資料流量照常轉發 • 底層跑 IS-IS（自動化,你不用設）+ VXLAN 封裝
必考：APIC 掛掉會怎樣
資料流量完全不受影響，因為 APIC 只負責政策的下發與管理，實際轉發是 Leaf/Spine 在做。
影響的是：不能做設定變更、看不到集中監控。

APIC 建議三台叢集：掛一台仍可讀寫；掛兩台只剩唯讀（因為失去多數決）。
Fabric Discovery接上線後透過 LLDP 自動發現，管理員在 APIC 上逐台「註冊」即納入 fabric。不用手動設 IP。
底層自動化IS-IS 與 VXLAN 都是 ACI 自己管的，你不會也不該手動設定。
Object Model所有設定都是物件（MO），有唯一的 DN 路徑。整台 APIC 的功能都能透過 REST API 操作。
三種紀錄Fault（目前的問題）、Event（發生過的事）、Audit Log（誰改了什麼）。排錯先看 Fault。

3. 邏輯模型：Tenant 到 EPG

由上而下的階層 Tenant（租戶） ── 最上層的隔離單位 │ 例:Production、Development、某個部門 │ ├── VRF（Context）── 一個獨立的路由表 │ │ 同一個 Tenant 可以有多個 VRF │ │ 不同 VRF 的 IP 可以重複 │ │ │ └── Bridge Domain（BD） ── 二層的邊界 │ │ ≈ 傳統的 VLAN,但更靈活 │ │ 一個 BD 可以有多個子網 │ │ │ └── EPG（Endpoint Group） ── 政策的最小單位 │ 端點依「角色」分組 │ 例:Web-EPG、App-EPG、DB-EPG │ └── Application Profile（AP） ── 把相關的 EPG 收在一起 例:「電商系統」含 Web / App / DB 三個 EPG
最重要的觀念：EPG 與 VLAN 解耦
傳統上「同一個 VLAN 的機器可以互通」。ACI 不是這樣：
同一個 Bridge Domain 裡的不同 EPG，預設「不能」互通——必須有 Contract 才通。

這就是 白名單模型：預設全部禁止，明確允許才通。和傳統網路「預設全通、用 ACL 擋」的黑名單模型剛好相反。

考試常問：兩台伺服器在同一個 BD、同一個子網，但屬於不同 EPG，能不能通？→ 不能，除非有 Contract。
EPG 怎麼分類端點可依 實體埠 + VLAN、VMM 整合（虛擬機的 port group）、IP 或 MAC。
BD 的關鍵設定ARP Flooding（預設關，用代答）、Unicast Routing（要做三層才開）、L2 Unknown Unicast（Hardware Proxy 或 Flood）。
Hardware Proxy未知單播不氾濫，改送到 Spine 查詢代理資料庫。這是 ACI 減少氾濫的關鍵。
Preferred Group把幾個 EPG 放進偏好群組，群組內免 Contract 互通。方便但要謹慎用。

4. Contract：ACI 的防火牆規則

Contract 的三層結構 Contract（合約） └── Subject（主題） └── Filter（過濾器） └── Entry:協定 + 埠號 誰提供、誰消費 Provider（提供者） ←─── Contract ───→ Consumer（消費者） 提供服務的一方 發起連線的一方 例:Web-EPG 要連 App-EPG 的 8080 → App-EPG 是 Provider（它提供 8080 服務） → Web-EPG 是 Consumer（它去用這個服務） 方向搞反是最常見的設定錯誤
必考：Provider vs Consumer 怎麼判斷
問一句話：「誰在監聽那個埠？」
監聽的那一方就是 Provider；主動去連的是 Consumer。

例：使用者瀏覽器連 Web 伺服器的 443 → Web-EPG 是 Provider，外部 EPG 是 Consumer。
方向設反的症狀：連線不通，但 Contract 看起來「有設」——這是 ACI 新手最常卡住的地方。
✅ vzAny 的用途：如果某個服務要讓 VRF 內所有 EPG 都能用（例如 DNS、NTP），不必為每個 EPG 各建一條 Contract——用 vzAny 代表「這個 VRF 內的所有 EPG」，一條搞定。
這在大型環境能把 Contract 數量從幾百條降到幾十條。

5. 對外連線：L2Out 與 L3Out

L2OutL3Out
用途把 ACI 內的二層延伸到外部ACI 與外部做三層路由
典型場景遷移期間與舊網路並存連到 WAN、防火牆、其他機房
協定—靜態路由、OSPF、BGP、EIGRP
外部端點怎麼表示External Bridged NetworkExternal EPG（用子網來分類）
陷阱：External EPG 也要 Contract
很多人設好 L3Out、路由也通了，但流量還是不通——因為忘了在 External EPG 與內部 EPG 之間建立 Contract。

記住 ACI 的白名單原則：路由通 ≠ 政策通。這兩件事是分開的。
✅ L3Out 的 External EPG 用「子網」分類外部端點。例如把 0.0.0.0/0 設成一個 External EPG 代表「整個外部世界」，或用更細的子網區分不同外部來源，套用不同的 Contract。

6. VMM 整合與 Service Graph

VMM Domain（虛擬機管理整合）

ACI 可以直接與 VMware vCenter、Hyper-V、OpenStack 整合，自動在虛擬化平台上建立對應的 port group。

整合後的流程 管理員在 APIC 建立 EPG「Web-EPG」 ↓ 自動 vCenter 上出現對應的 port group ↓ 虛擬機管理員把 VM 接到那個 port group ↓ 自動 ACI 知道這台 VM 屬於 Web-EPG,政策自動套用 ↓ VM 遷移到別台主機 → 政策跟著走,不用改設定 Resolution Immediacy（何時把政策下到 Leaf） On Demand ── 有 VM 真的上線才下（最省硬體資源） Immediate ── 一整合就下 Pre-provision ── 連 VMM 都還沒連上就先下（管理網路用）

Service Graph（服務插入）

要讓流量經過防火牆或負載平衡器，傳統做法是手動改路由或 VLAN 把流量「拐」過去——設定複雜且容易出錯。

✅ Service Graph 讓你用宣告的方式指定：「Web-EPG 到 App-EPG 的流量，中間要經過這台防火牆」。ACI 自動處理 VLAN 拼接與導流。

PBR（Policy-Based Redirect）是最常用的模式：不改變原本的路由，只是把符合條件的流量重導向到服務裝置。這樣防火牆不用當閘道，架構單純很多。

7. 管理與維運

Out-of-Band (OOB)走獨立的管理網路。fabric 出事時仍能連上，這是首選。
In-Band走 fabric 本身。頻寬大但 fabric 掛了就連不上。
設定備份APIC 可排程匯出設定快照，變更前務必先做。支援回滾。
升級先升 APIC 叢集，再分批升 Spine 與 Leaf（維持冗餘不中斷）。
排錯順序
① 看 Fault——ACI 會主動把問題列出來，而且附建議。這是最快的路徑。
② 檢查 Contract 方向——連線不通九成是 Provider/Consumer 設反或漏建。
③ 確認端點有沒有被學到——在 APIC 查該 EPG 的 endpoint 清單。
④ Audit Log——「昨天還好好的」就去看誰改了什麼。
