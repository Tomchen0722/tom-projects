1. 為什麼資料中心特別需要 Multicast

單播（Unicast）像一對一寄信——要寄給 100 人就印 100 份。
廣播（Broadcast）像對整棟大樓喊話——不管你要不要聽都聽得到。
多播（Multicast）像訂閱制的社區廣播——只有訂閱的人收得到，而且來源只送一份，中途才複製。
同樣送一份 1Gbps 的影音給 50 台伺服器 單播:來源要送 50 份 = 50 Gbps 出口頻寬 廣播:全網段都收到,包含不需要的機器（浪費 + 資安風險） 多播:來源只送 1 份,交換器在分歧點才複製 資料中心的常見用途 • 金融交易的行情推送（同一份報價給幾百個交易系統） • 影音串流與監控 • 叢集心跳與狀態同步 • VXLAN 的 BUM 流量處理（下一章會用到） • 儲存陣列的複寫

2. 多播位址與 MAC 對應

範圍用途
224.0.0.0/24Link-local，路由器不轉發。如 224.0.0.5（OSPF）、224.0.0.18（VRRP）
232.0.0.0/8SSM（Source-Specific Multicast）專用
239.0.0.0/8私有多播，等同單播的 10.0.0.0/8。企業內部自用一律選這段
必考：多播 IP 對應到 MAC 會「重疊」
多播 MAC 的前 25 bit 固定是 01:00:5E:0，只有後 23 bit 來自 IP。
但多播 IP 的主機部分有 28 bit——等於有 5 bit 被丟掉，32 個不同的多播 IP 會對應到同一個 MAC。

例：239.1.1.1 和 239.129.1.1 對應到同一個多播 MAC。
後果：交換器層級會把兩群流量都送給訂閱任一方的主機，造成非預期的流量。規劃多播位址時要避開這種重疊。

3. IGMP 與 MLD：主機怎麼說「我要訂閱」

IGMPMLD
用於IPv4IPv6
底層獨立的 IP 協定（編號 2）建構在 ICMPv6 之上
版本對應IGMPv2 ↔ MLDv1
IGMPv3 ↔ MLDv2		同左
IGMPv2主機說「我要 239.1.1.1」，不指定來源。支援 Leave 訊息，離開較快。
IGMPv3可指定來源：「我要來自 10.1.1.5 的 239.1.1.1」。這是 SSM 的必要條件。
Querier網段上負責定期詢問「還有人要聽嗎」的路由器。IP 最小的當選。
IGMP Snooping交換器偷看 IGMP 訊息，只把多播送給真正訂閱的埠，而不是整個 VLAN 氾濫。預設開啟，不要關。
陷阱：關掉 IGMP Snooping 會發生什麼
交換器會把多播當成廣播處理——氾濫到 VLAN 內每一個埠。
在資料中心，一條 1Gbps 的多播串流會瞬間打滿所有伺服器的網卡。這是很經典的「一個設定搞垮整個機櫃」案例。

4. PIM：路由器怎麼把流量送到訂閱者

IGMP 處理「主機 ↔ 最近的路由器」，PIM 處理「路由器之間」怎麼建立轉發路徑。

兩種分佈樹 ① Shared Tree（共享樹） 記法 (*, G) 所有來源的流量都先送到一個會合點 RP（Rendezvous Point） 接收者向 RP 註冊 Source ──→ RP ──→ Receiver 優點:路由器只要記 (*, G),狀態少 缺點:路徑不一定最短,RP 是瓶頸與單點 ② Source Tree / SPT（來源樹） 記法 (S, G) 接收者直接沿最短路徑找到來源 Source ──────────→ Receiver 優點:路徑最短、延遲最低 缺點:每個來源都要一組狀態,記憶體用量大 PIM Sparse Mode 的實際行為 先用 Shared Tree 建立連線 → 流量開始後,自動切換到 SPT（SPT Switchover） → 兩者的優點都拿到
PIM 模式行為適用
Dense Mode先氾濫給全部，再由不要的路由器「剪枝」已淘汰，浪費頻寬
Sparse Mode要有人明確加入才建立路徑，需要 RP企業與 DC 的標準做法
SSM接收者直接指定來源，完全不需要 RP來源固定且已知（如行情推送）
Bidir-PIM雙向共享樹，狀態最少多對多（如金融交易撮合）
必考：SSM 不需要 RP
這是常見選擇題。SSM 的接收者用 IGMPv3 直接說「我要來自某某來源的某某群組」，路由器可以直接建 (S, G) 樹，不必經過 RP。

所以 SSM 的優點：沒有 RP 這個單點故障、沒有 RP 選舉的複雜度、路徑最短、也不怕別人亂送同一個群組的流量（因為指定了來源）。
限制：接收者必須事先知道來源 IP，且主機要支援 IGMPv3。
Static RP手動指定，最簡單但沒有備援。小環境可用。
Auto-RPCisco 專有，用 224.0.1.39/40 宣告。較舊。
BSR標準做法（Bootstrap Router），可自動選舉與備援。
Anycast RP多台 RP 共用同一個 IP，用 MSDP 同步。DC 最常用，兼顧備援與負載。
# Nexus 上啟用 PIM N9K(config)# feature pim N9K(config)# ip pim rp-address 10.255.255.1 group-list 239.0.0.0/8 N9K(config)# interface ethernet 1/1 N9K(config-if)# ip pim sparse-mode # SSM（不用設 RP） N9K(config)# ip pim ssm range 232.0.0.0/8 # 驗證 N9K# show ip mroute N9K# show ip pim neighbor N9K# show ip igmp snooping
