資料中心交換與 vPC

企業網路可以忍受 STP 擋掉一半頻寬，資料中心不行。這一章講 vPC 怎麼讓兩台 Nexus 對下游偽裝成一台，以及它壞掉時會發生什麼事。

本章目錄

  1. 資料中心為什麼不能忍受 STP
  2. 先打好基礎：Port Channel
  3. vPC 的組成元件
  4. 三種故障情境（考試核心）
  5. 驗證與排錯
  6. 本章重點整理

1. 資料中心為什麼不能忍受 STP

企業辦公室的網路可以接受「一條路通、一條路備援」——反正一台電腦也用不了多少頻寬。
但資料中心是幾百台伺服器塞在同一個機櫃列，你買了兩條 40G 上行，STP 卻叫其中一條閒著。等於一半的錢丟到水裡。
傳統 STP 的浪費 Access Switch │ │ 40G│ │40G │ │ Agg-1 Agg-2 ↑ ↑ 轉發 STP 阻斷（閒置） 實際可用頻寬:40G（買了 80G） 而且切換要靠 STP 收斂,秒級 vPC 之後 Access Switch └─ Port-Channel（邏輯上一條） │ │ Nexus-1 Nexus-2 ← 對下游看起來像「一台」 實際可用頻寬:80G，兩條都在轉發 而且沒有 STP 阻斷埠
這就是 vPC（Virtual Port Channel）要解決的問題：讓兩台實體 Nexus 交換器，對下游裝置而言表現得像同一台，於是下游可以把兩條線綁成一個 Port-Channel，兩條都轉發。

2. 先打好基礎：Port Channel

vPC 是 Port Channel 的延伸，所以要先確認 Port Channel 的觀念。

協商協定標準模式說明
LACPIEEE 802.3ad
（開放標準）		active / passive建議使用。會協商，能偵測配線錯誤
PAgPCisco 專有desirable / autoNexus 不支援，只有 Catalyst 有
Static (on)不協商on兩端硬綁，設錯會產生迴圈
陷阱：Nexus 沒有 PAgP
這是 DCCOR 常考的一點。NX-OS 只支援 LACP 與 static，不支援 Cisco 自家的 PAgP。
所以 Nexus 與 Catalyst 對接時，Catalyst 那端也必須用 LACP 或 static。
# Nexus 上建立 Port Channel N9K(config)# feature lacp ← NX-OS 要先啟用 feature N9K(config)# interface ethernet 1/1-2 N9K(config-if-range)# channel-group 10 mode active N9K(config)# interface port-channel 10 N9K(config-if)# switchport mode trunk
NX-OS 的 feature 機制：和 IOS 不同，NX-OS 預設不載入大部分功能模組，要用 feature xxx 開啟。忘記開 feature 是新手最常見的「指令打不出來」原因。
常用的：feature lacp、feature vpc、feature ospf、feature interface-vlan、feature hsrp。

3. vPC 的組成元件

vPC 架構全圖 Nexus-1 ═══════════════ Nexus-2 │ ↑ ↑ │ │ └── vPC Peer-Link ────┘ │ ← 兩台之間的主幹 │ └── Peer-Keepalive ───┘ │ ← 心跳（走 mgmt0） │ │ └──────┐ ┌────────┘ │ │ vPC Member Port vPC Member Port └─── Port-Channel ───┘ │ 下游交換器/伺服器 （它以為對面只有一台） 四個必要元件 ① vPC Domain ── 兩台要設同一個 domain ID ② vPC Peer-Keepalive── 心跳,判斷對方是否還活著（不走 peer-link） ③ vPC Peer-Link ── 承載控制訊息與部分資料流量 ④ vPC Member Port ── 實際連到下游的成員埠
陷阱：Peer-Link 與 Peer-Keepalive 的差別必考
• Peer-Link：資料層。走 10G/40G 以上的實體介面，通常是 Port-Channel。承載 CFS 控制訊息、同步 MAC 表、以及孤兒埠的流量。
• Peer-Keepalive：心跳。只是輕量的 UDP 探測，必須走與 Peer-Link 不同的路徑（通常是 mgmt0 管理網路）。

為什麼要分開？因為要能區分「對方掛了」和「只是 Peer-Link 斷了」——這兩種情況的處理方式完全不同。
N9K-1(config)# feature vpc N9K-1(config)# vpc domain 10 N9K-1(config-vpc-domain)# peer-keepalive destination 10.1.1.2 source 10.1.1.1 N9K-1(config-vpc-domain)# peer-switch ← 兩台對外顯示同一個 STP 橋接 ID N9K-1(config-vpc-domain)# peer-gateway ← 允許代對方回應封包 N9K-1(config-vpc-domain)# ip arp synchronize ← 同步 ARP,加快收斂 N9K-1(config)# interface port-channel 1 N9K-1(config-if)# vpc peer-link N9K-1(config)# interface port-channel 20 N9K-1(config-if)# vpc 20 ← 成員埠,兩台要用同一個 vPC ID

4. 三種故障情境（考試核心）

情境 A：Peer-Link 斷，Keepalive 還在 → 兩台都知道對方活著,但資料主幹沒了 → Secondary 會把自己的 vPC 成員埠全部 shutdown → 避免流量分裂造成迴圈與 MAC 學習錯亂 → 所有流量集中走 Primary 情境 B：Keepalive 斷，Peer-Link 還在 → 只是心跳路徑掛了,資料還通 → 什麼都不會發生,系統只記錄警告 → 但要盡快修,因為此時失去了雙重確認 情境 C：兩個都斷（Dual-Active / Split-Brain） → 兩台都認為自己是唯一存活者 → 兩台都變成 Primary,同時轉發 → MAC 表分裂、流量迴圈 → 這是最糟的情況,設計上要盡量避免
必考：Peer-Link 斷掉時是「Secondary 關閉成員埠」
很多人會直覺以為「兩台都繼續跑」，那是錯的——那樣會造成迴圈。
vPC 的設計是犧牲 Secondary 保全一致性：Secondary 把 vPC 埠關掉，讓下游的 Port-Channel 只剩一半但仍然通，流量全走 Primary。

這也是為什麼 Peer-Link 一定要做成 Port-Channel 且跨不同板卡——單條線斷掉就觸發這個機制，代價太大。
orphan port（孤兒埠）連在 vPC 交換器上但不屬於任何 vPC 的埠。例如單接的伺服器。Peer-Link 斷掉時它的流量會受影響。
peer-gateway允許一台代替另一台回應以對方 MAC 為目的地的封包。解決某些儲存陣列不遵守標準的行為。
peer-switch兩台對外宣告同一個 STP 橋接 ID，讓下游看起來真的只有一台，加快收斂。
vPC 一致性檢查兩台的關鍵設定必須一致（MTU、VLAN、STP 模式）。Type-1 不一致會直接停用 vPC；Type-2 只警告。
陷阱：Type-1 vs Type-2 一致性
• Type-1（嚴重）：不一致會直接把 vPC 或該 VLAN 停用。例如 STP 模式、MTU、Port-Channel 模式。
• Type-2（次要）：只發出警告，vPC 繼續運作。例如某些 ACL、QoS 設定差異。

排錯指令：show vpc consistency-parameters global

5. 驗證與排錯

N9K# show vpc ← 最重要的一條,先看這個 Legend: (*) - local vPC is down, forwarding via vPC peer-link vPC domain id : 10 Peer status : peer adjacency formed ok ← 要看到 ok vPC keep-alive status : peer is alive ← 要看到 alive Configuration consistency status : success ← 要看到 success vPC role : primary N9K# show vpc peer-keepalive ← 心跳細節 N9K# show vpc consistency-parameters global ← 一致性比對 N9K# show port-channel summary ← 成員埠狀態
排錯順序（照這個查最快）
① show vpc 看三個狀態：peer adjacency、keepalive、consistency
② keepalive 不通 → 檢查 mgmt0 的 IP、VRF（keepalive 預設走 management VRF）
③ consistency failed → 跑 show vpc consistency-parameters 找出哪個參數不同
④ 成員埠 down → 確認兩台的 vPC ID 一致、下游確實設成 Port-Channel

最常見的錯：兩台的 vPC ID 設成不同數字，或下游忘了設 Port-Channel。

6. 本章重點整理

觀念要記住的
vPC 解決什麼讓 STP 不再阻斷一半的上行頻寬
Peer-Link資料層，走高速介面，做成 Port-Channel
Peer-Keepalive心跳，必須走不同路徑（通常 mgmt0）
Peer-Link 斷Secondary 關閉 vPC 成員埠
Keepalive 斷沒事，只警告
兩者都斷Split-brain，最糟情況
NX-OS 特性要 feature 開啟功能；不支援 PAgP
一致性Type-1 會停用，Type-2 只警告
✅ 一句話：vPC 讓兩台 Nexus 對下游偽裝成一台，換取雙倍頻寬與快速切換；代價是要維護 Peer-Link、Keepalive 與設定一致性這三件事。
