VXLAN BGP EVPN 深入

第 03 章講了 VXLAN 的封裝與 BUM 流量的兩種處理方式。這一章補上真正讓 VXLAN 在現代資料中心可用的那一半——EVPN 控制平面、分散式 Anycast 閘道，以及跨資料中心的擴展。

1. Flood-and-Learn 撐不住的地方

Flood-and-Learn 就像在辦公室大喊「請問王小明坐哪？」——每次找人都要吵到全部的人。
EVPN 則是先做一本通訊錄，每個人報到時就登記自己的座位，要找人直接查表。
純 VXLAN（Flood-and-Learn）的三個問題 ① 靠洪泛學 MAC 每個未知目的地都要向所有 VTEP 洪泛 規模一大,洪泛流量成為骨幹的沉重負擔 ② 需要 Multicast 或 Ingress Replication 用 Multicast → 底層網路要跑 PIM,設計與排錯都複雜 用 Ingress Replication → 每個 VTEP 各複製一份,N 個 VTEP 就 N 份 ③ 沒有控制平面 = 沒有可視性 哪個 MAC 在哪台 VTEP 後面?只能靠洪泛學到才知道 排錯時無從查起,也無法做主機移動的快速收斂 EVPN 用 BGP 當控制平面,一次解決這三件事。
對照理解：VXLAN 是資料平面（怎麼封裝、怎麼傳），EVPN 是控制平面（誰在哪裡）。
這跟傳統網路的分工一樣：乙太網路是資料平面，STP 與路由協定是控制平面。「VXLAN BGP EVPN」這個完整名稱就是把兩者都講出來。

2. EVPN 是什麼：用 BGP 送 MAC

EVPN 是 MP-BGP 的一個位址家族（address-family l2vpn evpn）。它做的事很直接：把 MAC 位址與 IP 位址當成路由來宣告。

傳統交換器學 MAC EVPN 學 MAC 伺服器送封包 伺服器一上線 ↓ ↓ 交換器從來源欄位學到 Leaf 學到 MAC ↓ ↓ 只有這台交換器知道 用 BGP 宣告給所有 Leaf ↓ ↓ 其他人要靠洪泛才知道 全網立刻都知道它在哪 結果： • 未知單播洪泛大幅減少（因為大家都已經知道 MAC 在哪） • 主機移動時收斂很快（BGP 撤銷舊的、宣告新的） • 有完整的可視性（show bgp l2vpn evpn 就看得到誰在哪）
用 BGP 的好處成熟穩定、支援 Route Reflector 減少全網狀、有豐富的政策工具（route-map、community）、可跨 AS 擴展。
Underlay 仍然需要EVPN 是 overlay 的控制平面。底層仍需 IGP（通常 OSPF 或 IS-IS）讓 VTEP 之間 IP 可達。兩層是分開的。
Spine 的角色在標準設計中 Spine 只做 Route Reflector 與 IP 轉送，不參與 VXLAN 封裝（不是 VTEP）。
最常見的觀念錯誤：以為 Spine 也是 VTEP。
在標準的 Spine-Leaf EVPN 設計中，VTEP 只存在於 Leaf。Spine 的工作是：① 底層 IP 轉送（把封裝好的 VXLAN 封包從一個 Leaf 送到另一個 Leaf）；② 當 BGP Route Reflector 反射 EVPN 路由。
Spine 完全不知道 overlay 裡有哪些 VLAN 或 VNI——這正是這個架構能擴展的原因，新增租戶只要動 Leaf。

3. 五種 Route Type（考試核心）

Type名稱帶什麼資訊解決什麼
Type 2MAC/IP AdvertisementMAC 位址、可選的 IP 位址、L2VNI、L3VNI最重要的一種。告訴大家「這個 MAC/IP 在我後面」，同時支撐 ARP 抑制
Type 3Inclusive MulticastVTEP 的 IP 與所屬 VNI建立 BUM 流量的複製清單。VTEP 一上線就宣告「我有這個 VNI」，其他人才知道要複製給誰
Type 5IP Prefix RouteIP 前綴（網段，不是單一主機）宣告整個網段，用於對外連線與跨 fabric 的路由彙總
Type 1Ethernet Auto-DiscoveryEthernet Segment 資訊多歸屬（Multi-Homing）時的快速收斂與流量分擔
Type 4Ethernet SegmentEthernet Segment 識別碼多歸屬時選出 Designated Forwarder，避免 BUM 流量重複送
✅ 考試只要記牢三個：
Type 2 = MAC/IP（誰在哪裡）→ 最常出現
Type 3 = 建立 BUM 複製清單（VTEP 報到）
Type 5 = IP 網段（對外與跨 fabric）
Type 1 與 Type 4 都跟多歸屬有關，記住這個關鍵字就能對上。
ARP 抑制（ARP Suppression）是 Type 2 帶來的重要副產品。
因為每個 Leaf 都透過 Type 2 知道了「哪個 IP 對應哪個 MAC」，當本地伺服器發 ARP 請求時，Leaf 可以直接代答，不必把 ARP 洪泛到整個 fabric。
在幾千台虛擬機的環境中，ARP 流量本身就是可觀的負擔，這個功能的效益非常明顯。

4. 分散式 Anycast 閘道

傳統集中式閘道的問題 VM-A（Leaf1 下）要跟 VM-B（Leaf2 下）跨網段通訊 Leaf1 ──▶ Spine ──▶ 核心閘道 ──▶ Spine ──▶ Leaf2 ↑ 明明兩台伺服器在隔壁機櫃 卻要繞到核心再回來（髮夾彎） 分散式 Anycast 閘道 每一台 Leaf 都是所有網段的閘道,而且用「同一個 IP、同一個 MAC」 Leaf1 （就是 VM-A 的閘道,直接路由） ──▶ Spine ──▶ Leaf2 最短路徑
同一個 IP每個 VLAN 的閘道 IP 在所有 Leaf 上都一樣。VM 不管搬到哪台 Leaf 下，閘道都在本地。
同一個 MAC全 fabric 共用一個 Anycast Gateway MAC。VM 遷移後連 ARP 快取都不用更新。
本地路由跨網段流量在入口 Leaf 就完成路由，不必繞核心。這是 VM 大量橫向流量（east-west）的關鍵優化。
✅ 這是 VXLAN EVPN 相對於傳統架構最大的實務價值。現代資料中心的流量有很高比例是伺服器之間的橫向流量（微服務互相呼叫、資料庫複寫、備份）。傳統集中式閘道會讓這些流量全部繞到核心，分散式閘道直接在機櫃層就解決。
! ── 全 fabric 共用同一個 Anycast Gateway MAC ──
N9K(config)# fabric forwarding anycast-gateway-mac 0000.2222.3333

! ── 每個 SVI 都設成 Anycast Gateway（每台 Leaf 都設一樣的）──
N9K(config)# interface vlan 10
N9K(config-if)# no shutdown
N9K(config-if)# vrf member TENANT-A
N9K(config-if)# ip address 10.1.10.1/24       ! 每台 Leaf 都是這個 IP
N9K(config-if)# fabric forwarding mode anycast-gateway
設定時最容易漏的是「每台 Leaf 都要設一樣的 IP」這件事。
傳統網路訓練出來的直覺會覺得「同一個網段兩台設備設同一個 IP 是衝突」——在 Anycast Gateway 的設計裡這是刻意的。
如果只在部分 Leaf 上設定，VM 遷移到沒設定的 Leaf 之後就會失去閘道，症狀是「同網段通、跨網段不通」而且只發生在特定機櫃。

5. L2VNI 與 L3VNI：橋接與路由

L2VNIL3VNI
對應到一個 VLAN / 廣播網域一個 VRF（租戶的路由表）
做什麼跨 fabric 的二層延伸（同網段的 VM 在不同機櫃也能通）跨 fabric 的三層路由（不同網段之間）
數量有幾個 VLAN 就有幾個一個租戶一個
對應 Route TypeType 2（MAC）、Type 3（BUM）Type 2（帶 IP）、Type 5（網段）
兩種轉送模式 Bridging（同網段） VM-A(10.1.10.5) → VM-B(10.1.10.6),都在 VLAN 10 走 L2VNI 10010,純二層轉送 Routing（跨網段） VM-A(10.1.10.5) → VM-C(10.1.20.7),VLAN 10 → VLAN 20 入口 Leaf 的 Anycast Gateway 直接路由 跨 fabric 時封裝在 L3VNI 50001（租戶的 VRF） 口訣：L2VNI 對 VLAN、L3VNI 對 VRF。
為什麼需要 L3VNI？因為多租戶環境中，不同租戶的 IP 網段可能重疊。
L3VNI 就是把「這個封包屬於哪個租戶的路由表」這個資訊帶在 VXLAN 標頭裡，讓對端 Leaf 知道要查哪一張 VRF 路由表。它是多租戶隔離的實作基礎。

6. 設定與驗證

! ═══ Leaf 上的 VXLAN EVPN 基本設定骨架 ═══

! ── 1. 開功能 ──
N9K(config)# feature ospf
N9K(config)# feature bgp
N9K(config)# feature pim
N9K(config)# feature interface-vlan
N9K(config)# feature vn-segment-vlan-based
N9K(config)# feature nv overlay
N9K(config)# nv overlay evpn

! ── 2. VLAN 對應到 L2VNI ──
N9K(config)# vlan 10
N9K(config-vlan)# vn-segment 10010

! ── 3. 租戶 VRF 與 L3VNI ──
N9K(config)# vrf context TENANT-A
N9K(config-vrf)# vni 50001
N9K(config-vrf)# rd auto
N9K(config-vrf)# address-family ipv4 unicast
N9K(config-vrf-af-ipv4)# route-target both auto evpn

! ── 4. NVE 介面（VTEP 本體）──
N9K(config)# interface nve1
N9K(config-if-nve)# source-interface loopback1     ! VTEP 的 IP
N9K(config-if-nve)# host-reachability protocol bgp  ! ← 這行就是「用 EVPN」
N9K(config-if-nve)# member vni 10010
N9K(config-if-nve-vni)# ingress-replication protocol bgp
N9K(config-if-nve)# member vni 50001 associate-vrf

! ── 5. BGP EVPN 鄰居（指向 Spine，Spine 當 RR）──
N9K(config)# router bgp 65001
N9K(config-router)# neighbor 10.0.0.1 remote-as 65001
N9K(config-router-neighbor)# update-source loopback0
N9K(config-router-neighbor)# address-family l2vpn evpn
N9K(config-router-neighbor-af)# send-community both
驗證指令看什麼
show nve peers學到哪些對端 VTEP，狀態是不是 Up
show nve vni本地有哪些 VNI、狀態、對應的 VLAN 或 VRF
show bgp l2vpn evpn summaryEVPN 鄰居關係是否建立
show bgp l2vpn evpn所有 EVPN 路由，可看到各種 Route Type
show l2route evpn mac all從 EVPN 學到的 MAC 在哪台 VTEP 後面
show ip route vrf TENANT-A租戶的路由表
排錯順序：由下而上，一層一層確認。
① Underlay 通嗎——VTEP 的 loopback 之間能不能互 ping？IGP 有沒有收斂？
② BGP EVPN 鄰居起來了嗎——show bgp l2vpn evpn summary。
③ NVE peer 有沒有學到——show nve peers。
④ VNI 狀態對嗎——show nve vni 看是不是 Up 且 VLAN 對應正確。
⑤ MAC 學到了嗎——show l2route evpn mac all。
跳過前面直接查 MAC 是浪費時間——underlay 不通的話上面全部都不會動。

7. 跨資料中心：Multi-Site

單一 fabric 做好之後，下一個問題是：兩個機房怎麼連？

做法怎麼做優缺點
直接延伸 VXLAN把兩個機房當成一個大 fabric簡單，但故障域也變成一個——一邊出問題另一邊會被拖累
VXLAN EVPN Multi-Site用 Border Gateway（BGW）當兩個 fabric 的交界，各自是獨立的故障域現行建議做法。可控制哪些 VNI 要延伸、BUM 流量在交界處被限制
只做三層互連兩邊只交換 Type 5 路由，不延伸二層最安全，但不支援跨機房的 VM 遷移（需要同網段）
Multi-Site 架構 Site-A Fabric Site-B Fabric Spine ── Leaf Leaf ── Spine │ │ BGW-A ════════ DCI（跨機房線路） ════════ BGW-B ↑ 兩個 fabric 的交界,各自是獨立的故障域 BGW 做三件事： • 重新封裝 VXLAN（Site-A 的 VNI ↔ Site-B 的 VNI） • 限制 BUM 流量跨站洪泛（可設速率限制） • 只把需要延伸的 VNI 傳過去,其餘不跨站
✅ Multi-Site 最重要的價值是「故障域隔離」。直接把兩個機房拉成一個大 fabric 看起來簡單，但一旦 Site-A 發生廣播風暴或控制平面問題，Site-B 會一起陪葬——這就失去了雙機房的意義。
BGW 讓兩邊的控制平面分開，只交換必要的資訊。考題問「跨資料中心延伸二層的建議做法」時，答案是 Multi-Site，不是直接延伸。
企業實例｜某金融機構的雙機房改造
原本用 OTV 做兩機房的二層延伸（見第 03 章），運作多年但有兩個痛點：① OTV 是 Cisco 專屬技術，設備更新受限；② 頻寬利用率不佳，且新增 VLAN 要兩邊同步改設定。
改造為 VXLAN EVPN Multi-Site：每個機房各自是獨立 fabric，用一對 BGW 互連。
設計決策：只有需要跨機房叢集的三個 VLAN 做二層延伸，其餘一律只做三層互連——刻意不把所有 VLAN 都延伸過去，因為每延伸一個就多一分廣播風暴跨站的風險。
成效：跨機房頻寬利用率提升（不再有 STP 阻斷埠），新增租戶只需在 Leaf 設定不必動兩邊，且一次 Site-A 的設定失誤造成的廣播問題沒有波及 Site-B——這正是當初改造的主要目的。

8. 本章重點整理

陷阱 1：以為 Spine 也是 VTEP
標準設計中 VTEP 只在 Leaf。Spine 只做底層 IP 轉送與 BGP Route Reflector，不知道 overlay 有哪些 VNI。
陷阱 2：搞混 VXLAN 與 EVPN 的分工
VXLAN = 資料平面（怎麼封裝）；EVPN = 控制平面（誰在哪裡）。完整名稱「VXLAN BGP EVPN」把兩者都講出來了。
陷阱 3：Route Type 記錯
Type 2 = MAC/IP（最重要）、Type 3 = BUM 複製清單、Type 5 = IP 網段。Type 1 與 4 都跟多歸屬有關。
陷阱 4：Anycast Gateway 只設在部分 Leaf
每台 Leaf 都要設同一個 IP 與同一個 MAC，這是刻意的不是衝突。漏設會造成「特定機櫃跨網段不通」。
陷阱 5：L2VNI 與 L3VNI 混淆
L2VNI 對 VLAN（廣播網域）、L3VNI 對 VRF（租戶路由表）。一個租戶一個 L3VNI。
陷阱 6：排錯直接從 overlay 開始查
要由下而上：underlay 可達 → BGP EVPN 鄰居 → NVE peer → VNI 狀態 → MAC 學習。underlay 不通時上面全部不會動。
陷阱 7：跨資料中心直接延伸 VXLAN
會讓兩個機房變成同一個故障域。建議用 Multi-Site + BGW，並且只延伸真正需要的 VNI。
✅ 一句話：VXLAN 負責把封包包起來送過去，EVPN 負責讓大家一開始就知道要送去哪；分散式 Anycast 閘道讓跨網段流量在機櫃層就完成路由，不必繞核心；跨機房用 Multi-Site 保住故障域隔離。
