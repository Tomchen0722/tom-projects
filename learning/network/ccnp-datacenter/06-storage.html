儲存網路：FC、VSAN 與 FCoE

儲存網路的哲學是「絕對不能丟包」，和乙太網的盡力而為完全不同。這一章講 FC 的定址與登入、VSAN 與 Zoning 的兩層隔離，以及 FCoE 需要的無損乙太網。

本章目錄

  1. 儲存網路的不同
  2. WWN、FCID 與登入
  3. VSAN 與 Zoning
  4. NPIV 與 NPV
  5. FCoE 統一網狀架構
  6. 本章重點整理

1. 儲存網路和一般網路差在哪

一般網路（乙太網）的設計哲學是「盡力而為」——塞車就丟封包，上層 TCP 自己重送。
儲存網路的哲學是「絕對不能丟」——因為那是硬碟的讀寫，丟一個封包可能就是資料損毀，作業系統會直接報 I/O 錯誤。
一般乙太網Fibre Channel
設計哲學Best-effort，允許丟包Lossless，零丟包
流量控制TCP 端對端重送Buffer-to-Buffer Credit（送之前先確認對方有空間）
定址MAC / IPWWN（World Wide Name）+ FCID
隔離VLANVSAN + Zoning
典型速率10/25/40/100G8/16/32/64G FC
核心觀念：B2B Credit
FC 不像乙太網「先送再說」。發送端有一個 credit 計數器，對方每接收一個訊框就回傳一個 credit，credit 用完就停止發送。

這保證了永遠不會因為對方緩衝區滿而丟包。
但也帶來一個實務問題：距離。光在光纖裡有傳播延遲，距離越遠、在途訊框越多，需要的 credit 就越多。長距離 FC 連線 credit 不足時，吞吐量會嚴重下降——這是跨機房 SAN 最常見的效能問題。

2. WWN、FCID 與登入流程

兩種名字 WWN（World Wide Name）── 64 bit,像 MAC,燒在硬體上永不改變 WWNN = 節點的名字（整台設備） WWPN = 單一埠的名字 ← Zoning 用這個 FCID ── 24 bit,像 IP,登入 fabric 時動態配發 ┌────────┬────────┬────────┐ │ Domain │ Area │ Port │ └────────┴────────┴────────┘ 交換器 群組 實際埠 主機開機後的三步登入 ① FLOGI（Fabric Login）── 向交換器報到,取得 FCID ② PLOGI（Port Login） ── 與目標儲存埠建立連線 ③ PRLI（Process Login） ── 協商 SCSI 層參數 排錯口訣:先看 FLOGI 有沒有成功 沒有 FLOGI = 實體層或 VSAN 設定有問題,後面都不用查了
MDS# show flogi database ← 誰登入了、拿到什麼 FCID MDS# show fcns database ← fabric 的名稱伺服器（誰在線上） MDS# show interface fc1/1 ← 實體埠狀態與 credit

3. VSAN 與 Zoning：兩層隔離

兩者不是二選一,是搭配使用 VSAN ── 像 VLAN,把實體 fabric 切成多個獨立的邏輯 fabric • 各自獨立的服務（名稱伺服器、Zoning 資料庫、路由） • 一個 VSAN 的故障不會影響另一個 • 用途:把正式與測試環境徹底分開 Zoning ── 在同一個 VSAN 內控制「誰能看到誰」 • 沒有 Zoning 的話,所有主機都看得到所有儲存 • 那是災難:Windows 看到別人的磁碟會想「初始化」它 結構 VSAN 10 └── Zoneset（一次只能啟用一個） ├── Zone: 主機A + 儲存埠1 └── Zone: 主機B + 儲存埠1
必考：Single Initiator Zoning
每個 Zone 只放「一個主機埠 + 一個或多個儲存埠」，絕對不要把多個主機放在同一個 Zone。

為什麼：同一個 Zone 內的成員會互相收到 fabric 的狀態變更通知（RSCN）。
如果 50 台主機在同一個 Zone，其中一台重開機會讓另外 49 台都收到通知並重新掃描——造成不必要的 I/O 中斷。

這是 SAN 設計的鐵律，考試必考。
Zoning 方式依據評價
WWPN Zoning（軟體）埠的 WWPN✅ 建議。換交換器埠不用改設定
Port Zoning（硬體）實體埠位置換線就要改，維護麻煩
Smart Zoning標記 initiator/target自動只建立必要的組合，大幅減少規則數
MDS(config)# vsan database MDS(config-vsan-db)# vsan 10 name PROD MDS(config-vsan-db)# vsan 10 interface fc1/1 # 用別名讓設定可讀 MDS(config)# device-alias database MDS(config-device-alias-db)# device-alias name ESX01-HBA1 pwwn 10:00:00:00:c9:aa:bb:01 MDS(config)# device-alias commit ← 別忘了 commit MDS(config)# zone name ESX01-to-ARRAY vsan 10 MDS(config-zone)# member device-alias ESX01-HBA1 MDS(config-zone)# member device-alias ARRAY-CTRL-A MDS(config)# zoneset name PROD-ZS vsan 10 MDS(config-zoneset)# member ESX01-to-ARRAY MDS(config)# zoneset activate name PROD-ZS vsan 10 ← 啟用才生效

4. NPIV 與 NPV

名字超像，但解決完全不同的問題
NPIV（N-Port ID Virtualization） 解決:一個實體 HBA 只能拿一個 FCID → 但一台實體主機上有 20 台虛擬機,每台都想要自己的身分 啟用 NPIV 後: 一個實體埠 → 可以註冊多個 WWPN / FCID → 每台 VM 有自己的身分 → 可以對「單一台 VM」做 Zoning 與 LUN 遮罩 NPV（N-Port Virtualization） 解決:Domain ID 數量有限（一個 fabric 最多 239 個） → 刀鋒伺服器機箱裡塞很多台交換器,很快就用完 啟用 NPV 後: 交換器不再是獨立的 fabric 成員 → 變成一個「代理」,把後面主機的登入轉送給上游交換器 → 不佔用 Domain ID,也不用管 Zoning
✅ 一句話分辨：
NPIV = 讓一個埠有多個身分（虛擬化用，在主機端／上游交換器啟用）
NPV = 讓交換器不佔 Domain ID（規模用，在邊緣交換器啟用）

兩者常一起用：刀鋒機箱的交換器跑 NPV，上游的核心交換器要開 NPIV 才能接受它轉送過來的多個登入。

5. FCoE：統一網狀架構

傳統資料中心每台伺服器要拉兩套線：乙太網（資料）+ FC（儲存）。FCoE 把 FC 訊框裝進乙太網訊框，一套線兩用。

FCoE 要成立,乙太網必須先變成「不丟包」 DCB（Data Center Bridging）的三個關鍵協定 PFC（Priority Flow Control, 802.1Qbb） → 針對特定優先權「暫停」,而不是整條線停 → 讓儲存流量不丟包,但一般流量照跑 ETS（Enhanced Transmission Selection, 802.1Qaz） → 保障頻寬分配（例:儲存 40%、資料 60%） DCBX（DCB Exchange） → 兩端自動協商上述能力,設定不一致會警告 其他要點 • FCoE 需要 MTU 2240 以上（FC 訊框 2112 + 標頭） • 伺服器端用 CNA（Converged Network Adapter）取代 NIC + HBA • FCoE 不可路由——它是二層封裝,只能在同一個二層網域
陷阱：FCoE 沒有取代 FC
FCoE 主要用在伺服器到第一台交換器這一段（存取層），減少線材與網卡數量。
再往上到儲存陣列通常還是原生 FC——因為核心 SAN 交換器與陣列大多還是 FC 介面。

而且近年 iSCSI 與 NVMe over TCP 因為只需要一般乙太網、不用 DCB，在很多場景反而更受歡迎。FCoE 的採用率不如當初預期。
協定底層特點
FC專用 FC 網路效能最穩，成本最高，要專門技能
FCoE乙太網 + DCB省線材，但要 DCB 支援
iSCSI一般 TCP/IP最便宜、可路由，中小企業首選
NVMe over FabricsFC / TCP / RoCE延遲最低，全快閃陣列的趨勢
NAS（NFS/SMB）一般網路檔案層級（前面都是區塊層級）
✅ 區塊 vs 檔案的差別（常考）：
SAN（區塊）——給伺服器一顆「裸磁碟」，作業系統自己格式化。適合資料庫、虛擬機。
NAS（檔案）——給的是「共享資料夾」，檔案系統在儲存端。適合共享文件、使用者家目錄。

6. 本章重點整理

觀念要記住的
FC 的哲學零丟包，靠 B2B Credit；長距離要注意 credit 不足
WWN vs FCIDWWN 像 MAC（固定）、FCID 像 IP（登入時配發）
登入順序FLOGI → PLOGI → PRLI；排錯先看 FLOGI
VSAN vs ZoningVSAN 切邏輯 fabric、Zoning 管誰看得到誰
Single Initiator一個 Zone 只放一個主機埠（避免 RSCN 風暴）
NPIV一個埠多個身分（虛擬化）
NPV交換器不佔 Domain ID（規模）
FCoE需要 DCB（PFC/ETS/DCBX）、MTU 2240、不可路由
