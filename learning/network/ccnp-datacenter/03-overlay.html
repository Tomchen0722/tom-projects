Overlay：VXLAN 與 OTV

VLAN 只有 4094 個、二層跨不了機房——這一章講怎麼把二層封裝進三層，讓網路格局能像活動隔板一樣重排。

本章目錄

  1. 為什麼需要 Overlay
  2. VXLAN：業界標準
  3. BUM 流量
  4. OTV：跨資料中心延伸
  5. 本章重點整理

1. 為什麼需要 Overlay

傳統網路像把房間格局砌成磚牆——要改格局就要打牆。
Overlay 像用活動隔板分隔空間——底下的地板（實體網路）不動，隔板隨時能重排。
傳統 VLAN 在資料中心的三個天花板 ① VLAN 只有 4094 個 多租戶雲端環境動輒上萬個租戶 → 12 bit 的 VLAN ID 根本不夠用 ② 二層網域無法跨機房 虛擬機要在兩個機房之間搬移,IP 不能變 → 但傳統上二層不能跨越三層邊界 ③ STP 的規模限制 大型二層網域的收斂與故障半徑都很可怕 Overlay 的解法:把二層封裝進三層 底層（Underlay）= 單純的 IP 網路,只管把封包送到對面 上層（Overlay） = 邏輯的二層網域,想怎麼切就怎麼切 兩者互相獨立——改上層不用動底層

2. VXLAN：現在的業界標準

項目內容
全名Virtual Extensible LAN
封裝方式MAC-in-UDP，外層是一般的 IP/UDP 封包
UDP 埠4789（考試會問）
識別碼VNI（VXLAN Network Identifier），24 bit → 約 1600 萬個
端點VTEP（VXLAN Tunnel Endpoint），負責封裝與解封裝
額外開銷約 50 bytes → 底層 MTU 建議設 9216（jumbo）
VXLAN 封包結構 ┌─────────────────────────────────────────┐ │ 外層 MAC │ 外層 IP │ UDP │ VXLAN │ 原始訊框 │ └─────────────────────────────────────────┘ ↑ ↑ ↑ ↑ ↑ 底層轉發 VTEP 對 4789 VNI 使用者原本的 VTEP 完整二層訊框 運作流程 伺服器 A（VLAN 10）送訊框給伺服器 B ↓ VTEP-1 收到 → 查 VNI 對應 → 加上外層 IP/UDP/VXLAN 標頭 ↓ 底層 IP 網路正常轉送（中間的設備完全不知道裡面是什麼） ↓ VTEP-2 收到 → 拆掉外層 → 還原原始訊框 → 送給伺服器 B
必考：MTU 一定要調大
VXLAN 加了約 50 bytes。如果底層 MTU 還是預設 1500，使用者送滿 1500 的封包就會超過而被丟棄或分片。
症狀很典型：ping 通、小封包正常，但傳大檔案就斷。
解法：底層所有路徑（含中間交換器）都設 MTU 9216。

3. BUM 流量：Overlay 最難的一段

BUM = Broadcast、Unknown unicast、Multicast。傳統二層靠氾濫解決，但 Overlay 底下是三層網路，沒有天然的廣播網域。

兩種處理方式 ① Multicast 模式（傳統做法） 每個 VNI 對應一個多播群組 VTEP 加入該群組 → BUM 流量用多播送出 優點:底層只複製一次,效率高 缺點:底層網路必須支援並設定好多播（第 2 章的 PIM） 很多企業的底層不想跑多播 ② Ingress Replication（頭端複製） 來源 VTEP 自己複製 N 份,分別單播給每個對端 VTEP 優點:底層只要能跑 IP 就好,不用多播 缺點:VTEP 數量多時來源端負擔重 ③ 更好的解法:根本不要氾濫 → EVPN
陷阱：VXLAN 有兩種控制平面
• Flood and Learn（傳統）：像傳統交換器一樣靠氾濫學習 MAC。設定簡單但效率差、規模受限。
• EVPN（現代標準）：用 BGP EVPN 當控制平面，VTEP 之間互相「宣告」自己後面有哪些 MAC 與 IP，不需要氾濫學習。

EVPN 的三個好處：① 抑制 ARP 氾濫（VTEP 直接代答）② 支援多租戶的三層路由 ③ 支援 Active-Active 多歸屬。
現在講 VXLAN 幾乎都預設是 VXLAN EVPN。

4. OTV：跨資料中心的二層延伸

OTV（Overlay Transport Virtualization）是 Cisco 專有技術，專門解決「兩個機房之間要延伸二層」的問題。

VXLANOTV
標準IETF 標準Cisco 專有
主要用途資料中心內部的多租戶與擴充資料中心之間（DCI）的二層延伸
控制平面EVPN 或氾濫學習IS-IS 宣告 MAC
封裝MAC-in-UDPMAC-in-IP（GRE 類）
現況主流，持續發展逐漸被 VXLAN EVPN 取代
✅ OTV 最重要的設計特點：故障隔離。
傳統把二層直接延伸到另一個機房，一邊的廣播風暴會直接燒到另一邊——兩個機房變成一個故障網域，失去了異地備援的意義。

OTV 的做法：
• 不轉發未知單播——沒學到的 MAC 就不送過去，避免氾濫跨站
• STP 不跨站——每個站點有自己獨立的 STP 網域
• ARP 快取代答——減少跨站的 ARP 流量

這就是 OTV 與「直接拉一條二層專線」的關鍵差別。
陷阱：跨機房延伸二層本身就是有爭議的設計
很多架構師的立場是「能不延伸就不要延伸」——因為它讓兩個機房耦合在一起，違反故障隔離的原則。

但實務上還是有需要的場景：虛擬機跨機房即時遷移（vMotion 要求同網段）、叢集心跳要求二層相鄰、舊系統寫死了 IP。
正確的態度是：先問「應用能不能改成三層就好」，真的不行才用 OTV 或 VXLAN EVPN 做多站延伸。
