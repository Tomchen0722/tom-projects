COMPUTER ARCHITECTURE & HARDWARE

計算機硬體結構探討中央處理器 CPU 、 記憶體階層架構與指令管線化之加速原理。

核心主題 英文術語與發音 繁體中文說明與運作機制 台酒常考題型重點
CPU 核心架構 ALU
Control Unit
Registers 		算術邏輯單元（執行計算與邏輯判斷）、控制單元（解碼指令與發出控制訊號）、暫存器組（程式計數器 PC、指令暫存器 IR、記憶體位址暫存器 MAR、資料暫存器 MDR）。 指令週期（Instruction Cycle）：擷取 Fetch ➔ 解碼 Decode ➔ 執行 Execute ➔ 寫回 Write-back。
指令管線化 Instruction Pipelining
Pipeline Hazard 		將指令執行切割為多個獨立階段（如 IF, ID, EX, MEM, WB），重疊平行執行以提升指令吞吐量（Throughput）。
三大冒險（Hazards）： 1. 結構相依（Structural Hazard）：硬體資源衝突。
2. 資料相依（Data Hazard）：後指令需使用前指令未寫回之結果（以 Forwarding 旁路轉發解決）。
3. 控制相依（Control Hazard）：分支跳躍指令造成排空（以分支預測 Branch Prediction 緩解）。 		計算題常考： 理想加速比（Speedup）接近管線階數 k；N 個指令在 k 階管線中耗時 (k + N - 1) × 時脈週期。
記憶體階層 Memory Hierarchy
Cache Memory
Locality of Reference 		依速度、成本與容量形成金字塔階層：暫存器 ➔ 快取快閃記憶體（L1, L2, L3 Cache，以 SRAM 實作）➔ 主記憶體（DRAM）➔ 次級儲存（SSD / HDD）。
局部性原理（Locality）： 1. 時間局部性（Temporal Locality）：剛存取過的資料近期很可能再次被存取。
2. 空間局部性（Spatial Locality）：存取某位址後，其鄰近位址之資料不久後很可能被存取。 		計算題： 平均記憶體存取時間（AMAT）：AMAT = Hit Time + (Miss Rate × Miss Penalty)。

⚙️ 第二單元：作業系統核心機制 (OS)

OPERATING SYSTEMS CORE PRINCIPLES
核心考點 英文術語與發音 原理機制詳解 台酒申論考點與答題關鍵
進程 vs. 執行緒 Process
Thread
Context Switch 		Process（進程/行程）： 作業系統分配資源的最小單位，擁有獨立的位址空間（Code, Data, Heap, Stack）與 PCB。
Thread（執行緒）： CPU 排程與執行的最小單位，同一個 Process 內的各 Thread 共享程式碼區、資料區與開啟檔案，但各自擁有獨立的 Stack 與 Program Counter。 		比較題： Thread 建立與 Context Switch 成本極低；但缺乏保護，一個 Thread 崩潰可能導致整程序終止；Process 具備記憶體隔離保護，安全性高但切換開銷大。
死結四大條件與防範 Deadlock
Banker's Algorithm 		死結四大必要條件（缺一不可）：
1. 互斥（Mutual Exclusion）： 資源一次僅能供一個進程使用。
2. 持有並等待（Hold and Wait）： 進程持有部分資源，並同時等待其他進程持有的資源。
3. 不可搶奪（No Preemption）： 資源只能由進程自願釋放，不可強行剝奪。
4. 循環等待（Circular Wait）： 存在一組進程鏈形成環形資源等待關係。
處理策略： 預防（破壞四條件之一）、避免（銀行家演算法確保安全狀態 Safe State）、偵測與復原。 		申論必備： 寫出銀行家演算法安全狀態判斷步驟；在台酒產銷併發庫存扣減系統中如何透過資源全局有序編號防範死結。
虛擬記憶體與分頁 Virtual Memory
Page Fault
Thrashing 		透過 MMU（記憶體管理單元）將虛擬位址對應至實體記憶體，使程式大小不受實體 RAM 限制。
分頁替換演算法： FIFO（先進先出，可能產生 Belady 異常）、LRU（最近最少使用）、LFU、Optimal 最適演算法。
Thrashing（系統抖動/顛簸）： 分配給進程的頁框數不足，導致頻繁發生 Page Fault，CPU 大部分時間均耗費在硬碟 I/O 置換，導致 CPU 利用率暴跌。 		計算與解釋： 給定頁面參考字串（Page Reference String）計算 Page Fault 次數；解決 Thrashing 需導入工作集模型（Working Set Model）。

零信任架構 Zero Trust Architecture
MFA 		核心原則：「永不信任，始終驗證」（Never Trust, Always Verify）。
三大核心構件：
1. 身分驗證（Identity）： 強制實施多因子認證（MFA）與單一登入。
2. 設備健康度（Device）： 檢測端末設備修補狀態與合規性。

PAST ESSAY QUESTIONS & BENCHMARK SOLUTIONS
📝 申論一：試述作業系統中「死結（Deadlock）」形成的四大必要條件，並說明如何利用「預防（Prevention）」與「避免（Avoidance）」策略解決死結問題。【台酒常考】 ▼

【審題重點】

本題為作業系統最經典考題。需精準寫出死結定義、四大條件之英文名稱與機制，並清楚區分「預防（靜態破壞條件）」與「避免（動態安全檢測）」之本質差異。

【參考標竿擬答】

一、死結（Deadlock）之定義：
死結係指在多工並行作業系統中，兩個或兩個以上的進程（Processes）各自持有特定系統資源，同時又在等待其他進程所持有的資源，致使所有相關進程均陷入永久停滯、無法繼續向前推進之狀態。

二、死結形成的四大必要條件（Coffman Conditions）：
死結之發生必須同時滿足下列四項條件，缺一不可：
1. 互斥條件（Mutual Exclusion ）： 資源具備不可共享性，同一時間僅能由一個進程獨立佔用。
2. 持有並等待（Hold and Wait ）： 進程已經持有至少一項資源，但又提出請求申請已被其他進程佔有之額外資源，且在等待期間不釋放手中已有之資源。
3. 不可搶奪（No Preemption ）： 資源一經配置給進程，只能由該進程在完成工作後自行主動釋放，作業系統不得強行剝奪。
4. 循環等待（Circular Wait ）： 存在一組進程集合 {P0, P1, ..., Pn}，其中 P0 等待 P1 持有之資源，P1 等待 P2 之資源，最後 Pn 等待 P0 之資源，形成閉合之環狀等待鏈。

三、「預防（Deadlock Prevention）」策略：
預防策略乃在設計系統協定時，預先破壞上述四大必要條件之一，使死結在理論上絕無發生之可能：
• 破壞「持有並等待」：要求進程必須在開始執行前一次申請所有所需資源，未湊齊前不給予任何資源；或要求進程在申請新資源前必須先釋放所有已持有資源。
• 破壞「不可搶奪」：若進程申請新資源遭拒，則系統強行剝奪其目前持有之所有資源，待未來重新排隊申請。
• 破壞「循環等待」：對全系統所有資源進行全局編號（Global Ordering），規定所有進程必須依照嚴格遞增的編號順序提出資源申請，此為實務上最可行且高效之預防方法。

四、「避免（Deadlock Avoidance）」策略：
避免策略不強加靜態限制，而是在系統執行動態過程中，每當進程提出資源申請時，由演算法即時評估若核准該請求，系統是否仍處於「安全狀態（Safe State ）」。
• 最具代表性者為戴克斯特拉（Dijkstra）提出之銀行家演算法（Banker's Algorithm ）。演算法維護 Allocation（已分配矩陣）、Max（最大需求矩陣）、Available（可用向量）與 Need = Max - Allocation（尚需矩陣），僅在確定存在一組「安全序列（Safe Sequence）」確保所有進程最終都能順利完成時，才核准當次分配；否則令進程暫時等待。

五、台酒資訊系統實務應用：
在台灣菸酒產銷物流與電商庫存交易中，跨倉儲扣帳與帳戶轉帳常發生多重資料列鎖定。實務上應採取「預防循環等待」策略，統一依資料庫主鍵（Primary Key）順序進行加鎖（如固定先鎖倉庫 A 再鎖倉庫 B），即可徹底杜絕應用層之死結產生。
