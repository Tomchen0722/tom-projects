CHFI 數位鑑識與法庭鐵證之境

真正的鑑識專家，是數位世界的神探與法醫。
從封鎖現場、RFC 3227 揮發性順序採證、保護證物鏈 (Chain of Custody)，
到深入 Windows 核心微物跡證（Prefetch, MFT, Shimcache）與記憶體逆向分析，讓真相水落石出。

第一單元 · 鑑識第一金律：RFC 3227 揮發性順序 (Order of Volatility)

🧒 高中生秒懂譬喻

搶救數位證物，就像搶救「正在融化的冰雕」！

當鑑識小組趕到犯罪現場時，電腦主機上的證據正在以驚人的速度蒸發！微秒級消逝的 CPU 暫存器就像薄薄的冰霜；記憶體 (RAM) 只要一拔電源就會在幾毫秒內徹底融化成水；而傳統硬碟上的磁區則像堅硬的巨石，關機十年資料依然存在。
因此，鑑識人員採集證據時，必須由「最容易蒸發」的先採！

1

第 1 優先級：暫存器與處理器快取 (Registers and Cache)

消逝速度以奈秒 (ns) / 微秒計。CPU 當前運算的變數與金鑰，重新開機或上下文切換瞬間蕩然無存。

2

第 2 優先級：實體記憶體與網路動態 (Routing Table, ARP Cache, RAM)

實體記憶體 (RAM)、路由表、ARP 快取、核心連線狀態與運行中的進程清單。
⚠️ 拔電源大忌：現代無檔案勒索軟體 (Fileless Malware) 完全不落硬碟，只藏在記憶體中！如果直接拔電源，關鍵證據將永久消失！

3

第 3 優先級：暫存檔案系統 (Temporary File Systems / Swap / Pagefile)

分頁檔 pagefile.sys、休眠檔 hiberfil.sys 與系統暫存磁區，裡面常殘留剛被記憶體交換出來的明文密碼與通訊記錄。

4

第 4 優先級：非揮發性磁碟 (Hard Disk Drives / SSD)

磁區、分割區、未配置空間 (Unallocated Space) 與檔案鬆弛空間 (Slack Space)。關機後仍可持久保留數月或數年。

5

第 5 優先級：遠端日誌與監控紀錄 (Remote Logs / SIEM)

遠端 Syslog、SIEM 集中伺服器、防火牆日誌。受中央控管，不易被單一遭駭端點竄改。

6

第 6 優先級：備份磁帶與封存媒體 (Archival Media / Backup Tapes)

離線存放的磁帶、冷儲存光碟，生命週期長達數十年，揮發性最低。

第二單元 · 證物保管鏈 (Chain of Custody) 與法庭鐵證標準

⚖️ 法庭採信最高準則

鑑識調查第一鐵律：絕不能在原始證物上進行任何操作！

在法庭上，被告律師一定會問：「調查官，你剛才插上隨身碟時，有沒有可能改變了硬碟最後修改時間？」
只要你動手直接在原始硬碟開機，整份證物將在法庭上被法官視為遭污染 (Tainted Evidence)，全案撤銷起訴！

🔌 硬體防寫保護裝置 (Write-Blocker)

將嫌疑人硬碟接到鑑識工作站時，中間必須串接硬體 Write-Blocker！該裝置從實體電路阻斷任何「寫入 (Write)」訊號，只允許傳輸「讀取 (Read)」指令，確保原始磁區一個位元都不被改變。

🧮 雜湊值校驗 (Hash Verification)

• 製作映像前：計算原始磁碟的 MD5 與 SHA-256 雜湊。
• 製作映像後：計算產出的映像檔 (E01 / Raw DD) 雜湊。
二者雜湊字串必須 100% 完全相同，此為法庭證明「映像與原始證物一模一樣」的數學鐵證。

💾 【硬體鑑識數學】RAID 5 奇偶校驗 (Parity) XOR 位元層級還原推導

在涉案伺服器查扣時，若其中一顆硬碟損壞，鑑識調查官如何利用布林代數中的 XOR (互斥或 ⊕) 運算，無損 100% 還原遺失磁碟的原始數位證據？

1
步驟 1：XOR 數學代數性質與校驗碼產生原理

XOR 滿足結合律、交換律，且任何數與自身 XOR 為 0 (A ⊕ A = 0)，任何數與 0 XOR 為自身 (A ⊕ 0 = A)。
三顆資料硬碟 D1, D2, D3 的奇偶校驗磁區 P 計算公式為：

P = D1 ⊕ D2 ⊕ D3
2
步驟 2：硬碟 D2 損毀時的數學反演推導

等式兩邊同時 ⊕ (D1 ⊕ D3)：

P ⊕ D1 ⊕ D3 = (D1 ⊕ D2 ⊕ D3) ⊕ D1 ⊕ D3 = D2 ⊕ (D1 ⊕ D1) ⊕ (D3 ⊕ D3) = D2 ⊕ 0 ⊕ 0 = D2
還原公式：D2 = D1 ⊕ D3 ⊕ P
3
步驟 3：真實位元組數值驗算示範

假設某區塊中三個磁碟的位元組資料如下：
• D1 = 1011 0011
• D2 = 1100 1101
• D3 = 0110 1010
計算得校驗區塊 P = D1 ⊕ D2 ⊕ D3 = 10110011 ⊕ 11001101 ⊕ 01101010 = 0001 0100
災難發生：D2 硬碟故障，調查官執行還原計算：
D1 ⊕ D3 ⊕ P = 10110011 ⊕ 01101010 ⊕ 00010100 = 1100 1101 (與 D2 完全一致，資料 100% 復活！)

📋 證物保管鏈表單 (Chain of Custody Form) 必備欄位
  • 證物唯一編號 (Case & Item ID)：精確對應嫌疑人主機序號與硬碟型號。
  • 採集時間與地理地點：由誰、在幾年幾月幾日幾分幾秒、在哪個辦公室查扣。
  • 移交與簽署人紀錄：每一次移交（如警方移交給鑑識實驗室、實驗室移交給法庭），雙方必須親自簽名並記錄原因。
  • 封存封條狀況：防篡改封條 (Tamper-evident Tape) 是否完好無損。

第三單元 · Windows 鑑識神器：隱藏在系統中的微物跡證

嫌疑犯在事後刪除了惡意木馬 payload.exe，並清空了資源回收筒。調查官如何向法官證明「這個程式確實曾在此電腦被執行過」？

微物跡證名稱 存放路徑與格式 鑑識調查可取得之關鍵情資 反鑑識對抗與破解手法
預先讀取檔 (Prefetch) C:\Windows\Prefetch\*.pf • 程式名稱與執行路徑
• 最近 8 次執行的精確時間戳記
• 程式執行總次數 (Run Count)
• 啟動時加載的所有 DLL 模組清單 		即使原 .exe 檔案被粉碎刪除，Prefetch 依然保留該檔案曾被執行的鐵證！
Shimcache (AppCompatCache) 登錄檔 SYSTEM 儲存單元中 Windows 為了相容性記錄的執行檔案清單，包含檔案完整路徑、大小與上次修改時間。 重開機時才會寫入磁碟登錄檔，記憶體鑑識時可直接從 RAM 抽取最新動態。
Amcache C:\Windows\appcompat\Programs\Amcache.hve 記錄程式安裝與執行歷史，最神之處在於記錄了程式的 SHA-1 雜湊值！ 即便駭客把木馬改名成 notepad.exe，透過 Amcache 的 SHA-1 查 VirusTotal 立即原形畢露！
Shellbags NTUSER.DAT 與 UsrClass.dat 使用者曾開啟、瀏覽過哪些資料夾，即便該資料夾存在於已拔除的外接隨身碟中！ 能證明嫌疑犯曾手動點擊瀏覽特定敏感機密目錄。
NTFS $MFT 磁區開頭 \$MFT 檔案主控表，內含 $STANDARD_INFORMATION 與 $FILE_NAME 兩套時間戳記。 偵破 Timestomping：駭客改得動 $SI，但 Windows 核心只允許修改 $FN 的受限操作。兩者時間矛盾即證明被竄改！
🔬 【鑑識底層數學】NTFS 叢集鬆弛空間 (Slack Space) 精確位元組分配推導

嫌疑犯將敏感檔案「粉碎刪除」後，再存入一個新檔案覆蓋。鑑識軟體（EnCase / Autopsy）為什麼依然能從磁碟深處抽出關鍵證據？核心在於叢集分配最小單位所產生的鬆弛空間 (Slack Space)：

1
步驟 1：檔案系統儲存幾何架構定義
實體磁區 (Sector) = 512 位元組 (Bytes)
NTFS 標準配置單位叢集 (Cluster) = 8 個磁區 = 8 × 512 = 4,096 位元組 (4KB)
作業系統鐵律：作業系統分配硬碟空間以「整顆叢集」為最小單位，哪怕檔案只有 1 個字元，也必須佔據整整 4,096 位元組！
2
步驟 2：案例計算 —— 儲存 5,000 位元組機密檔案

嫌疑犯寫入一個大小剛好為 5,000 位元組 的受賄名單，計算其磁碟分配：

所需叢集數 = ceil(5,000 / 4,096) = 2 個叢集 (總共分配 8,192 位元組)
• 第 1 叢集 (Offset 0 ~ 4,095)：完全寫滿 (4,096 位元組)
• 第 2 叢集 (Offset 4,096 ~ 8,191)：僅使用了 5,000 - 4,096 = 904 位元組
3
步驟 3：RAM Slack 與 Drive/File Slack 精確位元組推導

在第 2 個叢集中，剩餘未使用的空間被精細劃分為兩部分：

1. RAM Slack：從資料結尾 (904B) 到該實體磁區末端 (512 × 2 = 1,024B)：
RAM Slack = 1,024 - 904 = 120 位元組
(歷史作業系統在此處常以記憶體緩衝區直接填補，導致此 120 位元組殘留 RAM 中剛被複製的明文密碼！)

2. Drive / File Slack：從該磁區結尾 (1,024B) 到整顆叢集結尾 (4,096B)：
Drive Slack = 4,096 - 1,024 = 3,072 位元組
(完全不被寫入覆蓋！裡面完整保存了『上一個被刪除檔案』的原始磁區歷史資料！)

總未分配鬆弛空間 (Total Slack Space) = 120 + 3,072 = 3,192 位元組

🕵️ CHFI 法庭致勝關鍵：嫌疑犯以為把前一個機密檔案刪除並存入新檔案就能死無對證，但鑑識專家利用 Hex Editor 深入這 3,192 位元組的 Slack Space，成功抽取前一份犯罪檔案的關鍵殘留碎片！

⏱️ Windows 64-bit FILETIME 時間戳記與 Timestomping 偽造破案數學

Windows NTFS 使用 64 位元整數記錄時間戳記，以 自 1601 年 1 月 1 日 00:00:00 UTC 起算的 100 奈秒 (10^-7 秒) 間隔數 儲存。

Unix 時間戳記 (Epoch Time - 1970年起算秒數) 換算公式：
Unix Timestamp = (FILETIME - 116,444,736,000,000,000) / 10,000,000

⚖️ 破案玄機：黑客常用 timestomp.exe 竄改 $STANDARD_INFORMATION ($SI) 的時間以掩蓋行蹤，但該工具往往只能修改到「秒級（毫秒部分全歸零 .0000000）」，而且無法竄改 Windows 核心鎖定的 $FILE_NAME ($FN) 屬性！鑑識人員比對 $SI 與 $FN 的毫秒精度與時間矛盾，即成為法庭上判定「蓄意偽造跡證」的鐵證！

bash - Volatility 3 Memory Forensic Suite

investigator@box:~$ python3 vol.py -f memdump.raw windows.pslist

⚖️ CHFI 考證陷阱警示

五大高頻情境考點避坑指南

  1. 拔電源 vs 正常關機：若考題出現「嫌疑犯正在使用軟體抹除整個硬碟（全螢幕進度條狂跑覆蓋 00）」，此時是唯一的緊急例外——立刻拔除電源線！除此之外的任何情境，一律先採集 RAM 記憶體。
  2. Daubert Standard 法庭標準：專家證人的證詞是否具備科學公信力，依據 4 點：可驗證性 (Tested)、同儕審查 (Peer Reviewed)、已知錯誤率 (Error Rate)、該領域普遍接受 (General Acceptance)。
  3. Event ID 4624 登入類型： • Type 2：互動式本機鍵盤登入 (Interactive)。
    • Type 3：網路共享存取 (Network Share / SMB)。
    • Type 10：遠端桌面連線登入 (RemoteInteractive / RDP) ★ 高頻考點！
