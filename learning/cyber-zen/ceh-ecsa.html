CEH & ECSA 道德駭客與紅隊作戰藍圖

知己知彼，百戰不殆。若想抵禦頂級駭客，必須先行學會像駭客般思考。
本講義從 TCP 三向交握旗標與記憶體暫存器 EIP 切入，
深入解析 Nmap 掃描原理、Active Directory 企業網域提權、Kerberoasting 攻擊與滲透報告標準。

第一單元 · 駭客攻擊五大經典階段 (The 5 Phases of Hacking)

🧒 高中生秒懂譬喻

駭客就像「高明的小偷集團」，步步為營

  • 1. 偵察踩點 (Reconnaissance)：戴鴨舌帽在豪宅外散步，看哪天有送牛奶的、哪裡有監視器盲點（OSINT 公開情報蒐集、Google Hacking）。
  • 2. 探測掃描 (Scanning)：深夜拿鐵絲輕輕敲每扇窗戶、轉動後門把手，看哪扇窗沒上鎖（Nmap 端口掃描、漏洞掃描）。
  • 3. 破窗奪權 (Gaining Access)：從小氣窗鑽進去，成功進入客廳（利用漏洞 Exploit、SQL 注入、密碼暴力破解）。
  • 4. 留設後門 (Maintaining Access)：在地下室藏一把備用鑰匙，並挖一條暗道，即使屋主換了前門大鎖也能隨時溜進來（Rootkit、維持權限、橫向移動）。
  • 5. 抹除痕跡 (Clearing Tracks)：離開前拿吸塵器吸掉腳印、擦掉指紋、關掉監視錄影紀錄（清除 Windows 事件日誌、日誌偽造）。
1

階段一：偵察與足跡收集 (Reconnaissance & Footprinting)

分為被動偵察 (Passive)（不接觸目標系統，如 Whois、Shodan、LinkedIn、DNS 紀錄）與主動偵察 (Active)（直接發送封包探測，如 ping sweep）。
CEH 考點：被動偵察永遠是黑客的第一步，因為不會在目標的 IDS/IPS 留下任何警報！

2

階段二：掃描與枚舉 (Scanning & Enumeration)

使用 Nmap、Masscan 探測存活主機 (Host Discovery)、開放端口 (Port Scanning) 與服務版本 (Banner Grabbing)。進一步進行 SMB、SNMP、LDAP 枚舉，抓出有效使用者帳號與群組資訊。

3

階段三：獲取存取權限 (Gaining Access)

攻擊的核心分水嶺！利用目標系統的已知弱點（CVE）發送 Exploit 酬載，包含作業系統漏洞（如 MS17-010 EternalBlue）、Web 漏洞（SQLi, RCE）或社交工程（釣魚郵件 Payload）。

4

階段四：維持權限與橫向移動 (Maintaining Access & Pivoting)

植入木馬後門 (Trojan / C2 Agent)、建立持續性任務 (Scheduled Tasks / Registry Run Keys)。以此突破點為跳板 (Pivot)，向企業內部網路的 Active Directory 網域控制站發動橫向滲透。

5

階段五：清除痕跡 (Clearing Tracks)

修改檔案存取時間戳記 (Timestomping)、停用系統稽核日誌、覆蓋 Windows Security.evtx 與 Linux /var/log/auth.log，避免遭藍隊鑑識人員追查。

第二單元 · Nmap 掃描底層封包旗標與 RFC 793 陷阱

CEH 考試中最經典、失分率最高的題目，就是考察 Nmap 的掃描旗標 (Flags) 與目標伺服器的 TCP 反應機制：

bash - Kali Linux Nmap Suite 
# 1. TCP 半開隱匿掃描 (SYN Stealth Scan - 最常用、速度快、需要 root 權限)
attacker@kali:~$ nmap -sS -p 80,443,445 192.168.1.100

# 2. TCP 全連接掃描 (TCP Connect Scan - 建立完整三次交握，非 root 預設)
attacker@kali:~$ nmap -sT -p 80,443 192.168.1.100

# 3. 聖誕樹掃描 (Xmas Scan - 同時點亮 FIN, PSH, URG 三個旗標)
attacker@kali:~$ nmap -sX -p 22,80 192.168.1.100

# 4. 空標掃描 (Null Scan - 不開啟任何旗標)
attacker@kali:~$ nmap -sN -p 22,80 192.168.1.100
掃描技術 參數 發送的 TCP 旗標 目標端口「開啟」之回應 目標端口「關閉」之回應 RFC 793 規範與作業系統特性
TCP SYN 掃描 -sS SYN 回覆 SYN-ACK
(攻擊者隨即發送 RST 拆線)		 回覆 RST-ACK 適用所有作業系統，隱匿度高，因為尚未建立完整連線應用層不會寫入連線日誌。
TCP Connect 掃描 -sT SYN 回覆 SYN-ACK
(攻擊者回覆 ACK 完成交握)		 回覆 RST-ACK 使用系統 connect() API，普通權限可用，但容易被伺服器應用日誌記錄。
Xmas 聖誕樹掃描 -sX FIN + PSH + URG 完全靜默無回應 (No Response) 回覆 RST ⚠️ 致命考點：Windows 系統不遵守 RFC 793！對任何關閉或開啟的端口皆回覆 RST，因此 Xmas 無法掃描 Windows！
Null 掃描 -sN 無 (全部清零) 完全靜默無回應 (No Response) 回覆 RST 同上，僅對符合 RFC 793 的 Unix/Linux 系統有效，遇 Windows 均回覆 RST。
FIN 掃描 -sF FIN 完全靜默無回應 (No Response) 回覆 RST 能穿透某些僅阻擋 SYN 封包的無狀態防火牆 (Stateless Firewall)。

第三單元 · 記憶體深淵：緩衝區溢位 (Buffer Overflow) 底層剖析

🧒 高中生秒懂譬喻

倒水進玻璃杯，水淹過隔壁的控制開關

想像程式在記憶體劃出一個容積只有 100ml 的杯子（Buffer 緩衝區）。程式設計師沒有檢查使用者的輸入長度，壞蛋一口氣灌了 150ml 的毒水！多出來的 50ml 漫出杯緣，正好淹過隔壁負責控制大門去向的「返回地址指針 (EIP)」！於是壞蛋把 EIP 改成指向自己帶來的惡意程式碼（Shellcode），電腦就完全聽命於駭客了。

1

記憶體堆疊 (Stack) 的佈局

[ 低記憶體位址 ]
├── 區域變數 (Local Variables / Buffer)
├── 框架指針 (Saved Frame Pointer - EBP)
├── 返回位址 (Saved Return Address - EIP) ★ 關鍵攻擊目標
└── 函數參數 (Function Arguments)
[ 高記憶體位址 ]

2

NOP Sled (空指令滑梯) 的妙用

在 Shellcode 前面鋪上一長串 \x90 (x86 的 NOP 指令，代表「什麼都不做直接執行下一行」)。攻擊者即便無法精準命中 Shellcode 的第一行，只要 EIP 指針落在這塊 NOP 滑梯的任何位置，CPU 就會像溜滑梯一樣一路順滑滑到 Shellcode 觸發漏洞！

3

現代作業系統三大防禦鐵壁

  • DEP / NX (資料執行防止)：把堆疊 (Stack) 標記為不可執行。即便注入 Shellcode，CPU 也拒絕在此記憶體分頁執行指令。
  • ASLR (位址空間配置隨機化)：每次開機與程式載入時，將堆疊、堆積 (Heap) 與函式庫的基底位址隨機打亂，讓攻擊者猜不到位址。
  • Stack Canaries (金絲雀保護碼)：在 Buffer 與 EIP 之間塞入一個隨機秘密數字，函數結束前檢查該數字是否被改動，若被改動立刻終止程式。

第四單元 · 企業內網終局之戰：Active Directory 網域滲透與 Kerberoasting

🏢 企業實戰場景

為什麼全球 90% 的企業滲透，都在攻打 Active Directory (AD)？

在跨國企業內部，只要拿下網域控制站 (Domain Controller)，就等於掌握全公司的電子郵件、ERP 帳號、薪資檔案與伺服器特權。以下是現代紅隊與 ECSA 認證必考的標準提權攻擊鏈：

1

步驟 1：內網廣播欺騙 (LLMNR / NBT-NS Poisoning)

當內網員工打錯共享資料夾路徑時，Windows 會向區網廣播尋找主機。攻擊者啟動 Responder 工具搶先偽裝成該伺服器，誘騙員工電腦傳送 NetNTLMv2 Hash，隨後以 Hashcat 進行離線字典破解。

2

步驟 2：Kerberoasting 服務票據提取

任何合法的網域帳號（即便只是約聘實習生），都可以向網域 KDC 申請具有 SPN (Service Principal Name) 的服務票據 (TGS)。
攻擊原理：該票據是用「執行該服務的服務帳號密碼 NTLM Hash」加密的！攻擊者把票據匯出到自己本機，在沒有連線監控的情況下用 GPU 離線爆破服務帳號密碼！

3

步驟 3：Golden Ticket (黃金票據) 終極後門

一旦攻擊者獲取網域核心帳號 krbtgt 的 NTLM Hash，就能在不經過網域控制站的情況下，自行偽造出任意權限、有效期限長達 10 年的偽造 TGT (Golden Ticket)，成為企業網域的影子神祇！
企業唯一防禦法：定期連續重設兩次 krbtgt 密碼！

📑 ECSA 專業報告標準

滲透測試報告的靈魂：寫給 CEO 看的 Executive Summary

ECSA / CPENT 認證與 CEH 最大的不同在於：能否提出具備商業價值的專業滲透報告。

  • 高階主管摘要 (Executive Summary)：不寫技術指令！用餅圖與柱狀圖呈現高危、中危漏洞數量，並以業務損益（財務風險、合規罰款）說明修復優先級。
  • 技術發現 (Technical Findings)：附上 CVSS v3.1 評分向量（如 CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H - 9.8 嚴重）、重現步驟 (PoC) 與精確的廠商修補建議。
