🔀 平行運算
同時做一萬件事

GPU 最核心的超能力。理解平行運算，你就懂為什麼 GPU 跑 AI 比 CPU 快 100 倍。

🍜 從洗碗說起

💡 核心比喻

序列（CPU 方式）：一個人洗 100 個碗，一個接一個，共花 100 分鐘。

平行（GPU 方式）：100 個人同時洗，每人洗 1 個碗，共花 1 分鐘。

GPU 就是這 100 個人——但實際上它有 16,000 個人同時工作。

當然，現實更複雜：平行運算有它的條件和限制。但這個比喻抓住了核心概念。

🏗️ GPU 的三層執行架構

GPU 把工作組織成三層：Grid → Block → Thread。

🌐

Grid（網格）

一個完整的 GPU 任務叫一個 Grid。例如「把一張圖的每個像素都變亮」就是一個 Grid。

📦

Block（區塊）

Grid 被分成很多 Block。Block 是一組 Thread 的集合，同一個 Block 內的 Thread 可以共享快速記憶體（Shared Memory）並互相溝通。

🧵

Thread（執行緒）

最小單位。每個 Thread 執行同一段程式碼，但處理不同的資料。例如「把像素 (x,y) 的亮度 +10」——每個 Thread 負責不同的 (x,y)。

💡 比喻

Grid = 整個工廠的生產任務
Block = 一條生產線（線上工人可以互相傳料）
Thread = 每個工人（各自負責一個零件）

📌 什麼任務適合平行？什麼不適合？

✅ 適合平行的任務

  • 圖像的每個像素獨立處理
  • 矩陣的每個元素獨立計算
  • AI 模型的每一層前向傳播
  • 密碼學的大量雜湊計算
  • 大規模資料的統計分析

❌ 不適合平行的任務

  • 步驟 2 必須等步驟 1 的結果
  • 複雜的條件分支（if-else 多）
  • 遞迴演算法（每次呼叫自己）
  • 資料庫事務（需要鎖定）
  • 自然語言的逐字生成
💡 注意：LLM 生成文字其實不完全是平行的

ChatGPT 每次生成一個 token，下一個 token 依賴上一個——這部分是序列的。但每個 token 生成時，模型內部的矩陣計算是平行的。所以 GPU 加速的是「每一步」的計算，而不是「多少步」。

⚡ Amdahl's Law：平行加速有上限

平行不是萬能的。如果一個程式有 90% 可以平行、10% 只能序列，那無論用多少 GPU，最多只能快 10 倍（因為那 10% 序列的部分成了瓶頸）。

Amdahl 定律的直覺
  • 10% 序列 → 最多快 10 倍（不管有多少核心）
  • 1% 序列 → 最多快 100 倍
  • 0.1% 序列 → 最多快 1,000 倍

這就是為什麼 GPU 程式設計師要努力把序列部分壓到最小——哪怕一點點序列瓶頸，都會大幅限制加速效果。

✅ 本章重點整理

  • 平行運算 = 把一個大任務拆成很多份，同時執行
  • GPU 有數萬個核心，天生適合平行
  • GPU 用 Thread → Block → Grid 三層架構組織工作
  • 適合平行：各資料獨立計算（矩陣、圖像）
  • 不適合平行：步驟有前後依賴的任務
  • 平行加速有上限，序列部分是瓶頸（Amdahl 定律）
