⚙️ CUDA 與驅動程式
為什麼 AI 圈都用 NVIDIA

不是因為 NVIDIA 的 GPU 最強，而是因為 CUDA 的生態系統最完整。這篇解釋那個護城河。

🧱 軟體堆疊：你的程式到 GPU 的距離

model.generate(...)  |  你寫的 code

PyTorch  |  TensorFlow  |  JAX

↓

💡 比喻

你（應用程式）說繁體中文，GPU（硬體）只懂機器碼。CUDA 是中間的翻譯員兼效率顧問，幫你把每句話翻譯成 GPU 最能理解的形式，同時幫你優化表達方式。

🟢 CUDA 是什麼

CUDA（Compute Unified Device Architecture）是 NVIDIA 在 2006 年推出的 GPU 程式設計平台。它包含：

CUDA 生態系統的組成
  • CUDA 語言擴展：讓你用 C/C++ 寫 GPU 程式（.cu 檔）
  • cuBLAS：矩陣運算庫，AI 最常用的乘法加速
  • cuDNN：深度神經網路運算庫（卷積、BatchNorm 等）
  • cuSPARSE：稀疏矩陣運算（Transformer 的 Attention）
  • NCCL：多 GPU 通訊庫（多卡訓練必備）
  • Nsight：GPU 效能分析工具

PyTorch、TensorFlow 等框架的底層都直接呼叫 CUDA。換句話說，你不需要自己寫 CUDA，但 GPU 能不能跑你的程式，取決於 CUDA 支不支援。

🔴 AMD ROCm 為什麼沒追上？

🟢 NVIDIA CUDA（2006–）

  • 20 年的生態系統積累
  • 幾乎所有 AI 框架原生支援
  • cuDNN 優化極深
  • 大量開源模型預設 CUDA
  • Hugging Face 模型預設 CUDA
  • 遇到問題 Stack Overflow 都有答

🔴 AMD ROCm（2016–）

  • 生態系統較年輕
  • 部分框架支援有 bug
  • 優化深度不如 CUDA
  • 企業部署支援有限
  • 需要額外設定才能跑
  • 遇到問題較難找解答

💡 結論：AMD GPU 硬體性價比有時更好，但 AI 開發首選 NVIDIA，原因是 CUDA 生態、文件、支援遠遠領先。AMD 正在追趕（MI300X 很強），但 2025 年現在還是選 NVIDIA 比較省事。

🔢 CUDA 版本怎麼看

你會常常看到 CUDA 版本號，搞懂它能解決大量環境問題：

概念說明怎麼查
驅動版本NVIDIA 驅動程式版本（如 537.13）nvidia-smi 第一行
CUDA 版本驅動支援的最高 CUDA 版本nvidia-smi 右上角
PyTorch CUDAPyTorch 安裝時用的 CUDA 版本torch.version.cuda
# 查看 GPU 狀態和 CUDA 版本 nvidia-smi # 查看 PyTorch 的 CUDA 版本 python -c "import torch; print(torch.version.cuda)" # 確認 GPU 可用 python -c "import torch; print(torch.cuda.is_available())"

⚠️ 版本相容性陷阱：PyTorch 安裝的 CUDA 版本 ≤ 驅動支援的 CUDA 版本才能用。如果你裝了 CUDA 12.1 的 PyTorch，但驅動只支援 CUDA 11.8，就會出錯。先查驅動版本，再選 PyTorch 版本。

💡 你需要記住什麼

你不需要自己安裝這些（PyTorch 裝好了會自動帶）。但當遇到 「找不到 CUDA」或「版本不符」的錯誤，你要知道：問題不在你的程式碼，而在這個軟體堆疊的某一層版本對不上。

✅ 本章重點整理

  • CUDA = NVIDIA 的 GPU 程式設計平台，2006 年推出
  • 你的 Python → PyTorch → CUDA → 驅動 → GPU 硬體
  • CUDA 生態 20 年積累，AMD ROCm 追趕中但差距大
  • AI 選 NVIDIA 主要原因是 CUDA 生態，不只是硬體
  • 常見錯誤：PyTorch CUDA 版本 > 驅動支援版本
  • nvidia-smi 是診斷 GPU 環境的第一個指令
