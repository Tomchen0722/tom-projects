🗺️ 推論部署的全貌

訓練好一個模型只是開始。「推論部署」是讓它在生產環境服務真實使用者的整個過程。這比訓練難的原因是：你要同時兼顧速度、成本和品質。

📊 推論的三個核心指標
  • TTFT（Time to First Token）：使用者送出請求到收到第一個 token 的時間，影響「感覺快不快」
  • TPS（Tokens per Second）：每秒生成的 token 數量，影響「讀完的速度」
  • 吞吐量（Throughput）：每秒能同時服務多少個請求，決定成本

🧠 PagedAttention：vLLM 快在哪

傳統推論框架的問題：為每個請求預先保留最大長度的 KV Cache 記憶體，90% 的空間被浪費。

📖 比喻：書架管理

傳統方式：每個人來借書就保留整排書架給他（即使他只用了幾格）。PagedAttention：只在需要的時候分配一格格的「頁面」，不用的立刻歸還。結果：同樣的書架可以同時服務 5-10 倍的人。

# vLLM 快速啟動（安裝後一行啟動服務）
# pip install vllm

from vllm import LLM, SamplingParams

# 載入模型（自動用 PagedAttention）
llm = LLM(
    model="meta-llama/Llama-3.2-8B-Instruct",
    tensor_parallel_size=2,   # 跨 2 張 GPU 張量並行
    max_model_len=4096,
    gpu_memory_utilization=0.95,  # 使用 95% VRAM
)

params = SamplingParams(temperature=0.7, max_tokens=512)
outputs = llm.generate(["解釋 GPU 的 CUDA 架構"], params)
print(outputs[0].outputs[0].text)

# 或啟動 OpenAI 相容的 HTTP API

🗜️ 量化：讓模型塞進更小的 GPU

70B 模型用 FP16 需要 140 GB VRAM（約 2 台 H100）。量化後可以塞進一張 GPU。

量化格式精度70B 模型需要 VRAM品質損失用途
FP16（基準）16 bit~140 GB無訓練/高精度推論
INT8（GPTQ/bitsandbytes）8 bit~70 GB極小推論，精度優先
INT4（GPTQ/AWQ）4 bit~35 GB小推論，最常用
GGUF Q4_K_M（llama.cpp）~4 bit~28 GB小本地/CPU 推論
GGUF Q2_K~2 bit~18 GB明顯VRAM 極度受限

AWQ 量化（推薦）

# AWQ (Activation-aware Weight Quantization) — 比 GPTQ 更快，品質相當
# pip install autoawq

from awq import AutoAWQForCausalLM
from transformers import AutoTokenizer

model = AutoAWQForCausalLM.from_pretrained("Qwen/Qwen2-7B")
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2-7B")

quant_config = {"zero_point": True, "q_group_size": 128, "w_bit": 4}
model.quantize(tokenizer, quant_config=quant_config)
model.save_quantized("./qwen2-7b-awq")

# 之後載入量化模型（快又省 VRAM）
model = AutoAWQForCausalLM.from_quantized("./qwen2-7b-awq")

💡 選哪種量化？生產環境首選 AWQ INT4（速度/品質平衡最好）。本地開發用 Ollama 下載的 GGUF（自動選 Q4_K_M）。需要極致品質時用 FP16 或 INT8。

🖥️ 用 Ollama 本地部署（最快上手）

# 安裝 Ollama（Windows/Mac/Linux）
# 到 https://ollama.ai 下載安裝包，或
# Linux: curl -fsSL https://ollama.ai/install.sh | sh

# 拉取並執行模型
ollama pull llama3.2           # 下載 3B 模型（約 2.0 GB）
ollama pull qwen2.5:7b         # 繁中效果更好的 7B
ollama run llama3.2            # 進入對話模式

# 呼叫 REST API（OpenAI 相容格式）
curl http://localhost:11434/api/generate -d '{
  "model": "llama3.2",
  "prompt": "什麼是 GPU 的 CUDA 架構？",
  "stream": false
}'

# Python 呼叫（使用 OpenAI SDK）
# pip install openai
from openai import OpenAI
client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
response = client.chat.completions.create(
    model="llama3.2",
    messages=[{"role": "user", "content": "解釋 VRAM 和 RAM 的差異"}]
)

⚠️ Ollama 預設跑在 localhost，不對外開放。若要在 LAN 內共享，需設定 OLLAMA_HOST=0.0.0.0 環境變數，並注意防火牆與授權控制——開放後任何人都能存取，沒有認證機制。

📌 本章重點整理

  • 推論三指標：TTFT（體感速度）、TPS（生成速度）、Throughput（並發能力）
  • vLLM：生產首選，PagedAttention 讓吞吐量提升 5-10x
  • Ollama：本地開發最快，一行命令跑 LLM
  • AWQ INT4 量化：VRAM 用量減半，品質損失極小，推論速度還更快
  • Flash Attention 2 + INT4 量化 + Continuous Batching = 生產三件套
  • 70B 模型 FP16 需 140 GB，INT4 後降到 35 GB，一張 H100 搞定
