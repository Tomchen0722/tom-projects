🐍 CUDA Python 實戰

不用學 C++，用 Python 就能操控 GPU。從 PyTorch tensor 到記憶體管理，工程師必知的 GPU 程式設計基礎。

🤔 為什麼要學 CUDA Python？

很多人以為「用 GPU 跑 AI」就只是把 PyTorch 安裝好然後呼叫 .to("cuda")。這沒錯——但你不知道底層在做什麼，就不知道為何慢、怎麼快。

不懂引擎的賽車手只會油門跟煞車。懂引擎的賽車手能調教到每一圈都快半秒。GPU 程式設計就是學會調教的技術。

🏗️ CUDA 執行模型（白話版）

CUDA 程式分三個層次：Grid → Block → Thread。你可以把它想成一個大工廠：

層次CUDA 名詞比喻典型數量
最大Grid整個工廠1 個（一次任務）
中層Block一條生產線數百到數千個
最小Thread一個工人Block × 128~1024

當你呼叫 tensor.to("cuda")，PyTorch 替你管理這三層。但理解它讓你知道為什麼某些操作快、某些慢。

⚠️ 關鍵限制：同一個 Block 內的 Thread 才能共享快速的 Shared Memory（比 Global Memory 快約 100 倍）。跨 Block 的溝通只能透過慢速的 Global Memory（VRAM）。

💻 PyTorch 基本操作

搬資料到 GPU

import torch

# 確認 GPU 可用
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
print(f"使用設備: {device}")
print(f"GPU 名稱: {torch.cuda.get_device_name(0)}")

# 建立 tensor 並搬到 GPU
x = torch.randn(1000, 1000)    # 在 CPU
x_gpu = x.to(device)              # 搬到 GPU
x_gpu2 = x.cuda()                 # 等效寫法

# 也可以直接建在 GPU 上（更快，省去複製）
y = torch.randn(1000, 1000, device=device)

記憶體監控

# 查看 VRAM 使用量
print(f"已配置: {torch.cuda.memory_allocated() / 1e9:.2f} GB")
print(f"已保留: {torch.cuda.memory_reserved() / 1e9:.2f} GB")

# 清除快取（訓練中切換 batch 時用）
torch.cuda.empty_cache()

# 查看記憶體使用摘要（PyTorch 2.0+）
print(torch.cuda.memory_summary())

💡 memory_reserved vs memory_allocated：PyTorch 向 CUDA 要記憶體是一大塊一大塊要（reserved），然後再從裡面分配給 tensor（allocated）。empty_cache() 是把 reserved 但沒 allocated 的還回去，並不會讓你的模型記憶體用量下降。

🐌 最常見的效能陷阱

陷阱一：在迴圈裡把結果搬回 CPU

# ❌ 慢：每次迭代都強迫 GPU 同步
total = 0
for x in dataset:
    output = model(x.cuda())
    total += output.item()  # .item() 把 GPU tensor 搬到 CPU！

# ✅ 快：留在 GPU 上累加，最後才搬
total = torch.tensor(0.0, device="cuda")
for x in dataset:
    output = model(x.cuda())
    total += output.sum()
result = total.item()  # 只搬一次

陷阱二：CPU-GPU 資料不對齊

# ❌ 慢：DataLoader 預設用 pin_memory=False
loader = DataLoader(dataset, batch_size=32)

# ✅ 快：pin_memory 讓 CPU→GPU 傳輸更快（適合有獨立 GPU 的機器）
loader = DataLoader(
    dataset,
    batch_size=32,
    pin_memory=True,    # 使用固定記憶體，DMA 傳輸更快
    num_workers=4,      # 多執行緒預先載入資料
    prefetch_factor=2   # 每個 worker 預抓 2 個 batch
)

陷阱三：梯度累積但忘記 zero_grad

# ❌ 慢且錯：梯度一直累加
for batch in loader:
    loss = model(batch)
    loss.backward()
    optimizer.step()  # 梯度沒有歸零！

# ✅ 正確：每個 step 前清梯度
for batch in loader:
    optimizer.zero_grad(set_to_none=True)  # set_to_none 比 zero_grad() 更省記憶體
    loss = model(batch)
    loss.backward()
    optimizer.step()

⚡ Mixed Precision Training

模型預設用 FP32（32-bit 浮點數），但 Tensor Core 在 FP16（16-bit） 速度快 2-8 倍，而且 VRAM 用量只有一半。Mixed Precision 就是聰明地混用兩種精度。

精度位元數VRAM 用量速度精度
FP3232 bit基準基準最高
FP1616 bit1/22-8x可能下溢
BF1616 bit1/22-4x與 FP32 接近
INT88 bit1/44x+僅推論用

在 PyTorch 開啟 Mixed Precision

from torch.cuda.amp import autocast, GradScaler

scaler = GradScaler()  # 防止 FP16 梯度下溢

for batch in loader:
    optimizer.zero_grad(set_to_none=True)

    # autocast 自動決定哪些 op 用 FP16
    with autocast(dtype=torch.bfloat16):  # H100/A100 推薦 BF16
        output = model(batch)
        loss = criterion(output, labels)

    scaler.scale(loss).backward()   # 縮放梯度避免下溢
    scaler.step(optimizer)
    scaler.update()

🔍 效能分析：找出瓶頸在哪

方法一：torch.profiler（推薦）

from torch.profiler import profile, record_function, ProfilerActivity

with profile(
    activities=[ProfilerActivity.CPU, ProfilerActivity.CUDA],
    record_shapes=True,
    with_flops=True,
) as prof:
    with record_function("model_inference"):
        output = model(input_tensor)

# 印出前 10 最耗時的操作
print(prof.key_averages().table(
    sort_by="cuda_time_total",
    row_limit=10
))

方法二：快速計時

# GPU 操作是非同步的，不能用 time.time() 直接計時！
import time

# ❌ 錯誤：time.time() 在 GPU 還沒做完就回傳了
start = time.time()
output = model(x.cuda())
elapsed = time.time() - start  # 數字不對！

# ✅ 正確：先同步再計時
torch.cuda.synchronize()
start = time.time()
output = model(x.cuda())
torch.cuda.synchronize()  # 等 GPU 做完
elapsed = time.time() - start

⚠️ GPU 操作是非同步的：CPU 送出指令就繼續執行，不等 GPU。torch.cuda.synchronize() 才是強制等待點。這就是為什麼 profiler 幫你處理同步，你直接 time.time() 量到的數字往往接近 0。

🚀 torch.compile：一行大幅加速

PyTorch 2.0 引入的 torch.compile()，會把你的模型編譯成最佳化的核心程式碼。通常不需要改任何邏輯，只要一行。

# PyTorch 2.0+ 只需一行
model = torch.compile(model)

# 然後照常使用
output = model(x)

# 可以指定編譯模式
model = torch.compile(model, mode="reduce-overhead")  # 減少 overhead
model = torch.compile(model, mode="max-autotune")     # 最積極優化（編譯慢）

💡 torch.compile 第一次跑會花幾分鐘「暖機」（JIT 編譯），之後才快。適合要跑大量 epoch 的訓練任務；推論時若每次 input shape 不同，效果可能有限。

📌 本章重點整理

  • CUDA 執行模型：Grid → Block → Thread，同 Block 的 Thread 共享快速 Shared Memory
  • .to(device) 搬 tensor；direct on device 建立更快
  • 最常見陷阱：在迴圈裡呼叫 .item()、忘記 zero_grad、DataLoader 不開 pin_memory
  • Mixed Precision（BF16）：2x 速度、50% VRAM，只改 3 行程式碼
  • GPU 是非同步的：計時前要 synchronize()；profiler 幫你處理
  • torch.compile(model)：PyTorch 2.0 的一行加速魔法
