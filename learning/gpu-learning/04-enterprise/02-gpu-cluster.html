🏗️ GPU 叢集與
分散式訓練架構

一張 GPU 不夠怎麼辦？多張 GPU、多台機器如何協同工作，訓練出比單卡大上百倍的模型。

📈 從 1 張到 1000 張 GPU 的演進

💡 核心比喻

1 張 GPU = 一個工廠，一條生產線。
8 張 GPU（同一台機器） = 一個工廠，8 條生產線，共用同一個倉庫。
多台機器 × 多張 GPU = 多個工廠，生產線之間靠高速物流協調。

工廠之間的「物流速度」（頻寬）決定了整體效率。這就是為什麼叢集的網路硬體很重要。

🔀 三種平行訓練策略

① 資料平行（Data Parallelism）

每張 GPU 有完整的模型副本，但處理不同的訓練資料。計算完梯度後，所有 GPU 同步更新一次權重。

✅ 最常用。模型放得進單張 GPU 時的首選。PyTorch DDP。

② 模型平行（Model Parallelism）

把模型按「層」切開，每張 GPU 只跑部分的層。適合單張 GPU 放不下整個模型時。

✅ 超大模型（70B+）必用。資料像水管一樣流過不同 GPU。

③ 張量平行（Tensor Parallelism）

把單一個矩陣操作切開，分給多張 GPU 同時計算。最細粒度，通訊開銷最大。

✅ 通常搭配模型平行使用（稱為 3D Parallel），訓練 GPT-4 等超大模型。

💡 實際上怎麼用

7B–13B 模型微調：資料平行就夠（用幾張同型 GPU）。
70B 模型訓練：資料平行 + 模型平行（Megatron-LM、DeepSpeed）。
GPT-4 等超大模型：三種平行全用（業界稱 3D Parallel）。

🔌 GPU 間的連接方式

NVLink（NVIDIA 機器內）

900 GB/s

同一台機器內 GPU 之間的高速連接。H100 DGX 系統 8 張 GPU 透過 NVSwitch 全互連。

PCIe（一般機器內）

~128 GB/s

沒有 NVLink 的機器，GPU 透過 PCIe 連接。速度比 NVLink 慢 7 倍，多 GPU 效率較低。

InfiniBand（機器之間）

400 Gb/s

高端叢集用的低延遲網路。比普通網路快 10 倍，是大型訓練必備的網路硬體。

Ethernet（一般網路）

25–100 Gb/s

一般機器之間的網路。比 InfiniBand 慢且延遲高。適合推理服務，不適合大型訓練。

⚠️ 頻寬瓶頸：訓練中，GPU 需要不斷同步梯度。如果機器間的網路太慢，GPU 大部分時間在等待，利用率可能只有 30–50%。這是叢集設計最常見的問題。

GPU 效率（MFU）的概念
  • MFU（Model FLOP Utilization）= 實際效率 / 理論最大效率
  • 良好的叢集訓練：MFU 40–60%（算很好了）
  • MFU 低的原因：GPU 等資料、GPU 等網路同步
  • GPT-4 訓練據估計 MFU 約 32–38%
  • 提升 MFU 是 AI 基礎設施工程師最重要的工作

✅ 本章重點整理

  • 資料平行：每張 GPU 有完整模型，處理不同資料，最常用
  • 模型平行：模型按層切開，適合放不進單 GPU 的大模型
  • NVLink（機器內，900GB/s）比 InfiniBand（機器間，400Gb/s）快很多
  • 叢集網路是瓶頸，InfiniBand 是大型訓練必備
  • 70B 微調需要 4–8 張 A100；從頭訓練需要 64 張以上
  • DeepSpeed ZeRO 是目前最常用的大模型微調省 VRAM 技術
