# iPAS 資訊安全工程師 · 和風研鑽備考神盾

> **經濟部產業人才能力鑑定（iPAS）資訊安全工程師備考自學系統**  
> 純靜態 HTML5 / CSS3 / Vanilla JavaScript 架構，零外部依賴、無須後端伺服器，直接以瀏覽器開啟 `index.html` 即可使用。  
> 收錄初級與中級各 800 題（總計 1,600 題非重複實務題庫，90% 企業情境題）、32 單元官方考綱深度系統講義、英美雙音 Web Speech 語音辭典與全真計時模擬考。

## ⚡ 考前速讀筆記大綱（四大核心考科）

本大綱專為 iPAS 考生於考前 30 分鐘高效複習、鎖定核心考點而設計，完整涵蓋考綱最核心的四大架構維度：

### 一、治理（Governance）
1. **資訊安全政策**：明確規範組織的資安目標、方向，由最高管理階層簽署發布，每年定期審查。
2. **ISMS（資訊安全管理系統）**：依 ISO 27001 建立，保護資產 CIA 三要素，最新 ISO 27001:2022 具備 4 大主題維度與 93 項控制措施。
3. **PDCA 循環**：Plan（規劃）→ Do（執行）→ Check（檢查/稽核）→ Act（行動/持續改善），為資安持續運行的循環引擎。
4. **風險管理流程**：資產盤點 → 威脅弱點辨識 → 風險評估（風險值 = 威脅 × 弱點 × 資產）→ 風險處理。
5. **風險處理方式**：
   - *避免（Avoidance）*：終止高風險業務或關閉危險服務。
   - *轉嫁（Transference）*：投保資安綜合保險或外包合約要求 SLA 賠償。
   - *降低（Mitigation）*：部署防火牆、MFA、修補補丁與落實備份。
   - *接受（Acceptance）*：殘餘風險低於容忍度，經權責長官正式簽核認可。
6. **NIST CSF 2.0 六大功能**：Govern（治理，2.0 新增）/ Identify（辨識）/ Protect（保護）/ Detect（偵測）/ Respond（應變）/ Recover（復原）。
7. **CIS Controls**：優先落實的 18 項資安控制措施，以 IG1 基礎資安衛生為首要，前兩項為硬體與軟體資產清冊。
8. **組織角色**：高階主管（負最終法定全責）、資安長（CISO 專責規劃推動）、ISMS 負責人、資產擁有者、資產保管者、全員資安責任。
9. **內部稽核與管理審查**：內部稽核獨立客觀定期檢視合規性；管理審查由最高層主持，定期重新配置資源與持續改善。
10. **持續改善（Continuous Improvement）**：透過稽核缺失、外部情資與事件回饋，持續提出矯正與預防措施（CAPA）。

### 二、存取（Access）
1. **身分認證三要素**：
   - *你知道的（Something You Know）*：密碼、PIN 碼。
   - *你擁有的（Something You Have）*：Token、OTP 卡、FIDO2 金鑰。
   - *你是誰（Something You Are）*：指紋、臉部、虹膜等生物特徵。
2. **多因素認證（MFA）**：至少使用兩種**不同類別**的認證（如密碼＋OTP，同類別不算 MFA）。
3. **最小權限原則（PoLP）**：只授予完成工作所需的最低權限與最短必要時間（JIT）。
4. **零信任（Zero Trust / ZTA）**：核心理念「永不信任，始終驗證」，不預設信任任何內外部網路，包含 PEP（策略強制點）與 PDP（策略決策點）。
5. **存取控制模型**：
   - *DAC（自主）*：資源擁有者自行支配權限（如 Windows NTFS/Linux）。
   - *MAC（強制）*：中央系統依安全等級與機密標籤強制限制（如軍方、SELinux）。
   - *RBAC（角色）*：權限綁定角色，使用者指派至角色（企業標準）。
   - *ABAC（屬性）*：結合主客體、操作與環境動態屬性判定（雲端與零信任）。
6. **密碼管理政策**：長度 12 碼以上、複雜度、防暴力破解鎖定閾值、阻絕弱密碼庫。
7. **特權帳號管理（PAM）**：金庫代管、隨選即用（JIT）、強制 MFA、操作全程側錄與審計。
8. **帳號生命週期**：建立（Provisioning）→ 使用維護 → 停用（離職日立即停用）→ 刪除封存（Deprovisioning）。
9. **分離職務（SoD）**：避免單人同時擁有關鍵權限（如程式開發者不得兼有生產環境直接發布與寫入 DB 權限）。
10. **審計追蹤（Audit Trail）**：完整記錄 Who/What/When/Where，日誌集中隔離、防竄改（WORM）、同步 NTP 時間戳記。

### 三、事件（Incident）
1. **事件 vs 弱點**：弱點是靜態的潛在漏洞缺陷，事件是威脅利用弱點已造成的實際安全異常與損害。
2. **事件管理流程**：偵測（Detection）→ 通報（Reporting）→ 分析（Analysis）→ 控制（Containment/圍堵）→ 根除（Eradication）→ 復原（Recovery）→ 後續檢討（Lessons Learned）。
3. **通報時效**：
   - *資通安全管理法*：知悉事件後 **1 小時內**完成初報。
   - *個人資料保護法*：查明外洩後以適當方式通知當事人，主管機關重大事件通常於 **72 小時內**通報。
   - *金融業重大事件*：知悉後 **30 分鐘內**電話初報。
4. **事件分級**：1 級（輕微）、2 級（中等）、3 級（嚴重）、4 級（國家級重大），決定應變優先順序與處理時限。
5. **數位鑑識重點**：保全證據完整性（Chain of Custody 監管鏈）、使用防寫裝置製作映像檔、依揮發順序（Order of Volatility）最優先採集記憶體（RAM）。
6. **常見攻擊手法**：SQL Injection（參數化查詢防護）、XSS（輸出編碼＋HttpOnly）、CSRF（隨機 Token＋SameSite）、DDoS（流量清洗＋SYN Cookies）、釣魚（SPF/DKIM/DMARC 照會）、勒索病毒（3-2-1 離線備份）。
7. **偵測工具**：IDS（旁路偵測告警）、IPS（串聯即時阻斷）、SIEM（集中日誌與關聯分析）、EDR（端點深度監控與隔離）。
8. **資安演練**：桌上演練（Tabletop，劇本討論推演）與實兵攻防演練（Red-Blue Team，擬真攻防滲透）。
9. **災難復原計畫（DRP）**：確保事件後 IT 服務快速復原，核心量化指標為 RTO（最長可容忍中斷時間）與 RPO（最多可容忍資料遺失量）；備援機房包含熱站、溫站、冷站。
10. **事後檢討（Lessons Learned）**：事件後召開檢討會，以 5 Whys 進行根本原因分析（RCA），修正政策與防禦缺口。

### 四、法規（Compliance & Regulations）
1. **《資通安全管理法》**：主管機關為數位發展部資通安全署，納管公務機關與特定非公務機關（關鍵基礎設施 CI、公營事業、政府捐助財團法人）。
2. **資通安全責任等級**：分 A、B、C、D、E 五級，A 級最高最嚴（需配備專責 CISO、全職資安專責人員、每年外部紅藍演練與 ISMS 驗證）。
3. **通報義務**：知悉資安事件 1 小時內完成通報，1~2 級 72 小時內結報，3~4 級 36 小時內結報。
4. **《個人資料保護法》**：規範個資之蒐集、處理、利用需具備合法特定目的，符合比例原則與適當安全維護措施；第 6 條特種個資為病歷、醫療、基因、性生活、健康檢查、犯罪前科。
5. **個資法當事人權利**：查詢閱覽、製給複製本、補充更正、停止處理利用、請求刪除五大權利，不得預先約定拋棄。
6. **個資外洩處理**：查明事故後應即以適當方式通知當事人，告知事實、因應措施與建議處置。
7. **罰則**：行政罰鍰（最高可達新臺幣 1,500 萬元）、民事損害賠償（每人每一事件 500~20,000 元，單一事件上限可達 2 億元）、刑事責任（最高 5 年有期徒刑）。
8. **ISMS 認證要求**：政府與大企業要求供應商符合 ISO 27001，強化 ICT 供應鏈安全檢測（SBOM、實地稽核權）。
9. **內控與稽核**：留存完整稽核軌跡，日誌至少保存 6 個月至 1 年（金融日誌 3~5 年），作為落實適當安全維護之免責舉證。
10. **國際框架映射**：ISO 27001（全面管理體系）、NIST CSF 2.0（六大功能動態演進）、CIS Controls（18 項技術控制清單），相互映射支撐合規。

## 🚀 快速啟動

無需建置環境，直接開啟即可研鑽：
```bash
# 本地雙擊開啟
learning/ipas-security/index.html

# 或透過任何靜態網頁伺服器開啟 (如專案預設 Port 7030)
npx serve learning/ipas-security -p 7030
# 或
python -m http.server 7030 -d learning/ipas-security
```
開啟後即可在頂部導覽列切換「總覽首頁」、「全真模擬考」、「章節練習」、「錯題筆記本」、「題庫搜尋」、「術語發音辭典」、「考科全真講義」以及「考前速讀筆記」！
