📐 (二) 三向交握 
用戶端 ──── SYN (seq=x) ────────────→ 伺服器
       ←─── SYN+ACK (seq=y, ack=x+1) ──
       ──── ACK (ack=y+1) ───────────→
       ◄══════ 連線建立 ═══════════►

斷線：FIN → ACK ← FIN ← ACK →（四次）
問題原因
為何建立要三次連線是雙向的，兩邊都須確認「對方收得到我」；前兩次僅確認單方向，第三次 ACK 才使伺服器確知對方也收到其回應，同時完成初始序號同步
為何斷線要四次TCP 為全雙工，兩方向須各自關閉。一方送 FIN 僅表示「我沒資料要送了」，對方可能仍有資料待傳完，故 ACK 與 FIN 需分開送出
📊 (三) IP 通但網址不通
判斷內容
問題定位IP 可連 → 實體層到網路層皆正常；問題出在名稱解析（DNS）
檢查步驟① ipconfig /all 確認 DNS 伺服器設定是否正確
② nslookup 網域名稱 測試解析
③ 改用備援 DNS（如上級機關或公用 DNS）測試
④ 檢查本機 hosts 檔是否被竄改
⑤ 確認 DNS 伺服器服務是否正常、是否被防火牆阻擋（UDP 53）
可能原因DNS 伺服器故障或過載、DNS 設定錯誤、DNS 快取毒化、惡意程式竄改 hosts 檔
後續若為攻擊（快取毒化），應通報並考慮部署 DNSSEC；平時應設定備援 DNS

📐 (二) 數位簽章 
簽署端 A：原文 →①雜湊→ 摘要 →②A的私鑰加密→ 數位簽章
          →③傳送「原文 + 簽章」

驗證端 B：④用 A 的公鑰解開簽章 → 摘要A
          ⑤對收到原文重新雜湊 → 摘要B
          ⑥比對：相同 → 未竄改且確為 A 所簽
資安目標說明
完整性原文遭改則雜湊值不符
鑑別性只有持該私鑰者能產生此簽章
不可否認性私鑰僅簽署者持有（HMAC 做不到）
不提供機密性原文為明文，須另行加密

為何先雜湊再簽：非對稱運算慢且原文可能很大，雜湊為固定短長度，效率高得多。

📊 (三) 密碼儲存
做法評價理由
明文儲存❌ 最嚴重外洩即全部曝光，違反個資法安全維護義務
AES 加密❌可還原；金鑰洩漏則全毀，且系統本不需知道原始密碼
MD5／SHA-1❌運算太快（每秒可試數十億次）且可查彩虹表
bcrypt／Argon2 ＋ 隨機鹽✅ 正解① 慢速雜湊使暴力破解不可行
② 每帳號不同鹽使彩虹表失效，相同密碼雜湊值也不同

另應搭配密碼政策（長度、禁用常見密碼）與MFA；並依個資法採行適當之安全維護措施。

int n, i, sum = 0;      // 務必初始化
scanf("%d", &n);

for (i = 3; i <= n; i += 3) {   // 直接每次加 3，省去判斷
    sum += i;

驗算（n = 10）：3+6+9 = 18 ✔　複雜度：O(n)

📝 (三) GCD 與 LCM 
// 最大公因數（輾轉相除法）
int gcd(int a, int b) {
    while (b != 0) {
        int t = a % b;
        a = b;
        b = t;
    }
    return a;
}

// 最小公倍數：先除再乘，避免 a*b 溢位
int lcm(int a, int b) {
    return a / gcd(a, b) * b;
}

驗算：gcd(24, 36)
a=24,b=36 → t=24, a=36, b=24 → t=12, a=24, b=12 → t=0, a=12, b=0 → 回傳 12 ✔
lcm(24,36) = 24/12×36 = 72 ✔

加分點：說明「先除再乘」可避免溢位；複雜度 O(log min(a,b))。

📝 (三) 二分搜尋

前提條件（務必寫出）：陣列必須已排序。承第 (一) 小題已由多到少排序，故比較方向須對應調整（或先改為由小到大）。

// 於「由大到小」排序之陣列中搜尋
int binarySearchDesc(int a[], int n, int key) {
    int low = 0, high = n - 1;
    while (low <= high) {                  // 注意有等號
        int mid = low + (high - low) / 2;  // 防溢位寫法
        if (a[mid] == key) return mid;
        else if (a[mid] > key) low = mid + 1;   // 由大到小：大於則往右
        else high = mid - 1;
    }
    return -1;                             // 找不到
}

驗算（由大到小 {5000, 4200, 3800, 2500, 1200}，找 3800）：
low=0, high=4 → mid=2 → a[2]=3800 命中，回傳 2 ✔

複雜度：O(log n)；線性搜尋為 O(n)。
實務判斷：只查一次 → 直接線性搜尋（排序本身要 O(n²) 或 O(n log n)）；要查很多次才值得先排序。

📝 (一) 遞迴階乘 
long long factorial(int n) {
    if (n < 0)  return -1;      // 錯誤處理：負數無階乘
    if (n <= 1) return 1;       // 終止條件（0! = 1）
    return n * factorial(n - 1);  // 遞迴關係
}
要素說明
① 終止條件Base Case——不再遞迴的最小情形；缺少會造成無限遞迴與 Stack Overflow
② 遞迴關係以較小規模的自己表達目前問題，且規模須逐次縮小

驗算：factorial(5) = 5×4×3×2×1 = 120；factorial(0) = 1（定義）
注意溢位：13! 已超過 int 上限，20! 超過 long long → 應限制輸入範圍。

📝 (三) 回文判斷 
// 基本版
int isPalindrome(char s[]) {
    int len = 0;
    while (s[len] != '\0') len++;     // 計算長度

    int i;
    for (i = 0; i < len / 2; i++) {     // 只需比較一半
        if (s[i] != s[len - 1 - i])     // 注意是 len-1-i
            return 0;
    }
    return 1;
}

// 忽略大小寫版：比較前統一轉小寫
char toLower(char c) {
    if (c >= 'A' && c <= 'Z') return c + 32;   // ASCII 差 32
    return c;
}

int isPalinIgnoreCase(char s[]) {
    int len = 0, i;
    while (s[len] != '\0') len++;

    for (i = 0; i < len / 2; i++) {
        if (toLower(s[i]) != toLower(s[len - 1 - i]))
            return 0;
    }
    return 1;
}

驗算："Level"（len=5）→ i=0：'l' vs 'l' ✔；i=1：'e' vs 'e' ✔ → 是回文 ✔

進一步（若須忽略空白與標點）：可用雙指標法——左右指標各自跳過非字母字元後再比較，時間 O(n)、空間 O(1)。

兩個常錯處：① 索引是 len-1-i 不是 len-i（會越界）；② 迴圈只跑 len/2。

📊 (一) 錯誤分析
編號錯誤問題所在後果
①變數未初始化int sum; 未設為 0 就 sum += a[i]sum 起始為不確定的垃圾值，結果完全錯誤且每次執行可能不同
②陣列越界（差一錯誤）i <= 8 會存取 a[8]（合法索引 0~7）未定義行為，讀到不屬於陣列的記憶體
③整數除法截斷avg = sum / 8; 兩者皆為整數小數被截斷後才指定給 avg；本例 189/8 應為 23.625，卻得 23.0
④魔術數字程式中直接寫 8陣列大小改變時需多處修改，易遺漏
③ 的影響最隱蔽：avg 從 23.625 變成 23.0，使得剛好介於 23 與 23.625 之間的元素被誤判為「大於平均」——程式能跑、不會當掉，但答案是錯的。這正是最難發現的邏輯錯誤。
📝 (二) 修正後的程式

int a[N] = {12, 45, 8, 33, 27, 5, 19, 40};
int i;

for (i = 0; i < N; i++) {          // ② 用 < 不用 <=
    sum += a[i];
}

avg = (float)sum / N;             // ③ 轉型後再除
