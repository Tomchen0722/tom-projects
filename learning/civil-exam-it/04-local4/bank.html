A. 計算機概要（1～18 題）

1進位
某區公所設備編號以十六進位 1F4₍₁₆₎ 表示，其十進位值為？
  • (A) 484　(B) 500　(C) 504　(D) 520
詳解
答案：(B) 500
1×16² + 15×16¹ + 4×16⁰ = 256 + 240 + 4 = 500

快速驗算：1F4 → 二進位 0001 1111 0100 = 256+128+64+32+16+4 = 500 ✔
2進位
十進位 218 轉為二進位為？
  • (A) 11011010　(B) 11010110　(C) 11011100　(D) 11001010
詳解
答案：(A) 11011010 
權重: 128 64 32 16  8  4  2  1
218 ≥128 → 1，剩 90
 90 ≥ 64 → 1，剩 26
 26 ≥ 32 → 0
 26 ≥ 16 → 1，剩 10
 10 ≥  8 → 1，剩 2
  2 ≥  4 → 0
  2 ≥  2 → 1，剩 0
  0 ≥  1 → 0
→ 1 1 0 1 1 0 1 0
驗算：128+64+16+8+2 = 218 ✔
3補數
以 8 位元 2 的補數表示 −50，其二進位為？
  • (A) 11001101　(B) 11001110　(C) 10110010　(D) 11001100
詳解
答案：(B) 11001110 
+50 = 0011 0010
1 的補數（取反）= 1100 1101
2 的補數（+1）  = 1100 1110 ✔
驗算：−50 + 50 應為 0
11001110 + 00110010 = 1 00000000 → 捨棄進位 → 0 ✔

(A) 是 1 的補數（少加 1），最常見的錯誤。
4邏輯
依笛摩根定律，(A + B)' 等於？
  • (A) A' + B'　(B) A' · B'　(C) A · B　(D) A + B
詳解
答案：(B) A' · B'
口訣：「斷線、變號」——否定線斷開，中間符號改變（+ ↔ ·）。

白話驗證：「不是（下雨 或 颳風）」＝「沒下雨 而且 沒颳風」✔

另一式：(A · B)' = A' + B'
5邏輯
當 A=1、B=1 時，下列哪個邏輯閘輸出為 0？
  • (A) AND　(B) OR　(C) XOR　(D) 以上皆為 1
詳解
答案：(C) XOR——不一樣才是 1，兩者相同故為 0。

閘A=1,B=1口訣
AND1都是 1 才是 1
OR1有 1 就是 1
XOR0不一樣才是 1
NAND0AND 的相反
注意 (D) 是陷阱——若加上 NAND 則也為 0。
6組織
某公所伺服器以 5 顆 4TB 硬碟建立 RAID 5，可用容量為？
  • (A) 8 TB　(B) 12 TB　(C) 16 TB　(D) 20 TB
詳解
答案：(C) 16 TB
RAID 5 可用容量 = (n − 1) × 單顆容量 = (5−1) × 4TB = 16 TB
（相當於用一顆的容量分散存放同位資訊，可容許 1 顆故障）

對照：RAID 0 → 20 TB（無容錯）；RAID 6（5 顆）→ (5−2)×4 = 12 TB（可壞 2 顆）
7組織
關於備份與 RAID，下列敘述何者正確？
  • (A) 有 RAID 就不需要備份　(B) RAID 可防止誤刪檔案
  • (C) RAID 防硬碟故障，仍需異地與離線備份　(D) RAID 0 容錯能力最強
詳解
答案：(C)
RAID 不是備份。它防的是硬碟故障，但防不了：
‧ 誤刪檔案（會同步刪掉所有副本）
‧ 勒索軟體加密（會同步加密）
‧ 火災、水災、機房整個損毀

正確做法：RAID ＋ 備份並行，備份遵循 3-2-1 原則（3 份副本、2 種媒體、1 份異地），並保留離線副本防勒索。
8OS
三個作業同時抵達，執行時間分別為 10、4、6，採 SJF 排程之平均等待時間為？
  • (A) 4　(B) 4.67　(C) 6　(D) 6.67
詳解
答案：(B) 4.67
SJF 由短到長執行：4 → 6 → 10
作業執行時間開始時間等待時間
P2400
P3644
P1101010
平均等待 = (0 + 4 + 10) ÷ 3 = 14 ÷ 3 ≈ 4.67

關鍵觀念：某作業的等待時間 = 排在它前面的所有作業執行時間總和。

對照 FCFS（依抵達順序 10→4→6）：(0 + 10 + 14) ÷ 3 = 8
→ SJF 明顯較優，這就是「護送效應」的差異（長作業擋住短作業）。

但 SJF 的代價：需預知執行時間，且長作業可能飢餓（須以 Aging 機制補救）。
9OS
下列何者不是死結的必要條件？
  • (A) 互斥　(B) 持有並等待　(C) 可搶奪　(D) 循環等待
詳解
答案：(C)
死結四條件為「互斥、持有並等待、不可搶奪、循環等待」。若資源可以被搶奪，僵局即可打破。

破壞任一條件即可避免死結；實務最常用的是破壞循環等待——規定所有行程依相同順序取得資源。
10OS
Unix/Linux 中 chmod 640 代表的權限為？
  • (A) rwxr-x---　(B) rw-r-----　(C) rw-r--r--　(D) r--rw----
詳解
答案：(B) rw-r-----
r=4、w=2、x=1，三位數分別代表擁有者／群組／其他人：
6 = 4+2 = rw-｜4 = r--｜0 = ---

常見組合：755 = rwxr-xr-x（可執行檔）｜644 = rw-r--r--（一般檔案）｜777 = 資安大忌
11資料結構
戶政事務所叫號系統採「先到先服務」，最適合的資料結構為？
  • (A) 堆疊　(B) 佇列　(C) 二元搜尋樹　(D) 雜湊表
詳解
答案：(B) 佇列（Queue，FIFO 先進先出）

‧ 堆疊（Stack）是後進先出，用於函式呼叫、Undo、括號配對
‧ 若需支援「敬老號優先」，則應改用優先佇列（Priority Queue），並加老化（Aging）機制避免一般號長期等待

13資料結構
下列程式片段的時間複雜度為？
for(i=0;i<n;i++) for(j=n;j>0;j/=2) c++;
  • (A) O(n)　(B) O(n log n)　(C) O(n²)　(D) O(log n)
詳解
答案：(B) O(n log n)
‧ 外層 i++ → n 次
‧ 內層 j /= 2 → n, n/2, n/4… → log₂n 次

核心觀念：看迴圈變數怎麼「變」，不是看有幾層。
j++/j-- → 線性｜j*=k 或 j/=k → 對數
14資料庫
關聯 R(案件編號, 承辦人編號, 承辦人姓名, 區代碼)，主鍵為案件編號，且承辦人編號→承辦人姓名。此關聯違反？
  • (A) 1NF　(B) 2NF　(C) 3NF　(D) 未違反
詳解
答案：(C) 違反 3NF（遞移相依）
案件編號 → 承辦人編號 → 承辦人姓名。

為何不是 2NF？主鍵是單一屬性，不可能有部分相依 → 單一屬性主鍵必定符合 2NF（超好用的判斷捷徑）。

分解：案件(案件編號, 承辦人編號FK, 區代碼)、人員(承辦人編號, 承辦人姓名)
15資料庫
要查出「各區案件數超過 20 件」的行政區，SQL 應使用？
  • (A) WHERE COUNT(*)>20 GROUP BY 區代碼
  • (B) GROUP BY 區代碼 HAVING COUNT(*)>20
  • (C) HAVING COUNT(*)>20（無 GROUP BY）
  • (D) ORDER BY COUNT(*)>20
詳解
答案：(B)
WHERE 過濾「列」、HAVING 過濾「組」。

執行順序：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
WHERE 在 GROUP BY 之前執行，那時還沒分組，聚合函數不存在 → (A) 會報錯。

交換器（Switch）主要依據什麼轉送資料？
  • (A) IP 位址　(B) MAC 位址　(C) 埠號　(D) 網域名稱
詳解
答案：(B) MAC 位址（工作於 L2 資料連結層）

設備層級依據
集線器L1無（廣播）
交換器L2MAC
路由器L3IP

17網路
IP 192.168.8.90，遮罩 255.255.255.224，其網路位址為？
  • (A) 192.168.8.64　(B) 192.168.8.80　(C) 192.168.8.96　(D) 192.168.8.32
詳解
答案：(A) 192.168.8.64
① 遮罩 224 → 區塊大小 = 256 − 224 = 32
② 段界：.0、.32、.64、.96、.128…
③ 90 落在 64～95 → 網路位址 .64、廣播位址 .95

可用範圍 .65 ~ .94（30 台，2⁵−2）
18網路
下列協定與埠號對應何者錯誤？
  • (A) HTTP — 80　(B) HTTPS — 443　(C) DNS — 53　(D) SSH — 21
詳解
答案：(D)——SSH 是 22；21 是 FTP 控制埠。

必背：22 SSH｜23 Telnet｜25 SMTP｜53 DNS｜80 HTTP｜110 POP3｜143 IMAP｜443 HTTPS｜3389 RDP

資安提醒：3389（RDP）與 445（SMB）絕不可直接對外開放——是勒索軟體最常見的入侵管道。

B. 資通網路與安全概要（19～30 題）

19網路
某區公所辦公網段需容納 100 台電腦，最節省的遮罩為？
  • (A) /24　(B) /25　(C) /26　(D) /27
詳解
答案：(B) /25（2⁷ − 2 = 126 ≥ 100）

/26 只有 62 台不夠；/24 有 254 台但浪費 128 個位址。

解題技巧：從「需求 + 2」往上找最接近的 2 的次方 → 100+2 = 102 → 最接近且大於它的是 128 = 2⁷ → 主機位元 7 → /25
20網路
公所電腦 IP 顯示 169.254.20.5，代表？
  • (A) 已取得公有 IP　(B) DHCP 取得失敗　(C) 設為靜態 IP　(D) 已連上 VPN
詳解
答案：(B) DHCP 取得失敗
169.254.0.0/16 是 APIPA，Windows 在取不到 DHCP 位址時自動指派。

排查步驟：① 網路線與交換器埠 ② DHCP 伺服器是否運作、位址池是否耗盡 ③ 跨網段的 DHCP Relay 設定 ④ 是否被 Port Security 阻擋
21網路
TCP 三向交握的順序為？
  • (A) SYN → ACK → SYN　(B) SYN → SYN+ACK → ACK　(C) ACK → SYN → FIN　(D) SYN → FIN → ACK
詳解
答案：(B)
① 用戶端 SYN「我想連線」→ ② 伺服器 SYN+ACK「好，並確認收到你的」→ ③ 用戶端 ACK「確認收到」

為何三次：連線是雙向的，兩邊都要確認對方收得到；第三次 ACK 讓伺服器確知用戶端也收到回應。

斷線需四次（FIN→ACK→FIN→ACK），因全雙工需兩方向各自關閉。
22網路
區公所提供洽公民眾使用的 Wi-Fi，下列何者最為必要？
  • (A) 隱藏 SSID　(B) 與內部網路完全隔離並啟用用戶端隔離
  • (C) 使用 WEP 加密　(D) 開放內部檔案伺服器供下載表單
詳解
答案：(B)
公共 Wi-Fi 的第一原則就是隔離：獨立 VLAN + 防火牆隔離內網；並啟用用戶端隔離禁止訪客彼此連線。

‧ (A) 隱藏 SSID 不是有效安全措施（探測封包仍可發現）
‧ (C) WEP 已被破解，絕不可用
‧ (D) 開放內部伺服器等於自毀防線

另須依規定保存連線紀錄；蒐集手機號碼認證須符合個資法特定目的告知義務。
23資安
A 要傳機密文件給 B，只讓 B 能閱讀，應用何者加密？
  • (A) A 的公鑰　(B) A 的私鑰　(C) B 的公鑰　(D) B 的私鑰
詳解
答案：(C) B 的公鑰（只有 B 的私鑰能解，而私鑰只有 B 有）

必背口訣：
‧ 要保密 → 用「對方的公鑰」加密（機密性）
‧ 要簽名 → 用「自己的私鑰」簽章（鑑別性、不可否認性）
24資安
下列何者只有數位簽章能提供？
  • (A) 完整性　(B) 機密性　(C) 不可否認性　(D) 可用性
詳解
答案：(C) 不可否認性
HMAC 使用雙方共享金鑰 → A 能產生的訊息 B 也能產生 → 事後可互相推託，無法歸責。
數位簽章用的是只有簽署者持有的私鑰，因此無法抵賴。

注意：數位簽章不提供機密性（原文是明文傳送）。

三層遞進：雜湊（完整性）→ HMAC（＋來源鑑別）→ 數位簽章（＋不可否認性）
25資安
機關系統儲存使用者密碼，最適當的做法為？
  • (A) 明文儲存但限制資料庫權限　(B) 以 AES 加密後儲存
  • (C) 以 MD5 雜湊後儲存　(D) 以 bcrypt／Argon2 慢速雜湊搭配隨機鹽
詳解
答案：(D)
‧ (A) 明文是最嚴重的錯誤，違反《個人資料保護法》安全維護義務
‧ (B) 加密可還原，金鑰洩漏則全毀；系統本不需知道原始密碼
‧ (C) MD5 運算太快且可查彩虹表

正解的兩個關鍵：
① 慢速雜湊（刻意設計得慢，使暴力破解不可行）
② 每帳號不同的隨機鹽（使彩虹表失效，相同密碼的兩人雜湊值也不同）
26資安
下列何者屬於真正的多因子驗證（MFA）？
  • (A) 密碼 + 安全提示問題　(B) 密碼 + 手機 OTP　(C) 密碼 + PIN　(D) 指紋 + 臉部辨識
詳解
答案：(B)——密碼（你知道的）＋ OTP（你擁有的），屬不同類別。

‧ (A)(C) 都屬「你知道的」　‧ (D) 都屬「你本身的」

三大類別：你知道的｜你擁有的｜你本身的。

實務：機關 VPN 與遠端存取必須啟用 MFA——僅靠帳密的 VPN 是勒索軟體最常見入口。
27資安
某公所遭勒索軟體攻擊，連備份也一併被加密，最可能原因為？
  • (A) 備份頻率不足　(B) 備份持續連線於網路且與正式環境同網域
  • (C) 備份檔案太大　(D) 使用了 RAID 5
詳解
答案：(B)
勒索軟體會主動搜尋網路上的共享磁碟與備份目標並一併加密；若取得網域管理員權限，甚至會先刪除備份。

正確做法：
① 離線備份（Air-gapped）　② 不可變備份（Immutable）
③ 備份系統帳號與網域分離　④ 多版本保留（惡意程式可能潛伏數週）
⑤ 定期演練還原——「備份成功」不等於「還原成功」
28資安
承辦人接到自稱局長的電話，語音極為相似，要求緊急變更廠商匯款帳號。最適當的處理為？
  • (A) 依指示辦理以免延誤　(B) 以另一既有管道回撥確認　(C) 錄音後直接辦理　(D) 請對方再打一次
詳解
答案：(B)
生成式 AI 使深偽（Deepfake）語音門檻大幅降低——「聽到本人聲音」已不再是可靠的身分確認方式。

這是典型的 BEC 詐騙，運用權威與急迫兩種心理槓桿。

機關應有的控管：變更匯款帳號等關鍵作業採雙人覆核；重要指示須以另一管道回撥（打通訊錄上的分機，而非對方給的號碼）確認。
29法規
依《資通安全管理法》，機關知悉資安事件後應？
  • (A) 內部處理完再視情況通報　(B) 於規定時限內通報主管機關　(C) 僅重大事件才通報　(D) 由廠商代為通報
詳解
答案：(B)
依《資通安全管理法》及《資通安全事件通報及應變辦法》，知悉後即應於規定時限內通報，不得先處理完再通報。

事件依影響程度分 1～4 級；3、4 級為重大事件，須提出調查、處理及改善報告。

作答提醒：不必背精確時數，寫「規定時限內」最安全。
注意區分：機關資安責任等級 A～E 五級／事件 1～4 級，是兩套不同分級。
30法規
公所欲開放「各里低收入戶數統計」資料，最需注意的風險為？
  • (A) 檔案格式不美觀　(B) 某里僅 1～2 筆可能被指認出當事人　(C) 下載人數過多　(D) 資料量太大
詳解
答案：(B) 小樣本揭露風險
即使已移除姓名與身分證字號，若某里僅 1～2 筆資料，鄰里間即可能指認出當事人。

三層風險：
① 小樣本揭露 → 設最小揭露門檻或合併分組
② 間接識別 → 準識別欄位須泛化（年齡層、區級）

求陣列最大值的正確寫法為？
  • (A) max=0; for(i=0;i<n;i++) if(a[i]>max) max=a[i];
  • (B) max=a[0]; for(i=1;i<n;i++) if(a[i]>max) max=a[i];
  • (C) max=a[n]; for(i=0;i<n;i++) if(a[i]>max) max=a[i];
  • (D) for(i=0;i<n;i++) max=a[i];
詳解
答案：(B)——先假設第一個元素最大，再從第二個開始比較。

為什麼 (A) 錯：若陣列全是負數（如溫差、盈虧），max 初值 0 永遠不會被更新 → 錯誤回傳 0。這是經典的邊界條件陷阱。

(C) 錯：a[n] 已越界。
(D) 錯：max 一直被覆蓋，最後等於最後一個元素。
36程式
要反轉一個長度為 n 的陣列，迴圈應執行幾次？
  • (A) n　(B) n−1　(C) n/2　(D) 2n
詳解
答案：(C) n/2 
for (i = 0; i < n/2; i++) {
    int t = a[i];
    a[i] = a[n-1-i];
    a[n-1-i] = t;
}
為何只跑一半：每次交換同時處理兩個元素；若跑完 n 次，每對元素被交換兩次 → 又轉回原狀。

注意索引是 n-1-i 不是 n-i（最後一個元素的索引是 n−1）。
37程式
下列程式執行後 a 的值為？
void f(int x){ x=99; } int a=7; f(a);
  • (A) 7　(B) 99　(C) 0　(D) 不確定
詳解
答案：(A) 7（沒有改變）
C 語言預設是「傳值」——傳進去的是複製品，函式內修改的是副本。

要改到原變數必須傳址： 
void f(int *x) { *x = 99; }
f(&a);   // 現在 a 變成 99
比喻：傳值＝影印一份給對方（正本不受影響）；傳址＝告訴對方正本放哪（會被改到）。

重要例外：陣列傳入函式時自動是傳址。
38程式
遞迴函式必備的兩個要素為？
  • (A) 迴圈與陣列　(B) 終止條件與遞迴關係　(C) 指標與結構　(D) 全域變數與回傳值
詳解
答案：(B) 終止條件（Base Case）＋ 遞迴關係

缺少終止條件 → 無限遞迴 → Stack Overflow，程式當掉。
int factorial(int n) {
    if (n <= 1) return 1;           // ← 終止條件
    return n * factorial(n - 1);    // ← 遞迴關係
}
比喻：排隊問前面的人「你排第幾？」，一路問到第一個人說「我第 1 個」（終止條件），答案才能傳回來。
39程式
使用二分搜尋法的必要前提為？
  • (A) 資料量很大　(B) 資料必須已排序　(C) 必須使用遞迴　(D) 資料必須是整數
詳解
答案：(B) 資料必須已排序
二分搜尋每次比較後要判斷「往左找還是往右找」，這完全依賴資料的有序性。

複雜度比較：線性搜尋 O(n)（不需排序）｜二分搜尋 O(log n)（需先排序，排序本身要 O(n log n)）

實務判斷：只搜尋一次 → 直接線性搜尋；要搜尋很多次 → 先排序再用二分搜尋才划算。
40程式
下列程式片段有何錯誤？
int a[10], i, sum; for(i=0;i<=10;i++) sum+=a[i];
  • (A) 只有語法錯誤　(B) 陣列越界與變數未初始化　(C) 無窮迴圈　(D) 沒有錯誤
詳解
答案：(B) 兩個錯誤

① 陣列越界（差一錯誤）：a[10] 合法索引為 0~9，i <= 10 會存取 a[10] → 未定義行為
② 變數未初始化：int sum; 未設為 0 就直接累加 → sum 起始為垃圾值，結果完全錯誤且每次執行可能不同

修正： 
int a[10], i;
int sum = 0;                 // ① 初始化
for (i = 0; i < 10; i++)     // ② 用 < 不用 <=
    sum += a[i];
這兩個是最高頻的程式 bug，「找錯題」幾乎必考。

某區公所有 n 個里，各里本月案件數存於陣列 caseCount[]。請撰寫程式完成：

(二) 找出案件數最多與最少的里，並輸出其索引位置。（8 分）

看參考解答
📝 (一) 總數與平均

思路：以迴圈走訪陣列累加；平均值須轉型避免整數除法截斷。

// 以 C 語言撰寫
int i, total = 0;              // 務必初始化為 0

for (i = 0; i < n; i++) {      // 用 < 不用 <=
    total += caseCount[i];
}

float avg = (float)total / n;   // 轉型，否則整數除法截斷
printf("總案件數 = %d，平均 = %.2f\n", total, avg);
📝 (二) 最多與最少的里 
int maxIdx = 0, minIdx = 0;    // 先假設第 1 個里是最多也最少

for (i = 1; i < n; i++) {      // 從第 2 個開始比
    if (caseCount[i] > caseCount[maxIdx]) maxIdx = i;
    if (caseCount[i] < caseCount[minIdx]) minIdx = i;
}

printf("案件最多：第 %d 里，%d 件\n", maxIdx + 1, caseCount[maxIdx]);
printf("案件最少：第 %d 里，%d 件\n", minIdx + 1, caseCount[minIdx]);

技巧：記錄索引而非數值，可同時知道「幾件」與「第幾里」。
輸出時 maxIdx + 1 是把 0-based 索引轉為人類習慣的順位。
重要：初值取 0（第一個元素的索引）而非把 max 設為 0——若所有里案件數都是 0 以外的情形仍正確。

📝 (三) 高於平均之里數與前三名 
// 統計高於平均者
int aboveAvg = 0;
for (i = 0; i < n; i++) {
    if (caseCount[i] > avg) aboveAvg++;
}
printf("高於平均之里數 = %d\n", aboveAvg);

// 以選擇排序由「多到少」排序（同時搬移里別編號以免對應錯亂）
int j, temp;
int liNo[100];
for (i = 0; i < n; i++) liNo[i] = i + 1;   // 記錄原始里別

for (i = 0; i < n - 1; i++) {
    int maxPos = i;
    for (j = i + 1; j < n; j++) {
        if (caseCount[j] > caseCount[maxPos]) maxPos = j;
    }
    if (maxPos != i) {
        temp = caseCount[i];
        caseCount[i] = caseCount[maxPos];
        caseCount[maxPos] = temp;
        temp = liNo[i];                // 里別編號同步交換！
        liNo[i] = liNo[maxPos];
        liNo[maxPos] = temp;
    }
}

// 輸出前三名（須處理里數不足三個的情形）
int top = (n < 3) ? n : 3;
for (i = 0; i < top; i++) {
    printf("第 %d 名：第 %d 里，%d 件\n", i + 1, liNo[i], caseCount[i]);
}
⚠️ 本題最關鍵的一點 排序時必須同步搬移「里別編號」，否則案件數排好了，卻不知道是哪個里的——變成「甲里的案件數配到乙里頭上」。

實務上更好的做法是用結構陣列（struct Li { int no; int count; }），排序時整筆交換即可。

驗算（caseCount = {12, 30, 8, 25, 15}，n=5）：
總數 90，平均 18.00；最多第 2 里（30 件）、最少第 3 里（8 件）
高於平均者：30、25 → 2 個里
排序後 {30, 25, 15, 12, 8} → 前三名：第 2 里 30 件、第 4 里 25 件、第 5 里 15 件 ✔

✍️ 必寫拿分點 1. 變數初始化（total = 0）與迴圈用 <
2. 平均值轉型 (float)total / n
3. max/min 記錄索引且初值取第一個元素
4. 排序時同步搬移里別編號——本題核心，或改用結構陣列
5. 處理里數不足三個的邊界情形
6. 加註解、做驗算、標複雜度（本題皆為 O(n) 或 O(n²)）

📝 (一) 處理天數分級

思路：相減求天數後以 if-else if 分級；範圍判斷須由嚴格到寬鬆排序。

int startDay, endDay, days;
scanf("%d %d", &startDay, &endDay);

// 邊界檢查：結案日不得早於受理日
if (endDay < startDay) {
    printf("資料錯誤：結案日早於受理日\n");
} else {
    days = endDay - startDay;

    printf("處理天數 = %d 天，等級：", days);
    if (days <= 3)       printf("優\n");        // 由嚴格到寬鬆！
    else if (days <= 7)  printf("良\n");
    else if (days <= 15) printf("普通\n");
    else                 printf("待改善\n");
}
⚠️ 順序不可顛倒 若把 days <= 15 寫在最前面，則 2 天也會先符合而印出「普通」——if-else if 只執行第一個成立的分支。
規則：範圍判斷一律「由嚴格到寬鬆」排序。
📝 (二) 閏年判斷 
int year;
scanf("%d", &year);

// 能被 4 整除但不能被 100 整除；或能被 400 整除
if ((year % 4 == 0 && year % 100 != 0) || (year % 400 == 0)) {
    printf("%d 是閏年（2 月有 29 天）\n", year);
} else {
    printf("%d 不是閏年（2 月有 28 天）\n", year);
}
年份%4%100%400結果
20240 ✔≠0 ✔—閏年
19000 ✔0 ✘≠0 ✘平年
2000000 ✔閏年

驗證條件式最快的方法：代 1900 與 2000 兩個特例。

📊 (三) 邊界條件的重要性
類型說明本題實例
臨界值剛好等於門檻的值days = 3 時是「優」還是「良」？取決於用 <= 還是 <——須依題意確認
零值0 常需特別處理days = 0（當日結案）應歸「優」
無效輸入不合法的資料結案日早於受理日 → 須檢查並回報錯誤
特例看似符合但實為例外閏年的 1900（非閏年）與 2000（閏年）
跨年度—若案件跨年結案，單純相減會得到負數，須另行處理年份差
陣列邊界索引不可越界迴圈一律用 i < n
⚠️ 為什麼邊界條件這麼重要 絕大多數程式錯誤都發生在邊界——第一個、最後一個、零、空、剛好等於門檻。

這也是測試技巧中「邊界值分析」的由來：若規定 3 天內為「優」，就測 2、3、4 三個值。

機關實務的代價：「處理天數超過 15 天」與「達 15 天」差一個字，績效統計就會失真，而這關係到單位考核與民眾權益。
✍️ 必寫拿分點 1. if-else if 由嚴格到寬鬆排序——本題最容易錯的地方
2. 檢查「結案日早於受理日」的無效輸入
3. 閏年條件式三個條件都要有，並用 1900／2000 驗證
4. 第三小題要用本題實例說明，不能只講抽象原則
5. 提到邊界值分析與跨年度問題是明顯加分
