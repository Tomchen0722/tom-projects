第 1 章　現代作業系統排程演算法深度剖析

傳統講義只介紹 FIFO、SJF、RR 等單一演算法，但現代作業系統（如 Windows、Linux）實際使用的排程器遠比這複雜，通常採用多層級的排程架構。

1-1　多層佇列排程 (Multilevel Queue Scheduling)

系統將行程依據性質（如系統行程、互動式行程、批次行程）分類，並將它們分配到不同的佇列中。每個佇列有自己的排程演算法。

佇列類別優先權排程演算法特性說明
系統行程 (System)最高優先權排程 (Priority)如核心記憶體管理，不容延遲
互動式 (Interactive)中高輪轉法 (Round Robin, RR)如滑鼠移動、鍵盤輸入，需要極短的回應時間
批次式 (Batch)低先到先服務 (FCFS)如背景下載、報表產製，不需即時回應，只求吞吐量

1-2　多層回饋佇列排程 (Multilevel Feedback Queue, MFQ)

為了解決「多層佇列」中行程無法跨佇列移動導致「飢餓 (Starvation)」的問題，MFQ 允許行程在不同優先權的佇列之間移動（回饋）。

📐 MFQ 運作機制（以 3 個佇列為例） 1. Q0 (RR, Time Quantum = 4ms)：新行程進入最高優先權 Q0。若在 4ms 內無法執行完畢，表示它是耗費 CPU 的工作，會被降級放入 Q1。
2. Q1 (RR, Time Quantum = 8ms)：若在 8ms 內仍未執行完，再降級至 Q2。
3. Q2 (FCFS)：最低優先權，適合處理純運算的背景工作。
防飢餓機制 (Aging)：若低優先權的行程等待時間過長，系統會將其升級至高優先權佇列。
🎯 步驟化詳解：多層回饋佇列 (MFQ) 行程流轉與甘特圖推導五部曲

【範例情境】系統設有三層佇列：Q0 (RR, q=4ms)、Q1 (RR, q=8ms)、Q2 (FCFS)。三行程資訊如下：
‧ P1：到達時間 t=0，CPU 需求 18ms
‧ P2：到達時間 t=2，CPU 需求 5ms
‧ P3：到達時間 t=4，CPU 需求 7ms

  • 步驟 1Q0 第一輪排程（優先權最高，搶占式執行）
    ‧ t=0：P1 進入 Q0 開始執行。到 t=2 時 P2 到達 Q0，因同在 Q0，P1 繼續執行完其時間配額 4ms（t=0~4）。P1 剩餘 14ms，用盡配額被降級至 Q1。
    ‧ t=4：P3 到達 Q0。此時 Q0 中有 P2 與 P3。系統依 FCFS 順序挑選 P2（t=4~8 執行 4ms）。P2 剩餘 1ms，用盡配額被降級至 Q1。
    ‧ t=8：Q0 僅剩 P3，執行 4ms（t=8~12）。P3 剩餘 3ms，用盡配額被降級至 Q1。此時 Q0 變空。
  • 步驟 2Q1 第二輪排程（Q0 為空才調度 Q1，時間配額 8ms）
    此時 Q1 內有 P1 (剩 14ms)、P2 (剩 1ms)、P3 (剩 3ms)：
    ‧ t=12~20：P1 執行 8ms，剩餘 6ms 未完，被降級至 Q2。
    ‧ t=20~21：P2 執行 1ms，P2 順利執行完畢！（結束時間 t=21）
    ‧ t=21~24：P3 執行 3ms，P3 順利執行完畢！（結束時間 t=24）。此時 Q1 變空。
  • 步驟 3Q2 第三輪排程（FCFS 背景佇列）
    ‧ t=24~30：Q2 中僅有 P1，執行剩餘的 6ms 直至結束。P1 於 t=30 完工！
  • 結算甘特圖與各行程績效指標計算
    甘特圖序列：[P1: 0~4] → [P2: 4~8] → [P3: 8~12] → [P1: 12~20] → [P2: 20~21] → [P3: 21~24] → [P1: 24~30]
    ‧ 週轉時間 (Turnaround Time = 完工時間 − 到達時間)：
      P1: 30 − 0 = 30 ms；P2: 21 − 2 = 19 ms；P3: 24 − 4 = 20 ms。
      平均週轉時間 = (30 + 19 + 20) / 3 = 23.0 ms。
    ‧ 等待時間 (Waiting Time = 週轉時間 − CPU 需求)：
      P1: 30 − 18 = 12 ms；P2: 19 − 5 = 14 ms；P3: 20 − 7 = 13 ms。
      平均等待時間 = (12 + 14 + 13) / 3 = 13.0 ms。
  • 驗算邏輯合理性雙重檢查
    短工作（如 5ms 的 P2）在第二層就能完工，獲得絕佳回應時間；長運算（如 18ms 的 P1）自動沉澱至底層 Q2，不阻礙互動式行程。驗算無誤！
⚡ 考前 30 秒秒殺口訣卡：MFQ 排程五大特徵
【口訣】新程進頂配額小，超額沉降至底跑；短工速解回饋好，長佇老化抗飢餓
  • 佇列數量：由多個優先權不同的佇列組成。
  • 各層演算法：頂層與中層必為 Round Robin（時間配額由小變大），底層常為 FCFS。
  • 降級條件：耗盡當層時間配額（CPU Bound）。
  • 升級機制：等待時間超過門檻（Aging）或主動讓出 CPU 進行 I/O（I/O Bound）。

第 2 章　虛擬記憶體與分頁機制 (Paging)

記憶體管理的核心目標是「讓每個程式都以為自己擁有連續且巨大的記憶體空間」。

2-1　分頁 (Paging) 的底層轉換

作業系統將邏輯記憶體切成大小相同的分頁 (Page)，並將實體記憶體切成大小相同的頁框 (Page Frame)。Page Size 必須等於 Frame Size（通常為 4KB）。

邏輯位址 (Logical Address) = 分頁號碼 (Page Number, P) + 位移量 (Offset, d)
CPU 發出邏輯位址後，透過查閱分頁表 (Page Table)，將 P 轉換為對應的頁框號碼 (Frame Number, f)，最後與原本的位移量 d 組合，形成實體位址。

2-2　TLB 轉譯後備緩衝區 (Translation Lookaside Buffer)

如果每次記憶體存取都要先查一次主記憶體中的分頁表，速度會慢兩倍。因此硬體中加入了 TLB (一種極高速的關聯式記憶體快取) 來儲存最近查過的分頁紀錄。

情境動作流程耗時
TLB Hit (命中)CPU → 查 TLB → 找到 Frame → 存取實體記憶體極快
TLB Miss (未命中)CPU → 查 TLB 失敗 → 查主記憶體的分頁表 → 更新 TLB → 存取實體記憶體較慢 (需存取記憶體兩次)
🎯 步驟化詳解：TLB 快取與雙層分頁有效存取時間 (EMAT) 數值計算

【國考經典題型】某 32 位元電腦系統採用兩階分頁（Two-level Paging）架構，分頁大小為 4 KB。已知 TLB 查詢時間為 15 ns，主記憶體存取時間為 80 ns。若 TLB 的命中率（Hit Ratio）為 95%，求有效記憶體存取時間（Effective Memory Access Time, EMAT）。

  • 步驟 1剖析 32 位元邏輯位址結構
    ‧ 分頁大小 = 4 KB = $2^{12}$ Bytes → 位移量（Offset, $d$）佔 12 位元。
    ‧ 分頁號碼總位元數 = 32 − 12 = 20 位元。
    ‧ 採兩階分頁：第一階外部頁表（Outer Page, $p_1$）佔 10 位元，第二階頁表（Inner Page, $p_2$）佔 10 位元。
  • 步驟 2分析 TLB 命中 (Hit) 時的存取時間
    當 TLB 命中時，直接自 TLB 取得實體頁框號碼（Frame Number），不需走訪兩階頁表：
    $$T_{\text{hit}} = \text{TLB 查表時間} + \text{實體記憶體存取資料時間} = 15\text{ ns} + 80\text{ ns} = \mathbf{95\text{ ns}}$$
  • 步驟 3分析 TLB 未命中 (Miss) 時的存取時間
    當 TLB 未命中時，硬體必須走訪主記憶體中的頁表：
    ‧ 第 1 次存取記憶體：讀取第一階外部頁表（Outer Page Table）。
    ‧ 第 2 次存取記憶體：讀取第二階頁表（Inner Page Table）取得 Frame Number。
    ‧ 第 3 次存取記憶體：依實體位址讀取真正的資料。
    $$T_{\text{miss}} = \text{TLB 查表時間} + 3 \times \text{記憶體存取時間} = 15 + (3 \times 80) = 15 + 240 = \mathbf{255\text{ ns}}$$
  • 計算代入期望值公式計算 EMAT
    $$\text{EMAT} = \alpha \times T_{\text{hit}} + (1 - \alpha) \times T_{\text{miss}}$$ 代入數值：
    $$\text{EMAT} = 0.95 \times 95\text{ ns} + 0.05 \times 255\text{ ns} = 90.25\text{ ns} + 12.75\text{ ns} = \mathbf{103.0\text{ ns}}$$
  • 驗算若無 TLB 之效能對比驗算
    若完全沒有 TLB 快取，每次記憶體存取皆需 $3 \times 80 = 240\text{ ns}$。具備 95% 命中率的 TLB 讓存取時間大幅降至 103 ns（加速比達 2.33 倍），計算結果完全正確！
⚡ 考前 30 秒秒殺口訣卡：分頁與 TLB EMAT 公式速記
【通式】k 階分頁未命中，查表 k 次取資 1；TLB 命中一次足，百九命中速若飛
  • 單階分頁 Miss：$\text{TLB} + 2 \times \text{Mem}$（1次頁表 + 1次資料）。
  • 兩階分頁 Miss：$\text{TLB} + 3 \times \text{Mem}$（2次頁表 + 1次資料）。
  • $k$ 階分頁 Miss：$\text{TLB} + (k+1) \times \text{Mem}$。

第 3 章　多執行緒與並行處理 (Concurrency)

現代處理器皆為多核心架構，如何善用多執行緒 (Multithreading) 來榨乾 CPU 效能是進階重點。

3-1　行程 (Process) vs 執行緒 (Thread) 深度對比

比較項目行程 (Process)執行緒 (Thread)
資源擁有作業系統分配資源的基本單位CPU 排程的基本單位
記憶體空間互相獨立，有自己的 Code, Data, Heap 段共享所屬行程的 Code, Data, Heap，但有自己獨立的 Stack (堆疊) 與 Register (暫存器)
建立/切換成本極高（需切換記憶體空間與快取）極低（Lightweight Process）
通訊方式 (IPC)需透過 Pipe、Message Queue、Shared Memory直接讀寫共享變數（但需注意同步問題）

3-2　同步與競爭危害 (Race Condition)

當多個執行緒同時讀寫共享變數，且最後的結果取決於執行的順序時，就會發生競爭危害。為解決此問題，作業系統提供了多種同步機制：

同步機制說明與用途
互斥鎖 (Mutex)二元信號標。同一時間只允許一個執行緒進入臨界區間 (Critical Section)。就像是一把公廁的鑰匙，進去後鎖門，出來再還鑰匙。
號誌 (Semaphore)由 Dijkstra 提出，使用一個整數變數 S，支援 wait() (或 P) 與 signal() (或 V) 兩個原子操作。若 S=5，代表有 5 個資源可供存取，常用於生產者-消費者問題。
監視器 (Monitor)一種高階的語言層級同步機制（如 Java 的 synchronized 關鍵字），將共享變數與操作方法封裝起來，保證同一時間只有一個執行緒能執行 Monitor 內的方法。
🎯 步驟化詳解：臨界區間三要件與 Peterson 演算法推導證明

【演算法結構】兩個行程 $P_0$ 與 $P_1$ 共享變數 boolean flag[2]; int turn;。
$P_i$ 的進入區間代碼：flag[i] = true; turn = j; while (flag[j] && turn == j);
離開區間代碼：flag[i] = false;

  • 步驟 1檢驗要件一：互斥 (Mutual Exclusion)
    ‧ 假設兩行程同時處於臨界區間，則必滿足 flag[0] == true 且 flag[1] == true。
    ‧ 觀察其 while 迴圈終止條件：$P_0$ 進入時必有 flag[1] == false 或 turn == 0；$P_1$ 進入時必有 flag[0] == false 或 turn == 1。
    ‧ 由於 turn 為單一變數，在任一瞬間其值只能是 0 或 1，不可能同時為 0 且為 1。
    👉 矛盾成立！雙方絕不可能同時越過 while 迴圈，嚴格滿足互斥性。
  • 步驟 2檢驗要件二：進展 (Progress)
    ‧ 若 $P_1$ 不想進入臨界區間（flag[1] == false），則 $P_0$ 的 while 條件 (flag[1] && turn == 1) 立即為假，$P_0$ 暢行無阻。
    ‧ 若兩者同時想進（flag[0] = flag[1] = true），後賦值給 turn 的行程會覆寫前者的值，將優先權讓給對方（禮讓原則）。故決定權完全由想進入的行程裁定，絕不發生死結，滿足進展性。
  • 步驟 3檢驗要件三：有限等待 (Bounded Waiting)
    ‧ 當 $P_0$ 離開臨界區間時，會執行 flag[0] = false;，這會使卡在 while 迴圈的 $P_1$ 立即脫離等待並進入臨界區間。
    ‧ 即使 $P_0$ 企圖立即重進，它也必須先執行 turn = 1;，再度將機會禮讓給 $P_1$。
    👉 $P_1$ 最多只需等待 $P_0$ 進入一次，保證絕無飢餓現象，滿足有限等待。
  • 驗算死結四大必要條件核對
    作業系統死結（Deadlock）必同時滿足：互斥 (Mutual Exclusion)、持有並等待 (Hold and Wait)、不可搶奪 (No Preemption)、循環等待 (Circular Wait)。任何預防死結的演算法只要打破其中一項即可成功防禦。
⚡ 考前 30 秒秒殺口訣卡：同步臨界區間三要件與死結四條件
【同步三要件】互斥唯一進，進展不卡關，有限等待免飢餓
【死結四要素】互斥握等不搶奪，環形循環鎖終生
  • Peterson 核心技巧：意圖設自己（flag[i]=true），謙虛讓對方（turn=j）。
  • Semaphore 核心操作：$P(S)$（Wait，資源數減一，若 < 0 則睡眠阻塞）；$V(S)$（Signal，資源數加一，若 ≤ 0 則喚醒等待者）。

第 4 章　雲端運算與分散式系統

4-1　雲端服務模式 (SaaS, PaaS, IaaS)

服務模式說明例子
IaaS (基礎設施即服務)提供虛擬主機、儲存空間。使用者需自己裝 OS 與應用程式。AWS EC2, Google Compute Engine
PaaS (平台即服務)提供開發與執行環境 (如資料庫、執行環境)。使用者只需上傳程式碼。Google App Engine, Heroku
SaaS (軟體即服務)提供完整的軟體應用，透過瀏覽器即可使用。Gmail, Microsoft 365, Dropbox

4-2　分散式系統的 CAP 定理

在設計分散式資料庫（如 NoSQL）時，無法同時完美滿足以下三個屬性，最多只能「三選二」：

屬性意義
一致性 (Consistency)每次讀取都能取得最新的資料，或者讀取失敗。所有節點在同一時間看到的資料必須一模一樣。
可用性 (Availability)每個非故障的節點，都能保證對每個請求給出非錯誤的回應（但不保證是最新資料）。
分區容忍性 (Partition Tolerance)即使節點之間的網路斷線（分成多個孤島），系統仍能繼續運作。
⚠️ 實務選擇 因為網路斷線 (P) 是常態且無法避免，所以系統通常在 CP (一致性優先，如銀行轉帳) 或 AP (可用性優先，如社群貼文) 之間做取捨。
AP 系統通常依賴「最終一致性 (Eventual Consistency)」來彌補一致性的妥協。
🎯 步驟化詳解：CAP 定理網路分區與 Raft 演算法多數決 (Quorum) 推導

【分散式情境】由 5 台伺服器節點 ($N_1 \sim N_5$) 組成的 Raft 叢集，突然發生網路分區斷線，被分割成兩邊：分區 A 含 $\{N_1, N_2, N_3\}$，分區 B 含 $\{N_4, N_5\}$。

  • 步驟 1計算多數決法定人數 (Quorum Majority)
    ‧ 法定多數門檻公式：$Q = \lfloor N / 2 \rfloor + 1$。
    ‧ 對於 5 節點叢集：$Q = \lfloor 5 / 2 \rfloor + 1 = 2 + 1 = \mathbf{3}$ 個節點。
  • 步驟 2評估分區 A 之行為（一致性保障）
    分區 A 擁有 3 個節點，剛好達到 Quorum 門檻（$3 \ge 3$）：
    ‧ 分區 A 能順利選出 Leader 並繼續接收寫入（Write Request）。
    ‧ 每次日誌複製獲得 3 票同意即可完成 Commit，系統保持正常讀寫。
  • 步驟 3評估分區 B 之行為（避免腦裂 Split-Brain）
    分區 B 僅剩 2 個節點，未達 Quorum 門檻（$2 < 3$）：
    ‧ 分區 B 的節點即使發起選舉也絕不可能獲得 3 票，無法產生 Leader。
    ‧ 分區 B 若收到寫入請求，必須拒絕寫入或報錯 (Fail)。這是典型的 CP 系統行為（寧可犧牲可用性，也絕不允許雙頭寫入造成資料分歧）。
  • 驗算網路復原後的日誌對齊 (Reconciliation)
    當網路分區修復時，分區 B 節點發現分區 A 具有更高的任期編號 (Term)，會自動降為 Follower 並以分區 A 的 Leader 日誌覆寫自身未提交之日誌，系統無縫回歸一致性狀態。

雲端架構之所以能快速擴展，依賴底層的隔離技術。近年來，Docker 等容器技術大幅取代了傳統虛擬機。

技術Hypervisor 虛擬機 (VM)容器 (Container, 如 Docker)
隔離層級硬體層級的虛擬化作業系統 (OS) 層級的虛擬化
Guest OS每個 VM 都要安裝一個完整的客體作業系統 (如 Windows/Ubuntu)沒有 Guest OS，直接共用宿主機 (Host) 的 Linux 核心
啟動速度慢 (數分鐘，需開機)極快 (數秒以內)
資源占用巨大 (數 GB)極小 (數十 MB)
用途需要完全隔離的安全環境、執行不同 OS 系統微服務架構 (Microservices)、CI/CD 持續整合部署

第 5 章　最前沿科技 (邊緣運算與量子電腦)

隨著物聯網 (IoT) 與大數據的發展，傳統將所有資料送回雲端處理的架構已經面臨瓶頸。

5-1　邊緣運算 (Edge Computing)

將運算能力從「雲端中心」推移到靠近資料產生來源的「邊緣設備」（如智慧攝影機、自駕車、工廠感測器）。

優勢為什麼需要它？
極低延遲 (Low Latency)自駕車如果看到行人，把影像傳回雲端等 AI 判斷再傳回來煞車，車早就撞上去了。邊緣運算能在車上的電腦「瞬間」決定煞車。
節省頻寬 (Bandwidth)工廠的幾千台攝影機如果 24 小時把 4K 畫面全傳上雲端，網路會癱瘓。透過邊緣 AI，攝影機只把「異常畫面」回傳，省下巨量頻寬。
提升隱私與資安病患的醫療監測資料在本地端設備直接分析，不傳輸上網，降低被駭客半路攔截的風險。

5-2　量子電腦 (Quantum Computing) 基礎

量子電腦不是「算得更快的傳統電腦」，它是一種利用量子物理現象（量子疊加、量子糾纏）來進行運算的全新架構。

核心概念說明 (高中物理/常識比喻)
量子位元 (Qubit)傳統位元只能是 0 或 1（就像硬幣的正面或反面）。量子位元則處於 0 和 1 的疊加態 (Superposition)（就像旋轉中的硬幣，同時具備正反面的機率）。
量子霸權 (Quantum Supremacy)當量子電腦能解決「傳統超級電腦需要幾萬年才能算完」的特定問題時，就達到了量子霸權（例如 2019 年 Google 的 Sycamore 處理器）。
資安威脅 (Shor's Algorithm)目前全球網路最仰賴的 RSA 非對稱加密（利用大質數分解極難的特性），未來可能被量子電腦在幾秒內破解。因此目前全球密碼學界正在積極研發 「後量子密碼學 (PQC)」。
🎯 步驟化詳解：Shor 演算法因數分解複雜度降階與後量子密碼 (PQC) 轉移
  • 步驟 1傳統電腦破解 RSA 的瓶頸（次指數時間）
    目前傳統電腦最佳的大整數質因數分解演算法為普通數篩法（General Number Field Sieve, GNFS），其時間複雜度為次指數階： $$O\left(\exp\left(c \cdot (\ln N)^{1/3} (\ln \ln N)^{2/3}\right)\right)$$ 對於 RSA-2048，傳統超級電腦需要運算數萬年至上百萬年方可破解。
  • 步驟 2Shor 量子演算法降階原理（多項式時間）
    Shor 演算法巧妙地將質因數分解問題轉化為求模幕週期問題（Order Finding）：
    ‧ 利用量子疊加態同時計算所有可能的幕次。
    ‧ 利用量子傅立葉轉換（Quantum Fourier Transform, QFT）引發建設性干涉，直接抽出函數週期 $r$。
    ‧ 計算複雜度直接被驟降至多項式時間：$O((\log N)^3)$！RSA-2048 在足夠量子位元的量子電腦上僅需數秒至數分鐘。
  • 步驟 3對稱式金鑰的影響：Grover 演算法（平方加速）
    Grover 搜尋演算法可將暴力破解對稱金鑰的時間從 $O(2^n)$ 降為 $O(2^{n/2})$。
    👉 對策：只需將對稱加密金鑰長度加倍（例如由 AES-128 提升至 AES-256），即可確保在量子時代依然安全。
  • 驗算後量子密碼 (PQC) 防禦藍圖
    NIST 於 2022 年公布後量子密碼標準化首批名單：主要採用晶格密碼學 (Lattice-based Cryptography)：
    ‧ 金鑰封裝機制 (KEM)：CRYSTALS-Kyber（現改稱 ML-KEM）。
    ‧ 數位簽章：CRYSTALS-Dilithium（現改稱 ML-DSA）與 SPHINCS+。
    晶格問題（如最短向量問題 SVP）即使使用量子電腦也無法在多項式時間求解，是未來資訊系統升級的必考熱點！
