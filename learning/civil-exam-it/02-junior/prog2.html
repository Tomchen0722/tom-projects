程式設計概要 (進階)

給想拿 80 分以上的高手。本篇專注於進階資料結構實作、動態規劃 (DP)、物件導向設計原則 (SOLID) 以及安全程式設計。
掌握這些進階觀念，在面對申論題的「程式碼改寫」與「效能最佳化」題型時將游刃有餘。

📑 進階目錄
  1. 物件導向設計原則 (SOLID)
  2. 進階資料結構實作 (Linked List & Tree)
  3. C/C++ 指標與記憶體管理深度解析
  4. 安全程式設計 (Secure Coding)
  5. 最新程式技術趨勢 (AI 與無伺服器)

第 1 章　物件導向設計原則 (SOLID)

物件導向 (OOP) 的三大基礎是封裝、繼承、多型。而在系統架構設計上，考題常會要求解釋 SOLID 五大原則，這是寫出可維護程式碼的核心指引。

1-1　SOLID 五大原則剖析

原則名稱英文全稱核心精神與範例說明
單一職責原則 (SRP)Single Responsibility Principle「一個類別只負責一件事，只有一個改變的理由。」
反例：一個 Order 類別同時負責計算金額、存入資料庫、還負責寄 Email。
正解：拆分成 OrderCalculator、OrderRepository、EmailSender。
開閉原則 (OCP)Open/Closed Principle「對擴充開放，對修改封閉。」
當有新需求時，應該「新增」程式碼，而不是去「修改」舊的程式碼。
作法：透過介面 (Interface) 或抽象類別 (Abstract Class) 搭配多型來實作。
里氏替換原則 (LSP)Liskov Substitution Principle「子類別必須能夠完全替換掉父類別，且程式行為不變。」
經典反例：正方形繼承長方形。如果父類別 Rectangle 有 setWidth 和 setHeight，子類別 Square 改寫後會破壞長寬獨立的預期行為。
介面隔離原則 (ISP)Interface Segregation Principle「用戶端不應該被迫依賴它不使用的方法。」
與其寫一個包含十個方法的龐大 IWorker 介面，不如拆成 IWorkable 和 IFeedable。機器人實作 IWorkable，不需要被迫實作「吃飯」的方法。
依賴反轉原則 (DIP)Dependency Inversion Principle「高階模組不應依賴低階模組，兩者都應依賴抽象；抽象不應依賴細節，細節應依賴抽象。」
這是控制反轉 (IoC) 的基礎。類別不應該直接 new MySQLDatabase()，而是依賴 IDatabase 介面，再透過依賴注入 (DI) 傳入實體。
💡 考前破題技巧 如果題目問：「請說明何謂多型 (Polymorphism) 並舉例說明其優點？」
答題結構：
1. 定義：相同的訊息發送給不同的物件，會引發不同的行為。
2. 程式碼範例：定義 Animal 介面的 speak()，Dog 實作汪汪，Cat 實作喵喵。
3. 優點與結合 SOLID：強調多型是實現 開閉原則 (OCP) 的關鍵，未來若新增 Bird，完全不需要修改呼叫端 (Client) 的程式碼。

第 2 章　進階資料結構實作

普考雖然偏重陣列，但近年來對於「鏈結串列 (Linked List)」與「二元樹 (Binary Tree)」的實作要求逐漸增加，尤其是在 C 語言的指標操作上。

2-1　單向鏈結串列 (Singly Linked List) 反轉

這是一道極高頻的經典面試與考試題，考驗對指標操作的掌握度。

// 定義節點結構
struct Node {
    int data;
    struct Node* next;
};

// 反轉鏈結串列的函式
struct Node* reverseList(struct Node* head) {
    struct Node* prev = NULL;    // 前一個節點
    struct Node* curr = head;    // 當前節點
    struct Node* nextTemp = NULL; // 暫存下一個節點
    
    while (curr != NULL) {
        nextTemp = curr->next;   // 1. 先記住下一個是誰，避免斷鏈
        curr->next = prev;       // 2. 反轉：把當前的 next 指向前面
        prev = curr;             // 3. prev 往前挪一步
        curr = nextTemp;         // 4. curr 往前挪一步
    }
    return prev;                 // 新的 head 是原本的最後一個節點
}

2-2　二元搜尋樹 (BST) 的走訪

樹的走訪分為前序、中序、後序。若要將 BST 的節點「由小到大」印出，必須使用中序走訪 (Inorder Traversal)。

// 中序走訪：左 -> 中 -> 右
void inorderTraversal(struct TreeNode* root) {
    if (root == NULL) return;
    
    inorderTraversal(root->left);       // 走訪左子樹
    printf("%d ", root->data);         // 處理當前節點 (印出)
    inorderTraversal(root->right);      // 走訪右子樹
}

第 3 章　C/C++ 指標與記憶體管理深度解析

指標 (Pointer) 是 C 語言的靈魂，也是考試最容易失分的地方。指標本質上就是一個「儲存記憶體位址的變數」。

3-1　指標與陣列的關係

在 C 語言中，陣列名稱本身就是一個指標，指向陣列的第一個元素。

int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;  // p 指向 arr[0]

printf("%d\n", *p);       // 印出 10
printf("%d\n", *(p + 2)); // 指標加法：位址前進 2 個 int 的空間，印出 30
printf("%d\n", p[2]);     // 等同於 *(p + 2)，印出 30

3-2　動態記憶體配置 (Dynamic Memory Allocation)

靜態陣列必須在編譯時決定大小（如 int a[100];）。若要在執行時根據使用者輸入來決定陣列大小，必須使用 malloc() (C語言) 或 new (C++)，配置在 Heap（堆積）區塊中。

⚠️ 記憶體洩漏 (Memory Leak) 使用動態配置的記憶體，作業系統不會自動回收。如果程式碼沒有呼叫 free() (或 delete) 把空間還給作業系統，程式跑久了就會把記憶體吃光導致當機。 
// 動態產生一個大小為 n 的整數陣列
int n = 10;
int *ptr = (int*) malloc(n * sizeof(int));

if (ptr == NULL) {
    printf("記憶體配置失敗\n");
    return 1;
}

// 使用 ptr...

free(ptr); // 用完務必釋放記憶體！
ptr = NULL; // 避免迷途指標 (Dangling Pointer)

第 4 章　遞迴進階與動態規劃 (DP)

傳統的遞迴往往因為「重複計算」導致效能極差（如樸素的費氏數列為 $O(2^n)$）。動態規劃 (Dynamic Programming, DP) 的核心概念就是「用空間換取時間」——將計算過的子問題答案記錄下來，避免重複計算。

4-1　自頂向下 (Top-Down)：記憶化搜索 (Memoization)

// 使用陣列 memo 記錄算過的結果，初始化為 -1
int memo[100]; 
int fib_memo(int n) {
    if (n <= 1) return n;
    // 如果算過，直接查表回傳，時間複雜度降為 O(n)
    if (memo[n] != -1) return memo[n];
    
    memo[n] = fib_memo(n-1) + fib_memo(n-2);
    return memo[n];
}

4-2　自底向上 (Bottom-Up)：表格法 (Tabulation)

DP 的另一種寫法，直接用迴圈從最小的問題開始推導，甚至可以不使用遞迴函式呼叫，效能更好且不會發生 Stack Overflow。

int fib_dp(int n) {
    if (n <= 1) return n;
    int dp[n+1];
    dp[0] = 0;
    dp[1] = 1;
    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i-1] + dp[i-2];
    }
    return dp[n];
}

考點提示：如果題目要求「請寫出一個效能為 $O(n)$ 的費氏數列演算法」，請務必寫出上述的 DP 迴圈寫法。

第 5 章　安全程式設計與例外處理

在資安法規日益嚴格的今天，「安全程式設計 (Secure Coding)」已成為國考的新考點，常與 OWASP Top 10 結合出題。

5-1　防禦 SQL 注入 (SQL Injection)

駭客在輸入欄位輸入 ' OR '1'='1' --，若程式直接使用字串拼接組成 SQL 語法，會導致密碼驗證被繞過。唯一的防禦正解是「參數化查詢 (Parameterized Query) / 預備語句 (Prepared Statement)」。

❌ 錯誤寫法 (字串拼接)✅ 正確寫法 (參數化查詢)
String query = "SELECT * FROM users 
WHERE account='" + user + "' 
AND pwd='" + pass + "'";
// 駭客可輕易竄改語意
 
String query = "SELECT * FROM users 
WHERE account = ? AND pwd = ?";
PreparedStatement pstmt = conn.prepareStatement(query);
pstmt.setString(1, user);
pstmt.setString(2, pass);
// 資料庫引擎會將輸入嚴格視為「字串值」

5-2　例外處理 (Exception Handling)

程式執行過程中可能會發生預期之外的錯誤（如除以零、檔案找不到、網路斷線）。使用 try-catch-finally 區塊可以優雅地處理錯誤，而不是讓程式直接當機。

// Java 或 C# 範例
try {
    // 可能會發生錯誤的危險程式碼
    int result = 10 / 0; 
} catch (ArithmeticException e) {
    // 捕捉到特定錯誤時的處置方案
    System.out.println("發生數學錯誤：" + e.getMessage());
} catch (Exception e) {
    // 捕捉其他未知的錯誤
    System.out.println("發生未知錯誤");
} finally {
    // 無論是否發生錯誤，finally 區塊「一定會執行」
    // 常做為釋放資源、關閉資料庫連線的地方
    System.out.println("清理資源");
}

考點提示：考題常問「finally 區塊的功用為何？」標準答案是：確保無論程式是否拋出例外，關鍵的資源釋放工作（如關閉檔案、關閉資料庫連線）都絕對會被執行，避免資源洩漏 (Resource Leak)。
