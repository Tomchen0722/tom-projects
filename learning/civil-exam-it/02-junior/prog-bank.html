A. 基本概念與運算子（1～10 題）

1概念
下列何者屬於「直譯式」程式語言？
  • (A) C　(B) C++　(C) Python　(D) Go
詳解
答案：(C) Python
類型特性代表
編譯式整份翻譯成執行檔，執行快C、C++、Go
直譯式逐行翻譯執行，跨平台、開發快Python、JavaScript
混合式編譯成中間碼由虛擬機執行Java（bytecode+JVM）、C#
2運算
C 語言中，17 % 5 與 17 / 5 的結果分別為？
  • (A) 2, 3　(B) 3, 2　(C) 2, 3.4　(D) 3.4, 2
詳解
答案：(A) 2, 3
‧ 17 % 5 = 餘數 2（17 = 5×3 + 2）
‧ 17 / 5 = 3（整數除法會截斷小數，不是 3.4）

要得到 3.4 需寫 17.0 / 5 或 (float)17 / 5。
這是最高頻的陷阱——計算平均時忘記轉型，結果全部變整數。
3運算
執行下列程式後，a 與 b 的值分別為？
int a = 5; int b = a++;
  • (A) a=5, b=5　(B) a=6, b=5　(C) a=6, b=6　(D) a=5, b=6
詳解
答案：(B) a=6, b=5
後置 a++：先把 a 目前的值（5）給 b，a 才變成 6。

對照前置：int b = ++a; → a 先變 6，再給 b → a=6, b=6

口訣：++ 在前面就「先」加，在後面就「後」加。
4運算
下列運算式的結果為？
int x = 10; x += 5; x *= 2; x -= 10;
  • (A) 10　(B) 20　(C) 25　(D) 30
詳解
答案：(B) 20
步驟等同於x 的值
初始—10
x += 5x = 10 + 515
x *= 2x = 15 × 230
x -= 10x = 30 − 1020
提醒：複合指定運算子一律「先算右邊，再把結果放回左邊」，要逐步追蹤不要跳算。
5運算
關於 C 語言的短路求值，下列敘述何者正確？
  • (A) A && B 中若 A 為假，B 仍會被執行
  • (B) A || B 中若 A 為真，B 不會被執行
  • (C) 短路求值只適用於 ||
  • (D) C 語言沒有短路求值
詳解
答案：(B)
‧ A && B：A 為假 → 結果必為假 → B 不執行
‧ A || B：A 為真 → 結果必為真 → B 不執行

實務應用：if (p != NULL && p->value > 0)
先確認指標非 NULL 才存取它，避免程式當掉。順序寫反就會出錯——這是很重要的防禦式寫法。
6型別
下列關於浮點數的敘述，何者正確？
  • (A) 浮點數可精確表示所有小數
  • (B) 0.1 + 0.2 == 0.3 在多數語言中為真
  • (C) 金額計算應使用浮點數以提高精確度
  • (D) 比較浮點數應判斷差的絕對值是否小於極小值
詳解
答案：(D)
0.1 在二進位是無限循環小數，只能存近似值 → 0.1+0.2 常得 0.30000000000000004。

正確比較法：if (fabs(a - b) < 0.000001)

(C) 剛好講反：金額絕對不可用浮點數，應用整數（以「分」為單位）或 DECIMAL 型別。
機關的計費、稅額系統用浮點數會出現「差一分錢」的民眾申訴。
7型別
C 語言中，char c = 'A'; c = c + 32; 之後 c 的值為？
  • (A) 'a'　(B) 'B'　(C) 97 但無法顯示　(D) 語法錯誤
詳解
答案：(A) 'a'
'A' 的 ASCII 是 65，65 + 32 = 97，而 97 正是 'a'。

必背三組：'0'=48、'A'=65、'a'=97
推論：大寫 + 32 = 小寫；字元 − '0' = 該數字（'7' − '0' = 7）。

在 C 語言中 char 本質就是小整數，可直接參與算術運算。
8判斷
下列程式在 score = 95 時會輸出什麼？
if (score >= 70) printf("乙"); else if (score >= 80) printf("甲"); else if (score >= 90) printf("優");
  • (A) 優　(B) 甲　(C) 乙　(D) 優甲乙
詳解
答案：(C) 乙
if-else if 只執行「第一個成立」的分支。95 首先符合 score >= 70，印出「乙」後就結束，後面的條件根本不會被檢查。

正確寫法：範圍判斷要由「嚴格到寬鬆」排序： 
if (score >= 90) printf("優");
else if (score >= 80) printf("甲");
else if (score >= 70) printf("乙");
這是追蹤題最愛設的陷阱。
9判斷
下列 switch 程式在 x = 2 時的輸出為？
switch(x){ case 1: printf("A"); case 2: printf("B"); case 3: printf("C"); break; default: printf("D"); }
  • (A) B　(B) BC　(C) BCD　(D) ABC
詳解
答案：(B) BC
x = 2 → 進入 case 2 印出 B → 沒有 break，繼續往下貫穿 → case 3 印出 C → 遇到 break 才跳出。

所以輸出 BC（不會執行 default，因為已被 break 跳出）。

break 貫穿（Fall-through）是超高頻考點。有時是刻意設計： 
case 1:
case 2:
case 3:
    printf("上半年");  // 1、2、3 都執行
    break;
10判斷
判斷閏年的正確條件為？
  • (A) year % 4 == 0
  • (B) year % 4 == 0 && year % 100 == 0
  • (C) (year%4==0 && year%100!=0) || year%400==0
  • (D) year % 400 == 0
詳解
答案：(C)
規則：能被 4 整除但不能被 100 整除；或能被 400 整除。
年份%4%100%400結果
20240 ✔≠0 ✔—閏年
19000 ✔0 ✘≠0 ✘平年
2000000 ✔閏年
(A) 會誤判 1900 為閏年。驗證條件式的最快方法就是代 1900 與 2000 兩個特例。

B. 迴圈與追蹤（11～22 題）

11迴圈
for (i = 0; i < 5; i++) 迴圈本體會執行幾次？
  • (A) 4　(B) 5　(C) 6　(D) 無限次
詳解
答案：(B) 5 次（i = 0, 1, 2, 3, 4）

次數計算公式：for (i = a; i < b; i++) 執行 b − a 次；
for (i = a; i <= b; i++) 執行 b − a + 1 次。

陣列走訪一律用 < 不用 <=——用 <= 會越界，這是最高頻的 bug。
12迴圈
下列程式的輸出為？
int s=0; for(i=1;i<=5;i++){ if(i%2==0) continue; s+=i; } printf("%d",s);
  • (A) 6　(B) 9　(C) 15　(D) 10
詳解
答案：(B) 9
ii%2==0?動作s
1否s += 11
2是continue（跳過）1
3否s += 34
4是continue4
5否s += 59
即 1 + 3 + 5 = 9（只累加奇數）。

continue = 跳過這一輪；break = 跳出整個迴圈。
13迴圈
下列程式的輸出為？
int s=0; for(i=1;i<=10;i++){ if(i>4) break; s+=i; } printf("%d",s);
  • (A) 6　(B) 10　(C) 15　(D) 55
詳解
答案：(B) 10
i=1,2,3,4 時累加（1+2+3+4 = 10）；i=5 時 i > 4 成立 → break 跳出，5 沒有被加。

陷阱：判斷寫在累加之前，所以 i=5 這一輪 s += i 不會執行。
若把 break 判斷移到累加之後，答案就會變成 15——敘述順序決定結果。

下列巢狀迴圈中 printf 共執行幾次？
for(i=1;i<=4;i++) for(j=1;j<=i;j++) printf("*");
  • (A) 4　(B) 8　(C) 10　(D) 16
詳解
答案：(C) 10
i內層執行次數（j 從 1 到 i）
11

合計 1+2+3+4 = 10
注意內層條件是 j <= i（不是固定值）——這是印三角形的標準寫法。
若內層是 j <= 4，答案才是 4×4 = 16。

16迴圈
下列程式的輸出為？
int n=1234, r=0; while(n>0){ r=r*10+n%10; n/=10; } printf("%d",r);
  • (A) 10　(B) 1234　(C) 4321　(D) 24
詳解
答案：(C) 4321（反轉數字）
輪次nn%10r = r*10 + n%10

17迴圈
下列程式碼會發生什麼？
int i=1; while(i<=5){ printf("%d",i); }
  • (A) 印出 12345　(B) 印出 1 一次　(C) 無窮迴圈，一直印 1　(D) 語法錯誤
詳解
答案：(C) 無窮迴圈
迴圈本體內沒有 i++，i 永遠是 1，條件 i <= 5 永遠成立。

while 迴圈的三要素缺一不可：
① 迴圈外初始化（i = 1）
② 判斷條件（i <= 5）
③ 迴圈內更新變數（i++）← 最常忘記的一項

for 迴圈把三者寫在同一行，比較不會漏——這也是已知次數時建議用 for 的原因。
18迴圈
下列程式的時間複雜度為？
for(i=1;i<=n;i++) for(j=1;j<=n;j*=2) count++;
  • (A) O(n)　(B) O(n log n)　(C) O(n²)　(D) O(log n)
詳解
答案：(B) O(n log n)
‧ 外層 i++ → n 次
‧ 內層 j *= 2 → j 走 1, 2, 4, 8… → log₂n 次

核心觀念：看迴圈變數怎麼「變」，不是看有幾層。
j++ → 線性 O(n)｜j *= k 或 j /= k → 對數 O(log n)

看到雙層迴圈就答 O(n²) 是最常見的錯誤。

關於 do-while 迴圈，下列敘述何者正確？
  • (A) 條件不成立時完全不執行
  • (B) 至少執行一次
  • (C) 與 while 完全相同
  • (D) 不能使用 break
詳解
答案：(B) 至少執行一次
因為 do-while 是先執行、後判斷。
迴圈判斷時機最少執行典型用途
for / while先判斷0 次一般迴圈
do-while後判斷1 次選單、至少要輸入一次的情境
20迴圈
判斷 n 是否為質數時，迴圈檢查範圍取到 √n 的原因為？
  • (A) 節省記憶體
  • (B) 若 n = a×b 且 a ≤ b，則 a 必 ≤ √n，故超過 √n 不會有新因數
  • (C) √n 之後的數字不是整數
  • (D) 這是錯誤的做法
詳解
答案：(B)
若 n 有因數，必可寫成 n = a × b。假設 a ≤ b，則 a ≤ √n。
所以若在 2～√n 間找不到因數，√n 之後也一定找不到（那些因數的「另一半」早就被檢查過了）。

效益：複雜度由 O(n) 降為 O(√n)——n = 1,000,000 時，檢查次數由 100 萬降為 1000 次。

寫法：for (i = 2; i * i <= n; i++)（用乘法避免開根號的浮點誤差）。

輾轉相除法求 gcd(48, 18) 的結果為？

詳解
答案：(C) 6

460→ 迴圈結束
b 變成 0 時，a 就是答案。

C. 陣列與字串（23～30 題）

23陣列
宣告 int a[10];，合法的索引範圍為？
  • (A) 1 ~ 10　(B) 0 ~ 10　(C) 0 ~ 9　(D) 1 ~ 9
詳解
答案：(C) 0 ~ 9
C 語言陣列索引從 0 開始；宣告 10 個元素，索引就是 0~9，沒有 a[10]。

存取 a[10] 會越界——C 語言不會報錯，但會讀到不屬於這個陣列的記憶體（垃圾值），或造成程式當掉，甚至形成緩衝區溢位的資安漏洞。

因此陣列迴圈一律寫 for (i = 0; i < n; i++)，用 < 不用 <=。
24陣列
要反轉一個長度為 n 的陣列，迴圈應執行幾次？
  • (A) n　(B) n−1　(C) n/2　(D) 2n
詳解
答案：(C) n/2 
for (i = 0; i < n/2; i++) {
    int t = a[i];
    a[i] = a[n-1-i];
    a[n-1-i] = t;
}
為什麼只跑一半：每次交換同時處理兩個元素（前面一個、後面一個）。
若跑完 n 次，等於每對元素被交換兩次 → 又轉回原狀。

同樣的道理也用在判斷回文：只需比較前半段與後半段對應位置。
25陣列
求陣列最大值的正確寫法為？
  • (A) max=0; for(i=0;i<n;i++) if(a[i]>max) max=a[i];
  • (B) max=a[0]; for(i=1;i<n;i++) if(a[i]>max) max=a[i];
  • (C) max=a[n]; for(i=0;i<n;i++) if(a[i]>max) max=a[i];
  • (D) for(i=0;i<n;i++) max=a[i];
詳解
答案：(B)
正確做法：先假設第一個元素最大，再從第二個開始比較。

為什麼 (A) 錯：若陣列全部都是負數（如 −5, −3, −8），max 初值 0 永遠不會被更新 → 錯誤回傳 0。
這是很經典的邊界條件陷阱。

(C) 錯：a[n] 已越界。
(D) 錯：這是把 max 一直覆蓋成每個元素，最後等於最後一個元素。
26陣列
二維陣列 int m[3][4] 共有幾個元素？其中 m[2][3] 是第幾個元素（以列優先計算，從 1 起算）？
  • (A) 12 個，第 11 個　(B) 12 個，第 12 個　(C) 7 個，第 12 個　(D) 12 個，第 10 個
詳解
答案：(B) 12 個，第 12 個
總元素數 = 3 × 4 = 12 
列 0: m[0][0] m[0][1] m[0][2] m[0][3]   ← 第 1~4 個
列 1: m[1][0] m[1][1] m[1][2] m[1][3]   ← 第 5~8 個
列 2: m[2][0] m[2][1] m[2][2] m[2][3]   ← 第 9~12 個
m[2][3] 是最後一個 = 第 12 個。

公式：列優先時，m[i][j] 的序號（從 0 起算）= i × 行數 + j = 2×4 + 3 = 11（從 1 起算即第 12 個）。
27字串
C 語言中 char s[] = "Hello"; 實際佔用幾個 bytes？
  • (A) 5　(B) 6　(C) 10　(D) 依編譯器而定
詳解
答案：(B) 6
'H','e','l','l','o' 共 5 個字元，加上結束字元 '\0' 共 6 bytes。

但 strlen(s) 回傳 5（不含 '\0'）——「佔用空間」與「字串長度」是兩個不同的數字，常被混淆。

重要陷阱：若寫 char s[5] = "Hello"; → 沒有空間放 '\0' → 字串函式會一直往後讀垃圾資料 → 緩衝區溢位。
28字串
判斷兩個 C 字串是否相同，正確寫法為？
  • (A) if (s1 == s2)
  • (B) if (strcmp(s1, s2))
  • (C) if (strcmp(s1, s2) == 0)
  • (D) if (strlen(s1) == strlen(s2))
詳解
答案：(C)
strcmp 相等時回傳 0（很反直覺），所以必須明確寫 == 0。

‧ (A) 錯：== 比的是記憶體位址，不是內容
‧ (B) 錯：意義剛好相反——strcmp 回傳非 0（真）表示不相等
‧ (D) 錯：長度相同不代表內容相同（"abc" 與 "xyz"）

這是超高頻的陷阱題。
29字串
下列程式的功能為？
for(i=0; s[i]!='\0'; i++) if(s[i]>='A' && s[i]<='Z') s[i]+=32;
  • (A) 小寫轉大寫　(B) 大寫轉小寫　(C) 計算長度　(D) 反轉字串
詳解
答案：(B) 大寫轉小寫
條件 s[i] >= 'A' && s[i] <= 'Z' 判斷是否為大寫；+32 即轉為小寫（'A'=65 → 'a'=97）。

反向（小寫轉大寫）：判斷 >='a' && <='z'，然後 −32。

注意迴圈條件是 s[i] != '\0'——利用字串結束字元判斷何時停止，這是走訪 C 字串的標準寫法。
30字串
判斷字串是否為回文（如 "level"），核心比較條件為？
  • (A) s[i] == s[i+1]
  • (B) s[i] == s[len-i]
  • (C) s[i] == s[len-1-i]
  • (D) s[i] == s[0]
詳解
答案：(C) s[i] == s[len-1-i]
因為最後一個元素的索引是 len−1（不是 len）。

索引:  0  1  2  3  4
字元:  l  e  v  e  l

i=0 → 比 s[0] 與 s[4] → 'l' == 'l' ✔
i=1 → 比 s[1] 與 s[3] → 'e' == 'e' ✔
（i 只需跑到 len/2 = 2）
(B) 的 s[len-i] 在 i=0 時會存取 s[5] → 越界。
這正是「差一錯誤（Off-by-one）」的典型。

詳解

‧ 線性搜尋 O(n)：不需排序
‧ 二分搜尋 O(log n)：需先排序（排序本身要 O(n log n)）

40除錯
下列程式片段有何錯誤？
int a[5]; for(i=0; i<=5; i++) a[i]=i;
  • (A) 語法錯誤，無法編譯
  • (B) 陣列越界，a[5] 不存在
  • (C) 無窮迴圈
  • (D) 沒有錯誤
詳解
答案：(B) 陣列越界（差一錯誤 Off-by-one）
int a[5] 的合法索引是 0~4；i <= 5 會讓 i 跑到 5，存取 a[5] → 越界。

口訣：陣列迴圈用 < 不用 <=。

📝 (一) 氣泡排序

思路：相鄰兩元素比較，若前者大於後者即交換。每一回合結束後，最大值會「浮」到最後並固定，故內層迴圈可逐次縮短。

int i, j, temp;

for (i = 0; i < n - 1; i++) {              // 共需 n-1 回合
    for (j = 0; j < n - 1 - i; j++) {      // -i：後面已排好不必再比
        if (a[j] > a[j + 1]) {             // 前大於後即交換
            temp   = a[j];
            a[j]   = a[j + 1];
            a[j+1] = temp;
        }
    }
}

第 1 回合：5>2 換 → 5>8 不換 → 8>1 換 → 2,5,1,8
第 2 回合：2>5 不換 → 5>1 換 → 2,1,5,8

📝 (二) 改良：提早結束

思路：若某一回合完全沒有發生交換，代表資料已排序完成，可提早跳出。

for (i = 0; i < n - 1; i++) {
    int swapped = 0;                       // 旗標：本回合是否有交換
    for (j = 0; j < n - 1 - i; j++) {
        if (a[j] > a[j + 1]) {
            temp = a[j]; a[j] = a[j+1]; a[j+1] = temp;
            swapped = 1;
        }
    }
    if (swapped == 0) break;               // 沒交換 → 已排序完成
}

效果：資料已排序時，第一回合掃描完即發現無交換而跳出 → 僅需 n−1 次比較 → 最佳情況 O(n)。

項目傳值 Call by Value傳址 Call by Reference

能否改變原變數不能能

// 【傳值】改不到原變數
void byValue(int x) {

}

// 【傳址】可以改到原變數

    return gcd(b, a % b);       // 遞迴關係
}

驗算 gcd(48, 18)： 

gcd(48, 18) → gcd(18, 48%18=12)
            → gcd(12, 18%12=6)
            → gcd(6, 12%6=0)
            → b==0，回傳 6 ✔
延伸：最小公倍數 lcm(a,b) = a / gcd(a,b) * b（先除再乘可避免溢位）。

📝 (二) 河內塔

思路：要把 n 個盤子從起點柱搬到目標柱，可分三步：
① 先把上面 n−1 個搬到中繼柱　② 把最大的第 n 個搬到目標柱　③ 再把 n−1 個從中繼柱搬到目標柱

void hanoi(int n, char from, char to, char via) {
    if (n == 1) {                          // 終止條件
        printf("移動盤子 1: %c -> %c\n", from, to);
        return;
    }
    hanoi(n - 1, from, via, to);           // ① n-1 個搬到中繼柱
    printf("移動盤子 %d: %c -> %c\n", n, from, to);  // ② 搬最大的
    hanoi(n - 1, via, to, from);           // ③ n-1 個搬到目標柱
}

// 呼叫：hanoi(3, 'A', 'C', 'B');  從 A 搬到 C，B 為中繼

n = 3 的輸出（共 7 步）： 

盤1: A→C    盤2: A→B    盤1: C→B
盤3: A→C
盤1: B→A    盤2: B→C    盤1: A→C

📐 移動次數推導 設 T(n) 為搬 n 個盤子所需次數：
T(n) = T(n−1) + 1 + T(n−1) = 2·T(n−1) + 1，T(1) = 1

展開：T(n) = 2ⁿ⁻¹ + 2ⁿ⁻² + … + 2 + 1 = 2ⁿ − 1（等比級數和）

驗證：n=1 → 1；n=2 → 3；n=3 → 7 ✔
時間複雜度 O(2ⁿ)——n = 64 時需約 1.8×10¹⁹ 次，即使每秒一次也要數千億年。
📊 (三) 遞迴 vs 迴圈
項目遞迴迴圈（迭代）
程式碼簡潔、貼近數學定義較冗長
可讀性對遞迴性問題更直觀對簡單重複更直觀
記憶體每層占用呼叫堆疊省
執行速度較慢（函式呼叫開銷）快
風險層數太深 → Stack Overflow無此問題
適用樹狀結構、分治法、問題本身即遞迴定義（河內塔、走訪樹）簡單重複運算

結論：遞迴不必然較優。若問題本身具遞迴結構（河內塔、樹走訪）則遞迴清楚得多；若只是重複累加，迴圈更有效率。
另可用記憶化改善遞迴的重複計算問題（如費氏數列由 O(2ⁿ) 降為 O(n)）。

✍️ 必寫拿分點 1. 兩題都要有終止條件與遞迴關係
2. 河內塔三步驟的邏輯說明比程式碼更重要
3. 移動次數 2ⁿ−1 要有推導過程，不能只給公式
4. n=3 的實際輸出驗算
5. 比較表要指出「遞迴不必然較優」的判斷準則

📝 (一) 十進位轉二進位

思路：不斷除以 2 取餘數，餘數由下往上讀。可用陣列暫存後反向輸出，或用遞迴自然反轉。

// 【寫法一：陣列暫存後反向輸出】
void toBinary(int n) {
    if (n == 0) {                  // 邊界條件：0 要特別處理
        printf("0");
        return;
    }
    int bits[32];                  // 32 位元足夠存放 int
    int idx = 0;

    while (n > 0) {
        bits[idx++] = n % 2;       // 取餘數
        n = n / 2;                 // 縮小
    }
    for (idx = idx - 1; idx >= 0; idx--)   // 反向輸出
        printf("%d", bits[idx]);
}

// 【寫法二：遞迴版（更簡潔）】
void toBinaryR(int n) {
    if (n == 0) return;          // 終止條件
    toBinaryR(n / 2);              // 先處理高位
    printf("%d", n % 2);         // 回傳時才印，順序自然正確
}

驗算（n = 13）： 

13 / 2 = 6 餘 1  ↑
 6 / 2 = 3 餘 0  │ 由下往上讀
 3 / 2 = 1 餘 1  │
 1 / 2 = 0 餘 1  ┘
→ 1101₍₂₎

驗證：8 + 4 + 0 + 1 = 13 ✔

📝 (二) 階乘 
// 【遞迴版】
long long factR(int n) {
    if (n < 0) return -1;        // 錯誤處理：負數無階乘
    if (n <= 1) return 1;        // 終止條件（0! = 1）
    return n * factR(n - 1);
}

// 【迴圈版】
long long factL(int n) {
    if (n < 0) return -1;
    long long result = 1;
    int i;
    for (i = 2; i <= n; i++) {
        result *= i;
    }
    return result;
}

驗算：5! = 5×4×3×2×1 = 120；0! = 1（定義）
