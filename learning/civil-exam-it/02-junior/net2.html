第 1 章　零信任架構 (Zero Trust Architecture, ZTA)

傳統的網路安全建立在「邊界防禦（如防火牆）」上，預設「內部網路是安全的」。但隨著遠距辦公與雲端服務普及，邊界已變得模糊。零信任架構打破了這個迷思。

1-1　零信任的核心精神

📐 「Never Trust, Always Verify」 不論存取要求來自外網或內網，預設皆不信任。必須對「每一次」的存取請求進行嚴格的身分驗證與授權。

1-2　零信任三大支柱 (NIST SP 800-207)

支柱說明關鍵技術
身分 (Identity)確保是合法的人員或設備。多因子驗證 (MFA)、單一簽入 (SSO)、FIDO
設備 (Device)檢查設備的健康狀態與合規性。端點偵測與回應 (EDR)、行動裝置管理 (MDM)
網路 (Network) / 環境限縮橫向移動的範圍。微切分 (Micro-segmentation)、軟體定義邊界 (SDP)
🧒 微切分 (Micro-segmentation) 是什麼？

傳統網路像是一艘沒有水密艙的船，只要外殼（防火牆）破了一個洞，水就會淹滿整艘船（駭客在內網橫向移動）。

微切分則是把船艙切成許多獨立的水密艙。即使駭客攻破了一台印表機或員工電腦，他也無法輕易連線到旁邊的資料庫伺服器，因為每個區塊之間都有嚴格的存取控制。

第 2 章　軟體定義網路 (SDN) 與 NFV

隨著雲端資料中心的擴展，傳統由硬體路由器/交換器主導的網路架構已缺乏彈性。SDN 帶來了網路架構的革命。

2-1　SDN 的核心概念

SDN 的最大特色是「控制層 (Control Plane)」與「資料層 (Data Plane)」分離。

層面功能與特徵比喻
應用層 (Application Plane)提供防火牆、負載平衡等網路服務的軟體。企業老闆 (決定規則)
控制層 (Control Plane)SDN 控制器，掌握全網視角，計算最佳路徑。透過 Northbound API 與應用層溝通。交通警察局長 (統一指揮)
資料層 (Data Plane)純硬體轉發設備（如 SDN 交換器），只負責依照控制層下達的規則轉發封包。透過 Southbound API (如 OpenFlow) 與控制層溝通。路口交警 (只負責吹哨指揮)

2-2　網路功能虛擬化 (NFV)

將原本需要專屬硬體（如實體防火牆、實體負載平衡器）的網路功能，改為用軟體執行在標準的 x86 伺服器上。

SDN 與 NFV 的差異：SDN 是改變網路架構（控制與轉發分離），而 NFV 是改變設備形態（軟體取代專屬硬體）。兩者常搭配使用以達到最高彈性。

第 3 章　現代網頁協定 (HTTP/2, HTTP/3, QUIC)

HTTP/1.1 已經使用了超過 20 年，但其「隊頭阻塞 (Head-of-Line Blocking)」問題嚴重影響了現代富網頁的載入速度。

3-1　HTTP/2 的改良

  • 多工處理 (Multiplexing)：在單一 TCP 連線上，可以交錯傳送多個請求與回應，解決了 HTTP 層的隊頭阻塞。
  • 標頭壓縮 (HPACK)：壓縮重複的 Header，減少頻寬浪費。
  • 二進位分框 (Binary Framing)：不再使用純文字傳輸，改用電腦更容易解析的二進位格式。
  • 伺服器推送 (Server Push)：伺服器可主動將 CSS/JS 推送給客戶端，不需等客戶端解析 HTML 後才來要。

3-2　HTTP/3 與 QUIC

HTTP/2 雖然解決了 HTTP 層的阻塞，但底層仍然使用 TCP。只要 TCP 掉了一個封包，整個連線都會卡住等待重傳（TCP 層的隊頭阻塞）。

特性說明
基於 UDP 的 QUIC 協定HTTP/3 捨棄了 TCP，改用基於 UDP 開發的 QUIC 協定。由 QUIC 在應用層實作可靠傳輸與壅塞控制。
解決 TCP 隊頭阻塞因為多個串流在 QUIC 中是獨立的，掉了一個封包只會影響該串流，其他串流可繼續傳輸。
零往返時間 (0-RTT) 交握結合了傳輸層與加密層 (TLS 1.3) 的交握，以前連線過的伺服器可以直接傳送資料，連線速度極快。

第 4 章　IPv6 深度解析與過渡機制

4-1　IPv6 封包標頭簡化

IPv6 標頭大小固定為 40 Bytes（IPv4 為 20~60 Bytes）。為了加速硬體路由，IPv6 移除了 IPv4 標頭中一些不必要的欄位：

  • 移除 Checksum：因為第二層 (Ethernet) 與第四層 (TCP/UDP) 都有 Checksum，網路層不再重複檢查。
  • 移除 Fragmentation (分段) 欄位：IPv6 路由器不負責分段，若封包過大直接丟棄並回傳 ICMPv6 "Packet Too Big"。分段只能由來源端主機執行。

4-2　IPv4 到 IPv6 的過渡機制

技術說明
雙堆疊 (Dual Stack)設備同時跑 IPv4 與 IPv6 兩個協定。最直接，但仍需消耗 IPv4 位址。
穿隧技術 (Tunneling)把 IPv6 封包「包在」IPv4 封包裡面（如 6to4, Teredo），藉此通過不支援 IPv6 的 IPv4 網路。
位址轉換 (NAT64)類似 NAT 的概念，將 IPv6 的標頭轉換為 IPv4 標頭，讓純 IPv6 的主機可以連上純 IPv4 的伺服器。

第 5 章　進階 VPN 與 IPsec 實作

5-1　IPsec 協定套件

IPsec 運作於網路層 (Layer 3)，可保護 IP 封包的機密性與完整性。

核心協定功能說明
AH (Authentication Header)提供完整性與資料來源驗證。不提供機密性 (無加密)。
ESP (Encapsulating Security Payload)提供機密性 (加密)、完整性與身分驗證。實務上最常使用。
IKE (Internet Key Exchange)用來在通訊雙方之間建立安全關聯 (SA) 並自動交換金鑰。

5-2　IPsec 的兩種運作模式

模式保護範圍應用場景
傳輸模式 (Transport Mode)只加密/驗證 IP 封包的 Payload (資料部分)。原本的 IP 標頭保留不變。Host-to-Host (主機到主機的端點連線)
通道模式 (Tunnel Mode)加密/驗證 整個原始 IP 封包，並在外面加上一個新的 IP 標頭（通常是 VPN 閘道器的 IP）。Site-to-Site (分公司到總公司的 VPN)

第 6 章　次世代網路與物聯網 (5G/6G, 衛星, IoT)

隨著無線通訊與衛星技術的突破，網路的範圍已經從地表延伸到太空，連線的對象也從「人」變成了「萬物」。

6-1　5G 與網路切片技術 (Network Slicing)

5G 的三大特性是：大頻寬 (eMBB)、低延遲 (URLLC)、大連結 (mMTC)。為了一次滿足這三個截然不同的需求，5G 引入了「網路切片」技術。

📐 網路切片 (Network Slicing) 是什麼？ 想像一條實體的高速公路（實體 5G 網路），我們可以把它「虛擬切分」成好幾條專用車道（切片）：
- 車道 A（大頻寬）：專門給看 4K/8K 影片的人走，路很寬，但不用太管煞車反應時間。
- 車道 B（低延遲）：專門給「自駕車」與「遠距醫療」走，這條路保證絕對不塞車、反應極快，確保開刀不會卡頓。
- 車道 C（大連結）：專門給幾百萬個路燈、水表（物聯網）走，這些設備傳送的資料很小，但數量極多。
結論：同一組實體設備，透過軟體定義網路 (SDN)，切出多個各自獨立的虛擬網路，互不干擾。

6-2　低軌衛星通訊 (LEO, 如 Starlink)

衛星種類特色與優缺點
同步衛星 (GEO)高度約 36,000 公里，和地球自轉速度一樣（看起來永遠停在天空同一個點）。涵蓋範圍大（三顆就能覆蓋全球），但延遲極高 (約 250ms 以上)，打遊戲會非常卡。
低軌衛星 (LEO)高度僅 500~2,000 公里。延遲超低 (約 20~40ms)，媲美光纖！缺點是因為飛太低，轉得很快，需要發射成千上萬顆衛星（衛星星系）才能確保地面永遠收得到訊號。

6-3　物聯網通訊協定 (MQTT)

物聯網 (IoT) 設備通常電池很小、網路很爛（例如裝在深山裡的溫濕度計）。如果用傳統網頁的 HTTP 來傳資料，標頭 (Header) 太肥大，會耗光電池。因此出現了 MQTT。

  • 極輕量化：MQTT 標頭最小只有 2 Bytes（HTTP 動輒幾百 Bytes）。非常省電！
  • 發布/訂閱模式 (Publish/Subscribe)：設備不用互相連線。感測器只要把資料「發布 (Publish)」到中心的仲介伺服器 (Broker)，手機 App 向 Broker「訂閱 (Subscribe)」即可收到資料。
  • QoS (服務品質) 保證：分為 0 (最多送一次)、1 (至少送一次)、2 (確實只送一次)，確保在爛網路下資料不會遺失或重複。
