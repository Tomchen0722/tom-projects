A. 網路模型與設備（1～8 題）

1OSI
OSI 模型中負責「實體定址（MAC）」的是哪一層？
  • (A) 實體層　(B) 資料連結層　(C) 網路層　(D) 傳輸層
詳解
答案：(B) 資料連結層（L2）
兩種定址要分清：MAC 是 L2、IP 是 L3。
L4 傳輸層則負責埠號與端對端可靠傳輸。

口訣（由上而下）：應表會傳網資實
2設備
下列何種設備可分割「廣播網域」？
  • (A) 集線器　(B) 中繼器　(C) 交換器（未設 VLAN）　(D) 路由器
詳解
答案：(D) 路由器
核心口訣：交換器分割「碰撞網域」，路由器分割「廣播網域」。

交換器若設定 VLAN 也能分割廣播網域，但題目已註明未設 VLAN。

例：24 埠交換器接一台路由器（未切 VLAN）→ 24 個碰撞網域、1 個廣播網域。
3OSI
資料在網路層的單位名稱為？
  • (A) Bit　(B) Frame　(C) Packet　(D) Segment
詳解
答案：(C) Packet
由上而下：Data → Segment（傳輸層）→ Packet（網路層）→ Frame（資料連結層）→ Bit（實體層）

封裝概念：每往下一層就加上該層的標頭，像一層層信封。
交換器只拆到 L2、路由器只拆到 L3——這也解釋了為什麼交換器比路由器快。
4VLAN
關於 VLAN，下列敘述何者錯誤？
  • (A) 可在同一台交換器上分割多個廣播網域
  • (B) 不同 VLAN 間通訊需經 L3 設備
  • (C) 同一 VLAN 的主機必須連在同一台實體交換器
  • (D) 可用於隔離訪客網路與內部網路
詳解
答案：(C)
VLAN 是邏輯分群，可跨多台交換器——這正是 Trunk Port 存在的目的（以 802.1Q 標籤承載多個 VLAN）。

VLAN 的核心價值就是「脫離實體位置的限制」：三樓與一樓的會計人員可在同一 VLAN，換座位不用重拉線。
5L2
交換器收到訊框但 MAC 表中查不到目的位址時，會如何處理？
  • (A) 丟棄　(B) 洪泛到除來源埠外的所有埠　(C) 送回來源　(D) 轉給路由器
詳解
答案：(B) 洪泛（Flooding）
交換器三種行為：Forward（查到→只送該埠）、Flooding（查不到→送所有其他埠）、Filter（目的埠＝來源埠→丟棄）。

資安延伸：MAC 洪泛攻擊即大量偽造來源 MAC 塞爆位址表，使交換器對所有流量洪泛 → 攻擊者可竊聽。防護為 Port Security。
6L2
交換器網路使用 STP 的主要目的為？
  • (A) 加密資料　(B) 防止迴圈造成廣播風暴　(C) 分配 IP　(D) 提升傳輸速率
詳解
答案：(B)
交換器間若成環，廣播訊框會無限循環放大 → 廣播風暴。

深度考點：IP 封包有 TTL 可防無限迴圈，但 L2 訊框沒有 TTL——這就是 L2 特別需要 STP 的原因。

STP 的設計哲學：實體上要有備援線路，但邏輯上只啟用一條；故障時自動啟用備援。
7無線
無線網路採用 CSMA/CA 而非 CSMA/CD 的原因為？
  • (A) 無線速度較快
  • (B) 無線網卡無法同時收發，且有隱藏節點問題
  • (C) 無線不會發生碰撞
  • (D) CSMA/CD 已被淘汰
詳解
答案：(B)
兩個原因：
1. 無線網卡是半雙工，無法「邊說邊聽」——而 CD 的前提就是邊傳邊偵測碰撞。
2. 隱藏節點問題：A 與 C 都在 B 的範圍內，但彼此聽不到 → 同時傳送而在 B 處碰撞。

因此改採事前避免：RTS/CTS 交握取得傳送許可 + ACK 確認。
8實體層
下列關於光纖之敘述，何者錯誤？
  • (A) 不受電磁干擾　(B) 頻寬大　(C) 單模光纖傳輸距離較多模短　(D) 較銅線難以竊聽
詳解
答案：(C)
單模：蕊徑細、光走單一路徑、色散小 → 距離最遠（數十公里），成本較高
多模：蕊徑粗、多路徑色散 → 距離較短，成本低

記憶法：「單一路線跑得遠」。

B. IP 與子網路（9～18 題）

9子網路
IP 192.168.1.200/26 的網路位址為？
  • (A) 192.168.1.128　(B) 192.168.1.192　(C) 192.168.1.224　(D) 192.168.1.0
詳解
答案：(B) 192.168.1.192
① /26 → 遮罩 192 → 區塊大小 = 256 − 192 = 64
② 段界：.0、.64、.128、.192
③ 200 落在 192～255 → 網路位址 .192、廣播 .255

可用範圍 .193 ~ .254（62 台）。
10子網路
遮罩 255.255.255.224 對應的 CIDR 與可用主機數為？
  • (A) /26，62　(B) /27，30　(C) /28，14　(D) /29，6
詳解
答案：(B) /27，30 台
224 = 11100000（3 個 1）→ 24 + 3 = /27
主機位元 = 32 − 27 = 5 → 2⁵ − 2 = 30

必背九個遮罩值：0、128、192、224、240、248、252、254、255
考前寫在草稿紙角落，所有子網路題都會變快。
11子網路
將 192.168.1.0/24 切成 4 個大小相同的子網路，每個子網路的可用主機數為？
  • (A) 30　(B) 62　(C) 64　(D) 126
詳解
答案：(B) 62
切 4 個 → 借 2 個位元（2² = 4）→ /24 + 2 = /26
主機位元 = 6 → 2⁶ − 2 = 62

四個子網路（區塊 64）：.0、.64、.128、.192　驗算：4 × 64 = 256 ✔

(C) 64 是區塊大小，不是可用主機數——忘記減 2 是常見錯誤。
12子網路
某部門需 100 台主機位址，最節省的遮罩為？
  • (A) /24　(B) /25　(C) /26　(D) /27
詳解
答案：(B) /25（2⁷ − 2 = 126 ≥ 100）

/26 只有 62 台不夠；/24 有 254 台但浪費 128 個位址。

解題技巧：從「需求 + 2」往上找最接近的 2 的次方。
100 + 2 = 102 → 最接近且大於它的是 128 = 2⁷ → 主機位元 7 → /25
13子網路
下列哪個 IP 可以指派給主機使用？
  • (A) 10.1.1.0/24　(B) 10.1.1.255/24　(C) 10.1.1.150/24　(D) 以上皆可
詳解
答案：(C)
/24 網段 10.1.1.0 ~ 10.1.1.255：
‧ (A) .0 = 網路位址 ✘
‧ (B) .255 = 廣播位址 ✘
‧ (C) .150 → 落在 .1 ~ .254 可用範圍 ✔

口訣：每個網段的「頭」（網路位址）與「尾」（廣播位址）都不能給主機。這就是「減 2」的由來。
14IP
下列何者不是私有 IP 位址？
  • (A) 10.5.1.1　(B) 172.20.1.1　(C) 192.168.1.1　(D) 172.35.1.1
詳解
答案：(D) 172.35.1.1
三個私有網段：
‧ 10.0.0.0/8（10.x.x.x）
‧ 172.16.0.0/12 → 範圍是 172.16 ~ 172.31（不含 172.35）
‧ 192.168.0.0/16

陷阱：172 那段是 /12 不是 /16，很多人誤以為 172.x.x.x 都是私有位址。
15IP
電腦 IP 顯示 169.254.5.10，代表？
  • (A) 取得公有 IP　(B) DHCP 取得失敗　(C) 設為靜態 IP　(D) 已連 VPN
詳解
答案：(B)
169.254.0.0/16 是 APIPA，Windows 在 DHCP 取得失敗時自動指派。

排查步驟：① 網路線與交換器埠 ② DHCP 伺服器是否運作、位址池是否耗盡 ③ 跨網段的 DHCP Relay 設定 ④ 是否被 Port Security 阻擋。
16NAT
關於 NAT，下列敘述何者正確？
  • (A) NAT 等同防火牆，可完整保護內網
  • (B) NAT 可節省公有 IP，並提供有限的隱蔽性，但不等於安全性
  • (C) NAT 會加密封包內容
  • (D) 使用 NAT 後不需要防火牆
詳解
答案：(B)
NAT 讓外部無法直接連入內部主機，但那是副作用而非設計目的；它完全不檢查封包內容，也擋不住內部主機主動連出後回來的惡意流量。

正確說法：「NAT 提供有限的隱蔽性（Obscurity），但不等於安全性，仍需搭配防火牆。」

NAPT/PAT：以埠號區分多台內部主機（多對一），是家用與機關最常見的做法。
17IPv6
關於 IPv6，下列敘述何者錯誤？
  • (A) 位址 128 位元　(B) 取消廣播改用多播與任播　(C) 保留標頭檢查碼以提升可靠性　(D) 支援 SLAAC 自動設定
詳解
答案：(C)
IPv6 移除了標頭檢查碼，理由：
1. L2（Ethernet FCS）與 L4（TCP/UDP checksum）已有檢查，重複是浪費
2. IPv4 每經一台路由器都要因 TTL 改變而重算 → 移除後路由更快

這正是 IPv6「簡化標頭以提升繞送效能」的設計精神。
18診斷
tracert 的運作原理為？
  • (A) 送出大量 ping 統計延遲
  • (B) 逐次遞增 TTL，利用 TTL 歸零時路由器回送的 ICMP 訊息
  • (C) 查詢 DNS 反向記錄
  • (D) 讀取路由器繞送表
詳解
答案：(B)
送 TTL=1 → 第一台路由器把 TTL 減為 0 → 丟棄並回送 ICMP Time Exceeded → 得知第一台位址；再送 TTL=2… 依此類推。

這是把協定機制拿來當診斷工具的經典設計。

註：部分路由器不回應 ICMP，會顯示 * * *，不代表網路不通。

C. 傳輸層與應用層（19～28 題）

19TCP
TCP 三向交握的順序為？
  • (A) SYN → ACK → SYN　(B) SYN → SYN+ACK → ACK　(C) ACK → SYN → FIN　(D) SYN → FIN → ACK
詳解
答案：(B)
① 用戶端 SYN：「我想連線」
② 伺服器 SYN+ACK：「好，我也想連，並確認收到你的」
③ 用戶端 ACK：「確認收到」

為何三次：連線是雙向的，兩邊都要確認對方收得到；第三次 ACK 讓伺服器確知用戶端也收到回應，並完成初始序號同步。

斷線四次（FIN→ACK→FIN→ACK），因全雙工需兩方向各自關閉。
20TCP
下列何者不是 UDP 的特性？
  • (A) 標頭僅 8 bytes　(B) 非連線導向　(C) 具備流量控制　(D) 傳輸速度快
詳解
答案：(C)
UDP 沒有流量控制、也沒有擁塞控制——這正是它快但不可靠的原因。

TCPUDP
標頭20+ bytes8 bytes
連線連線導向非連線導向
流量／擁塞控制✅❌
21TCP
TCP 中，「解決接收端來不及處理」的機制稱為？
  • (A) 擁塞控制　(B) 流量控制　(C) 慢啟動　(D) 快速重送
詳解
答案：(B) 流量控制（Flow Control），以滑動視窗實作（接收端回報 rwnd）。

易混淆對照：
‧ 流量控制 → 管接收端：「你講太快，我聽不完」
‧ 擁塞控制 → 管網路：「馬路太塞，大家慢一點」（慢啟動、擁塞避免、快速重送、快速回復）

實際傳送量 = min(rwnd, cwnd)。
22埠號
下列協定與埠號對應何者正確？
  • (A) HTTPS — 80　(B) SSH — 23　(C) DNS — 53　(D) SMTP — 110
詳解
答案：(C) DNS — 53
更正其他選項：HTTPS = 443（80 是 HTTP）；SSH = 22（23 是 Telnet）；SMTP = 25（110 是 POP3）。

必背：22 SSH｜23 Telnet｜25 SMTP｜53 DNS｜80 HTTP｜110 POP3｜143 IMAP｜443 HTTPS｜3389 RDP
23埠號
下列何者不應直接開放於網際網路？
  • (A) 443　(B) 80　(C) 3389　(D) 53（對外 DNS 服務）
詳解
答案：(C) 3389（RDP 遠端桌面）
RDP 對外開放是勒索軟體最常見的入侵管道——攻擊者以自動化工具暴力破解帳密。

正確做法：遠端管理應走 VPN ＋ MFA 或跳板機，絕不直接對外。

同理高風險的還有：445（SMB）、資料庫埠（1433、3306、5432）、23（Telnet 明文）。
24DNS
DNS 中將網域名稱指向另一個名稱的記錄類型為？
  • (A) A　(B) AAAA　(C) CNAME　(D) MX
詳解
答案：(C) CNAME（別名）
‧ A：名稱 → IPv4
‧ AAAA：名稱 → IPv6（四個 A，位址是 IPv4 的四倍長）
‧ CNAME：名稱 → 另一個名稱
‧ MX：郵件伺服器｜PTR：IP → 名稱｜TXT：SPF/DKIM/網域驗證
25DNS
可驗證 DNS 回應真實性、防止快取毒化的技術為？
  • (A) DNSSEC　(B) NAT　(C) VLAN　(D) DHCP Snooping
詳解
答案：(A) DNSSEC
以數位簽章為 DNS 記錄簽名，解析器可驗證回應確實來自權威伺服器且未遭竄改。

重要區辨：DNSSEC 提供完整性與來源鑑別，不提供機密性（查詢內容仍是明文）。
要加密查詢內容需用 DoH（DNS over HTTPS）或 DoT。
26HTTP
HTTP 狀態碼 401 與 403 的差異為？
  • (A) 401 是伺服器錯誤，403 是用戶端錯誤
  • (B) 401 表示未經身分驗證，403 表示已驗證但無權限
  • (C) 兩者相同
  • (D) 401 表示找不到資源
詳解
答案：(B)
‧ 401 Unauthorized：還沒證明你是誰 → 請先登入
‧ 403 Forbidden：知道你是誰，但你沒資格

其他：404 找不到｜429 請求過多｜500 伺服器內部錯誤｜503 服務不可用

記憶：4xx 是用戶端的錯，5xx 是伺服器的錯。
27HTTP
HTTPS 相較於 HTTP，提供了哪些保障？
  • (A) 僅機密性　(B) 僅完整性　(C) 機密性、完整性與伺服器身分鑑別　(D) 僅提升傳輸速度
詳解
答案：(C)
HTTPS ＝ HTTP over TLS，提供：
‧ 機密性（加密內容）
‧ 完整性（MAC 驗證未遭竄改）
‧ 身分鑑別（伺服器憑證由 CA 簽發）

機關網站應設定的安全標頭：HSTS（強制 HTTPS）、CSP（防 XSS）、X-Frame-Options（防點擊劫持）、Cookie 加 Secure/HttpOnly/SameSite。
28診斷
若「用 IP 可以連線，但用網域名稱無法連線」，最可能的問題為？
  • (A) 網路線鬆脫　(B) DNS 設定或服務異常　(C) 防火牆封鎖 ICMP　(D) IP 位址衝突
詳解
答案：(B) DNS 問題
IP 通表示實體層到網路層都正常，只剩「名稱轉 IP」這一步出問題。

標準排查順序（申論情境題可用）：
① 實體層（線、燈號）→ ② IP 設定（是否 169.254）→ ③ ping 閘道 → ④ ping 外部 IP → ⑤ ping 網域名稱（此處失敗＝DNS） → ⑥ 應用層（埠、防火牆、服務）

D. 密碼學與驗證（29～36 題）

29密碼學
A 要傳機密文件給 B，只讓 B 能閱讀，應用何者加密？
  • (A) A 的公鑰　(B) A 的私鑰　(C) B 的公鑰　(D) B 的私鑰
詳解
答案：(C) B 的公鑰（只有 B 的私鑰能解，而私鑰只有 B 有）

必背口訣：
‧ 要保密 → 用「對方的公鑰」加密
‧ 要簽名 → 用「自己的私鑰」簽章

若同時要保密與簽章：先用自己的私鑰簽章，再用對方的公鑰加密整包。
30密碼學
下列何者只有數位簽章能提供，HMAC 無法提供？
  • (A) 完整性　(B) 來源鑑別　(C) 不可否認性　(D) 機密性
詳解
答案：(C) 不可否認性
HMAC 使用雙方共享的祕密金鑰 → A 能產生的訊息 B 也能產生 → 事後 A 可主張「那是 B 偽造的」，無法歸責。
數位簽章用的是只有簽署者持有的私鑰，因此無法抵賴。

(D) 兩者都不提供機密性。

三層遞進：雜湊（完整性）→ HMAC（＋來源鑑別）→ 數位簽章（＋不可否認性）
31密碼學
關於 HTTPS 的加密方式，下列敘述何者正確？
  • (A) 全程僅使用非對稱式加密
  • (B) 全程僅使用對稱式加密
  • (C) 以非對稱式交換金鑰，再以對稱式加密資料
  • (D) 不使用任何加密
詳解
答案：(C) 混合加密
設計精神：用慢但能解決信任問題的非對稱式處理「金鑰交換與身分驗證」，用快的對稱式處理「大量資料傳輸」。

因為非對稱式慢 100～1000 倍，全程使用會慢到無法使用。

前向保密（PFS）：採 ECDHE 等臨時金鑰交換，即使日後伺服器私鑰洩漏，過去錄存的通訊仍無法被解密。
32密碼學
下列雜湊演算法中，何者目前仍被視為安全？
  • (A) MD5　(B) SHA-1　(C) SHA-256　(D) CRC32
詳解
答案：(C) SHA-256
‧ MD5：已可實際製造碰撞
‧ SHA-1：已被證實可碰撞，應停用
‧ CRC32：是錯誤偵測碼而非密碼學雜湊，設計目的只是偵測傳輸錯誤，完全無抗碰撞性

易錯點：CRC 與 checksum 防的是「意外錯誤」，密碼學雜湊防的是「惡意竄改」，目的完全不同。
33密碼學
機關系統儲存使用者密碼，最適當的做法為？
  • (A) 明文儲存但限制資料庫權限
  • (B) 以 AES 加密後儲存
  • (C) 以 MD5 雜湊後儲存
  • (D) 以 bcrypt／Argon2 等慢速雜湊搭配隨機鹽儲存
詳解
答案：(D)
‧ (A) 明文是最嚴重的錯誤，違反《個人資料保護法》安全維護義務
‧ (B) 加密可還原，金鑰洩漏則所有密碼一次曝光；系統本來就不需要知道原始密碼
‧ (C) MD5 運算太快（每秒可試數十億次）且可查彩虹表

正解的兩個關鍵：
1. 慢速雜湊（刻意設計得慢，使暴力破解不可行）
2. 每帳號不同的隨機鹽（使彩虹表失效，且相同密碼的兩人雜湊值也不同）
34PKI
數位憑證中，用來確保憑證本身未被竄改的是？
  • (A) 持有人的公鑰　(B) 簽發 CA 的數位簽章　(C) 憑證序號　(D) 有效期間
詳解
答案：(B) CA 的數位簽章
CA 用自己的私鑰為整份憑證簽章，驗證者以 CA 的公鑰驗證 → 內容改一個位元，驗證就失敗。

信任的起點：作業系統／瀏覽器內建的根憑證清單。
→ 這也是為什麼「安裝來路不明的根憑證」極度危險——等於讓對方可偽造任何網站的身分。
35驗證
下列何者屬於真正的多因子驗證（MFA）？
  • (A) 密碼 + 安全提示問題　(B) 密碼 + 手機 OTP　(C) 密碼 + PIN　(D) 指紋 + 臉部辨識
詳解
答案：(B)——密碼（你知道的）＋ OTP（你擁有的），屬不同類別。

‧ (A)(C) 都屬「你知道的」
‧ (D) 都屬「你本身的」

三大類別：你知道的｜你擁有的｜你本身的。
補充：簡訊 OTP 雖合格，但有 SIM 卡挾持風險，安全性低於 FIDO2 實體金鑰或驗證器 App。
36存取控制
機關系統依「職稱」授予權限，人員異動時只需變更角色指派。這屬於？
  • (A) DAC　(B) MAC　(C) RBAC　(D) ABAC
詳解
答案：(C) RBAC（角色存取控制）

為何機關最適合 RBAC：公務機關人事異動頻繁（輪調、代理、升遷），若權限綁個人，異動時容易漏收回舊權限，長期累積成權限膨脹。
RBAC 只要改角色指派，管理成本低且不易出錯。

搭配定期權限盤點（Access Review）效果更好——這是資安稽核常見的查核項目。

E. 攻擊防護與法規（37～45 題）

37攻擊
攻擊者大量送 SYN 但不完成交握，耗盡伺服器連線資源，屬於？
  • (A) SQL Injection　(B) SYN Flood　(C) XSS　(D) ARP 欺騙
詳解
答案：(B) SYN Flood（DoS/DDoS 的一種）
伺服器收到 SYN 會配置資源並記入「半開連線表」等待第三次 ACK；攻擊者不回應（且常偽造來源 IP），使表被塞滿。

防護：SYN Cookie（不預先配置資源，把狀態編碼在序號中）、縮短逾時、限制連線速率、流量清洗服務。
38攻擊
防範 SQL Injection 最根本的做法為？
  • (A) 過濾單引號等特殊字元　(B) 使用參數化查詢　(C) 隱藏錯誤訊息　(D) 加裝 WAF
詳解
答案：(B) 參數化查詢（Prepared Statement）
根本原因是「資料與指令未分離」，參數化查詢直接解決根因：使用者輸入永遠被當成「值」，不會被解讀為 SQL 語法。

(A) 黑名單過濾容易被繞過（編碼變形）；(C)(D) 屬縱深防禦但無法根治。

申論完整答法（分層）：程式層（參數化查詢、白名單）／資料庫層（最小權限、錯誤訊息不外露）／網路層（WAF）／管理層（安全開發規範、上線前檢測）。
39攻擊
關於 XSS 與 CSRF，下列敘述何者正確？
  • (A) XSS 是誘使瀏覽器送出非預期請求；CSRF 是注入惡意腳本
  • (B) XSS 是注入惡意腳本於他人瀏覽器執行；CSRF 是利用既有登入狀態送出請求
  • (C) 兩者防禦方式完全相同
  • (D) HttpOnly Cookie 可完全防止 CSRF
詳解
答案：(B)
一句話：XSS 是「偷你的身分」，CSRF 是「借你的手」。

XSSCSRF

40惡意程式
下列何者能自我複製並自動傳播，不需使用者操作？
  • (A) 病毒　(B) 蠕蟲　(C) 木馬　(D) Rootkit
詳解
答案：(B) 蠕蟲（Worm）

核心區辨：病毒需要「人」幫忙執行，蠕蟲不用。
‧ 病毒：需附著於檔案，靠使用者執行才傳播
‧ 木馬：偽裝成正常軟體，誘使使用者自行安裝
‧ Rootkit：藏於系統深層（甚至核心），極難偵測與移除
41勒索軟體
關於勒索軟體防護，下列何者最為關鍵？
  • (A) 安裝防毒軟體即可
  • (B) 使用 RAID 5 即可保障資料
  • (C) 備份須有離線或不可變副本
  • (D) 支付贖金以取回資料
詳解
答案：(C)
若備份一直連在網路上，會被一起加密——這是實務上最常見的失敗原因。

‧ (B) RAID 不是備份：它防硬碟故障，防不了誤刪與加密（會同步加密所有副本）
‧ (D) 原則上不支付贖金：不保證能解、助長犯罪，公務機關支付另涉預算與法律問題

3-2-1 原則：3 份副本、2 種媒體、1 份異地；再加1 份離線／不可變。
42防護
IDS 與 IPS 的主要差異為？
  • (A) IDS 偵測告警、IPS 主動阻擋　(B) IDS 較新　(C) IDS 只用於無線網路　(D) 兩者相同
詳解
答案：(A)
‧ IDS：旁接部署，不在流量路徑上 → 不影響效能，但只能事後告警
‧ IPS：串接部署，可即時阻擋，但誤判會直接中斷業務，本身也成為單點故障

實務細節：IPS 新規則常先以「僅告警」模式觀察一段時間，確認誤報率可接受後才啟用阻擋。
43架構
關於 DMZ 的設計，下列何者錯誤？
  • (A) 放置需對外提供服務的主機
  • (B) 即使 DMZ 主機被攻陷，攻擊者仍無法直接進入內網
  • (C) 資料庫伺服器應放在 DMZ 方便網站存取
  • (D) DMZ 與內網之間應有防火牆隔離
詳解
答案：(C)
資料庫絕不可放在 DMZ。DMZ 是「預期可能被攻破」的區域，把最有價值的資料放在那裡等於自毀防線。

正確架構：網頁伺服器放 DMZ → 資料庫放內部受保護網段 → 兩者間以防火牆規則只允許特定 IP 與特定埠連線。

DMZ 的核心價值是限制橫向移動。
44法規
依《資通安全管理法》，公務機關的資安責任等級如何劃分？
  • (A) 高中低三級　(B) A 至 E 五級　(C) 1 至 3 級　(D) 不分級
詳解
答案：(B) A、B、C、D、E 五級
依機關業務重要性與資料敏感程度核定，等級越高應辦事項越多（專責人力、防護措施、演練與稽核頻率）。

注意區分兩套分級（常見陷阱）：
‧ 機關的資安責任等級：A~E 五級
‧ 資安事件：依影響程度分 1~4 級，3、4 級為重大事件
45應變
機關發現伺服器遭入侵，下列處置何者最不適當？
  • (A) 將受害主機自網路隔離
  • (B) 立即重灌系統以盡快恢復服務
  • (C) 依規定通報主管機關
  • (D) 保存記憶體與磁碟證據
詳解
答案：(B) 立即重灌
三個嚴重後果：
1. 證據全毀——記憶體中的惡意程式與攻擊軌跡消失，無法查明入侵管道
2. 無法防止再犯——不知道怎麼進來的，重灌後可能立刻再被入侵
3. 後門可能仍在——攻擊者可能已在其他主機植入後門、竊得管理員帳密

正確順序：圍堵（隔離，拔網路線而非關機）→ 保存證據 → 通報 → 根除（含重設所有可能外洩憑證）→ 由乾淨備份復原 → 事後檢討

FIN → ACK ← FIN ← ACK →
問題原因
為何建立要三次連線是雙向的，兩邊都須確認「對方收得到我」；前兩次僅確認單方向，第三次 ACK 才使伺服器確知對方也收到其回應，同時完成雙方初始序號（ISN）交換與同步
為何斷線要四次TCP 為全雙工，兩方向須各自關閉。一方送 FIN 僅表示「我沒有資料要送了」，對方可能仍有資料待傳完，故其 ACK 與 FIN 需分開送出

弱點可被利用的缺陷（未修補漏洞、弱密碼、缺乏訓練）
風險處理做法機關實例

(二) 說明 RTO 與 RPO 之意義及其與備份備援設計之關係。（8 分）
(三) 某機關核心系統要求 RTO ≤ 4 小時、RPO ≤ 1 小時，且須能因應勒索軟體，請提出建議。（9 分）
看答題架構
📊 主表①　三種備份比較
類型備份內容備份時間儲存空間復原步驟
完整全部資料最長最大最簡單、最快
差異自上次完整備份後的變更中中完整 ＋ 最後一次差異
增量自上次任何備份後的變更最短最小完整 ＋ 所有增量（最慢）
📊 主表②　RTO 與 RPO
指標意義決定什麼
RTO（復原時間目標）可容忍的停機時間上限備援架構（熱／溫／冷備援）
RPO（復原點目標）可容忍的資料遺失量上限備份／日誌傳送頻率
          RPO              事件           RTO
  ←─遺失多少資料─┤   ▼ 發生   ├─多久恢復服務─→
   最後一次備份                     服務恢復

另需說明 BIA（營運衝擊分析）：盤點關鍵業務、評估中斷衝擊，作為訂定 RTO／RPO 的依據。

📊 主表③　本案架構建議
目標建議做法
達成 RPO ≤ 1 小時① 每日完整備份 ＋ 每小時交易日誌備份並傳送異地
② 或採非同步複寫至備援站，可使 RPO 逼近數分鐘
達成 RTO ≤ 4 小時① 建置溫備援或熱備援站台，預先部署系統環境
② 虛擬化叢集 ＋ 高可用（HA），單機故障可自動切換
③ 訂定明確切換決策程序（誰有權決定、判斷準則），避免決策延誤耗掉時間
④ 冷備援於 4 小時內完成還原風險偏高，不建議
因應勒索軟體
（本題重點）		① 離線備份（Air-gapped）——實體隔離使惡意程式無法觸及
② 不可變備份（Immutable／WORM）——保留期間內不可刪改
③ 備份系統帳號與網域分離——攻擊者常先取得網域管理員權限再刪備份
④ 多版本保留——惡意程式可能潛伏數週，僅留最新備份可能已受污染
⑤ 還原前先掃描，避免二次感染
管理配套① 定期演練還原並記錄——「備份成功」不等於「還原成功」
② 演練應包含實際切換至備援站
③ 備份加密並控管存取
④ 備份監控與失敗告警
⑤ 異地備援站應位於不同地理區域
⑥ 依《資通安全管理法》納入維護計畫並定期演練
✍️ 必寫拿分點 1. RTO 與 RPO 要分開回應（架構 vs 頻率）
2. 離線／不可變備份是抗勒索的核心
3. 備份帳號與網域分離、多版本保留
4. 「備份成功不等於還原成功」——必須定期演練
5. 3-2-1 原則

申論 12綜合 · 25 分
機關因應遠距辦公需求，需開放同仁自家中連回機關內部系統。

請就連線方式、身分驗證、權限控管、端點安全、管理制度五個面向提出資安建議。（25 分）
看答題架構
📋 答題骨架 一、前言：遠距存取將機關邊界延伸至家庭網路，風險大幅提高 → 二～六、五個面向逐項（各一表）→ 七、結論
📊 面向一：連線方式
建議說明
採 VPN 加密通道SSL/TLS VPN（部署簡便）或 IPsec VPN；禁止直接對外開放 RDP（3389）——這是勒索軟體最常見入口
高敏感系統採 VDI虛擬桌面，資料不落地至個人裝置
中長期評估 ZTNA以應用程式為單位授權，逐步取代傳統 VPN
VPN 設備維護優先納入修補管理——VPN 漏洞常被優先鎖定攻擊
📊 面向二：身分驗證
建議說明
強制 MFA最重要的單一措施；僅靠帳密的 VPN 極易遭撞庫或釣魚
密碼政策長度與複雜度、禁用常見密碼、定期檢查是否出現在外洩資料庫
帳號管理定期停用久未使用帳號；離職即時停權
異常登入偵測非上班時間、境外 IP、短時間多地登入 → 告警或阻擋
📊 面向三：權限控管
建議說明
最小權限VPN 連入後不應可存取整個內網，須以 ACL 限制可達之系統與埠
RBAC依角色授權，人員異動只需改角色指派
分級開放依系統敏感度決定是否開放遠端存取；最機敏者可不開放
特權帳號管理者帳號不得用於遠端日常作業；採跳板機並全程稽核
存取紀錄完整保留連線與操作日誌，納入 SIEM 監控
📊 面向四：端點安全
建議說明
優先配發公務筆電可統一納管；若須使用個人裝置（BYOD），風險顯著較高
裝置健康檢查連線前確認已更新修補、防毒／EDR 運作中、磁碟加密已啟用
資料落地控管禁止將機敏資料存於個人裝置；必要時以 DLP 或 VDI 控管
實體安全螢幕自動鎖定、避免於公共場所處理機敏資料、遺失時可遠端抹除
家庭網路提醒同仁變更家用路由器預設密碼、使用 WPA2/WPA3、避免使用公用 Wi-Fi
📊 面向五：管理制度
建議說明
訂定遠距辦公資安規範明定可存取系統、禁止事項、資料處理原則；經權責單位核定並公告
申請與核准程序遠端存取權限應經主管核准並定期檢視
教育訓練釣魚郵件辨識、社交工程演練；因應深偽（Deepfake），重要指示須以另一管道回撥確認
事件通報明確告知同仁發現異常時的通報窗口與程序
法規遵循依《資通安全管理法》納入資通安全維護計畫；涉個資者依《個人資料保護法》辦理
定期檢討依實際使用狀況與威脅情勢調整規範
✍️ 必寫拿分點 1. 五個面向全部回答——缺一面向即扣 5 分
2. MFA 是最重要的單一措施
3. 禁止直接對外開放 RDP
4. VPN 連入後仍須最小權限（不是進來就通行無阻）
5. 資料不落地／VDI與裝置健康檢查
6. 結論：「遠距辦公使機關邊界延伸至家庭網路，防護不能僅靠 VPN；須以身分驗證、最小權限、端點管理與制度規範並行，並考量機關維運能量分階段導入。」
