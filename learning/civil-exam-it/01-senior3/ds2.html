第 5 章　搜尋樹、平衡樹與堆積

5-1　二元搜尋樹（Binary Search Tree, BST）

📐 BST 性質 對任一節點：左子樹所有值 < 該節點值 < 右子樹所有值（通常不允許重複值）
🧒 白話版：為什麼 BST 快

像玩「猜數字 1～100」。你猜 50，對方說「太大」，你立刻知道 51～100 全部不用管了——一次砍掉一半。

100 個數字，最多猜 7 次就中（2⁷=128 > 100）。這就是 O(log n)。

但如果 BST 建成「歪斜樹」（例如照 1,2,3,4,5 的順序插入），它就變成一條線，找東西要一個一個走 → 退化成 O(n)。這就是為什麼需要「平衡樹」。

操作平均最壞（歪斜）
搜尋 SearchO(log n)O(n)
插入 InsertO(log n)O(n)
刪除 DeleteO(log n)O(n)

BST 刪除節點的三種情況（申論常考）

情況處理方式
① 葉節點直接刪除
② 只有一個子節點用該子節點取代自己（子節點「升級」）
③ 有兩個子節點用左子樹的最大值（中序前驅）或右子樹的最小值（中序後繼）取代，再遞迴刪除那個節點
情況③ 為什麼可以這樣做？因為中序前驅／後繼是「最接近被刪節點的值」，換上去之後 BST 性質仍然成立。
申論題請務必畫圖示範一次刪除過程，圖比文字說服力強得多。

5-2　AVL 樹（高度平衡二元搜尋樹）

📐 平衡因子（Balance Factor） BF(節點) = 左子樹高度 − 右子樹高度
AVL 樹要求每個節點的 BF ∈ {−1, 0, +1}

插入或刪除後若某節點 |BF| ≥ 2，即需旋轉（Rotation）回復平衡。

四種旋轉（必考，一定要會畫）

類型發生情形處理旋轉次數
LL在左子樹的左邊插入對失衡節點做一次右旋單旋轉
RR在右子樹的右邊插入對失衡節點做一次左旋單旋轉
LR在左子樹的右邊插入先對左子做左旋，再對失衡節點做右旋雙旋轉
RL在右子樹的左邊插入先對右子做右旋，再對失衡節點做左旋雙旋轉
LL 型（插入 10、20、30 之後的 30 導致失衡是 RR；此處示範 LL：插入 30、20、10）

      30(BF=2)              20
      /                    /  \
    20         →最右旋→   10    30

  10

🧒 旋轉在幹嘛？

想像樹是一串掛在天花板的風鈴，一邊掛太重就歪了。旋轉就是「把中間那個節點提上來當老大」，讓重量重新分配到兩邊。

怎麼判斷用哪一種？看「從失衡節點往下走兩步，走的是哪兩個方向」：左左→LL、右右→RR、左右→LR、右左→RL。名字就是路徑。

單旋轉不夠用的原因：LR 型的節點卡在「中間」，直接旋轉會變成另一邊失衡，所以要先把它扳直（第一次旋轉），再整體旋轉（第二次）。

💡 AVL 的高度上界（可能考推導） 設 N(h) 為高度 h 的 AVL 樹最少節點數：
N(0)=0、N(1)=1、N(h) = N(h−1) + N(h−2) + 1
這是類費氏數列 → h ≈ 1.44 log₂(n+2)，故 AVL 樹高度為 O(log n)，所有操作保證 O(log n)。

5-3　紅黑樹（Red-Black Tree）

五個性質
1. 每個節點是紅色或黑色
2. 根節點是黑色
3. 所有葉節點（NIL）是黑色
4. 紅色節點的兩個子節點都必須是黑色（不能有連續兩個紅色）
5. 從任一節點到其所有後代葉節點的路徑，黑色節點數相同（黑高相同）

AVL vs 紅黑樹（比較題）

項目AVL 樹紅黑樹
平衡嚴格度嚴格（高度差 ≤ 1）寬鬆（最長路徑 ≤ 2×最短路徑）
樹高較低 ≈1.44 log n較高 ≈2 log n
搜尋速度略快略慢
插入／刪除旋轉次數多，較慢旋轉次數少，較快
適用查詢多、修改少修改頻繁
實務應用資料庫索引（部分）C++ STL map/set、Java TreeMap、Linux 排程器

5-4　B 樹與 B+ 樹（資料庫索引的核心）

📐 m 階 B 樹（B-Tree of order m）性質 1. 每個節點最多 m 個子節點、m−1 個鍵值
2. 除根與葉外，每個節點至少有 ⌈m/2⌉ 個子節點
3. 根節點至少 2 個子節點（除非它是葉）
4. 所有葉節點都在同一層（完美平衡）
5. 節點內的鍵值由小到大排序
🧒 為什麼資料庫要用 B 樹而不是二元樹

因為硬碟很慢。從硬碟讀一次資料（一次 I/O）比 CPU 運算慢幾萬倍，所以目標是「讀最少次數的硬碟」。

二元樹每個節點只有 2 個分支，100 萬筆資料要走 20 層 → 20 次硬碟存取。

但硬碟一次讀取的最小單位是一個「區塊」（例如 4KB），既然一次就要讀 4KB，何不把 4KB 塞滿鍵值？假設一個節點能放 100 個鍵值（101 個分支），100 萬筆資料只要 3 層就裝得下（101³ ≈ 100 萬）→ 只要 3 次硬碟存取。

這就是 B 樹的全部精神：用「寬而淺」換取「硬碟存取次數少」。

B 樹 vs B+ 樹（必考）

項目B 樹B+ 樹
資料存放位置內部節點與葉節點都存資料只有葉節點存資料，內部節點只存索引鍵
葉節點連結無葉節點以鏈結串列相連
範圍查詢需回到上層再往下（較慢）沿著葉節點的鏈結走即可（極快）
單筆查詢可能在中間層就找到（有時較快）一定要走到葉節點（路徑長度固定）
分支度較小（節點要放資料）較大（內部節點只放鍵，同樣空間能放更多）→ 樹更矮
實務應用部分檔案系統幾乎所有關聯式資料庫索引（MySQL InnoDB、Oracle）
💡 一句話記住 「B+ 樹為範圍查詢而生」。SQL 裡的 WHERE age BETWEEN 20 AND 30、ORDER BY、GROUP BY，全都受益於葉節點的鏈結串列。
這是資料結構與「資料庫應用」的交會點，兩科都會考。

5-5　堆積（Heap）

📐 定義 Heap 是一棵完整二元樹，且滿足：
最大堆積（Max-Heap）：每個父節點 ≥ 其子節點（根為最大值）
最小堆積（Min-Heap）：每個父節點 ≤ 其子節點（根為最小值）
⚠️ 最常見的誤解 Heap 不是 BST！ Heap 只保證「父子關係」，兄弟之間沒有順序，左子也不一定小於右子。
所以：Heap 的中序走訪不會得到排序結果；Heap 中搜尋任意值是 O(n)，不是 O(log n)。這是高頻考點。
操作複雜度作法
取最大／最小值O(1)直接看根節點
插入 InsertO(log n)放到最後一個位置，然後往上浮（sift-up）
刪除根 Delete-maxO(log n)把最後一個元素搬到根，然後往下沉（sift-down）
搜尋任意值O(n)沒有順序可利用
建堆 Build-HeapO(n)從最後一個非葉節點往前逐一 sift-down
🧒 為什麼建堆是 O(n) 而不是 O(n log n)

直覺會想「n 個元素各做一次 O(log n) 的調整 = n log n」。但實際上：

  • 最底層（約 n/2 個節點）是葉節點，完全不用調整
  • 倒數第二層（約 n/4 個）最多下沉 1 層
  • 倒數第三層（約 n/8 個）最多下沉 2 層

總成本 ≈ n/4×1 + n/8×2 + n/16×3 + … = n × Σ(k/2^(k+1)) ≈ n × 1 = O(n)

關鍵洞察：節點數量多的那幾層，剛好是要移動距離最短的那幾層。這是很漂亮的申論素材，寫出來會讓閱卷老師知道你真的懂。

其他堆積變形

類型特點
Min-Max Heap奇偶層交替為 min/max，可同時 O(1) 取最大與最小
Binomial Heap由多棵二項樹組成，合併（union）為 O(log n)
Fibonacci Heapdecrease-key 攤還 O(1)，使 Dijkstra 降為 O(E + V log V)
Deap（Double-ended Heap）左半為 min-heap、右半為 max-heap

6-3　圖的走訪

項目DFS 深度優先BFS 廣度優先
資料結構堆疊（或遞迴）佇列
策略一路走到底才回頭先走完同一層再往下

主要應用偵測循環、拓樸排序、找強連通元件、迷宮求解、回溯法無權圖最短路徑、分層走訪、找連通元件、社群網路「幾度關係」
🧒 白話版

DFS 像走迷宮：選一條路一直走到底，撞牆了才退回上一個路口換別條。

BFS 像水波擴散：先看所有離我 1 步的地方，再看所有 2 步的，再 3 步…所以第一次碰到目標時，一定是最短路徑（前提是每條邊長度相同）。

這也解釋了為什麼「找最短路徑」用 BFS 而不是 DFS——DFS 第一次找到的路徑可能繞很遠。

// BFS
BFS(G, s):
  visited[s] = true;  Q.enqueue(s)
  while Q 非空:
      u = Q.dequeue()
      visit(u)
      for each v in adj[u]:
          if !visited[v]:
              visited[v] = true
              Q.enqueue(v)

// DFS（遞迴）
DFS(u):
  visited[u] = true;  visit(u)
  for each v in adj[u]:
      if !visited[v]: DFS(v)

6-4　拓樸排序（Topological Sort）

對 DAG（有向無循環圖）的頂點排序，使所有邊 <u,v> 都滿足 u 排在 v 前面。

📐 Kahn 演算法（入度法） 1. 計算所有頂點的入度
2. 把入度為 0 的頂點放入佇列
3. 取出一個頂點輸出，把它的所有出邊移除（鄰居入度 −1）
4. 若有鄰居入度變 0，放入佇列
5. 重複到佇列空

若輸出的頂點數 < V，表示圖中有循環，無法拓樸排序。
複雜度：O(V + E)

應用：課程先修順序、專案工作排序（與資訊管理的 CPM 要徑法直接相關）、編譯器決定編譯順序、套件相依性解析。

拓樸排序的結果通常不唯一。申論題若問「請寫出一種拓樸排序」，寫出一組即可，但最好加一句「本圖之拓樸排序不唯一，另一可能為…」，展現理解深度。

6-5　關節點與雙連通元件

  • 關節點（Articulation Point）：刪除該頂點後，圖的連通元件數增加。
  • 橋（Bridge）：刪除該邊後圖不再連通。
  • 雙連通元件：不含關節點的最大子圖。

用 DFS + 追蹤 dfn（發現時間）與 low（可回溯的最小 dfn） 可在 O(V+E) 找出所有關節點。實務意義：網路上的關節點就是「單點故障（SPOF）」，這是資通網路科目常結合的考點。

第 7 章　最小生成樹與最短路徑

7-1　最小生成樹（MST）

在加權連通無向圖中，找出包含所有頂點、總權重最小的生成樹（n−1 條邊）。

項目Kruskal 演算法Prim 演算法
核心思想以邊為主：把所有邊由小到大排序，不成環就加入以點為主：從任一點出發，每次加入「連到樹外最便宜的邊」
關鍵資料結構並查集（Union-Find）判斷是否成環最小堆積（優先佇列）
複雜度O(E log E)相鄰矩陣 O(V²)；堆積+相鄰串列 O(E log V)
適用稀疏圖（邊少）稠密圖（邊多）
過程中的形態可能是多個森林，最後才連成一棵始終是一棵連通的樹，逐步長大
演算法類型貪婪法貪婪法
🧒 白話版：兩種蓋馬路的思路

假設要用最少的錢，讓 6 個村莊互相連通。

Kruskal：把所有可能的道路依造價從便宜排到貴，從最便宜的開始蓋，「只要不會蓋出一個繞回原地的環就蓋」。過程中可能同時有好幾組村莊各自連成小團，最後才合併。

Prim：從村莊 A 開始，每次問「從我目前已連通的這一片，往外連最便宜的路是哪條」，蓋那條。永遠只有一片，越長越大。

兩種都保證得到最省的總造價（這是 MST 的美妙之處），只是過程長相不同。

📐 Kruskal 手算範例與實作 邊：AB=1、CD=2、BC=3、AD=4、BD=5、AC=6　（V=4，需 3 條邊）

排序後：AB(1)、CD(2)、BC(3)、AD(4)、BD(5)、AC(6)
① AB(1) → 不成環，加入　{A,B} {C} {D}
② CD(2) → 不成環，加入　{A,B} {C,D}
③ BC(3) → 不成環，加入　{A,B,C,D} ← 已 3 條邊，結束

MST 權重 = 1 + 2 + 3 = 6

C++ 實作 (Union-Find 概念)

struct Edge { int u, v, weight; };
bool compare(Edge a, Edge b) { return a.weight < b.weight; }

int parent[100];
int find(int i) {
    if (parent[i] == i) return i;
    return parent[i] = find(parent[i]); // Path compression
}
void unite(int i, int j) { parent[find(i)] = find(j); }

void kruskal(vector<Edge>& edges, int V) {
    sort(edges.begin(), edges.end(), compare);
    for(int i = 0; i < V; i++) parent[i] = i;
    int mst_weight = 0;
    for(Edge e : edges) {
        if(find(e.u) != find(e.v)) {
            unite(e.u, e.v);
            mst_weight += e.weight;
        }
    }
}

Python 實作

def kruskal(edges, V):
    edges.sort(key=lambda x: x[2]) # (u, v, weight)
    parent = [i for i in range(V)]
    
    def find(i):
        if parent[i] != i:
            parent[i] = find(parent[i])
        return parent[i]
        
    mst_weight = 0
    for u, v, weight in edges:
        root_u = find(u)
        root_v = find(v)
        if root_u != root_v:
            parent[root_u] = root_v
            mst_weight += weight
    return mst_weight
💡 並查集（Union-Find） Kruskal 需要快速判斷「兩個點是否已在同一集合」。並查集用兩個技巧達到近乎 O(1)：
(1) 路徑壓縮（Path Compression）：find 時把路上的節點都直接指向根
(2) 依大小／高度合併（Union by Rank）：小樹掛到大樹底下
兩者併用後，m 次操作的攤還複雜度為 O(m · α(n))，α 是反 Ackermann 函數，實務上 < 5，可視為常數。

7-2　單源最短路徑：Dijkstra

📐 Dijkstra 演算法 1. dist[起點]=0，其餘 = ∞；建立未訪問集合 S
2. 從 S 中取出 dist 最小的頂點 u，標記為已確定
3. 鬆弛（Relaxation）：對 u 的每個鄰居 v，若 dist[u] + w(u,v) < dist[v]，則更新 dist[v]
4. 重複到 S 空

複雜度：陣列 O(V²)；二元堆積 O((V+E) log V)；Fibonacci Heap O(E + V log V)

C++ 實作 (Priority Queue)

void dijkstra(int start, int V, vector<pair<int,int>> adj[]) {
    priority_queue<pair<int,int>, vector<pair<int,int>>, greater<pair<int,int>>> pq;
    vector<int> dist(V, INF);
    pq.push({0, start});
    dist[start] = 0;
    
    while(!pq.empty()) {
        int u = pq.top().second;
        int d = pq.top().first;
        pq.pop();
        
        if (d > dist[u]) continue; // Lazy deletion
        
        for(auto edge : adj[u]) {
            int v = edge.first;
            int weight = edge.second;
            if(dist[u] + weight < dist[v]) {
                dist[v] = dist[u] + weight;
                pq.push({dist[v], v});
            }
        }
    }
}

Python 實作 (heapq)

import heapq

def dijkstra(start, V, adj):
    dist = [float('inf')] * V
    dist[start] = 0
    pq = [(0, start)]
    
    while pq:
        d, u = heapq.heappop(pq)
        
        if d > dist[u]:
            continue
            
        for v, weight in adj[u]:
            if dist[u] + weight < dist[v]:
                dist[v] = dist[u] + weight
                heapq.heappush(pq, (dist[v], v))
    return dist
⚠️ Dijkstra 不能處理負權邊 因為它一旦「確定」某個頂點的最短距離就不再回頭修改。若有負權邊，後來可能出現更短的路徑，但已經來不及了。
有負權邊時要用 Bellman-Ford。這是最高頻的申論考點之一，一定要能舉出反例：
A→B 權重 2、A→C 權重 5、C→B 權重 −4。Dijkstra 會先確定 B=2，但實際最短是 A→C→B = 1。

7-3　Bellman-Ford 與 Floyd-Warshall

演算法解決問題負權邊複雜度核心作法
Dijkstra單源最短路徑❌ 不可O((V+E) log V)貪婪＋優先佇列
Bellman-Ford單源最短路徑✅ 可（並能偵測負權循環）O(V·E)對所有邊鬆弛 V−1 次
Floyd-Warshall所有點對最短路徑✅ 可（無負循環）O(V³)動態規劃，三層迴圈
BFS單源最短路徑僅限無權圖O(V+E)逐層擴散
// Floyd-Warshall：k 一定要放最外層！
for k = 1 to V:           // 允許經過的中繼點
  for i = 1 to V:
    for j = 1 to V:
      if d[i][k] + d[k][j] < d[i][j]:
          d[i][j] = d[i][k] + d[k][j]
Floyd-Warshall 的 DP 語意：d(k)[i][j] = 只允許用前 k 個頂點當中繼時，i 到 j 的最短距離。
k 若不放最外層，語意就錯了——這是考程式碼填空題的重點。
偵測負權循環：跑完後若存在 d[i][i] < 0，代表有負權循環。

8-2　什麼是「穩定」

🧒 白話版

假設有一份成績單，已經按姓名排好。現在你要按分數重新排序。

兩個人都考 85 分：小明（原本排前面）、小華（原本排後面）。

  • 穩定排序：排完後小明還是在小華前面（維持原本的相對順序）
  • 不穩定排序：可能變成小華在前面

為什麼實務上重要？因為多欄位排序。要「先按部門、再按年資」排序時，可以先按年資排、再用穩定排序按部門排——這樣同部門內的年資順序會保留下來。如果第二次用不穩定排序，第一次的排序結果就毀了。

8-3　Quick Sort 詳解（最常考的一個）

📐 步驟 1. 選一個樞紐（pivot）
2. 分割（Partition）：把小於 pivot 的放左邊、大於的放右邊，pivot 歸位
3. 對左右兩半遞迴 
quickSort(A, low, high):
  if low < high:
      p = partition(A, low, high)
      quickSort(A, low, p−1)
      quickSort(A, p+1, high)

partition(A, low, high):        // Lomuto 分割法
  pivot = A[high];  i = low − 1
  for j = low to high−1:
      if A[j] <= pivot:
          i++;  swap(A[i], A[j])
  swap(A[i+1], A[high])
  return i+1
⚠️ 最壞情況 O(n²) 何時發生 當每次分割都極度不平均（一邊 0 個、一邊 n−1 個）。最典型的情況：資料已經排序好（或完全反序），而 pivot 固定取第一個或最後一個元素。
這是最反直覺的一點：Quick Sort 在「已排序資料」上表現最差，而 Insertion Sort 在已排序資料上表現最好（O(n)）。考試很愛考這個對比。

改善方法（申論要寫出來）

  • 隨機化樞紐（Randomized Quicksort）：隨機挑 pivot，使最壞情況機率極低。
  • 三數取中（Median-of-Three）：取首、中、尾三個數的中位數當 pivot。
  • 小陣列改用 Insertion Sort：n < 10～20 時遞迴開銷不值得。
  • Introsort：遞迴深度超過 2log n 時改用 Heap Sort，保證最壞 O(n log n)。C++ STL 的 std::sort 就是這樣做的。
  • 三路分割：處理大量重複值時效率更好。

8-4　Merge Sort 與 Heap Sort

Merge Sort

分割 → 遞迴排序 → 合併兩個已排序陣列。合併是 O(n)、共 log n 層 → O(n log n)，任何情況都是。

  • 優點：穩定、複雜度有保證、適合外部排序（資料放不進記憶體時）、適合鏈結串列（可 O(1) 空間）。
  • 缺點：陣列版需 O(n) 額外空間。

Heap Sort

先 Build-Heap（O(n)），然後重複「把根（最大值）與最後一個元素交換、堆積縮小 1、sift-down」n−1 次（O(n log n)）。

  • 優點：O(1) 額外空間、最壞情況仍 O(n log n)。
  • 缺點：不穩定、快取局部性差（跳著存取），實測常比 Quick Sort 慢。

8-5　線性時間排序（不用比較的排序）

📐 比較排序的理論下界 任何基於比較的排序，最壞情況至少需要 Ω(n log n) 次比較。

證明概念（決策樹論證）：n 個元素有 n! 種可能排列，每次比較只能二分（樹的分支度 2），要區分 n! 種結果，決策樹高度至少 log₂(n!)。由 Stirling 公式 log₂(n!) = Θ(n log n)。
這個證明是高頻申論題，把上面三行寫出來就有分。

要突破 n log n，就不能用比較，改用「資料本身的值當索引」：

演算法作法限制
計數排序 Counting統計每個值出現幾次，再依序輸出只適用整數且範圍 k 不大；k 很大時空間爆炸
基數排序 Radix從最低位（LSD）或最高位（MSD）逐位用穩定排序需要固定位數 d；d 大時退化
桶子排序 Bucket把資料分到若干桶，各桶內排序後串接資料需均勻分布，否則最壞 O(n²)
基數排序的每一輪必須使用穩定排序（通常用計數排序），否則前幾輪的結果會被破壞。這是很常考的細節。

binarySearch(A, key):
  low = 0;  high = n − 1
  while low <= high:
      mid = low + (high − low) / 2   // 不寫 (low+high)/2 以免溢位
      if A[mid] == key: return mid
      else if A[mid] < key: low = mid + 1
      else high = mid − 1
  return −1

10-1　分治 vs 動態規劃（必考比較）

🧒 用費氏數列看差別

計算 F(5)，樸素遞迴會這樣展開：

F(5)
├ F(4)
│ ├ F(3)
│ │ ├ F(2) ← 算過
│ │ └ F(1)
│ └ F(2) ← 又算一次！
└ F(3) ← 又算一次！
  ├ F(2) ← 第三次！
  └ F(1)

看到 F(2)、F(3) 被重複計算了嗎？這就是「重疊子問題（Overlapping Subproblems）」。

DP 的作法很簡單：算過就記在表格裡，下次直接查表。複雜度從 O(1.618ⁿ) 降到 O(n)。

而 Merge Sort 的子問題（左半、右半）完全不重疊，記下來沒有意義——所以它是分治，不是 DP。

結論：分治的子問題互相獨立；DP 的子問題重疊。這是唯一也是最關鍵的差別。

DP 的兩個必要條件

  1. 最佳子結構（Optimal Substructure）：大問題的最佳解包含子問題的最佳解。
  2. 重疊子問題（Overlapping Subproblems）：同一個子問題會被反覆求解。

DP 的兩種實作方式

方式作法優點缺點
自上而下＋備忘錄
(Top-down / Memoization)		遞迴 ＋ 查表只算需要的子問題、程式直觀遞迴呼叫開銷、可能堆疊溢位
自下而上
(Bottom-up / Tabulation)		迴圈由小填到大無遞迴開銷、可做空間優化可能算了不需要的子問題

10-2　經典 DP 題型

0/1 背包問題（Knapsack）

📐 遞迴式 dp[i][w] = max( dp[i−1][w] ,　dp[i−1][w − wᵢ] + vᵢ )
（不放第 i 個物品　／　放第 i 個物品）

複雜度：時間 O(n·W)、空間 O(n·W)（可壓成 O(W)）

注意：這是「擬多項式時間（pseudo-polynomial）」，因為 W 是數值大小而非輸入位元數。0/1 背包本質上是 NP-Complete。
問題可用貪婪法？原因
分數背包（可切割）✅ 可按單位價值排序，貪心取即為最佳
0/1 背包（不可切割）❌ 不可貪心可能因為「塞不進」而浪費空間，需 DP

最長共同子序列（LCS）

if X[i] == Y[j]:　dp[i][j] = dp[i−1][j−1] + 1
else:　dp[i][j] = max(dp[i−1][j], dp[i][j−1])

複雜度 O(m·n)。應用：DNA 序列比對、diff 檔案比較、版本控制。

注意區分：子序列（Subsequence，可不連續）vs 子字串（Substring，必須連續）。考題常在這裡設陷阱。

矩陣鏈乘法（Matrix Chain Multiplication）

求最少純量乘法次數的加括號方式。dp[i][j] = min over k { dp[i][k] + dp[k+1][j] + pᵢ₋₁·p_k·p_j }，複雜度 O(n³)。

10-3　貪婪法什麼時候會失敗

⚠️ 經典反例：找零錢問題 幣值 {1, 5, 10, 25}：找 30 元 → 貪婪取 25+5 = 2 個硬幣，正確。

幣值 {1, 3, 4}：找 6 元 → 貪婪取 4+1+1 = 3 個硬幣；但最佳解是 3+3 = 2 個硬幣。

結論：貪婪法只在問題具備「貪婪選擇性質」時才正確，不能想當然。 申論題要求「說明貪婪法之限制」時，這個例子是最好的答案。

🧒 白話版：P 與 NP 的差別

P 是「好解的」：像解一元二次方程式，有公式，套進去就有答案。

NP 是「好檢查的」：像數獨。要你從空白盤面解出來很難（可能要試很久），但如果我拿一個填好的盤面給你，你10 秒就能檢查對不對。

P = NP 嗎？ 這就是那個著名的百萬美元問題。直覺上「好檢查」不代表「好解」（否則所有密碼都不安全了），但目前沒有人能證明。主流相信 P ≠ NP。

顯然 P ⊆ NP（能算出來當然就能檢查）。

💡 實務意義（申論結論可以這樣寫） 一旦證明某問題是 NP-Complete，實務上就不再追求最佳解，改採：
(1) 近似演算法（Approximation，保證誤差在某倍數內）
(2) 啟發式演算法（Heuristic，如貪婪、模擬退火、基因演算法）
(3) 限制輸入規模或特殊結構（如樹狀圖上的問題可能變簡單）
(4) 整數規劃求解器（實務上對中等規模問題往往夠用）

歸約（Reduction）：若問題 A 可在多項式時間轉換為問題 B（A ≤ₚ B），則 B 至少和 A 一樣難。證明某問題是 NP-Complete 的標準流程是：(1) 證明它屬於 NP；(2) 找一個已知的 NP-Complete 問題歸約到它。Cook-Levin 定理證明了 SAT 是第一個 NP-Complete 問題。

最容易被考倒的 12 個觀念

  1. Heap 不是 BST，中序走訪不會排序，搜尋任意值 O(n)。
  2. Quick Sort 在已排序資料上最慢（O(n²)），Insertion Sort 最快（O(n)）。
  3. 前序 + 後序無法唯一還原二元樹。
  4. Dijkstra 不能有負權邊。
  5. Build-Heap 是 O(n)，不是 O(n log n)。
  6. 穩定排序：泡插合、計基桶；不穩定：選快堆謝。
  7. n₀ = n₂ + 1（樹葉數 = 分支度 2 的節點數 + 1）。
  8. B+ 樹只有葉節點存資料，且葉節點相連（範圍查詢快）。
  9. 比較排序的下界是 Ω(n log n)，要更快必須不用比較。
  10. 分治的子問題獨立，DP 的子問題重疊。
  11. 開放定址不能直接刪除，要用墓碑標記。
  12. 作業系統不是演算法（不會終止，違反有限性）。
