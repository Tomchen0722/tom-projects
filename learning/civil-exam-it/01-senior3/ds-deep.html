深化 1　複雜度：三種漸進符號的嚴謹定義與常見誤用

1-1　三個符號的正式定義

符號定義白話
O(g(n))存在正常數 c 與 n₀，使得對所有 n ≥ n₀，0 ≤ f(n) ≤ c·g(n)上界（最多這麼慢）
Ω(g(n))存在正常數 c 與 n₀，使得對所有 n ≥ n₀，0 ≤ c·g(n) ≤ f(n)下界（至少這麼慢）
Θ(g(n))同時是 O 與 Ω緊界（就是這麼慢）
⚠️ 三個最常見的誤用

① 「插入排序的複雜度是 O(n²)」——這句話沒錯，但不精確。
正確說法：最壞情形是 Θ(n²)，最好情形是 Θ(n)。
因為 O 只是上界，說「插入排序是 O(n³)」在數學上也成立（只是沒有意義）。

② 「最壞情形」與「上界」是兩個獨立的概念，常被混為一談。
可以說「最好情形是 O(n)」，也可以說「最壞情形是 Ω(n²)」——情形（case）講的是輸入，符號（O/Ω/Θ）講的是界限方向。

③ 「n² + 100n 的複雜度是 O(n²)，所以 100n 可以忽略」——在 n 很大時對，在考題給的具體數字下未必。
若 n = 50，則 n² = 2,500 而 100n = 5,000——低次項反而比較大。
這正是「小資料量時 O(n²) 的插入排序比 O(n log n) 的合併排序快」的原因。

1-2　為什麼「常數可以忽略」是一個假設，而不是事實

漸進分析忽略常數，前提是「我們比較的是 n 趨近無限大時的行為」。但公務系統的實際資料量往往是有限且可預估的，此時常數就會顯現：

情境漸進複雜度相同實際差異的來源
陣列走訪 vs 鏈結串列走訪都是 Θ(n)快取命中率——陣列連續存放，一次載入取得多個元素；鏈結串列幾乎每次都是快取失誤
兩種 O(n log n) 排序相同常數因子、額外記憶體配置、比較函數的成本
兩種 O(1) 雜湊相同雜湊函數本身的計算成本、碰撞處理方式
💡 申論怎麼寫才完整
「本案兩方案漸進複雜度同為 O(n log n)，惟考量實際資料量約 5 萬筆、且需頻繁隨機存取，選擇陣列基礎之實作，以取得較佳之記憶體區域性；並建議以接近正式環境之資料量進行基準測試驗證。」

——同時展現了「懂理論」與「知道理論的界線」，這是高考三級要的層次。
✅ 深化 1 必背結論 ① O 是上界、Ω 是下界、Θ 是緊界；「情形」與「界限方向」是兩個獨立維度。
② 漸進分析忽略常數，是「n 趨近無限」的假設；有限資料量下常數與快取效應會主導。
③ 複雜度回答「規模成長的趨勢」，不回答「實際速度」——後者只能量測。

深化 2　遞迴式求解三法：代入、遞迴樹、主定理

2-1　主定理（Master Theorem）的完整敘述與適用界線

形式：T(n) = a·T(n/b) + f(n)，其中 a ≥ 1、b > 1。令 nlog_b a 為「分割項」。

情形條件結果直覺
情形一f(n) = O(nlog_b a − ε)T(n) = Θ(nlog_b a)葉節點主導（分割成本較小）
情形二f(n) = Θ(nlog_b a)T(n) = Θ(nlog_b a · log n)各層平均分攤
情形三f(n) = Ω(nlog_b a + ε) 且滿足正規條件 a·f(n/b) ≤ c·f(n)T(n) = Θ(f(n))根節點主導（合併成本較大）

2-2　常考遞迴式一次算完

遞迴式a, bnlog_b a情形解對應演算法
T(n)=2T(n/2)+O(n)2, 2n¹二Θ(n log n)合併排序
T(n)=2T(n/2)+O(1)2, 2n¹一Θ(n)二元樹走訪
T(n)=T(n/2)+O(1)1, 2n⁰=1二Θ(log n)二分搜尋
T(n)=T(n/2)+O(n)1, 21三Θ(n)Quickselect（期望）
T(n)=4T(n/2)+O(n)4, 2n²一Θ(n²)樸素矩陣相乘
T(n)=7T(n/2)+O(n²)7, 2n^2.807一Θ(n^2.807)Strassen 矩陣相乘
T(n)=3T(n/4)+O(n²)3, 4n^0.79三Θ(n²)—
⚠️ 主定理用不上的三種情形（考題常在這裡設陷阱）
① 子問題大小不一：T(n)=T(n/3)+T(2n/3)+O(n) → 主定理形式不符，須用遞迴樹。
　（答案是 Θ(n log n)：每層總工作量仍為 O(n)，最深路徑長 log_{3/2} n。）
② 減法型遞迴：T(n)=T(n−1)+O(n) → 主定理只處理除法型，須直接展開。
　（答案是 Θ(n²)：n + (n−1) + … + 1。）
③ 落在情形一與二之間的間隙：如 f(n) = nlog_b a·log n，三種情形都不適用，須用擴充版主定理。

2-3　遞迴樹法：把它畫出來就會了

以 T(n) = T(n/3) + T(2n/3) + n 為例：

第 0 層：            n                       總計 n
第 1 層：      n/3        2n/3                 總計 n
第 2 層：   n/9  2n/9  2n/9  4n/9              總計 n
   ⋮
每一層的總工作量都是 n（因為子問題大小加起來仍是 n）
最短路徑：一直往 n/3 走 → 深度 log₃ n
最長路徑：一直往 2n/3 走 → 深度 log_{3/2} n

總計 = n × 層數 = Θ(n log n)
💡 重要洞見：分割「不必平均」也能維持 Θ(n log n)
只要分割比例是常數比例（1:2、1:9 都行），深度就仍是 Θ(log n)。
這解釋了為何快速排序即使 pivot 選得不完美通常仍很快——只有在極端不平均（1 : n−1）時才退化為 Θ(n²)。
✅ 深化 2 必背結論 ① 主定理只適用 T(n)=aT(n/b)+f(n)；比較 f(n) 與 nlog_b a 的大小定情形。
② 子問題大小不一 → 遞迴樹；減法型遞迴 → 直接展開。
③ 常數比例的不平均分割，深度仍是 Θ(log n)。

深化 3　攤還分析：聚合法、記帳法、位能法

攤還分析回答的問題是：「單次操作最壞可能很慢，但一連串操作的平均成本是多少？」——注意它與「平均情形分析」不同：攤還分析不涉及機率，它是對「任意一連串操作」的保證。

3-1　三種方法的比較

方法做法適用
聚合法算出 n 次操作的總成本，再除以 n最簡單，但只給「平均」不區分操作類型
記帳法對便宜的操作「多收費」，存起來付給昂貴的操作直覺好，須證明存款不會透支
位能法定義位能函數 Φ；攤還成本 = 實際成本 + ΔΦ最有力，適用複雜結構

3-2　經典例子：動態陣列的倍增擴充

陣列滿了就配置兩倍大的新陣列並複製過去。單次插入最壞是 O(n)（要複製），但攤還成本是 O(1)。

聚合法證明：
n 次插入中，擴充只發生在容量為 1, 2, 4, 8, …, 2^k 時。
複製的總成本 = 1 + 2 + 4 + … + 2^k < 2·2^k ≤ 2n（等比級數）。
加上 n 次插入本身的 O(n)，總成本 < 3n。
→ 攤還成本 = 3n / n = O(1) ∎
⚠️ 為何一定要「倍增」而不是「每次加固定量」
若每次只加 c 個位置，擴充會發生 n/c 次，每次複製約 n 個元素 → 總成本 Θ(n²/c) = Θ(n²) → 攤還成本變成 Θ(n)。
「倍增」才能讓等比級數收斂——這是攤還分析最經典的結論。

3-3　其他常考的攤還結論

結構或操作單次最壞攤還理由
動態陣列插入O(n)O(1)倍增擴充，等比級數
雜湊表插入（含 rehash）O(n)O(1)同上
併查集（路徑壓縮＋按秩合併）—O(α(n))，近乎常數位能法
兩個堆疊模擬佇列O(n)O(1)每個元素最多被搬動一次
二進位計數器加一O(log n)O(1)記帳法：翻成 1 時預收，翻回 0 時支付
LSM-Tree 寫入O(n)（合併時）接近 O(1)順序寫 ＋ 分層合併
✅ 深化 3 必背結論 ① 攤還分析是「一連串操作的保證」，不涉及機率，與平均情形分析不同。
② 動態陣列必須「倍增」擴充，攤還才是 O(1)；固定量擴充會退化成 Θ(n)。
③ 併查集加上路徑壓縮與按秩合併後，攤還為 O(α(n))，實務上視為常數。

深化 4　樹的數學性質：全部推導一次

4-1　五個必背等式與它們的證明

① n₀ = n₂ + 1（葉節點數 = 度為 2 的節點數 + 1）
證明：設節點總數 n = n₀ + n₁ + n₂。
邊數 = n − 1（樹的性質）。
另一方面，每個節點貢獻的子節點數 = 0·n₀ + 1·n₁ + 2·n₂ = 邊數。
故 n₁ + 2n₂ = n₀ + n₁ + n₂ − 1 → n₀ = n₂ + 1 ∎

② n 個節點的二元樹，空鏈結（null link）有 n + 1 個
證明：每個節點有 2 個鏈結欄位，共 2n 個。
其中被使用的（指向實際子節點的）恰為 n − 1 個（＝邊數）。
故空鏈結 = 2n − (n − 1) = n + 1 ∎
→ 這正是「引線二元樹（threaded binary tree）」能利用的空間。

③ 高度為 h 的二元樹，節點數介於 h+1 與 2^{h+1} − 1 之間
（高度定義為根到最深葉的邊數；最少是每層一個節點的斜樹，最多是完滿樹。）

④ n 個節點的二元樹，最小高度為 ⌊log₂ n⌋
由 ③ 反推：n ≤ 2^{h+1} − 1 → h ≥ log₂(n+1) − 1。

⑤ n 個節點可組成的相異二元樹數目 = 第 n 個 Catalan 數 = C(2n, n)/(n+1)
n=1→1、n=2→2、n=3→5、n=4→14、n=5→42。

4-2　完滿、完整、完美：三個容易混淆的名詞

名稱定義節點數
完滿二元樹（full）每個節點的度為 0 或 2必為奇數（n = 2n₀ − 1）
完整二元樹（complete）除最後一層外皆填滿，且最後一層靠左填任意；可用陣列緊密表示
完美二元樹（perfect）所有葉節點在同一層且每層填滿n = 2^{h+1} − 1
💡 為什麼堆積（Heap）一定要用「完整二元樹」
因為完整二元樹可以用陣列緊密儲存而不浪費空間：索引 i 的左子為 2i、右子為 2i+1、父為 ⌊i/2⌋（1-based）。
若允許不完整，陣列中就會出現大量空洞——這是「結構限制換取儲存效率」的經典設計。

4-3　走訪順序的還原問題（高頻計算題）

給定能否唯一還原理由
前序 ＋ 中序可以前序第一個是根，中序據以切左右子樹，遞迴
後序 ＋ 中序可以後序最後一個是根
層序 ＋ 中序可以層序第一個是根
前序 ＋ 後序不可以（一般情形）無法區分「只有左子」與「只有右子」
⚠️ 例外：若已知是「完滿二元樹」，前序＋後序可以唯一還原
因為完滿樹不存在「只有一個子節點」的情形，歧義就消失了。
考題若特別聲明「完滿二元樹」，就是在考這一點。
✅ 深化 4 必背結論 ① n₀ = n₂ + 1；空鏈結 = n + 1；相異二元樹數 = Catalan 數。
② 完滿（度 0 或 2）／完整（靠左填滿）／完美（全滿）——堆積用完整。
③ 前序＋後序一般無法唯一還原；除非是完滿二元樹。

深化 5　平衡樹：AVL 與紅黑樹的高度界證明

5-1　AVL 樹的高度上界：為什麼是 1.44 log₂ n

設 N(h) 為「高度 h 的 AVL 樹最少需要幾個節點」。

要讓節點最少，兩棵子樹的高度應差 1（平衡因子的極限）：
N(h) = N(h−1) + N(h−2) + 1，且 N(0)=1、N(1)=2

展開：N(2)=4、N(3)=7、N(4)=12、N(5)=20、N(6)=33、N(7)=54…

這個遞迴式與 Fibonacci 幾乎相同（N(h) = F(h+3) − 1），因此
N(h) ≈ φ^{h+2}/√5，其中 φ ≈ 1.618

反解得 h ≤ log_φ(n) ≈ 1.44 log₂ n ∎
💡 這個數字的意義
AVL 的高度最多比完美平衡樹高 44%——這是「保證」，不是「期望」。
對照：隨機插入的普通 BST 期望高度約 1.39 log₂ n——數字接近，但那只是期望值。
而公務資料常依時間或編號順序產生（接近已排序），正是普通 BST 的最壞情形（退化成鏈結串列，高度 n）——所以必須用自平衡樹。

5-2　AVL 四種旋轉的判別法

失衡型態判別處理
LL左子樹的左邊過高右旋一次
RR右子樹的右邊過高左旋一次
LR左子樹的右邊過高先對左子左旋，再對根右旋
RL右子樹的左邊過高先對右子右旋，再對根左旋
⚠️ 插入與刪除的旋轉次數不同
插入：最多 一次旋轉（單旋或雙旋）就能恢復平衡。
刪除：可能需要沿著路徑一路旋轉到根，最多 O(log n) 次。
這是 AVL 常考的細節，也是紅黑樹在「刪除頻繁」的場景較受青睞的原因之一。

5-3　紅黑樹：五個性質與高度界

性質
①每個節點非紅即黑
②根為黑
③所有葉（NIL）為黑
④紅節點的子節點必為黑（不得有連續兩個紅）
⑤任一節點到其後代葉的路徑，黑節點數相同（黑高相同）
高度界的推導：
由性質⑤，黑高為 bh 的子樹至少有 2^bh − 1 個內部節點。
由性質④，任一路徑上紅節點不超過黑節點，故 h ≤ 2·bh。
合併得 n ≥ 2^{h/2} − 1 → h ≤ 2·log₂(n+1) ∎

5-4　AVL vs 紅黑樹：什麼時候選哪一個

AVL紅黑樹
高度界1.44 log₂n（較嚴）2 log₂n（較鬆）
查詢較快稍慢
插入／刪除旋轉較多旋轉較少（插入最多 2 次、刪除最多 3 次）
適用讀多寫少讀寫均衡；多數標準函式庫的有序容器採用
✅ 深化 5 必背結論 ① AVL 高度上界 1.44 log₂n，由 Fibonacci 型遞迴 N(h)=N(h−1)+N(h−2)+1 推得。
② 紅黑樹高度上界 2 log₂n，由「無連續紅」＋「黑高相同」兩性質推得。
③ AVL 插入最多旋轉一次，刪除可能 O(log n) 次；紅黑樹旋轉次數有常數上界。

深化 6　B 樹與 B+ 樹：磁碟導向的完整推理

6-1　為什麼資料庫不用 AVL 或紅黑樹

🧒 白話說明

AVL 與紅黑樹的高度是 log₂n。一億筆資料 → 高度約 27 層。

如果每一層都要讀一次硬碟（隨機 I/O，約 0.1 毫秒），一次查詢就要 2.7 毫秒。

B+ 樹一個節點就是一個磁碟頁（如 8KB），可以裝下數百個鍵——高度只要 4 層，查詢只要 0.4 毫秒。

差別不在演算法巧妙，而在「一次 I/O 能帶回多少資訊」。

6-2　高度的計算（必考）

設扇出（每節點的子節點數）為 m，資料筆數為 n。
樹高 h ≈ log_m n。

例：n = 1 億、m = 200
200¹ = 200
200² = 40,000
200³ = 8,000,000
200⁴ = 1,600,000,000 ≥ 1 億
→ h = 4 層
💡 關鍵推論：資料量成長 160 倍，I/O 次數幾乎不變
從 1,000 萬（4 層）到 16 億（仍是 4 層）——而全表掃描的成本會成長 160 倍。
這就是 B+ 樹能支撐超大型資料庫的根本原因。

6-3　B 樹 vs B+ 樹：三個關鍵差異

B 樹B+ 樹
資料存放內部節點也存資料只有葉節點存資料
扇出較小（內部節點要放資料）較大（內部節點只放鍵）→ 樹更矮
範圍查詢須中序走訪，效率差葉節點串成鏈結串列，範圍掃描極快

⚠️ 為什麼資料庫索引幾乎都選 B+ 樹
因為資料庫最常見的操作是 「WHERE 日期 BETWEEN A AND B」「ORDER BY」「分頁」——全都是範圍操作。
而 B+ 樹的葉節點鏈結，讓「找到起點後往後順序讀」變成純粹的循序 I/O。

6-4　樹高何時增加：一個常考的觀念題

插入時葉節點滿了會分裂，並把中間鍵推給父節點。
只有當分裂一路傳播到根、導致根也分裂時，樹高才 +1（產生新的根）。

推論：B 樹的樹高只能「從根往上長」，不會某個分支自己變深——這正是它永遠完美平衡的原因。
✅ 深化 6 必背結論 ① B+ 樹的高度 h ≈ log_m n；1 億筆、扇出 200 時 h = 4。
② B+ 樹只有葉節點存資料且串成鏈結，範圍查詢與排序極快，故為資料庫索引的標準選擇。
③ 樹高只在「分裂傳播到根」時增加，故永遠完美平衡。

深化 7　圖演算法的正確性：為什麼 Dijkstra 是對的

7-1　Dijkstra 的貪心正確性論證

命題：當節點 u 被從優先佇列取出時，dist[u] 已是從起點 s 到 u 的最短距離。

證明（反證法）：
假設 u 被取出時 dist[u] > 真正的最短距離 δ(s,u)。
考慮真正的最短路徑 P：s → … → x → y → … → u，其中 y 是 P 上第一個尚未被取出的節點（x 已取出）。
由於 x 已取出，dist[x] = δ(s,x) 且已對邊 (x,y) 做過鬆弛 → dist[y] = δ(s,y)。
因所有邊權非負，δ(s,y) ≤ δ(s,u) < dist[u] → dist[y] < dist[u]。
那麼優先佇列應該先取出 y 而非 u——矛盾。∎
⚠️ 證明中「所有邊權非負」這一步是關鍵
若有負權邊，δ(s,y) ≤ δ(s,u) 就不成立（後面可能有負邊把總長拉低），整個論證垮掉。
這就是「Dijkstra 不能處理負權邊」的真正原因——不是實作問題，是正確性的根基被破壞。

7-2　Bellman-Ford：為什麼恰好是 V−1 輪

無負權迴路時，任兩點間的最短路徑最多包含 V−1 條邊（否則必有重複節點，即存在迴路）。
每一輪鬆弛所有邊，至少能確定「多一條邊的最短路徑」。
→ V−1 輪後所有最短路徑必已收斂。

第 V 輪若仍有邊可以鬆弛 → 必存在負權迴路。（這就是負環偵測的原理。）

7-3　MST 的兩個核心性質

性質敘述用於證明
切割性質
（cut property）		任一切割中，權重最小的橫跨邊必屬於某棵 MSTPrim 與 Kruskal 的正確性
迴路性質
（cycle property）		任一迴路中，權重最大的邊必不屬於任何 MST刪邊法的正確性
💡 MST 唯一性的判準
若所有邊的權重皆相異 → MST 唯一。
若有權重相同的邊 → MST 可能不唯一（但總權重必相同）。
考題常問「MST 是否唯一」，判準就是「有沒有等權邊」。

7-4　Prim 與 Dijkstra：只差一行

// Prim（最小生成樹）
if (w(u,v) < key[v])            key[v] = w(u,v);

// Dijkstra（最短路徑）
if (dist[u] + w(u,v) < dist[v]) dist[v] = dist[u] + w(u,v);
💡 差別的本質
Prim 問的是「這條邊本身多重」（只看邊權）——因為它要的是「把所有點連起來的總成本最小」。
Dijkstra 問的是「從起點走到這裡的累積距離」——因為它要的是「從 s 出發的最短路徑」。
✅ 深化 7 必背結論 ① Dijkstra 的正確性建立在「邊權非負」；有負權邊則證明不成立。
② Bellman-Ford 跑 V−1 輪，因最短路徑最多 V−1 條邊；第 V 輪仍可鬆弛即有負環。
③ 切割性質支撐 Prim 與 Kruskal；邊權全相異則 MST 唯一。

深化 8　排序下界：比較排序為何跨不過 n log n

8-1　決策樹論證（這是可以直接寫進申論的證明）

任何基於比較的排序演算法，都可以畫成一棵決策樹：
內部節點 = 一次比較（a < b？），分支 = 比較結果，葉節點 = 一種可能的排列。

n 個元素有 n! 種排列，演算法必須能區分全部 → 葉節點至少 n! 個。
高度 h 的二元樹最多有 2^h 個葉 → 2^h ≥ n!
取對數：h ≥ log₂(n!)
由 Stirling 近似 log₂(n!) = Θ(n log n)
→ 任何比較排序的最壞情形至少需要 Ω(n log n) 次比較 ∎

8-2　那為什麼計數排序可以 O(n)？

⚠️ 因為它「不比較」——它跳出了決策樹模型的前提
計數排序、基數排序、桶排序不做元素間的比較，而是直接用值當索引。
代價：對輸入有額外假設（值域有限、分布已知或均勻）。
演算法複雜度前提假設穩定額外空間
計數排序O(n + k)值域 k 不能太大是O(k)
基數排序O(d(n + k))固定位數 d是O(n+k)
桶排序期望 O(n)輸入均勻分布視實作O(n)
💡 公務應用的判斷
「依身分證號排序」——值域極大，計數排序不可行；
「依年齡排序」——值域 0～120，計數排序極快（O(n)）；
「依案件狀態排序」——值域約 10 種，計數排序或直接分組即可。

8-3　排序演算法完整比較表

演算法平均最壞空間穩定備註
氣泡Θ(n²)Θ(n²)O(1)是—
插入Θ(n²)Θ(n²)O(1)是近乎已排序時 Θ(n)，小陣列最快
選擇Θ(n²)Θ(n²)O(1)否交換次數最少
合併Θ(n log n)Θ(n log n)O(n)是外部排序的基礎

⚠️ 「穩定性」在公務系統是有法律意義的
先依「申請時間」排序，再依「案件類別」排序——若第二次排序不穩定，同類別內的時間順序就會被打亂。
而「先到先辦」若是公告的處理原則，順序被打亂就可能構成程序上的瑕疵。
✅ 深化 8 必背結論 ① 比較排序的下界 Ω(n log n)，由決策樹「葉節點 ≥ n!」推得。
② 計數／基數／桶排序能突破下界，因為它們不比較，代價是對輸入有額外假設。
③ 快速排序平均最快但最壞 Θ(n²)；堆積排序最壞有保證且原地；合併排序穩定且適合外部排序。

深化 9　雜湊：載入因子與探測次數的推導

9-1　兩種碰撞處理的期望成本

設載入因子 α = n / m（n 個元素、m 個槽），並假設簡單均勻雜湊。

鏈結法（chaining）：
　不成功搜尋 = 走完整條鏈 → 期望 Θ(1 + α)
　成功搜尋 = 平均走到鏈的一半 → 期望 Θ(1 + α/2)

開放定址（open addressing）：
　不成功搜尋期望探測數 ≤ 1/(1−α)
　成功搜尋期望探測數 ≤ (1/α)·ln(1/(1−α))
α開放定址·不成功開放定址·成功評價
0.502.01.39良好
0.754.01.85常見的擴表門檻
0.9010.02.56偏高
0.9520.03.15嚴重劣化
💡 為什麼是「懸崖式」下降
因為 1/(1−α) 在 α 趨近 1 時發散。從 0.75 到 0.95，α 只增加 27%，探測數卻增加 5 倍。
所以必須在達到門檻前就擴表，不能等到快滿——這是 Java HashMap 預設 0.75 的由來。

9-2　開放定址的三種探測方式

方式探測序列問題
線性探測h(k), h(k)+1, h(k)+2, …一次群聚（primary clustering）：連續佔用區塊越長越容易變更長
二次探測h(k), h(k)+1², h(k)+2², …二次群聚；且可能探測不到所有槽
雙重雜湊h₁(k) + i·h₂(k)群聚最少，最接近理論值；h₂ 須與表大小互質

9-3　刪除為什麼是開放定址的難題

⚠️ 不能直接把槽清空
因為探測序列會在「空槽」停止。若把中間的元素清空，後面的元素就再也找不到了。
解法：標記為「已刪除（tombstone）」而非「空」——但墓碑會累積，使探測變長，最終仍需重建。

→ 這是「鏈結法在刪除頻繁的場景較受青睞」的原因。

9-4　鏈結法 vs 開放定址

鏈結法開放定址
α > 1可運作（只是變慢）不可能（塞滿就無法插入）
刪除簡單需墓碑標記
記憶體指標額外開銷較省、區域性較好
快取較差較好
✅ 深化 9 必背結論 ① 鏈結法不成功搜尋 Θ(1+α)、成功 Θ(1+α/2)；開放定址不成功 ≤ 1/(1−α)。
② 開放定址的效能在 α 接近 1 時懸崖式下降，故門檻常設 0.75。
③ 開放定址的刪除須用墓碑標記；鏈結法刪除簡單且容許 α > 1。

深化 10　動態規劃與貪心：可用性的判定

10-1　動態規劃的兩個必要條件

條件意義如何檢驗

10-2　貪心法可用的判準：交換論證

證明貪心正確的標準寫法（交換論證 exchange argument）：
① 設 OPT 為某個最佳解，G 為貪心解。
② 找出兩者第一個相異之處。
③ 證明把 OPT 的該選擇「換成」貪心的選擇，結果不會變差。
④ 反覆交換，OPT 可被轉換為 G 而不變差 → G 也是最佳解 ∎
問題貪心可行？理由
活動選擇（最早結束優先）✔交換論證成立
Huffman 編碼✔合併兩個最小頻率
分數背包✔依單位價值排序
0/1 背包✘不能切割 → 須用 DP
找零（任意幣值）✘反例：幣值 {1,3,4}，湊 6 → 貪心 4+1+1（3 枚），最佳 3+3（2 枚）

⚠️ 「找零問題」是最經典的陷阱
因為用新臺幣硬幣（1、5、10、50）貪心永遠對，所以很多人以為貪心通用。
但只要換一組幣值（如 1、3、4），貪心就會失敗。考題常故意給非常規幣值。

深化 11　P、NP 與歸約：申論怎麼寫才不會出錯

11-1　四個名詞的精確定義

類別定義白話
P可在多項式時間內求解的決策問題好算
NP可在多項式時間內驗證一個解的決策問題答案給你，你能快速檢查
NP-hardNP 中所有問題都可多項式歸約到它至少和 NP 中最難的一樣難
NP-complete屬於 NP 且為 NP-hardNP 中最難的那一群
⚠️ 申論最常寫錯的三句話

✘「NP 是指無法在多項式時間解決的問題」
✔ NP 是「可在多項式時間驗證」的問題。P ⊆ NP——所有好算的問題都在 NP 裡。

✘「NP-hard 問題一定屬於 NP」
✔ 不一定。NP-hard 可能比 NP 更難（例如停機問題是 NP-hard 但不在 NP）。

✘「已證明 P ≠ NP」
✔ 這是至今未解的公開問題。只能寫「目前尚未找到多項式時間的解法，且一般認為 P ≠ NP」。

11-2　歸約的方向（考題最愛的陷阱）

💡 「A 歸約到 B」的意思是：A 不會比 B 難
若已知 A 很難，而 A 可歸約到 B → B 至少和 A 一樣難（用來證明 B 也難）。
若已知 B 很好算，而 A 可歸約到 B → A 也好算。

證明「某問題是 NP-hard」的標準做法：找一個已知的 NP-complete 問題，把它歸約到你的問題——方向千萬別寫反。

③ 證明某問題 NP-hard，是「把已知 NP-complete 問題歸約到它」——方向不可寫反。
