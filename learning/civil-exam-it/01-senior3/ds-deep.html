深化 1　複雜度：三種漸進符號的嚴謹定義與常見誤用

1-1　三個符號的正式定義

符號定義白話
O(g(n))存在正常數 c 與 n₀，使得對所有 n ≥ n₀，0 ≤ f(n) ≤ c·g(n)上界（最多這麼慢）
Ω(g(n))存在正常數 c 與 n₀，使得對所有 n ≥ n₀，0 ≤ c·g(n) ≤ f(n)下界（至少這麼慢）
Θ(g(n))同時是 O 與 Ω緊界（就是這麼慢）
⚠️ 三個最常見的誤用

① 「插入排序的複雜度是 O(n²)」——這句話沒錯，但不精確。
正確說法：最壞情形是 Θ(n²)，最好情形是 Θ(n)。
因為 O 只是上界，說「插入排序是 O(n³)」在數學上也成立（只是沒有意義）。

② 「最壞情形」與「上界」是兩個獨立的概念，常被混為一談。
可以說「最好情形是 O(n)」，也可以說「最壞情形是 Ω(n²)」——情形（case）講的是輸入，符號（O/Ω/Θ）講的是界限方向。

③ 「n² + 100n 的複雜度是 O(n²)，所以 100n 可以忽略」——在 n 很大時對，在考題給的具體數字下未必。
若 n = 50，則 n² = 2,500 而 100n = 5,000——低次項反而比較大。
這正是「小資料量時 O(n²) 的插入排序比 O(n log n) 的合併排序快」的原因。

1-2　為什麼「常數可以忽略」是一個假設，而不是事實

漸進分析忽略常數，前提是「我們比較的是 n 趨近無限大時的行為」。但公務系統的實際資料量往往是有限且可預估的，此時常數就會顯現：

情境漸進複雜度相同實際差異的來源
陣列走訪 vs 鏈結串列走訪都是 Θ(n)快取命中率——陣列連續存放，一次載入取得多個元素；鏈結串列幾乎每次都是快取失誤
兩種 O(n log n) 排序相同常數因子、額外記憶體配置、比較函數的成本
兩種 O(1) 雜湊相同雜湊函數本身的計算成本、碰撞處理方式
💡 申論怎麼寫才完整
「本案兩方案漸進複雜度同為 O(n log n)，惟考量實際資料量約 5 萬筆、且需頻繁隨機存取，選擇陣列基礎之實作，以取得較佳之記憶體區域性；並建議以接近正式環境之資料量進行基準測試驗證。」

——同時展現了「懂理論」與「知道理論的界線」，這是高考三級要的層次。
✅ 深化 1 必背結論 ① O 是上界、Ω 是下界、Θ 是緊界；「情形」與「界限方向」是兩個獨立維度。
② 漸進分析忽略常數，是「n 趨近無限」的假設；有限資料量下常數與快取效應會主導。
③ 複雜度回答「規模成長的趨勢」，不回答「實際速度」——後者只能量測。

深化 2　遞迴式求解三法：代入、遞迴樹、主定理

2-1　主定理（Master Theorem）的完整敘述與適用界線

形式：T(n) = a·T(n/b) + f(n)，其中 a ≥ 1、b > 1。令 nlog_b a 為「分割項」。

情形條件結果直覺
情形一f(n) = O(nlog_b a − ε)T(n) = Θ(nlog_b a)葉節點主導（分割成本較小）
情形二f(n) = Θ(nlog_b a)T(n) = Θ(nlog_b a · log n)各層平均分攤
情形三f(n) = Ω(nlog_b a + ε) 且滿足正規條件 a·f(n/b) ≤ c·f(n)T(n) = Θ(f(n))根節點主導（合併成本較大）

2-2　常考遞迴式一次算完

遞迴式a, bnlog_b a情形解對應演算法
T(n)=2T(n/2)+O(n)2, 2n¹二Θ(n log n)合併排序
T(n)=2T(n/2)+O(1)2, 2n¹一Θ(n)二元樹走訪
T(n)=T(n/2)+O(1)1, 2n⁰=1二Θ(log n)二分搜尋
T(n)=T(n/2)+O(n)1, 21三Θ(n)Quickselect（期望）
T(n)=4T(n/2)+O(n)4, 2n²一Θ(n²)樸素矩陣相乘
T(n)=7T(n/2)+O(n²)7, 2n^2.807一Θ(n^2.807)Strassen 矩陣相乘
T(n)=3T(n/4)+O(n²)3, 4n^0.79三Θ(n²)—
⚠️ 主定理用不上的三種情形（考題常在這裡設陷阱）
① 子問題大小不一：T(n)=T(n/3)+T(2n/3)+O(n) → 主定理形式不符，須用遞迴樹。
　（答案是 Θ(n log n)：每層總工作量仍為 O(n)，最深路徑長 log_{3/2} n。）
② 減法型遞迴：T(n)=T(n−1)+O(n) → 主定理只處理除法型，須直接展開。
　（答案是 Θ(n²)：n + (n−1) + … + 1。）
③ 落在情形一與二之間的間隙：如 f(n) = nlog_b a·log n，三種情形都不適用，須用擴充版主定理。

2-3　遞迴樹法：把它畫出來就會了

以 T(n) = T(n/3) + T(2n/3) + n 為例：

第 0 層：            n                       總計 n
第 1 層：      n/3        2n/3                 總計 n
第 2 層：   n/9  2n/9  2n/9  4n/9              總計 n
   ⋮
每一層的總工作量都是 n（因為子問題大小加起來仍是 n）
最短路徑：一直往 n/3 走 → 深度 log₃ n
最長路徑：一直往 2n/3 走 → 深度 log_{3/2} n

總計 = n × 層數 = Θ(n log n)
💡 重要洞見：分割「不必平均」也能維持 Θ(n log n)
只要分割比例是常數比例（1:2、1:9 都行），深度就仍是 Θ(log n)。
這解釋了為何快速排序即使 pivot 選得不完美通常仍很快——只有在極端不平均（1 : n−1）時才退化為 Θ(n²)。
✅ 深化 2 必背結論 ① 主定理只適用 T(n)=aT(n/b)+f(n)；比較 f(n) 與 nlog_b a 的大小定情形。
② 子問題大小不一 → 遞迴樹；減法型遞迴 → 直接展開。
③ 常數比例的不平均分割，深度仍是 Θ(log n)。

深化 3　攤還分析：聚合法、記帳法、位能法

攤還分析回答的問題是：「單次操作最壞可能很慢，但一連串操作的平均成本是多少？」——注意它與「平均情形分析」不同：攤還分析不涉及機率，它是對「任意一連串操作」的保證。

3-1　三種方法的比較

方法做法適用
聚合法算出 n 次操作的總成本，再除以 n最簡單，但只給「平均」不區分操作類型
記帳法對便宜的操作「多收費」，存起來付給昂貴的操作直覺好，須證明存款不會透支
位能法定義位能函數 Φ；攤還成本 = 實際成本 + ΔΦ最有力，適用複雜結構

3-2　經典例子：動態陣列的倍增擴充

陣列滿了就配置兩倍大的新陣列並複製過去。單次插入最壞是 O(n)（要複製），但攤還成本是 O(1)。

聚合法證明：
n 次插入中，擴充只發生在容量為 1, 2, 4, 8, …, 2^k 時。
複製的總成本 = 1 + 2 + 4 + … + 2^k < 2·2^k ≤ 2n（等比級數）。
加上 n 次插入本身的 O(n)，總成本 < 3n。
→ 攤還成本 = 3n / n = O(1) ∎
⚠️ 為何一定要「倍增」而不是「每次加固定量」
若每次只加 c 個位置，擴充會發生 n/c 次，每次複製約 n 個元素 → 總成本 Θ(n²/c) = Θ(n²) → 攤還成本變成 Θ(n)。
「倍增」才能讓等比級數收斂——這是攤還分析最經典的結論。

3-3　其他常考的攤還結論

結構或操作單次最壞攤還理由
動態陣列插入O(n)O(1)倍增擴充，等比級數
雜湊表插入（含 rehash）O(n)O(1)同上
併查集（路徑壓縮＋按秩合併）—O(α(n))，近乎常數位能法
兩個堆疊模擬佇列O(n)O(1)每個元素最多被搬動一次
二進位計數器加一O(log n)O(1)記帳法：翻成 1 時預收，翻回 0 時支付
LSM-Tree 寫入O(n)（合併時）接近 O(1)順序寫 ＋ 分層合併
✅ 深化 3 必背結論 ① 攤還分析是「一連串操作的保證」，不涉及機率，與平均情形分析不同。
② 動態陣列必須「倍增」擴充，攤還才是 O(1)；固定量擴充會退化成 Θ(n)。
③ 併查集加上路徑壓縮與按秩合併後，攤還為 O(α(n))，實務上視為常數。

深化 4　樹的數學性質：全部推導一次

4-1　五個必背等式與它們的證明

① n₀ = n₂ + 1（葉節點數 = 度為 2 的節點數 + 1）
證明：設節點總數 n = n₀ + n₁ + n₂。
邊數 = n − 1（樹的性質）。
另一方面，每個節點貢獻的子節點數 = 0·n₀ + 1·n₁ + 2·n₂ = 邊數。
故 n₁ + 2n₂ = n₀ + n₁ + n₂ − 1 → n₀ = n₂ + 1 ∎

② n 個節點的二元樹，空鏈結（null link）有 n + 1 個
證明：每個節點有 2 個鏈結欄位，共 2n 個。
其中被使用的（指向實際子節點的）恰為 n − 1 個（＝邊數）。
故空鏈結 = 2n − (n − 1) = n + 1 ∎
→ 這正是「引線二元樹（threaded binary tree）」能利用的空間。

③ 高度為 h 的二元樹，節點數介於 h+1 與 2^{h+1} − 1 之間
（高度定義為根到最深葉的邊數；最少是每層一個節點的斜樹，最多是完滿樹。）

④ n 個節點的二元樹，最小高度為 ⌊log₂ n⌋
由 ③ 反推：n ≤ 2^{h+1} − 1 → h ≥ log₂(n+1) − 1。

⑤ n 個節點可組成的相異二元樹數目 = 第 n 個 Catalan 數 = C(2n, n)/(n+1)
n=1→1、n=2→2、n=3→5、n=4→14、n=5→42。

4-2　完滿、完整、完美：三個容易混淆的名詞

名稱定義節點數
完滿二元樹（full）每個節點的度為 0 或 2必為奇數（n = 2n₀ − 1）
完整二元樹（complete）除最後一層外皆填滿，且最後一層靠左填任意；可用陣列緊密表示
完美二元樹（perfect）所有葉節點在同一層且每層填滿n = 2^{h+1} − 1
💡 為什麼堆積（Heap）一定要用「完整二元樹」
因為完整二元樹可以用陣列緊密儲存而不浪費空間：索引 i 的左子為 2i、右子為 2i+1、父為 ⌊i/2⌋（1-based）。
若允許不完整，陣列中就會出現大量空洞——這是「結構限制換取儲存效率」的經典設計。

4-3　走訪順序的還原問題（高頻計算題）

給定能否唯一還原理由
前序 ＋ 中序可以前序第一個是根，中序據以切左右子樹，遞迴
後序 ＋ 中序可以後序最後一個是根
層序 ＋ 中序可以層序第一個是根
前序 ＋ 後序不可以（一般情形）無法區分「只有左子」與「只有右子」
⚠️ 例外：若已知是「完滿二元樹」，前序＋後序可以唯一還原
因為完滿樹不存在「只有一個子節點」的情形，歧義就消失了。
考題若特別聲明「完滿二元樹」，就是在考這一點。
✅ 深化 4 必背結論 ① n₀ = n₂ + 1；空鏈結 = n + 1；相異二元樹數 = Catalan 數。
② 完滿（度 0 或 2）／完整（靠左填滿）／完美（全滿）——堆積用完整。
③ 前序＋後序一般無法唯一還原；除非是完滿二元樹。

深化 5　平衡樹：AVL 與紅黑樹的高度界證明

5-1　AVL 樹的高度上界：為什麼是 1.44 log₂ n

設 N(h) 為「高度 h 的 AVL 樹最少需要幾個節點」。

要讓節點最少，兩棵子樹的高度應差 1（平衡因子的極限）：
N(h) = N(h−1) + N(h−2) + 1，且 N(0)=1、N(1)=2

展開：N(2)=4、N(3)=7、N(4)=12、N(5)=20、N(6)=33、N(7)=54…

這個遞迴式與 Fibonacci 幾乎相同（N(h) = F(h+3) − 1），因此
N(h) ≈ φ^{h+2}/√5，其中 φ ≈ 1.618

反解得 h ≤ log_φ(n) ≈ 1.44 log₂ n ∎
💡 這個數字的意義
AVL 的高度最多比完美平衡樹高 44%——這是「保證」，不是「期望」。
對照：隨機插入的普通 BST 期望高度約 1.39 log₂ n——數字接近，但那只是期望值。
而公務資料常依時間或編號順序產生（接近已排序），正是普通 BST 的最壞情形（退化成鏈結串列，高度 n）——所以必須用自平衡樹。

5-2　AVL 四種旋轉的判別法

失衡型態判別處理
LL左子樹的左邊過高右旋一次
RR右子樹的右邊過高左旋一次
LR左子樹的右邊過高先對左子左旋，再對根右旋
RL右子樹的左邊過高先對右子右旋，再對根左旋
⚠️ 插入與刪除的旋轉次數不同
插入：最多 一次旋轉（單旋或雙旋）就能恢復平衡。
刪除：可能需要沿著路徑一路旋轉到根，最多 O(log n) 次。
這是 AVL 常考的細節，也是紅黑樹在「刪除頻繁」的場景較受青睞的原因之一。

5-3　紅黑樹：五個性質與高度界

性質
①每個節點非紅即黑
②根為黑
③所有葉（NIL）為黑
④紅節點的子節點必為黑（不得有連續兩個紅）
⑤任一節點到其後代葉的路徑，黑節點數相同（黑高相同）
高度界的推導：
由性質⑤，黑高為 bh 的子樹至少有 2^bh − 1 個內部節點。
由性質④，任一路徑上紅節點不超過黑節點，故 h ≤ 2·bh。
合併得 n ≥ 2^{h/2} − 1 → h ≤ 2·log₂(n+1) ∎

5-4　AVL vs 紅黑樹：什麼時候選哪一個

AVL紅黑樹
高度界1.44 log₂n（較嚴）2 log₂n（較鬆）
查詢較快稍慢
插入／刪除旋轉較多旋轉較少（插入最多 2 次、刪除最多 3 次）
適用讀多寫少讀寫均衡；多數標準函式庫的有序容器採用
✅ 深化 5 必背結論 ① AVL 高度上界 1.44 log₂n，由 Fibonacci 型遞迴 N(h)=N(h−1)+N(h−2)+1 推得。
② 紅黑樹高度上界 2 log₂n，由「無連續紅」＋「黑高相同」兩性質推得。
③ AVL 插入最多旋轉一次，刪除可能 O(log n) 次；紅黑樹旋轉次數有常數上界。

深化 6　B 樹與 B+ 樹：磁碟導向的完整推理

6-1　為什麼資料庫不用 AVL 或紅黑樹

🧒 白話說明

AVL 與紅黑樹的高度是 log₂n。一億筆資料 → 高度約 27 層。

如果每一層都要讀一次硬碟（隨機 I/O，約 0.1 毫秒），一次查詢就要 2.7 毫秒。

B+ 樹一個節點就是一個磁碟頁（如 8KB），可以裝下數百個鍵——高度只要 4 層，查詢只要 0.4 毫秒。

差別不在演算法巧妙，而在「一次 I/O 能帶回多少資訊」。

6-2　高度的計算（必考）

設扇出（每節點的子節點數）為 m，資料筆數為 n。
樹高 h ≈ log_m n。

例：n = 1 億、m = 200
200¹ = 200
200² = 40,000
200³ = 8,000,000
200⁴ = 1,600,000,000 ≥ 1 億
→ h = 4 層
💡 關鍵推論：資料量成長 160 倍，I/O 次數幾乎不變
從 1,000 萬（4 層）到 16 億（仍是 4 層）——而全表掃描的成本會成長 160 倍。
這就是 B+ 樹能支撐超大型資料庫的根本原因。

6-3　B 樹 vs B+ 樹：三個關鍵差異

B 樹B+ 樹
資料存放內部節點也存資料只有葉節點存資料
扇出較小（內部節點要放資料）較大（內部節點只放鍵）→ 樹更矮
範圍查詢須中序走訪，效率差葉節點串成鏈結串列，範圍掃描極快
查詢穩定性可能在淺層就找到一律走到葉層，效能穩定
⚠️ 為什麼資料庫索引幾乎都選 B+ 樹
因為資料庫最常見的操作是 「WHERE 日期 BETWEEN A AND B」「ORDER BY」「分頁」——全都是範圍操作。
而 B+ 樹的葉節點鏈結，讓「找到起點後往後順序讀」變成純粹的循序 I/O。

6-4　樹高何時增加：一個常考的觀念題

插入時葉節點滿了會分裂，並把中間鍵推給父節點。
只有當分裂一路傳播到根、導致根也分裂時，樹高才 +1（產生新的根）。

推論：B 樹的樹高只能「從根往上長」，不會某個分支自己變深——這正是它永遠完美平衡的原因。
✅ 深化 6 必背結論 ① B+ 樹的高度 h ≈ log_m n；1 億筆、扇出 200 時 h = 4。
② B+ 樹只有葉節點存資料且串成鏈結，範圍查詢與排序極快，故為資料庫索引的標準選擇。
③ 樹高只在「分裂傳播到根」時增加，故永遠完美平衡。

深化 7　圖演算法的正確性：為什麼 Dijkstra 是對的

7-1　Dijkstra 的貪心正確性論證

命題：當節點 u 被從優先佇列取出時，dist[u] 已是從起點 s 到 u 的最短距離。

證明（反證法）：
假設 u 被取出時 dist[u] > 真正的最短距離 δ(s,u)。
考慮真正的最短路徑 P：s → … → x → y → … → u，其中 y 是 P 上第一個尚未被取出的節點（x 已取出）。
由於 x 已取出，dist[x] = δ(s,x) 且已對邊 (x,y) 做過鬆弛 → dist[y] = δ(s,y)。
因所有邊權非負，δ(s,y) ≤ δ(s,u) < dist[u] → dist[y] < dist[u]。
那麼優先佇列應該先取出 y 而非 u——矛盾。∎
⚠️ 證明中「所有邊權非負」這一步是關鍵
若有負權邊，δ(s,y) ≤ δ(s,u) 就不成立（後面可能有負邊把總長拉低），整個論證垮掉。
這就是「Dijkstra 不能處理負權邊」的真正原因——不是實作問題，是正確性的根基被破壞。

7-2　Bellman-Ford：為什麼恰好是 V−1 輪

無負權迴路時，任兩點間的最短路徑最多包含 V−1 條邊（否則必有重複節點，即存在迴路）。
每一輪鬆弛所有邊，至少能確定「多一條邊的最短路徑」。
→ V−1 輪後所有最短路徑必已收斂。

第 V 輪若仍有邊可以鬆弛 → 必存在負權迴路。（這就是負環偵測的原理。）

7-3　MST 的兩個核心性質

性質敘述用於證明
切割性質
（cut property）		任一切割中，權重最小的橫跨邊必屬於某棵 MSTPrim 與 Kruskal 的正確性
迴路性質
（cycle property）		任一迴路中，權重最大的邊必不屬於任何 MST刪邊法的正確性
💡 MST 唯一性的判準
若所有邊的權重皆相異 → MST 唯一。
若有權重相同的邊 → MST 可能不唯一（但總權重必相同）。
考題常問「MST 是否唯一」，判準就是「有沒有等權邊」。

7-4　Prim 與 Dijkstra：只差一行

// Prim（最小生成樹）
if (w(u,v) < key[v])            key[v] = w(u,v);

// Dijkstra（最短路徑）
if (dist[u] + w(u,v) < dist[v]) dist[v] = dist[u] + w(u,v);
💡 差別的本質
Prim 問的是「這條邊本身多重」（只看邊權）——因為它要的是「把所有點連起來的總成本最小」。
Dijkstra 問的是「從起點走到這裡的累積距離」——因為它要的是「從 s 出發的最短路徑」。
✅ 深化 7 必背結論 ① Dijkstra 的正確性建立在「邊權非負」；有負權邊則證明不成立。
② Bellman-Ford 跑 V−1 輪，因最短路徑最多 V−1 條邊；第 V 輪仍可鬆弛即有負環。
③ 切割性質支撐 Prim 與 Kruskal；邊權全相異則 MST 唯一。

深化 8　排序下界：比較排序為何跨不過 n log n

8-1　決策樹論證（這是可以直接寫進申論的證明）

任何基於比較的排序演算法，都可以畫成一棵決策樹：
內部節點 = 一次比較（a < b？），分支 = 比較結果，葉節點 = 一種可能的排列。

n 個元素有 n! 種排列，演算法必須能區分全部 → 葉節點至少 n! 個。
高度 h 的二元樹最多有 2^h 個葉 → 2^h ≥ n!
取對數：h ≥ log₂(n!)
由 Stirling 近似 log₂(n!) = Θ(n log n)
→ 任何比較排序的最壞情形至少需要 Ω(n log n) 次比較 ∎

8-2　那為什麼計數排序可以 O(n)？

⚠️ 因為它「不比較」——它跳出了決策樹模型的前提
計數排序、基數排序、桶排序不做元素間的比較，而是直接用值當索引。
代價：對輸入有額外假設（值域有限、分布已知或均勻）。
演算法複雜度前提假設穩定額外空間
計數排序O(n + k)值域 k 不能太大是O(k)
基數排序O(d(n + k))固定位數 d是O(n+k)
桶排序期望 O(n)輸入均勻分布視實作O(n)
💡 公務應用的判斷
「依身分證號排序」——值域極大，計數排序不可行；
「依年齡排序」——值域 0～120，計數排序極快（O(n)）；
「依案件狀態排序」——值域約 10 種，計數排序或直接分組即可。

⚠️ 「穩定性」在公務系統是有法律意義的

而「先到先辦」若是公告的處理原則，順序被打亂就可能構成程序上的瑕疵。
✅ 深化 8 必背結論 ① 比較排序的下界 Ω(n log n)，由決策樹「葉節點 ≥ n!」推得。
② 計數／基數／桶排序能突破下界，因為它們不比較，代價是對輸入有額外假設。
③ 快速排序平均最快但最壞 Θ(n²)；堆積排序最壞有保證且原地；合併排序穩定且適合外部排序。

深化 9　雜湊：載入因子與探測次數的推導

9-1　兩種碰撞處理的期望成本

設載入因子 α = n / m（n 個元素、m 個槽），並假設簡單均勻雜湊。

鏈結法（chaining）：
　不成功搜尋 = 走完整條鏈 → 期望 Θ(1 + α)
　成功搜尋 = 平均走到鏈的一半 → 期望 Θ(1 + α/2)

開放定址（open addressing）：
　不成功搜尋期望探測數 ≤ 1/(1−α)
　成功搜尋期望探測數 ≤ (1/α)·ln(1/(1−α))
α開放定址·不成功開放定址·成功評價
0.502.01.39良好
0.754.01.85常見的擴表門檻

💡 為什麼是「懸崖式」下降
因為 1/(1−α) 在 α 趨近 1 時發散。從 0.75 到 0.95，α 只增加 27%，探測數卻增加 5 倍。
所以必須在達到門檻前就擴表，不能等到快滿——這是 Java HashMap 預設 0.75 的由來。

9-3　刪除為什麼是開放定址的難題

⚠️ 不能直接把槽清空
因為探測序列會在「空槽」停止。若把中間的元素清空，後面的元素就再也找不到了。
解法：標記為「已刪除（tombstone）」而非「空」——但墓碑會累積，使探測變長，最終仍需重建。

→ 這是「鏈結法在刪除頻繁的場景較受青睞」的原因。

深化 11　P、NP 與歸約：申論怎麼寫才不會出錯

11-1　四個名詞的精確定義

類別定義白話
P可在多項式時間內求解的決策問題好算
NP可在多項式時間內驗證一個解的決策問題答案給你，你能快速檢查
NP-hardNP 中所有問題都可多項式歸約到它至少和 NP 中最難的一樣難

⚠️ 申論最常寫錯的三句話

✘「NP 是指無法在多項式時間解決的問題」
✔ NP 是「可在多項式時間驗證」的問題。P ⊆ NP——所有好算的問題都在 NP 裡。

✘「NP-hard 問題一定屬於 NP」
✔ 不一定。NP-hard 可能比 NP 更難（例如停機問題是 NP-hard 但不在 NP）。

✘「已證明 P ≠ NP」
✔ 這是至今未解的公開問題。只能寫「目前尚未找到多項式時間的解法，且一般認為 P ≠ NP」。

11-2　歸約的方向（考題最愛的陷阱）

💡 「A 歸約到 B」的意思是：A 不會比 B 難
若已知 A 很難，而 A 可歸約到 B → B 至少和 A 一樣難（用來證明 B 也難）。
若已知 B 很好算，而 A 可歸約到 B → A 也好算。

證明「某問題是 NP-hard」的標準做法：找一個已知的 NP-complete 問題，把它歸約到你的問題——方向千萬別寫反。

深化 13　隨機化的力量：快速排序期望 O(n log n) 的推導

13-1　為什麼要談「期望」而不是「平均」

平均情況分析假設「輸入是隨機的」——但真實資料常常已經排序好（例如按日期匯入的案件檔）。
隨機化分析把隨機性放進演算法自己（隨機選樞紐），不論輸入長什麼樣，期望值都成立。

這個差別在申論題很值錢：「對已排序資料，傳統快排退化為 O(n²)；改用隨機樞紐後，期望仍為 O(n log n) 且與輸入分布無關。」

13-2　期望比較次數的推導

📐 用「指示變數」推導（申論可直接照抄） 設排序後的元素為 z₁ < z₂ < … < zₙ。
令 Xij = 1 表示 zi 與 zj 曾被互相比較，否則為 0。

關鍵觀察：zi 與 zj 會被比較，當且僅當 兩者之中有一個是 {zi, …, zj} 這 (j−i+1) 個元素中第一個被選為樞紐的。

（若先選到中間的某個 zk，zi 與 zj 就被分到兩邊，永遠不會再比較。）

故 P(Xij = 1) = 2 / (j − i + 1)

總期望比較次數 = ΣᵢΣⱼ 2/(j−i+1) = Σ 2·Hn ≈ 2n ln n ≈ 1.39 n log₂ n → O(n log n)
⚠️ 最常寫錯的地方 寫「隨機樞紐讓最壞情況變成 O(n log n)」是錯的——最壞情況仍然是 O(n²)（只是機率極低，約 n!⁻¹ 等級）。
正確說法：「最壞情況不變，但期望值為 O(n log n)，且不依賴輸入分布。」

13-3　三數取中 vs 隨機樞紐

策略對已排序輸入可被惡意構造攻擊成本
取首元素退化為 O(n²)是0
三數取中良好是（可構造出殺手輸入）極低
隨機樞紐良好否每次一個亂數
Introsort（混合）良好否遞迴過深即改用堆積排序，最壞保證 O(n log n)

公務系統的選擇：對外服務若使用者可控制輸入順序，應採 Introsort 或隨機樞紐——否則構成一種可被利用的演算法複雜度攻擊（送出精心排列的資料讓伺服器 CPU 爆掉）。

✅ 深化 13 必背結論 ① 兩元素被比較的機率 = 2/(j−i+1)，總和得 2n ln n
② 隨機化改變的是「與輸入分布無關」，不是改變最壞情況
③ 對外服務要防演算法複雜度攻擊 → 用 Introsort 或隨機樞紐

深化 14　建堆為何是 O(n)：一個最常被答錯的複雜度

14-1　直覺為何會騙人

常見錯誤推理：「有 n 個節點，每個下沉最多 log n 步，所以是 O(n log n)。」
這個上界成立但不緊——因為大部分節點根本不在頂端，下沉不了幾層。

14-2　嚴謹推導

📐 按層加總 高度為 h 的節點，最多有 ⌈n / 2h+1⌉ 個，每個下沉成本 O(h)。

總成本 = Σh=0log n (n / 2h+1) · h = (n/2) · Σ h/2h

而 Σh=0∞ h/2h = 2（收斂級數）

故總成本 ≤ (n/2) × 2 = n → O(n)
層（由下往上）節點數每個下沉步數該層成本
葉（h=0）n/200
h=1n/41n/4

h=3n/1633n/16

一半的節點是葉節點，成本為零——這就是直覺出錯的原因。

14-4　公務應用：Top-K 統計的正確做法

情境：從 500 萬筆案件中找出「處理天數最長的 20 件」。

錯誤做法：全部排序後取前 20 → O(n log n)，且需把 500 萬筆載入記憶體。
正確做法：維護一個大小為 20 的最小堆積，掃過一遍，比堆頂大就替換 → O(n log k)，記憶體只需 20 個元素。
✅ 深化 14 必背結論 ① 建堆 O(n)，堆積排序整體 O(n log n)——這兩個常被混為一談
② 推導關鍵：Σ h/2h 收斂到 2；一半節點是葉、成本為零
③ Top-K 用大小 k 的堆積掃一遍，O(n log k)，記憶體 O(k)

深化 15　字串比對：KMP 失敗函數與 Rabin-Karp 的推理

15-1　樸素比對為什麼慢

文字長 n、樣式長 m。樸素法每次錯位就把樣式往右移一格，把之前比對過的資訊全部丟掉 → 最壞 O(nm)。

15-2　KMP 的核心：失敗函數

📐 失敗函數的定義 π[i] = 樣式前 i 個字元中，「既是真前綴又是真後綴」的最長長度。

意義：比對失敗時，不必從頭來過，直接把樣式往右滑到「已知一定相符」的位置。

例：樣式 ABABAC

i123456
字元ABABAC
π[i]001230

在第 6 位（C）失敗時，π[5] = 3 → 樣式右滑 5−3 = 2 格，且前 3 個字元已確定相符，不用重比。

複雜度：建表 O(m) ＋ 掃描 O(n) = O(n + m)。
為什麼是線性：文字指標永不回頭；樣式指標每次回退都對應先前的一次前進，攤還後總移動不超過 2n。

15-3　Rabin-Karp：用雜湊做比對

KMPRabin-Karp
原理失敗函數跳躍滾動雜湊，O(1) 更新視窗雜湊值
平均O(n+m)O(n+m)
最壞O(n+m)O(nm)（大量雜湊碰撞時）
強項單一樣式同時比對多個樣式（把樣式雜湊值放進集合）

公務應用：敏感詞過濾、個資樣態偵測（同時比對數百個樣式）用 Rabin-Karp 或 Aho-Corasick；單一關鍵字搜尋用 KMP。

15-4　實務上的正解通常不是自己寫演算法

⚠️ 申論的加分句 「若為全文檢索需求（大量文件、多樣關鍵字、需相關性排序），應建置倒排索引而非逐次字串比對——
前者是 O(結果數)，後者是 O(全部文件總長度)。」

這句話能把「會背 KMP」提升到「知道什麼時候不該用 KMP」。
✅ 深化 15 必背結論 ① KMP 的 π[i] = 最長的「既是真前綴又是真後綴」；整體 O(n+m)
② 線性的理由：文字指標永不回頭（攤還分析）
③ 多樣式比對用 Rabin-Karp／Aho-Corasick；大量文件檢索用倒排索引

深化 16　併查集：兩個優化如何把複雜度壓到近乎常數

16-1　基本操作與樸素版的問題

Find(x)：找 x 所屬集合的代表元；Union(x,y)：合併兩集合。
樸素版可能形成一條長鏈 → Find 為 O(n)。

深化 17　最短路徑家族：一張表選對演算法

17-1　完整判準表

演算法來源負權邊複雜度何時用
BFS單源—O(V+E)所有邊權重相同
Dijkstra單源不可O((V+E) log V)一般正權圖
Bellman-Ford單源可O(VE)有負權，或需偵測負環
Floyd-Warshall全點對可（無負環）O(V³)點少、要所有點對距離
A*單源單匯不可視啟發式而定有好的距離估計（如地理座標）

17-2　為什麼 Dijkstra 遇負權會錯

📐 一個三點反例（申論可直接畫） 邊：A→B 權重 2；A→C 權重 5；C→B 權重 −4

Dijkstra 從 A 出發：先確定 B = 2（因為 2 < 5）並永久標記。
但實際最短路是 A→C→B = 5 + (−4) = 1 < 2。

根本原因：Dijkstra 的貪心正確性建立在「路徑越長距離只會增加」；負權破壞了這個前提。

17-3　A* 的可採納性條件

A* 以 f(n) = g(n) + h(n) 排序（g 為已走距離，h 為估計剩餘距離）。

可採納（Admissible）：h(n) 永不高估真實剩餘距離 → 保證找到最短路。
一致（Consistent）：h(n) ≤ cost(n,n') + h(n') → 每個節點只需展開一次。

地圖應用：用直線距離當 h 是可採納的（直線一定不長於實際路徑）；
但若用「直線距離 × 1.3」就可能高估，會更快卻不保證最短。

17-4　公務情境的正確對應

需求選什麼常見錯選

深化 18　網路流：最大流最小割與指派問題

18-1　最大流最小割定理

📐 定理 從來源 s 到匯點 t 的最大流量，等於所有 s-t 割中容量最小者。

直覺：流量最終一定要穿過每一個「把 s 與 t 分開的切面」；
所以最窄的那個切面就是瓶頸。

公務意義：問「這個系統最多能同時服務多少人」時，答案就是找出瓶頸環節——擴充非瓶頸環節完全沒有用。

18-2　二分圖最大匹配 = 最大流

建模方法（申論必背的轉換技巧）：
①加一個超級來源 s，連向所有「人員」，容量 1
②每個人員連向他能做的「任務」，容量 1
③所有任務連向超級匯點 t，容量 1
④求 s→t 最大流 = 最多能配對幾組
公務情境左側右側邊的意義
稽查人員排班稽查員待查場所該員具備該類證照
志工媒合志工服務時段該志工可服務該時段
公宅配租申請戶房型符合資格條件
避難收容分配受災戶收容處所距離可達；容量改為收容上限

加上容量就從「匹配」升級為「最小成本流」——避難所可收 200 人時，把 t 端的容量設為 200 即可。

18-3　最小成本流：同時考慮公平

⚠️ 純最佳化的公務陷阱 把「總距離最小」設為唯一目標，可能讓某一戶被分配到極遠的收容所——總和最佳但個別極差。

公務上的正確做法：
①加入硬約束（任何一戶距離不得超過 X 公里）
②或改為最小化最大值（Minimax）而非最小化總和
③保留人工調整與申訴機制
✅ 深化 18 必背結論 ① 最大流 = 最小割；擴充非瓶頸環節無效
② 二分匹配的建模：超級來源 → 人 → 任務 → 超級匯點，容量皆 1
③ 有上限就設容量；公務上要加公平性約束，不能只最佳化總和

深化 19　快取局部性：為什麼理論最佳不等於實際最快

19-1　一個違反直覺的事實

對 100 萬筆資料做「循序走訪」，陣列比鏈結串列快 10 倍以上——
即使兩者的漸進複雜度都是 O(n)。

原因：CPU 讀記憶體是以「快取線」（通常 64 位元組）為單位整批讀取。
陣列元素在記憶體中連續 → 讀一次就拿到十幾個元素；
鏈結串列節點散落各處 → 每個節點都是一次快取未命中，要等主記憶體。

19-2　記憶體階層的延遲差距（數量級記憶）

類型意思如何善用
時間局部性剛用過的資料很快會再用快取、記憶化
空間局部性用了某個位址，附近的很快會被用連續儲存、循序存取
📐 實務三條規則 ① 大量循序處理 → 用陣列或連續配置，不要用鏈結串列
② 二維陣列走訪 → 依儲存順序走（列為主就先跑列），順序寫錯效能可差數倍
③ 大檔案處理 → 分塊讀取（Buffer），不要一筆一筆讀

19-4　公務系統的實際案例

⚠️ 申論加分段落 「本系統效能瓶頸經分析並非演算法複雜度，而在磁碟 I/O 次數。
因此改善方向為：①建立適當索引以減少掃描 ②批次讀取取代逐筆查詢（消除 N+1） ③熱資料快取於記憶體——
三者皆屬常數項的改善，卻可帶來數十倍的實際效能提升。」

這段話展現的是「懂實務」，比多背一個演算法有價值。
✅ 深化 19 必背結論 ① 同為 O(n)，陣列因空間局部性遠快於鏈結串列
② 磁碟比記憶體慢約 10⁵～10⁷ 倍 → B+ 樹寧可增加比較、減少 I/O
③ 實務調校往往在常數項：索引、批次、快取

深化 20　外部排序：資料放不進記憶體時怎麼辦

20-1　問題設定

要排序 50 GB 的案件檔，但伺服器只有 8 GB 記憶體。所有「把資料載入記憶體再排序」的方法全部失效。

20-2　多路合併排序（標準解）

📐 兩階段 【階段一】產生排序好的區段（Run）
每次讀入記憶體裝得下的量（如 4 GB），在記憶體內排序，寫回磁碟成為一個區段。
50 GB ÷ 4 GB → 得到 13 個已排序區段。

【階段二】多路合併
同時開啟 13 個區段，各讀一小塊進記憶體；
用最小堆積反覆取出當前最小值寫出 → 一次掃過即完成。

總 I/O：讀 1 次 ＋ 寫 1 次 ＋ 合併時再讀寫 1 次 = 約 2 遍資料量

20-3　關鍵參數的取捨

參數調大調小
區段大小區段數變少，合併輪數少記憶體壓力小但區段多
合併路數 k合併輪數 = logk(區段數)，k 越大輪數越少每路的緩衝區可以大一點
緩衝區大小減少隨機 I/O，磁碟友善可支援更多路

取捨的本質：k 越大輪數越少，但每一路分到的緩衝區越小、隨機 I/O 越多。實務上取一個折衷值，而非極大化 k。

20-4　公務系統的外部處理場景

情境做法
年度全國資料勾稽雙方各自排序後雙指標合併掃描，避免全部載入
大量匯入前的去重外部排序後掃一遍找相鄰重複
跨機關名冊比對小檔建雜湊集合、大檔串流掃過（記憶體只需裝小檔）
日誌分析分塊處理 ＋ 逐塊彙總，最後合併結果
💡 更務實的第一選擇
在公務環境中，這類需求應優先交給資料庫——資料庫的排序、合併與外部暫存已經高度最佳化，
自己寫外部排序通常只在「資料不在資料庫內」（如純檔案交換）時才需要。
✅ 深化 20 必背結論 ① 外部排序 = 分段排序 ＋ 多路合併，約 2 遍 I/O
② 合併時用最小堆積選出 k 路中的最小值
③ k 不是越大越好——緩衝區會變小，隨機 I/O 增加
④ 公務上優先交給資料庫處理

深化 21　布隆過濾器：誤判率公式與它的正確用法

21-1　結構與操作

一個 m 位元的位元陣列 ＋ k 個獨立雜湊函數。
加入：把 k 個雜湊位置設為 1。查詢：k 個位置都是 1 才回答「可能存在」。

📐 最重要的性質 只會偽陽性（False Positive），絕不會偽陰性（False Negative）。

回答「不存在」→ 100% 確定不存在
回答「可能存在」→ 需要再查一次真實資料確認

21-2　誤判率推導

插入 n 個元素後，某個位元仍為 0 的機率 = (1 − 1/m)kn ≈ e−kn/m

故誤判率 p ≈ (1 − e−kn/m)k

最佳雜湊函數個數：k = (m/n) · ln 2 ≈ 0.693 · (m/n)
此時每個元素約需 1.44 · log₂(1/p) 位元
目標誤判率每元素所需位元1000 萬筆需要
1%約 9.6 bits約 12 MB
0.1%約 14.4 bits約 18 MB
0.01%約 19.2 bits約 24 MB

對比：1000 萬個身分證字號用雜湊集合存，至少要數百 MB。布隆過濾器只要 12 MB——這就是它的價值。

21-3　公務適用與不適用

可以用不可以用
大量比對前的快速過濾（先篩掉「確定不在名單」的，剩下的再查資料庫）資格判定——不能因為誤判就核給或否准
快取穿透防護（先問布隆過濾器，避免每次都打資料庫）任何作為行政處分依據的判斷
已處理案件的去重初篩金額或件數的精確統計
⚠️ 公務使用的鐵則 布隆過濾器只能用來「排除」，不能用來「認定」。
任何回答「可能存在」的結果，必須再查一次權威資料源確認——否則就是用機率決定民眾權益。

21-4　不能刪除的問題與變形

標準布隆過濾器不支援刪除（把位元改回 0 會誤傷其他元素）。
需要刪除時改用 Counting Bloom Filter（每格改存計數器，代價是空間變 3～4 倍）。

✅ 深化 21 必背結論 ① 只有偽陽性，沒有偽陰性——說「沒有」就一定沒有
② 最佳 k = 0.693 · m/n；1% 誤判約需每元素 10 bits
③ 公務上只能用於「排除」與「初篩」，不可作為認定依據
④ 不支援刪除 → 需要刪除改用 Counting 版

深化 22　併發環境下的資料結構：鎖、無鎖與不可變

22-1　為什麼單執行緒的正確不等於多執行緒的正確

⚠️ 經典錯誤 count = count + 1 看起來是一個動作，實際上是三步：讀取 → 加一 → 寫回。
兩個執行緒同時做，可能兩個都讀到 5，各自算成 6，寫回後結果是 6 而不是 7。

這就是競爭條件（Race Condition）——丟失的那一次更新永遠找不回來，而且不會報錯。

22-2　三種策略比較

策略做法優點缺點
加鎖同一時間只讓一個執行緒進入簡單、易懂可能死結；競爭激烈時成為瓶頸
無鎖（CAS）比較並交換，失敗就重試無死結、高吞吐實作困難；有 ABA 問題
不可變資料建立後不再修改，要改就產生新版本天然執行緒安全、易推理記憶體用量較大
分片把資料切成多份各自加鎖降低競爭跨片操作變複雜

22-3　樂觀鎖 vs 悲觀鎖（公務系統最常遇到的選擇）

悲觀鎖樂觀鎖
假設一定會衝突很少衝突
做法先鎖住再操作記版本號，寫回時比對
適合衝突頻繁、操作極短人為編輯（公文、案件表單）
公務例號碼牌配號、餘額扣減公文會辦、案件編修
為什麼公文編輯要用樂觀鎖：
承辦打開公文可能編輯 30 分鐘，甚至去開會。悲觀鎖會把資料鎖住 30 分鐘，其他人全部卡住。
樂觀鎖則是：存檔時才發現有人改過，提示「本文件已被 OOO 於 X 時修改」並顯示差異。

22-4　ABA 問題

📐 什麼是 ABA 執行緒 1 讀到值 A，準備用 CAS 換成 C。
期間執行緒 2 把它改成 B，又改回 A。
執行緒 1 的 CAS 「看起來成功」——但中間發生的事已經被忽略了。

解法：加上版本號（值 ＋ 版本一起比較），這也正是樂觀鎖的原理。
✅ 深化 22 必背結論 ① count++ 不是原子操作 → 競爭條件，會靜默丟失更新
② 長時間人為編輯用樂觀鎖；短交易高衝突用悲觀鎖
③ 不可變資料天然執行緒安全
④ CAS 有 ABA 問題，加版本號解決

深化 23　索引該不該建：用選擇率算給主管看

23-1　選擇率（Selectivity）

📐 定義與判準 選擇率 = 符合條件的列數 ÷ 總列數

選擇率低（結果很少，如 < 5%）→ 索引有效
選擇率高（結果很多，如 > 20%）→ 全表掃描反而更快

為什麼結果多反而不該用索引：透過索引找到每一列後還要回表（隨機 I/O）；
當要回表 50 萬次時，還不如把整張表循序讀一遍（順序 I/O 快得多）。

23-2　實際算一次

欄位相異值數選擇率建索引？
案件編號500 萬（唯一）0.00002%✔ 極有效
身分證字號約 200 萬0.00005%✔ 有效
行政區代碼12約 8%視查詢而定（可作複合索引前綴）
案件狀態5約 20%單獨建效益低
性別2約 50%✘ 幾乎無效
💡 例外：低選擇率欄位仍可能有用
若查詢是 WHERE 狀態 = '待補件' 而待補件只占 0.5%，那這個查詢的選擇率其實很低 → 索引有效。
選擇率要看「這個查詢」，不是只看「這個欄位」。

23-3　索引的成本（申論必寫的另一半）

成本說明
空間每個索引都是一份額外的資料結構
寫入變慢每次 INSERT／UPDATE／DELETE 都要同步維護所有相關索引
維護統計資訊過期會導致執行計畫選錯
鎖競爭高併發寫入時，索引本身成為競爭點

結論句：「索引不是越多越好——讀取加速的代價是寫入變慢。應依實際查詢樣態（可由慢查詢日誌分析）建立，並定期檢視未被使用的索引予以移除。」

23-4　覆蓋索引：連回表都省掉

📐 概念 若查詢需要的所有欄位都在索引裡，資料庫就不必回表——直接從索引取值即可。

例：SELECT 案號, 收件日 FROM 案件 WHERE 區碼 = ? AND 收件日 >= ?
建索引 (區碼, 收件日, 案號) → 三個欄位都在索引中，零次回表。
✅ 深化 23 必背結論 ① 選擇率 < 5% 索引有效；> 20% 全表掃描可能更快（回表是隨機 I/O）
② 選擇率看「這個查詢」，不是只看「這個欄位」
③ 索引的代價是寫入變慢 ＋ 空間；要定期清掉沒在用的
④ 覆蓋索引可完全省去回表

深化 24　關鍵字反查表：看到題目就知道要用什麼

24-1　題目關鍵字 → 資料結構／演算法

題目出現這些字對應複雜度
「連接所有節點」「總成本最小」「不重複繞行」最小生成樹（Kruskal／Prim）O(E log V)
「兩點之間最短」「最快到達」DijkstraO((V+E) log V)
「到最近的某設施」多來源 DijkstraO((V+E) log V)
「走過每一條路」尤拉路徑／中國郵差可多項式判定
「拜訪每一個點各一次」漢米爾頓／TSPNP-完全
「先後順序」「相依關係」拓樸排序（DAG）O(V+E)
「工期最短」「哪一項延誤會影響全案」關鍵路徑 CPM（DAG 最長路徑）O(V+E)
「有限資源下效益最大」「不可分割」0/1 背包（DP）O(nW)，NP-完全
「配對」「媒合」「一對一分派」二分圖最大匹配／最大流多項式
「優先處理」「避免長期等待」優先佇列 ＋ 老化機制O(log n)
「前綴查詢」「自動完成」Trie／B+ 樹O(字串長度)
「範圍查詢」「日期區間」「分頁」B+ 樹索引O(log n + 結果數)
「前 N 名」「最大的 K 個」大小 k 的堆積O(n log k)
「是否曾經出現過」（可容誤判）布隆過濾器O(k)
「合併」「是否屬於同一群」併查集O(α(n))
「資料放不進記憶體」外部排序／串流處理約 2 遍 I/O

24-2　陷阱關鍵字（看到要提高警覺）

陷阱字要注意什麼
「最緊的上界」2n² = O(n³) 為真，但不是最緊；答 O(n²)
「最壞情況」快排是 O(n²) 不是 O(n log n)
「穩定排序」快、堆、選、希 不穩定
「根為第 0 層」公式要改為 2h+1 − 1
「等待時間」vs「完成時間」完成 = 等待 ＋ 執行
「索引 由 1 起算」陣列位址公式要 +1
「負權邊」Dijkstra 不可用，改 Bellman-Ford
「不倒扣」選擇題一格都不能空

24-3　把技術答案升級為「高考三級」答案

🎯 每一題都可以再補的三句話 ①最壞情況與因應：「本演算法最壞為 O(n²)，故須設定資料量上限與逾時保護。」

②法規與稽核：「處理結果涉及民眾權益，須保留完整稽核軌跡並提供人工複核。」

③公平與可及性：「最佳化目標不應僅為總和最小，須加入個別上限之公平性約束，並保留非數位替代管道。」

這三句可以套用在幾乎所有申論題上——而且每一句都是分數。
✅ 深化 24 必背結論 ① 「所有邊」→ 尤拉；「所有點」→ 漢米爾頓（NP）；「連接所有點」→ MST
② 「到最近的 X」→ 多來源 Dijkstra 跑一次
③ 看到「最緊」「最壞」「穩定」「第 0 層」就要停下來想一秒
④ 申論結尾三句：最壞情況 ＋ 稽核法遵 ＋ 公平可及
