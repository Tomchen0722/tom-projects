第 1 章　演算法與複雜度分析

1-1　什麼是資料結構、什麼是演算法

資料結構（Data Structure）：資料在電腦中的組織與儲存方式。
演算法（Algorithm）：解決問題的有限步驟集合。

🧒 白話版

把「資料結構」想成收納方式，「演算法」想成做事的步驟。

同樣是找一本書：如果書隨便堆在地上（陣列、無序），你只能一本一本翻；如果書按書名字母順序排在書架上（有序陣列），你可以從中間開始猜（二分搜尋）；如果有一本索引目錄告訴你「這本書在第 3 排第 5 格」（雜湊表），你可以一步到位。

收納方式決定了你能用什麼方法找，方法又決定了要花多少時間。這就是這門科目的全部核心。

演算法的五個必要特性（考過名詞解釋）

特性英文說明
輸入Input零個或多個輸入
輸出Output至少一個輸出
明確性Definiteness每個步驟必須清楚無歧義
有限性Finiteness執行有限步驟後必須停止
有效性Effectiveness每個步驟都是可執行的基本操作
考點：作業系統不是演算法（因為它不會停止，違反有限性）。這是經典的觀念題。

1-2　漸進符號（Asymptotic Notation）

我們不在意「跑幾秒」（那跟機器有關），只在意「輸入變大時，時間怎麼成長」。

符號意義數學定義白話
O(g(n)) 大 O上界（最壞情況） 存在 c > 0、n₀，使 n ≥ n₀ 時 f(n) ≤ c·g(n) 「最慢不會超過這個」
Ω(g(n)) 大 Omega下界（最好情況） f(n) ≥ c·g(n) 「最快也要這麼久」
Θ(g(n)) 大 Theta上下界皆同（緊界） c₁·g(n) ≤ f(n) ≤ c₂·g(n) 「就是這個等級」
o(g(n)) 小 o嚴格上界 對所有 c > 0 皆成立 f(n) < c·g(n) 「絕對比它小一個等級」
ω(g(n)) 小 omega嚴格下界 對所有 c > 0 皆成立 f(n) > c·g(n) 「絕對比它大一個等級」
🧒 用高中數學理解「為什麼可以丟掉常數」

假設演算法 A 要 3n² + 100n + 5000 個步驟。當 n = 10 時，100n 和 5000 反而比較大；但 n = 10000 時：

  • 3n² = 300,000,000
  • 100n = 1,000,000（只有 0.3%）
  • 5000 ≈ 0%

n 越大，最高次項越是壓倒性地主宰一切。所以我們直接說它是 O(n²)。這跟高中學極限時「分子分母同除最高次項」是同一個道理。

常數 3 也丟掉，是因為換一台快 3 倍的電腦就抵銷了——我們比較的是「演算法本身好不好」，不是「電腦快不快」。

成長速度排序（必背）

O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!) < O(nⁿ)
複雜度n=10n=100n=1000典型演算法

1-3　遞迴式求解（Recurrence Relation）

申論題常出：「請分析下列遞迴演算法之時間複雜度」。三種解法要會。

方法一：展開法（Substitution / Iteration）

以 T(n) = 2T(n/2) + n，T(1) = 1 為例（Merge Sort）：

T(n) = 2T(n/2) + n
► 說明：將 T(n/2) 再次代入原公式：T(n/2) = 2T(n/4) + n/2
► 算式：= 2[2T(n/4) + n/2] + n 
► 計算：將外面的 2 乘進去，2*(n/2) 變成 n，再加上後面的 n，得到 2n
     = 4T(n/4) + 2n

► 說明：再次把 T(n/4) 代入公式：T(n/4) = 2T(n/8) + n/4
► 算式：= 4[2T(n/8) + n/4] + 2n 
► 計算：將外面的 4 乘進去，4*(n/4) 變成 n，加上後面的 2n，得到 3n
     = 8T(n/8) + 3n
     ...
► 說明：觀察規律，展開第 k 次時，係數與分母皆為 2^k，後面的項數則為 k*n
     = 2^k · T(n/2^k) + k·n

► 說明：遞迴的終點是當括號內為 1，也就是 n/2^k = 1 時停止
► 推導：n = 2^k，兩邊取以 2 為底的對數，得到 k = log₂n
令 n/2^k = 1 → k = log₂n

► 代入：將 k 替換回原本的算式中
► 算式：= 2^(log₂n) · T(1) + (log₂n)·n
► 計算：根據對數性質，2^(log₂n) 剛好等於 n；且已知 T(1) 等於 1
     = n·T(1) + n·log₂n
     = n + n log n
► 結論：忽略常數與低次項，取得最高次數的項
→ T(n) = Θ(n log n)

方法二：遞迴樹（Recursion Tree）

把每一層的成本畫出來相加。以 T(n)=2T(n/2)+n：

► 說明：第 0 層 (頂層)，只有 1 個問題，大小為 n。成本為 n。
層 0:            n              = n

► 說明：第 1 層，切分為 2 個子問題，每個大小為 n/2。成本為 2 * (n/2) = n。
層 1:      n/2       n/2        = n

► 說明：第 2 層，切分為 4 個子問題，每個大小為 n/4。成本為 4 * (n/4) = n。
層 2:   n/4  n/4  n/4  n/4      = n
...
► 說明：到達最底層 (Base Case)，此時子問題大小為 1。
► 算式：從 n 每次除以 2，要除幾次才會等於 1？答案是 log₂n 次。
► 計算：最底層共有 n 個節點，每個成本為 1，總成本為 1 * n = n。
層 log n:  1 1 1 ... 1 (n 個)   = n

► 結論：從層 0 到層 log n，總共有 (log n + 1) 層。
► 總計：每一層的成本都是 n，總共有 (log n + 1) 層，所以總成本為 n * (log n + 1) = n log n + n。
► 漸進符號：取最高次數項，即 Θ(n log n)。
共 (log n + 1) 層，每層成本 n → 總計 n log n

方法三：主定理（Master Theorem）— 最常用

📐 主定理 對於 T(n) = a·T(n/b) + f(n)，其中 a ≥ 1、b > 1，比較 f(n) 與 n^(log_b a)：

Case 1：若 f(n) = O(n^(log_b a − ε))　→　T(n) = Θ(n^(log_b a))　（遞迴部分較重）
Case 2：若 f(n) = Θ(n^(log_b a))　→　T(n) = Θ(n^(log_b a) · log n)　（兩者相當）
Case 3：若 f(n) = Ω(n^(log_b a + ε)) 且滿足正規條件 a·f(n/b) ≤ c·f(n)　→　T(n) = Θ(f(n))　（合併部分較重）
遞迴式a, bn^(log_b a)f(n)Case結果
T(n)=2T(n/2)+n2, 2n¹ = nn2Θ(n log n)
T(n)=2T(n/2)+12, 2n11Θ(n)
T(n)=T(n/2)+11, 2n⁰ = 112Θ(log n)（二分搜尋）
T(n)=4T(n/2)+n4, 2n²n1Θ(n²)
T(n)=3T(n/4)+n log n3, 4n^0.79n log n3Θ(n log n)
T(n)=7T(n/2)+n²7, 2n^2.81n²1Θ(n^2.81)（Strassen 矩陣乘法）
⚠️ 主定理不適用的情況 1. T(n) = T(n−1) + n（不是除法遞減，是減法）→ 用展開法，答案 Θ(n²)。
2. T(n) = 2T(n/2) + n/log n（f(n) 落在兩個 case 中間的「間隙」）→ 主定理無法判定。
申論題如果遇到這種，寫「本式不符主定理適用條件，改以展開法求解」反而是加分點。

1-5　攤還分析（Amortized Analysis）

某些操作偶爾很貴，但平均下來很便宜。不是平均情況分析（那是機率），而是「一連串操作的總成本除以次數」。

🧒 白話版：動態陣列的例子

動態陣列（如 Java 的 ArrayList）滿了就要「擴充成兩倍並複製舊資料」，這次操作是 O(n)，看起來很貴。

但擴充不是每次都發生。假設容量從 1→2→4→8→…→n，總複製次數是 1+2+4+…+n/2 ≈ n 次。做 n 次插入，總成本約 2n，平均每次 O(1)。

就像手機月租費：你偶爾要換一支新手機（很貴），但攤到每個月其實還好。攤還分析看的是「長期平均」，且是最壞情況下的長期平均，有保證。

三種分析方法：聚合分析（Aggregate）、記帳法（Accounting）、位能法（Potential）。考試通常只要求會用聚合分析說明動態陣列或 Union-Find 即可。

第 2 章　陣列與鏈結串列

2-1　陣列（Array）

連續記憶體空間，用索引直接計算位址，故存取為 O(1)。

位址計算公式（考過計算題）

一維：A[i] 的位址 = 基底位址 + (i − 下界) × 元素大小

二維（列優先 Row-major，C/Java 採用）：
A[i][j] 位址 = base + [(i − l₁) × (u₂ − l₂ + 1) + (j − l₂)] × size

二維（行優先 Column-major，Fortran 採用）：
A[i][j] 位址 = base + [(j − l₂) × (u₁ − l₁ + 1) + (i − l₁)] × size

例：A[1..5][1..8]，base = 1000，每個元素 4 bytes，列優先，求 A[3][4]？
→ 1000 + [(3−1) × 8 + (4−1)] × 4 = 1000 + (16+3)×4 = 1000 + 76 = 1076

特殊矩陣的壓縮儲存（考點）

矩陣類型特性所需空間
對稱矩陣A[i][j] = A[j][i]n(n+1)/2
上／下三角矩陣一半為 0n(n+1)/2
對角矩陣只有對角線有值n
三對角矩陣對角線及其上下各一條3n − 2
稀疏矩陣大多數為 0用三元組 (row, col, value) 儲存

2-2　鏈結串列（Linked List）

類型結構特點
單向串列node = {data, next}只能往前走，最後一個 next = NULL
雙向串列node = {prev, data, next}可雙向走訪，刪除節點不需前驅指標
環狀串列尾端 next 指回開頭可從任一點走完全部；用於輪轉排程
雙向環狀＋標頭節點加一個 dummy head插刪不需特判空串列，程式最簡潔

陣列 vs 鏈結串列（必考比較題）

項目陣列鏈結串列
記憶體配置連續、靜態（宣告時決定）不連續、動態
隨機存取第 i 個O(1)O(n)
已知位置插入／刪除O(n)（要搬移元素）O(1)（改指標）
搜尋（未排序）O(n)O(n)
額外空間無每節點多一個（或兩個）指標
記憶體碎片需連續大塊，易失敗可利用零碎空間

💡 申論題怎麼寫這一段 不要只寫表格就結束，最後要加一段「如何選擇」：
「若應用以查詢為主、資料量穩定（如查表、影像像素），宜採陣列；若頻繁插入刪除、資料量變動大（如工作佇列、編輯器的復原紀錄），宜採鏈結串列。實務上多採動態陣列兼顧兩者，惟需注意擴充時的複製成本（攤還後仍為 O(1)）。」

常考的鏈結串列題型

  • 反轉串列：用三個指標 prev、curr、next 逐一翻轉，O(n) 時間、O(1) 空間。
  • 偵測環路（Floyd 龜兔演算法）：慢指標一次一步、快指標一次兩步，若相遇則有環。O(n) 時間、O(1) 空間。
  • 找中點：同樣用快慢指標，快指標到底時慢指標在中間。
  • 合併兩個已排序串列：類似 Merge Sort 的合併步驟。
  • 多項式相加：每個節點存 (係數, 指數)，依指數大小合併。經典申論題。
// 反轉單向串列
Node reverse(Node head) {
    Node prev = NULL, curr = head;
    while (curr != NULL) {
        Node next = curr.next;   // 先記住下一個
        curr.next = prev;          // 掉頭
        prev = curr;               // 兩個指標各前進一步
        curr = next;
    }
    return prev;                   // prev 是新的頭
}

第 3 章　堆疊與佇列

3-1　堆疊（Stack）— 後進先出 LIFO

操作：push、pop、top/peek、isEmpty，皆為 O(1)。

🧒 白話版

像洗好疊起來的盤子：你只能拿最上面那個，也只能放在最上面。最後放上去的最先被拿走。

或者想成瀏覽器的「上一頁」：你逛了 A→B→C，按上一頁會回到 B（最近去過的先回來）。

堆疊的五大應用（申論愛考）

  1. 函式呼叫與遞迴：系統用呼叫堆疊（Call Stack）記住返回位址與區域變數。遞迴太深 → Stack Overflow。
  2. 運算式轉換與求值：中序 ↔ 前序 ↔ 後序。
  3. 括號配對檢查：遇左括號 push、遇右括號 pop 比對。
  4. 復原機制（Undo）：每個動作 push 進去，Undo 就 pop。
  5. DFS 深度優先搜尋（非遞迴版）。

運算式轉換（每年可能出的計算題）

表示法又稱範例（A+B*C）特點
中序 Infix—A + B * C人類習慣，但需括號與優先權
前序 Prefix波蘭表示法+ A * B C運算子在前
後序 Postfix逆波蘭 RPNA B C * +電腦最好處理，不需括號
📐 中序轉後序的手算口訣 方法一（完全括號法，最不會錯）：
1. 依運算優先順序，把每一組運算加上完整括號
2. 把每個運算子移到它所屬括號的右括號位置
3. 去掉所有括號

例：A + B * C − D
→ ((A + (B * C)) − D)
→ ((A (B C)*)+ D)−
→ A B C * + D −

轉前序：同樣加括號，但運算子移到左括號位置 → − + A * B C D
📐 後序求值（用堆疊） 由左至右掃描：遇到運算元就 push；遇到運算子就 pop 兩個（先 pop 的是右運算元），運算後把結果 push 回去。

例：6 2 / 3 − 4 2 * +　求值
6,2 → push；遇 / → pop 2、pop 6 → 6/2=3 → push 3
3 → push；遇 − → pop 3、pop 3 → 3−3=0 → push 0
4,2 → push；遇 * → 4*2=8 → push 8
遇 + → 0+8 = 8
⚠️ 最容易錯的地方 減法與除法順序不能顛倒。pop 出來的第一個是右運算元，第二個才是左運算元。
a b − 是 a − b，不是 b − a。考試很愛在這裡設陷阱。

3-2　佇列（Queue）— 先進先出 FIFO

操作：enqueue（從 rear 進）、dequeue（從 front 出），皆為 O(1)。

🧒 白話版

就是排隊買飲料：先來的先買到，後來的排後面。

電腦裡的印表機工作、CPU 排程、網路封包緩衝，全都是這個模型。

環狀佇列（Circular Queue）— 高頻考點

普通陣列佇列有「假性溢滿」問題：front 一直往後移，前面空間浪費掉。環狀佇列讓 rear 走到底時繞回 0。

📐 環狀佇列公式 入列：rear = (rear + 1) % MAX;　Q[rear] = x;
出列：front = (front + 1) % MAX;　return Q[front];

判斷條件（犧牲一格的做法）
空：front == rear
滿：(rear + 1) % MAX == front

元素個數：(rear − front + MAX) % MAX
為什麼要犧牲一格？因為「空」和「滿」都會讓 front == rear，無法區分。解法有三：
(1) 犧牲一格（最常考）　(2) 額外用一個 count 變數　(3) 額外用一個 flag 記錄上次操作是入列或出列。

其他佇列變形

類型說明應用
雙向佇列 Deque兩端都可進出滑動視窗最大值、瀏覽器歷史
優先佇列 Priority Queue依優先權出列，非 FIFO作業排程、Dijkstra、Huffman
多層佇列依優先權分成多條佇列作業系統排程

優先佇列通常用 Heap 堆積實作，插入與刪除皆 O(log n)。如果用未排序陣列實作：插入 O(1)、取最大 O(n)；用排序陣列：插入 O(n)、取最大 O(1)。Heap 是兩者的折衷，也是最佳選擇。

樹 Tree由 n(≥1) 個節點組成的有限集合，有一個根節點，其餘節點分為互斥的子樹
分支度 Degree節點的子節點個數；樹的分支度＝所有節點中最大的分支度
階層 Level根為 Level 1（有些書從 0 開始，作答時務必寫明定義）
高度 Height樹中最大的階層數
樹葉 Leaf分支度為 0 的節點
森林 Forestn(≥0) 棵互斥樹的集合；把樹的根拿掉就變成森林

4-2　二元樹（Binary Tree）

每個節點最多兩個子節點，且區分左右。注意：二元樹可以是空的，一般樹不行（這是經典觀念題）。

重要種類

種類定義節點數
歪斜樹 Skewed所有節點只有左（或右）子樹退化成鏈結串列，高度 n
完滿二元樹 Full每個節點的分支度都是 0 或 2—
完美／滿枝二元樹 Perfect高度 h 且節點數達到最大2^h − 1
完整二元樹 Complete除最後一層外皆填滿，且最後一層靠左排列可用陣列緊密儲存

重要性質（必背，常出計算題）

設二元樹高度為 h、節點數為 n：
1. 第 i 層最多有 2^(i−1) 個節點（根為第 1 層）
2. 高度 h 的二元樹最多有 2^h − 1 個節點，最少 h 個
3. n 個節點的二元樹，最小高度為 ⌈log₂(n+1)⌉
4. n₀ = n₂ + 1（樹葉數 ＝ 分支度為 2 的節點數 + 1）
5. n 個節點的二元樹有 n + 1 個空鏈結（可用於 Threaded Binary Tree）
🧒 性質 4（n₀ = n₂ + 1）怎麼來的

用兩種方式數「邊」的數量：

方法一：除了根節點，每個節點都有一條邊連向它的父節點 → 邊數 = n − 1 = n₀ + n₁ + n₂ − 1

方法二：從父節點往下數，分支度 0 的貢獻 0 條、分支度 1 的貢獻 1 條、分支度 2 的貢獻 2 條 → 邊數 = 0·n₀ + 1·n₁ + 2·n₂

兩式相等：n₀ + n₁ + n₂ − 1 = n₁ + 2n₂　→　n₀ = n₂ + 1

這就是高中數學的「兩種方式算同一個東西」技巧。申論題如果要你「證明」，把上面兩行寫出來就是滿分。

陣列表示法（Heap 用得到）

若根從索引 1 開始：
節點 i 的左子 = 2i，右子 = 2i+1，父 = ⌊i/2⌋

若根從索引 0 開始：
左子 = 2i+1，右子 = 2i+2，父 = ⌊(i−1)/2⌋

陣列表示法對完整二元樹最省空間；對歪斜樹則極浪費（高度 n 需要 2ⁿ−1 格）。

4-3　二元樹走訪（Traversal）— 每年必考

走訪順序用途
前序 Preorder根 → 左 → 右（VLR）複製樹、輸出前序運算式
中序 Inorder左 → 根 → 右（LVR）BST 中序走訪 = 由小到大排序
後序 Postorder左 → 右 → 根（LRV）刪除樹、計算運算式的值
層序 Level-order由上而下、由左而右用佇列實作，即 BFS

C++ 實作（指標寫法，國考標準答案格式）

struct Node {
    int data;
    Node* left;
    Node* right;
};

// 前序走訪 (VLR)
void preorder(Node* t) {
    if (t == NULL) return;
    cout << t->data << " "; // V: Visit 處理根節點
    preorder(t->left);       // L: 走訪左子樹
    preorder(t->right);      // R: 走訪右子樹
}

// 中序 (LVR): preorder() 內的順序改為 left -> data -> right
// 後序 (LRV): preorder() 內的順序改為 left -> right -> data

Python 實作（物件導向寫法，適合觀念釐清）

class Node:
    def __init__(self, data):
        self.data = data
        self.left = None
        self.right = None

# 前序走訪 (VLR)
def preorder(t: Node):
    if t is None: return
    print(t.data, end=" ") # V
    preorder(t.left)       # L
    preorder(t.right)      # R

由走訪結果還原樹（超高頻申論題）

📐 還原規則 ✅ 前序 + 中序 → 可唯一還原
✅ 後序 + 中序 → 可唯一還原
❌ 前序 + 後序 → 無法唯一還原（除非是完滿二元樹）

關鍵：中序負責「切左右」，前序／後序負責「找根」。少了中序就不知道左右子樹的分界在哪。
📐 實作步驟（以前序＋中序為例） 前序：A B D E C F　中序：D B E A C F

1. 前序第一個 A = 根
2. 在中序中找到 A，左邊 D B E = 左子樹，右邊 C F = 右子樹
3. 左子樹前序取 3 個：B D E，中序 D B E → 根是 B，左 D、右 E
4. 右子樹前序 C F，中序 C F → 根是 C，右子是 F

還原結果：
　　A
　／　＼
　B　　C
／＼　　＼
D　E　　 F

4-4　引線二元樹（Threaded Binary Tree）

n 個節點有 n+1 個空指標，把它們拿來指向中序的前驅／後繼節點，就是引線二元樹。

  • 優點：走訪不需遞迴或堆疊，空間 O(1)。
  • 缺點：插入刪除較複雜，需額外的標記位元（tag）區分「這是子樹指標還是引線」。

4-5　運算式樹（Expression Tree）

葉節點是運算元、內部節點是運算子。

  • 前序走訪 → 前序運算式（Prefix）
  • 中序走訪 → 中序運算式（需補括號）
  • 後序走訪 → 後序運算式（Postfix）
申論題常給你一個中序運算式，要你「畫出運算式樹並寫出前序與後序」。
作法：先按優先權加括號 → 最後才算的運算子當根 → 遞迴往下建。

4-6　霍夫曼編碼（Huffman Coding）

依字元出現頻率建立最佳前綴碼，達成資料壓縮。是貪婪演算法的經典應用。

📐 建構步驟 1. 把每個字元依頻率放入最小優先佇列
2. 取出頻率最小的兩個，合併成一個新節點（頻率 = 兩者相加）
3. 新節點放回佇列
4. 重複到只剩一個節點 → 即為 Huffman Tree
5. 左邊標 0、右邊標 1，從根到葉的路徑就是該字元的編碼

時間複雜度：O(n log n)

例：A:45、B:13、C:12、D:16、E:9、F:5（共 100）

合併 F(5)+E(9)  = 14
合併 C(12)+B(13) = 25
合併 14 + D(16)  = 30
合併 25 + 30     = 55
合併 A(45) + 55  = 100  ← 根

編碼結果（一種可能）：
A = 0      (1 位元)
B = 101    (3 位元)
C = 100    (3 位元)
D = 111    (3 位元)
E = 1101   (4 位元)
F = 1100   (4 位元)

平均碼長 = (45×1 + 13×3 + 12×3 + 16×3 + 9×4 + 5×4) / 100
        = (45 + 39 + 36 + 48 + 36 + 20) / 100 = 2.24 位元/字元
若用固定長度編碼需 3 位元（2³=8≥6），壓縮率 = (3−2.24)/3 ≈ 25.3%
⚠️ 前綴碼（Prefix Code）的意義 任何字元的編碼都不是另一個字元編碼的前綴。這保證解碼時不會有歧義，不需要分隔符號。
Huffman 樹中所有字元都在葉節點，這就自動保證了前綴性質——這是常考的申論說明點。
