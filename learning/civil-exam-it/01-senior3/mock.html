看評分配分表
（一） 
SELECT d.單位名稱,
       COUNT(*) AS 未結案件數,
       ROUND(AVG(CURRENT_DATE - c.收件日期), 1) AS 平均已辦天數
FROM 案件 c
JOIN 單位 d ON c.單位代碼 = d.單位代碼
WHERE c.狀態 = '未結案'          -- ② 先過濾「列」
GROUP BY d.單位代碼, d.單位名稱   -- ③ 分組
HAVING COUNT(*) >= 10             -- ④ 過濾「組」
ORDER BY 未結案件數 DESC;
（二） 
WITH 承辦統計 AS (
    SELECT p.人員編號, p.姓名, p.單位代碼, COUNT(c.案號) AS 件數
    FROM 人員 p
    LEFT JOIN 案件 c ON p.人員編號 = c.承辦人編號
    GROUP BY p.人員編號, p.姓名, p.單位代碼
),
單位平均 AS (
    SELECT 單位代碼, AVG(件數) AS 平均件數
    FROM 承辦統計 GROUP BY 單位代碼
)
SELECT s.姓名, d.單位名稱, s.件數
FROM 承辦統計 s
JOIN 單位平均 a ON s.單位代碼 = a.單位代碼
JOIN 單位 d      ON s.單位代碼 = d.單位代碼
WHERE s.件數 > a.平均件數;
（三） 
-- 寫法一：NOT EXISTS（最安全，不受 NULL 影響）
SELECT 姓名 FROM 人員 p
WHERE NOT EXISTS (
    SELECT 1 FROM 案件 c WHERE c.承辦人編號 = p.人員編號
);

-- 寫法二：LEFT JOIN + IS NULL
SELECT p.姓名 FROM 人員 p
LEFT JOIN 案件 c ON p.人員編號 = c.承辦人編號
WHERE c.案號 IS NULL;

不宜用 NOT IN：若子查詢結果含 NULL，因 SQL 三值邏輯將回傳空集合。

生命週期訂定保存年限；原始高頻資料逾期降頻彙總以控制成本
後設資料資料字典與資料血緣，確保數據可追溯
📊 面向三：資安防護
層面措施
IoT 裝置納入資產清冊；強制變更預設密碼；建立韌體更新機制；裝置身分認證；實體防護（設於戶外易遭破壞）
網路IoT 獨立網段與內部網路隔離；限制裝置僅能連往指定平台；傳輸加密
平台API 安全（驗證、授權、流量限制）；最小權限；邊緣運算降低敏感資料回傳
監控日誌集中至 SIEM；異常行為偵測（避免遭組成殭屍網路發動 DDoS）
治理依《資通安全管理法》納入資通安全維護計畫；定期演練；委外契約明定資安要求
📊 面向四：法制與倫理
議題因應
個人資料影像、車牌、人流軌跡可間接識別特定個人，仍屬個資 → 依《個人資料保護法》特定目的與必要範圍蒐集；去識別化後始得分析與開放
隱私衝擊導入前辦理隱私衝擊評估；於監視區域明確告示
AI 公平性模型不得因訓練資料偏見而形成差別待遇（違反平等原則）；不得作為行政處分之唯一依據，須可解釋且經人工複核
比例原則蒐集範圍與監控密度須與目的相當，避免過度監控
資料開放去識別化＋小樣本揭露門檻；評估交叉比對重新識別風險
法規調適檢視現行法規對感測資料蒐集、無人載具等之限制，必要時研議修法
📊 面向五：推動策略
策略作法
分期推動第一期：資料平台與標準、擇 1～2 項先導試辦；第二期：擴大應用；第三期：跨域整合與 AI 分析
快速見效優先選民眾最有感之應用（如停車位查詢），建立支持基礎
避免鎖定契約要求開放 API、資料可攜、原始碼交付；採標準通訊協定
維運能量評估人力技能落差並及早培訓；考量委外監控（MSSP）補足能量；設備生命週期與汰換預算須一併編列
公民參與公開規劃資訊、辦理說明會；建立回饋管道，提升接受度
效益衡量訂定可量化 KPI（如平均車程縮短、稽查命中率），定期檢討；避免淪為只建不用的蚊子建設
