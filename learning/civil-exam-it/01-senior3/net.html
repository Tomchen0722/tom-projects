第 1 章　網路參考模型：OSI 與 TCP/IP

1-1　為什麼要分層

🧒 白話版：分層就像寄信

你要寄一封信給朋友，這件事其實有好幾「層」在運作：

  • 你寫信的內容（應用層）— 只有你和朋友看得懂
  • 裝進信封、寫上地址（傳輸層／網路層）— 郵局看地址就好，不用看內容
  • 郵局分揀、上卡車（資料連結層）— 只負責「從這個郵局送到下一個郵局」
  • 卡車在馬路上跑（實體層）

分層的價值：卡車換成飛機，你完全不用改寫信的方式；你改用英文寫信，郵局也不用改流程。每一層只跟上下相鄰的層打交道，可以各自獨立演進。

這就是為什麼 Wi-Fi 取代網路線時，你的網頁瀏覽器完全不用改寫——它們在不同層。

⚠️ 常考觀念題 1. OSI 是「參考模型」（理論），TCP/IP 是「實作」（實際在用）。
2. ARP 屬於哪一層？ 教科書說法不一：它把 IP 轉成 MAC，跨越第 2、3 層。常見答案是「資料連結層」或「網路層」，作答時應說明「介於第 2 與第 3 層之間，多數教材歸為資料連結層」，這樣兩種標準都不會錯。
3. 加密在哪一層？ OSI 定義在表達層（第 6 層），但實務上 TLS 運作於傳輸層與應用層之間。

1-4　封裝與解封裝（Encapsulation）

傳送端（由上而下，每層加上自己的標頭）
應用層    [        Data        ]
傳輸層  [TCP標頭][    Data    ]         → Segment
網路層 [IP標頭][TCP標頭][Data ]         → Packet
連結層 [Frame標頭][IP][TCP][Data][FCS]  → Frame
實體層 0101110100101110...              → Bits

接收端（由下而上，每層拆掉自己的標頭）
每一層的標頭就像「一層信封」。路由器只拆到網路層（看 IP 決定往哪送）；交換器只拆到資料連結層（看 MAC）。
這解釋了為什麼交換器比路由器快——它要處理的層數更少。

📐 兩個關鍵網域概念 碰撞網域（Collision Domain）：共享傳輸媒介、會互相碰撞的範圍。

2-2　乙太網路（Ethernet）

標準速度常見介質
10BASE-T10 MbpsCat3
100BASE-TX（Fast Ethernet）100 MbpsCat5
1000BASE-T（Gigabit）1 GbpsCat5e
10GBASE-T10 GbpsCat6a
📐 CSMA/CD 與 CSMA/CA CSMA/CD（Collision Detection）— 有線乙太網路
　「先聽再說，邊說邊聽」：偵測到碰撞就停止傳送、送出干擾訊號，並依二進位指數後退（Binary Exponential Backoff）隨機等待後重送。
　→ 全雙工交換式網路已無碰撞，故現代 Ethernet 實質不再需要 CD。

CSMA/CA（Collision Avoidance）— 無線網路（Wi-Fi）
　為什麼無線不能用 CD？因為無線網卡無法同時收發，也存在隱藏節點問題（A、C 都能連 B 但彼此聽不到對方）。
　→ 改用「事前避免」：先送 RTS/CTS 取得傳送許可，並用 ACK 確認。

2-3　MAC 位址

  • 48 位元（6 bytes），以 16 進位表示，如 00:1A:2B:3C:4D:5E。
  • 前 24 位元為 OUI（廠商識別碼），後 24 位元由廠商指派。
  • 廣播位址：FF:FF:FF:FF:FF:FF。
  • 理論上全球唯一，但可被軟體偽造（MAC Spoofing）——這是為什麼「MAC 位址過濾」不是可靠的安全機制。

2-4　交換器運作原理

📐 交換器如何學習 1. 收到訊框時，記錄「來源 MAC ↔ 進入的埠」到 MAC 位址表（自我學習）
2. 查表找目的 MAC：
　‧ 找到 → 只轉送到該埠（Forward）
　‧ 找不到 → 洪泛（Flooding）到所有其他埠
　‧ 目的埠與來源埠相同 → 丟棄（Filter）
3. 表項有老化時間（Aging Time），通常 300 秒
轉送模式行為延遲錯誤檢查
Store-and-Forward收完整個訊框才轉送高會檢查 FCS
Cut-Through讀到目的 MAC 就開始轉送最低不檢查
Fragment-Free讀完前 64 bytes 才轉送中可濾掉碰撞碎片

2-5　VLAN（虛擬區域網路）

在同一台實體交換器上，邏輯切分成多個廣播網域。

優點說明
分割廣播網域減少廣播流量，提升效能
安全隔離不同 VLAN 間需經路由器（可套用 ACL 管控）；如把訪客網路與內部網路隔開
彈性管理依部門而非實體位置分群，人員換座位不需重拉線
降低成本不需為每個網段買獨立交換器
  • Access Port：連接終端裝置，屬於單一 VLAN。
  • Trunk Port：連接交換器之間，可承載多個 VLAN 的流量，以 IEEE 802.1Q 標籤（Tag）標示 VLAN ID（12 位元，1～4094）。
  • Inter-VLAN Routing：不同 VLAN 通訊需經 L3 設備，常用「單臂路由（Router-on-a-stick）」或 L3 交換器的 SVI。
✅ 公部門實務應用 機關常見的 VLAN 規劃：行政內網、公務機密網、IP 電話、監視系統（IP Cam）、訪客 Wi-Fi、機房管理網各自獨立 VLAN。
這是《資通安全管理法》要求的網段隔離之基本實作，申論題談網路架構時務必提到。

2-6　STP 生成樹協定

交換器之間若有迴圈，會造成廣播風暴（Broadcast Storm）、MAC 表震盪、訊框重複。STP（IEEE 802.1D）自動偵測並阻斷多餘路徑，形成無迴圈的樹狀拓樸。

  • 選出 Root Bridge（Bridge ID 最小者）。
  • 其餘交換器計算到 Root 的最短路徑成本，選出 Root Port。
  • 多餘路徑的埠設為 Blocking 狀態（不轉送資料，但仍收 BPDU）。
  • 鏈路故障時重新計算，達成備援。
  • RSTP（802.1w）收斂速度更快（秒級 vs 傳統 30～50 秒）。
這裡有一個重要的架構思維：備援路徑必須存在（實體上有兩條線），但邏輯上只能用一條。STP 就是負責「平時擋住備援線、故障時放行」的機制。
這也對應到資料結構的最小生成樹概念——同樣是「用最少的邊連通所有節點且無迴圈」。跨科連結，申論可加分。

第 3 章　網路層：IP 位址與子網路切割

⚠️ 本章是必考計算題 子網路切割幾乎年年出現，而且是「會就一定拿分、不會就完全空白」的題型。
考場不能用計算機，必須練到手算流暢。本章從二進位開始教，請務必親手算過每個範例。

3-1　IPv4 位址基礎

32 位元，分成 4 組每組 8 位元（octet），以十進位點分表示，如 192.168.10.5。

📐 必背：2 的次方與 8 位元權重 權重：128　64　32　16　8　4　2　1

2⁰=1、2¹=2、2²=4、2³=8、2⁴=16、2⁵=32、2⁶=64、2⁷=128
2⁸=256、2⁹=512、2¹⁰=1024、2¹¹=2048、2¹²=4096

常用子網路遮罩的十進位值（這 9 個數字背下來，考場能省一半時間）：
0、128、192、224、240、248、252、254、255
對應 1 的個數：0、1、2、3、4、5、6、7、8
🧒 十進位 ↔ 二進位手算法

十進位轉二進位（以 200 為例）：從權重最大的開始問「夠不夠減」。

200 ≥ 128 ? 是 → 寫 1，剩 200−128 = 72
 72 ≥  64 ? 是 → 寫 1，剩  72− 64 =  8
  8 ≥  32 ? 否 → 寫 0
  8 ≥  16 ? 否 → 寫 0
  8 ≥   8 ? 是 → 寫 1，剩 0
  0 ≥   4 ? 否 → 0
  0 ≥   2 ? 否 → 0
  0 ≥   1 ? 否 → 0
→ 200 = 11001000

二進位轉十進位：把 1 對應的權重加起來。11001000 = 128+64+8 = 200 ✔

3-3　CIDR 與子網路切割（核心）

📐 四個關鍵公式（背下來） 設 n = 網路位元數（/n）、h = 主機位元數 = 32 − n：

1. 子網路數 = 2^(借用的位元數)
2. 每個子網路的位址總數（區塊大小） = 2^h
3. 可用主機數 = 2^h − 2
4. 區塊大小（Block Size） = 256 − 遮罩該組的十進位值　←手算最好用的技巧
CIDR子網路遮罩主機位元區塊大小可用主機數

範例一：判斷網路位址、廣播位址與可用範圍

題目：192.168.10.100/26，求網路位址、廣播位址、可用主機範圍與主機數。

步驟 1：/26 → 遮罩 255.255.255.192
　（第 4 組：26 − 24 = 2 個網路位元 → 11000000 = 192）

步驟 2：區塊大小 = 256 − 192 = 64

步驟 3：列出這個網段可能的網路位址（以 64 為間隔）
　.0　.64　.128　.192

步驟 4：100 落在 64 ~ 127 之間
　→ 網路位址 = 192.168.10.64
　→ 廣播位址 = 192.168.10.127（下一個網路位址 128 減 1）
　→ 可用範圍 = 192.168.10.65 ~ 192.168.10.126
　→ 可用主機數 = 2⁶ − 2 = 62
🧒 為什麼「區塊大小」這個技巧有效

/26 表示在第 4 組借了 2 個位元當網路位元，剩 6 個位元給主機。6 個位元能表示 2⁶ = 64 個數字。

所以整個 0~255 的空間被切成 256 ÷ 64 = 4 塊：0-63、64-127、128-191、192-255。

而「256 − 192 = 64」剛好就是每塊的大小——這不是巧合，是因為遮罩值就是「被切掉的部分」。

用這個方法，你完全不需要在考場上寫二進位，直接用十進位跳格子就好。速度差三倍以上。

範例三：路由聚合（Route Summarization / Supernetting）

題目：將 192.168.8.0/24、192.168.9.0/24、192.168.10.0/24、192.168.11.0/24 聚合成一條路由。

步驟 1：把變動的那一組（第 3 組）轉二進位，找出共同前綴
  8 = 00001000
  9 = 00001001
 10 = 00001010
 11 = 00001011
      ↑↑↑↑↑↑ 前 6 位元相同（000010）
步驟 2：前兩組已相同（16 位元）＋ 第 3 組相同的 6 位元 = 22 位元

步驟 3：聚合結果 = 192.168.8.0/22
　驗證：/22 的第 3 組區塊大小 = 256 − 252 = 4 → 涵蓋 8、9、10、11 ✔

好處：4 條路由變 1 條，縮小繞送表、加快查表、減少路由更新流量。

3-4　IPv4 標頭重點欄位

欄位作用
Version4 或 6
TTL（Time To Live）每經過一台路由器減 1，歸零則丟棄並回送 ICMP 逾時 → 防止封包無限迴圈；traceroute 即利用此機制
Protocol上層協定（TCP=6、UDP=17、ICMP=1）
Fragment Offset / Flags分片重組資訊；DF（Don't Fragment）位元
Header Checksum只檢查標頭，不檢查資料；每經路由器需重算（因 TTL 改變）
Source / Destination IP來源與目的位址

3-6　NAT 網路位址轉換

類型說明
靜態 NAT一對一固定對應（如對外服務的伺服器）
動態 NAT從公有 IP 池中動態取用
NAPT / PAT多對一，以埠號區分不同內部主機（家用路由器與多數機關的做法）
  • 優點：節省公有 IP、隱藏內部網路結構（附帶的安全效果）。
  • 缺點：破壞端對端連線、影響部分協定（FTP 主動模式、SIP、IPsec）、增加疑難排解難度、不利點對點應用。
⚠️ 觀念釐清（常考陷阱） NAT 不是防火牆，也不能當作安全機制。
它確實讓外部無法直接連入內部主機，但那是「副作用」而非設計目的。內部主機主動連出去建立的連線，惡意流量仍可回來；且 NAT 完全不檢查封包內容。
正確說法：「NAT 提供有限的隱蔽性（Obscurity），但不等於安全性，仍需搭配防火牆與其他防護。」

第 4 章　網路層：路由與相關協定

4-1　繞送（Routing）基本原理

路由器依繞送表決定封包往哪個介面送出，遵循最長前綴匹配（Longest Prefix Match）原則。

📐 最長前綴匹配 若繞送表中同時有：
10.0.0.0/8 → 介面 A
10.1.0.0/16 → 介面 B
10.1.1.0/24 → 介面 C

封包目的為 10.1.1.5 → 三條都符合，但選前綴最長（/24）的 → 介面 C

白話：越精確的指示優先。就像「台北市大安區」比「台北市」更精確，當然聽前者。
預設路由 0.0.0.0/0 前綴最短，所以是「都找不到時」的最後選擇。

這套流程寫進申論，會顯得非常有實務感。

4-4　ARP 與相關風險

ARP（Address Resolution Protocol）將 IP 位址解析為 MAC 位址：主機在區網內廣播「誰是 192.168.1.1？」，擁有者以單播回覆自己的 MAC。

⚠️ ARP 的先天弱點 ARP 沒有任何驗證機制——誰回答都算。因此攻擊者可偽造回覆，把自己的 MAC 對應到閘道的 IP，讓所有流量都經過自己（ARP 欺騙／中間人攻擊）。

防護：
‧ 靜態 ARP 綁定（管理成本高，僅用於關鍵主機）
‧ Dynamic ARP Inspection（DAI）＋ DHCP Snooping（交換器功能，實務主要手段）
‧ Port Security 限制每埠 MAC 數量
‧ 網段隔離（VLAN）縮小攻擊範圍
‧ 端點偵測異常 ARP 流量

第 5 章　傳輸層：TCP 與 UDP

5-1　TCP vs UDP（必考比較）

項目TCPUDP
連線連線導向（需三向交握）非連線導向
可靠性可靠（確認、重送、排序）不可靠（送出就算）
順序保證順序不保證
流量控制有（滑動視窗）無
擁塞控制有無
標頭大小20 bytes 以上8 bytes
速度／負擔較慢、負擔大快、負擔小
適用網頁、檔案傳輸、郵件（不能錯）影音串流、DNS、VoIP、線上遊戲（不能慢）
🧒 白話版：掛號信 vs 明信片

TCP 像掛號信：寄之前先確認對方在家（三向交握），寄出後對方要簽收（ACK），沒收到就再寄一次（重送），而且保證按順序拆封。可靠，但手續多、比較慢。

UDP 像明信片：直接丟進郵筒，不管對方收不收到，也不管順序。快、便宜，但可能掉。

為什麼視訊通話要用 UDP？因為如果第 100 個影格掉了，TCP 會停下來重送——等它送到，畫面早就過去了，反而造成卡頓。對即時影音來說，「掉一格」比「卡一下」好得多。

5-2　三向交握（Three-way Handshake）

用戶端                                    伺服器
   │                                        │
   │──────── ① SYN (seq=x) ───────────────→│   用戶端請求連線
   │                                        │
   │←─── ② SYN+ACK (seq=y, ack=x+1) ───────│   伺服器同意並回應
   │                                        │
   │──────── ③ ACK (ack=y+1) ─────────────→│   用戶端確認
   │                                        │
   │◄══════ 連線建立，開始傳資料 ═══════════►│
💡 為什麼要「三次」而不是兩次 因為連線是雙向的，兩邊都必須確認「對方收得到我」與「我收得到對方」。
兩次交握只能確認用戶端→伺服器這個方向；第三次的 ACK 才讓伺服器確知「用戶端也收到我的回應了」。
此外，三次交握也讓雙方交換初始序號（ISN）並同步，避免舊的重複封包造成混亂。

四向斷線（Four-way Handshake）

① FIN  →     ② ACK ←     ③ FIN ←     ④ ACK →

為什麼斷線需要四次？因為 TCP 是全雙工，兩個方向要各自關閉。一方送 FIN 只表示「我沒資料要送了」，對方可能還有資料要傳完才關。

5-3　流量控制與擁塞控制（易混淆，必考）

項目流量控制 Flow Control擁塞控制 Congestion Control
解決的問題接收端處理不及（緩衝區滿）網路壅塞（路由器排隊丟包）
對象端點對端點整個網路
機制滑動視窗（接收端告知可接收量 rwnd）慢啟動、擁塞避免、快速重送、快速回復（cwnd）
白話「你講太快，我聽不完」「馬路太塞，大家慢一點」
📐 TCP 擁塞控制四階段 ① 慢啟動（Slow Start）：cwnd 從 1 開始，每收到 ACK 加倍（指數成長），直到達到門檻 ssthresh
② 擁塞避免（Congestion Avoidance）：超過門檻後改為每 RTT 加 1（線性成長）
③ 快速重送（Fast Retransmit）：收到 3 個重複 ACK 即判定封包遺失，立刻重送，不等逾時
④ 快速回復（Fast Recovery）：ssthresh 減半、cwnd 設為新門檻，回到擁塞避免（而非重新慢啟動）

若發生逾時（Timeout）：視為嚴重壅塞，ssthresh 減半且 cwnd 歸 1，重新慢啟動
🧒 「慢啟動」其實一點都不慢

名字容易誤導。它的意思是「從很小的量開始」，但成長速度是指數的：1 → 2 → 4 → 8 → 16…

設計邏輯：一開始不知道網路能承受多少，所以先小量試探；沒出問題就快速加倍，很快就能找到頻寬上限。一旦丟包（代表踩到上限），就退回去慢慢加。

這是很經典的「探測未知上限」演算法設計，和二分搜尋的精神類似。

5-4　TCP 標頭重點欄位與旗標

旗標意義
SYN請求建立連線（同步序號）
ACK確認欄位有效
FIN正常結束連線
RST強制重置連線（如連到未開放的埠）
PSH要求立即推送給應用層，不等緩衝區滿
URG緊急資料指標有效
✅ 資安連結：旗標與掃描技術 SYN Scan（半開放掃描）：只送 SYN，收到 SYN+ACK 表示埠開放，然後送 RST 中斷 → 不完成交握，較不易被記錄。
SYN Flood 攻擊：大量送 SYN 但不回第三次 ACK，耗盡伺服器的半開連線表 → 阻斷服務。
防護：SYN Cookie（不預先配置資源，把狀態編碼在序號裡）、縮短逾時、限制連線速率、部署 DDoS 清洗服務。

這一段同時是網路題也是資安題，兩科通吃。

2. 採最小權限：VPN 連入後不應可存取整個內網，須以網段與 ACL 限制。
3. 端點檢查：確認連入設備已更新、有防毒。
4. 保留連線日誌供稽核。
5. 考慮以零信任網路存取（ZTNA）逐步取代傳統 VPN。

7-4　新興網路技術

技術核心概念公部門應用
SDN（軟體定義網路）控制平面與資料平面分離，由集中控制器以軟體下達繞送策略資料中心彈性調度、快速套用網段隔離政策
NFV（網路功能虛擬化）以軟體取代專用硬體（防火牆、負載平衡器）降低設備採購成本、快速擴充
SD-WAN以軟體智慧選擇多條 WAN 線路分支機關連線最佳化與備援
5G高頻寬、低延遲、大連結；網路切片（Slicing）智慧城市、遠距醫療、應變通訊
邊緣運算在靠近資料來源處運算，減少回傳延遲與頻寬交通監控影像分析、IoT 感測
IoT大量低功耗裝置聯網環境監測、路燈與水電表管理
零信任網路不預設信任內網，每次存取皆驗證詳見下半部資安章節
⚠️ 新技術的資安風險（申論必寫的一段） SDN：控制器成為單點故障與高價值攻擊目標，一旦被入侵可操控全網 → 須高可用部署、控制通道加密、嚴格存取控管。
IoT：裝置運算資源少難以加密、預設密碼未更改、韌體長期不更新、生命週期長 → 常被組成殭屍網路（如 Mirai）發動 DDoS。應納入資產清冊、獨立網段、強制變更預設憑證、建立韌體更新機制。
5G／邊緣：攻擊面由中心擴散至邊緣節點，實體安全與遠端管理皆須納管。
