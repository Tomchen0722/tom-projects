# AWS SAA-C03 四大領域重點筆記

考試資訊：65 題（50 計分 + 15 不計分）｜130 分鐘｜及格 720/1000（約 72%）｜題型：單選 + 多選

---

## 領域 1：設計安全架構（30%）

### 1.1 身分與存取（IAM）
- **最小權限原則**是所有題目的底層邏輯。
- 明確 Deny > SCP/Boundary 上限 > 明確 Allow > 預設隱含 Deny。
- EC2/Lambda/ECS 存取 AWS 服務 → 一律用 **IAM Role**，不用 Access Key。
- 跨帳號 → **AssumeRole (STS)**；第三方 → 加 **External ID**。
- 大量終端使用者（App/網站會員）→ **Cognito**，不是 IAM User。
- 企業 AD/SAML 整合 → IAM Identity Center（SSO）或 SAML 聯合。
- 組織強制限制（區域、服務、防止關閉 CloudTrail）→ **SCP**。

### 1.2 資料加密
- 靜態加密：S3（SSE-S3/SSE-KMS/SSE-C）、EBS、RDS、DynamoDB 皆整合 KMS。
- 需要「金鑰使用稽核 + 自訂輪換」→ **KMS 客戶管理金鑰**。
- 需要「完全掌控金鑰 + 專用硬體」→ **CloudHSM**。
- 傳輸加密：TLS/HTTPS；ACM 免費管理憑證（自動續期）。
- RDS/EBS 已存在的未加密資源 → 建快照 → 複製時加密 → 還原（不能直接開啟加密）。

### 1.3 網路安全
- 分層防護：WAF（L7）→ SG（執行個體、有狀態）→ NACL（子網路、無狀態）。
- 私有子網路出網際網路 → NAT Gateway（放在公有子網路）。
- 私有存取 AWS 服務 → VPC Endpoint（S3/DynamoDB 用 Gateway、其他用 Interface）。
- 堡壘機已過時，考題偏好 **SSM Session Manager**（免開 22 port、有稽核）。

### 1.4 監控與偵測
- CloudTrail = 誰做了什麼 API（稽核）。
- Config = 資源組態變更與合規（例如「偵測未加密的 EBS」）。
- GuardDuty = 智慧威脅偵測。Inspector = 弱點掃描。Macie = S3 PII。
- Security Hub = 全部彙整。Detective = 深入調查根因。

## 領域 2：設計彈性架構（26%）

### 2.1 高可用基本功
- 標準組合：**多 AZ 的 ASG + ELB**，資料層 RDS Multi-AZ。
- ELB 健康檢查失敗 → 停止導流；ASG 健康檢查失敗 → 終止並替換。
- 無狀態化：Session 移到 **ElastiCache / DynamoDB**，檔案移到 **S3 / EFS**。

### 2.2 解耦
- 元件間直接呼叫 → 改用 **SQS**（緩衝、削峰）或 **SNS**（fan-out）。
- 佇列深度（ApproximateNumberOfMessagesVisible）可作為 ASG 擴展指標。
- 工作流程協調 → Step Functions。

### 2.3 災難復原（必考）
| 策略 | RTO/RPO | 成本 | 關鍵字 |
|---|---|---|---|
| Backup & Restore | 小時級 | 最低 | 僅備份到 S3/Glacier |
| Pilot Light | 十分鐘級 | 低 | 核心（DB）常駐複寫，其餘關閉 |
| Warm Standby | 分鐘級 | 中 | 縮小版全系統常駐 |
| Multi-Site Active-Active | 秒級 | 最高 | 雙站全量 + Route 53 分流 |

- RPO = 能容忍遺失多少資料；RTO = 能容忍停機多久。
- Aurora Global Database：RPO ~1 秒、RTO <1 分鐘。

### 2.4 備份
- AWS Backup：跨服務集中備份政策（EBS/RDS/DynamoDB/EFS...）。
- S3 跨區域複寫 (CRR)：需開 Versioning，僅複寫新物件。
- 快照皆存於 S3（看不到），可跨區域複製。

## 領域 3：設計高效能架構（24%）

### 3.1 運算擴展
- 垂直（加大機型）有上限；**水平（加台數）**才是雲的答案。
- 突發流量且無法預測 → 無伺服器（Lambda / Fargate / DynamoDB On-Demand）。
- Lambda 冷啟動 → Provisioned Concurrency。

### 3.2 儲存效能
- gp3 可獨立調 IOPS/吞吐（不綁容量，比 gp2 划算）。
- >16K IOPS → io2；>64K IOPS → io2 Block Express（需 Nitro）。
- S3 效能：prefix 分散可平行擴展；大檔用 Multipart；範圍讀取用 Byte-Range Fetch。

### 3.3 快取層層疊
使用者 → CloudFront（邊緣） → API Gateway 快取 → ElastiCache / DAX（資料層） → 資料庫
- 「降低資料庫負載」幾乎都選 ElastiCache 或 Read Replica（讀多場景）。
- 「微秒級 DynamoDB 讀取」→ DAX。

### 3.4 網路效能
- 同 AZ 延遲最低；Cluster Placement Group 用於 HPC。
- Enhanced Networking (ENA) 免費預設；EFA 用於 MPI HPC 工作負載。
- 全球加速：HTTP → CloudFront；TCP/UDP → Global Accelerator。

## 領域 4：設計成本優化架構（20%）

### 4.1 運算成本
- 穩定基載 → Savings Plans / RI；尖峰 → On-Demand；可中斷 → Spot。
- 混合策略：ASG 可同時使用 On-Demand（基載）+ Spot（彈性）。
- 開發環境下班自動關機（Instance Scheduler）。

### 4.2 儲存成本
- Lifecycle Policy 是 S3 省錢核心；未知模式用 Intelligent-Tiering。
- 注意隱藏費：IA/Glacier 有**取回費**與**最短儲存天數**（IA 30 天、Glacier 90 天、Deep Archive 180 天）。
- EBS：gp2 → gp3 直接省 20%；刪除未掛載磁碟區與過期快照。

### 4.3 網路成本（常被忽略的考點）
- 傳入免費、同 AZ 免費、跨 AZ 收費、出網際網路最貴。
- NAT Gateway 資料處理費 → S3/DynamoDB 流量改走 Gateway Endpoint（免費）。
- 大量傳出 → CloudFront 單價較低且有免費額度。

### 4.4 監控與治理
- Budgets 警示（可用預測值）、Cost Explorer 分析、CUR 明細。
- Cost Allocation Tags 分部門追蹤；Organizations 合併帳單共享折扣。

## 考試技巧

1. **先找限制條件**：題目中的 MOST cost-effective / HIGHLY available / LEAST operational overhead 決定答案方向。
2. **LEAST operational overhead** → 幾乎都選無伺服器/全受管服務。
3. **刪去法**：先刪明顯錯誤的兩個選項，再比較剩下兩個的差異。
4. 看到「不要走網際網路」→ VPC Endpoint / Direct Connect / PrivateLink。
5. 看到「立即、全域、毫秒」→ 快取類服務。
6. 不確定就選 AWS 原生全受管服務，而非自建方案。
