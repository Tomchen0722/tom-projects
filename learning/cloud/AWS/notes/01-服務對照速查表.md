### 容器選型（第 11、16 章）

| 需求關鍵字 | 選擇 |
|---|---|
| 沒有 K8s 經驗、最少維運 | **ECS + Fargate** |
| 需多雲可攜、要用 Helm / Istio / Argo CD | **EKS** |
| 容器內程式要存取 AWS 服務 | ECS **Task Role**（不是 Execution Role） |

## 儲存

| 需求關鍵字 | 選擇 |
|---|---|
| 存取模式未知、自動優化成本 | S3 Intelligent-Tiering |
| 低頻存取但要即時取得 | S3 Standard-IA |
| 封存、可接受數小時取回 | Glacier Flexible / Deep Archive |
| 防刪改（WORM）合規 | S3 Object Lock |
| 多台 EC2 跨 AZ 共用檔案（Linux） | **EFS** |
| 資料庫用高 IOPS 磁碟 | EBS io2 / io2 Block Express |
| 通用 SSD、性價比 | EBS gp3 |
| 超高效能暫存、可遺失 | Instance Store |
| PB 級離線遷移 | Snowball Edge |
| 遠距離加速上傳 S3 | Transfer Acceleration + Multipart |

### FSx 四選一（第 20 章）

| 需求關鍵字 | 選擇 |
|---|---|
| Windows 共用、**AD 整合**、NTFS ACL | **FSx for Windows File Server** |
| HPC / ML、高吞吐 POSIX、**連結 S3** | **FSx for Lustre** |
| **NFS + SMB + iSCSI 多協定**、NetApp 既有環境 | **FSx for NetApp ONTAP** |
| Linux NFS 遷移、要 **ZFS 快照** | **FSx for OpenZFS** |
| 只是單純的 Linux 共用目錄 | **EFS**（不要硬選 FSx） |

- **Lustre Scratch vs Persistent**：Scratch 不複寫、故障即遺失、算完就丟；Persistent 同 AZ 內複寫且自動修復，長期執行用。
- Lustre 吞吐量**跟著容量走**（每 TiB 多少 MB/s），要更快就要買更大。
- FSx 與 EFS 都**必須用 DNS 名稱掛載**——Multi-AZ 容錯移轉後 IP 會變。

### EFS 細節（第 20 章）

| 需求關鍵字 | 選擇 |
|---|---|
| 開發測試、可接受單 AZ 故障、要最省 | EFS **One Zone** |
| 不知道哪些檔案還在用、想自動省錢 | **生命週期管理**（N 天未存取轉 IA，被讀到自動轉回） |
| 資料量小卻要高吞吐、效能忽快忽慢 | 從 Bursting 改 **Elastic** 或 Provisioned |
| Lambda / 多租戶要強制 POSIX 身分與根目錄 | **EFS Access Point** |
| 傳輸加密 | 掛載加 `-o tls`（amazon-efs-utils） |

### Storage Gateway 四種（第 20 章）

| 需求關鍵字 | 選擇 |
|---|---|
| 地端用 NFS/SMB 寫進 S3 | **S3 File Gateway** |
| 分公司存取雲端 Windows 共用太慢 | **FSx File Gateway** |
| **地端空間不夠**、但要保留低延遲 | Volume Gateway — **Cached** |
| **地端要完整低延遲**、雲端只當災備 | Volume Gateway — **Stored** |
| 淘汰實體磁帶庫、**備份軟體不能換** | **Tape Gateway** |

> 記法：**Cached = 快取在地端**（主體在雲）；**Stored = 儲存在地端**（主體在地）。名字說的是「地端有什麼」。

### 備份（第 20 章）

| 需求關鍵字 | 選擇 |
|---|---|
| 多服務 + 多帳號 + 跨區域統一備份 | **AWS Backup**（+ Organizations 備份政策） |
| **只有** EBS 快照與 AMI，要最輕量 | **DLM**（Data Lifecycle Manager） |
| 備份不可刪除（含 root）、法規 WORM | **Vault Lock — Compliance 模式**（不可逆） |
| 防誤刪但保留管理彈性 | Vault Lock — Governance 模式 |
| **防勒索軟體** | 跨帳號複製到獨立備份帳號 **+ Vault Lock** |
| 證明備份真的還原得回來 | AWS Backup **還原測試計畫** |

> **沒測過的備份等於沒有備份。**「從未執行還原測試」通常判 Major。

### S3 進階功能（第 04 章）

| 需求關鍵字 | 選擇 |
|---|---|
| 單一大檔只要其中幾欄、想少傳資料 | **S3 Select** |
| 對整個資料湖下完整 SQL、要 JOIN | **Athena**（不是 S3 Select） |
| 一個 bucket 多團隊共用、政策太肥 | **S3 Access Point** |
| 只允許從特定 VPC 存取 | **VPC-only Access Point** |
| 一個全球端點自動導到最近複本 | **Multi-Region Access Point** |
| 同一份資料兩種視圖（去識別化 / 完整） | **S3 Object Lambda**（不要存兩份） |
| 公開資料集、不想付傳出費 | **Requester Pays**（需已驗證 AWS 身分） |
| 對幾百萬個**既有**物件做同一件事 | **S3 Batch Operations** |
| 讓「**以後**」符合條件的自動處理 | Lifecycle 規則 |
| 全帳號 S3 用量與異常儀表板 | **S3 Storage Lens**（免費版就很好用） |
| 分析哪些前綴適合轉 IA | **Storage Class Analysis** |

## 網路與內容遞送

| 需求關鍵字 | 選擇 |
|---|---|
| HTTP 全球快取 CDN | CloudFront |
| TCP/UDP、固定 Anycast IP、全球加速 | Global Accelerator |
| L7 路徑 / 主機路由 | ALB |
| L4 超高效能、固定 IP | NLB |
| 部署第三方防火牆 | Gateway Load Balancer |
| 私有存取 S3/DynamoDB（免費） | **Gateway VPC Endpoint** |
| 私有存取其他 AWS 服務 | **Interface Endpoint (PrivateLink)** |
| **地端**要私有存取 S3 | **Interface Endpoint** 或 DX Public VIF（Gateway Endpoint **做不到**） |
| 大量 VPC 互連中樞 | Transit Gateway |
| **只有兩個** VPC、要最低成本 | VPC Peering（不可遞移、網段不可重疊） |
| 只曝露一個服務、不想開放整個 VPC | **PrivateLink Endpoint Service**（+ NLB） |
| 多帳號共用同一個 VPC、要最低成本 | **RAM 共享子網路** |
| DNS 主備容錯 | Route 53 Failover + Health Check |
| 依延遲導流 | Route 53 Latency Routing |
| 依地理位置導流（版權限制） | Route 53 Geolocation |
| IPv6 只出不進 | **Egress-Only Internet Gateway**（NAT GW 只管 IPv4） |

### 混合連線（第 19 章）

| 需求關鍵字 | 選擇 |
|---|---|
| **盡快 / 下週就要**通 | Site-to-Site VPN |
| 穩定頻寬、可預測延遲 | Direct Connect |
| DX 施工中的過渡方案 | 先 VPN，DX 完成後轉備援 |
| DX 的**低成本備援** | DX 主 + **VPN 備**（兩邊都要跑 BGP） |
| 要 **99.99%** SLA | **兩個 DX 位置，各兩條連線** |
| 要 99.9% SLA | 兩個 DX 位置各一條 |
| VPN 頻寬不夠、不想拉 DX | **TGW + 多條 VPN + ECMP**（VGW 不支援 ECMP） |
| 跨洲、公網品質差 | **Accelerated VPN**（僅 TGW 支援） |

**Direct Connect 三種 VIF**

| 要進哪裡 | 用哪種 VIF |
|---|---|
| **一個** VPC 的私有 IP | **Private VIF**（接 VGW 或 DX Gateway） |
| S3/DynamoDB 等**公有端點**、可跨區 | **Public VIF**（也可在上面跑 VPN over DX 做加密） |
| **一堆** VPC（後面接 TGW） | **Transit VIF**（接 DX Gateway → TGW） |

- DX **預設不加密**。要加密 → VPN over DX，或 MACsec（僅 10G/100G 專用連線且地點支援）。
- **LAG ≠ 高可用**：4 條線都在同一個 DX 位置，只擋裝置故障。
- **DX Gateway 不做 VPC 互轉**：掛在上面的兩個 VPC 彼此不通。
- **TGW 附件沒涵蓋到的 AZ 走不通**——最難查的 TGW 故障。

### 混合 DNS（第 19 章）

| 需求關鍵字 | 選擇 |
|---|---|
| VPC 內建 resolver 位址 | CIDR 基底 **+2**（如 10.0.0.2），或 169.254.169.253 |
| **地端 → 查 AWS** 的私有名稱 | **Inbound Endpoint** |
| **AWS → 查地端** 的名稱 | **Outbound Endpoint + Resolver Rule** |
| 題目說「**互相**解析」 | **兩個 Endpoint 都要建** |
| 封鎖惡意網域查詢 | Route 53 **DNS Firewall** |
| 規則要給全組織共用 | 用 **RAM** 分享 Resolver Rule |

> 每個 Endpoint 至少兩個 IP 且不同 AZ；SG 要開 **TCP 與 UDP 53**（只開 UDP 會出現部分查詢逾時）。

### CloudFront 進階（第 04 章）

| 需求關鍵字 | 選擇 |
|---|---|
| S3 只能經由 CloudFront 存取 | **OAC**（取代舊的 OAI） |
| 保護**單一檔案** | **Signed URL** |
| 保護**整個路徑**、不想改網址 | **Signed Cookie** |
| 讓使用者直接上傳到 S3、不經自家伺服器 | **S3 預簽章網址**（繞過 CDN） |
| 僅限特定國家觀看 | CloudFront **Geo Restriction** |
| 標頭 / URL 改寫、極高 QPS、最低成本 | **CloudFront Functions** |
| 要連網路 / 讀請求主體 / A-B 測試 | **Lambda@Edge**（須建在 **us-east-1**、無環境變數） |

### 維運與目錄（第 21 章）

| 需求關鍵字 | 選擇 |
|---|---|
| 登入私有 EC2、不開 22 埠、要稽核 | **SSM Session Manager** |
| 從筆電連私有 RDS、不想開 VPN | Session Manager **連接埠轉發** |
| 對一批機器**執行一次**命令 | **Run Command** |
| **多步驟**跨資源流程、自動修復 | **Automation**（Runbook） |
| **持續維持**組態、防漂移 | **State Manager** |
| 作業系統修補與合規報表 | **Patch Manager** |
| 盤點機器**裡面裝了什麼軟體** | **SSM Inventory** |
| 已有地端 AD、**不在雲端放副本** | **AD Connector**（地端斷線即無法驗證） |

**SSM 三個前置條件**（機器沒上線就依序查這三個）：

1. SSM Agent 有裝且在跑
2. **IAM 執行個體設定檔**（`AmazonSSMManagedInstanceCore`）← 最常漏掉
3. 網路通（NAT/IGW 或 Interface Endpoint）

> 私有子網路要 **ssm / ssmmessages / ec2messages** 三個 Endpoint + S3 Gateway Endpoint。
> **看得到機器但連不進去 = 缺 `ssmmessages`。**
> Patch Group 的標籤鍵名固定是 `Patch Group`（**中間有空格、大小寫敏感**）。

## 遷移與混合基礎架構（第 15、19、22 章）

| 需求關鍵字 | 選擇 |
|---|---|
| 檔案**搬一次**或排程同步（NFS/SMB → S3/EFS/FSx） | **DataSync** |
| 地端**持續**透過檔案介面存取雲端 | **Storage Gateway** |
| 資料庫遷移、最小停機 | **DMS**（異質先用 **SCT** 轉結構） |
| 整台伺服器 lift-and-shift | **MGN**（Application Migration Service） |
| 地端伺服器要 DR，RPO 秒級、平時不想開機 | **Elastic Disaster Recovery (DRS)** |
| 既有 SFTP 流程、想直接落地 S3 | **Transfer Family** |
| 頻寬不足、離線寄送 | **Snowball Edge** |
| 追蹤整體遷移進度 | **Migration Hub**（它不搬東西，只是儀表板） |
| 資料**必須留在自家機房** | **Outposts** |
| 大都會個位數毫秒、**不自建機房** | **Local Zones** |
| **5G** 行動使用者極低延遲 | **Wavelength** |
| 船舶 / 工地 / **斷網**環境要邊緣運算 | **Snowball Edge / Snowcone** |

> **7R 策略**：Rehost（純搬）／Replatform（小改）／Refactor（重寫）／Repurchase（改買 SaaS）／Relocate（VMware 整批）／Retain（暫時不動）／Retire（淘汰）。
> 「最快上雲、改動最小」→ Rehost；「長期成本與彈性最佳」→ Refactor。

### 常被忽略的成本陷阱

| 陷阱 | 說明 |
|---|---|
| **Interface Endpoint 開太多** | 每個 AZ 一個 ENI、每個都在跳表。20 個服務 × 3 AZ = 60 個 ENI 的固定月費，可能比 NAT Gateway 還貴。**S3/DynamoDB 一律用免費的 Gateway Endpoint。** |
| **TGW vs Peering** | TGW 有附件時數費 + 每 GB 處理費；**Peering 兩者都沒有**。只有兩個 VPC 時 Peering 更省。 |
| **RAM 共享子網路** | 多帳號能共用一個 VPC 時最省——同 VPC 內流量**沒有處理費**。 |
| **跨 AZ 流量** | HA 架構的隱藏成本，每 GB 計費。 |
| **NAT Gateway 處理費** | S3/DynamoDB 流量改走 Gateway Endpoint 可直接消除。 |
| **冷儲存最短天數** | IA 30 天、Glacier 90 天、Deep Archive 180 天；提前刪除仍按最短天數計費。 |
| **未掛載的 EBS 與閒置 EIP** | 機器刪了磁碟沒刪；2024 年起**所有**公網 IPv4 每小時收費。 |
| **FSx 吞吐容量** | 與儲存容量**分開計費**，一開始常開太大，帳單有一半是吞吐費。 |

## 最後一分鐘：最容易搞反的十組

| A | B | 判斷點 |
|---|---|---|
| Multi-AZ | Read Replica | **高可用** vs **讀取擴展** |
| Gateway Endpoint | Interface Endpoint | 只有 S3/DynamoDB 且**地端用不到** vs 幾乎所有服務且**地端可用** |
| Cached Volume | Stored Volume | 主體**在雲** vs 主體**在地端** |
| Inbound Resolver | Outbound Resolver | 地端**查** AWS vs AWS **查**地端 |
| Signed URL | Signed Cookie | **一個**檔案 vs **一整個路徑** |
| CloudFront Functions | Lambda@Edge | 不用連網、要最快最便宜 vs 要連網或讀請求主體 |
| Outposts | Local Zones | 在**你的**機房 vs 在 **AWS 的**都會據點 |
| Detective | GuardDuty | **調查根因** vs **偵測有事發生** |
| Artifact | Audit Manager | **AWS 自己**的報告 vs **我的**環境證據 |
| Secrets Manager | Parameter Store | 要**自動輪換** vs 要**免費** |
| DataSync | Storage Gateway | **搬一次** vs **長期持續存取** |
| DLM | AWS Backup | **只有 EBS** vs 多服務多帳號 |
