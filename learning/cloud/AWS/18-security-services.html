資安服務家族全解

GuardDuty、Inspector、Macie、Security Hub、WAF、Shield——名字都很像，但各看一個不同的面向。這一課把它們排進一張圖，讓你看到題目就知道該選誰。

1. 先建立地圖：六個服務各看什麼

把公司想成一棟大樓：
Shield / WAF = 大門的警衛與門禁（擋外面的壞人）
GuardDuty = 保全監視系統（發現有人在做奇怪的事）
Inspector = 定期消防安檢（找出建築本身的缺陷）
Macie = 資料室盤點（哪裡放了機密文件卻沒鎖）
Security Hub = 保全中控室（把所有警報集中在一面牆上）
服務看什麼資料來源一句話關鍵字
GuardDuty行為異常CloudTrail、VPC Flow Logs、DNS 日誌可疑活動、加密貨幣挖礦、外洩憑證
Inspector漏洞EC2、ECR 映像、LambdaCVE、未修補的軟體
Macie敏感資料S3 物件內容S3 裡有沒有個資
Security Hub彙整上面全部 + 合規基準統一儀表板、CIS/PCI 合規分數
WAF第 7 層攻擊HTTP 請求SQL 注入、XSS、速率限制
ShieldDDoS網路層流量大流量攻擊
📋最重要的一組分辨：GuardDuty vs Inspector。
• Inspector 問「我的系統有沒有已知的弱點」——這是預防，沒被攻擊也會有發現。
• GuardDuty 問「現在有沒有人正在做壞事」——這是偵測，看的是實際發生的行為。
考試把這兩個放同一題選項是常態。

2. GuardDuty：威脅偵測

GuardDuty 持續分析三種日誌，用機器學習與威脅情報找出異常行為。它不需要你安裝任何代理程式，開啟就開始看。

GuardDuty 分析的三個來源 CloudTrail 事件 ──→ 誰呼叫了什麼 API VPC Flow Logs ──→ 誰跟誰在通訊 DNS 日誌 ──→ 查詢了什麼網域 典型的發現 • EC2 正在與已知的挖礦礦池通訊 • IAM 憑證從異常的國家被使用 • EC2 對外進行連接埠掃描 • 有人嘗試停用 CloudTrail（攻擊者在湮滅證據） • S3 資料被異常大量下載 可額外啟用的保護 S3 Protection / EKS Protection / Malware Protection / RDS Protection
✅ 考試關鍵字：「不需安裝代理程式」「持續監控可疑活動」「偵測遭外洩的憑證」→ GuardDuty。
企業實務：一定要開在 Organization 層級
GuardDuty 支援指定一個委派管理員帳號，一次涵蓋組織下所有帳號，新開的帳號自動納管。
如果一個帳號一個帳號手動開，一定會漏——而攻擊者最愛的就是那個被遺忘的測試帳號。

同樣的原則適用於 Security Hub、Inspector、Config：組織層級啟用 + 自動納管新帳號。

3. Inspector：漏洞掃描

Inspector 檢查你的運算資源有沒有已知漏洞（CVE）與不安全的網路暴露。

EC2 掃描透過 SSM Agent 檢查安裝的套件版本，比對 CVE 資料庫。所以 EC2 要先被 Systems Manager 納管。
ECR 映像掃描映像推上去就自動掃，找出基底映像與相依套件的漏洞。可設定持續重掃（新 CVE 公布時回頭比對）。
Lambda 掃描檢查函式的相依套件與程式碼。
網路可達性分析 SG/NACL/路由，找出「這台機器意外地能從網際網路直接連到」。
陷阱：Inspector 需要 SSM Agent
EC2 掃描不是憑空發生的——Inspector 透過 Systems Manager 的代理程式取得套件清單。
所以題目若說「Inspector 掃不到某些 EC2」，方向是：SSM Agent 沒裝、EC2 沒有 SSM 的 IAM 角色、或沒有到 SSM 端點的網路路徑（私有子網路要有 VPC Endpoint）。

對照記憶：GuardDuty 不需要代理程式（看日誌），Inspector 需要（看機器內部）。
企業實務：把掃描往左移
等到 EC2 上線才掃漏洞，發現了也很難改。成熟做法是在 CI 階段就掃（第 17 課）：
映像推上 ECR 時掃 → 有 critical 漏洞就擋下管線，不讓它進到正式環境。

再搭配 ECR 的持續重掃：新 CVE 公布時，已經在跑的映像也會被重新標記——因為「當時安全」不等於「現在安全」。

4. Macie：敏感資料發現

Macie 專門掃 S3 裡的物件內容，找出個資與機密。它回答的問題是「我到底把什麼東西放在哪裡了」。

Macie 能找出例子
個人識別資訊（PII）姓名、地址、身分證字號、護照號碼
金融資料信用卡號、銀行帳號
憑證與金鑰不小心上傳的 API key、私鑰
儲存桶風險哪些 bucket 是公開的、沒加密、與外部帳號共享
陷阱：Macie vs Comprehend 的 PII 偵測
第 14 課提過 Comprehend 也能找個資，兩者差在切入點：
• Macie = 從資產面掃描。「我的 S3 裡有沒有個資」，會自動探索 bucket、抽樣、評估風險。
• Comprehend = 從內容面分析。你把一段文字丟給它，它告訴你裡面有哪些 PII 實體。

題目說「盤點 S3 中的敏感資料」→ Macie。說「在應用流程中即時遮蔽文字裡的個資」→ Comprehend。
企業實務：Macie 是按掃描量計費的
對著 PB 級的資料湖無差別全掃，帳單會很可觀。務實做法：
① 先讓 Macie 做bucket 層級的盤點（哪些公開、哪些沒加密）——這部分便宜且價值高
② 只對可能有個資的 bucket 開內容掃描
③ 用抽樣而非全量，並設定排程而非持續

這件事在導入前就要試算，不然第一張帳單會嚇到人。

5. Security Hub：集中儀表板

前面每個服務都各自產生發現（findings）。服務一多，沒有人看得完。Security Hub 解決這個問題。

Security Hub 的兩個角色 ① 聚合器 GuardDuty ─┐ Inspector ─┤ Macie ─────┼──→ Security Hub ──→ 統一格式（ASFF） Config ────┤ │ IAM Access ┘ └─→ 依嚴重度排序、去重、跨帳號彙總 Analyzer ② 合規檢查 內建基準,自動打分數： • AWS 基礎安全最佳實務 • CIS AWS Foundations Benchmark • PCI DSS → 產出「你有 87% 的檢查項目通過」這種可向管理層報告的數字
✅ 考試關鍵字：「跨帳號彙整所有資安發現」「統一檢視」「合規分數」→ Security Hub。
注意它自己不做偵測——它是把別人的發現集中起來。題目若問「誰去偵測威脅」，答案是 GuardDuty 不是 Security Hub。

6. 邊界防禦：WAF、Shield、Network Firewall

服務OSI 層擋什麼掛在哪
Shield Standard3/4 層常見 DDoS，免費且自動啟用全 AWS 自動
Shield Advanced3/4/7 層大規模 DDoS + 費用保護 + 24/7 應變團隊需訂閱（月費高）
WAF7 層SQL 注入、XSS、惡意 Bot、地理封鎖、速率限制CloudFront、ALB、API Gateway、AppSync
Network Firewall3-7 層VPC 層級的流量過濾、網域白名單、IPSVPC（需專用子網路）
陷阱：WAF 不能掛在 EC2 或 NLB 上
WAF 只能關聯到 CloudFront、ALB、API Gateway、AppSync、Cognito User Pool。
NLB 是第 4 層，看不到 HTTP 內容，所以掛不了 WAF。
如果架構是「NLB → EC2」而需要 WAF，就要改成 ALB，或在前面加 CloudFront。
陷阱：Shield Advanced 的隱藏價值是「費用保護」
被 DDoS 攻擊時，就算服務沒掛，自動擴展與流量費用會暴增。Shield Advanced 提供這部分的費用抵免。
題目若提到「擔心 DDoS 造成的意外帳單」→ 這是 Shield Advanced 的賣點之一，不只是防護能力。
企業實務：WAF 一定要先用「計數模式」
直接把 WAF 規則開成封鎖，很可能擋掉正常使用者——尤其是託管規則組裡的一些規則對正常流量誤判率不低。

正確流程：
① 規則先設為 Count（只計數不封鎖）
② 觀察一到兩週，看哪些規則會誤傷正常流量
③ 調整例外後，才改成 Block

跳過這一步而在上線日直接開封鎖，是很典型的自己打自己。

7. 自動化應變

偵測到問題之後，人不可能 24 小時盯著儀表板。企業會把常見的處置自動化。

標準的自動應變架構 GuardDuty 發現 ──→ EventBridge 規則 ──→ 動作 │ ┌───────────────────┼───────────────────┐ ↓ ↓ ↓ Lambda SNS Systems Manager 自動隔離主機 通知資安團隊 執行 Runbook （換成隔離用 SG） （或進 Slack） （收集鑑識資料） 常見的自動處置 • 憑證外洩 → 立即撤銷該 IAM 使用者的金鑰 • EC2 被入侵 → 換成隔離 SG、建立快照留證、移出 ASG • S3 意外公開 → 自動關閉公開存取並通知擁有者
陷阱：自動處置要考慮誤判
自動關機、自動撤銷憑證聽起來很帥，但誤判一次就是自己造成的服務中斷。
實務上的分級：
• 高信心且低風險的處置才全自動（例如關閉 S3 公開存取）
• 影響服務的處置（隔離主機、撤銷憑證）先送通知 + 一鍵執行的 Runbook，由人按下去

「自動偵測 + 人工決策 + 一鍵處置」通常比全自動更實用。

8. 考試陷阱整理

陷阱 1：GuardDuty vs Inspector
行為異常（正在被攻擊）→ GuardDuty；已知漏洞（有弱點）→ Inspector。
陷阱 2：Macie 只管 S3
它掃的是 S3 物件內容。要找 RDS 或 DynamoDB 裡的個資不是 Macie 的工作。
陷阱 3：Security Hub 不做偵測
它只彙整。偵測是 GuardDuty/Inspector/Macie 的事。
陷阱 4：WAF 掛不上 NLB
只能是 CloudFront / ALB / API Gateway / AppSync / Cognito。
陷阱 5：Shield Standard 是免費且已經啟用的
題目問「如何取得基本 DDoS 防護」→ 已經有了，不用做任何事。要進階才需 Advanced。
陷阱 6：Inspector 需要 SSM Agent
掃不到 EC2 → 檢查 SSM Agent、IAM 角色、VPC Endpoint。
陷阱 7：組織層級啟用
多帳號環境的資安服務，答案幾乎都是「用委派管理員在 Organization 層級啟用並自動納管新帳號」。
💡一句話記憶：
看行為找 GuardDuty，看漏洞找 Inspector，看 S3 個資找 Macie，看總表找 Security Hub，擋 7 層找 WAF，擋 DDoS 找 Shield。
