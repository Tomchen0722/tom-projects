1. Cognito 兩個池：一句話區分

User Pool = 「你是誰？」 → 身分驗證（Authentication）→ 發 JWT Token
Identity Pool = 「你能做什麼？」 → AWS 資源存取授權 → 發 STS 臨時憑證

Cognito User Pool（身分提供者）

  • 管理使用者帳號（Email/密碼）
  • 支援 Google、Facebook、SAML SSO 整合
  • MFA、帳號驗證、密碼政策
  • 登入後發 JWT Token（ID / Access / Refresh）
  • 常搭配 API Gateway Cognito Authorizer

Cognito Identity Pool（聯合身分）

  • 不儲存使用者帳號
  • 接受外部身分（User Pool JWT、Google、Facebook、SAML、未認證）
  • 換取 STS 臨時 IAM 憑證
  • 直接 call AWS API（S3、DynamoDB、Kinesis）
  • 常用：手機 App 直接上傳到 S3
最常考的組合：User Pool + Identity Pool
使用者 → 在 User Pool 登入拿 JWT → 把 JWT 丟給 Identity Pool 換 STS 臨時憑證 → 用 STS 憑證直接存取 S3 / DynamoDB

2. User Pool 深入

用戶端（手機 App / SPA）
↓ 帳密 / 第三方 SSO 登入
Cognito User Pool
↓ 回傳 3 個 Token
├── ID Token（JWT）：包含使用者身分資訊（email、sub、groups）
├── Access Token（JWT）：用於呼叫受保護的 API
└── Refresh Token：刷新 Access Token（預設 30 天）

API Gateway（設定 Cognito Authorizer）
└── 驗證 Access Token 的簽章和有效期 → 通過才放行

Hosted UI

User Pool 內建一個託管的登入頁（Cognito Hosted UI），不用自己寫登入介面。支援 OAuth 2.0 標準流程（Authorization Code + PKCE），可以自訂網域（如 auth.yourapp.com）。

Triggers（Lambda 觸發器）

觸發時機用途
Pre Sign-up自訂驗證邏輯（如：只允許公司域名 Email）
Post Confirmation使用者確認帳號後，把使用者資料寫入 DynamoDB
Pre Token Generation在 JWT Token 裡加入自訂屬性（如：使用者的訂閱層級）
Custom Authentication自訂挑戰（如：簡訊驗證碼 OTP）

3. Identity Pool 深入

App → User Pool 拿 JWT
↓
Identity Pool（設定信任的 User Pool）
↓ 呼叫 STS:AssumeRoleWithWebIdentity
STS → 回傳臨時憑證（最長 12 小時）
↓
App 直接 call AWS API（S3 / DynamoDB / Kinesis）

精細化授權（Row-Level Security）

IAM Policy 中可以用 Cognito Sub 當條件：

{
"Effect": "Allow",
"Action": "s3:GetObject",
"Resource": "arn:aws:s3:::my-bucket/${cognito-identity.amazonaws.com:sub}/*"
}

→ 每個使用者只能存取 S3 自己的「資料夾」，其他人的看不到
Guest Access（未認證存取）
Identity Pool 可以允許未登入的匿名使用者，給他們一個受限的 IAM Role（如只能讀公開內容）。這是 "Unauthenticated identities" 設定。

4. API Gateway 三種類型

類型協議適合場景考試關鍵點
REST API HTTP/HTTPS 標準 RESTful API，功能最完整（快取、使用量計劃、WAF 整合） 支援 API Key、Usage Plan（限流）；較貴
HTTP API HTTP/HTTPS 低延遲輕量 API（比 REST API 便宜 70%），適合 Lambda + OIDC/JWT 授權 不支援 AWS WAF；不支援 API Key；支援 OIDC/OAuth 2.0 JWT Authorizer
WebSocket API WebSocket 雙向即時通訊（聊天室、即時通知、遊戲） 連線管理用 connection ID；後端可 push 到客戶端
REST API vs HTTP API 選擇關鍵
需要 WAF、API Key 限流、Request/Response 轉換、Edge-Optimized → REST API
只需要低延遲 Lambda proxy + JWT 授權、成本敏感 → HTTP API

5. API Gateway 三種授權方式

Cognito Authorizer 驗證 Cognito User Pool 發的 JWT Token。

優點：AWS 管理，零程式碼。
適合：使用者登入後呼叫的 API。
Lambda Authorizer 你自己寫 Lambda 做驗證（Token 型或 Request 型）。

優點：完全自訂（第三方 OAuth、自建 JWT）。
成本：每次呼叫執行 Lambda（但有快取）。
IAM 授權 呼叫 API 需要有 AWS STS 臨時憑證，用 Signature Version 4 簽署請求。

優點：AWS 原生，適合服務間呼叫（S2S）。
適合：機器呼叫機器（不適合最終使用者）。
Cognito Authorizer：
App → API GW → 驗 JWT（User Pool 公鑰） → Lambda

Lambda Authorizer：
App → API GW → Lambda Authorizer（自訂邏輯） → IAM Policy → Lambda
（Lambda Authorizer 可快取授權結果 TTL 最長 3600 秒）

IAM 授權：
Service → STS 拿臨時憑證 → 用 SigV4 簽署請求 → API GW → Lambda

Resource Policy

API Gateway 還有 Resource Policy（資源政策），可以用 IP 白名單、VPC Endpoint 限制誰能存取 API，即使有認證也可以額外限制來源。

6. Organizations SCP：邏輯與陷阱

SCP（Service Control Policy）是 Organizations 組織層級的「硬上限」：即使帳號的 IAM Policy 允許某個操作，SCP 說「不行」就是不行。SCP 是守門員，IAM 是通行證——有通行證但守門員不讓過，還是進不去。
AWS Organizations 架構
├── Management Account（主管理帳號）
│ └── ⚠️ SCP 不影響 Management Account！
│ Management Account 永遠有全部權限
├── OU（組織單位）
│ ├── SCP 套用到整個 OU，OU 下所有帳號都受限
│ └── OU 可以嵌套，子 OU 繼承父 OU 的 SCP（更嚴格）
└── Member Account（成員帳號）
└── 同時受：帳號本身的 IAM Policy + 所在 OU 的 SCP

SCP 評估邏輯

有效權限 = IAM 允許的 ∩ SCP 允許的

兩個都允許 → 可以執行
IAM 允許 但 SCP 拒絕 → 不能執行
IAM 拒絕 但 SCP 允許 → 不能執行

明確 Deny（在任何地方）→ 永遠勝過任何 Allow
SCP 常見用途範例
Region 限制Deny 所有非 ap-northeast-1 的操作（只允許日本 Region）
禁止關閉 CloudTrailDeny cloudtrail:DeleteTrail / StopLogging（防止稽核紀錄被刪）
禁止建立外部 IAM 使用者Deny iam:CreateUser（強制用 SSO 登入，不允許長期憑證）
禁止離開組織Deny organizations:LeaveOrganization（防止成員帳號自己脫離）
資源標籤強制Deny 建立 EC2 / S3 但沒有 cost-center tag 的操作
最重要的 SCP 陷阱：Management Account 不受 SCP 限制
題目說「用 SCP 限制整個組織不能刪除 S3 Bucket」——但 Management Account 的使用者還是可以刪！SCP 對 Management Account 無效，這是 AWS 的設計（Management Account 是最後的緊急存取點）。解決方案：不要把工作資源放在 Management Account 裡。

7. 常見架構模式

模式一：行動 App 用戶直接存取 S3

手機 App
→ Cognito User Pool 登入，拿 JWT
→ Cognito Identity Pool 換 STS 臨時憑證
→ 直接呼叫 S3 API（上傳/下載自己的檔案）
→ S3 Bucket Policy + IAM Policy 控制存取（用 cognito sub 隔離）

模式二：API Gateway + Lambda 後端

手機 App
→ Cognito User Pool 登入，拿 JWT Access Token
→ 呼叫 API Gateway（Header: Authorization: Bearer {JWT}）
→ API Gateway Cognito Authorizer 驗 JWT
→ 驗通過 → 呼叫 Lambda（context 裡有使用者資訊）
→ Lambda 回傳結果

模式三：多帳號企業（Organizations）

Organizations
├── Management Account：只放 Billing、Organizations 管理
├── Security OU：Security Tooling Account（GuardDuty、Security Hub 集中）
├── Production OU：Production Account（SCP：禁止 Region 外操作）
└── Dev OU：Dev Account（SCP：禁止大型 EC2、禁止高費用服務）
📋 考前速查：三個選擇題
Q：要讓手機 App 登入並直接存取 S3？ → Cognito User Pool + Identity Pool
Q：要讓 API Gateway 驗 JWT 授權？ → Cognito Authorizer（User Pool 提供 JWT）
Q：要禁止某個 OU 的所有帳號使用 EC2？ → SCP Deny ec2:*（記得 Management Account 不受限）
