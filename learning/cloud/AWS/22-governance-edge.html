多帳號治理與邊緣基礎架構

企業規模一大，問題就從「這台機器怎麼設」變成「三十個帳號怎麼保持一致」。這一課補上 Control Tower、Service Catalog、RAM、Firewall Manager 等治理工具，再把 Outposts / Local Zones / Wavelength 這組邊緣選項一次講清楚。

1. 為什麼要拆成很多帳號

單一帳號像把全公司的東西堆在同一個倉庫——找東西方便，但一場火就全沒了，而且沒辦法說清楚哪些貨是哪個部門的。
多帳號像每個部門一個獨立倉庫——多一點管理成本，但爆炸半徑被限制住，帳也算得清楚。
理由說明考題怎麼問
爆炸半徑隔離開發環境出事不會波及正式環境「限制安全事件的影響範圍」
權限邊界最乾淨帳號是 AWS 最硬的隔離邊界，比 IAM 政策可靠「確保團隊絕對無法存取彼此的資源」
服務配額獨立配額是每個帳號算的，不會互相排擠「一個團隊用光配額影響其他團隊」
成本歸屬清楚帳號層級的分帳比標籤可靠（標籤會忘記打）「精確分攤各部門雲端成本」
合規範圍縮小把受規範的工作負載關在專用帳號，稽核範圍就小「PCI DSS 稽核範圍最小化」
SAA 的預設立場是「多帳號 + Organizations」。只要題目出現「多個團隊」「多個環境」「集中管控」，正確答案幾乎不會是「在同一個帳號用 IAM 政策區分」——那是規模小的時候才成立的做法。

2. OU 結構怎麼設計

第 12 章講過 SCP 的評估邏輯，這裡補上「OU 樹要長什麼樣」——這是真正會出現在情境題裡的部分。

Root │ ├── Security OU ← 不放工作負載，只放安全與稽核 │ ├── Log Archive 帳號 （集中 CloudTrail / Config 日誌，唯讀） │ └── Audit 帳號 （Security Hub / GuardDuty 委派管理員） │ ├── Infrastructure OU ← 共用基礎設施 │ ├── Network 帳號 （TGW、DX、Route 53 Resolver、共享 VPC） │ └── Shared Services （AD、映像檔、CI/CD） │ ├── Workloads OU │ ├── Prod OU ← 最嚴格的 SCP │ └── NonProd OU ← 較寬鬆，但仍禁止高風險動作 │ ├── Sandbox OU ← 個人實驗，設預算上限、限制區域 │ └── Suspended OU ← 待關閉帳號，SCP 全 Deny
三個設計原則：
① 依「治理需求」分組，不要依組織架構分組——公司改組很頻繁，但「正式 vs 非正式」的治理需求不會變。
② OU 層級不要太深，SCP 是逐層相交的，太深會很難推理最終權限。
③ 管理帳號（management account）不放任何工作負載，因為 SCP 對管理帳號不生效。
SCP 對管理帳號完全無效。這代表管理帳號裡的資源沒有任何組織防護欄保護。所以管理帳號應該只做三件事：管理 Organizations、合併帳單、Control Tower。任何工作負載都不該放在那裡——這是常考的設計題。
Sandbox OU 的標準 SCP：限制區域 + 禁止昂貴機型
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyOutsideApproved Regions",
      "Effect": "Deny",
      "NotAction": [
        // 全球型服務要放行，否則帳號會壞掉
        "iam:*", "sts:*", "organizations:*", "route53:*",
        "cloudfront:*", "support:*", "budgets:*", "ce:*"
      ],
      "Resource": "*",
      "Condition": {
        "StringNotEquals": {
          "aws:RequestedRegion": ["ap-northeast-1", "us-east-1"]
        }
      }
    },
    {
      "Sid": "DenyExpensiveInstances",
      "Effect": "Deny",
      "Action": "ec2:RunInstances",
      "Resource": "arn:aws:ec2:*:*:instance/*",
      "Condition": {
        "StringNotLike": {
          "ec2:InstanceType": ["t3.*", "t4g.*", "m5.large"]
        }
      }
    }
  ]
}

3. Control Tower 與三種防護欄

Organizations提供零件：帳號、OU、SCP、合併帳單。什麼都要自己組。
Control Tower提供整套組好的：Landing Zone、標準 OU、日誌帳號、防護欄、開帳號流程。
兩者不是二選一。Control Tower 是建在 Organizations 之上的。考題問「基礎能力」（SCP、合併帳單）→ Organizations；問「快速建立符合規範的新帳號」「自動套用基準」→ Control Tower。

Landing Zone 幫你做好的事

1
建立 Security OU 與兩個帳號Log Archive（集中存放 CloudTrail 與 Config 日誌）、Audit（集中安全檢視與跨帳號稽核角色）。
2
集中日誌組織級 CloudTrail 與 Config 自動開啟並寫入 Log Archive 帳號，成員帳號無法關閉。
3
套用強制防護欄例如「禁止刪除日誌儲存貯體」「禁止關閉 CloudTrail」。
4
設定 IAM Identity Center員工用單一登入進入各帳號，不必在每個帳號建 IAM User。
5
Account Factory用標準化流程開新帳號，一建立就自動納入 OU、套上防護欄、設好網路基準。

三種防護欄（Controls）——這是考點

類型底層用什麼實作作用時機例子
預防性
Preventive		SCP動作發生前直接擋下禁止在未核准區域建立資源
偵測性
Detective		AWS Config 規則事後發現不合規偵測到 S3 儲存貯體公開讀取
主動性
Proactive		CloudFormation Hooks部署前檢查範本範本裡的 RDS 沒開加密就不讓部署
三個時間點記法：主動性在「還沒部署」時擋（看範本）；預防性在「正要執行 API」時擋（看動作）；偵測性在「已經做了」之後報（看結果）。
題目說「要能阻止而不是只是發現」→ 一定是預防性（SCP）或主動性，不會是 Config。
陷阱：用 Config 規則來「防止」不合規
Config 只能偵測與觸發修復，不能阻止動作發生。題目要求「使用者根本無法執行某動作」→ SCP。Config 是「做了之後把它改回來」。
導入提醒：Control Tower 對既有的 Organizations 是可以納管的，但既有帳號要一個一個 enroll，過程中如果帳號裡有跟防護欄衝突的資源會失敗。實務上通常是「新帳號一律走 Account Factory，舊帳號分批 enroll」。另外 Control Tower 本身不收費，但它開啟的 CloudTrail、Config、GuardDuty 等會產生費用，而且是每個帳號都有——帳號數量一多這筆固定成本相當可觀，要先估算。

4. Service Catalog：自助但受控

治理的兩難：完全放權會亂，完全集中會塞車。Service Catalog 的答案是「只准用我核准過的架構，但你可以自己按按鈕」。

平台團隊 開發團隊 │ │ 寫 CloudFormation 範本 │ │ │ ▼ │ Product（產品） │ │ │ ▼ │ Portfolio（產品組合） ──授權給──▶ 瀏覽可用產品 │ │ 設定啟動限制 ▼ （用指定的 Role 啟動） 點「啟動」填參數 │ │ └─────────────────────────────────────▶ 資源建立完成 開發者「沒有」建立 RDS 的權限，但可以透過產品啟動一台合規的 RDS。
啟動限制（Launch Constraint）是 Service Catalog 的精髓。使用者本身不需要底層資源的權限——實際建立資源的是產品指定的那個 IAM Role。所以開發者可以開出一台符合公司標準的 RDS，卻無法自己隨便開一台不合規的。
需求答案
快速建立符合規範的新帳號Control Tower（Account Factory）
讓團隊自助佈建但只能用核准過的架構Service Catalog
強制不能做某些動作SCP
偵測既有資源是否合規AWS Config
把資源分享給其他帳號用RAM

5. RAM：跨帳號分享資源

AWS Resource Access Manager 解決的是「同一份資源，多個帳號用」——不必複製、不必跨帳號 API 呼叫、不必額外付流量費。

常考的可分享資源

VPC 子網路網路集中管理，各帳號在共享子網路裡建自己的資源。同 VPC 內流量沒有處理費。
Transit Gateway網路帳號建一個 TGW，其他帳號直接附掛，不必各建一個。
Route 53 Resolver Rules混合 DNS 的轉送規則做一次，全組織共用（見第 19 章）。
License Manager 設定BYOL 授權集中管理與追蹤。
Capacity Reservation容量預留共享，避免各帳號各自預留造成浪費。
Service Catalog 產品組合核准過的架構一次分享給所有帳號。
# 先在 Organizations 啟用 RAM 共享（只需做一次，在管理帳號執行）
$ aws ram enable-sharing-with-aws-organizations

# 分享 Transit Gateway 給整個 Workloads OU
$ aws ram create-resource-share \
    --name shared-tgw \
    --resource-arns arn:aws:ec2:ap-northeast-1:111122223333:transit-gateway/tgw-0abc123 \
    --principals arn:aws:organizations::111122223333:ou/o-exampleorgid/ou-examplerootid-exampleouid \
    --allow-external-principals false

# 接收方確認自己拿到了什麼
$ aws ram list-resources --resource-owner OTHER-ACCOUNTS \
    --query 'resources[].[type,arn]' --output table
--allow-external-principals false 是重要的安全預設——它限制只能分享給組織內部帳號。設成 true 就可以分享給任意 AWS 帳號，那是需要格外小心的設定。
陷阱：RAM 與 Peering / TGW 的成本題
「多帳號的工作負載要互相通訊、要最低成本」——如果可以待在同一個 VPC，RAM 共享子網路最省（同 VPC 內沒有附件費也沒有處理費）。
但如果題目強調「各團隊要獨立的 VPC」，那就是 TGW（然後 TGW 本身也用 RAM 分享）。

6. 稽核與合規：Artifact / Audit Manager / Detective

這三個名字都跟「查」有關，但回答的是完全不同的問題。這是第 18 章資安服務家族的延伸，也是常見的誘答組。

服務回答什麼問題典型題目
AWS ArtifactAWS 自己合規嗎？「客戶稽核要求提供 SOC 2 / ISO 27001 / PCI 報告」→ 到 Artifact 下載
Audit Manager我的環境合規嗎？「持續蒐集證據、對應到 CIS／PCI 框架、自動產生稽核報告」
Detective這個資安事件怎麼發生的？「GuardDuty 發現異常後，要深入調查根本原因」
Config資源現在的組態合規嗎？「持續評估資源組態、偵測漂移」
CloudTrail誰做了什麼？「API 呼叫的完整紀錄」
Artifact 的關鍵字是「AWS 的報告」。題目通常長這樣：「稽核人員要求提供雲端供應商的合規證明」——這不是要你去掃自己的資源，而是要 AWS 自己的第三方稽核報告，答案就是 AWS Artifact。它也是簽署 BAA（HIPAA） 與 GDPR 資料處理附約的地方。
Detective vs GuardDuty 的分工：
GuardDuty 說「有事發生了」（偵測）。
Detective 說「事情是這樣發生的」（調查）——它把 CloudTrail、VPC Flow Logs、GuardDuty 發現自動整合成行為關聯圖，讓你追出攻擊路徑。
題目出現「調查根本原因」「釐清事件範圍」→ Detective。

7. Firewall Manager 與 License Manager

Firewall Manager：跨帳號的防護策略

單一帳號用 WAF 就夠了，但三十個帳號怎麼保證每個 ALB 都掛上同一組規則？而且下週新開的帳號、明天新建的 ALB 怎麼辦？Firewall Manager 就是回答這個問題的。
能集中管什麼WAF 規則群組、Shield Advanced 保護、Security Group 稽核與基準、Network Firewall、Route 53 DNS Firewall。
自動套用政策可設成「自動套用到所有現有與未來的符合資源」——新建的 ALB 一出現就自動被保護。
前提條件需要 Organizations（全功能） + 啟用 AWS Config + 指定委派管理員帳號。
考題句型：「確保所有帳號的所有 ALB 都套用同一組 WAF 規則，包括未來新建的」→ Firewall Manager。
只答「AWS WAF」是錯的——WAF 是單一帳號、單一資源的層次，做不到跨帳號自動套用。

License Manager：BYOL 的授權管控

追蹤 Windows Server、SQL Server、Oracle、SAP 這類「按實體核心或插槽計價」的自帶授權（BYOL）用量。
可以設定授權規則上限並選擇「超過就阻止啟動」，避免不知不覺超用而在原廠稽核時吃罰單。也能與 Dedicated Host 整合，確保授權綁在正確的實體主機上。
考題關鍵字：「追蹤 BYOL 授權用量」「防止授權超用」「原廠授權稽核」。
陷阱：把 License Manager 當成成本工具
它管的是第三方軟體授權合規，不是 AWS 帳單。AWS 的成本問題是 Cost Explorer / Budgets / Compute Optimizer 的守備範圍。

8. 邊緣與混合基礎架構四選一

這一組的判斷點只有一個：「東西要放在哪裡」。

AWS 區域 ────────────────────────── 標準情況 │ ├── Local Zones AWS 管的小型據點，靠近大都會 │ 個位數毫秒延遲，不在你機房 │ ├── Wavelength Zones 嵌在電信商 5G 網路內 │ 行動使用者的極低延遲 │ ├── Outposts AWS 機架放進你的機房 │ 資料落地合規、與地端系統整合 │ └── Snowball Edge 可搬運的邊緣運算裝置 船舶、工地、戰地等斷網環境
選項硬體在哪解決什麼關鍵字
Outposts你的機房資料不能離開自家機房，但想用 AWS API 與服務資料落地法規、與地端系統極低延遲整合、既有機房投資
Local ZonesAWS 的都會據點使用者在某大都會，需要個位數毫秒延遲即時遊戲、影音串流製作、醫療影像、AR/VR
Wavelength電信商的 5G 網路內行動裝置使用者的極低延遲5G、連網車、行動 AR
Snowball Edge可搬運的裝置沒有網路或網路極差的地方要運算與收資料船舶、油田、偏遠工地、離線
四題快速判斷

Q：「法規要求病歷資料必須存放在醫院自己的機房，但院方想用 AWS 的 API 與工具管理。」→ Outposts

Q：「線上遊戲公司希望某大都會的玩家獲得個位數毫秒的延遲，但不想自建機房。」→ Local Zones

Q：「連網車的即時影像分析需要在 5G 網路內處理以達到最低延遲。」→ Wavelength

Q：「研究船在海上沒有網路，需要就地處理感測器資料，回港後再上傳。」→ Snowball Edge

陷阱 1：Outposts 與 Local Zones 搞反
Outposts = 在「你的」機房（AWS 把機架搬過去）。
Local Zones = 在「AWS 的」據點（只是離使用者更近）。
題目說「資料必須留在自家資料中心」→ Outposts；說「不想自建機房但要低延遲」→ Local Zones。
陷阱 2：低延遲需求直接跳 Outposts
如果只是「使用者延遲要更低」而沒有資料落地要求，先想 CloudFront / Global Accelerator（第 19 章與第 04 章），再想 Local Zones。Outposts 是要買硬體、有實體交付前置期的重型方案，只有資料必須留在自家時才是最佳解。
實務提醒：Outposts 是需要簽約與實體交付的長期承諾（以年計），還要你的機房滿足電力、散熱、網路的規格要求。它不是「按需開一台」的東西。企業評估時要把機房改造成本與最短承諾期一起算進去——很多案子最後發現，把資料加密後放區域、只在地端留一個快取閘道，比買 Outposts 划算得多。

實作 Lab：OU + SCP + RAM 分享

約 45 分鐘。需要 Organizations 的管理帳號與至少一個成員帳號。

這個 Lab 會改動組織層級的權限，請務必看完這段再動手。
① SCP 套錯 OU 可能讓成員帳號完全動彈不得。務必先在測試 OU 演練，不要直接套 Root。
② 管理帳號不受 SCP 影響，所以你永遠有一條退路——但前提是你人在管理帳號。
③ 啟用 SCP 需要 Organizations 開啟「所有功能」，只有合併帳單的組織無法使用。
如果這是公司的正式 Organizations，請先跟負責人確認再操作。
Organizations、OU、SCP、RAM 本身都不收費。這個 Lab 唯一可能的費用是你在成員帳號裡實際建立的資源。

階段一：建立 OU 結構

  1. 確認 Organizations 已啟用所有功能（describe-organization 看 FeatureSet）
  2. 建立一個 Sandbox OU，把測試用的成員帳號移進去
  3. 確認移動成功：list-accounts-for-parent
$ aws organizations describe-organization --query 'Organization.FeatureSet'
"ALL"

$ aws organizations create-organizational-unit \
    --parent-id r-exam --name Sandbox

$ aws organizations move-account \
    --account-id 444455556666 \
    --source-parent-id r-exam \
    --destination-parent-id ou-exam-sandbox

階段二：套用區域限制 SCP

  1. 用第 2 節的 JSON 建立 SCP（先只放區域限制那一段，機型限制之後再加）
  2. 把政策附加到 Sandbox OU（attach-policy）
  3. 切到成員帳號，試著在未核准的區域建立 EC2 → 應該被拒絕
  4. 在核准的區域建立 → 成功
  5. 用 IAM Policy Simulator 或 CloudTrail 確認拒絕來源是 SCP 而不是 IAM
被 SCP 擋掉的錯誤訊息長這樣：with an explicit deny in a service control policy。看到這句就知道要去查組織政策，不是查 IAM——這在實務排錯時能省下大量時間。

階段三：RAM 分享子網路

  1. 在管理帳號執行 enable-sharing-with-aws-organizations
  2. 在網路帳號（或管理帳號）建一個 VPC 與兩個子網路
  3. 建立 Resource Share 把兩個子網路分享給成員帳號
  4. 切到成員帳號，list-resources --resource-owner OTHER-ACCOUNTS 確認看得到
  5. 在成員帳號用那個共享子網路開一台 EC2 → 成功
  6. 試著在成員帳號修改子網路 → 被拒絕（參與者不能改網路設定）

階段四：清理

  1. 終止成員帳號裡的 EC2
  2. 刪除 Resource Share
  3. 先 detach SCP 再刪除政策（還在附加中就刪不掉）
  4. 把帳號移回原本的位置，刪除 Sandbox OU（OU 裡還有帳號就刪不掉）

10. 考試陷阱整理

陷阱 1：SCP 對管理帳號生效
不生效。管理帳號不受任何 SCP 限制，所以不該在裡面放工作負載。
陷阱 2：SCP 會「給」權限
不會。SCP 是權限上限（防護欄），最終權限 = SCP ∩ IAM。只有 SCP 允許、IAM 沒給，一樣不能做。
陷阱 3：用 Config 來「阻止」動作
Config 只能偵測與事後修復。要「根本不能做」→ SCP（預防性防護欄）；要「部署前擋下範本」→ 主動性防護欄。
陷阱 4：Control Tower 與 Organizations 二選一
不是二選一，Control Tower 建在 Organizations 之上。問「快速建立符合規範的新帳號」→ Control Tower；問「SCP 與合併帳單」→ Organizations。
陷阱 5：跨帳號套 WAF 只答「AWS WAF」
要跨帳號、自動涵蓋未來新建資源只有 Firewall Manager 做得到。WAF 本身是單帳號單資源的層次。
陷阱 6：Artifact 與 Audit Manager 搞混
Artifact = 下載 AWS 自己的合規報告（SOC、ISO、PCI）；Audit Manager = 蒐集我自己環境的證據產生稽核報告。
陷阱 7：Detective 拿來做偵測
偵測是 GuardDuty，Detective 是事後調查根本原因。名字容易誤導。
陷阱 8：Outposts 與 Local Zones 反了
Outposts 在你的機房（資料落地）；Local Zones 在 AWS 的都會據點（低延遲但不自建機房）。
陷阱 9：低延遲直接跳 Outposts
沒有資料落地要求時，先考慮 CloudFront / Global Accelerator，再考慮 Local Zones。Outposts 是有實體交付與長期承諾的重型方案。
陷阱 10：License Manager 是成本工具
它管第三方軟體授權合規（BYOL 用量），不是 AWS 帳單。帳單是 Cost Explorer / Budgets 的守備範圍。
陷阱 11：忘了 RAM 要先在 Organizations 啟用
沒執行 enable-sharing-with-aws-organizations 的話，分享給 OU 或組織會失敗——只能分享給個別帳號 ID。
💡一句話記憶：
要擋住用 SCP，要發現用 Config，要開帳號用 Control Tower，要自助佈建用 Service Catalog，要共用資源用 RAM；
AWS 的合規報告在 Artifact，我的合規證據在 Audit Manager，事後調查找 Detective，跨帳號防火牆找 Firewall Manager；
機房在你家是 Outposts，據點在都會是 Local Zones，網路在 5G 是 Wavelength，沒網路就搬 Snowball Edge。
