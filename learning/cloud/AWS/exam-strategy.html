消去法（Elimination Method）——4 步驟

Step 1：找題目的「限制條件」
讀題時畫線：最少改動 / 成本最低 / 高可用 / 無伺服器 / 現有基礎設施
這些詞決定了哪些選項可以直接排除

Step 2：排除明顯錯誤的選項
❌ 技術上不可能的（如「Lambda 在 EC2 上運行」）
❌ 違反條件的（說成本最低，但選了 Multi-AZ RDS）
❌ 過度複雜的（SAA 考的是架構師思維，不是最複雜的方案）

Step 3：對比剩下的 2 個選項
通常剩下 2 個相似的選項，找它們的關鍵差異
例如：SQS 標準 vs FIFO → 差別是「順序」和「去重」

Step 4：選符合題意約束的那個
✅ 題目說「最少運維負擔」→ 選受管服務（RDS 不是 EC2+MySQL）
✅ 題目說「最低成本」→ 選 Spot / Reserved / S3 Intelligent-Tiering
# 如果還是不確定，選「功能最精確匹配需求」的選項，不是最貴或最複雜的

AWS 關鍵字對應答案（必背清單）

📌 情境關鍵字 → 服務選擇

「無伺服器 + HTTP API」→ API Gateway + Lambda（不是 EC2）
「消息順序 + 不重複」→ SQS FIFO（不是 SQS Standard）
「Fan-out（廣播）」→ SNS → 多個 SQS（不是多個 SQS 各自輪詢）
「全球加速 / 靜態 IP」→ Global Accelerator（不是 CloudFront，CloudFront 用於內容分發）
「靜態網站 + CDN」→ S3 + CloudFront（不是 EC2）
「多區域 + 全球一致性」→ DynamoDB Global Tables 或 Aurora Global Database
「real-time 資料流」→ Kinesis Data Streams（不是 SQS）
「On-premises 到 S3 / Glacier」→ Storage Gateway（不是 DataSync for NFS；DataSync 是純複製）
「混合雲低延遲」→ AWS Direct Connect（VPN 走網際網路，延遲不穩定）
「機器學習 + SQL 分析」→ Athena（無伺服器 S3 查詢）或 Redshift（BI 資料倉庫）
「暫時性憑證給第三方」→ STS AssumeRole（不是 IAM User）
「加密 + 合規 + 硬體」→ CloudHSM（KMS 是 AWS 管理，CloudHSM 是你管理的硬體 HSM）

⚠️ 常見混淆對（記住差異就是拿分）

CloudFront vs Global AcceleratorCF：快取靜態內容（HTTP）；GA：TCP/UDP 加速、靜態 IP Anycast
SQS vs SNS vs EventBridgeSQS：Queue 排隊；SNS：即時廣播；EventBridge：事件路由（跨帳號、複雜規則）
Multi-AZ vs Read ReplicaMulti-AZ：HA 故障轉移（同步複製，Standby 不對外服務）；Read Replica：分散讀取（非同步，可以是不同 Region）
Reserved vs Savings PlansRI：特定 EC2 類型；Savings Plans：更靈活（涵蓋 Lambda、Fargate）
NLB vs ALBNLB：Layer 4（TCP/UDP）、靜態 IP；ALB：Layer 7（HTTP）、路徑/Header 路由
Provisioned vs Reserved ConcurrencyProvisioned：預熱 Lambda（消除冷啟動）；Reserved：限制 Lambda 最大併發數

最高頻考試陷阱（每人必錯一次）

陷阱正確知識點
NAT Gateway 放在 Private SubnetNAT Gateway 必須放在 Public Subnet（需要 IGW 出網路），Private Subnet 的路由表指向 NAT GW
S3 Bucket Policy vs IAM PolicyS3 Bucket Policy 可以授權給其他 AWS 帳號；IAM Policy 只對同帳號有效。跨帳號存取用 Bucket Policy
Security Group 是 StatefulSG 是 Stateful（允許入站，回應自動允許）；NACL 是 Stateless（入站出站規則分開設）
CloudTrail vs CloudWatchCloudTrail：API 操作記錄（誰做了什麼）；CloudWatch：監控指標和日誌（資源用了多少）
Lambda@Edge vs CloudFront FunctionsLambda@Edge：完整 Lambda 功能、支援複雜邏輯、Origin Request/Response；CF Functions：簡單轉換、毫秒級、Viewer Request/Response
EBS 跨 AZ 搬移EBS 無法直接跨 AZ。方法：建立 Snapshot → 從 Snapshot 在目標 AZ 建立新 EBS Volume
RDS Multi-AZ Standby 的用途Standby 只是故障轉移用途，不能接受讀取流量（讀取分流要用 Read Replica）

考試當天檢查清單

  • IAM：Policy 評估邏輯（明確 Deny 勝過 Allow，預設 Deny）
  • VPC：Subnet CIDR、Route Table、IGW、NAT GW、Security Group vs NACL 的差異
  • S3：加密類型（SSE-S3 / SSE-KMS / SSE-C）、版本控制、生命週期
  • EC2：購買選項（On-Demand / Reserved / Spot / Dedicated）
  • RDS：Multi-AZ（HA）vs Read Replica（效能），不要搞混
  • Cognito：User Pool（身分）vs Identity Pool（AWS 存取）
  • SQS FIFO vs Standard：FIFO 保順序 + 去重；Standard 吞吐量更高
  • CloudFront：Origin、Behavior、Distribution；Lambda@Edge vs CF Functions
  • KMS vs CloudHSM：KMS 是 AWS 托管；CloudHSM 是你托管的硬體
  • 成本優化：Reserved Instance、Savings Plans、Spot、S3 Intelligent-Tiering
