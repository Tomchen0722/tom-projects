1. 三層架構:先搞懂你在哪一層

把 AI 服務想成買菜煮飯的三種方式:叫外送(現成 AI 服務,直接呼叫 API)、買食材自己煮(SageMaker,自己訓練模型)、自己種菜(EC2 + 深度學習框架,全部自己來)。SAA 考的絕大多數是第一層。
第三層
AI 服務
直接呼叫 API,不用懂 ML。Rekognition、Comprehend、Polly、Transcribe、Translate、Textract、Lex、Personalize、Forecast。
→ SAA 考試 80% 的題目在這一層。
第二層
SageMaker
託管平台,自己準備資料與訓練模型。提供 Notebook、訓練、調參、部署端點的一條龍服務,但基礎設施由 AWS 管。
→ 考「需要自訂模型」時出現。
第一層
框架與基礎設施
全部自己來。Deep Learning AMI、EC2 GPU 執行個體(P 系列、G 系列)、TensorFlow / PyTorch / MXNet。
→ 考「需要完全控制環境」或「既有的訓練腳本」時出現。
📋 解題直覺:能用現成服務就選現成服務。題目如果只是「辨識圖片裡有什麼」「把語音轉文字」,選 Rekognition / Transcribe 就對了。看到選項有 SageMaker 自訓模型,通常是干擾項——除非題目明說「業界特有的資料」「現成服務不支援的分類」。

2. 影像與影片類服務

服務做什麼典型情境
Rekognition影像/影片分析:物體偵測、人臉比對、名人辨識、文字偵測、不當內容審核使用者上傳照片自動審核、門禁人臉辨識、影片內容標記
Textract從文件中抽取文字與結構:表格、表單欄位、鍵值對掃描的發票、保單、申請書自動輸入
陷阱:Textract vs Rekognition 的文字偵測
兩個都能「看到文字」,但完全不同:
• Rekognition 的文字偵測 = 找出圖片裡「有哪些字」(例如招牌、車牌上的字)
• Textract = 理解文件的結構,知道「這格是姓名、那格是金額」,能抽出表格與表單

題目出現「表單」「表格」「發票」「PDF 文件自動化」→ 一律 Textract。單純「圖片裡的文字」→ Rekognition。
✅ 常考組合:使用者上傳圖片到 S3 → 觸發 Lambda → 呼叫 Rekognition 做內容審核 → 不當內容標記後通知 SNS。這是「Serverless + AI」的標準架構題,S3 事件通知是起點。

3. 文字與語言類服務

服務做什麼考試關鍵字
Comprehend自然語言處理:情緒分析、關鍵字擷取、實體辨識、語言偵測、個資(PII)偵測情緒分析、客戶評論分析、找出文件裡的個資
Comprehend Medical專門處理醫療文本,抽取病症、用藥、劑量病歷、臨床筆記
Translate神經機器翻譯,多語言互轉翻譯、多語系網站
Lex對話機器人引擎(與 Alexa 同源),做語音/文字聊天機器人Chatbot、客服機器人、語音 IVR
Kendra企業內部的智慧搜尋,用自然語言問問題找文件企業知識庫搜尋、用問句找答案
陷阱:Kendra vs OpenSearch
兩者都是「搜尋」,但層次不同:
• OpenSearch = 關鍵字/全文檢索引擎,適合日誌與結構化搜尋,你要自己設計查詢
• Kendra = ML 驅動的問答式搜尋,使用者可以問「請假規定是什麼?」直接得到答案段落

題目說「員工用自然語言問問題,從內部文件找答案」→ Kendra。說「分析大量日誌」→ OpenSearch。
✅ 個資合規常考:要在文件或日誌中「自動找出並遮蔽個人資料」→ Comprehend 的 PII 偵測。搭配 Macie(專門掃 S3 裡的敏感資料)一起記,兩者常在同一題的選項中出現:Macie 掃 S3 儲存的資料,Comprehend 分析文字內容。

4. 語音類服務

這兩個名字很像,方向剛好相反,是考試最愛的一組:

Amazon Transcribe 語音 → 文字 會議錄音 → 逐字稿 客服通話 → 文字記錄(可做後續分析) 支援即時串流轉錄、講者辨識、自訂字彙 Amazon Polly 文字 → 語音 文章 → 有聲書 網站內容 → 語音播報 支援 SSML 調整語調、多種音色
Transcribe聽寫。記法:Transcribe = 轉錄,把聽到的寫下來。
Polly朗讀。記法:鸚鵡(Polly)會說話。
Lex對話。負責「聽懂意圖並回應」,常和 Polly 搭配輸出語音。
Connect雲端客服中心。Connect + Lex + Polly = 全自動語音客服。
✅ 經典架構題:「建立自動語音客服,能聽懂客戶問題並回答」→ Amazon Connect(接電話)+ Lex(理解意圖)+ Polly(語音回覆)。三個一起出現時就是這題。

5. 預測與推薦類服務

服務做什麼典型情境
Personalize個人化推薦(Amazon.com 同款技術)「猜你喜歡」、商品推薦、內容推薦
Forecast時間序列預測銷售預測、庫存需求、人力排班預估
Fraud Detector線上詐欺偵測假帳號註冊、盜刷交易識別
💡 這三個的共同點:都是「把 Amazon 自己在用的模型包成服務賣你」。你只要餵歷史資料,不用懂演算法。考試看到「推薦」→ Personalize;「預測未來數字」→ Forecast;「偵測詐欺」→ Fraud Detector,對應很直接。

6. SageMaker:自己訓練模型

當現成的 AI 服務不夠用(例如要辨識自家工廠的特定瑕疵),就進到 SageMaker 這一層。

① 準備資料 Data Wrangler(視覺化清洗)/ Ground Truth(人工標註) ② 開發 SageMaker Studio(整合式開發環境)/ Notebook 執行個體 ③ 訓練 Training Job → 自動開機器、跑完自動關 Spot Training 可省最高 90% ④ 調參 Automatic Model Tuning(自動找最佳超參數) ⑤ 部署 Real-time Endpoint(即時,持續計費) Batch Transform(批次,跑完就關) Serverless Inference(用量不固定時最省)
陷阱:Endpoint 的三種部署方式怎麼選?
• Real-time Endpoint:需要毫秒級回應、流量穩定 → 但只要開著就一直計費
• Batch Transform:一次處理大量資料、不需要即時 → 最省錢
• Serverless Inference:流量零星、有明顯離峰 → 不用時不計費

題目說「推論成本太高,但流量很不穩定」→ Serverless Inference。說「每天半夜跑一次全量計算」→ Batch Transform。
💰 訓練成本優化:SageMaker 的 Managed Spot Training 可省最高 90%,代價是訓練可能被中斷——但 SageMaker 會自動存檔點(checkpoint)並續跑,所以對「可以慢一點」的訓練幾乎沒有壞處。這是成本題的固定答案。

7. ML 的算力與成本

選項用途特點
P 系列(p3/p4/p5)模型訓練高階 GPU,訓練大模型用,很貴
G 系列(g4dn/g5)推論、圖形工作負載比 P 系列便宜,推論的 CP 值較高
Inf 系列(Inferentia)專用推論晶片AWS 自研,推論成本最低
Trn 系列(Trainium)專用訓練晶片AWS 自研,訓練成本較 GPU 低
Deep Learning AMI預裝框架的映像省去自己裝 CUDA、TensorFlow 的時間
📋 字首記憶法:P = Power(訓練用的大馬力)、G = Graphics(圖形與推論)、Inf = Inference(推論)、Trn = Training(訓練)。題目說「降低推論成本」→ Inferentia;說「加速訓練」→ P 系列或 Trainium。
⚠️ 白皮書已過時之處:這份 2020 年的白皮書大篇幅介紹 Elastic Inference(把 GPU 加速器掛到 EC2 上)。AWS 已不再向新客戶提供該服務,現行的正解是改用 Inferentia(Inf 系列) 或 SageMaker Serverless Inference。白皮書也提到 DeepLens 等教學硬體,同樣已停售,考試不會考。

8. ML 架構的資安要點

SAA 是架構師考試,所以 ML 題常常真正在考的是「網路與權限」,不是演算法:

VPC 端點SageMaker 訓練/端點放在 VPC 內,用 VPC Endpoint(PrivateLink)存取 S3,流量不走公網。
加密訓練資料在 S3 用 KMS 加密;訓練中的暫存磁碟、模型產出物也可加密。
IAM 角色SageMaker Execution Role 決定它能讀哪些 S3 bucket,遵守最小權限。
網路隔離訓練 Job 可開啟 Network Isolation,容器完全無法對外連網。
✅ 高頻題型:「訓練資料含敏感個資,不希望流量經過網際網路」→ 答案是 把 SageMaker 放進 VPC + 建立 S3 的 VPC Endpoint。這題本質上考的是第 02 章的 VPC 觀念,只是包了一層 ML 的外衣。

10. 考試陷阱整理

陷阱 1:能用現成服務就別自己訓練
題目描述的是常見任務(辨識、翻譯、轉錄),選項卻有 SageMaker 自訓模型——後者通常是干擾項。AWS 的出題邏輯永遠偏向「用託管服務、少維運」。
陷阱 2:Transcribe 和 Polly 方向別搞反
Transcribe = 語音→文字(轉錄);Polly = 文字→語音(朗讀)。這一題送分,但緊張時很容易看反。
陷阱 3:Textract 不是 OCR 而已
如果題目只說「圖片裡有文字」,Rekognition 就夠;只要出現「表格」「表單」「鍵值對」「結構化抽取」,就是 Textract。
陷阱 4:Comprehend 與 Macie 的分工
Macie = 掃描 S3 儲存桶裡有沒有敏感資料(資產面);Comprehend = 分析文字內容並抽出 PII(內容面)。題目說「盤點 S3 有沒有個資外洩風險」→ Macie。
陷阱 5:ML 題常常在考 VPC
看到「不能走公網」「資料不能離開 VPC」,不管題目包裝成 SageMaker 還是別的,答案都是 VPC Endpoint / PrivateLink。
陷阱 6:白皮書的服務名可能已改
這份白皮書是 2020 年版本,提到的 Elastic Inference、DeepLens、DeepRacer 等,有的已停止提供或僅剩教學用途。白皮書適合建立「AWS 有哪些類別的服務」的全貌,但個別服務的現況要以 AWS 官方文件為準。
💡 一句話記憶法:
看圖找 Rekognition,讀表單找 Textract,懂文意找 Comprehend,聽寫找 Transcribe,朗讀找 Polly,聊天找 Lex,問答找 Kendra,推薦找 Personalize,預測找 Forecast,以上都不夠才找 SageMaker。
