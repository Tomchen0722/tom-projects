消去法——ACE 版本

ACE 特有：先找「操作約束」
題目常限制：「用 gcloud CLI」、「用 Cloud Console」、「最少步驟」
→ 確認解法符合指定工具

排除管理負擔高的選項
❌ 自己管 VM（Compute Engine）= 高管理負擔
✅ 受管服務（Cloud SQL、GKE Autopilot、Cloud Run）= 低管理負擔
→ 若題目沒有特別要求自訂，選受管服務

注意 Regional vs Zonal 的區別
高可用（HA）題目 → 選 Regional 資源（跨 Zone）
單 Zone 夠用 → 選 Zonal（節省成本）

gcloud 指令選擇
看到 gcloud 指令選項 → 確認「資源類型」對不對
❌ gcloud compute vms list（錯誤，沒有 vms 這個資源）
✅ gcloud compute instances list（正確）

GCP 關鍵字對應答案

🔑 情境 → 服務選擇

「無伺服器容器 API」→ Cloud Run（不是 GKE；Cloud Run 是無伺服器）
「Kubernetes 自動管理 Node」→ GKE Autopilot（不是 Standard；Autopilot 不管 Node）
「全球分散式關聯式資料庫」→ Cloud Spanner（不是 Cloud SQL；SQL 是單 Region）
「TB 級資料 SQL 分析」→ BigQuery（不是 Cloud SQL；BQ 是 OLAP）
「即時串流處理」→ Pub/Sub + Dataflow（不是 BigQuery；BQ 是批次）
「批次 ETL 資料管線」→ Dataflow（或 Cloud Composer 做編排）
「降低成本、可中斷工作負載」→ Preemptible VM / Spot VM（最高 91% 折扣）
「Pod 存取 GCP API 不用金鑰」→ Workload Identity（不是 SA JSON Key）
「VM 間私有連線（無公開 IP）」→ VPC 內部 IP + 防火牆規則（不需要 VPN）
「On-premises 到 GCP 低延遲」→ Cloud Interconnect（Dedicated/Partner）
「Organization 層級的存取限制」→ Organization Policy（不是 IAM）
「VM 沒有外部 IP 但需要對外」→ Cloud NAT（不是給 VM 加外部 IP）

⚠️ 常見混淆對

IAM vs Organization PolicyIAM：誰能做什麼（授權）；Org Policy：什麼能被做（資源守護欄，連 Owner 都受限）
Cloud Run vs App EngineCloud Run：容器、彈性、Cold Start 可配置；App Engine：原始碼部署、固定語言 Runtime
Cloud SQL vs SpannerCloud SQL：單 Region 關聯式（便宜）；Spanner：全球分散（貴 10-100x）
CUD vs SUD vs PreemptibleSUD：自動折扣；CUD：承諾更大折扣；Preemptible/Spot：可中斷才用
VPC Peering vs Shared VPCPeering：對等互連兩個 VPC（不傳遞）；Shared VPC：一個 Host Project 的 VPC 給多個 Service Project 共用
Cloud Armor vs IAPCloud Armor：DDoS/WAF 防護外部攻擊；IAP：員工 Zero Trust 存取內部應用

高頻 gcloud 指令考點

考試情境正確指令常見錯誤
讓 kubectl 連到 GKEgcloud container clusters get-credentials CLUSTER --zone ZONE忘了這步就直接 kubectl（會找不到 cluster）
設定預設專案gcloud config set project PROJECT_ID誤用 --project 旗標而不是全域設定
列出 Compute Engine VMgcloud compute instances listgcloud compute vms list（不存在）
BigQuery 估算費用bq query --dry_run ...忘記 --dry_run，直接執行並被收費
部署 Cloud Run 服務gcloud run deploy SERVICE --image IMAGE --region REGION少 --region 旗標（會問你）
授予 IAM 角色gcloud projects add-iam-policy-binding PROJECT --member=user:EMAIL --role=roles/ROLE角色格式：必須是 roles/xxx，不是直接寫角色名
SSH 連線到 VMgcloud compute ssh INSTANCE --zone ZONE忘記 --zone 旗標（若無預設 zone）

考試當天檢查清單

  • gcloud 基礎：config set、auth list、projects list、services enable
  • Compute Engine：機器類型（E2/N2/C2）、Preemptible vs Spot、Instance Template vs Managed Instance Group
  • GKE：Standard vs Autopilot、get-credentials、Workload Identity、HPA vs CA
  • Cloud Run：min-instances（消除冷啟動）、concurrency、--allow-unauthenticated vs IAP
  • Cloud Storage：4 種儲存類別（Standard/Nearline/Coldline/Archive）、Lifecycle Rule
  • Cloud SQL：REGIONAL availability（HA）vs ZONAL（單 Zone）、Cloud SQL Auth Proxy
  • BigQuery：按掃描量計費、--dry_run 估算、分區表減少掃描、Slot 容量型計費
  • IAM：Primitive Roles（不推薦）vs Predefined Roles；Organization Policy 的 Guardian 概念
  • VPC：Shared VPC vs Peering；Cloud NAT（私有 VM 對外）；Cloud Armor（WAF/DDoS）
  • 成本：SUD（自動）、CUD（承諾）、Preemptible（可中斷）、Budget Alert（只通知不自動停）
