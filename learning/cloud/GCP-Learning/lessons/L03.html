LESSON 03

開帳號、拿免費額度、設好防爆預算

這一課全部都是動手做。做完你會有一個可用的 GCP 帳號、一個乾淨的專案，以及一道「不會半夜收到天價帳單」的保險。

操作 40 分費用 0 元實作

一、免費額度到底給你什麼

Google Cloud 的免費資源分成兩塊，很多人搞混：

新戶試用金Always Free 永久免費層
內容300 美元額度每月固定的小額免費用量
期限90 天，到期或用完就結束永久，只要不超量
需要信用卡要（僅驗證，不自動扣款）要
典型內容任何服務都能用1 台 e2-micro VM（美國特定區）、5GB Cloud Storage、每月 1TB BigQuery 查詢量、200 萬次 Cloud Run 請求等
小心踩雷
試用金到期不會自動扣你的卡。Google 的設計是：90 天結束後帳號會暫停，需要你主動「升級為付費帳戶」才會開始收費。這點比其他雲友善。
但——一旦你手動升級成付費帳戶，就沒有任何自動剎車了。所以下面的預算警報一定要設。
動手實作

實作 1：建立帳號與第一個專案

  1. 打開 cloud.google.com/free，用你的 Google 帳號登入，點「免費開始使用」。
  2. 填寫國家（台灣）、帳戶類型選個人（除非你有公司統編要報帳）。
  3. 綁定信用卡。Google 會做一筆小額授權（通常 1 美元）後取消，不會實際扣款。虛擬卡、預付卡多半會失敗，請用實體信用卡。
  4. 進入 Console 後，點左上角專案選單 →「新增專案」。
  5. 專案名稱填 GCP 學習，然後點旁邊的「編輯」修改 Project ID，改成有意義的名字，例如 tom-gcp-lab-2026。
    這一步很多人跳過，結果拿到 gcp-learning-483920 這種亂數 ID，之後每次打指令都要複製貼上。
  6. 建立完成後，確認右上角顯示的是新專案，而不是預設的「My First Project」。

二、最重要的一步：設定預算警報

這是整套教材裡我最希望你別跳過的一步。雲端帳單的恐怖之處在於，出錯的時候你不會馬上知道。一個忘了關的 GPU 機器，一週就能燒掉五百美元。

動手實作

實作 2：設定三段式預算警報

  1. Console 左上漢堡選單 → 帳單（Billing） → 預算與快訊（Budgets & alerts）。
  2. 點「建立預算」。名稱填 學習用月預算。
  3. 範圍選擇你剛建的專案（不要選「所有專案」，除非你想管全部）。
  4. 金額設定：選「指定金額」，填 10 美元。
    學習階段每月 10 美元很夠。設低一點，警報才有意義。
  5. 設定警報門檻：刪掉預設的，改成三段 50% / 90% / 100%。
    50% = 提醒你注意；90% = 該去看看發生什麼事；100% = 出事了。
  6. 勾選「將電子郵件通知傳送給帳單管理員和使用者」，確認你的 Email 正確。
  7. 儲存。
小心踩雷
預算警報只會寄信，不會自動關掉服務。它是煙霧偵測器，不是灑水器。
真正要做到自動斷電，需要把預算警報接到 Pub/Sub，再觸發一個 Cloud Function 去停用計費帳戶——這在第 36 課會實作。學習階段先靠信件就好，但務必知道這個限制。

三、關掉不必要的花費來源

新帳號有幾個預設設定會偷偷花錢，先處理掉：

定期健檢指令
# 檢查有沒有閒置的外部 IP（未綁定的靜態 IP 每小時要錢！）
gcloud compute addresses list --filter="status=RESERVED"

# 檢查有沒有孤兒磁碟（VM 刪了但磁碟留著，持續收費）
gcloud compute disks list --filter="-users:*"

# 檢查所有正在跑的 VM
gcloud compute instances list
實務提醒
養成習慣：每週五收工前跑一次上面三行。九成的意外帳單都來自這三類——忘了關的機器、沒綁定的 IP、刪 VM 沒刪磁碟。

四、啟用你會用到的 API

GCP 每個服務都要先啟用 API。這不是刁難——沒啟用的 API 完全不會產生費用，也不會有攻擊面。

bash
# 先確認 gcloud 指向正確的專案
gcloud config set project tom-gcp-lab-2026

# 一次啟用學習常用的 API（會跑一兩分鐘）
gcloud services enable \
  compute.googleapis.com \
  storage.googleapis.com \
  run.googleapis.com \
  cloudbuild.googleapis.com \
  artifactregistry.googleapis.com \
  logging.googleapis.com \
  monitoring.googleapis.com \
  cloudresourcemanager.googleapis.com

# 確認啟用了哪些
gcloud services list --enabled

五、本課檢核

  • 已建立 GCP 帳號並取得 300 美元試用金
  • 已建立一個 Project ID 有意義的專案
  • 已設定 10 美元月預算 + 三段警報，且信箱正確
  • 已啟用上述常用 API
  • 把「每週跑一次健檢指令」寫進行事曆

自我檢測

你設了 10 美元預算，某天收到 100% 警報信。此時服務會怎樣？
什麼都不會發生，服務照常跑、照常收費。預算警報純粹是通知。
這是最常見的誤解，也是很多人收到四位數帳單的原因——他們以為設了預算就有上限。真正的自動停用要另外做（第 36 課）。
為什麼建議把預算設得比實際預期還低，而不是設一個「安全的高標」？
因為預算的價值在於異常偵測，不是控制支出。設 10 美元，你在花到第 5 美元時就會被提醒；設 500 美元，等你收到警報時已經燒掉 250 美元了。
門檻要設在「不正常」的位置，不是「不可接受」的位置。
試用金 90 天到期，你的資料會怎樣？
帳號進入暫停狀態，資源會被停止但資料保留約 30 天，等你升級付費帳戶就能恢復。超過保留期才真的刪除。
實務建議：如果只是學習，到期前把想留的東西匯出來（例如 Terraform 設定檔、資料備份），不要指望寬限期。
