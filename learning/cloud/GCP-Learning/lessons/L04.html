LESSON 04

Cloud Shell 與 gcloud：你的第一組指令

Console 點來點去適合探索，但真正的工作都在指令列完成。這一課讓你把 gcloud 練到有肌肉記憶——它是後面每一課的共同語言。

操作 45 分費用 0 元實作

一、為什麼一定要學指令列

三個理由，一個比一個重要：

  1. 可重複：滑鼠點過的步驟，三個月後你記不得。指令可以存成檔案，隨時重跑。
  2. 可審閱：指令可以放進 Git，同事能 review，出事能追溯。
  3. 可自動化：CI/CD、排程、災難復原，全都建立在「機器能執行的指令」上。

更現實的理由：Console 介面每半年就改版一次，但 gcloud 指令十年來大致穩定。

二、Cloud Shell：不用裝任何東西的免費終端機

Cloud Shell 是 GCP 送你的一台小型 Linux 虛擬機，開在瀏覽器裡。它有：

  • 5GB 永久家目錄（$HOME），關掉再開檔案還在
  • 預裝 gcloud、kubectl、Docker、Terraform、Python、Node.js、Go、git
  • 已經幫你登入好了，不用處理認證
  • 免費（每週有使用時數上限，正常學習用不完）
動手實作

實作 1：開啟 Cloud Shell 並認識環境

  1. 在 Console 右上角，點那個 >_ 圖示（啟用 Cloud Shell）。第一次會等 30 秒左右佈建。
  2. 跑第一組指令，確認身分與專案：
    bash
    gcloud auth list          # 我是誰
gcloud config list        # 目前設定
gcloud version            # 版本資訊
  3. 設定預設專案與區域（這一步做了，之後所有指令都能省略 --project 和 --zone）：
    bash
    gcloud config set project tom-gcp-lab-2026
gcloud config set compute/region asia-east1
gcloud config set compute/zone asia-east1-b

# 確認
gcloud config list
  4. 試試看內建編輯器：輸入 cloudshell edit hello.txt，會跳出一個類似 VS Code 的圖形編輯器。
實務提醒
Cloud Shell 的虛擬機閒置 20 分鐘會回收，超過 120 天沒用家目錄會被清空。
所以：重要東西一律推到 Git 或 Cloud Storage，不要只留在 Cloud Shell。

三、gcloud 指令的文法規則

gcloud 的指令有嚴格的結構，看懂之後你可以「猜」出沒學過的指令：

gcloud 文法
gcloud  <群組>  <子群組>  <動作>  [名稱]  [--參數]

範例拆解：
gcloud compute instances create my-vm --machine-type=e2-micro
  │      │        │         │       │            │
  │      │        │         │       │            └─ 參數
  │      │        │         │       └─ 資源名稱
  │      │        │         └─ 動作（create/list/delete/describe/update）
  │      │        └─ 子群組（要操作的資源類型）
  │      └─ 服務群組（compute / storage / sql / run / container ...）
  └─ 主指令

動作動詞幾乎都一樣，這是最好用的規律：

動詞意思例子
list列出所有gcloud compute instances list
describe看單一個的詳細內容gcloud compute instances describe my-vm
create建立gcloud compute instances create my-vm
delete刪除gcloud compute instances delete my-vm
update修改設定gcloud compute instances update my-vm ...
add-* / remove-*加上／移除子項目gcloud compute instances add-labels ...

四、最重要的四個通用參數

四大通用參數
# 1. --help ：什麼都忘了就打這個
gcloud compute instances create --help

# 2. --format ：控制輸出格式（table / json / yaml / value）
gcloud compute instances list --format="table(name, status, zone)"
gcloud compute instances list --format="value(name)"     # 只印名字，適合餵給其他指令
gcloud compute instances list --format=json               # 給程式吃

# 3. --filter ：篩選（語法很像 SQL 的 WHERE）
gcloud compute instances list --filter="status=RUNNING"
gcloud compute instances list --filter="zone:asia-east1 AND labels.env=prod"

# 4. --project ：臨時指定專案，不影響預設值
gcloud compute instances list --project=another-project
實務提醒
--format=value(...) + --filter 組合起來威力極大，這是所有自動化腳本的基礎：
bash
# 一次刪掉所有標記為 temp 的 VM
gcloud compute instances list \
  --filter="labels.purpose=temp" \
  --format="value(name)" \
  | xargs -I {} gcloud compute instances delete {} --quiet

五、設定檔（Configurations）：切換多個環境

實務上你會同時管 dev、prod、客戶 A、客戶 B。gcloud 的 configuration 讓你一秒切換：

bash
# 建立一組叫 dev 的設定
gcloud config configurations create dev
gcloud config set project my-app-dev
gcloud config set compute/zone asia-east1-b

# 再建一組 prod
gcloud config configurations create prod
gcloud config set project my-app-prod
gcloud config set compute/zone asia-east1-c

# 列出、切換
gcloud config configurations list
gcloud config configurations activate prod

# 單次使用而不切換
gcloud compute instances list --configuration=dev
小心踩雷
最危險的操作錯誤：以為自己在 dev，其實在 prod。
建議把目前的 configuration 顯示在你的 shell 提示字元裡。在 ~/.bashrc 加上：
bash
export PS1='[$(gcloud config configurations list --filter="is_active=true" --format="value(name)")] \w $ '

六、在自己電腦上安裝 gcloud（選用）

Cloud Shell 夠用，但如果你想在本機工作：

bash
# Windows：下載安裝程式
# https://cloud.google.com/sdk/docs/install

# macOS
brew install --cask google-cloud-sdk

# 安裝後初始化（會開瀏覽器讓你登入）
gcloud init

# 另外設定應用程式預設憑證（給程式碼用的認證）
gcloud auth application-default login

七、本課檢核

  • 能開啟 Cloud Shell 並確認自己的身分
  • 已設定預設 project / region / zone
  • 能說出 gcloud 指令的五段結構
  • 會用 --filter 和 --format=value 組合出腳本
  • 知道 configurations 可以切換環境，也知道切錯環境的風險

自我檢測

你要找出專案裡「所有在 asia-east1 且狀態為 TERMINATED」的機器名稱，一行指令怎麼寫？
bash
gcloud compute instances list \
  --filter="zone:asia-east1 AND status=TERMINATED" \
  --format="value(name)"
注意 zone:asia-east1 用冒號是包含比對（會match asia-east1-a/b/c），用等號則是完全相等。這個差別很常考。
為什麼 gcloud config set project X 之後，同事在他的 Cloud Shell 還是看到別的專案？
因為 configuration 是存在每個使用者自己的 ~/.config/gcloud/ 目錄裡，屬於本機設定，不是雲端狀態。每個人、每台機器都要各自設定。
這也是為什麼正式的自動化腳本永遠要顯式帶 --project，不要依賴預設值——你不知道腳本會在誰的環境上跑。
gcloud auth login 和 gcloud auth application-default login 差在哪？
auth login 是給 gcloud 指令本身用的憑證。
application-default login 是給 你寫的程式碼（用 Google Cloud client library 時）用的憑證，會存成 ADC（Application Default Credentials）檔案。
兩者獨立。常見症狀：gcloud 指令跑得好好的，但 Python 程式報 DefaultCredentialsError——就是少做了第二個。
