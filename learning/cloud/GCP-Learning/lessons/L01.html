LESSON 01

雲端到底是什麼

在碰任何 GCP 按鈕之前，先把「雲」這個字拆開來看。它不是魔法，只是別人家的電腦——加上一套讓你用起來像水電的計費與自動化機制。

閱讀 20 分無需帳號

一、先講結論

「上雲」= 你不再自己買伺服器、不再自己顧機房，而是用租的，並且用多少付多少。GCP（Google Cloud Platform）就是 Google 把自己蓋的機房切出來租給你。

這件事之所以會改變整個產業，不是因為便宜——很多時候上雲比自架貴——而是因為它把「等待」變成「指令」。以前要新增一台伺服器，要採購、要等貨、要進機房裝機，兩週跑不掉。現在打一行指令，30 秒後機器就在跑了。把時間換成錢，這才是雲的本質。

生活比喻
想像你要開一家飲料店。

自建機房＝買地蓋房子。前期砸一大筆錢，之後每月成本固定，但生意好的時候位子不夠，生意差的時候空著也是浪費。
上雲＝租共享空間，按小時計費。午餐尖峰租 20 個座位，離峰縮到 3 個座位。你不用管水電維修、不用管保全，那是房東的事。

GCP 就是那個房東，而且是全世界最大的房東之一。

二、雲端的三種形態：IaaS / PaaS / SaaS

這三個詞你會一直看到，先在這裡一次搞懂。差別只有一個問題：哪些事是你管、哪些事是雲廠商管？

層級你要管什麼雲廠商管什麼GCP 對應服務比喻
IaaS
基礎設施即服務		作業系統、修補、軟體、應用程式實體機器、電力、網路、虛擬化Compute Engine（虛擬機）租一間空屋，家具自己買
PaaS
平台即服務		只要管你的程式碼作業系統、執行環境、擴充、修補Cloud Run、App Engine租一間附家具的套房
SaaS
軟體即服務		只要管你的資料與設定全部Gmail、Google Workspace住飯店

越往下走，你能控制的越少，但要操心的事也越少。企業架構的核心決策之一，就是每個元件該放在哪一層。一般原則：能用 PaaS 就別用 IaaS，除非你有非管作業系統不可的理由。

三、為什麼是 Google Cloud？

市場上三大雲：AWS（約 30% 市佔）、Azure（約 20%）、GCP（約 12%）。GCP 排第三，但在三個領域是明確的領先者：

  • 資料分析：BigQuery 幾乎沒有對手。可以在幾秒內掃過幾 TB 的資料，而且你不需要管任何伺服器。
  • Kubernetes：K8s 本身就是 Google 開源出來的，GKE 是體驗最完整的託管版本。
  • 全球網路：Google 自己有一張橫跨全球的私有光纖網路（就是撐起 YouTube 和搜尋的那張網）。你的跨區流量走的是這張網，不是公共網際網路。
補充
如果你已經用過 AWS：GCP 最大的差異是專案（Project）是最小的隔離單位，而不是帳號；而且很多服務預設就是全球性或區域性的，不像 AWS 那麼多東西綁死在單一 Region。這個差異在第二課會詳談。

四、幾個你一定要先認識的名詞

名詞白話解釋
Region（區域）一個地理位置的機房群，例如 asia-east1 是台灣彰化。你的資料放哪個 Region，就受哪個國家的法律管。
Zone（可用區）Region 裡面互相獨立的機房，例如 asia-east1-a、-b、-c。一個 Zone 停電，其他 Zone 不受影響。
Project（專案）GCP 的資源容器。所有東西都必須屬於某個專案，計費、權限、配額都以專案為單位。
Resource（資源）任何你開出來的東西：一台虛擬機、一個儲存桶、一個資料庫。
APIGCP 每個服務都要先「啟用 API」才能用，這是為了避免你不小心用到不需要的服務。
Quota（配額）上限保護。新帳號預設限制很多（例如最多 8 顆 CPU），避免你或駭客暴衝花錢。
小心踩雷
Region 選錯是最常見的新手錯誤。台灣使用者請優先用 asia-east1（彰化）。放到 us-central1 不是不能用，但每個請求會多 150～200 毫秒的延遲，而且跨洲流量費用更高。

五、雲端的計費邏輯（先建立正確直覺）

GCP 的收費大致可以拆成四類。你之後看到任何帳單，都可以套進這個框架：

  1. 運算時間：虛擬機開著就算錢，按秒計費（最少 1 分鐘）。關機不刪除，CPU 不收錢但磁碟還是收。
  2. 儲存容量：你放了多少 GB，按月計費。
  3. 網路流出（Egress）：資料離開 Google 的網路要錢，流入免費。這是最容易被忽略、也最容易爆炸的一項。
  4. API 呼叫次數／處理量：像 BigQuery 是按掃描的資料量計費，Cloud Run 是按請求數與執行時間計費。
實務提醒
記住這條：「進來免費，出去要錢。」把大量資料倒進 GCP 不用錢，但要搬出來會很痛。這叫做資料引力（data gravity），也是雲廠商鎖住客戶的主要手段。做架構決策時要意識到這件事。

六、本課小結

  • 能用自己的話解釋 IaaS / PaaS / SaaS 的差別
  • 知道 Region 和 Zone 不是同一件事
  • 知道「網路流出要錢、流入免費」
  • 知道台灣使用者應該優先選 asia-east1

自我檢測

公司要跑一個現成的商業軟體，這套軟體必須裝在 Windows Server 上並手動設定登錄檔。你該用 IaaS 還是 PaaS？
IaaS（Compute Engine）。因為你需要控制作業系統層級的設定。PaaS 不讓你碰作業系統，所以做不到。這也說明了「能用 PaaS 就用 PaaS」是原則，不是鐵律——被相依性綁住時就得往下一層走。
你把 5TB 的影片存在 Cloud Storage，每月被下載 100 次。哪一項成本可能最高？
網路流出費。5TB × 100 次 = 500TB 的 egress。以每 GB 約 0.12 美元估算，這是數萬美元；而 5TB 的儲存費一個月只要約 100 美元。這就是為什麼影音服務一定要搭 CDN（Cloud CDN），把流量擋在邊緣節點。
Zone 和 Region 各故障一次，影響範圍有什麼不同？該怎麼設計？
Zone 故障 = 一棟機房出事，同 Region 其他 Zone 還活著。Region 故障 = 整個地理區出事（極罕見，通常是天災或大規模網路事件）。
設計原則：一般服務做跨 Zone 高可用就夠（成本低、效果好）；金融、醫療等關鍵系統才做跨 Region 災難復原，因為跨 Region 同步資料的延遲與費用都很高。
