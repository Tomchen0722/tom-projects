LESSON 31

Vertex AI：訓練與部署機器學習模型

Vertex AI 是 GCP 的統一 ML 平台。這一課走一遍從資料到線上預測的完整流程，重點放在「什麼時候該用哪個層級的工具」。

閱讀 25 分進階

一、四種使用層級：先選對抽象層

層級做什麼誰用例子
① 現成 API直接呼叫訓練好的模型任何開發者Vision API 認圖、Speech-to-Text 轉語音、Translation 翻譯
② AutoML上傳資料，自動訓練沒有 ML 背景的人上傳 1000 張瑕疵照片，自動訓練出品管模型
③ BigQuery ML用 SQL 訓練模型資料分析師CREATE MODEL ... OPTIONS(model_type='boosted_tree_classifier')
④ 自訂訓練自己寫 PyTorch / TensorFlowML 工程師客製化架構、研究型專案
實務提醒
大多數企業 ML 需求，用第 ①③ 層就解決了。
「辨識發票欄位」→ Document AI（現成 API）；「預測客戶流失」→ BigQuery ML（一段 SQL）。
直接跳到自訂訓練通常是浪費——你會花三個月做出一個比 AutoML 差的模型。先用簡單方案建立基準線（baseline），證明它不夠好，再往下走。

二、BigQuery ML：分析師的 ML

BigQuery ML 完整流程
-- 情境：預測客戶會不會流失
-- 步驟 1：準備特徵
CREATE OR REPLACE TABLE ml.churn_features AS
SELECT
  customer_id,
  DATE_DIFF(CURRENT_DATE(), MAX(order_date), DAY)  AS days_since_last_order,
  COUNT(*)                                          AS total_orders,
  AVG(amount)                                       AS avg_order_value,
  SUM(amount)                                       AS lifetime_value,
  COUNT(DISTINCT product_category)                  AS category_diversity,
  IF(MAX(order_date) < DATE_SUB(CURRENT_DATE(), INTERVAL 90 DAY), 1, 0) AS churned
FROM mart.fact_orders
GROUP BY customer_id;

-- 步驟 2：訓練（就這樣，真的）
CREATE OR REPLACE MODEL ml.churn_model
OPTIONS(
  model_type = 'BOOSTED_TREE_CLASSIFIER',
  input_label_cols = ['churned'],
  auto_class_weights = TRUE,          -- 處理類別不平衡
  data_split_method = 'RANDOM',
  data_split_eval_fraction = 0.2,
  enable_global_explain = TRUE        -- 開啟特徵重要性分析
) AS
SELECT * EXCEPT(customer_id) FROM ml.churn_features;

-- 步驟 3：評估
SELECT * FROM ML.EVALUATE(MODEL ml.churn_model);
-- 輸出：precision, recall, accuracy, f1_score, log_loss, roc_auc

-- 步驟 4：看哪些特徵最重要（可解釋性）
SELECT * FROM ML.GLOBAL_EXPLAIN(MODEL ml.churn_model);

-- 步驟 5：預測
SELECT
  customer_id,
  predicted_churned,
  predicted_churned_probs[OFFSET(0)].prob AS churn_probability
FROM ML.PREDICT(MODEL ml.churn_model,
  (SELECT * FROM ml.churn_features WHERE churned = 0))
WHERE predicted_churned = 1
ORDER BY churn_probability DESC
LIMIT 100;

BigQuery ML 支援的模型類型：線性/邏輯迴歸、Boosted Tree、隨機森林、深度神經網路、K-means 分群、矩陣分解（推薦系統）、ARIMA_PLUS（時間序列預測）、以及直接呼叫 Gemini 做文字處理。

四、MLOps：模型上線之後才是開始

小心踩雷
機器學習專案失敗的主因不是模型不夠準，是模型上線後沒人管。
模型會衰退——因為真實世界一直在變，而模型停留在訓練時的那個世界。
問題說明偵測方式
資料漂移 Data Drift輸入資料的分布改變了（例如疫情後消費行為劇變）監控輸入特徵的統計分布
概念漂移 Concept Drift輸入與輸出的關係改變了監控預測準確率（需要真實標籤）
訓練/服務偏斜 Skew訓練時與線上預測時的特徵計算邏輯不一致比對兩邊的特徵分布
特徵管線失效上游資料源改了欄位，特徵變成 NULL資料品質檢查 + 告警
實務提醒
訓練/服務偏斜是最陰險的問題。典型情境：訓練時用 SQL 算「過去 30 天訂單數」，線上預測時用 Python 重新實作一次——兩邊對「30 天」的定義差一天，模型表現就大幅下降，而且離線評估看起來完全正常。

解法是 Feature Store：訓練與線上預測讀取同一份特徵定義與同一份資料，從架構上消除不一致的可能。

六、成本注意事項

小心踩雷
Vertex AI 的端點是本教材裡最容易產生意外帳單的服務。
• 部署的模型端點只要存在就收費，即使完全沒有請求。一個 n1-standard-4 端點約 $150/月。
• GPU 訓練工作忘記停止 → 一台 A100 每小時約 $3.9，一週就是 $650。

必做的防護：
① 實驗完立即 undeploy-model 並刪除端點。
② 訓練工作設定 --timeout。
③ 不需要即時預測就用 Batch Prediction——它跑完就結束，不會常駐收費。
④ 設定嚴格的預算警報。

自我檢測

業務要「用 AI 自動分類客服工單」。你的第一步是什麼？
先做一個不用 ML 的基準線。寫 20 條關鍵字規則，測一下準確率。

為什麼：
• 如果規則就有 85% 準確率，而 ML 只能到 88%，那 ML 增加的維運成本可能不划算。
• 這個過程會逼你把問題定義清楚：有幾個類別？類別互斥嗎？準確率要多高才有價值？錯誤的代價是什麼？
• 你會得到一批標註資料，這正是 ML 需要的。

然後依序嘗試：
① Gemini API + 提示工程——現在這往往是最快的方案，不用訓練、不用標註大量資料，幾小時就能驗證可行性。
② AutoML 文字分類——如果需要更穩定、更便宜的推論。
③ 自訂模型——只有在前兩者都不夠時。

核心原則：ML 是達成目標的手段，不是目標。「用 AI」這個需求本身應該被翻譯成可衡量的業務指標。
模型上線三個月後，客訴增加。離線測試準確率仍然很高。為什麼？
這個症狀直指「訓練/服務偏斜」或「漂移」。離線測試用的是訓練時的資料分布，所以看不出問題。

診斷順序：
① 比對特徵分布——把線上預測時實際收到的特徵值，跟訓練資料的分布做比較。如果某個特徵的平均值差很多，就找到方向了。
② 檢查特徵計算邏輯——訓練用 SQL、線上用 Python 的話，逐一驗證每個特徵在兩邊算出來是否相同。用同一筆資料跑兩邊，比對結果。
③ 檢查上游資料變更——是不是某個欄位改了格式、某個 API 改了回傳值、某個系統升級後語意變了。
④ 用近期真實資料重新評估——如果拿最近一個月的真實標籤來評估，準確率就掉了，那是概念漂移，需要重新訓練。

長期修正：導入 Feature Store（消除偏斜）+ Model Monitoring（自動偵測漂移）+ 定期重訓管線。
團隊想自己訓練一個大型語言模型。你的評估？
幾乎確定不該做，除非有極特殊的理由。

成本現實：從頭預訓練一個有競爭力的 LLM 需要數千張 GPU、數月時間、數百萬到數千萬美元，加上一支有經驗的研究團隊。這不是「有預算就能做」的事。

依需求的正確路徑：
① 需要特定領域知識 → RAG（檢索增強生成）。把你的文件放進向量資料庫，讓 Gemini 檢索後回答。成本低、資料可即時更新、可追溯來源。90% 的「我們需要自己的 AI」實際上需要的是這個。
② 需要特定的輸出格式或風格 → 提示工程 或 微調（fine-tuning）。Vertex AI 支援對 Gemini 做監督式微調，成本是預訓練的萬分之一。
③ 資料絕對不能離開內部 → 用開源模型（Llama、Gemma）在自己的 GKE 上部署，或用 Vertex AI 的私有端點。
④ 真的需要從頭訓練 → 通常只有兩種情況：極特殊的語言/領域（例如蛋白質序列），或者你本身就是 AI 研究機構。

建議的提問：「我們想解決什麼問題，是現有模型解決不了的？」如果答不出具體的技術差距，那答案就是不要自己訓練。
