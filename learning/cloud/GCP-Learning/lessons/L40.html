認證路線圖與考前衝刺

最後一課。這裡整理三張證照的準備策略、考試技巧，以及你之後該怎麼持續學習。

二、ACE 準備策略

範圍佔比對應本教材

ACE 的特色是「重指令、重操作」。大量題目會給你一個 gcloud 指令問你結果，或問你「達成 X 目標該用哪個指令」。

  1. 把本教材的所有實作至少做過一遍——不要只看，要真的打指令。
  2. 做 Google Cloud Skills Boost 的 ACE 學習路徑——它的實驗環境不用自己付費。
  3. 背熟常見指令的參數——特別是 gcloud compute、gcloud iam、kubectl。
  4. 做官方模擬題——至少三輪，每一題都要能說出「為什麼其他選項錯」。

三、PCA 準備策略：完全不同的考法

小心踩雷
PCA 不考指令，考判斷。題目通常是「某公司有這些需求與限制，下列哪個方案最合適」——四個選項可能都能運作，但只有一個最符合題目給的限制條件。

PCA 的解題方法：

  1. 先找限制條件——題目裡的「必須」「不能」「最低成本」「最短時間」「法規要求」才是答案的依據。技術上最完美的方案往往不是答案。
  2. 刪去法——先刪掉明顯違反限制的選項，通常能刪掉兩個。
  3. 在剩下的選項中找「Google 推薦做法」——考試偏好託管服務勝過自架、偏好無伺服器勝過 VM、偏好受管服務勝過自己造輪子。
  4. 注意「最」字——「最具成本效益」「最少維運負擔」「最快實作」，這三個關鍵字會導向完全不同的答案。

PCA 的案例研究（必讀）

PCA 考試有四份官方案例研究（虛構公司的背景描述），約 30% 的題目基於它們。務必在考前完整讀過並自己畫出架構：

  • EHR Healthcare——醫療業，重點在法規遵循、混合雲、資料保護
  • Helicopter Racing League——媒體串流，重點在全球分發、即時預測、CDN
  • Mountkirk Games——遊戲，重點在全球低延遲、自動擴充、即時排行榜
  • TerramEarth——製造業 IoT，重點在大量裝置資料、預測性維護
實務提醒
案例研究的準備方法：對每一個案例，自己動手畫出完整架構圖，並針對每個元件寫下「為什麼選它、替代方案是什麼、為什麼不選替代方案」。
這個練習做完，你不只會考試，是真的具備架構能力了。

四、考試當天

  • 題數與時間：ACE 50 題 / 2 小時；PCA 50～60 題 / 2 小時。時間通常夠，但 PCA 的題目很長，要控制節奏。
  • 可以標記題目回頭再看——第一輪先把有把握的做完，不要卡在難題上。
  • 沒有倒扣——不確定也一定要選。
  • 線上考試要注意環境：桌面淨空、不能有第二個螢幕、全程開鏡頭、不能離開座位。建議選實體考場，免除環境風險。
  • 證照有效期 2 年，到期前需要重考。

五、走完這 40 課之後

① 做一個完整的個人專案

證照證明你懂概念，專案證明你會做事。建議做一個包含以下要素的專案：

  • 用 Terraform 管理所有基礎設施
  • 應用容器化並部署到 Cloud Run 或 GKE
  • 有 CI/CD 流水線（推程式碼自動部署）
  • 有資料庫（Cloud SQL）與快取（Memorystore）
  • 有完整的監控、日誌與告警
  • 有 SLO 定義與錯誤預算
  • 程式碼放在 GitHub，README 說明架構決策與取捨

面試時能拿出這樣一個專案，比三張證照更有說服力。

② 持續學習的資源

③ 建立自己的判斷力

這是最重要的一項，也是這套教材真正想留給你的東西。

GCP 的服務會改名、會下架、會有新的替代品。但底層的判斷邏輯不會變：

  • 先問需求，再選技術。「我們要用 K8s」不是需求，「我們需要在 5 分鐘內從 10 台擴到 200 台」才是。
  • 每個選擇都是取捨。沒有免費的午餐。看到「這個方案什麼都好」時，那是你還沒看到代價。
  • 從簡單開始，保留退路。過早最佳化的成本是實實在在的，未來的需求則是猜測。
  • 可觀測性優先於功能。看不見的系統無法維護、無法優化、無法信任。
  • 沒演練過的計畫等於沒有計畫。備份、DR、事故處理都適用。
  • 安全流程如果讓人痛苦，人就會繞過它。設計時要讓「做對的事」比「繞過」更容易。

六、結語

你從「完全沒碰過雲」走到這裡，經過了 40 課、8 個章節、24 個動手實作。

但真正的學習從現在才開始。這套教材給你的是地圖，不是目的地——它讓你知道每個服務在哪裡、大概長什麼樣、什麼時候該用它。真正的能力來自於你接下來親手蓋出來的東西，以及蓋壞之後修好它的過程。

去開一個專案，把它做完，讓它上線，然後想辦法讓它更便宜、更穩、更快。那才是這 40 課的用途。

自我檢測

PCA 題目：某公司要把地端 Hadoop 叢集搬上雲，要求「最少的維運負擔」且「保留現有的 Spark 程式碼」。選什麼？
Dataproc（或 Dataproc Serverless）。

解題過程示範：
① 找限制條件——「保留現有 Spark 程式碼」排除了 Dataflow（需要改寫成 Beam）；「最少維運負擔」排除了在 Compute Engine 上自架 Hadoop。
② 剩下的選項——Dataproc（託管 Hadoop/Spark）符合兩個條件。
③ 進一步優化——如果選項中有 Dataproc Serverless，那是更好的答案，因為它連叢集都不用管。

但要注意題目的其他線索：如果題目強調「長期成本最低」且「願意投入改造」，答案可能變成 BigQuery + Dataflow（真正的雲原生方案）。同樣的技術背景，不同的限制條件會導向不同答案——這就是 PCA 的考法。
你考過 PCA 了，但面試官問「你實際做過什麼」。你怎麼準備這個問題？
證照回答不了這個問題，只有專案可以。準備一個能講 20 分鐘的專案，結構如下：

① 問題是什麼——不要從技術講起，從要解決的問題講起。
② 你考慮過哪些方案——這裡展現的是判斷力。「我考慮過 A 和 B，選了 A 因為...，但如果流量再大 10 倍我會改選 B」。面試官想聽的是取捨，不是你會用什麼服務。
③ 實際遇到什麼問題——這是最有價值的部分。「一切都很順利」是最糟的答案，因為那表示你沒做到夠深。講一個真實的踩坑：冷啟動太慢、成本失控、部署造成停機，以及你怎麼發現與解決的。
④ 學到什麼、下次會怎麼做——展現反思能力。
⑤ 可量化的結果——「回應時間從 800ms 降到 120ms」「月成本從 $400 降到 $150」。

建議：邊做專案邊寫技術部落格或 README，記錄決策過程。三個月後你會忘記為什麼那樣選，但寫下來的不會忘。這也是面試時最好的佐證。
學完這 40 課，你覺得自己「懂 GCP 了」。這個判斷正確嗎？
你懂的是「地圖」，不是「地形」。這兩者的差距，只有真的做過專案才會知道。

你現在具備的：
• 知道 GCP 有哪些服務、各自解決什麼問題
• 能在架構討論中聽懂並提出意見
• 遇到問題知道該往哪個方向查
• 能通過認證考試

你還不具備的（只能靠實戰累積）：
• 直覺——看到一個架構圖，三秒內感覺到「這裡會出事」
• 除錯經驗——凌晨三點服務掛了，能快速縮小範圍
• 成本的體感——知道什麼設定會讓帳單暴增
• 組織的現實——技術上正確的方案，怎麼在有既有系統、有政治、有預算限制的環境裡落地

接下來三個月的建議：
① 做一個真的會被人用的專案（哪怕使用者只有你自己）
② 讓它上線並跑三個月，觀察成本與故障
③ 至少經歷一次「線上出問題」並修好它

學習的順序是：不知道自己不知道 → 知道自己不知道 → 知道自己知道 → 不用想就知道。這 40 課帶你走完了第二步。第三步要靠專案，第四步要靠年資。

祝你順利。
