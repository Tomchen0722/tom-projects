LESSON 06

Compute Engine：開你的第一台虛擬機

虛擬機是雲端最古老、也最好理解的服務。這一課從零開一台機器、連進去、裝好網站，然後——很重要——把它關掉。

操作 50 分約 0.1 美元實作

一、虛擬機到底是什麼

Google 機房裡有一台超大的實體伺服器，可能有 128 顆 CPU、1TB 記憶體。它不會整台租給你，而是切成很多份。你租到的那一份，就是虛擬機（Virtual Machine, VM）。

生活比喻
實體伺服器 = 一整棟透天厝。
虛擬機 = 把透天厝隔成套房出租。

你在自己的套房裡想幹嘛都行（裝什麼軟體、改什麼設定），而且隔壁套房的人看不到你——這由虛擬化技術（hypervisor）保證。
但你不能拆承重牆（碰到實體硬體），也不能決定整棟樓的水電（機房設施）。

二、開機前要決定的五件事

決定項目選什麼為什麼重要
名稱小寫英數與連字號，如 web-server-01建立後不能改，命名要有規則
Region / Zone台灣用 asia-east1-b決定延遲、法遵、價格
機器類型學習用 e2-micro（2 vCPU 共享 / 1GB）直接決定價格，最重要的成本槓桿
開機磁碟Debian 12 / Ubuntu 22.04 / 自訂映像作業系統與容量
網路與防火牆是否要外部 IP、開哪些連接埠決定能不能連進來，也是資安第一道關

三、實作：三種方式開同一台機器

動手實作

實作 1：用 gcloud 開機（推薦從這裡開始）

  1. 在 Cloud Shell 執行：
    bash
    gcloud compute instances create web-01 \
  --zone=asia-east1-b \
  --machine-type=e2-micro \
  --image-family=debian-12 \
  --image-project=debian-cloud \
  --boot-disk-size=10GB \
  --boot-disk-type=pd-standard \
  --tags=http-server \
  --labels=env=lab,owner=tom,purpose=temp
  2. 等 20～30 秒。成功後會印出內部 IP 與外部 IP。
    把外部 IP 記下來（也可以隨時用 gcloud compute instances list 查）。
  3. 連進去（gcloud 會自動幫你產生並管理 SSH 金鑰，不用手動處理）：
    bash
    gcloud compute ssh web-01 --zone=asia-east1-b
  4. 第一次連線會問你要不要產生金鑰，直接 Enter 兩次（passphrase 留空）即可。連進去後你會看到 tom@web-01:~$。
  5. 在機器裡裝一個網頁伺服器：
    bash
    sudo apt update -y
sudo apt install -y nginx
echo "<h1>Hello from GCP! 這是我的第一台雲端機器</h1>" | sudo tee /var/www/html/index.html
sudo systemctl status nginx    # 確認在跑
  6. 在機器裡用 curl localhost 測試，應該看得到你剛寫的 HTML。
    但從瀏覽器連外部 IP 還是連不上——因為防火牆還沒開。
  7. 回到 Cloud Shell（打 exit 離開 VM），開防火牆規則：
    bash
    gcloud compute firewall-rules create allow-http-lab \
  --allow=tcp:80 \
  --target-tags=http-server \
  --source-ranges=0.0.0.0/0 \
  --description="實驗用：開放 80 埠給貼有 http-server 標記的機器"
  8. 現在用瀏覽器打開 http://外部IP，應該看得到你的網頁。你剛剛把一個網站上線了。
實務提醒
注意上面用的是 network tag（--tags=http-server），不是直接對機器開防火牆。
這是 GCP 防火牆的核心設計：規則綁在「標記」上，機器貼標記就套用規則。這樣新開 100 台機器只要貼同一個標記，不用改防火牆。

四、SSH 的三種連線方式

方式指令／位置適用情境
gcloud sshgcloud compute ssh NAME日常首選。自動管理金鑰、自動處理 IAP
Console 瀏覽器 SSHVM 列表點「SSH」按鈕臨時查東西、手邊沒有終端機
傳統 SSH 金鑰ssh -i key user@ip要用自己的工具鏈（如 Ansible）時
小心踩雷
不要為了 SSH 而給機器公開的外部 IP。暴露在網際網路上的 22 埠，開機後幾分鐘內就會開始被暴力破解掃描。
正確做法是用 IAP TCP Forwarding，讓機器完全沒有外部 IP 也能連：
bash
# 開一台沒有外部 IP 的機器
gcloud compute instances create private-vm \
  --zone=asia-east1-b --machine-type=e2-micro --no-address

# 允許 IAP 的來源網段連 SSH
gcloud compute firewall-rules create allow-iap-ssh \
  --allow=tcp:22 --source-ranges=35.235.240.0/20

# 透過 IAP 連線（流量走 Google 內部，不經過公網）
gcloud compute ssh private-vm --zone=asia-east1-b --tunnel-through-iap

五、生命週期：開、關、刪的差別（會影響帳單）

生命週期指令
gcloud compute instances stop web-01     # 停止：CPU/RAM 不收錢，磁碟仍收錢
gcloud compute instances start web-01    # 啟動：外部 IP 會變（除非用靜態 IP）
gcloud compute instances reset web-01    # 硬重開（等於拔電源，資料可能受損）
gcloud compute instances delete web-01   # 刪除：預設連開機磁碟一起刪
狀態CPU / 記憶體費用磁碟費用外部 IP資料
RUNNING 執行中收費收費保留在
TERMINATED 已停止免費仍收費釋放（非靜態 IP）在
已刪除免費免費（磁碟同時刪除）釋放消失
小心踩雷
「停止」不等於「不花錢」。一顆 100GB 的 SSD 磁碟，即使機器關著，一個月還是要約 17 美元。
學習完畢請確實刪除，不要只是停止。

六、開機腳本（Startup Script）：自動化的第一步

每次開機都手動 SSH 進去裝軟體太蠢。開機腳本讓機器一啟動就自動完成設定——這是走向自動擴充的必要基礎。

帶開機腳本建立 VM
gcloud compute instances create web-auto \
  --zone=asia-east1-b \
  --machine-type=e2-micro \
  --image-family=debian-12 --image-project=debian-cloud \
  --tags=http-server \
  --metadata=startup-script='#!/bin/bash
apt update -y
apt install -y nginx
HOSTNAME=$(hostname)
cat > /var/www/html/index.html <<HTML
<h1>Server: $HOSTNAME</h1>
<p>啟動時間：$(date)</p>
HTML
systemctl restart nginx'
實務提醒
腳本比較長時，改成從 Cloud Storage 讀取，避免指令變成一團亂：
bash
# 上傳腳本
gcloud storage cp startup.sh gs://my-bucket/scripts/

# 建立 VM 時指向它
gcloud compute instances create web-auto \
  --metadata=startup-script-url=gs://my-bucket/scripts/startup.sh

七、收工：一定要做的清理

動手實作

實作 2：清理你開的所有資源

  1. 列出目前有什麼：
    bash
    gcloud compute instances list
  2. 刪除機器（--quiet 跳過確認）：
    bash
    gcloud compute instances delete web-01 web-auto \
  --zone=asia-east1-b --quiet
  3. 刪除防火牆規則：
    bash
    gcloud compute firewall-rules delete allow-http-lab --quiet
  4. 確認沒有殘留的磁碟與 IP：
    bash
    gcloud compute disks list
gcloud compute addresses list

八、本課檢核

  • 能用一行 gcloud 指令開出一台 VM
  • 知道防火牆規則要靠 network tag 綁定
  • 能說出 stop 與 delete 在計費上的差別
  • 會寫基本的 startup script
  • 知道 IAP 可以讓 VM 不需要外部 IP 也能 SSH
  • 已清乾淨所有實驗資源

自我檢測

你開了 VM、裝好 nginx、防火牆也開了，但瀏覽器還是連不上。列出排查順序。
由內而外五層依序檢查：
① 服務有沒有在跑：VM 內 curl localhost。不通就是 nginx 的問題。
② 有沒有綁對介面：sudo ss -tlnp 看是否 listen 在 0.0.0.0:80 而非 127.0.0.1:80。
③ 作業系統防火牆：Ubuntu 的 ufw、CentOS 的 firewalld 可能擋著。
④ GCP 防火牆規則：gcloud compute firewall-rules list，確認 target tag 有貼在這台機器上。
⑤ 機器有沒有外部 IP：gcloud compute instances list。
九成的情況是第 ④ 步的 tag 沒貼對。
機器 stop 之後再 start，外部 IP 變了，導致 DNS 失效。怎麼解？
把外部 IP 從臨時（ephemeral）改成靜態（static）：
bash
gcloud compute addresses create web-ip --region=asia-east1
gcloud compute instances delete-access-config web-01 --zone=asia-east1-b
gcloud compute instances add-access-config web-01 --zone=asia-east1-b \
  --address=$(gcloud compute addresses describe web-ip --region=asia-east1 --format='value(address)')
但更好的答案是：不要讓 DNS 指向單一 VM。正式架構應該指向負載平衡器，這樣換機器完全不影響 DNS（第 9 課會做）。
startup script 明明寫了，機器起來卻沒生效。怎麼查？
看開機腳本的執行日誌：
bash
# 在 VM 內
sudo journalctl -u google-startup-scripts.service

# 或從外面看序列埠輸出
gcloud compute instances get-serial-port-output web-auto --zone=asia-east1-b
常見原因：① 忘了第一行 #!/bin/bash；② 腳本裡用了需要互動的指令（如 apt install 沒加 -y）；③ 腳本以 root 執行，寫了 sudo 通常沒事但路徑假設會錯。
