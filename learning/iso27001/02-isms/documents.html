📁 必備文件清單

取得 ISO 27001 認證必須備齊的文件，逐一說明用途、寫法重點和常見地雷。

📚 文件的兩個層次

ISO 27001 要求的文件分兩種：文件化資訊（Documented Information）和記錄（Records）。

文件化資訊（政策、程序）記錄（執行證據）
是什麼「怎麼做」的規定，是一種制度設計「做了什麼」的證明，是執行的證據
例子資訊安全政策、密碼管理程序員工訓練簽到表、稽核報告
更新頻率重大變更時更新，至少每年審查每次執行後產生新記錄
稽核重點內容是否完整、是否有被授權是否真的有做、記錄是否完整
💡 稽核員的口頭禪：「如果沒有文件，等於沒做到。」 制度設計很好，但沒有執行記錄，稽核員會判定不符合。

🔴 強制必備文件（缺一不可）

📜

1. 資訊安全政策（Information Security Policy）

強制條款 5.2

ISMS 的最高層文件，說明公司對資安的承諾、目標和基本原則。通常 1-3 頁。

📝 必包含：適用範圍、高層承諾聲明、資安目標方向、違反的後果。必須由最高管理者（CEO 或董事會）簽署。
🗺️

2. ISMS 範疇文件（Scope of the ISMS）

強制條款 4.3

明確說明 ISMS 覆蓋的範圍：哪些部門、哪些地點、哪些系統、哪些流程在 ISMS 的管控範圍內。

📝 常見地雷：範疇定太廣（整個公司），導致文件量和控制措施量爆炸。首次認證建議從核心業務系統開始，範疇定清楚。
⚠️

3. 風險評估程序（Risk Assessment Process）

強制條款 6.1

說明公司如何進行風險評估：採用什麼方法論（例如：資產基礎法）、風險計算公式、風險接受準則。

📝 重點：這是「程序」文件，說明怎麼做風險評估，不是風險評估的結果報告（結果另外在風險登記表記錄）。
📊

4. 風險評估結果（Risk Assessment Results）

強制記錄條款 8.2

實際做完風險評估後的結果，通常是一張 Excel 表，列出所有資產、威脅、脆弱性、風險值、風險排序。

📝 格式建議：資產 → 威脅 → 脆弱性 → 影響程度（1-5）× 可能性（1-5）= 風險值 → 風險等級（高/中/低）。
🛡️

5. 風險處理計畫（Risk Treatment Plan, RTP）

強制條款 6.1.3

針對高風險項目，說明要採取什麼處理措施（接受/降低/移轉/規避），由誰負責，什麼時間完成。

📝 格式建議：每個高/中風險都要有對應的控制措施、負責人、完成期限、複查日期。這份文件在稽核時會被仔細檢查。
📝

6. SOA 適用性聲明書（Statement of Applicability）

強制條款 6.1.3(d)

最核心的文件之一。列出 Annex A 所有 93 個控制項，說明每一個是否適用、理由、現有措施或計畫措施。

📝 特別注意：排除某個控制項必須有充分理由，稽核員會逐一詢問。「公司很小用不到」通常不被接受，要說明具體原因。
🎯

7. 資安目標（Information Security Objectives）

強制條款 6.2

具體、可量測的資安目標。例如：「本年度零勒索病毒事件」、「員工資安訓練完成率 100%」、「漏洞修補 SLA 達成率 ≥ 95%」。

📝 SMART 原則：目標要 Specific（具體）、Measurable（可量測）、Achievable（可達成）、Relevant（相關）、Time-bound（有時限）。
📚

8. 能力與意識訓練記錄

強制記錄條款 7.2/7.3

員工資安訓練的記錄：訓練日期、內容、參加人員簽到表、測驗結果（如果有測驗）。

📝 常見地雷：訓練做了但沒有保留記錄，稽核員會判定不符合。至少要有出席簽到表和訓練大綱。
🔍

9. 內部稽核結果（Internal Audit Results）

強制記錄條款 9.2

每年至少一次的內部稽核報告，包含：稽核計畫、稽核員、稽核日期、發現項目（觀察/輕微不符合/主要不符合）。

🏛️

10. 管理審查結果（Management Review Results）

強制記錄條款 9.3

高層管理者定期開會審查 ISMS 的會議記錄，包含：討論議題、決策內容、後續行動計畫。

🔧

11. 矯正措施記錄（Corrective Action Records）

強制記錄條款 10.2

發現不符合項目後的處理記錄：不符合描述、根本原因分析、矯正措施、預防再發措施、有效性確認。

🟡 建議加上的程序文件

這些不是 ISO 27001 強制要求的文件，但稽核員通常會預期看到，沒有的話可能會被標記為「觀察事項」。

文件名稱說明對應控制項
資訊資產清冊所有資訊資產的清單，含資產擁有者、分類等級、存放位置A.5.9
存取控制程序帳號申請、審核、授權、撤銷的標準作業程序A.5.15-18
事件回應程序資安事件發生時的通報、處理、升級、記錄流程A.5.24-28
備份與還原程序備份頻率、媒介、存放地點、還原測試周期A.8.13
變更管理程序IT 系統變更的申請、審核、測試、實施、回滾流程A.8.32
供應商管理程序供應商評估、合約要求、定期複審的標準A.5.19-22
業務持續計畫（BCP）重大災難時如何維持業務運作，含 DR 演練計畫A.5.29-30
人員安全程序新進、在職、離職各階段的資安措施A.6.1-5

📋 文件管理的基本要求

ISO 27001 條款 7.5 要求文件必須受到管控，最低限度需要符合以下要求：

  • ①版本控制：每份文件有版本號（V1.0、V1.1）和修訂日期
  • ②審查與核准：重要文件需要有人審查、有人核准（不能自己寫自己批）
  • ③可取得性：需要的人可以找到並看到，不能只有一個人知道在哪裡
  • ④保護：重要文件要防止未授權修改和意外刪除
  • ⑤保存期限：記錄類文件要規定保存年限（通常 2-5 年，視法規要求）
💡 工具建議：文件可以用 SharePoint、Confluence、Google Drive 管理，只要有版本歷史記錄和存取權限控制即可。不需要買昂貴的文件管理系統。
