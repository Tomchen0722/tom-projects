半導體機台資安：TI 經驗 vs Teradyne Eagle 364 與 SEMI E187

深度結合德州儀器（TI）高標準晶圓測試產線、Teradyne Eagle 364（ETS-364）類比測試機台架構，以及全球半導體設備資安標準 SEMI E187，貫通 ISO 27001:2022 核心條文與 Annex A 稽核重點。

🏭 為什麼半導體機台是 ISO 27001 稽核的重中之重？

在傳統辦公室 IT 環境中，資安主要關注電子郵件釣魚、資料庫洩漏或網站防護。但在半導體製造與封裝測試（OSAT / IDM）領域，核心命脈在於產線上的自動化測試設備（ATE, Automated Test Equipment）。

一旦機台遭受勒索病毒感染（如台積電 2018 年機台遭 WannaCry 變種感染停線事件），造成的損失是每分鐘數百萬新台幣！這促使國際半導體產業協會（SEMI）在台積電、聯電、工研院等推動下，正式發布了專屬的半導體製造設備資安標準——SEMI E187。

💡 TI（Texas Instruments, 德州儀器）實務的核心訴求：
德儀作為全球類比 IC 與嵌入式處理器龍頭，對測試廠與代工廠的要求極端嚴格：
1. 保護測試智慧財產權（Test Program IP）：IC 測試向量（Pattern）、修調（Trimming）演算法直接決定晶片性能與成本，絕不可外洩或遭逆向工程。
2. 測試資料完整性與防篡改（STDF Yield Data）：標準測試資料格式（STDF）紀錄每一顆晶粒（Die）的 Pass/Fail 與電氣參數，一旦被惡意篡改將導致瑕疵晶片流入車用或航太供應鏈。
3. 機台持續可用性（Availability ≥ 99.9%）：產線 24 小時連續不停機，維護窗口極端有限。

⚡ Teradyne Eagle 364（ETS-364）測試機台資安弱點與架構拆解

Teradyne ETS-364（Eagle 364）是全球高精度類比、電源管理（PMIC）與混合訊號晶片測試的標竿測試平台。從資安與系統稽核視角檢視，其內部結構具有非常典型的「OT 工業設備特徵」：

🖥️ 機台控制器（System Controller）

• 硬體結構：工控工業電腦（IPC），配備專屬背板匯流排與儀器板卡（APU、OVI、SPU、QTM 等）。
• 作業系統：多數運行專用 Windows 或 Linux 嵌入式系統。
• 資安痛點：受限於原廠軟體相容性，作業系統往往無法隨意安裝最新微軟補丁，甚至運行已終止支援之舊版 OS，極易成為勒索軟體溫床！

🔌 通訊介面與資料傳輸鏈路

• GPIB / USB 介面：連接晶圓針測機（Wafer Prober）或封裝分選機（Handler）。
• 雙網卡實體分流：一張網卡連封閉測試儀器內網（Private Tester Bus），另一張網卡連廠務產線 MES 網路。
• 資安痛點：現場工程師為了除錯或載入測試程式，常有私自插拔 USB 隨身碟或連接個人筆電之違規風險。

⚠️ Eagle 364 機台常見 4 大資安稽核弱點：
1. 預設原廠特權帳號密碼未變更（如原廠維修工程師 Administrator 或 Service 帳號長年沿用出廠密碼）。
2. 第三方維護人員（Teradyne FAE）遠端連線未審計（透過 TeamViewer 或外接 4G 網卡連線進機台除錯，繞過廠務防火牆）。
3. 測試程式未加密且缺乏版本雜湊校驗（測試程式直接以明文存放於本機硬碟共用資料夾）。
4. 缺乏防毒或防惡意軟體端點防護（工程師常以「防毒會干擾微秒級量測中斷」為由擅自停用資安軟體）。

🛡️ SEMI E187 半導體設備資安標準四大核心支柱

SEMI E187 是台灣半導體產業引領全球制定的首套製造設備資安標準。主導稽核員在審查半導體與高科技製造時，必須能將 SEMI E187 與 ISO 27001 控制項相互對映：

1. 作業系統安全（OS Security）

• 要求機台必須使用仍受原廠支援之作業系統。
• 若因測試架構限制必須使用舊版 OS（如 Eagle 364 的相容性需求），必須實施書面補償控制（Compensating Controls）：關閉不必要服務、移除預設遊戲與瀏覽器、鎖定本機群組原則。
• 對映 ISO 27001:2022：A.8.8 技術弱點管理、A.8.9 組態管理。

2. 網路傳輸安全（Network Security）

• 嚴格禁止機台直連外網；預設關閉所有不安全明文通訊協定（停用 Telnet、FTP、SMBv1、HTTP，全面改用 SSH、SFTP、HTTPS）。
• 機台網路實施白名單控制（Network Allowlisting），僅允許機台與 MES 主機、測試資料伺服器（STDF Server）在指定 Port 通訊。
• 對映 ISO 27001:2022：A.8.20 網路安全、A.8.22 網路隔離（微隔離）。

3. 端點安全防護（Endpoint Protection）

• 機台出廠必須無任何已知病毒或惡意程式（提供惡意軟體清潔證明書）。
• 導入應用程式白名單防護機制（Application Whitelisting），取代傳統特徵碼防毒，鎖死測試行程（ETS Runtime），任何非白名單未授權執行檔一律禁止啟動。
• 嚴格封鎖實體 USB 外接儲存裝置（USB Port Locking）。
• 對映 ISO 27001:2022：A.8.7 惡意軟體防護、A.7.10 儲存媒體管理。

4. 資安監控與日誌審計（Security Monitoring）

• 機台必須具備資安事件記錄能力，包括：使用者登入/登出、特權變更、測試程式載入、系統設定變更。
• 機台系統時間必須透過 NTP 伺服器同步，避免鑑識時序混亂。
• 對映 ISO 27001:2022：A.8.15 記錄作業（Logging）、A.8.17 時鐘同步（Clock synchronization）。

📑 ISO 27001:2022 核心條文 vs TI 半導體實務對照矩陣

主導稽核員在查核半導體封測廠與測試機台時，應依據下表查核條文符合性與採集客觀佐證：

ISO 27001:2022 條文 標準條文核心要求 TI / Teradyne Eagle 364 機台實務對應 稽核員現場查核重點與客觀證據
Clause 4.2
利害關係人需求		 組織應鑑別與 ISMS 相關的利害關係人及其法律、合約要求。 TI 德州儀器客戶合約中明確要求的機密測試程式保密條款與供應鏈資安規範。 查核 TI 專案合約（NDA）與客戶資安規範是否已完整轉化為內部產線作業準則（SOP）。
Clause 6.1.2
風險評鑑流程		 系統性識別資訊資產之機密性、完整性、可用性風險。 Eagle 364 機台停機損失評估、良率資料被竄改的召回賠償風險評估。 查核「測試廠機台資產風險評估表」，確認是否有將機台中毒停產列入高風險評估並定有處理計畫。
A.5.19 ~ 5.23
供應商關係資安		 控制外部供應商、設備商與技術支援人員之存取風險。 Teradyne（泰瑞達）原廠客服與 FAE 工程師進廠維修或遠端連線診斷。 查核原廠簽署的資安承諾書、遠端維護是否經雙人審批、連線期間是否全程側錄並於完成後立即關閉帳號。
A.8.8
技術弱點管理		 獲取技術弱點資訊、評估暴露程度並採取適當補償措施。 Eagle 364 系統控制器作業系統無法升級時之安全加固與補償控制。 查核機台是否具備書面補償評估報告、微隔離防火牆規則，以及是否每年複審該弱點風險。
A.8.20 / 8.22
網路安全與隔離		 網路必須受到妥善保護，敏感系統實施分段與隔離。 普渡模型（Purdue Model）：將 Eagle 364 置於 Level 2 / Level 3 工業網段，杜絕直連辦公網與外網。 現場檢視交換器與防火牆 Access List（ACL），查驗機台 IP 是否確實禁止對外連線（ping 8.8.8.8 應失敗）。
A.8.24
密碼學控制		 適當使用密碼技術保護敏感資訊之機密性與完整性。 TI 晶片測試程式（Test Program）原始代碼與修調演算法的二進位加密與雜湊簽章。 查核測試程式派送系統是否具備 SHA-256 完整性校驗，防止產線作業員擅自修改測試 Limit 參數放行不良品。

📋 稽核員現場查核表：Teradyne Eagle 364 機台資安查核

  • 符合樣態
    USB 實體與軟體雙重封鎖： 機台主機 USB 埠塗抹封膠或加裝實體防盜鎖，登錄檔停用 USB 儲存裝置（usbstor.sys = 4），測試程式一律由加密內部網路自動派送。
  • 不符合 NCR
    特權帳號共享且無管控： 現場工程師坦承為了方便三班輪值，全體測試員共用同一組具備本機管理員權限之「operator」帳號登入 Eagle 364，密碼貼在機台外殼黃色便利貼上。（違反 A.5.15 / A.8.5）
  • 不符合 NCR
    未授權遠端桌面直連： 稽核員查驗防火牆日誌，發現某台 Eagle 364 機台於凌晨 02:15 接受來自外部未知 IP 的 TeamViewer 遠端連線，現場無任何申請工單與核准紀錄。（違反 A.5.21 / A.8.20）
  • 符合樣態
    定期校正與防毒白名單日誌同步： 機台配置 Application Whitelisting 軟體，只允許 ets_runtime.exe 等白名單程式運作；每日校正日誌與測試結果 STDF 檔每 30 分鐘自動同步至備份伺服器。

🧠 實務情境即測即評

情境題：你在查核一家為 TI 代工測試的封測廠，廠長表示：「我們的 Teradyne Eagle 364 機台是純封閉離線運作，既不連外網，也不連辦公室網路，所以我們把機台完全排除在 ISO 27001 ISMS 驗證範圍之外，SOA 也不用評估機台控制項。」身為主導稽核員，你接受這個說法嗎？理由為何？

點擊展開主導稽核員專業判定解析
【稽核判定】：絕不接受！這屬於不合理的範圍刻意切割（Scope Exclusion）！
【理由解析】：
1. 實質業務相依性：測試廠的核心業務即為晶片測試，測試程式（客戶 TI 的核心資產）與測試良率數據均在該機台上運行儲存，若排除機台，整個 ISMS 驗證形同虛設，失去商業與法規可信度（違反 Clause 4.3 決定 ISMS 範圍）。
2. 並非真正完全隔離：機台雖然不連網際網路，但仍需透過隨身碟或內部局域網載入測試程式、輸出 STDF 資料，且人員會直接實體操作，存在實體、儲存媒體與人員維運風險。
3. 正確做法：機台必須納入 ISMS 範圍，並將「離線/網路隔離」作為實踐 A.8.20 / A.8.22 的防禦控制手段，而非排除驗證範圍的理由。
